# Physician sign-off packets

Generated by `scripts/dev/signoff_packet.py` from the committed candidates, proposals and verification trail. Regenerate it; never edit it by hand. A packet records decisions and never edits a pack.

One packet per committed review candidate: 8 cluster packets and 91 branch packets. The verification trail holds 203 open items, filed 367 times across 88 packets; 13 name no packet ([`_unassigned.md`](_unassigned.md)).

## How to sign

1. Open the department's packet: `<branch>.md`, or `cluster_<id>.md` for the questions every member branch inherits. Read §1 to §3, then each open item in §4.
2. Copy the packet to `docs/signoff/signed/<packet>-<YYYY-MM-DD>.md`. The generator writes only the top level of `docs/signoff/`, so it never overwrites a signed copy.
3. In the copy's §5, fill signer, role and date, and write one decision per open item: `accept`, `change: <text>` or `reject`.
4. The candidate sha256 in the header binds the decisions to those candidate bytes. When the candidate changes, its packet regenerates with a new sha256, and a signed copy naming the old one no longer describes the candidate.
5. Signing edits no pack. Promotion past L0 still needs the candidate's `clinical_signoff` block (HB-C1).

## How decisions flow back

1. A follow-up PR applies each decision to the proposal (`docs/evidence/proposals/<slug>.md`), never to a candidate or the served tree.
2. It regenerates the candidates: `uv run python scripts/dev/gen_specialty_packs.py`.
3. An independent verifier checks the regenerated candidates against the decisions and records the review under `docs/evidence/verification/`.
4. `uv run python scripts/dev/signoff_packet.py` regenerates these packets; `--check` exits 1 on drift, and `tests/protocols/test_signoff_packet.py` fails on it.

## How open items are chosen and filed

- An open item is a table row, outside code fences, that names a human decider (an HB-C id, a psychiatrist, a paediatrician, the owner, the clinician, or `awaiting-human`). The trail read: `docs/evidence/verification/cluster-wave-a.md`, `docs/evidence/verification/cluster-wave-b.md`, `docs/evidence/verification/near-twin-sweep-582.md`, `docs/evidence/verification/reorder-op-582.md`, `docs/evidence/verification/sibling-rebinds-582.md`, `docs/evidence/verification/specialty-wave1-3.md`, `docs/evidence/verification/specialty-wave4-5.md`, `docs/evidence/verification/specialty-wave6-internal-mental.md`, `docs/evidence/verification/specialty-wave7-onc-women-peds.md`, `docs/evidence/verification/specialty-wave8-geriatric-dental.md`, `docs/evidence/verification/specialty-wave9-occupational-public.md`, `docs/evidence/INT-353.md`.
- A row is filed under every packet that it or its section heading names: by slug, Turkish name, a prefix of either, the name's initials, or the cluster id (`scripts/dev/signoff_trail.py`). A row that names no packet is filed under the packets whose candidates declare a slot id it quotes. A row that names nothing is listed in `_unassigned.md` and is never forced into a packet.
- Deciders are the HB ids a row cites, then the roles it names.
