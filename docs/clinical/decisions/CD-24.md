# CD-24 — Generic RED escalation copy (base.generic_red.remote / on_site / unknown)

Machine-readable record: `packages/protocols/decisions/CD-24.yaml`. Status: **active** for the three scripts, the UNKNOWN verdict, the numeral form, and the register policy for ALERT, CALM and DEFERRED_CLINICIAN. **draft_needs_source** for the SILENT copy, the register when the fired rules declare different registers, the wait before an unanswered location question resolves, and any generic driving, accompaniment or nil-by-mouth do-not.

Scope: simulated-patient stress testing only (owner decision D18, 2 Oct 2026). A licensed physician's review is required before any real patient.

## Question

When a RED fires but its own pre-positioned script cannot be addressed (more than one rule fired with none named, or the pack holds no script for the named RED at that location), what does the device show and say under REMOTE, ON_SITE and UNKNOWN? The copy must be correct for any adult RED of either EK-4 KIRMIZI category and may not name a condition. Under UNKNOWN, is 112 shown before the location question or only after it? And which register delivers the generic: always ALERT, or the engine result's own register?

Origin: INT-453 (PR #773). `talker/red_path.py` publishes a generic `red_trigger` (register ALERT, scriptId `base.generic_red.{remote,on_site,unknown}`); the device catalog entry for that scriptId had no copy.

## Decision

The copy states the action and the service, never the patient's condition, so it holds for any KIRMIZI rule whichever register delivers it.

### Register policy: carry the engine result's register

The generic `red_trigger` carries the register of the engine result that produced it. It is never fixed at ALERT. An always-ALERT generic (`GENERIC_RED_REGISTER = ALERT`) is a default register chosen once by an engineer, which CLAUDE.md invariant 21 forbids ("required fields with no permitted default"). It would also deliver ALERT for rules whose own register the base.life_threat schema refuses as ALERT: distress_sensitive rules, subject_is_child rules and the consent-independent crisis path. Files/02 §5.3: "register decides *how* the patient is told, location decides *what they are told to do*". So the scripts below are the content under every register that reaches the device.

| engine register | what the device does | status |
|---|---|---|
| ALERT | The scripts below, with a red header and full-screen takeover; the primary action is 112 under REMOTE and the named acil servis under ON_SITE; spoken with urgent prosody and an alert sound. | active |
| CALM | The same scripts, unchanged, with no red and no alarm colour, action first, the do-not list shown, spoken softly, no alert sound. No attention-grabbing interrupt runs (files/04 §8.1 rule 6). The 112 call stays the REMOTE action, as in the files/02 worked CALM text. | active |
| SILENT | What a SILENT generic should say stays pending. Meanwhile it shows the same generic text for the resolved location (and, under UNKNOWN, the location question) in the flow of the session, with no headline, no colour change, no takeover and no audio ever. A SILENT generic is never left without words. Delivery floor: intake stops when the generic fires, so no further question is asked or spoken (as `REGISTER_DELIVERY` `stops_intake` does in `red_path.py` for every device-triggering register), and the guidance is the last thing in the flow. When SILENT is chosen over a co-fired ALERT or CALM rule, the clinic notification states that a time-critical RED was delivered silently. | draft_needs_source |
| DEFERRED_CLINICIAN | Never triggers the device; the finding routes to the clinician only. | active |
| several rules fired, different registers | The final rule stays pending. Meanwhile the device uses the most restrictive register among the fired device-triggering rules: SILENT over CALM over ALERT. DEFERRED_CLINICIAN members are not counted, and ALERT is never used when any fired rule is CALM or SILENT. When all fired rules declare the same register, that register is carried. Delivery floor: intake stops when the generic fires, so no further question is asked or spoken (as `REGISTER_DELIVERY` `stops_intake` does in `red_path.py` for every device-triggering register), and the guidance is the last thing in the flow. When SILENT is chosen over a co-fired ALERT or CALM rule, the clinic notification states that a time-critical RED was delivered silently. | draft_needs_source |

Suppressing the interrupt for every CALM generic is this author's reading of rule 6. The generic cannot tell a distress_sensitive CALM rule from another CALM rule, and suppression is the only choice that never breaks rule 6. The SILENT-over-CALM-over-ALERT ordering is also this author's: it is chosen so that no rule gets a register its own declaration refuses. A generic also cannot supply the condition-specific do-nots that a distress_sensitive or paediatric rule carries. Those belong to the rule's own script, which the compiler requires for all three locations.

### Verdict on UNKNOWN: ask first

The location question is shown and spoken first, with no 112 affordance on screen. The REMOTE script, including the 112 affordance, appears only after "hayır" or no answer; the ON_SITE script appears after "evet". Showing 112 before the answer would resolve UNKNOWN by guessing REMOTE, which can send a patient who is already in the hospital out of it. Files/02 §5.3 ("Never guess") and files/04 §8.1 rule 7 ("never resolved by guessing") both forbid that. The cost is one question.

### How each sentence is supported

- **"Hemen 112 Acil Çağrı Merkezi'ni arayın."** The 2024 amendment of the Tebliğ names the 112 acil çağrı merkezi as the place where emergency health calls are answered and ambulances dispatched. Files/04 §4.1 fixes 112 as the national emergency number. `docs/legal/strings.yaml` does not exist in this repository (finding G3).
- **"Randevuyu beklemeyin." / "Poliklinik sırasında beklemeyin."** EK-4 takes KIRMIZI Kategori 1 in "hiç bekletilmeden" and gives Kategori 2 a ten-minute target, so waiting for a booked slot contradicts both. Files/02 §5.3 calls "Randevunuzu beklemeyin" the sentence that changes behaviour. The wording drops the possessive so it also reads correctly in a proxy session.
- **"112 ambulansıyla getirilen hastalar, acil serviste ayrıca öncelik sırası için bekletilmez."** Tebliğ MADDE 8(5): patients brought by a 112 ambulance get no separate triage. "Öncelik sırası" renders triyaj through the Tebliğ's own definition in MADDE 4(1)(p) (determining medical priority), so no jargon is left unexplained, and "ayrıca … bekletilmez" states what that means for the patient.
- **"Tek başınıza gitmeyin; bir görevliden yardım isteyin."** (ON_SITE) Tebliğ MADDE 8(3): a walk-in patient judged to be in danger of life is taken to the area escorted by health personnel ("sağlık personeli eşliğinde"). This is a service fact that holds for any KIRMIZI condition, including collapse on the way, and `notify_staff_immediate` already summons staff.
- **"Acil serviste hastaların önceliği girişte belirlenir ve en öncelikli hastalar bekletilmeden içeri alınır."** MADDE 8(3) (registration and triage together at the entrance) and EK-4 Kategori 1 ("hiç bekletilmeden").
- **"Verilen cevaplara göre beklemeden değerlendirme gerekiyor."** This is the KIRMIZI outcome stated as a need for assessment without waiting (EK-4 Kategori 1 and 2). It is not a statement about the patient's condition. Files/02 §5.3 says statements about the service are safe in every register.
- **"Görevlilere haber verildi."** Under ON_SITE the staff notification fires automatically with the alert (files/02 §5.3).
- **The 112 numeral.** Written as a bare token followed by a space, so the compiler expands it to "yüz on iki" for speech while the screen keeps the digits (invariant 22).

### Not generalised (REMOTE)

The chest-pain exemplars carry three more do-nots: "Kendi aracınızla yola çıkmayın", "Tek başınıza kalmayın" and "Bir şey yiyip içmeyin". None is carried into the generic REMOTE script. Outside the hospital, the only retrieved source on transport and accompaniment is NICE NG232 1.2.6–1.2.7, which is specific to head injury and allows being driven in a car when accompanied. No retrieved source states any of the three for every KIRMIZI condition outside the hospital. On site, accompaniment is sourced (MADDE 8(3)) and is in the ON_SITE script.

### Findings

- **G1.** Exemplar 1's REMOTE action_tr `Hemen **112**'yi arayın.` is refused by `expand_tr`, which raises `TrExpansionError` on the token `**112**'yi` and also on `112'yi`. So that line cannot be compiled into a spoken clip. The generic avoids the form; the exemplar is not changed here.
- **G2.** INT-453's `red_path.py` publishes the generic `red_trigger` with a fixed register (`GENERIC_RED_REGISTER = ALERT`) whichever rules fired. The base.life_threat schema refuses ALERT for a distress_sensitive rule, a subject_is_child rule and the consent-independent crisis path. CD-24 decides that the generic carries the engine result's register, so the constant should be removed.
- **G3.** `docs/legal/strings.yaml`, which files/04 §4.1 names as the home of crisis numbers, does not exist. The 112 number here rests on the files/04 §4.1 table and the Tebliğ text.
- **G4.** Most-restrictive-wins can under-alert an ALERT-worthy RED in a voice-led session: when an ALERT rule co-fires with a CALM or SILENT rule, the time-critical action is delivered softly or silently. The delivery floor (intake stops, the guidance is last in the flow, and the clinic notification states a silent delivery) limits this but does not remove it. The mixed-register value is a physician decision before any real patient.

## Near-miss tests that pin it

- `generic_red_on_site_has_no_112_anywhere` — positive: the ON_SITE entry has `show112: false`, `primary: GO_TO_IN_HOUSE_ACIL` and `notify_staff_immediate: true`. Near-miss negative: an ON_SITE entry whose action_tr, do_nots_tr, why_tr or action code contains "112" is refused.
- `generic_red_unknown_asks_before_112` — positive: under UNKNOWN the first thing on screen is "Şu anda hastanede misiniz?" with no 112 affordance, and "hayır" then shows the REMOTE script with 112. Near-miss negative: an UNKNOWN render that shows the 112 affordance before the answer fails.
- `generic_red_unknown_no_answer_goes_remote` — positive: no answer resolves to the REMOTE script. Near-miss negative: no answer never resolves to ON_SITE and never leaves the screen without an action.
- `generic_red_copy_names_no_condition` — positive: no generic string contains a condition or organ word (for example "kalp", "inme", "kanama"). Near-miss negative: the chest-pain exemplar's why_tr ("kalple ilgili olabilir") would fail the same check.
- `generic_red_strings_expand_for_tts` — positive: every generic string passes `expand_tr`, and "112" becomes "yüz on iki". Near-miss negative: the exemplar form "**112**'yi" raises `TrExpansionError`.
- `generic_red_carries_the_engine_register` — positive: a single CALM result with no addressable script gets the generic copy in CALM (no alarm colour, soft speech, no alert sound, no interrupt). Near-miss negative: the same result never arrives as ALERT.
- `generic_red_mixed_registers_take_the_most_restrictive` — positive: two fired REDs, one ALERT and one CALM, deliver CALM; one ALERT and one SILENT deliver SILENT. Near-miss negative: two ALERT REDs deliver ALERT, not a quieter register.
- `generic_red_silent_is_never_wordless` — positive: a SILENT generic shows the action text in the flow with no audio. Near-miss negative: a SILENT generic that renders no text, or plays any audio, fails.
- `generic_red_stops_intake` — positive: after any device-triggering generic (ALERT, CALM or SILENT) no further intake question is asked or spoken, so the guidance is the last item in the flow. Near-miss negative: a generic followed by another protocol question fails.
- `silent_over_alert_is_stated_to_the_clinic` — positive: an ALERT rule co-fired with a SILENT rule delivers SILENT, and the clinic notification states that a time-critical RED was delivered silently. Near-miss negative: a lone SILENT RED adds no such statement.
- `generic_red_on_site_asks_for_an_escort` — positive: the ON_SITE do-nots include "Tek başınıza gitmeyin; bir görevliden yardım isteyin." Near-miss negative: the REMOTE script carries no accompaniment or driving do-not while that stays pending.

## What stays draft_needs_source and why

- **The SILENT copy.** Files/02 §5.3 defines how SILENT is presented. No retrieved source states what a safeguarding, crisis or third-party-present RED should say when its own script is unknown, and the crisis path itself is blocked on the files/04 §4.2 escalation policy (HB-C8). Meanwhile the generic text is shown in the flow with no audio, never nothing, and the clinic notification fires.
- **The register for a fired set with different registers.** No source says how to combine registers in one delivery, and most-restrictive-wins can under-alert an ALERT-worthy RED (G4). Meanwhile the most restrictive register present is used (SILENT over CALM over ALERT), and ALERT is never used when any fired rule is CALM or SILENT. Intake stops, and a silent delivery over an ALERT or CALM rule is stated in the clinic notification. This is a physician decision before any real patient.
- **The wait before an unanswered location question resolves to REMOTE.** The sources fix the branch but state no wait. EK-4's ten-minute figure is a treatment target, not a question timeout. Whatever wait the device uses is an unsigned engineering value, and on expiry the branch is always REMOTE.
- **Generic driving, accompaniment or nil-by-mouth do-nots for REMOTE.** These stay out of the REMOTE script until a source states them for every KIRMIZI condition outside the hospital. On-site accompaniment is not pending: it is sourced and adopted.
