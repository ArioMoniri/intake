# Evidence: INT-560 · the operability registry page tells the truth

GitHub #948, owner request of 17 Oct 2026 ("solve these"). **Sec-Row:** `monitoring-contract`
(files/10 §9; `docs/security/threat-model.md` § `monitoring-contract`).
**Branch:** `int-560-registry-truth`, from `origin/main` at `ab9b8819`.

## 1. The defect

On the synthetic AWS host, the admin console's registry tile (`/ops`, "Model sunucuları ve
kayıt") was wrong in three ways:

- **Yoklama durumu read `no_result` on every row.** Nothing probed that host. The compose file ran
  no probes service, and the API was never given `INTAKE_PROBE_RESULTS_PATH`, so
  `load_probe_sweep()` returned `probe_results_unconfigured` and every row's result was empty.
- **Önem read "blocking" on rows the host does not run.** The column was INT-183's registry-wide
  INT-022 verdict. It blocks every enabled PHI-path row without a healthy fallback, on any host.
  So `hapi`, `qwen3.5-9b`, `whisper-tr-medical`, `freya-tts` and `voxcpm2-tts` were red on a host
  that has none of them. `postgres`, `minio` and `openbao` were red for a missing `backups`
  fallback, which is a PHI-release fact and says nothing about whether this host works.
- **Şu an kendi sunucumuzda read "evet" for anything self-hosted anywhere.** The column printed
  the registry's single `self_hosted_now` flag. The team GPU server's models are reached from the
  laptop over SSH tunnels and never from AWS, yet they read "evet".

## 2. The change

### The host inventory (`infra/staging/inventory.yaml`, `intake_probes.inventory`)

- A recorded inventory of the synthetic host. It lists every compose service, the registry
  components each one carries, whether the deployed stack **needs** it (and a coded reason when
  not), and the internal compose name the probe dials.
- The loader refuses the file, with a code and nothing from the file, in these cases:
  - its services are not exactly `compose.yaml`'s;
  - a component is not a registry row, or is placed on two services;
  - a probe address carries a credential, names no compose service, or is a probe the host
    cannot run (`backup_freshness`, `livekit_room_join`, `runner_heartbeat`);
  - a service is needed and also has a reason not to be.
- It is honoured only by a process whose baked data class is `synthetic`
  (`intake_platform.model_lanes.guard.deployment_data_class`). The relaxed, host-scoped reading
  therefore cannot reach a PHI deployment.
- **Needed:** `api`, `postgres`, `redis`, `openbao`, `minio`, `keycloak`, `oauth2-proxy`,
  `admin-web`, `caddy` and `edge-tls`. That is the owner's list plus the console's two links and the
  certificate Caddy serves. A test holds that every service a needed service waits on
  `service_healthy` is itself needed.
- **Not needed:** `egress-proxy` (`fails_closed_without_it`), `sms-egress` (`fails_closed_without_it`;
  ADR-042's SMS proxy, on main since #905 — the OTP send answers 503 without it and nothing else
  calls it) and `probes` (`observes_only`).

### The host sweep (`intake_probes.host_sweep`, wired into `intake_probes.app`)

- **Every registry row gets a result every sweep:**
  - a component the host runs is probed at its compose name, with the registry row's own probe id;
  - a component the host does not run is `skipped` with `not deployed on synthetic-aws`;
  - each boundary proxy (`egress-proxy` on `outbound`/`vendor`, `sms-egress` on `sms-out`/`sms-wan`)
    is `skipped` with `deployed on synthetic-aws; not probed: outside_probe_networks`.
- **Credentials are the probe's own and minimal.** Postgres is probed as `svc_probe` (LOGIN and
  CONNECT on `intake`, no table grant). Redis is probed as `intake-probe`, which may run PING and
  nothing else. The passwords arrive by environment variable, never from the committed file. A
  missing one is a `skipped` that names the variable, never a `healthy`.
- `fetch_tls_not_after` gains `server_name=`. The edge certificate is read from `caddy:443` with
  SNI set to the host's public name.
- **No PHI or secret leaves a sweep (invariant 6).** `scrub_detail` masks TCKN, phone and IBAN
  (`redact_text`), every email and every credential inside a URL, and caps the length.
- **The results file is replaced atomically** (write beside it, then rename).
- **Two series go live**, `probe_status{component}` and `probe_latency_ms{component}`. Both were
  catalogued as planned (files/08 §4) and are now `status: live` (invariant 13). A skipped
  component has no `probe_status` series.
- **The probes app** gains the shared `setup_otel` and JSON logging, which it lacked
  (invariant 15). It runs the sweep loop off the event loop when both env variables are set. An
  inventory it cannot load starts no sweep and fails `/readyz` (`host_inventory`), while `/healthz`
  stays 200, so a probes fault never fails a deploy.

### The console (`intake_probes.standing`, `ops_console._models_tile`)

Each row gains:

- `deployment`: `this_host`, `elsewhere`, `not_deployed` or `undeclared`;
- `needed` and `not_needed_reason`;
- `probe_checked_at`, `probe_age_s` and `probe_stale` (past `STALE_AFTER_S` = three sweeps, or of
  unknown age);
- `severity_reason`.

The tile gains `host` and `host_reason`. With an inventory, the columns derive as follows:

- **blocking** only when the stack needs the row and its probe is not currently healthy;
- everything else is advisory, with its reason;
- the INT-022 verdict on a row becomes the advisory `phi_release_gate`.

The tile's release badge is still INT-022's registry-wide verdict, now labelled as such. Without
an inventory the INT-183 reading stands unchanged (the strict direction), and the page says there
is no inventory.

### The page (`apps/admin-web/src/ops`)

- The **Şu an kendi sunucumuzda** column reads `evet`, `bu sunucuda değil (başka bir
  sunucumuzda)`, `hayır (hiçbir yerde kurulu değil)` or `bilinmiyor (sunucu envanteri yok)`.
- **Yoklama durumu** shows the status word and its age (`0 sn önce`), and `eski sonuç` when the
  result is stale.
- **Lisans doğrulandı** shows the date, or `doğrulanmadı`. Before this change it showed "yok".
- **Önem** shows `sorun yok`, `uyarı` or `engelleyici`, with the reason underneath.
- `renderOps` refuses a tile that claims what it cannot know (`OpsRegistryUntrue`):
  - a healthy status with no observation;
  - a `no_result` that carries an age;
  - a result of unknown age shown as current;
  - a host word without an inventory;
  - `needed` set on a row the host does not run;
  - a blocking row that the host does not run, does not need, or whose probe is currently healthy.
- The `Age` formatter moved to `ops/guards.ts`, shared with the overview, which re-exports it.

### The synthetic host (`infra/staging`)

- `compose.yaml` gains the `probes` service:
  - it runs the api image (one SBOM), with the probes app as its command;
  - it joins `backend` and `edge` only, so it has no route off the host and no leg on `outbound`;
  - it publishes no port, runs read-only and drops every capability;
  - its credentials come from host secrets.
- The `probe-results` volume is written by `probes` and mounted read-only by `api`. The api is
  given `INTAKE_PROBE_RESULTS_PATH` and `INTAKE_HOST_INVENTORY_PATH`.
- The redis config gains the `intake-probe` ACL user (PING only). Its password reaches
  redis-server on stdin, like `requirepass`.
- `Dockerfile.api` creates `/var/lib/intake/probe-results` for the service user, so the fresh
  named volume takes that ownership.
- `staging.env.template` gains `PG_PROBE_PASSWORD` and `REDIS_PROBE_PASSWORD`.
- In `lib.sh`, `ensure_probe_secrets` fills exactly those two when absent. `deploy.sh` runs it
  before `load_env`, so a host initialised before INT-560 needs no `init.sh` re-run.
  `ensure_probe_role` creates `svc_probe` after the migrations, with its SQL on stdin and
  statement logging off.
- `docs/runbooks/staging.md` gains "Probes and the registry page".

### The registry

- `probes` → `self_hosted_now: true`, with host prose naming the compose service. It is not on
  the PHI path, so the INT-022 set is unchanged.
- **New rows**: `keycloak`, `oauth2-proxy`, `admin-web` and `caddy`. Each runs on the synthetic
  host only, has `phi_path: false` with the reason in the file, and has a licence that reads
  `UNVERIFIED — …; INT-561's to record`. No licence data was otherwise touched; licences are
  INT-561 (#949), which was told the four new component names.

### Fixtures

- `tests/fixtures/ops/host_sweep.json` is the host sweep, re-taken by
  `scripts/dev/record_ops_fixture.py --sweep`. It runs the shipped wiring on the recording machine
  with every dial refused rather than sent, so no compose name is resolved on the laptop's
  network.
- `ops.payload.json` is built over the inventory, that sweep and the recorded Prometheus answers,
  dated at the sweep's last probe.
- `tests/fixtures/reliability/probe_sweep.json` was re-taken with
  `record_reliability_fixture.py --sweep`, as INT-528 does, because the registry gained rows that
  the old sweep never saw. The overview's pinned postgres latency moved from 74 to 302 ms with the
  re-take, and to 156 ms with the re-take on the refresh onto main (§9).
- `models.payload.json` and the `reliability.*` payloads were re-recorded.

## 8. Not proven here, and for the owner

- **Nothing was deployed from this branch.** The merge queue deploys. The first deploy after
  the merge:
  - fills `PG_PROBE_PASSWORD` and `REDIS_PROBE_PASSWORD` (deploy.sh `ensure_probe_secrets`);
  - recreates redis once to load the `intake-probe` ACL line (AOF keeps its data);
  - creates `svc_probe` after the migrations.
- The redis `user` line and the Keycloak management port's reachability from another container
  are validated statically only: no container runtime runs here.
  - If redis refused the line, `compose up` would stop at redis and nothing else would restart.
  - If the management port were bound to loopback, the keycloak row would read unhealthy and
    blocking, which is the honest reading of a probe that cannot reach it.
- The registry's own `self_hosted_now` for `api`, `edge-tls` and `egress-proxy` still says
  `false` although all three run on the synthetic host. The page no longer reads that flag for
  "on this host", so nothing here is wrong on the page. Flipping them would add api and edge-tls
  to the INT-022 blocked set, which `tests/observability/test_release_gate.py` pins, so that is
  left as a separate, conscious change.
- `/admin/models` (INT-183, no page renders it) and the overview's dependency tile (INT-181) keep
  their registry-wide reading. Both now see live results on the host, because the API reads the
  sweep.
