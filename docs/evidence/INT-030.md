## What the tests pin

- **Tenant A cannot read tenant B even with SQL** (acceptance verbatim):
  as `app_rw` with `app.tenant_id = A`, every visible row on
  patients/notes/consents is A's; `SELECT … WHERE tenant_id = B` and
  `WHERE id = <B's row>` return zero rows — the policy, not the
  application's WHERE clause, is the boundary. Mirror-checked under B.
- **Fail closed**: with no tenant GUC set, `NULLIF(current_setting(
  'app.tenant_id', true), '')::uuid` reads NULL and every tenant table
  returns zero rows. Cross-tenant INSERT is rejected by `WITH CHECK` (42501).
- **FORCE ROW LEVEL SECURITY** is asserted from pg_class
  (`relrowsecurity AND relforcerowsecurity`) on all eight tenant-scoped
  tables plus tenants — the owner bypass is off. (The dev owner is the
  bootstrap superuser, which Postgres always exempts; production runs a
  non-superuser owner, which is whom FORCE exists for.)
- **RLS by role, not only tenant**: `clinician_ro` reads
  patients/sessions/slots/notes/documents inside its tenant via a separate
  `FOR SELECT` policy, cannot INSERT, and has no grant at all on consents.
- **INSERT-only audit chain**: `svc_audit_writer` appends through
  `SqlAlchemyAuditStore` + `AuditChain` (live chain verifies against the
  running head), then UPDATE and DELETE both raise InsufficientPrivilege for
  the writer itself; `app_rw` can run the daily verifier's SELECT but cannot
  INSERT/DELETE. UPDATE/DELETE on audit_chain is granted to no principal
  anywhere (files/10 §2, the grant half of invariant 40). events are
  append-only for `app_rw` the same way.
- **pgaudit, honestly**: the migration probes `pg_available_extensions` —
  installs and configures (`pgaudit.log = 'write, ddl, role'`) where the
  server offers the extension, logs a loud warning where it does not (the
  dev image pgvector/pg16 ships without it, and it needs
  shared_preload_libraries at boot, which no migration can add). The
  integration test asserts installed == available, so "pgaudit on" can never
  be silently assumed.
- **Pseudonymised patients** (unit): the patients table is exactly
  {id, tenant_id, pseudonym, created_at}; a forbidden-name scan over the
  whole metadata (name/phone/tckn/address/… incl. Turkish variants) proves no
  raw-identifier column exists in any app table — composing with INT-013's
  vault-only design and its existing SQL grep gate.
- **Envelope columns compose with INT-014**: notes.payload (always) and
  slots.value (when `sensitivity = sensitive`) carry EncryptedField JSON;
  the helpers roundtrip losslessly through the real `EnvelopeCipher`, reject
  malformed payloads with ValueError instead of coercing, and the RLS seed
  itself stores a genuine envelope. No LargeBinary column exists anywhere;
  documents carry object_ref + sha256 + provenance, never bytes.
- **Invariant 18**: every column of every table carries the complete
  {category, purpose, basis, retention, recipients} annotation
  (`Column.info`), enforced by tests/data/test_inventory.py; retention
  strings quote the files/06 §3 matrix, and the `inv()` helper refuses an
  empty field at write time.
- **Static DDL gate** (unit, no docker): the migration source must contain,
  literally, ENABLE + FORCE + `<table>_tenant_isolation` (with WITH CHECK)
  for all eight tenant tables, the clinician read policies, the three roles,
  the exact audit_chain/events grant lines with no UPDATE/DELETE token on
  them, and the guarded pgaudit probe — so a future edit that drops a policy
  fails in the unit lane before it ever reaches a database.
