## What shipped

- **`ClamAvScanner`** (`intake_platform/uploads.py`): our own ~80-line typed
  client over clamd's INSTREAM wire protocol (TCP or unix socket) instead of
  pyclamd — the protocol is three frames, pyclamd is unmaintained and
  untyped. Config from `INTAKE_CLAMD_HOST`/`INTAKE_CLAMD_PORT`/
  `INTAKE_CLAMD_UNIX_SOCKET`/`INTAKE_CLAMD_TIMEOUT_SECONDS`; **no default
  endpoint exists** — unconfigured refuses at construction, and unreachable/
  timeout/ERROR/garbage replies are `ScanFailedError`, never a verdict: the
  document stays quarantined and the worker retries (test-pinned).
- **Sniffing + limits before the scan**: magic-byte sniffing for
  `application/pdf`, `image/jpeg`, `image/png` (promotable — the store
  allow-list is the single source of truth) plus `image/heic` and
  `application/dicom` (sniffed for precise refusals, unpromotable until
  their sandboxed parsers land). Claimed types and bare extensions normalise
  to canonical MIME. Size cap defaults to the store's 20 MiB
  (`MAX_DOCUMENT_BYTES`) so both ingestion paths agree, env-overridable via
  `INTAKE_UPLOAD_MAX_BYTES`; the check runs on a HEAD before any byte is
  fetched and is re-checked after the read (presigned-PUT replay growth).
- **Promotion worker**: `UploadPipeline.process` /
  `process_quarantined_document` — state-check → limit → claimed-type →
  sniff → mismatch → scan → promote via the documents.py path
  (`release_quarantined` rewrites the object under `clean/` with the
  canonical content type; `reject_quarantined` moves to `rejected/`, or
  `infected/` for malware). Idempotent: re-running on an already-promoted or
  rejected object is a no-op (test-pinned, unit + real MinIO). Every
  rejection audits `document.rejected.<reason-code>` — reason codes only,
  never content (invariant 6). `services/workers` does not exist on main, so
  the Celery wrapper is deferred to the workers issue; the plain callable is
  its exact wrapping surface.
- **OCR seam, not engine**: `OcrExtractor` protocol + fail-closed `NoOcr`
  default that parses nothing and marks every promoted document
  `ocr_pending`. Engine + sandbox selection (files/10 §4: seccomp-isolated
  parsing) is an **open ADR** — deliberately not picked here. The
  "malformed/fuzz PDFs never crash host" acceptance holds structurally in
  this process: sniffing reads magic bytes only, and no parser ever touches
  untrusted bytes until the sandboxed engine lands (fuzz suite pins it).
- **Signals** (files/10 §9 records): `document_upload_pipeline_total`
  counter by `{outcome, reason}` — catalogued in
  `observability/metrics_catalog.yaml` (invariant 13), enumerated labels
  only.
- **Dev tier**: `clamav/clamav:1.4.6` in infra/docker-compose.dev.yml behind
  the `clamav` profile (image carries the signature DB; freshclam disabled
  in dev/CI), loopback port 3310; `make check-integration` activates the
  profile and keeps postgres/openbao/minio intact.
