# INT-134 — Visits: create (manual + MHRS SMS), branch picker from taxonomy, visit types

Issue: `docs/backlog/issues.yaml` INT-134 (P0, E08-mobile).
Acceptance, verbatim: *"branch list from taxonomy; unknown branch -> cluster with notice; OCR path behind documents consent"*.
Depends on INT-130 (mobile shell) and INT-042 (branch taxonomy) — both merged.

## What the acceptance asked for, and what shipped

**SMS text parse, not image OCR.** The issue *title* says "MHRS SMS OCR"; the
*acceptance* — the source of truth — says only "OCR path behind documents
consent" and never requires an image reader. files/02 §3 lists "Add visit
(manual; screenshot OCR of MHRS/hospital SMS)" as the P1 feature. The two
legs were therefore separated:

- **The SMS text paste-parse shipped in full.** `parseMhrsSms` is a pure
  TS function: the patient pastes the MHRS message body, it yields
  {date, time, hospital, branch} against the taxonomy. Real-shaped
  synthetic fixtures, no real PHI.
- **The image-OCR leg is wired and fail-closed, not faked.** files/03
  §4.9.2(f) is a hard gate: OCR rows 20–21 are *"the one layer in this stack
  where NOTHING has been licence-verified"* and *"no OCR component reaches
  the PHI path without a `licence_verified_at` entry read from the raw
  LICENSE blob"* (invariant 19 requires the same). So `ocrImportAvailable`
  is `documents consent AND OCR_ENGINE_LICENCE_VERIFIED`, and the second
  term is honestly `false`. The consent half of the acceptance is live and
  tested; the engine half stays closed until the licence is verified. The
  adjacent open ask is **HB-A1** (the e-Nabız text-layer / OCR fork). No
  mock reader, no fabricated extraction (invariant 17).

## Taxonomy feed design

`GET /v1/taxonomy/branches` serves a projection of
`packages/protocols/taxonomy/branches.yaml` — 9 clusters, 92 branches,
`name_tr` verbatim (invariant 5: the taxonomy's own tr names *are* the
labels; the app holds no competing copy). Loading and cross-checking reuse
`protocols.taxonomy` (INT-042) rather than re-implementing it.

- **Versioned:** `version` is the sha256 of the served file's bytes, so a
  client caches last-good and detects change without diffing 92 rows.
- **Consent declaration, decided not defaulted:** the route reads no patient
  data — it projects a committed artefact — so demanding a clinical consent
  scope would over-claim, and would also block the picker before the patient
  has granted anything. A third scan marker, `reference_data`, was added
  alongside `pre_auth` and `consent_management`, **caged to `/v1/taxonomy`**
  by the same segment-boundary rule, so no data route elsewhere can borrow
  it. `unguarded_data_routes` remains the authority and still returns `[]`.
  Authentication is unchanged (401 without a principal). Reads are **not**
  audited: invariant 4 audits reads and shares of clinical data, and a
  branch list contains none.
- **Fails closed:** an absent or invalid taxonomy answers `503
  taxonomy_unconfigured`. An empty branch list would tell the patient their
  hospital has no clinics, so it is refused on both sides (the client's
  `parseTaxonomyFeed` rejects `branches: []` as an outage, not a taxonomy).
- **Never empty on the device:** server feed → cached last-good → the
  bundled seed, which is generated from the same YAML and pinned to it
  field-for-field by `branches.test.ts`.

## Data handling

- **The raw SMS is never persisted.** It is parsed on the device and the
  reducer clears it in the same action (`apply_sms` sets `sms: ""`); only the
  structured fields reach `NewVisitInput`. It is never written to disk, never
  uploaded and never logged, so it carries **no inventory annotation because
  it is never stored** (invariant 18 applies to persisted fields).
- **No new tables or columns** (invariant 18): `visit.branch` and
  `visit.visit_type` are rows in the already-inventoried `slots` table
  (INT-030), written only when known. A pre-INT-134 visit simply lacks them
  and reads back as `None`.
- **The date became optional** (02 §2b): a patient adding a visit they have
  not booked yet gets a visit with no date, never an invented one — the
  reminders, the Doctor Link expiry and the note-staleness clock all key off
  that field. A dateless visit sorts as *upcoming*.
- No PHI in logs: the taxonomy-load failure logs the path and the exception
  class only (a committed artefact, and the exception text is dropped anyway).

## One gate defect found and corrected

`apps/mobile/e2e/nav.spec.ts` carried a filler-token guard with a
case-insensitive flag, while the authority — `scripts/ci/no_placeholders.sh`
— matches case-**sensitively**. Adding the real taxonomy surfaced the
consequence: **"Ortodonti"**, a Turkish dental branch from files/09 §1,
contains the letters of the lowercased marker token and tripped the spec.
The spec was aligned to the canonical gate (uppercase markers matched
case-sensitively, prose tokens still case-insensitively) rather than either
gate being weakened; the canonical gate's own pattern and allow-list are
untouched. This is why `branches.yaml` itself has always passed CI on main.
