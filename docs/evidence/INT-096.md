## What was built

`services/voice-runtime/src/intake_voice_runtime/typed/` (new package, 243 statements,
**100 %** statement coverage) plus one extracted helper.

- **`typed/session.py` — `TypedSession`.** Layer A without a microphone. It takes the same
  `EngineSnapshotSource`, `WorkSubmitter`, `PatientMemoryStore` and `Clock` the Talker
  takes, and **none** of `ClipStore`, `SpeechSynthesizer` or `AudioSink`. There is no
  scheduler, no `accept_result`, no `preempts` and no playback to cancel. Invariant 3 is
  therefore a property of the typed path's *type*: there is no buffer to zero because
  there is no buffer.
- **`typed/affordance.py` — the invariant-22 gate.** `NUMERIC_SLOT_TYPES` is
  `{integer, decimal, duration, quantity}`; a numeric slot with no authored `choices_tr`
  has **no typed affordance** and `SlotFacts.affordance()` raises
  `FreeNumericEntryRefused`. There is deliberately no fallback text field, no
  "numbers only" input and no parser, because the failure mode is not malformed input —
  it is well-formed input that means something else (`parseFloat("1.500") → 1.5`,
  files/00 §2). `free_numeric_critical_path_steps(protocol)` is the pack gate at the
  invariant's own boundary (`must_ask or required`).
- **`typed/render.py` — the displayed prompt.** `text_tr` byte for byte (invariant 10 does
  not weaken when the channel stops being audio), and `render_measure` /`numeric_rail` for
  quantities: `useGrouping:false` and number + unit joined by U+00A0, one
  non-breaking atom.
  The rendering is `intake_platform.llm.units.render_quantity`, **reused rather than
  re-derived** — a second implementation of "how a clinical quantity is written" is exactly
  how the two drift and one of them starts printing `1.500`.
- **`typed/switch.py` — the kill switch.** `LaneSwitchReason` has the three routes the
  blueprint names and no more: `operator_kill_switch` (files/02 §375, a files/08 §8.2 T1
  safe-direction action taken by one actor), `unreliable_audio` (files/03 §4.5b T3) and
  `abort_voice` (T9). It is a **latch**: a second `to_typed` returns the first record, a
  session that started typed raises, and there is no `to_voice` at all. It **holds no
  engine reference**, which is the whole safety argument — a flip cannot lose a bound slot
  value because there is nothing here for one to be lost from (T3: *"keep the session and
  every slot"*).
- **`typed/lanes.py`.** `lanes_without_input(TYPED) == {affect, acoustic, asr_quality}` —
  the three lanes whose input files/03 §4.7.5 states as audio frames or an ASR confidence.
  Named for what it proves; it is not a lane-availability policy (see "Findings").
- **`utterance.py` (new, at the package root).** `submit_extraction` — the request shape
  and the derived-`work_id` check of files/12 §7.5, extracted from `TalkerSession` so both
  lanes feed one queue through one copy of that check. `TalkerSession.submit_utterance` now
  calls it; behaviour is unchanged and `tests/voice/test_talker_session.py` is untouched
  and green.

Nothing else in `services/voice-runtime/` changed, and nothing outside it changed.

## The kill switch

`switch_after=N` in the harness flips the lane mid-session, at three different points, on
the same shared engine.

- The switched run reaches **exactly** the all-typed run's values, states, coverage,
  `data_gaps` and triage — at every flip point tested.
- Speech stops at the flip: one played step, then prompts for the remainder.
- The record carries the reason, the two profiles, `modality_degraded` and a session-clock
  timestamp — ids and closed enumerations only, no session id, no free text.
- It is one way. `to_voice` does not exist, a second `to_typed` returns the first record,
  and a session that started typed raises `LaneSwitchLatched`. files/03 §4.5b's anti-flap
  rule is written for the degradation ladder and states no hysteresis for returning a
  *session* to voice; inventing one would be an engineering decision standing in for a
  clinical one.
- No seventh tool. `RepeatReason.TYPED_SWITCH` already exists on
  `request_repeat_or_clarify` (files/03 §4.2, §4.5b T3), so the in-band signal is on the
  surface invariant 9 froze.

## The parity simulator run

`tests/voice/typed_harness.py` drives a real `TypedSession` and a real `TalkerSession`
over **one** shared `IntakeEngine`, the real `protocols.triage.evaluate_triage`, and a
protocol resolved through the production compiler from the committed fixture tree
`tests/fixtures/protocols/compile/tree` — the same tree `tests/voice/conftest.py` already
builds the clip-cache bundle from. No LLM, no model, no network, no room, no wall clock.
The whole run happens inside `record_disk_writes`, which watches `builtins.open`,
`io.open` and `os.open`, so "raw audio is never written to disk" is a **measurement of the
run**; `test_the_disk_probe_can_actually_see_a_write` proves the probe is not blind.

**`tests/sim` was read and not edited.** Its driver already runs both profiles, but its
`typed` lane is *the absence of a Talker* — it proves the engine is channel-neutral and
says nothing about the typed lane's own surface (the displayed prompt, the affordance, the
switch), and the mid-session flip cannot be expressed there at all. This harness is
additive, not a replacement.

Two mechanical mutations are applied to the fixture in `parity_protocol()`, both documented
at the call site, neither touching clinical semantics:

1. `ziyaret.sure_dakika` (a required `quantity` slot) is given two discrete answer labels,
   which is what turns a free numeric field into the chip set files/00 §2 requires. The
   labels are synthetic fixture tokens in the same register as the rest of the tree.
   **The unmutated pack is kept as the negative control**: `free_numeric_critical_path_steps`
   names that slot, `TypedSession.prompt()` refuses it, and
   `test_the_unmutated_pack_cannot_complete_typed` asserts the whole run refuses.
2. The RED rule is re-anchored from the unresolvable bare `sure_dakika` to a synthetic
   dated slot, so that a RED can fire at all and the near-miss control has something to be
   a near miss of. Level, predicate, register, source and all three per-location actions
   are untouched.

## Deliberately not built, and why

- **A maximum typed-entry length.** The `intake-typed` threat row names input limits as a
  control for [D]. The Talker's `submit_utterance` has no length bound either, so adding
  one to the typed lane alone would create the appearance of coverage while the voice lane
  stayed unguarded, and the bound belongs at the ingress both lanes share
  (`services/api` / the transport adapter), not in one Layer-A lane. What *is* asserted
  here is the property that limits the blast radius: the lane retains no patient entry at
  all. **Recommend a follow-up issue on the shared ingress**; it is not INT-096's scope
  and nothing here pretends to be it.
- **The typed consent copy.** `respond_permission` relays a decision against a prompt hash
  it does not author. The eleven Turkish açık rıza texts are INT-038's deliverable and are
  still blocked; nothing here authors one.
- **A chip set for any real pack's numeric critical-path slot.** The gate is built and
  fails closed; the content is clinical. HUMAN_BLOCKERS **HB-C6** names exactly this ask —
  *"Author the six `base.intake` additions with `ask_tr`, `follow_up_tr` and
  `choices_tr[]`"*, including `weight_kg` — and **HB-C16** covers the valueset members
  behind `code` slots. No new blocker row is needed and none was invented.
- **A metric.** No queue-depth, prompt-count or switch-count row exists in
  `observability/metrics_catalog.yaml`; invariant 13 admits only catalogued names, and the
  signals the threat row asks for (`policyguard_blocks_total` with its `profile` label,
  delivery latency) already exist.

## Findings — reported, not worked around

1. 🔴 **`files/03 §4.6 invariant 8` names two profiles that do not exist.** Its text reads
   *"the same simulator scenarios pass on `typed`, `cascade_fast`, and `residency_tr` …
   `s2s_cloud` is disabled unless `VOICE_S2S_ENABLED=1`"*. CLAUDE.md invariant 19 and
   ADR-010 delete both; `files/00 §0b` and `files/03 §4.4` already say so. The runtime
   invariant that the *code* must satisfy is therefore stated against a profile set the
   code refuses to construct. `files/**` is not this issue's to edit — reported for
   whoever owns the next `files/03` correction.
2. 🔴 **The committed compiler fixture's RED rule can never fire.**
   `tests/fixtures/protocols/compile/tree/base/intake.yaml` declares
   `tense_anchor: sure_dakika`, bare, while every slot reference in that pack is
   section-qualified, so `rule_truth` reads Unknown for the anchor in every session. No
   existing test asserts that rule fires, which is why it has gone unnoticed. Worth a
   compiler check: **a `tense_anchor` that resolves to no declared slot should be a
   compile refusal**, since the failure mode is a red-flag rule that silently stops
   firing. (`packages/protocols/**` is out of scope here.)
3. 🟠 **`tests/sim/driver.py::free_text_critical_path_steps` under-detects.** It filters on
   `SlotType.STRING | DECIMAL | INTEGER` and omits **`QUANTITY` and `DURATION`** — the two
   slot types a clinical pack actually uses for doses and intervals. A required `quantity`
   slot with no `choices_tr` is precisely the free-numeric-entry case invariant 22 forbids
   and that gate would not name it. `tests/sim` is not this issue's to edit;
   `intake_voice_runtime.typed.affordance.free_numeric_critical_path_steps` covers all four
   numeric types and is the gate INT-096 relies on. **Recommend aligning the sim's helper.**
4. 🟠 **`files/03 §4.7.5` marks `asr_quality` profile availability `all`.** There is no ASR
   in `typed`, so that column cannot be literally true now that the profile set is
   `{residency_tr, typed}`; it was written when "all" meant three *voice* profiles.
   `typed/lanes.py` states only the structural fact (no audio frames, no ASR confidence)
   and deliberately does not legislate an availability table.
5. ✅ **`files/HUMAN_BLOCKERS.md` had duplicate ids — found here, fixed on commit.** The
   activity-labels and valueset-members rows were filed the same day as `HB-C10` and
   `HB-C11`, ids that were already taken by the Turkish eval set and the labelled emotional
   speech corpus. Both were renumbered to **HB-C15** and **HB-C16**, the two rows that were
   already there kept their ids, and every reference to the new pair was updated. This
   evidence file cites HB-C6 and the *valueset* row, **HB-C16**.

   One duplicate is left standing and is NOT mine to renumber: **`HB-L21` appears twice**,
   on the KSVY m.16 research-export row and the store-listing determinations row. Both
   pre-date this session and both are referenced from `docs/backlog/blockers.md`, where the
   intended row is recoverable from the text but not from the id. Renumbering an existing
   row changes an identity in a file whose whole discipline is that ids are stable, so it
   is recorded for the owner rather than guessed at.
