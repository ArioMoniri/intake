## 0. A prior attempt exists, and this issue starts by judging it

A stranded 40-commit branch, `origin/claude/github-actions-billing-34om2r`, carries
`6cf4304 feat(voice): INT-096 typed profile — parity stated as an inequality, not as
sameness`. It was never packaged into a PR and never reviewed. It is genuinely good work
and this issue is not a rewrite of it: four of its modules are ported here close to
verbatim, and its central idea is adopted outright.

**Adopted.** *Parity stated in both directions.* Its commit message puts it better than a
paraphrase would: a suite that asserts only sameness is *"either false or vacuous"*.
Given one answer stream the two profiles must reach an identical record; where the answer
streams legitimately diverge — typed has no ASR, so no low-confidence clarification — the
claim that survives is an inequality, that typed is never the worse channel. §4 of
`tests/voice/test_typed_parity.py` is that idea, in this tree's shapes.

**Ported, near-verbatim.**

| module | what it carries | change on porting |
|---|---|---|
| `typed/affordance.py` | invariant 22's *"no free numeric text entry on the clinical critical path"*, as a refusal | dropped the stale `HB-C11` citation (see finding F3); tightened the docstring's account of why the refusal is wider than the pack gate |
| `typed/render.py` | verbatim prompt; `useGrouping:false`; number + unit as one non-breaking atom | `render_measure` is local — the `intake_platform.llm.units.render_quantity` it imported is INT-083's on **that** lineage and does not exist on `main` (finding F2) |
| `typed/lanes.py` | the three observer lanes with no input in typed | verbatim |
| `typed/switch.py` | the kill switch: closed reason set, latched, first reason wins, PHI-free record | verbatim, plus `KillSwitchNotArmed`; the latch is now held *by* the session rather than beside it |

**Refused, with the reason.** `typed/session.py` — a second `TypedSession` class
re-implementing `protocol_next`, `submit_utterance`, `cancel_work`,
`request_repeat_or_clarify`, `patient_memory`, `respond_permission`,
`open_permission_request` and `retained_frames`. The brief for this issue names that
outcome exactly: *"a `typed` profile that re-implements the flow in a second place is the
opposite of parity."* Three concrete consequences, not a stylistic objection:

1. **A third of that suite existed to prove the copy still behaved like the original.**
   `TestTheSixToolsBehaveInTyped`, `TestTypedConsentGates` and
   `TestEveryTypedToolIsCallableThroughTheRegistry` are ~25 tests that have no subject
   once there is one session class. A property being *checked* repeatedly is the shape of
   a property that is not *held*.
2. **`respond_permission` had already drifted.** The three rungs it drops are argued and
   the argument is sound (no prompt audio, no playback overlap, no ASR confidence in a
   typed session). But it also silently dropped the backchannel and lexeme-whitelist
   checks that the voice copy runs. One drift, in the first copy, on a consent gate.
3. **It has no `take_turn`** — so no ask ledger, no insertion scheduler, no
   `drain_results`. On current `main` that is not a subtraction but a defect: without the
   ask note `IntakeEngine._bind` drops every answer, and without the scheduler a YELLOW
   that expires unheard never reaches the note on typed while it does on voice. That is a
   parity break with clinical consequence, in the direction the note cares about.

`utterance.py` is also not ported. It hashes the transcript directly; `main` deposits it
into `SessionTranscripts` first (INT-083's boundary crossing, which also refuses the
data-block control token). Porting it would have been a regression against invariants 6
and 14.

**Judgement, stated rather than defaulted.** Porting the whole commit was more expensive
than the selective port *and* would have left the defect: the branch predates INT-083's
vault, INT-084, INT-095's composition root and INT-112, so `TalkerSession`, `data_gaps`
(now a property), the harness doubles and the handler registration all conflict — and
after resolving every one of them the egress refactor below would still have been owed.
So: port the four safety modules and the inequality idea; implement the profile as a
transport on the one session.

## 1. What was built

**The seam.** `talker/egress.py` defines `TurnEgress` — `profile`, `emit`, `cancel` — plus
`Emission` and the free function `text_for`. `SpeechRouter` is its `residency_tr`
implementation; `typed/egress.py`'s `TypedEgress` is its `typed` one, holding a
`ScreenSink` and nothing else. `TalkerSession.router` is typed as the port, so nothing
above the seam can reach a sink, a clip or a synthesizer.

`text_for` moved **above** the seam deliberately. Invariant 10 says "spoken" because the
profile it was written for speaks; displaying an improvised rewording of an authored
Turkish question is the same defect through a different device. One function means the
paraphrase permission cannot be granted on one transport and withheld on the other.

`assert_no_numeral` deliberately did **not** move. It is a property of the TTS transport —
files/03 §4.9.6 is about what a speech model's normaliser does to `2.5 mg` — and a screen
showing `2,5 mg` is invariant 22's inline clause satisfied, not broken. The two halves of
invariant 22 are now enforced in the two places they apply.

**The four speech ports are optional and absent on typed.** `catalogue`, `clip_store`,
`synthesizer`, `sink` are `| None`; `TalkerConfig` refuses a `typed` profile carrying a
`voice_id` or a `safe_bridge_clip_id`; `_build_egress` refuses a typed session holding any
of the four, and a speaking session missing any. Invariant 3 becomes a property of the
typed path's *shape*: there is no buffer to zero because there is no object that could
hold one.

**The kill switch.** `TalkerSession.fall_back_to_typed(reason)`. One actor, no approver
(files/08 §0c F17 — a second approver on the safe direction is an availability control on
a safety control), one gate: the session must have a `ScreenSink`, because going silent
mid-intake is worse than the degraded voice being left. It replaces **one** field — the
egress — and drops the four speech ports to `None`; it touches neither the engine, the
Work queue, the transcript vault, the ask ledger, the insertion scheduler, nor
PolicyGuard's learned form of address. That list is what makes files/03 §4.5b T3's *"keep
the session and every slot"* structural rather than tested.

**The parity run.** `ParityTrace` is a `ScenarioReport` with every transport-specific
quantity removed, and `divergence()` names the field rather than returning `False`.
`make runtime-sim SCENARIO=RT-01 PROFILE=typed PARITY=1` runs the scenario on every
profile it declares and exits 4 on a divergence.

**Readiness.** `VoiceRuntimeWiring.profile` makes the three speech bindings conditional. A
kill-switch target that can never report ready is not a target; the checks stay in the
report rather than disappearing, because a readiness report that silently shrinks is one
nobody can compare across deployments.

## 4. Findings

**F1 — the latency harness let Layer B run only because Layer A happened to sleep.**
`Stack.turn` in `tests/voice/test_invariants.py` started the Layer B pump as a task and
cancelled it when the turn returned. On `residency_tr` the pump got its scheduling tick
from the playback sleep inside the sink; a typed turn awaits no playback, so the pump was
cancelled having never been scheduled — and RT-05 produced two different step orders on
the two profiles. That is the coupling ADR-009 forbids, read in the other direction: *the
Talker never waits for the Backend* also means the Backend must not depend on the Talker
having waited. Fixed by pumping on both sides of the turn. Neither pump costs virtual
time, so a genuinely stalled Layer B stays parked and RT-03 still proves a ten-second
backend does not lengthen a turn. **This was invisible while `typed` had no code path**,
which is the argument for giving it one.

**F2 — there is no shared renderer for a clinical quantity, and this makes a fourth
private copy.** `clinical_schemas.mappers.document`, `note.composer` and
`summary.builder` each keep their own `_NBSP` and their own format call.
`typed/render.py` now makes four. It produces the same bytes as the other three for the
same input — including leaving the decimal separator exactly as they print it, since
files/00 §2 settles grouping and the atom but not the separator, and diverging here alone
would create the drift the rule exists to prevent. No issue owns unifying them; one
renderer would touch the note and the patient summary. **Recorded, not fixed.**

**F3 — `HB-C16` is duplicated on `main`.** `files/HUMAN_BLOCKERS.md` line 45 (the four
Turkish marker lexicons, INT-112) and line 81 (whether a RED patient keeps a patient
summary, INT-085) both carry the id `HB-C16`, both dated 2 September 2026. The stranded
branch's commit message records renumbering its own rows to `HB-C15`/`HB-C16` after
finding an earlier collision; INT-085 then took `HB-C16` independently. Not touched here —
a blockers-file renumber collides with every concurrent merge (and the file's ids are
meant to be stable), so it wants its own change. The ported `affordance.py` cites `HB-C6`
only, which is unambiguous.

**F4 — no committed pack resolves, on either profile.** All **93** packs are `maturity:
L0`; `packages/protocols/dist/` holds only `.gitkeep`. Resolving each of the 92 pack ids
in the tree: `base.intake` refuses with `PACK_NOT_SERVABLE base.intake: maturity L0 is
review-queue only and is never served`, and every specialty pack refuses because its
cluster parent does not exist (`UNKNOWN_PACK cluster.dental`, `cluster.allied_and_reports`,
…). That is invariant 13's gate working. Consequence for the typed profile's own serving
precondition: `free_numeric_critical_path_steps` could not be run over authored content,
because there is no resolved authored content to run it over. The gate exists, is tested
against a synthetic negative control, and will bite the first time a pack reaches L1.

**F5 — the framing that INT-096 "puts compiled packs behind both surfaces" is stale.**
`docs/backlog/blockers.md` and `HUMAN_BLOCKERS.md` HB-C15 both say the note-vs-mobile
disagreement about what "missing" means *"becomes live the moment INT-096 puts compiled
packs behind both"*. It does not. INT-096 is the runtime half — it gives `typed` a code
path on the one session. The *mobile* surface is INT-136 (`depends_on: [INT-096,
INT-130]`), and per F4 no pack is servable to either surface. **HB-C15 stays open and
stays not-yet-live.** The prediction was reasonable when written; it named the wrong
issue.

**F6 — `ExtractSlotsHandler` assigns the triage wiring to this issue, and no acceptance
line carries it.** Its docstring: *"It sets no `triage_update`. The rules engine is
`packages/protocols/triage` and running it from here is INT-096's scope."* INT-096's
acceptance says nothing about triage, and wiring it needs a per-session `RedLocation` —
which invariant 21 permits no default for — and a RED delivery path `composition.py`
records as blocked on HB-C1. Doing it here would have been two issues in one PR. Parity
over triage holds in the meantime because there is one handler, not because two
evaluations agreed, which is the property that survives the day one is wired in.
**No issue's acceptance owns that wiring; it needs one filed.**
