# INT-233 — Spoken dialogue intake (turn-by-turn voice over the pack)

Owner directive: "the voice model should interact and ask questions and go
on a disturbable voice interaction and previsit intake … in general voice
based asking and transcribing what patient told and agent asked and going
on a visit dialogue".

## What this is, honestly (dev tier vs the product runtime)

This iteration is the **DEV-TIER dialogue in-app**: an Expo turn loop over
the HTTP dev bridges — whisper ASR (:8802, INT-194), FreyaTTS (:8803,
POST /synthesize → WAV), extract (:8804, INT-199) — driving the existing
department packs (`packForDepartment`). The production voice path is the
**LiveKit Talker** (files/03 §4.9, files/13 Part II): mlocked ≤60 s
buffers, the six-tool boundary (invariant 9), pre-synthesised clip
manifests from compiled protocol packs, safe-insertion-window delivery.
Nothing built here claims to be that runtime; the packs remain UI fixtures
with no red-flag logic, candidates remain answer suggestions the patient
confirms (invariant 1 posture), and nothing is presented as triage.

Audio hygiene distinction stated for the record: the WAVs cached under
`FileSystem.cacheDirectory/dialogue/` are **agent-voice clips** synthesized
from catalog tr strings — they are not patient audio, so invariant 3
(which governs PATIENT audio) is not what forces their deletion; they are
still deleted wholesale on unmount AND on session end as hygiene. Patient
recordings keep the existing INT-194 posture untouched: uploaded to the
dev ASR and deleted in `transcribeRecording`'s finally block, or discarded
immediately on cancel (`discardRecording`).

## Design

- `apps/mobile/src/lib/dialogue/turn.ts` — pure reducer, TDD'd like
  voiceFirst's. Phases: `speaking(question|confirm)` → `listening` →
  `transcribing` → `extracting` → `confirming` → advance; `typing` is the
  per-step text fallback; `done`/`failed` are absorbing terminals.
- DISTURBABLE: `barge_in` from either speaking intent lands in
  `listening`; the component stops playback synchronously in the tap
  handler (`player.pause()` on the shared native object) before
  dispatching, and a single player ref cleared before every new clip means
  no overlapping audio.
- Speech is composed ONLY from catalog tr strings
  (`lib/dialogue/speech.ts`): question tr text + hint + option hints
  (enumerated only ≤ 4 options — files/13 §5.3, Cowan ~4 chunks; longer
  lists point to the screen). Confirm prompts echo catalog option labels;
  free-text steps get the generic catalog confirm line because patient
  words are displayed, never synthesized (invariant 2/10 posture).
- Invariant 22 mirror: `assertSpeakableTr` throws on any Unicode decimal
  digit BEFORE every `/synthesize` call; FreyaTTS rejects digits
  independently; a test sweeps every question and option across all ten
  packs.
- Single-question extract per turn (the daemon accepts any subset), so the
  per-turn wait is the fast path.
- Entry: the "Sesli anlatın" offer now carries the second path
  "Karşılıklı konuşarak ilerleyin" (`dialogue` phase added to the
  voiceFirst machine, offer-only). The one-shot flow is unchanged.
- Continuity: answers commit to the session note per step; dialogue
  failure (TTS unreachable, mic denied, ASR HTTP error, extract down) →
  outer `failure` → the existing manual StepFlow with the notice, resuming
  at the first unanswered question; leaving by choice → `skip`, quietly.
  An empty transcript or no usable candidate is NOT a failure: that one
  step falls to typing and the dialogue continues.
- Module split: the imperative session driver (reducer wiring, clip
  synthesis/cache, playback, recorder, single-question extract, teardown)
  is `lib/dialogue/useDialogueSession.ts`; the screen
  (`components/DialogueIntake.tsx`) renders state and stores answers —
  both under the 500-line bound.

## Barge-in latency note

expo-audio's `AudioPlayer.pause()` is a synchronous call on the shared
native object; the tap handler calls it before dispatching any state
change, so playback halts in the same JS tick as the gesture — no await
sits between the tap and the stop. The reducer admits no state in which
speaking and listening coexist, and the component holds exactly one player
ref, cleared before any new clip is created; overlapping audio is
structurally impossible rather than merely avoided. (No VAD auto-stop in
the dev tier: listening ends on "Bitirdim" or a tap on the surface —
silence detection belongs to the LiveKit runtime.)
