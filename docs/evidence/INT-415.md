# INT-415: ElevenLabs delivery profiles per question context + on-prem TTS wiring guide

**Epic:** E05-voice · **Phase:** P1 · **Sec-Row:** `cloud-clipgen` · **GitHub:** #706 ·
**Depends on:** INT-326 · **Branch:** `int-415-delivery-profiles` · **Date:** 2026-09-27

## The ask

The owner wants questions to sound natural: warm at the opening, professional afterwards. The
ElevenLabs lane we use today (the ADR-028 offline clip build and the INT-326 dev on-demand
route) should carry delivery settings per question context. The owner also wants a written
guide for wiring the same profiles to the self-hosted `residency_tr` TTS later. That guide is
`docs/voice/on-prem-tts-wiring.md`.

## What changed

- **The shared contract with INT-414.** `apps/mobile/src/lib/dialogue/deliveryContext.ts` holds
  the seven contexts: welcome, routine, sensitive, instrument, acknowledgement, red, closing.
  The default is `routine`. The file is byte-identical to the brief.
- **The mobile client** (`georgeClip.ts`):
  - `fetchGeorgeClip(base, text, { context })` POSTs `{ text_tr, delivery_context }`, with
    `routine` as the default.
  - `georgePreferringSynth(george, fallback)` returns `(text, context?)`. The context is per
    utterance and is forwarded to George.
  - A `red` context is never sent. The client throws `george_unavailable` before any request,
    and the caller falls back.
  - The `ScriptedTr` brand and the numeral guard are unchanged. `clips.ts` forwards the
    context.
- **The profile table** is `packages/voice-clips/src/voice_clips/delivery.py`. It is typed and
  versioned, and it lives on the server only. Each context maps to a `DeliveryProfile`: the
  context, a version, the pinned model id `eleven_multilingual_v2`, and the five
  `voice_settings` fields. A profile's cache segment is `delivery.<context>@v<version>`.
  - **Why it lives beside the gateway.** Both consumers already depend on `voice_clips`: the
    offline build and the API route. The mobile app never imports it, so the table is
    server-only by structure. The protocols package is I/O-free and vendor-free by
    construction, and vendor voice settings are an adapter concern.
- **The request body.** `ElevenLabsClipGenGateway` now sends `voice_settings` alongside
  `model_id` and `apply_text_normalization: "off"`. That normaliser-off setting is invariant
  22, unchanged. A profile tuned for another model is refused before the wire
  (`DeliveryProfileMismatchError`). The model stays pinned; changing it needs an ADR.
- **`TtsGateway.synthesise` takes a required `profile`.** A caller that forgets one is a mypy
  error, not a silently routine clip.
  - The self-hosted `HttpTtsGateway` accepts the profile and sends its body exactly as before,
    `{text, voice_id}`. That contract has no delivery controls. A test pins the body so no
    vendor setting leaks into it.
  - `RecordedTtsGateway` refuses a recording made under another profile. A recording that
    names no profile is profile-free, which is what a self-hosted take is.
- **Offline clipgen (ADR-028).**
  - The builder reads each manifest row's context from its subject, never from a caller:
    - a rule id (`rf.*`) is `red`;
    - an instrument item (`<InstrumentId>.<item>`) is `instrument`;
    - a slot question is `routine`.
  - It synthesises each row under that profile.
  - The object key is now `clips/<locale>/<voice>/<profile key>/<clip_id>`, so a retuned
    profile (version bump) is a cache miss that re-synthesises instead of replaying the old
    tuning.
  - The compiler's `clip_id` and `text_hash` binding are untouched, and
    `load_clip_manifest`'s tamper check is unchanged (invariant 10).
  - No runtime `ClipStore` implementation reads these keys today; the guide records the
    lookup for whoever wires one.
- **The on-demand route** (`intake_api.dev_voice`):
  - `GeorgeClipIn.delivery_context` is the same seven-value `Literal`, with `routine` as the
    default. `extra="forbid"` still refuses any voice id, model, voice setting or profile
    from the client.
  - **RED is refused on demand** (422 `red_not_on_demand`), both when it is labelled `red` and
    when the text is a compiled rule script under any label. The catalogue pins those rows
    server-side (`ScriptedCatalogue.pinned_contexts`, derived from the manifest subject). RED
    audio is pre-positioned on the device and never fetched on demand (invariant 21).
  - An instrument item is served only under `instrument`; otherwise the route answers 422
    `delivery_context_mismatch`.
  - The cache path is `<cache_dir>/<profile key>/<clip_text_hash>`, so the same text in two
    contexts is two clips.
- **Unchanged:** authentication, the catalogue door, the budget, absence in production, 503
  when unconfigured, 502 on a vendor error (the key is never echoed), and the 422 numeral
  refusal. No patient words can reach the vendor: only compiled catalogue text is admitted.
- **No new metric.** `observability/metrics_catalog.yaml` and the cost config are untouched.

## Sources — ElevenLabs API (retrieved 2026-09-27)

The parameter names, ranges and model support were checked against the vendor's own
documentation, not a blog or an SDK:

- Text-to-speech endpoint, request body (`voice_settings`, `model_id` default
  `eleven_multilingual_v2`, `apply_text_normalization` `auto|on|off`):
  <https://elevenlabs.io/docs/api-reference/text-to-speech/convert>
- The voice-settings object (`stability` default 0.5, `similarity_boost` 0.75, `style` 0,
  `use_speaker_boost` true, `speed` 1.0, with their descriptions):
  <https://elevenlabs.io/docs/api-reference/voices/settings/update>
- Ranges and advice: speed runs 0.7 to 1.2, and the vendor advises keeping style at 0. Speed,
  similarity and speaker boost are unavailable on Eleven v3, so the pinned v2 model supports
  all five fields:
  <https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech>
- v2 supports SSML break tags; v3's audio tags (`[whispers]` and similar) are v3 only:
  <https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices>
- `eleven_multilingual_v2` covers 29 languages, Turkish among them:
  <https://elevenlabs.io/docs/models>

The request host stays env-supplied (`TTS_ELEVENLABS_BASE_URL`), so
`scripts/ci/assert_no_vendor_calls.sh` still finds no vendor endpoint in the tree.

## The profile table (v1) and why

These are **voice-tuning values, not clinical values**. They set pace, steadiness and
expressiveness. They decide no triage level and nothing a clinician reads. They start from the
vendor's documented defaults (stability 0.5, similarity 0.75, style 0, speaker boost on, speed
1.0) and move only the delivery knobs.

| context | stability | style | speed | why |
|---|---|---|---|---|
| welcome | 0.40 | 0.20 | 0.98 | The warmest: lower stability lets the voice vary naturally, and a modest style is added. A touch unhurried. |
| routine | 0.55 | 0.05 | 1.00 | Calm and neutral, near the vendor defaults. Professional after the opening. |
| sensitive | 0.65 | 0.00 | 0.92 | Steadier and slower than routine, with no exaggeration, for questions that need care. |
| instrument | 0.80 | 0.00 | 0.95 | Validated items: very stable, no exaggeration, slightly slower so every word lands. |
| acknowledgement | 0.48 | 0.15 | 1.02 | Brief and warm: a little livelier than routine, never slower. |
| red | 0.85 | 0.00 | 0.95 | The most stable of all, with no exaggeration. Clear rather than rushed. |
| closing | 0.42 | 0.20 | 0.97 | Warm like the welcome, a touch steadier. |

Rules fixed in code and asserted by tests, not by ear:

- `similarity_boost` 0.75 and `use_speaker_boost` true in every row. Those are identity knobs,
  and one voice per session is files/03 §4.9.1 row 11.
- RED and instrument are the most stable rows and carry style 0.
- Style is capped at 0.3.
- Every value sits inside the vendor's range, enforced at construction.

**A listening review is still owed.** The numbers are a reasoned starting point, not a settled
tuning. The owner should listen to each context on a few catalogue sentences, and any change
bumps that row's `version`. That is an owner ask in the PR, and no HB id was minted.

**Other models are only an option.** `eleven_v3` audio tags could express warmth per phrase,
but v3 drops `speed`, `similarity_boost` and speaker boost. Switching model is an ADR, not a
profile edit, and the gateway refuses a profile tuned for another model.

What the new tests prove:

- **The table:**
  - every context resolves to its own pinned profile;
  - the contexts equal the mobile contract byte for byte (the TS file is parsed);
  - seven near-miss labels are refused;
  - the table is read-only;
  - the request carries exactly the five vendor fields.
- **The principles:**
  - RED and instrument have style 0 and are the most stable;
  - welcome and closing are the warmest;
  - sensitive is slower and steadier than routine;
  - an acknowledgement is warm and does not drag;
  - similarity and speaker boost are constant.
- **The bounds:** ten out-of-range settings are refused, and the edges themselves are admitted
  as near-miss controls.
- **The request body:** for every context, the fake transport sees `voice_settings` equal to
  the profile, `model_id` pinned, the normaliser off, and nothing else. RED and instrument
  send style 0. A profile tuned for `eleven_v3` is refused before the wire.
- **Offline clipgen:**
  - each row is synthesised under its subject's profile;
  - the object key carries the profile key;
  - the same entry under seven profiles gives seven keys;
  - a version bump misses the cache;
  - a recording made under another profile is refused.
- **The route:**
  - every context except `red` is served under its own profile, with one dial per (text,
    profile);
  - a profile change is a new cache key, and a repeat is a hit;
  - `red` → 422 with no dial;
  - six near-miss labels → 422;
  - a client-sent `voice_settings`, `model_id` or profile → 422;
  - a compiled RED script under any label → 422;
  - an instrument item outside `instrument` → 422 `delivery_context_mismatch`;
  - the real compiler's catalogue pins every rule row to red.
- **Mobile:**
  - `delivery_context` is sent, and the default is `routine`;
  - every non-red context is sent verbatim;
  - `red` is never fetched;
  - `georgePreferringSynth` forwards the context.
