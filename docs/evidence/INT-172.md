## Invariant 12 is the feature, so it is enforced structurally, not by review

CLAUDE.md invariant 12 and files/09 §4 ("Forbidden for the agent") name six subjects
`services/learning` may never change. The obvious control — validate a proposal before
applying it — presumes the service is in a position to apply something. Six gates in
`tests/learning/test_proposal_scope.py` remove that position instead. None of them imports
the package and hopes; all six read source with `ast`.

| gate | what it asserts | why the weaker version has a hole |
|---|---|---|
| `test_the_import_closure_never_reaches_a_forbidden_module` | the **transitive** first-party import closure of the whole package reaches none of `protocols`, `intake_voice_runtime`, `intake_platform.legal`, `intake_platform.consent`, `intake_platform.profiles`, `intake_api`, `voice_clips` | a direct-import check is defeated by one hop through a helper; ancestor `__init__` modules are walked because importing `a.b.c` executes `a/__init__.py` |
| `test_the_pipeline_closure_reaches_no_network_or_process_module` | the pipeline's transitive closure holds no `httpx`, `urllib`, `socket`, `http`, `requests`, `aiohttp`, `smtplib`, `ftplib`, `subprocess`, `os`, `pathlib`, `shutil`, `tempfile` | files/09 §7's "sandboxed job … no egress" enforced only by a container policy is enforced in exactly one place |
| `test_the_pipeline_imports_nothing_outside_the_declared_allow_list` | the pipeline's own imports are ten stdlib modules, `prometheus_client`, and first-party | a deny-list answers "did we think of that one"; an allow-list answers "what can this reach at all" |
| `test_the_package_contains_no_write_capable_call` | no `open(`, `exec(`, `eval(`, `compile(`, and no `.write*`/`.mkdir`/`.unlink`/`.rename`/`.replace`/`.rmtree`/`.system` anywhere | "may not write to a protocol pack" needs no path allow-list if the package holds no writer to point at a path |
| `test_the_pipeline_composes_no_sql_of_its_own` | no `text(`, `insert(`, `update(`, `delete(`, `execute(`, `commit(` in the pipeline | this is *why* a read-only credential suffices: the package has no expression through which a write could be attempted, so the grant is a belt rather than the only strap |
| `test_the_read_path_is_int_171s_gated_one_and_never_the_ungated_projection` | the pipeline names `materialise_view` and never `read_cells`/`cells_query` | `read_cells` projects rows without applying the k floor; naming it would move the gate off the query layer, where the INT-171 acceptance puts it |

`test_the_gate_would_report_a_forbidden_import` is the negative control: a synthetic module
importing `protocols.triage` and `intake_voice_runtime.talker` is named by the same walker,
so silence is not the only answer the gate can give. `test_the_scan_walks_a_real_corpus`
pins that the walker actually finds the pipeline modules, follows a hop out of the package,
and excludes `app.py` from the pipeline-scoped gates.

**Why the shell is scoped past on gates 2 and 3.** `app.py` mounts the four invariant-15
endpoints through `intake_platform.health`/`metrics`/`otel`, which are shared platform code
every service mounts and which legitimately reach `os` and the OTel exporter. The
invariant-12 gate and the no-writer gate still cover it: both bind the whole package.

## A red-flag level is refused by type, not validated at the edge

The posture INT-091 used for RED preemption (`services/voice-runtime/.../talker/preemption.py`
and `clinical_schemas.triage`, where `LlmCandidateTriage.level` is
`Literal["YELLOW_REVIEW"]` and there is deliberately no shared base class to widen).

- `intake_learning.proposals.PROPOSAL_TARGETS` is a module-level tuple of exactly ten frozen
  dataclasses — files/09 §4's "Proposal types (allowed)" list and nothing else. There is no
  shared base class, for INT-091's reason: a base class is a thing to widen and a shared
  field is a thing to confuse.
- `test_no_proposal_target_can_carry_a_triage_level_or_a_path` walks every field of every
  member and asserts no annotation names `TriageLevel`, `RedFlagLevel`, `RuleFire`, `Path`,
  `PurePath` or `PosixPath`. A proposal names a pack and a step; there is no field that
  could hold a rule id, an instrument id, a consent-text id, a tool name, a profile id or a
  file path.
- `CandidateRedFlag` has **no `level` field**. `_LEVEL` is a `ClassVar` — which `dataclasses`
  excludes from the field set, so it is not a constructor argument either — exposed through a
  read-only property. `CandidateRedFlag(..., level="RED")` is a `TypeError` at the call site;
  `flag.level = "RED"` is an `AttributeError`. Nothing clamps, because nothing can be said.
- `PromptModuleId` has two members, `EXTRACTION` and `NOTE`. files/09 §4 puts "the Talker
  prompt and safety prompts … out of scope for automatic optimisation", and the exclusion is
  the enumeration: there is no `TALKER` member to disable.
- `PackMaturity` promotes and refuses to demote — files/09 §2's ladder is the record of what
  a clinician reviewed, and walking it backwards is a withdrawal decision.

## The read path: INT-171's gate, on INT-171's credentials

`intake_learning.run` is the weekly loop, and it holds no policy of its own.

- It reads through `intake_platform.analytics.materialise_view` — the gated
  entry point — and the scope test asserts it can never name `read_cells`, which projects
  rows without a floor. The INT-171 acceptance says "k>=10 enforced at query layer"; naming
  the ungated projection would move it off.
- The `Cohort` description is taken from the view registry, never from a caller. So the run
  produces exactly the one cohort `EvidenceBundle.build` will accept, and "the only prose in
  a bundle is committed prose" is true by construction on both ends.
- `LEARNING_READER_ROLE = "svc_learning_reader"` names INT-171's role so an operator wiring
  the sandbox can grep for it. The grant itself is the control
  (`migrations/versions/0009_int171_analytics_views.py`), and INT-171's integration lane
  already proves it reaches the three views and no base table — not restated here.
- `tests/learning/test_weekly_run.py` drives the whole loop against a fake session that
  answers by relation name. **The fake replaces the driver, never the gate**: the real
  `materialise_view` runs on every row, so a thin cell off the wire stops the run
  (`BELOW_K`), a narrative `slot_id` off the wire stops it (`DIMENSION_NOT_ID_SHAPED`,
  without echoing the sentence), an empty window refuses identically to a thin one, and a
  `k` under the floor raises before anything is read. The test also asserts the run issues
  exactly two statements and both start with `SELECT`.

## The adversarial evidence-bundle proof

`test_a_planted_turkish_symptom_sentence_never_reaches_a_bundle`, planting two sentences at
every surface a bundle touches. The first is borrowed **verbatim** from
`tests/observability/test_langfuse_gate.py` (INT-175), the way `tests/infra/test_siem_feed.py`
(INT-205) borrows it, so every PHI gate in the tree agrees on what patient narrative looks
like:

```
TURKISH_SYMPTOM   = "Göğsümde iki gündür şiddetli bir ağrı var ve nefes almakta zorlanıyorum."
TURKISH_WITH_NAME = "iki gündür göğsümde baskı var, Ahmet Bey aradı"
```

| surface | result |
|---|---|
| a `Cell` dimension value (`slot_id`) | `KAnonymityRefusal(DIMENSION_NOT_ID_SHAPED)` — INT-171's gate, re-run by `EvidenceBundle.build` rather than trusting the `Measurement` it was handed |
| a `slot_id` arriving **off the database wire** (`test_weekly_run.py`) | same refusal, before any finding exists — the run stops rather than proposing something scrubbed |
| a `Cohort.description` | `ValueError` — a bundle accepts only the view registry's committed `cohort_description`, byte for byte |
| both refusal messages | neither echoes the sentence (`assert planted not in f"{exc!r} {exc}"`, the INT-171 form) |
| the serialised bundle, the digest, the MAC, the PR branch, title, body and attachment | swept as one decoded blob: neither sentence, none of `Göğsümde`/`ağrı`/`baskı`/`Ahmet`, and no character in `ğşıİöüçĞŞÖÜÇ` |

The sweep decodes before it looks. `EvidenceBundle.to_json` is ASCII-escaped — it is the
digest's canonical form, matching `intake_platform.audit._entry_hash` byte for byte — so a
substring sweep over the raw JSON alone would pass on an escaped sentence.
`_blob()` round-trips through `ensure_ascii=False` first.

It passes by construction rather than by scrubbing. Every string in a bundle is an id that
came through INT-171's id-shape gate, a member of the `EvidenceSource` enumeration, an ISO
instant, or the analytics registry's own committed prose;
`test_every_string_in_a_bundle_is_an_id_an_enum_or_committed_prose` holds that line
independently. `test_the_pr_body_carries_no_turkish_letter` closes the terminal surface: the
PR body's only non-ASCII characters are `§` (the blueprint's own citation form) and the
em-dash inside the registry's committed `narrative_exclusion`.

**files/09 §4's "de-identified exemplars" are absent, not empty.** That is precisely the
claim HB-L6 records as one "Turkish NLP cannot support", and files/10 §3 puts the residue at
0.3–1.0 direct identifiers per four-minute intake. The evidence bundle a clinician reads
closely is the last place to re-make it, so there is no exemplar slot at all —
`test_the_required_checks_are_the_files_09_list_minus_the_exemplars` asserts the departure
rather than leaving it for a reader to notice.

## Values refused rather than invented, with their asks

files/09 §4 states four promotion thresholds. Three are numbers; one is not.

| threshold | value | source |
|---|---|---|
| ≥ 10 patients | `K_ANONYMITY_FLOOR`, **imported from INT-171** | files/09 §4 "≥ 10 patients"; files/09 §6 "n < 10". Not re-declared: two copies of a privacy threshold are two chances for one to drift down, and INT-171's evidence file made the same call about `intake_metrics.rollups.MIN_COHORT` |
| ≥ 2 clinics | `MIN_TENANTS = 2` | files/09 §4 "≥ 2 clinics" |
| stable over 2 weeks | `STABILITY_WEEKS = 2` | files/09 §4 "direction stable over 2 weeks" |
| **effect size** | **refused** | files/09 §4 says "effect size" and states no floor. No other file states one; no sign-off records one |

`PromotionThresholds.from_blueprint()` — the constructor a scheduled weekly run would call —
raises `AwaitingHumanValue` with the ask:

> **Named human:** the clinical lead (the files/09 §2 L2 sign-off role), instructed by the
> owner.
> **The one sentence they must answer:** *"Below what step-level skip rate should a Loop 2
> finding NOT be put in front of a reviewing clinician?"*

Until that number is recorded with its source, `PromotionThresholds` must be constructed
explicitly with an `EffectSizeFloor` that names where it came from, and `/readyz` answers
**503** naming the missing value (`{"checks": {"promotion_thresholds": "error"}}`). A job
that reported itself ready while structurally unable to promote anything would be the wrong
answer. `test_readyz_turns_green_the_moment_the_threshold_is_recorded` proves the check
flips, because a readiness probe wired to something that can only be false is
indistinguishable from one wired to nothing.

**A second refusal, one level down.** files/09 §4 names session abandonment as a signal and
does not say which of its allowed changes an abandoned session implies. The Architect maps
step skip rate to a reword proposal (files/09 §4 lists "reword … questions"; a step most
sessions never answer is a wording question) and maps abandonment to **nothing** — recording
`learning_proposals_refused_total{reason="no_stated_target_mapping"}` so the finding is
visible to a human without a mapping being invented.

**A third: the PR-bot identity.** files/09 §7 wants "a PR-bot identity that can open but not
merge". A GitHub App with `contents:write` and `pull_requests:write` on `ArioMoniri/intake`,
scoped so it can neither merge nor approve, is a credential nobody has issued.

> **Named human:** the owner (the same person HB-I3 records authenticating `gh`).
> **The one sentence they must answer:** *"Which GitHub App identity may `services/learning`
> open pull requests as, and is it scoped so it cannot merge or approve?"*

So `ProposalPublisher` is a Protocol and **no concrete implementation ships**
(`test_no_concrete_publisher_ships_because_the_bot_identity_is_unset`). Writing an `httpx`
client against a credential nobody issued would also break the "no egress" property gate 2
asserts. There is no row in files/HUMAN_BLOCKERS.md for this and this branch does not add
one — that file is outside the scope this issue was given; the ask is recorded here and in
`intake_learning.publisher`'s module docstring.

Nothing else was invented. No retention period, no cadence, no confidence cut-off, no
sampling rate and no canary percentage appears anywhere in this change (canary/rollback is
INT-173).

## What "signed" means here, and why not a new scheme

files/09 §7 and files/10 §9 both say the bundles are signed. The repository has already
chosen this primitive twice — `intake_platform.room_tokens` mints LiveKit tokens with
stdlib `hmac` alone, and files/12 §5 specifies the rules-engine attestation the same way
(that one is **INT-093's scope and is deliberately not duplicated here**). `cosign` appears
in CLAUDE.md and ADR-017 for *images and protocol bundles* — release artefacts with a
build-time identity; a weekly job's output is neither, and there is no `make sign` target or
cosign call anywhere in the tree today.

So: SHA-256 over the canonical serialisation (`sort_keys=True`, `separators=(",", ":")`,
`ensure_ascii=True` — byte for byte `intake_platform.audit._entry_hash`'s format, so a
reviewer can re-derive the digest without this package), then a detached HMAC-SHA256 over
that digest, verified with `hmac.compare_digest`. `verify_bundle` checks **both** halves —
the MAC over the digest and the digest over the bundle — so a swapped bundle under a
still-valid MAC fails (`test_a_swapped_bundle_under_a_valid_digest_fails_verification`).
The key is a `bytes` argument, never fetched: the package holds no secrets client and no
HTTP client, and an absent or short key raises `SigningKeyUnavailable` rather than emitting
an unsigned bundle that looks signed. The refusal never echoes the key.

`Measurement.measured_at` is carried through the re-gate rather than re-stamped. The instant
in the provenance sentence is when the view was *read*; re-stamping would also make the
digest irreproducible, and a signature over a value nobody can recompute is not evidence.

## Deviations

1. **No migration.** A proposal is an artefact, not a row. The job holds INT-171's
   `svc_learning_reader` credentials, which are `SELECT` on three aggregate views and
   nothing else — so it *could not* persist anything even if a table existed. `uv run
   alembic heads` reports the single head `0009_int171`, unchanged.
2. **No entry in `scripts/ci/coverage_thresholds.yaml`.** That file is hook-protected and
   its guard requires an ADR. `services/metrics` sets the precedent: it has a 90 % lane in
   the Makefile and no entry in that file. `services/learning` follows it — the lane is
   `make check-py`'s, at 90, and it measures 99.6 %.
3. **`.replace(` is refused package-wide**, which catches `str.replace` as well as
   `os.replace`/`Path.replace`. The package spells the one string substitution it needs out
   in `intake_learning.publisher._slug` rather than the gate carrying an exception list it
   would have to keep correct. Documented at both ends.
4. **Inspectors exist only for the two signals INT-171's views can carry.** files/09 §4
   lists more — clarification rate, `follow_up` rate, time, PolicyGuard blocks, ASR
   confusions per term. No view projects those columns, so those Inspectors are not written
   rather than written against data that does not exist. Recorded in `Signal`'s docstring.
5. **files/HUMAN_BLOCKERS.md is untouched**, per the scope this issue was given. The two
   asks above (the effect-size floor, the PR-bot identity) have no row there yet and need
   one.
6. **`make check-integration` was not run**: this change adds no migration, no integration
   test and nothing under the compose lane. (Separately observed and *not* introduced here:
   INT-171's `-m integration` DB lane errors on this machine with `Can't locate revision
   identified by '0005_int141'` — a stale `alembic_version` row in the local dev Postgres
   from another branch. The committed migration chain is intact and single-headed.)
