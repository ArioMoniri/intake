## 2. Invariant 14 — a document is data, never instructions

This is the property the issue turns on, and the first decision was where the control
lives.

INT-083 built it for a transcript: a namespaced fence, a nonce derived from `sha256` of
the text so the speaker cannot pre-compute the token that closes their own block, and a
**refusal** rather than an escape, because escaping rewrites what the patient said and a
boundary that rewrites its input is a boundary that can be talked past. A document needs
exactly that control. It could not import it: `intake_platform` is *below*
`intake_voice_runtime` in the dependency graph (`services/voice-runtime/pyproject.toml`
depends on `intake-platform`, not the other way round), and `services/api` — which serves
the confirm cards — does not depend on voice-runtime at all.

The two available answers were a second implementation with a divergence test, or one
implementation moved down. **A second implementation of a security control is a control
that drifts**, so the rule moved down and the wrappers stayed put:

- `intake_platform/data_boundary.py` owns the rule: `DATA_TAG`, the refused
  `CONTROL_MARKER`, `digest`, `sentinel_for`, `carries_control_token`, `render_fence`,
  `injection_event` and the one `sec_injection_suspected_total` counter.
- `intake_voice_runtime/extraction/boundary.py` keeps `PatientData`, byte-identically as
  far as any caller can tell — same fields, same `repr`, same `BoundaryEscape`, same
  `injection_event(correlation_id=…, tenant_id=…)` signature. `tests/ai` (92 tests, INT-083's
  own contract suite including its `ast` import-graph gate) passes unchanged.
- `intake_platform/records/document.py` adds `FencedDocument`, a **different type** on
  purpose: a transcript and a document are both untrusted text, and a parameter should say
  which one it takes.

Two further properties are asserted rather than asserted-about:

1. **There is no function anywhere on this path that takes document text and returns
   instructions.** `tests/records` walks `dir()` of the extraction module for anything
   named `prompt` or `instruction`. That is INT-083's move 1 applied to documents: the
   instruction region has no parameter a document could enter through, which is what
   "data, never instructions" has to mean if it is to survive a refactor.
2. **The whole text layer is fenced, hidden runs included.** A hidden PDF text run
   carrying an injection is the RT-11 shape (INT-102); stripping it here would move the
   protection into the parser, where a different parser will not have it. A region
   carrying the control token refuses the **document**, and the refusal names no content.

## 3. Invariant 12 — "patient confirms before use", and why there is no `by=`

INT-170 made this type-level for `PatientOverlay` facts and the same shape is used here:
`UnconfirmedRecordItem` has no field a confirmation could occupy, `ConfirmedRecordItem`
cannot be constructed without one, both are frozen, and `ConfirmedRecordStore.admit` takes
the confirmed type alone. Six attempts to get an unconfirmed value into clinical use are
each refused by a different lock (`tests/records`, class `TestPatientConfirmsBeforeUse`).

The stranded branch's bridge took `by=Confirmer.PATIENT | Confirmer.CLINICIAN` and an
`actor_ref`. **`confirm_record_item` takes neither, and the absence is the design.**
`main`'s `Confirmation` carries `source`, `source_ref` and `confirmed_at`, and derives its
actor from `CONFIRMING_ACTOR`, a total map over a closed enum with no unconfirmed member.
`CONFIRMED_IMPORTED_RECORD` maps to `PATIENT`. So *"patient confirms"* is **read off the
vocabulary** rather than passed in by a caller who could pass something else, and a
clinician accepting a note stays what it already is — a different event with its own
source. `source_ref` is derived from the box, so a confirmation naming another document
is not a case to reject: the bridge cannot mint one.

The confirm **card** is `ConfirmCard`: the document's own line, the box a patient taps to
see it on the page, the unit-conflict flag and the date. It carries no authored Turkish
and no field a level or a confirmation could occupy. The mobile rendering of it is not
this issue.

**→ FHIR.** INT-031 already owns `record_item_to_r4` and its provenance extensions, so
this issue adds a seam rather than a mapper: an unconfirmed lab maps to a `preliminary`
Observation carrying `source-document`, `source-page` and `source-bbox`; the same item
after confirmation maps to `final`; a confirmed diagnosis maps to a Condition whose native
`verificationStatus` is `confirmed`; and `unit-conflict` rides along as its own extension
rather than being dropped at the boundary.

## 4. Invariant 1 — a document may not triage

`UnconfirmedRecordItem` has no field a level could occupy (asserted against
`LEVEL_SHAPED_KEYS`), and the completion's key set is closed at both levels. A
level-shaped key — `level`, `triage`, `priority`, `preempt`, `register`, `severity`,
`urgency`, `acuity`, `triage_level` — is refused **specifically**, so the failure reads
"the document tried to triage" rather than "the model added a key". The completion is
refused whole, never trimmed: dropping the unknown key and keeping the rest is how the
remainder of a hallucinated answer gets through.

## 5. Invariant 22, and the two near-miss controls

### 5a. Magnitude outranks the printed unit token

`files/03 §4.9.6` records the demonstrated failure: a published **2024** Turkish
university handbook prints adult ALT `0 - 55 U/mL` and AST `5 - 34 U/mL` when the values
are U/L — wrong by 1000× — and another prints Total Protein and Albümin in `mg/dL` when
both should be `g/dL`. Two independent documents, same class of error. The magnitude is
the trustworthy half, which is why nothing converts.

`resolve_unit` returns a `UnitResolution` with **no path that rescales**: `value` is the
magnitude exactly as parsed and `unit` is the token exactly as printed, whatever the
verdict. Comparison is byte equality after trimming — never a fold and never a synonym
table, because §4.9.6 keeps `µ` U+00B5 and `μ` U+03BC distinct on purpose and a synonym
table is exactly where a silent conversion gets reintroduced.

- **The control:** ALT printed as `30 U/mL` against an authored expectation of `U/L` →
  `unit_conflict=True`, `value_magnitude == Decimal("30")` (asserted, not rounded),
  `unit == "U/mL"`. The flag rides to FHIR as the `unit-conflict` extension.
- **The near-miss negative control:** the same line printed as `30 U/L` against the same
  expectation → `unit_conflict=False`. Without it the first test passes for a guard that
  flags everything, which converts nothing and helps nobody.
- **And the honest gap:** no expectation is committed anywhere (HB-C24). So the check does
  not run, and every analyte it did not run for is named in
  `DocumentExtraction.units_unchecked` — visible, rather than reading as a pass.

### 5b. `üre` is never substring-matched

§4.9.6, verbatim: *"`Üre 45 mg/dL` is near-normal while `BUN 45 mg/dL` is markedly
azotaemic (factor 2.14), and `Üre Nitrojeni` contains the token 'Üre' but means BUN"*.

The guard inverts the naive matcher. The substring is a **trigger**, not a match: its
presence demands whole-token-sequence resolution through a closed table of exactly the
three surface forms §4.9.6 states, and its absence means the name is simply not one of the
two analytes this guard is about — which is `None`, a different thing from an ambiguity.

- **The control:** `Üre` → UREA, `BUN` → BUN, and `Kreatinin` → `None`.
- **The near-miss negative control:** `Üre Nitrojeni` → **BUN**, and explicitly *not*
  UREA. That is the string a naive matcher would have called `Üre`, and the factor between
  the two readings is 2.14.
- **A second near miss:** `Üremi` carries the trigger, is not in the table, and is
  **refused** (`AnalyteAmbiguous`) rather than resolved to the nearest thing.
- Turkish-correct folding is load-bearing and is tested: `ÜREMİ` under Python's default
  `casefold` becomes a string the trigger no longer matches, and would walk straight past
  the guard.
- **No conversion factor is authored.** 2.14 appears in prose that cites §4.9.6 and
  nowhere a program could read it — an AST test skips docstrings (comments are not in the
  tree at all) and checks every remaining constant in the package. A codebase that knows
  the number is one edit from applying it, and the rule is *refuse rather than guess*.

### 5c. The printed magnitude, resolved per value

`parseFloat("1.500")` is `1.5` where Turkish grouping says `1500`, and the separator is
mixed **within one document**, so a locale cannot be chosen per document. `1.500`, `1,500`
and `100.000` each read two ways and are **refused**; `1.500,25`, `1,500.25`, `0,08`,
`0.123` and `12.3456` are unambiguous and resolve exactly. `>100.000 mIU/mL` is a bound
and not a magnitude — dropping the qualifier to keep the number is itself a corruption.
`8,4 - 10,2` stops the parse: §4.9.6 says a two-number reference cell is a signal to stop,
not to average. Rendering is the same rule outbound: `useGrouping:false`, plain positional
notation (never an exponent), and number + unit joined by a NO-BREAK SPACE so they cannot
wrap apart in a narrow column.

§4.9.6 also asks for the separator to be *"cross-checked against the analyte's expected
magnitude"*. That table is HB-C24 and does not exist, so what runs is the fail-closed
reading of the same rule — refuse the ambiguous form. That refusal is strictly safer than
the cross-check and never becomes wrong when the table lands: a table only turns some
refusals into readings.

## 6. Acceptance, line by line

**"labs/meds/diagnoses extracted with source boxes" — met.** All three kinds come back
with their own page, rectangle and character interval. `box` is a defaultless field, so a
value with no box is not a case to reject — it cannot be written down; `read_document_regions`
**raises** on an empty layout rather than returning an extraction with no geometry, because
an empty result would read as "this document contains no labs"; a region index outside the
document is `RegionUnknown`. The box projects onto INT-031's `RecordProvenance` and onto
the note's `document:doc-1 p1` trail from one object, so the rectangle a clinician clicks
and the string the note prints cannot disagree.

**"patient confirms before use" — met.** §3. Type-level, INT-170's shape, INT-170's
vocabulary, and a store that admits the confirmed type alone.

**"accuracy metric on corpus >=90 percent LOINC+unit" — NOT met, deliberately.** Four
things stand between the harness and a figure and not one is an agent's to close:

1. **HB-A13 — there is no corpus, and there is nowhere for one to live.** A named corpus
   needs real Turkish documents; a set we wrote ourselves would measure the harness rather
   than the pipeline, and a figure over it is precisely the accuracy claim invariant 20
   exists to prevent. And a Turkish lab report is a patient's own record, so `06 §5`'s "CI
   carries no PHI, synthetic fixtures only" means the corpus may not be committed to this
   repository at all — which makes *where it lives* a decision to persist a new category
   of personal data, and CLAUDE.md sends that to a human by name.
2. **HB-A10 — no LOINC distribution is committed**, with its standing prohibition riding
   along (do not author Turkish LOINC display names; §12 of the licence assigns any
   translation to Regenstrief).
3. **HB-A2 — no SKRS Turkish lab-name table.** That row already names *"INT-121's `LOINC +
   unit` accuracy target"* as what it blocks, in those words, since 25 Aug 2026.
4. Consequently `NoTerminology` binds nothing and every claimed code is reported in
   `unbound_codes` as `system#index` — never the code itself, because the set of codes on
   one person's report is clinical data.

So the mechanism ships and refuses. `records_corpus_root()` reads
`INTAKE_RECORDS_CORPUS_ROOT`, refuses a relative path (the shape the "just put the
documents in the repo" mistake takes) and refuses outright when unset, naming HB-A13.
`load_records_corpus` refuses an absent, unnamed, undated, unlicensed corpus and one that
disagrees with its own manifest — 17 damage cases, one assertion each.
`LoincUnitMeasurement` **cannot be constructed** without a corpus name, a retrieval date
and a measurement date, so a figure that could travel without its provenance is not
representable; an empty corpus raises rather than scoring 0/0, because every ratio over
0/0 reads as a figure. `describe()` speaks in the measurement voice —
*"…measured on 2026-08-20 against corpus 'x' retrieved 2026-08-01"* — never as a property
of the product.

`LOINC+unit` is deliberately **one agreement over two axes, not two scores**: a case
counts only when the code *and* the unit agree, so a run with every code right and every
unit wrong scores zero, which is the honest answer for a pipeline whose output is a
quantity. The per-axis counts are reported beside the joint one because "the codes are
fine and the units are not" and "both are half wrong" are different engineering problems
with the same joint score. A case the run produced nothing for counts against the total —
silence is not agreement — and a produced case id the corpus does not contain is refused,
because then the run and the corpus are not the same experiment.

**No figure appears in this file, in a README, in a docstring or anywhere else,** because
none has been measured.

## 8. What is deliberately absent

- **No REST endpoint and no migration.** `POST /records/items/{id}/confirm` (`files/03
  §6`) needs a table for extracted items, which is INT-030 schema territory and reaches
  INT-123's pgvector index. This issue delivers the gate the endpoint would enforce; a
  route that stored unconfirmed items would be the larger change and is not in the
  acceptance.
- **No OCR or layout engine.** `NoLayout` is wired for the same reason `NoOcr` is: the
  engine-and-sandbox decision is an open ADR (`files/10 §4`, seccomp-isolated parsing).
  Untrusted bytes meet no parser in this process, and the seam refuses rather than
  returning nothing.
- **No LLM adapter.** INT-124 owns the self-hosted extraction model (`03 §4.9.1` row 9),
  its schema-constrained decoding and the Turkish unit-resolution eval. This module parses
  a completion; it does not obtain one, and it calls nothing.
- **No mobile confirm-card UI.** `ConfirmCard` is the payload; the screen is E08.
- **No `tr` resource key.** Everything Turkish on this path is what a document printed.
