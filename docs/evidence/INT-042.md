## Matrix semantics (invariant 13)

`protocols coverage` (console script wired behind `make coverage-matrix`)
prints one row per branch: **DIRECT** (own `specialty.<branch_id>` pack at
L1+), **CLUSTER** (the cluster's `cluster.<id>` pack at L1+ — "a real,
reviewed protocol, not a fallback", files/09 §2), **MISSING** (nothing
servable; an L0 draft is named in the note but never counted), **EXCLUDED**
(Acil Tıp — pre-visit intake is never used for emergencies, files/09 §1).
Live resolution (`resolve_branch`) fails closed on every other outcome:
`UnknownBranchError` (unmapped MHRS booking — the acceptance's "unknown
booked branch fails a test"), `ExcludedBranchError`, `L0PackServedError`
(invariant 13: an L0 pack resolved for a live session raises) and
`NoServablePackError` (no patient ever runs on bare base.intake).

## Notes and deviations

- **EXCLUDED is a fourth matrix status** beyond the DIRECT/CLUSTER/MISSING
  triple: files/09 §1 row 9 excludes Acil Tıp from pre-visit intake (RED
  routing only; files/12 §1 names `cluster.excluded`), so counting it
  MISSING would be a permanently-red lie and dropping it would violate "no
  branch not in 09 §1". `base.life_threat` still applies to every session
  as the sibling set outside this chain (files/12 §1) — nothing here
  touches it.
- **Exit-code posture, documented per scope:** `--strict` makes MISSING
  branches exit 1; CI runs unstrict until the nine cluster packs land
  (files/09 §2 P1), then flips to `--strict` — recorded in the Makefile
  target comment and the CLI epilog.
- An L0 direct draft with a reviewed cluster pack serves the cluster pack
  (files/09 §2: "a branch without an L1 pack runs its cluster pack"); the
  L0 raise fires whenever the L0 would otherwise be the session's pack.
- Zero clinical content: the taxonomy carries ids, booked Turkish names,
  cluster mapping and visit types only — no default_instruments, no
  red_flag_families, no rules (those are clinician-signed content issues;
  the richer files/09 §1 fields arrive with them).
