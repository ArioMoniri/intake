## The one design decision worth stating

Satisfaction free text is written by a patient about a hospital visit, so it will carry
symptoms and names. `events.payload` is declared *"event body — id-shaped values only, no
PHI (invariant 6)"* because the rollups and the admin console read it. Those two facts
cannot both survive if the comment goes into the event row, so a response is written as
two rows:

| | row | regime |
|---|---|---|
| score + reason | `events` (`event_type='csat.v1'`) | operational, PHI-free, `RET_EVENTS` — unchanged declaration |
| the sentence | `csat_texts.payload` | `EncryptedField` envelope, `CAT_HEALTH`, `BASIS_HEALTH_CONSENT`, `RET_SATISFACTION` |

The rollup path never joins `csat_texts`, and — the stronger half — the reader projects
each payload into `CsatPoint(score, reason)`, a frozen type with no text member. So a
fragment cannot reach an aggregate even if a future writer stopped splitting it out. That
is what `test_a_rollup_of_adversarial_responses_exposes_none_of_it` proves by forcing
exactly that regression.

**Erasure is a foreign key, not a sweeper.** Both FKs on `csat_texts` are
`ON DELETE CASCADE`: `session_id`, because a KVKK m.7/m.11 erasure deletes the subject's
sessions (`intake_api.dsar.shred`, after de-linking telemetry), and `event_id`, because
the files/06 §3 `satisfaction` class destroys event rows
(`retention.executors.destroy_events`). No new executor and no edit to either existing
path — a third sweeper could fall out of step with the two that already exist; a foreign
key cannot. Both directions are tested against real DDL with `PRAGMA foreign_keys=ON`.

## Values refused, and the asks

Nothing invented; three things deliberately left empty.

1. **Survey cadence, sampling rate, prompt schedule — refused.** The blueprint states
   none for CSAT, and INT-242 ("NPS scheduling + clinician pulse survey cadence") owns
   them by name. The routes record what arrives; nothing here decides when to ask.
   *Ask:* none for this issue — INT-242 is the place.
2. **`clinician_pulse.v1` has a rollup but no ingest route.** The acceptance enumerates
   exactly two POST routes. The schema exists (INT-031), the rollup reads real
   `clinician_pulse.v1` event rows and is tested against them, but inventing a third
   endpoint would be inventing the clinician-side survey surface that INT-242 scopes.
3. **Retention window — not invented, because one already exists.** files/06 §3
   "Satisfaction: with account" is a *sourced* row (`retention_policy.yaml`, `status:
   sourced`, `kind: with_account`, `dsar_erasable: true`). `RET_SATISFACTION` quotes it.
   Had it been absent this table would have shipped behind a closed gate on the INT-223
   `guardian_link` precedent.

Two boundaries this issue could not close, both named rather than worked around:

- **DSAR *export* does not yet include the satisfaction comment.** Erasure reaches it
  (the session cascade); export is assembled table-by-table in
  `services/api/src/intake_api/dsar/`, which this issue was scoped out of. The comment is
  the patient's own words about their own visit, so it belongs in an m.11 access
  response. *Ask:* a follow-up on INT-037's surface to add `csat_texts` to the export
  assembler. Nothing is lost meanwhile — the row is erasable and reachable.
- **`scripts/ci/coverage_thresholds.yaml` is hook-protected** (`guard-protected-files.sh`
  requires an ADR), so `services/metrics` has no declared floor row. The floor is
  enforced concretely instead: `check-py` runs
  `--cov=services/metrics/src --cov-branch --cov-fail-under=90`, and
  `test_check_py_type_checks_and_covers_the_new_service` pins that exact string. *Ask:*
  whoever next opens an ADR touching the floors file should add
  `services/metrics: 90` to it.

## Invariant notes

- **6** — the response body is `{session_id, recorded}`; the audit entry is
  `session:<uuid>` under `scope:satisfaction`; the 422 handler already strips `input`/`ctx`
  (tested with the adversarial sentence in the rejected body). The event payload is built
  with `model_dump(exclude={"text"})` rather than a hand-built dict, so a future schema
  field has to be considered here instead of flowing into a PHI-free column.
- **13** — `csat.score`, `csat.reason`, `nps.monthly` and `clinician.pulse` moved from
  `status: planned` to `status: live` in `observability/metrics_catalog.yaml`, which the
  catalogue's own honesty test forces the moment `intake_metrics.metrics` constructs them.
  Labels are as files/08 §4 states: one closed enum on `csat.reason`, none on the other
  three — no tenant, clinic or clinician label anywhere, so no dashboard can re-slice a
  satisfaction series down to one person (files/08 §0c F9).
- **15** — `services/metrics` is a new service: `mount_health` + `mount_http_metrics`
  + `setup_otel("metrics")`, `docs/slo/metrics.yaml`, and a `metrics` row in
  `observability/registry.yaml` with `probe: http_health`. `/readyz` is **503** on an
  unwired process: `events_db` is a named check that reports not-ready when
  `INTAKE_METRICS_EVENTS_DB_URL` is unset, rather than a stand-in that answers healthy on
  a process that can roll nothing up.
- **18** — every new column carries `inv(category, purpose, basis, retention, recipients)`.
  `RET_SATISFACTION` is new and quotes the sourced files/06 §3 row.
- **20** — a figure cannot be constructed detached from what produced it: every rollup
  type carries its `Cohort` (tenant + window) and a `measured_at`, and `Cohort` refuses a
  window that does not move forward or a bound without a timezone.
  `test_no_satisfaction_figure_appears_in_the_regulatory_or_legal_trees` scans
  docs/regulatory/ and docs/legal/ for CSAT/NPS figures and memnuniyet percentages.
- **k ≥ 10** (files/06 §8; files/08 §0c F9; the `experience` control line) — suppression
  is **total** below the floor: no mean, no distribution, no promoter split, only the
  count that says why. A suppressed rollup publishes nothing at all — not a zero.
