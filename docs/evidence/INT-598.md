# INT-598 — Vizitlerim's chips show the note's real state

GitHub #1015 · Sec-Row: `mobile` · branch `int-598-visits-chips` from main `5d6984a7`. Found in
INT-594 (#1007, PR #1013).

## 1. The defect

`apps/mobile/src/app/(tabs)/visits/index.tsx` gave each card's chip and spoken name the raw
`noteStatus`. A hospital-feed visit always carries null there (`syncVisits` in
`lib/auth/api.ts`), so an OTP account's list showed no status at all. That held even for a draft
on the phone, and even for a note the server had confirmed. The visit detail already resolved
status with `effectiveStatus`, and Bugün does too after INT-594.

## 2. What changed

`visits/index.tsx` only; no copy changes:

- Each row is now a `VisitRow` component.
- It reads the draft from the session (`notes[visit.id]`) and its own outbox verdict
  (`useDelivery(visit.id)?.stage === "delivered"`).
- It resolves `effectiveStatus(visit.noteStatus, note, delivered)` and hands that one value to
  the chip (`statusOverride={status}`) and to the card's accessible name
  (`cardLabel(visit, status)`).
- The list's Yaklaşan and Geçmiş groups and the calendar's day list all render through the same
  row.

The chips use the existing `status.*` keys, so the delivery-claim test is unchanged.
`status.sent` ("Gönderildi") renders only through StatusChip and StatusLadder (buildCopy.test.ts).

## 3. Tests

`apps/mobile/e2e/visitsChips.spec.ts`, 10 tests.

**The rule.**
- A feed visit with nothing on the phone has no chip.
- With answers it shows "Taslak".
- **Near miss:** a sent note the server has not confirmed stays "Taslak".
- **Near miss:** a confirmed delivery without the patient's send is not "Gönderildi".
- A confirmed note shows "Gönderildi".
- A dev fixture keeps its own ladder step.

**The screen.**
- Each row reads its outbox verdict and its draft.
- The chip and the spoken name carry the resolved status.
- **Near miss:** no raw `visit.noteStatus ===` and no `statusLabelKey(visit.noteStatus)`. The
  pattern catches the line the list shipped with.
- Every group renders the same row.
