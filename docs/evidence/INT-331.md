# INT-331 — One fail-closed reduce-motion store, bridged to Reanimated

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile · **GitHub:** #530 · **Depends on:** INT-330 (merged)
**Spec:** `docs/design/motion/motion-verification.md` §3 S-2 and §4 MOTION-2, with the
shape in `motion-system-spec.md` §4 (both on branch `merge-305`, not yet on `main`
when this was written).

## Problem (S-2, high, live)
- `src/lib/a11y/prefs.ts` started every `useReducedMotion()` consumer at
  `useState(false)` until its own `AccessibilityInfo.isReduceMotionEnabled()`
  promise resolved. With the OS setting on, the dialogue's `PulseDot` loop and
  the first navigator transition could animate before the answer arrived.
  Each call site also made its own OS read and registered its own listener.
- Reanimated adds two more fail-open paths. Its `useReducedMotion` reads only
  the OS, never the in-app switch (INT-260). Its "follow the system" mode is
  captured once when the module loads
  (`react-native-reanimated/src/ReducedMotion.ts`) and never sees the in-app
  switch or a later change in Settings.

## Change
- New pure module `apps/mobile/src/lib/motion/policyStore.ts`, with no
  react-native import:
  - `ReduceMotionSource`: `read`, `onChange`, `onForeground`, as in the spec's
    §4.2 shape.
  - `createReduceMotionStore(source)`: `subscribe` and `getSnapshot(): boolean | null`.
    - The first subscriber starts one read and one listener, and later
      subscribers share them.
    - `null` means the OS has not answered. A read that is refused, throws, or
      returns a non-boolean leaves the snapshot where it was, so it stays
      `null` (reduced) or keeps the last known answer.
    - A change event reaches every subscriber. Reads and events are ordered by
      a ticket, so a read that settles after a newer event or read cannot undo
      it.
    - It re-reads on return to the foreground.
    - The last unsubscribe releases both OS listeners and forgets the answer.
      With nothing listening, a change could be missed, so the next subscriber
      starts from reduced and makes a fresh read.
  - `deferredReduceMotionSource(load)`: loads the device adapter on first use,
    once. A loader that rejects leaves every read refused (reduced). A
    listener released before the adapter arrives is never attached.
- New `apps/mobile/src/lib/motion/native/reduceMotionSource.ts`: the thin
  adapter over `AccessibilityInfo` (`isReduceMotionEnabled`,
  `reduceMotionChanged`) and `AppState` (a transition to `active`). It is
  reached only through the lazy `import()` in `prefs.ts`, the same pattern
  `KioskGate` uses for `nativeKiosk.ts`.
- `apps/mobile/src/lib/prefs/appearance.ts`:
  `reducedMotion(appOverride: boolean, osReduced: boolean | null)` returns
  `appOverride || osReduced !== false`, so unknown means reduced.
- `apps/mobile/src/lib/a11y/prefs.ts`: `useReducedMotion` keeps its name and
  import path. It is now `reducedMotion(prefs.reduceMotion, useSyncExternalStore(store.subscribe, store.getSnapshot, store.getSnapshot))`
  over one module-level store. The server snapshot (static web rendering) is
  the same `null`, so it is reduced. No call site changed.
- `apps/mobile/src/app/_layout.tsx`: `ReanimatedMotionPolicy` renders
  `<ReducedMotionConfig mode={reduceMotion ? ReduceMotion.Always : ReduceMotion.Never} />`
  as the first child of `AppearanceProvider`. Reanimated's `ReducedMotionConfig`
  calls `ReducedMotionManager.setEnabled` in an effect keyed on `mode`
  (`react-native-reanimated/src/component/ReducedMotionConfig.tsx`), so every
  Reanimated animation follows the combined policy and its live changes. No
  new dependency: `react-native-reanimated` 4.5.1 has been in
  `apps/mobile/package.json` since INT-130. This is its first import in `src`.

## Tests (TDD)
- New `apps/mobile/src/lib/motion/policyStore.test.ts` (London school, with a
  fake OS source). It has the seven MOTION-2 tests, verbatim:
  - "reads the OS once however many consumers subscribe"
  - "an unanswered OS read resolves to reduced"
  - "a rejected OS read resolves to reduced, never to motion" (also covers a
    non-boolean answer and a source that throws)
  - "a failed re-read keeps the last known answer" (both known values)
  - "a change event updates every snapshot"
  - "re-reads on return to foreground"
  - "the last unsubscribe releases the OS listener"

  Four more tests cover behaviour this implementation adds:
  - "a read that settles after a newer change event does not undo it"
  - "a native source that fails to load resolves to reduced"
  - "loads the adapter once, and forwards the OS through it"
  - "an unsubscribe before the adapter loads attaches nothing"
- Added to `apps/mobile/src/lib/prefs/appearance.test.ts`:
  - "unknown OS answer is reduced"
  - "the in-app switch still only adds reduced motion"

  The existing "is the OR of the OS setting and the app's own switch" test is
  unchanged.
- New `apps/mobile/e2e/motion.spec.ts`, which scans `src`, `e2e`, `plugins` and
  `app.config.ts`. It excludes itself, because its mandated titles name what
  they forbid. Its forbidden literals and non-vacuity samples are assembled
  from parts. The three spec tests, verbatim:
  - "nothing imports useReducedMotion from react-native-reanimated": catches
    named imports, re-exports, `require` destructuring and namespace member
    access, each proven on a sample.
  - "no ReduceMotion.System anywhere": catches `.`, `?.` and `["…"]`
    spellings, each proven on a sample.
  - "the root mounts ReducedMotionConfig from the app policy": both names are
    imported from Reanimated. The mode is `<flag> ? Always : Never`, where the
    flag is `const <flag> = useReducedMotion()` imported from
    `@/lib/a11y/prefs`. The component hosting it is mounted inside
    `<AppearanceProvider>` by a different component. It is the only
    `ReducedMotionConfig` in the app.

  One test is added beyond the spec's list: "the app hook reads the one store,
  and only the native source asks the OS". It checks that there is exactly one
  `createReduceMotionStore(` call site (in `prefs.ts`), and that the only file
  naming `isReduceMotionEnabled` or `"reduceMotionChanged"` is the native
  adapter. The hook body uses `useSyncExternalStore(` and no `useState(`. No
  static import reaches the adapter, and `prefs.ts` loads it with `import()`.
  This is the source-level half of "one OS read and one listener, whatever the
  consumer count".
- `e2e/appearance.spec.ts` is unchanged and green. Its "five call sites" test
  still finds every `useReducedMotion()` caller importing from
  `@/lib/a11y/prefs`.

## Device check: not recorded
No release-build device run is recorded in this PR. The felt change is
confined to the window before the first OS answer, which is now reduced
instead of animated. How long that window lasts on a device has not been
measured. The owner's two reference devices are still unnamed (see INT-330's
evidence).

In a dev build, Reanimated's `ReducedMotionConfig` logs one `console.warn`
when it mounts ("Reduced motion setting is overwritten with mode …"). That
warning is the intended override announcing itself. It is not suppressed
here.
