## Route contracts as shipped (matching the merged INT-132 seam verbatim)

- `GET /v1/consents` → `{scopes: [{scope, reason, version, text_hash}],
  texts: [{purpose, version, text_hash, body}]}`; one scopes row per
  non-parameterised files/06 §2 purpose in registry order; reasons are the
  pinned INT-038 set `granted|default_on|unbound|absent|withdrawn|stale`
  (the client's closed REASONS list). texts include the share family text
  (the client drops rows it has no purpose for). Patient-only; read audited
  as `api.consent.read`.
- `POST /v1/consents/grant {scope, version, text_hash, at?}` → 201
  `{scope, version, text_hash}`; 409 `consent_text_changed` when the
  submitted pair no longer matches the served text (checked before AND after
  the bind — a mid-flight text move rolls the row back); 409 `text_missing`
  when no text exists (no text, no grant); `at` becomes evidence_ref
  provenance (`client-at:<utc>`), never the grant instant.
- `POST /v1/consents/withdraw {scope, at?}` → 200
  `{scope, withdrawn_scopes, revoked_share_ids}`; instant, cascaded and
  audited by the INT-038 service; `at` accepted for seam compatibility only —
  the revocation instant is the server's.
- Unknown purposes (`lane:acoustic`, bare `share`, anything off the closed
  list) → 422 `{error: purpose_unknown, scope}` — the id and nothing else.

## The consent_management scan design

`consent_guard.ConsentManagementDeclaration` mirrors `PreAuthDeclaration`:
these routes are ABOUT consent, so requiring a consent scope would be
circular (a snapshot that 403s on the very staleness it exists to report
could never trigger a re-prompt). The scan accepts the marker ONLY under
`CONSENT_MANAGEMENT_PREFIX = "/v1/consents"`, matched at a path-segment
boundary (`/v1/consents` or `/v1/consents/...` — a lookalike
`/v1/consentsish` does not qualify, pinned by a negative control). Silence
still fails: a route with neither a policy, a caged pre_auth marker, nor a
caged consent_management marker stays in `unguarded_data_routes`.
`consent_management_routes()` pins the exact marked surface.
