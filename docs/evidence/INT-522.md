## What CD-05 says

CD-05 (status `active`, verifier `agree`, D18 scope: simulated-patient stress
testing only). Both active chest-pain rules anchor on `chest_pain.onset_at`,
which holds the most recent episode, or "ongoing now" (NICE CG95 1.2.1.1). The
anchor is asked as one scripted closed choice with NICE's four bands. The
engine's tense windows are calendar days, and `now` and `today` are both the
reference day (`temporal_within`).

| Choice | CD-05 `resolves_to` | Status | Built as | Record basis |
|---|---|---|---|---|
| şu anda var | `reference_day` | active | reference day | `decided` |
| son on iki saat içinde | `reference_day` (deliberately, even across midnight) | active | reference day | `decided` |
| on iki saatten önce ama son üç gün içinde | the invariant-17 literal; `while_draft.resolves_to: reference_day`, `never_unknown: true`, `record_label: while_draft_resolution` | draft_needs_source | reference day (the while-draft resolution) | `while_draft_resolution` |
| üç günden daha önce | `reference_day_minus_3` | active | reference day − 3 | `decided` |
| answer fitting no choice, or "bilmiyorum" (`unresolved_answer`, `answer_state: UNCLEAR`) | `reference_day` | active | reference day | `unresolved_answer` |

Also from CD-05: `ambiguity: more_acute`, `document_may_feed_anchor: false`,
`council_may_fill: false`. The anchors of the paediatric-airway and crisis
rules are `draft_needs_source` and are not resolved.

Through the tense windows this gives, as CD-05 says:
- The first three bands fire the now-tensed K2 and the today-tensed SARI
  sibling wherever their gates hold.
- "üç günden daha önce" fires neither, while a draft `within_7d` rule would
  still read True.

## Left to the D18 lane (nothing new)

CD-05's own open item is unchanged and is not built:
`value.choices[2].resolves_to` for "on iki saatten önce ama son üç gün içinde"
is the literal `TODO: resolving a last episode twelve to seventy-two hours old
onto the calendar-day tenses requires clinical sign-off`, under
`status: draft_needs_source`.

CD-05's `source_gap` says why it is open. NICE CG95 1.2.1.8 asks for urgent
same-day assessment, but K2 has only tense `now`, and the Tense enum has no
seventy-two-hour member. Closing it needs a same-day cardiac-features arm and a
tense member, which are rule and DSL changes for the signing clinician.

`protocols.anchor_choices` refuses to build if that entry stops being the open
literal without its status changing. A re-decision therefore cannot slip in
unseen, and the record labels every use of the interim day
`while_draft_resolution`. This build adds no new clinical value and no new
open item.

## Hedged and unresolved answers

The issue's test bullet says an Unknown or hedged answer "stays Unknown and
the rule's Unknown branch behaves as authored". CD-05 also decides what
happens when an answer never fits a choice: it is "recorded UNCLEAR and
resolved to the more acute reading, the reference day". Both are built, in
order. Leaving that answer Unknown would have been a clinical re-decision
against CD-05, and in the under-triage direction.

1. **A hedged answer** ("emin değilim") binds nothing. The model may answer
   only an authored choice, so it asks to clarify. The anchor stays
   `ASKED_PENDING` and reads Unknown. With a cardiac character, K2's `when` is
   True and `when ∧ anchor` is Unknown, so the rule does not fire (its Unknown
   branch). The scripted `follow_up_tr` is asked verbatim (invariant 10), and
   that Work is not evaluated. An answer to the follow-up that is a choice
   binds that choice's day.
2. **An answer that never fits.** Once the bounded clarification is spent
   (files/13 §11.1, two follow-ups), the engine records UNCLEAR (its existing
   give-up state, which is CD-05's `answer_state`). CD-05 then resolves the
   anchor to the reference day, the Work is evaluated, and K2 fires where its
   gate holds. The record says `unresolved_answer` with no choice.

The interval this introduces is up to two scripted follow-ups between a first
"bilmiyorum" and the RED. That is the engine's existing bound for every slot,
not a new value. Whether CD-05 meant the first such answer to resolve at once
is a question for the D18 lane. It is recorded here and not decided.

## Residuals (no id minted; for the orchestrator)

1. **The app's API hop** (`services/api/.../triage_hop.py`, INT-446) evaluates
   the answers the device posts. Today the app does not ask the onset (its
   packs are ask-only). If it ever does, it must post the CD-05 day and not the
   choice, or the hop must resolve it through `protocols.anchor_choices`. A
   choice string there reads as an unparseable anchor (Unknown).
2. **The reference time's producer.** The runtime stamps nothing itself: both
   composition roots take `reference_time` from their caller (the session
   router's builders; `scripts/voice/live_smoke.py` passes
   `datetime.now(UTC)`). Whichever worker composes live sessions supplies it
   from its clock at session start. The reference day is then that time's own
   calendar day, so the caller's timezone decides which day "today" is. Today
   the call sites are UTC.
3. **CD-05 interpretation for the D18 lane:** whether the first
   "bilmiyorum" should resolve immediately, rather than after the engine's two
   scripted follow-ups, as built (see *Hedged and unresolved answers*).
