## Honest scope (why `doing`)

- **services/api has not landed on main** (no `services/` directory exists
  yet), so `http_requests_total`/`http_request_duration_seconds` had no
  emitter anywhere. Rather than catalogue series nothing serves, the shared
  middleware `mount_http_metrics` now emits them from
  `packages/intake_platform` — the same place `mount_health` lives — and the
  api mounts both when it lands. The every-service-dir-has-an-SLO-file gate
  binds the moment the first directory under `services/` appears.
- `docs/slo/voice-runtime.yaml` and `docs/slo/workers.yaml` are NOT written:
  those services do not exist, no metric they would reference is emitted by
  any code, and an SLI over series nobody serves would be an invented value.
  They follow with their services, through the same schema and generator.
- "golden-signal dashboards provisioned" — the dashboard exists as code and
  is test-bound, but nothing provisions it into a running Grafana: no live
  Prometheus/Grafana exists in CI, and alerting is untested against a live
  stack until the INT-023 observability deploy.
- sec_row `monitoring-contract` (files/10 §6): endpoints unchanged
  (INT-010), SLOs + burn-rate alerts + runbook + dashboard are this issue;
  probes remain INT-022.

### Found and fixed

1. **Six SLO files had objectives and no alert.** `prometheus-rules.yaml` was generated
   from `api.yaml` alone. The objectives of voice-runtime, probes, metrics, learning,
   langfuse and siem could burn to zero with nobody paged. The rules, the dashboards and
   18 runbook headings now exist for all six.
2. **`services/probes` never emitted the series its SLO reads.** `docs/slo/probes.yaml`
   is written against `http_requests_total{service="probes"}`, and the service never
   called `mount_http_metrics`, so the SLO could never be breached. It is fixed in
   `intake_probes/app.py`. `http_emitter_problems` now holds every HTTP SLI to an emitter
   in its own service directory (an AST scan resolving literals and module constants),
   and `test_the_probes_service_serves_its_own_request_series` proves it end to end.
3. **The 8 cost alerts linked no runbook.** `intake_platform.cost.rules` now adds a
   per-kind link, and `docs/runbooks/cost-budgets.md` is new. `cost-rules.yaml` was
   regenerated; `test_cost_rules.py` still passes, 13 of 13.
4. **Nothing read `sec_audit_chain_ok`.** files/08 §5 pages on audit-chain verification
   failure, and the INT-016 job's docstring says it pages. The new
   `AuditChainVerificationFailed` (`sec_audit_chain_ok == 0`, page) and
   `docs/runbooks/audit-chain.md` cover it.
5. **The gates themselves were weaker than they read.** `slo.metric_references` only sees
   a name followed by a selector, so a bare-name rule such as
   `sec_secret_rotation_due_days < 0` was invisible to it. The first slice's runbook test
   also dropped `_` when slugging, so an anchor like `langfuse-trace_emission-fast-burn`
   could never have resolved. `intake_platform.alert_rules.promql_series` and
   `github_slug` replace both, and each has near-miss tests.

### Found and recorded, not fixed

- **`docs/slo/workers.yaml`.** `services/workers` does not exist and no backlog row
  creates it. The work it would host — upload promotion, retention destruction,
  event-bus consumers, notification dispatch — is library code that no process runs.
  files/08 §4 A gives the tier one objective, note ready within 60 s for 99 %, but its
  series (`note_time_to_ready_s`) is planned, not emitted. An SLI over series nobody
  serves is an objective nobody could breach. **Awaiting the owner**
  (`docs/backlog/blockers.md` INT-021). No HB id is minted here.
- **admin-web has no probe row.** files/08 §6 names `/healthz` plus a CSP header
  assertion, and `app/healthz/route.ts` serves the first half. A registry row changes the
  recorded runner sweep (`tests/fixtures/reliability/probe_sweep.json`, held equal to the
  registry by `tests/admin/test_reliability_console.py`) and the e2e payloads recorded
  from it. Those have to be re-taken on the recording host. A CSP-asserting probe id also
  does not exist yet. This is engineering follow-up, recorded in the coverage manifest.
- **One-shot job gauges reach no Prometheus.** `sec_secret_rotation_due_days`,
  `sec_audit_chain_ok` and the auto-disable `admin_offboarding_total` live in the process
  that ran the tick. `docs/runbooks/key-rotation.md` already says so for the rotation.
  Until a scheduler runs the jobs inside a scraped process, their alerts have no series.
  Recorded as `gaps.alert` per job.
- **A readiness 503 burns the HTTP availability budget.** The shared middleware counts
  `/readyz` answering 503. `learning`'s readiness is permanently not-ready until the
  clinical lead states the effect-size floor (`PromotionThresholds.from_blueprint`), so
  its SLO would burn in any deployment that probes readiness. `slo-burn.md` tells the
  on-call how to tell the two cases apart. Whether `/readyz` belongs in these SLIs at all
  is an SLI design decision for the owner and SRE, not a target this close-out may
  change.
- **Backup age.** files/08 §5 pages on backup age over 30 min, but `sec_backup_age_min`
  is planned and the backup job emits no metric. The `backups` probe row is today's only
  signal.
