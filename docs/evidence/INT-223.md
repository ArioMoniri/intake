# Evidence — INT-223 · Minor & guardian rules engine (age gates, guardian consent, adolescent policy) as code

Acceptance (docs/backlog/issues.yaml, verbatim): *"age from verified DOB;
under-18 requires guardian account+consent; adolescent private-section share
policy per 06 §6; tests for each age band"*. Legal: TMK-339, HHY-24.

What landed is the **mechanism**, with every legally contested value left
empty and fail-closed rather than guessed (HUMAN_BLOCKERS rules 1 and 2):

- `intake_platform.consent.minors` — age banding from a verified DOB, actor
  resolution per scope, adolescent-private visibility, and `POLICY_TABLE`:
  the whole rule set as data, each row either `SET` with the files/06 §6 (or
  statute) citation, or `AWAITING_HUMAN` with the named human, the one
  sentence they must answer, and the fail-closed behaviour actually
  implemented meanwhile;
- `intake_api.consent_guard.ensure_age_actor` — the age axis of the **same**
  enforcement point, run before the consent ledger so a minor's own grant
  can never answer for the guardian's (invariant 4, no forked refusal path);
- `intake_platform.consent.guardian` + the `guardian_links` table and
  migration `0003_int223` — built, migrated, RLS-protected, and **shut**:
  persisting a guardian↔minor relationship is a new personal-data category,
  which CLAUDE.md makes a stop-and-ask, so the `guardian_link` safety flag
  (default False) refuses the write path *and* the read path, and every
  column carries an `awaiting-human` basis and retention (invariant 18).

No consent text was authored; `docs/legal/` is untouched. No DOB is
collected or persisted by this issue — `intake_api.age_context.NoAgeRecordSource`
truthfully reports that none exists, which the engine maps to
`no_dob_recorded` (the minor regime is not asserted, the ledger alone
answers).

Sec-Row: companions

files/10 §9 **"Companion / guardian profiles"** (threats:

plus a typed age refusal on the single enforcement point → signals:

tests/legal/test_minor_rules.py).
