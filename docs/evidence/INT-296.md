# Evidence — INT-296 · Session locale: one language per session, chosen rather than detected, and a resource layer that refuses an incomplete one

Date: **3 September 2026**. Branch `int-296-session-locale`, off `origin/main`.

## The shape of this issue

The owner asked for languages beyond Turkish. INT-296 is the only one of the six
issues in that set (INT-296…302) that can be built before a human supplies
content, and it lands with **no second language enabled**. That is not a partial
delivery — it is CLAUDE.md's own instruction for an open blocker, in its own
words: *build the mechanism, wire the gate, make it fail closed, leave the
content empty.*

Four blockers govern what a second language costs, and none of them is an
agent's to answer: **HB-O5** (which languages, owner), **HB-C19** (who signs
their clinical text and do they read it, clinician), **HB-L23** (what a
translated `aydınlatma metni` legally is, counsel), **HB-L24** (instrument
licences and validation, per language). A fifth was filed by this issue —
**HB-L25**, below.

**Invariant 5 is not weakened anywhere.** `tr` remains the source of truth and
remains the default. The lint generalises from *"`tr` must exist"* to *"`tr`
must exist **and** every ENABLED locale must be complete against it"*, which is
strictly more, never less.

## Acceptance, line by line

- [x] **"a session carries exactly one locale, fixed at the start and changed
  only by an explicit act… recorded on the session so the note, the audit entry
  and every metric label agree"** — `SessionLocale` is a frozen two-field value
  (`code`, `source`); `sessions.locale` is a non-null column with a full
  invariant-18 annotation (migration `0011_int296`); `METRIC_LABEL_NAME` is
  `"locale"` and `SessionLocale.metric_label` can only ever return a registered
  code. See *One caveat, stated plainly* below for what "metric label" does and
  does not mean here.
- [x] **"the language is chosen by the patient, never inferred from speech…
  detection may at most OFFER a switch the patient confirms, and the offer is
  unreachable while a red-flag script is in flight"** — `LocaleChoiceSource` has
  three members and no fourth meaning *inferred*; `offer_locale_switch` raises
  `RedScriptInFlight` and its `red_script_in_flight` argument is keyword-only
  with **no default**, asserted from the parsed source; a source-level scan
  fails the build if any recogniser-shaped name reaches the package.
- [x] **"a locale is offered only when it is complete, and completeness is a
  build property… the `tr` lint generalises to every ENABLED locale… a locale
  that is not complete is simply absent from the chooser rather than falling
  back"** — `tests/release/test_i18n_complete.py` now reads the registry and
  holds every enabled locale complete against `tr`, **in both directions**: a
  claim the tree does not support fails, and so does completeness the registry
  withholds. Proven by perturbation, below.
- [x] **"there is no per-string fallback, and a test asserts its absence over
  the whole tree… the resolver has no fallback parameter, takes no default, and
  raises on a miss"** — asserted against the modules' own `ast` parse, not their
  behaviour: no fallback-shaped parameter name anywhere in the package, **no
  default argument at all** on any function in the package, no two-argument
  `.get()`, no `except` that swallows a lookup, no `or` in the resolver, and
  `resolve` has exactly `(catalogues, locale, key)`. The TypeScript half asserts
  the same over `locale.ts` with comments and string literals stripped, so prose
  that *discusses* a fallback is not mistaken for one.
- [x] **"the chooser offers a locale only when the pack that will be served
  carries signed content for it… the two conditions are separate fields rather
  than one flag"** — `ui_catalogue_complete` and `clinical_signoff` are two
  fields on `LocaleRegistration`, and `offerable_for_app` / `offerable_for_intake`
  are two properties. Proven by perturbation, below.
- [x] **"no locale is enabled by this issue except `tr`: the mechanism ships
  with exactly one locale registered and the registry empty of others"** —
  `enabled_locales() == ("tr",)`, pinned in both test files, and `registry.py`
  is required by test to name HB-O5, HB-C19, HB-L23 and HB-L24 so a widening
  edit cannot be made without reading them.

## What `clinical_signoff` means here, and what it does not

HB-C1 is still open: all six fields of `base.life_threat.yaml`'s own
`clinical_signoff` block are `null`. It would therefore have been an invented
value to claim in this registry that Turkish clinical content is *signed*.

It does not claim that. The registry field answers **HB-C19's** question and only
that one — *"who signs the clinical text for that language, and do they read
it"* — and HB-C19's own `blocks` column reads *"Every locale except `tr` running
an intake"*, which is the register of record stating that Turkish's answer is
already settled. The citation is carried in the value
(`recorded_in="HUMAN_BLOCKERS.md HB-C19 — …"`), and
`test_the_locale_signoff_is_not_a_second_copy_of_the_pack_signoff` fails the
build if the two are ever conflated. Whether a given *pack* is signed remains
HB-C1 and the compiler's serve interlock. Both gates must hold; a locale being
offerable never makes an unsigned pack servable.

## The new blocker — HB-L25

`sessions.locale` is filed as `operational_metadata` under the contract basis,
and that is defensible for exactly one reason: `tr` is the only registered
locale, so the column records the *service's* language and states nothing about
the patient. The moment a second locale is registered it becomes a fact about a
person, and a language choice can proxy ethnic origin — KVKK m.6 special
category, which needs açık rıza rather than m.5/2-c. CLAUDE.md makes a new
category of personal data a stop-and-ask, so it was not decided here. The
annotation says so in its own purpose text, and HB-L25 carries the one sentence
counsel must answer before a second locale is enabled.

## One defect this change found in an existing test

`make check` first came back **rc=2** on
`tests/experience/test_csat_flow.py::test_the_text_row_cascades_away_with_its_session_and_with_its_event`
— `NOT NULL constraint failed: sessions.locale`. Not a flake and not a wrong
column: that test builds a **sqlite DDL clone**, and `sqlite_ddl_clone()`
strips every non-`DateTime` `server_default`, so neither the ORM-side nor the
server-side default runs on its raw `INSERT`. The file already carried the same
note for `attribution` from INT-133. Fixed the same way — `locale` named in the
insert with `'tr'` — and the comment updated to say that both defaults are
stripped, which is the part the original comment left out. The four other raw
`INSERT INTO sessions` sites run against the real migrated Postgres, where
`DEFAULT 'tr'` applies, and were not touched.

## What was not done, and why

- **No new Prometheus series was added.** Invariant 13 makes
  `observability/metrics_catalog.yaml` complete against `files/08 §4`, and
  `tests/observability/test_metrics_catalog.py` pins the §4 id count — so a new
  `locale`-labelled family would have required inventing a spec id in a
  blueprint file. What this issue delivers is the *label source*: a name checked
  against the `PHI_RISK_LABEL_NAMES` denylist and a value that can only be a
  registry code. Wiring it onto a series is INT-297…302's to do once §4 names
  one.
- **`t(key, locale)` in `lib/i18n/index.ts` was not removed.** Its two callers
  (`lib/health/format.ts`, `components/VisitCard.tsx`) thread one session locale
  through a formatter rather than mixing languages, and removing the parameter
  is a refactor this issue did not ask for. The hazard it represents is closed
  by gate instead: `locale.test.ts` fails the build if any shipped source passes
  a **literal** locale to `t()`, which is the shape that would assemble one turn
  out of two languages.
- **`en.ts` was neither removed nor registered.** It is INT-253's reviewer
  mirror of the Turkish source of truth, held to key parity by the tests that
  already existed. A catalogue existing is not a language being offered, and
  registering English would answer HB-O5 and HB-C19 on their owners' behalf. The
  visible consequence is that the Me screen's language row now renders one pill
  instead of two — which is the honest state of this product.
