## Live-bug fix — empty extract landed as a silent success (int-199-fix-prefill)

Coordinator repro (iOS sim, Expo Go, tunnel Metro): the voice flow ran end to
end but the confirm flow landed at step one of nine with no pre-selected
suggestions, no "Söylediğiniz:" provenance and no failure notice — exactly
like manual entry. Diagnosis against the live daemon: the app-shaped request
(`{transcript, pack, questions:[{id,kind,options}]}`, pack "İç Hastalıkları")
against the WARM daemon returns all eight candidates with quotes — the wire
contract matches, ruling out a request mismatch, probe caching (none exists)
and the abort wiring (extract answered). But the daemon's /health stays HTTP
200 through its restart window (`llm_upstream` is a separate payload field
the probe never reads), and in that window /extract answers a VALID envelope
with zero usable candidates; the reducer then recorded `candidates` with an
empty prefill map as a SUCCESSFUL voice run (`failed: false`) — silent manual
landing, indistinguishable from typed entry. Honest rule restored: an extract
that yields no usable suggestion is a FAILED voice attempt.
