## Placement blocker — one human step remains (fail-closed until then)

`.github/workflows/security.yml` is hook-protected (07 §3.8 / §F rule 2), and
both `guard-protected-files.sh` and the agent session's permission classifier
refused its creation from the INT-019 build session — which is the protection
working as designed: protected gate files move only under the human-sanctioned
`ALLOW_PROTECTED=1`. The byte-final workflow content is therefore committed at
`scripts/ci/security_workflow.yml`, every content assertion in
`tests/ci/test_security_gates.py` pins it, and one test —
`test_workflow_is_installed` — stays RED on this branch until a human runs:

```
ALLOW_PROTECTED=1 git mv scripts/ci/security_workflow.yml .github/workflows/security.yml
```

(delete nothing else; the tests then pin the installed file, and while both
copies exist they must be byte-identical). The branch cannot go green — and
the issue cannot close — without the sanctioned placement actually happening.
This is invariant-14 fail-closed behaviour, not a workaround: nothing merges
with the gate set silently absent.

declared metadata only (dist-info METADATA, package.json license fields) —
a tripwire for AGPL/SSPL/unknown, not legal review. Documented per-package

## Deferrals (documented, never silently dropped)

- **trivy image + cosign image signing**: no container images are built yet.
  The tags-only `sign-and-attest` job signs what exists (the SBOM, keyless
  sign-blob + SLSA provenance via actions/attest-build-provenance) and its
  comment marks the exact extension point for images and protocol bundles.
- **schemathesis fuzz**: services/api does not exist, so no OpenAPI schema is
  available offline and CI never makes live calls; wired with the api issue.
- **eslint-plugin-security**: workspace eslint already runs in ci.yml
  check-ts. Wiring the plugin needs a root package.json + pnpm-lock.yaml
  change while several parallel branches are editing the workspace — a merge
  hazard for a lint rule set, so it lands as its own follow-up, not half-wired
  here.
- **PHI scan scope**: files/10 §6 (25 Aug revision) moves the PHI-pattern scan
  to *runtime* (inv. 36); the INT-019 acceptance line predates that and asks
  for the fixtures scan, which is what this delivers. Both are wanted: the
  runtime redaction path is INT-015/INT-176 territory; this gate keeps the
  *repo* PHI-free.
- **PHI allow-list**: the de-id engine's own labeled corpus
  (tests/fixtures/deid/, tests/fixtures/logs/app_lines.txt) is deliberately
  checksum-valid synthetic data (ATTRIBUTION.md) — it is the redactor's test
  bench, so it is allow-listed with a pinned, shrink-only set exactly like
  no_placeholders_allow.txt. Everything else under tests/fixtures/** and
  docs/** scans clean today.
