The base score is **computed from the CVSS vector** (v3.1 §7.1 plus the

would be the cheapest way through the gate.

*everything*, including a LOW advisory, while looking like it was grading. The
computation replaced it.

## Signing: which half is exercised and which is not

`cosign` keyless signing derives its identity from the OIDC token GitHub
Actions mints. **There is no way to exercise it on a developer machine, and it
was not faked.** The tags-only `sign-and-attest` job is the authority, and it
has never run (HB-I9).

- **Protocol bundles — the selection half is proved.**
  `scripts/ci/protocol_bundles.sh` enumerates every file under the compiler's
  emit root, which is what a tag signs, and **fails closed on an empty root**:
  "signed nothing" and "signed everything" print the same green tick otherwise.
  Today the root is empty — no pack compiles (every pack is L0 and the
  life-threat sign-off is empty, HB-C1) — so a tag cut today fails at this step
  rather than producing a release with no protocol content in it, and
  `make sign` refuses on this tree. **The first draft did not fail**, because
  `packages/protocols/dist/` is held in git by a `.gitkeep` and `find` counted
  it: a tag would have signed one empty placeholder file and reported a signed
  release — the exact failure the script exists to prevent, found by running it
  rather than by reading it. Dot-files are now excluded, and four tests cover
  the directions: empty root fails, a root holding only `.gitkeep` fails, the
  real emit root fails today, and a populated root lists exactly its files. The job then runs `cosign sign-blob` per file and immediately
  `cosign verify-blob` against the workflow's own certificate identity, so an
  unverifiable signature fails the tag.
- **Images — unexercised, and there is nothing to exercise.** No `Dockerfile`
  is tracked anywhere in the repository, so this tree builds no image: there is
  nothing to scan with `trivy image` and nothing to sign with `cosign sign`.
  Both the `trivy-image` gate and the `sign-images` step enumerate tracked
  Dockerfiles and are wired to fail the moment one exists without a build and a
  signature behind it. This is the honest state, not a deferral.
- **SLSA provenance — unexercised.** `actions/attest-build-provenance` only
  runs inside Actions. It is pinned and wired over the bundle emit root.

`make sign` exists and does the half that is honest here: it requires cosign,
enumerates what a tag would sign, and then **exits 1** saying that keyless
signing needs the Actions OIDC token.

## Three debt baselines, and why they are not suppressions

`eslint-security` (272), `bandit` (4) and `checkov` (3) all report pre-existing
findings in trees INT-019 does not own — `apps/`, `packages/`, `services/`,
`infra/`. The two ways to make a gate green over such a tree are to turn rules
off and to record what is already there. Turning rules off is silent forever; a
baseline is a file with a number in it that somebody has to change on purpose,
in a diff, with a reviewer. So **every rule stays at `error`**, the current
findings are recorded, and a new one fails the build. Each baseline is
regenerated by an explicit command documented beside its gate, each gate
**fails closed when its baseline file is missing**, and none of them is an
allow-list of safe code — a baseline is a list of places nobody has looked at
yet. `scripts/ci/eslint_security_baseline.json` additionally refuses to carry a
parse error: a file the security rules could not read is never a pass.

The largest entry, `security/detect-object-injection` (162 of the 272), is the
rule's well-known noise on indexing a typed record; `detect-unsafe-regex` in
`apps/mobile/src/lib/telemetry/scrub.ts` is the one worth a human's eye first,
because a catastrophically backtracking regex in a **redaction** path is a
denial-of-service in the component whose job is to remove identifiers.

| `pyproject.toml` | `torch = [{ index = "pytorch-cpu", marker = "platform_system == 'Linux'" }]` — CPU-only, pulls no CUDA packages |

Earlier in this session I ran `uv pip install torch` to close the `test_deid_ner.py`
verification gap (invariant 6 surface). The pinned CPU index is 403'd by this
container's proxy, so that install resolved the **default PyPI wheel**, which is the
CUDA build and drags the `nvidia-*` / `cuda-*` stack with it. Those distributions are
in the venv and in no lockfile.

**So the gate did exactly the right thing** — it scans installed distributions, which
is the correct thing to scan, and it refused to pass a proprietary licence. What is
wrong is the environment it scanned. On a machine that can reach `download.pytorch.org`
the CPU wheel installs and the finding disappears.

Two consequences worth keeping:

- **`make security`'s licence gate cannot be read as green or red from this container**
  until the venv matches the lockfile. That belongs with HB-I9's reporting rule: name
  the tier that could not be read, do not report its verdict.
- **The gate would have caught a real proprietary dependency**, which is the point. Its
  first live finding being a false positive from an agent's own workaround is a good
  sign about the gate and a bad sign about the workaround.
