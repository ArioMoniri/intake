## What the decisions decide, and how it is built

Nothing below is re-decided.

- **CD-01** (active, verifier agree) `value.proxy_unasked_inbox_item`:
  - kind `proxy_chest_pain_screen_unasked`, `decision_ref: CD-08`,
    `pinned_to_note: true`;
  - raised when "identity_check.subject_role is 'yakınım adına' and the subject
    is in the adult age band of rf.chest_pain_cardiac_features and
    rf.chest_pain_no_cardiac_history (both age_band: adult), or the subject's age
    is unknown";
  - not raised when "the subject is known to be outside that adult age band".

  CD-01 `proxy_until_dsl_selects_copy`: the self-worded copy of the seven slots
  is not spoken in a proxy session, so they stay NOT_ASKED and neither
  chest-pain RED rule can fire (finding F13). `base.intake` carries that
  stop-gap as the screen's `skip_if: "identity_check.subject_role == 'yakınım
  adına'"`.
- **CD-08** routes the kind to the clinic inbox (`applies_to`,
  `item_kind_notes`; both active). Its SLA, cover and escalation stay
  `draft_needs_source`. The item "makes the gap visible to a clinician but does
  not close it".

How it is built, on INT-547's mechanism:

| Piece | What it holds to |
|---|---|
| `protocols.clinic_items` | `ProxyScreenRule` is read from CD-01: the kind, the seven slots from `sections`, and the screen (the one slot with no `ask_if`; refused unless exactly one). `raised_when` is kept so the runtime can check which reading the stop-gap rests on. `raised(screen_skipped, slots_unasked, subject_age)` raises for an adult or unknown age, never for a subject known to be outside the band. `SubjectAge` is a closed enum on the band, not a number. 7 new decision refusals. |
| `ClinicItemWatch` | At composition it parses the screen's own `skip_if` from the pinned protocol. It refuses (`ClinicItemWiringError`) a `skip_if` that reads a slot CD-01's `raised_when` does not name, because that would raise a proxy item for a session that is not a proxy one. A screen with no `skip_if` has nothing to watch. After every Work it raises the item when the `skip_if` reads TRUE over the engine's answered slots, all seven CD-01 slots are NOT_ASKED, and the subject is not known to be outside the band. Once per session, ids only, through INT-547's route and audit row. |
| The subject's age | The voice runtime holds no age fact, so the watch reads `SubjectAge.UNKNOWN`. That is CD-01's "or the subject's age is unknown", and the item is raised. The band check is tested at the rule (`OUTSIDE_ADULT_BAND` raises nothing). No runtime parameter carries an age, because nothing produces one. INT-223 refuses every under-18 subject before attribution. |
| The inbox | `EntryKind.PROXY_CHEST_PAIN_SCREEN_UNASKED`. Like the arms item it has no register, no visit index and no SLA, and it is its own entry beside the arms item. |

**Behind today's subject-role reading.** Proxy sessions arrive with ADR-040
(#833, not merged). Today a session becomes a proxy one when its subject-role
answer binds 'yakınım adına' (INT-518) and the screen's `skip_if` retires the
screen. The item is raised on exactly that reading, live, on both profiles.
Nothing fakes a proxy session.

**The one line #833 needs.** #833 starts a proxy-skipped step in
`NOT_ASKED_PROXY`, an eighth answer state. When it lands, that state joins
`_UNASKED` in `clinical_agent/clinic_items.py`
(`frozenset({AnswerState.NOT_ASKED, AnswerState.NOT_ASKED_PROXY})`), so a
screen skipped by the proxy path counts as unasked. #833's proxy path also
refuses the CD-01 stop-gap until CD-01's proxy copy is spoken. A spoken screen
closes the gap this item reports, and the item is then not raised. On the self
path, a speaker who answers 'yakınım adına' (#833's finding 3) still retires
the screen through the stop-gap, and the item is still raised.

## Residuals (for the orchestrator)

1. **Pinned to the note:** INT-548 (#928).
2. **A screen answered before the subject role binds.** In a proxy session the
   speaker may answer the screen about their own chest before the proxy answer
   binds. Ask-ahead and a late subject-role Work make this possible. The
   engine invalidates a screen still pending, so the item is raised. A screen
   already answered stays answered, and neither CD-01 nor the engine retracts
   it. That is the hazard CD-01's stop-gap exists to avoid, and an engine
   reordering question (subject role strictly first) rather than this item's.
3. INT-546 is applying CD-04 round 3 (INT-519) as a hook that `ClinicItemWatch`
   can implement. Whichever PR merges second wires it.
