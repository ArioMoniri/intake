## Update, 29 Oct 2026: the jar pin moves and the passkey login is re-recorded

**What CI reported.** check-py on ea3c54d4 (run 40778760167, job 123152960290) built the
jar under `--strict-checksums` (`BUILD SUCCESS`), then `make keycloak-provider` failed at the
pin check:

```

shasum: WARNING: 1 computed checksum did NOT match
intake-webauthn-session-notes-1.0.0.jar: FAILED
make: *** [Makefile:367: keycloak-provider] Error 1
```

The jar embeds its pom (`META-INF/maven/intake/intake-webauthn-session-notes/pom.xml`), so
the version bump changes the jar's bytes even though no class changed. This is the same
mechanism as the 3 Oct bump in docs/evidence/INT-378.md. The three check-py shards passed,
because the old pin and the old recording still agreed with each other.

**The rebuild.** `./mvnw -B clean verify` ran with Temurin 21.0.11, strict checksums on, and
an empty `-Dmaven.repo.local` in a scratch directory. It is a client build, and no service
ran on the laptop.

- main's pom (56bfb5ec) reproduces the committed pin `91da1232…` byte for byte, so the build
  is still reproducible.
- This branch's pom gives
  **`3ca703b66c79734521cfa2a2ff56909cccebf793488256b979f10898887cd323`**. That build used 258
  trusted checksums, and its Java tests passed 46 of 46 (12 + 5 + 20 + 9 across the four test
  classes).
- The new pin is in `infra/keycloak/providers/webauthn-session-notes.sha256` and the runbook
  (`docs/runbooks/keycloak-realm.md`, **Build and check**).
