the patient is already composing, now held encrypted rather than only in RAM,

### Acceptance, clause by clause

1. **drafts encrypted at rest.** `src/lib/intake/offline/envelope.ts` seals a
   draft with AES-256-GCM (`@noble/ciphers`, the MIT pure-JS family the auth
   path already signs with); the key is the device DEK held in
   `expo-secure-store` (`nativeBackend.ts`, following `auth/tokens.ts`), and
   the sealed blobs live under the document directory. `session.tsx` mirrors
   every note change to this store (lazy native import, fire-and-forget) and
   crypto-shreds the blobs and the DEK on sign-out. Only ciphertext reaches
   disk — proved by `draftStore.test.ts` "writes ONLY ciphertext …" and by
   `envelope.test.ts` "carries no plaintext PHI/PII …". The draft is typed /
   structured text only; no audio buffer is ever on this path (invariant 3).

2. **sync conflict rules.** `reconcile.ts` is a pure, deterministic rule:
   remote-absent → push; local-absent → take-remote; clean local → take-remote
   only if the server advanced, else in-sync; dirty local → fast-forward push
   if the server has not moved past our base, else **conflict**. A conflict is
   resolved last-writer-wins by `updatedAt` with `origin` as the deterministic
   tiebreaker, and — the property the feature rests on — **the losing copy is
   never dropped**: `sync.ts` writes it as a conflict copy. Every branch is
   covered in `reconcile.test.ts` (9 cases incl. the tie-break determinism and
   the both-null throw).

3. **airplane-mode e2e.** `apps/mobile/e2e/offline.spec.ts` drives the journey
   over an in-memory backend and a transport whose reachability is a switch:
   create a draft with the network down → it lands encrypted → sync returns
   `offline` and the draft survives → reconnect → sync pushes it and the server
   acks → and a separately staged divergence resolves to a `conflict` with the
   losing copy preserved.

## Invariants touched

- **Invariant 3** (raw audio never persists) — respected and reinforced: the
  draft store seals typed / structured text only; `session.tsx`'s header states
  it, and the audio-path guard's own scope (`e2e/voice.spec.ts`, scoped to

- **Invariant 6** (no PHI/PII in logs) — the store and its backend log nothing;
  `DraftDecryptError` carries a generic message with no key, payload or id.
- **Invariant 14** (field-level envelope encryption; dependency licences from
  the raw blob) — the on-device draft is envelope-encrypted; `@noble/ciphers`
  is **MIT**, verified from its raw `LICENSE` blob (`@noble/ciphers@2.4.0`,
  Copyright Paul Miller / Thomas Pornin — the same maintainer as the
  `@noble/curves`/`@noble/hashes` already in the tree), and MIT is on
  `scripts/ci/check_licenses.py`'s allow-list.

## No new PHI egress path

The change adds **no outbound call**. `sync.ts` takes an *injected* transport
and no production transport is wired (see the backlog note): the app writes the
draft to local encrypted storage and nothing leaves the device. `nativeBackend`
reaches only `expo-secure-store` (Keychain/Keystore), `expo-file-system` (the
app's own document directory) and `expo-crypto` (local RNG) — all device-local.

## Dependency

`@noble/ciphers@^2.0.0` (resolved 2.4.0) added to `apps/mobile/package.json`
for AES-256-GCM. Chosen over a bespoke construction (rejected — hand-rolled
crypto on a PHI-adjacent path) and over relying on WebCrypto `subtle` (absent
on the device, so it would pass the node tests and fail on the phone); the
`@noble` family is pure-JS and behaves identically in the vitest node
environment and on the device, which is why the auth path already uses it.
