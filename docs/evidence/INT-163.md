# INT-163 — Check-in: signed QR payload + desk verification + checkin_to_seen metric

**Issue:** INT-163 (E10-connectors, P2) · depends on INT-160 (connector framework), INT-143 (kiosk).
**Sec-Row:** `kiosk` (files/10 §9).
**Branch:** `int-163-checkin-signed-payload`.

## Acceptance (verbatim), one check per line

> "QR payload signed+short-lived; desk verification flow; wait metric emitted"

- [x] **QR payload signed + short-lived.** `intake_connectors.checkin.mint_checkin`
  produces a compact HS256-over-stdlib-`hmac` token — the **same** signing scheme the
  embed launch ticket (`intake_platform.embed.tickets`) and `room_tokens` use, not a new
  one (invariant 14). The closed claim set is `{tid, cid, nonce, iat, exp, purpose}`; the
  key is resolved from OpenBao through the connector framework's own `CredentialResolver`
  (`resolve_checkin_signing_key`, reading a hex `signing_key`). Short-lived: `DEFAULT_TTL_S`
  = 15 min, `MAX_TTL_S` = 60 min, refused at mint beyond the ceiling and again at verify
  (a forged long TTL under a leaked key is still bounded). The check-in id `cid` is the one
  caller-supplied field and is refused unless id-shaped, so it cannot carry PHI (invariant 6).
  Tests: `test_a_minted_token_is_three_segments_and_verifies`,
  `test_the_claims_carry_a_closed_id_shaped_set_and_no_phi`,
  `test_a_checkin_id_that_is_not_id_shaped_is_refused_at_mint`,
  `test_a_ttl_beyond_the_ceiling_is_refused_rather_than_clamped`.
- [x] **Desk verification flow (validates signature AND expiry, fails closed).**
  `verify_checkin` checks, in fail-closed order: signature → closed claim set → purpose →
  TTL ceiling → clock window (with skew) → expected tenant → single-use nonce (consumed
  last, so a tampered replay never burns a genuine nonce). Every branch raises; there is no
  silent accept. Tests: `test_a_tampered_signature_is_refused`,
  `test_a_tampered_payload_is_refused`, `test_an_expired_token_is_refused`,
  `test_a_not_yet_valid_token_is_refused`, `test_a_forged_over_long_ttl_is_bounded_at_verify`,
  `test_the_wrong_tenant_is_refused`, `test_the_wrong_purpose_is_refused`,
  `test_a_replayed_nonce_is_refused_and_a_tampered_replay_does_not_burn_it`.
- [x] **Wait metric emitted.** `record_desk_checkin` verifies the payload, appends one
  hash-chained audit entry recording the check-in (invariant 4), and emits the
  `checkin_to_seen` wait as a single `wait.v1` event via `intake_platform.wait_times.record_wait`
  — duration = desk-verification instant − signed `iat`, carrying a duration and the tenant
  only (invariant 6). The metric `wait.checkin_to_seen_min` exists in
  `observability/metrics_catalog.yaml` and is promoted `planned → live` (invariant 15/13);
  its Prometheus family `WAIT_CHECKIN_TO_SEEN_MIN` is added to `intake_metrics.metrics` and
  published only from a k ≥ 10 rollup (never raw). INT-241 left this exact seam
  (`WaitSource(... blocked_by="INT-163")`), now flipped to `observable=True`.
  Tests: `test_the_source_is_now_observable_so_record_wait_no_longer_refuses_it`,
  `test_a_verified_desk_checkin_is_audited_and_emits_one_wait_event`,
  `test_the_wait_event_carries_no_document_type_label`,
  `test_a_bad_token_at_the_desk_writes_nothing_at_all`.

## On QR rendering (out of scope, per the issue framing)

The deliverable is the **signed payload** — data + signature + TTL + verification — built and
tested as pure logic. No QR-render/scan native dependency is added (it would need a licence
audit and trips prior QR controls); the signed payload is machine-read text. No check-in
numeral is routed to any voice/TTS path (invariant 22 does not apply to a machine-read QR).

## Invariants touched

- **4** (consent scope + hash-chained audit): a recorded desk check-in appends one id-shaped
  `AuditChain` entry (`connector.checkin_recorded`, scope `operational:checkin`); the chain
  still verifies. A check-in reads/shares no clinical data, so the scope names the operation
  rather than a consent purpose.
- **6** (no PHI): the payload claim set is closed and id-shaped; the `cid` is refused unless
  id-shaped; the audit `resource_ref` and the wait event carry ids/duration/tenant only —
  no name, TC Kimlik, phone or free text. Metric is unlabelled.
- **13/15** (honest catalogue; every emitted metric catalogued): `wait.checkin_to_seen_min`
  moves `planned → live` alongside a real family and an observable source; the three other
  group-G ids stay `planned`. `unpublished_wait_series` still reports only `wait.answer_latency_s`.
- **14** (signed, schema-constrained data; secrets from OpenBao): HS256 over the existing
  scheme; signing key from OpenBao via `CredentialResolver`; the payload is data, never an
  instruction.
- **22** (numerals across a boundary): the QR is machine-read; no check-in numeral reaches a
  TTS path. N/A but checked.

## No new PHI egress path

The change adds no outbound call. `record_desk_checkin` writes a local audit entry and a local
`wait.v1` event; nothing leaves the process. The connector push path (INT-160, egress-guarded)
is untouched.
