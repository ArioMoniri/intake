## What the tests pin

**Pseudonyms:** deterministic (joins), keyed (a different key changes every
pseudonym — this is HMAC, not a bare hash anyone can precompute), format-
normalised (`0532 111 44 55` == `05321114455`), and carrying their key id
(`v1.<hex>`). Logs get exactly `pseudonym[:8]` and never the raw value.

**Rotation:** new writes move to the new key id; an old pseudonym stays
reproducible by naming its key id (re-tokenisation jobs link old→new);
an unknown key id refuses.

**The vault (integration, real Postgres + real OpenBao Transit):** the raw
value is stored only as Transit ciphertext (asserted at rest); fetch through
the tokenization role decrypts the roundtrip; **the app role's SELECT on
identity_vault raises InsufficientPrivilege** — "readable only by the
tokenization role" is a database fact, not a convention. Crypto-shredding is
destroying the Transit key — the engine work for that (rewrap, per-tenant
DEKs) is INT-014, deliberately not folded in here.

**The grep gate:** every committed `*.sql` is scanned — a column named after
a raw identifier (tckn/phone/msisdn/telefon) may exist only in the vault DDL
as ciphertext. INT-030's migrations are bound by this test the moment they
land.

## Notes

- Dev-only literals (`tokenization-dev-only`, `app-dev-only`) are compose-tier
