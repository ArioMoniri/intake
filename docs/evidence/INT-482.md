## 5 · Findings for the orchestrator

1. **The static 112 notice is not in the app.** The listing and the review notes say that the app
   shows "Acil bir durum yaşıyorsanız 112'yi arayın…" at static points (files/06 §0.3 Stage A,
   §7). No screen renders it today. INT-117 is `todo`, and the fixed strings are unsigned
   (HB-L27). `app-review-notes.draft.md` §1 makes this the first condition before submission.
2. **No reviewer can sign in.** Release builds sign in only by SMS one-time code, and a store
   reviewer cannot receive one. Adding a reviewer path changes authentication on the production
   host. It needs its own issue and the security reviewer. No id was minted here.
3. **The device-claim gate rejects a bare denial.** `device_claim_hits("Önvizit tanı koymaz.")`
   reports `diagnosis_tr`, because the negation sits inside the matched span (`koy\w*`). The
   app's own `app.disclaimer` ("Vizite tanı koymaz. …") would fail the same gate if it were put
   into a listing. The copy here avoids it ("tanı koymaz ve tedavi önermez"). The gate belongs to
   INT-224 and was not changed.
4. **`bare_percentage` misses the Turkish order.** The Python pattern `\d\s*%` misses `%20`, the
   Turkish order. The CI shell scan's `FIG` covers both orders. Not changed.
5. **The Play frames of #738 are iPhone captures.** #738 itself says to replace them before
   submitting to Play.
