## Process

1. **Medical-author pass.** The author was a family-medicine agent focused on patient
   communication and health literacy. It read each of the 48 rows of the HB-C1 table in
   docs/evidence/INT-414.md against the shipped catalogue (`tr.ts` at #726 head `03c47dfb`).
   The Turkish in each entry is extracted by script and asserted byte-equal to both the table
   and the catalogue. Each line was checked against six criteria:
   - PolicyGuard: no diagnosis, treatment, prognosis, reassurance or minimising;
   - B1 plain Turkish;
   - the siz register;
   - not a question;
   - no numerals;
   - fits its context.

   For context, the author confirmed behaviour claims in the INT-414 code (e.g. that a silent
   turn's question returns on screen). Every line was also run through the canonical
   `PolicyGuard.filter(..., scripted=False)`.
2. **Independent verifier pass.** A separate agent saw only the five records, the two source
   snapshots, the repository rules and the INT-414 code. It never saw the author's working. It
   returned a verdict for every line and for every record.
3. **Records.** The result is CD-19..CD-23 in INT-432's format: `packages/protocols/decisions/`
   plus the `docs/clinical/decisions/` twin. The numbers were agreed with the INT-432 lead;
   INT-448 uses CD-100 and up. There is one record per slot family and one entry per line, so
   each of the 48 lines has its own decision: its checks, the author's verdict and the
   verifier's verdict.
