# INT-308 — carrier/geo sanity checks against SMS pumping were named in files/10 §2 and implemented nowhere

**Date:** 4 September 2026 · **Branch:** `int-308-sms-pumping` · **Sec-Row:** files/10 §9 `onboarding`

files/10 §2 has named *"carrier/geo sanity checks against SMS pumping"* in the same sentence
as the OTP request budgets since the spec was written. INT-263 discovered while making those
budgets roll that no code honoured the clause, marked it *named but unbuilt* in §2 and in the
threat-model onboarding row rather than let the sentence read as coverage, and declined to
mint an id for it because ids were moving mid-iteration. This is that issue.

## Acceptance, verbatim from docs/backlog/issues.yaml

1. "the control exists or the sentence stops claiming it: either a carrier/geo check runs on
   the OTP request path, or files/10 §2 is rewritten to say the budgets are the whole of what
   stands against SMS pumping - a spec that names a control nobody built is worse than a spec
   that admits the gap, because it is read as coverage"
2. "if built, it fails OPEN on lookup failure and CLOSED on a positive signal: a carrier
   lookup that times out must not lock a legitimate patient out of their own intake, and the
   asymmetry is asserted by two tests"
3. "no new personal data is stored to achieve it: a carrier or country derivation is a fact
   about a person, so anything persisted carries the inventory annotation
   {category,purpose,basis,retention,recipients} - and if the check needs a vendor, that is a
   HUMAN_BLOCKERS row and not a dependency added quietly (invariant 19 applies to the licence
   too)"
4. "invariant 6 holds: no phone number, carrier name or country reaches a log, a metric label
   or an error report - the budgets already key on a Tokenizer pseudonym and this must not
   regress that"

## What was found before writing any code

The control has two halves and they were in completely different states. Conflating them is
how the §2 sentence came to read as coverage in the first place, so they are kept apart
everywhere in this change — in the module docstring, in §2, in the threat-model row and in the
test names.

**Geo was already enforced, and by nothing this issue wrote.**
`intake_api.otp.normalise_tr_phone` admits a Turkish mobile and nothing else: `+90` (or `90`,
or `0`, or bare) followed by ten digits beginning `5`. Every other destination is a 422 before
the abuse gate is even consulted. Since SMS pumping profits from termination fees on
high-payout international ranges, being a Turkish-only product is the single most load-bearing
anti-pumping property this system has — and it had no test asserting that the delivery adapter
is never reached. It has one now. Recording this rather than claiming new work for it is the
point: the honest statement is "the geo half already held", not "INT-308 built geo".

**Carrier was absent and cannot be completed here.** Deciding which `5XX` prefixes the BTK has
allocated to a Turkish mobile operator is a published fact nobody in this repository has read
from the publication. Writing the list from memory is the invented value HUMAN_BLOCKERS rule 1
forbids, and it fails in the expensive direction: a prefix wrongly recorded as unallocated
refuses every real subscriber behind it, silently, with a 422 that reads to the patient like a
typo in their own number.

## What was built

`services/api/src/intake_api/carrier_geo.py` — the control, on the OTP request path.

- `split_e164` derives `("90", "532")` from an already-normalised `+905321114455`, **in memory,
  for the length of one request**.
- `MsisdnAuthority` is the seam. Four answers: `True` (allocated → admit), `False`
  (**positively** not allocated → refuse), `None` (no opinion → admit), and raising (a lookup
  failure, including a timeout → admit).
- `AllocationTableAuthority` is the only implementation: file-backed, no network, no vendor.
- `infra/security/msisdn_allocation.yaml` is the authority and it declares **zero prefixes**,
  so the carrier half admits every request today and says so in one log line at wiring time.

Three refusals are built into the data model so that filling the file badly is visible rather
than silent:

- a non-empty `allocated_prefixes` with no `source` block **is refused by the loader**, so the
  list cannot be typed in from memory without the refusal appearing in the diff;
- `exhaustive` has **no default**. It is the entire difference between "absent from a complete
  list, therefore positively unallocated, therefore refuse" and "absent from a partial list,
  therefore unknown, therefore admit". A partial list marked complete refuses every subscriber
  it forgot;
- duplicate and non-digit prefixes are refused.

**Placement, and why it is not arbitrary.** The check runs *after* the abuse gate and *before*
the code is minted. After the gate, so a refused caller still spends its budget — otherwise
probing which prefixes refuse is free on an unauthenticated endpoint, and the budgets, which
are what actually stands against pumping today, stop counting the traffic. Before the code, so
no SMS is sent to a number no operator has allocated, which is the cost the control exists to
avoid. The refusal reuses the generic `phone_invalid` code rather than a code of its own:
files/10 §9 row 1 asks for generic error messages, and a distinct code would tell a caller
which of its numbers exist.

## What was deliberately NOT built

A live per-number lookup — HLR, or a number-portability query. It answers a stronger question
than prefix allocation, it needs a contracted vendor, and it sends the patient's own phone
number to a third party: a decision to disclose a new category of personal data and a licence
question under invariant 19, not a configuration change. So the seam is **narrower than any
such vendor by construction** — it is handed a country code and an operator prefix and never
the subscriber number, and a vendor that needs the whole MSISDN cannot be dropped in behind it
without that conversation happening first. Both halves of the ask are written out in
`docs/backlog/blockers.md`.

## Acceptance, clause by clause

**1 — the control exists or the sentence stops claiming it.** Both, and deliberately. The check
runs on the request path; §2 is rewritten to say exactly which half is enforced (geo, by
normalisation) and which half is wired but inert (carrier, empty authority), and to state that
until the list is supplied the budgets and the Turkish-only normalisation remain what stands
against SMS pumping. The threat-model onboarding row carries the same split and the asymmetry.
The sentence no longer reads as coverage in either direction. **Met.**

**2 — fails OPEN on lookup failure, CLOSED on a positive signal, asserted by two tests.**
`test_a_carrier_lookup_that_fails_still_lets_the_patient_in` (parametrised over a timeout, a
connection failure and a plain bug) asserts the lookup was attempted, the request was admitted
and the SMS went out. `test_a_positively_unallocated_prefix_refuses_before_any_sms` asserts the
422, that the delivery adapter recorded **zero** sends, and that no code was minted. **Met.**

**3 — no new personal data is stored; a vendor would be a blocker row, not a quiet dependency.**
Nothing is persisted: `test_the_carrier_check_stores_no_prefix_carrier_or_country` asserts that
the Redis key namespaces after a refused and an admitted request stay within the closed set the
OTP tier already had, and that no key or value carries an operator prefix;
`test_a_carrier_refusal_writes_no_audit_row` asserts the refusal writes no audit entry. Because
nothing is persisted, no inventory annotation is owed. No dependency was added — the authority
is a committed YAML file read with the pyyaml that already arrives with `intake-platform`. The
vendor half is written out in `docs/backlog/blockers.md` with its lawful-basis and licence
questions stated. **Met as to storage and the dependency; the blocker row's id is the open
part — see below.**

**4 — invariant 6 holds.** No phone number, prefix, carrier or country reaches a log line, a
metric label or an error report. The fail-open path logs a fixed string with **no exception
detail and no `logger.exception`**, because the traceback of a vendor client is the one place a
subscriber number would plausibly appear; the test greps the captured log for the prefix. No
metric was added, so `observability/metrics_catalog.yaml` is untouched and invariant 13 is
unaffected. The budgets still key on the Tokenizer pseudonym and the device digest, unchanged.
**Met.**

## Why the issue is `awaiting-human` rather than `done`

The mechanism is delivered, wired and green, and all four clauses are met as mechanism. What is
open is the content, and it is a human's: the BTK prefix list, and the separate decision about
whether a per-number vendor lookup is wanted at all. Clause 3 also requires the vendor question
to be *a HUMAN_BLOCKERS row*, and this session may not mint an HB id — ids move under
concurrent branches and a blind allocation is how ids get double-issued. The full row text is
written into `docs/backlog/blockers.md` for the coordinator to file with an id it can allocate
safely. This matches INT-206 and INT-161, where the mechanism shipped complete against an empty
declaration and the issue stayed open.

Per HUMAN_BLOCKERS rule 2, nothing is built around the gap. The empty table is the shipping
state, `test_the_shipped_allocation_table_declares_no_prefixes_and_cannot_refuse` pins it so
that supplying the list is a visible change, and
`test_a_supplied_exhaustive_table_wires_a_check_that_can_refuse` proves that supplying it is a
**data** change and not a code change.

The one place rule 2's usual shape is inverted is the fail direction, and it is inverted by the
acceptance itself: this gate fails **open**. A carrier check that failed closed would lock a
patient out of their own intake the first time a lookup timed out. The cost of a missed pumping
attempt is money; the cost of a locked-out patient is an intake that does not happen.

## Findings reported rather than fixed

- **`services/api` imports `yaml` without declaring `pyyaml`.** `intake_api.carrier_geo` does
  what `intake_voice_runtime.adapters.pins` already does — relies on pyyaml arriving with the
  `intake-platform` dependency. Declaring it directly is correct hygiene and was not done here
  because it is a `uv.lock` edit, and a lockfile edit races every open branch (the dependency
  lane owns that file). Two services, one declaration to add.
- **The issue's `tests:` field names `tests/api/test_otp_abuse.py`; the file is
  `tests/security/test_otp_abuse.py`.** The whole OTP abuse suite and its harness live under
  `tests/security`, so the tests were added there rather than duplicating a 300-line harness at
  the path the backlog row names. The row is stale, not the file.
- **`tests/security/test_otp_abuse.py` is now ~1 300 lines**, past CLAUDE.md's 500-line
  guidance. It was already at 926 before this change. Splitting it means either moving the
  harness to a shared module or duplicating it, which is a refactor of a security suite and does
  not belong inside another issue's PR.
- **The abuse gate is still not atomic**, unchanged from INT-131 and INT-263 and restated here
  because the carrier check sits directly behind it: `otp_request_gate` reads, decides, then
  writes, so racing workers can both admit. Making it atomic needs a Lua script `fakeredis`
  cannot execute, so the fix would ship with no test that runs in `make check`.
