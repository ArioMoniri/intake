# INT-311 — Issuing a Doctor Link from the patient's phone

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** `share-centre` (files/10 §9)
**Depends on:** INT-150 (server surface), INT-139 (share centre)

Nobody owned the ACT of issuing a Doctor Link: INT-137 refused the QR while
INT-150 was open, INT-150 built the server side and refused the delivery
channel (HB-O7), INT-139 refused the issuing screen. This delivers the single
issuing surface, in-app only, against the redemption path that already exists.

## Acceptance (verbatim from docs/backlog/issues.yaml) → artefact

1. **"the act of issuing has one owner and one surface … so the refusals are
   consistent and the capability is simply absent, which is a state nobody
   chose"**
   → One screen, `apps/mobile/src/app/(tabs)/visits/[visitId]/issue-link.tsx`,
   reached from the share centre hub (`shares.tsx` entry row), with its
   transport owned by `apps/mobile/src/lib/shares/issue.ts`. Registered in the
   nav map (`e2e/nav.spec.ts`). Asserted by `e2e/issueLink.spec.ts` §1.

2. **"no bearer credential is rendered in the patient app until there is a
   redemption path whose consent scope and audit entry are checked on the
   server: INT-137's four negative controls (no link, no scheme, no token, no
   serialised note) stay standing and are relaxed only by a change that says in
   its own body why each one may now go"**
   → The credential renders because the SERVER redemption path is real and
   guarded: `services/api/src/intake_api/doctor_link/redeem.py::open_link` runs
   `ensure_consent(scope=SHARE_SCOPE)` and writes a hash-chained audit entry
   (`action="api.doctor_link.opened"`) before it discloses a section
   (invariant 4). The issuing act is itself consent-gated and audited
   (`api.doctor_link.issued`, router.py). The four INT-137 negative controls
   on the review surface are **untouched and still stand** — proved in
   `e2e/issueLink.spec.ts` §2 and unchanged in `review_send.spec.ts` §6. The
   only guard relaxed is INT-139's own tree-wide "nobody issues a link or mints
   a code anywhere" (`e2e/shares.spec.ts` §2), and the relaxation **says in its
   own body why**: the routes now have one owner because the redemption path
   they feed checks a consent scope and writes an audit entry; the control is
   narrowed to that one module, not dropped.

3. **"the copy implies no channel that does not exist: HB-O7 records that the
   phone or e-mail destination files/10 §2 names has no recorded value and no
   contracted vendor, so an issuing surface that says 'we sent you a code' is
   false until that is answered"**
   → The link and the opening code are shown **in-app only** — the patient
   shows their phone to the clinician. The opening code is minted over the
   patient's own authenticated session (the channel that exists), never sent.
   No "we sent / we'll text / we'll e-mail" appears in the copy or the
   transport; the crux sentence is the negated, in-app form
   (`"…hiçbir yere gönderilmez. Ekranı hekiminize gösterin."`). Asserted by
   `e2e/issueLink.spec.ts` §3 with a channel-claim scanner that matches the
   affirmative send forms and deliberately spares the negated one. **HB-O7 is
   not a blocker here: INT-311 does not use the delivery channel it gates.**

4. **"whatever it renders is reachable across the app's own text steps, because
   INT-136 measured 52 of 248 Turkish labels overflowing the row at the largest
   one"**
   → The screen scrolls, wraps (no `numberOfLines`/`ellipsizeMode`/
   `adjustsFontSizeToFit`), and every `shares.issue.*` label's longest word
   fits the content row at every `APP_STEPS` size on 320/375/390 pt phones.
   Asserted by `e2e/issueLink.spec.ts` §4 with `readFontMetrics` against the
   Inter TTF.

## Invariants touched (named individually, per DoD)

- **Inv. 4 (consent scope + hash-chained audit on every share/redeem):** held.
  The issuing act runs `ensure_consent(scope=SHARE_SCOPE)` and audits
  `api.doctor_link.issued`; the redemption it feeds runs `ensure_consent` and
  audits `api.doctor_link.opened`. No server code changed — INT-150 already
  enforces both; INT-311 renders a credential only against them.
- **Inv. 6 (no PHI/PII/credential in logs, no leak surface):** held. The token
  and code live only in React state; the transport and screen reach no
  `AsyncStorage`/`SecureStore`/`expo-file-system`/`Clipboard`/`console.*`;
  neither the token nor the recipient crosses into a URL (both routes POST the
  payload in the body). Capture is blocked with `useClinicalScreenPrivacy`.
- **Inv. 2 (PolicyGuard: B1 Turkish, siz register):** held. New copy is
  share-mechanics, no diagnosis/treatment/prognosis; `siz` throughout, `-in`/
  `-iniz` split; asserted no `sen`/`sana`/`senin`.
- **Inv. 5 (tr source of truth, en mirror):** held. Every `shares.issue.*` and
  `a11y.shares.issueHint` key is in `tr.ts` first and mirrored, distinctly, in
  `en.ts`.
- **Inv. 20 (no accuracy/latency figure in copy):** held. No duration or
  numeral appears in any `shares.issue.*` string; the opening code is a runtime
  value, never a catalogue string.
- **Inv. 17 (no placeholders / no fabricated value):** held. No delivery
  channel is invented; HB-O7 is referenced, not built around. No TODO/mock.

## Gate runs (`make check` / `make safety` / `make security`)

The full `make check` fan-out (`check-py` / `check-ts` / `check-golden` /
`check-integration`), `make safety` and `make security` were **not run
locally**: `check-integration` requires a container runtime that is banned
locally and absent here (see MEMORY — "no container runtime anywhere"), and the
machine is under heavy load / near-full disk per the iteration constraints, so
only the targeted mobile slice was run. This change is mobile-only (TS), adds
no PHI egress path (the two routes are the existing INT-150 ones, called from
the app over the already-allowed API host), adds no dependency, no metric, no
service, and no server code — so the relevant gate is `make check-ts`, whose
mobile portion (`vitest` + `tsc` + `eslint`) is green above. `make check`,
`make safety` and `make security` must be confirmed green by CI from a clean
clone before merge (DoD list A).
