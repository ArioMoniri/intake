## What was actually wrong

INT-303 put `Decimal` into `clinical_schemas.common.JsonScalar` so the
comparison grammar could see the type extraction produces. Holding a type in a
union says nothing about what happens when the union is written down. Three
sibling paths lost or misreported it:

| # | boundary | file:line at `ec40e6c` | what it did |
|---|---|---|---|
| 1 | FHIR scalar mapper | `packages/clinical-schemas/src/clinical_schemas/mappers/to_r4.py:409` | fell past bool/int/float/str and raised `a None answer inside a list is malformed` — a **false** diagnosis |
| 2 | overlay store | `packages/intake_platform/src/intake_platform/overlay/store.py:243` | `json.dumps` with no `default=` → `TypeError`, raised **after** the fact was minted |
| 3 | JSON round trip | `packages/clinical-schemas/src/clinical_schemas/common.py:37` | `Decimal("38.50")` → `"38.50"` → validated back as `str`, which `canonical_scalar` reads as Unknown |

Boundary 3 is a **regression** against the pre-INT-303 `float`: a float at
least still compared.

### The measurement that forced ADR-030

Both encodings the acceptance names were measured before anything was written,
so the decision rests on numbers rather than preference:

```
$ uv run python probe.py          # host 10.6.110.10, commit ec40e6c
pydantic 2.13.4
Decimal('38.50')              -> b'"38.50"'             -> '38.50'  str
Decimal('9007199254740993')   -> b'"9007199254740993"'  -> '...'    str
TypeAdapter(Decimal).validate_json("38.50")             -> Decimal('38.5')
QrAnswer(value_decimal=Decimal("38.50"))                -> 38.5     (float field)
json.dumps({"v": Decimal("38.50")})  -> TypeError: Object of type Decimal is not JSON serializable
```

Read in order: a JSON **number** cannot carry the declared scale (`38.50`
parses back as `38.5`), and a **bare** JSON string is indistinguishable from a
string answer (which the carrier legitimately holds — the INT-031 fixture is
`slots={"ates": "38.6"}`). Neither is available, which is why the wire form is
tagged. ADR-030 records the decision and the object-wrapper alternative that
was rejected.

The undecidable union was already committed, not introduced here — the
exported `JsonScalar` carried two indistinguishable `string` members:

```
$ python3 -c "...openapi.json JsonScalar..."       # commit ec40e6c
```

### The near-miss controls, per boundary

Each is a case a naive fix passes:

| control | what it catches |
|---|---|
| `Decimal("38.50")` vs `Decimal("38.5")` | equal as floats, distinct in declared scale — `default=float`, `float(value)` and a `float`-typed field all pass 38.5 and fail here |
| `Decimal("9007199254740993")` (2**53 + 1) | the smallest integer a float cannot hold; the test asserts `Decimal(float(big)) != big` first, so the control's own premise is checked |
| `"38.50"` as a string answer | `default=str` serialises and reads back a string the comparison grammar cannot use — the same shape as the defect |
| `"~d38.50"` typed by a patient | the escape rule; the answer is carried, never refused and never turned into a number |
| a `None` inside a list | the old message was wrong for a `Decimal` and **right** here, so the fix keeps it rather than deleting it |
