## The one decision this issue turns on

files/08 §6 is blunt about what Langfuse is: *"it stores prompts and
completions verbatim, and the extraction prompt **is** the patient's
transcript, so this is a transcript store with its own login page."*
files/HUMAN_BLOCKERS.md **HB-L6** names Langfuse spans as one of four
unmanaged staff read paths into patient content and records that counsel has
not ruled.

files/08 §3 and §6 both say "hashed-content mode by default, raw-content
project break-glass only". **This iteration does not build hashed-content
mode, and that is deliberate.** Hashing a transcript is still shipping the
transcript's information into a store with its own login page — it is
reversible by dictionary attack on any short utterance, it survives no
argument with counsel, and it leaves a *mode* whose sibling is the raw one.
What ships instead is stricter and simpler:

**There is no field a transcript can occupy, and no configuration that could
grow one.**

- `LlmSpan` is a frozen dataclass with 16 fields: ids, two closed enums and
  six counts. Every string field must be **id-shaped**
  (`[A-Za-z0-9._:/@-]`, ≤128, ASCII, no spaces), so a Turkish sentence cannot
  be constructed into one.
- `emit_llm_span` serialises from `LLM_SPAN_FIELDS` — a module constant —
  rather than from the instance, so a subclass attribute or an
  `object.__setattr__` never reaches the payload; and it **re-validates**
  first, because `frozen=True` is a typo-catcher, not a boundary.
- The content-carrying mode is **absent**, not off. There is no
  `ContentReadGranted`, no `raw` project, no env var, no flag. `spans.py`
  imports neither `os` nor the flag provider and a test asserts its whole
  import set. Opening the gate means *adding a type and deleting the tests
  that assert it does not exist* — a reviewed change, not an operator's
  mistake.

Redaction was considered and rejected as the primary control.
`intake_platform.redaction.redact_text` says so in its own docstring: it
catches TCKN, phone and IBAN. The planted adversary in the test file —
`"Göğsümde iki gündür şiddetli bir ağrı var ve nefes almakta zorlanıyorum."` —
contains none of those patterns and would pass through a redactor untouched.
Scrubbing is the wrong control for narrative. A carrier that does not exist is
the right one.

## Licence verification (invariant 19) — read from raw blobs, 2026-08-29

Langfuse is **open core**, not open source end to end, and "MIT" on its own
would be exactly the laundered claim files/03 §4.9.0 rule 3 exists to catch.
Both blobs were read at the pinned release commit
`0037ad19dac83b857201632ba9e37c06a1c7eacd` (tag `v4.24.0`):

| blob | lines | sha256 | finding |
|---|---|---|---|
| `LICENSE` | 25 | `fd09d42b…f229d6` | MIT Expat, **with a carve-out in its own preamble** for `ee/`, `web/src/ee/`, `worker/src/ee/` |
| `ee/LICENSE` | 50 | `760f5202…dccee6` | "Langfuse Enterprise license" — *"may only be used, if you … have a valid Langfuse Enterprise License"* |

The published Docker image **contains** the `ee/` code. What decides whether
we may use this at all is therefore not the top-level badge but *which
directory the features we want live in*:

- `web/src/ee/features` at that commit is exactly: `admin-api`,
  `audit-log-viewer`, `billing`, `multi-tenant-sso`, `sfdc-sync`,
  `sso-settings`, `ui-customization`, `verified-domains`.
- **Annotation queues are not among them.** They live at
  `web/src/features/annotation-queues`, under the MIT tree.
- `web/src/features/entitlements/constants/entitlements.ts` gives plan `oss`
  `"annotation-queue-count": false`, which in that file's own typing
  (`| false // unlimited`) means unlimited.

So the three acceptance queues are usable under MIT. No enterprise licence key
is set anywhere in this repo, which keeps the `ee/` paths inert; setting one
without a signed agreement would be an unlicensed commercial use. Both blobs
are re-verified on every version bump — an open-core vendor moves the line,
not the licence text.

ClickHouse `25.12.11.4` (tag `v25.12.11.4-stable` → commit
`7852f16b4962eb6e129cc446b2c889b91d702061`): `LICENSE`, 203 lines, sha256
`e276e9cd…e33f62`, stock Apache-2.0. The single grep hit for "addendum" is
line 121 of the standard appendix (*"or as an addendum to the NOTICE text"*) —
boilerplate, not a rider. No acceptable-use clause, no field-of-use
restriction. ClickHouse acquired Langfuse in January 2026, so both licences
now sit under one owner and are re-verified together.

The other three images in the tier — `pgvector/pgvector:pg16`,
`redis:7.4-alpine`, `minio/minio:RELEASE.2024-01-16T16-07-38Z` — are the pins
INT-001 already registered, deliberately reused so the tier adds two licence
rows rather than five. Upstream's compose uses an **untagged**
`cgr.dev/chainguard/minio`; an unpinned image is not auditable and was not
adopted.

Both new rows are in `observability/registry.yaml` with
`licence_verified_at: 2026-08-29`, the blob url and the blob sha256 — the
schema in `intake_probes.registry` refuses a `licence_verified_at` that does
not name the blob it was read from.

## What HB-L6 gates, and how it fails closed

The three annotation queues all exist to put a human in front of something a
model produced from a patient's words. Every one of them therefore needs a
staff read of patient content, and two preconditions for that do not exist:

1. **HB-L6 is open.** Counsel has not ruled on staff access, and Langfuse
   spans are named in the blocker.
2. **There is no lawful basis to check against.** files/08 §2.6 works it
   through: in the consumer deployment we are the controller, KVKK m.6/3's
   care ground runs to persons under an obligation of secrecy, and *"an INTAKE
   support engineer is not that person"*. The purposes enumerated in
   files/06 §2 — and so in `intake_platform.consent.registry` — contain
   **nothing** covering staff access. The `support_access` explicit-consent
   purpose that would cover it is a question for counsel, not a row we may
   add.

So the mechanism ships with the gate wired and shut:

| capability | state | why |
|---|---|---|
| `enqueue` | **works** | an item is a pointer (ids, span ref, timestamp). Consent-checked against `learning:service_improvement` and audited — including the refusal, because a denial is a detection signal (files/10 §7) |
| `pending_items` | **works** | listing pointers is not a read of content |
| `record_review` | **works** | closed-enum verdict (`accept`/`edit`/`reject`) and closed-enum `SectionReason`. There is no free-text field, so the reviewer's note cannot become where the transcript reappears |
| `authorize_content_read` | **always refused** | see below |

`authorize_content_read` returns `ContentReadRefused` and that is its **only**
return type. There is no `ContentReadGranted` anywhere in the module, so this
is a wall rather than a branch — a test enumerates `dir()` for
granted/allowed/opened/raw and asserts the set is empty. The refusal object
carries the attempt's identifiers and `blocker_id="HB-L6"`, and no handle, url
or token that could later be exchanged for content. The audit row is written
**before** the decision is returned (files/08 §2.5 item 6), on the
hash-chained log, with `consent_scope_ref = "HB-L6"` — so the chain records
*which blocker* refused, not a scope that does not exist.
`annotation_content_reads_refused_total{queue,blocker}` makes standing demand
for a read path visible, which is the same posture files/08 §2.5 puts on
break-glass rate.

`QueueDef.content_scope` is `None` for all three queues. It is a field rather
than an absence so that the day counsel answers, the change is one value and a
type, both reviewed — not the discovery that nobody wired a check.

## `phi_path: false` on the Langfuse row — the argument, since it is contestable

files/08 §6 lists Langfuse as a PHI store. This registry row says otherwise,
and the difference is the emission boundary. A stock Langfuse *is* a
transcript store; the one in this repo receives ids, enums and counts because
the only code that can emit to it cannot express anything else, and
`tests/observability/test_langfuse_gate.py` plants a Turkish symptom sentence
at every seam to hold that true. The row carries that reasoning in a comment
naming HB-L6, and states the flip condition: the day a content-carrying mode
exists, `phi_path` becomes `true` and the release gate binds on it. A reviewer
who disagrees should flip it — the consequence is that `release_gate.py`
blocks on a `fallback: none` row, which is a conversation worth having rather
than a silent difference of opinion.

## Provenance of the "recorded simulator experiment"

Stated plainly rather than glossed: **the simulator does not exist in this
repo.** `packages/llm-evals` is in the repo map and not on disk; no module
under `packages/` or `services/` produces simulator runs today.

What ships is the *gate*, which is the half INT-175 owns: `load_records`
refuses a run file carrying unknown keys or non-id-shaped strings (a run
regenerated with transcripts in it **fails to load**, it is not scrubbed),
`score` computes five structural numbers, and `gate` judges them against
`observability/experiment_thresholds.yaml` with **invariant 1 as a hard rule
outside the thresholds** — a case in which the extractor produced a triage
level fails outright, whatever the ratios say.

The committed run file
(`tests/fixtures/experiments/extraction_recorded_run.jsonl`, 20 cases) is
hand-authored structural data in exactly the shape the simulator will emit. It
lives under `tests/fixtures/` for that reason (invariant 17 permits fixture
data only there). When the simulator lands it overwrites that one file and
nothing else here moves.

## What was NOT exercised

- **Langfuse was never booted.** Not once, on any host. Every compose
  assertion in this iteration is **static** — the file parses, profiles gate
  every service, images are tag-pinned, ports bind loopback, healthchecks
  exist, no secret has an inline default. That is the same posture INT-023
  took for the obs tier and INT-202 for the backup tier, and it is a real
  limit: **nothing here proves Langfuse 4.24.0 starts against ClickHouse
  25.12.11.4, that its migrations run, or that the healthcheck paths
  (`/api/public/ready`, `/api/health`, `/ping`) answer.** They were taken from
  upstream's own `docker-compose.yml` at the pinned commit, not observed.
  HB-I1 (13 GiB free of 926) and HB-I2 (15.1 GB Docker RAM) are why: this is
  six containers including a ClickHouse. The most likely first failure, named
  so whoever boots it looks there first: **bucket creation.** Upstream's
  compose makes the `langfuse` bucket with `entrypoint: sh` + `mkdir` against
  an untagged Chainguard MinIO; this tier keeps that shape but against the
  repo's pinned `minio/minio:RELEASE.2024-01-16T16-07-38Z`, and whether that
  image's shell accepts the same argv has not been observed.
- **Nothing in production calls the boundary yet.** No code under `services/`
  or `packages/` constructs an `LlmSpan` today — the extraction call site is
  the LLM gateway's issue (files/07: *"Langfuse scores wiring (self-hosted)"*),
  and INT-153 owns the clinician-feedback path into `note_quality`. What
  INT-175 owes is the boundary, the queues and the gate, and those are here
  and proven. But it means the *live* claim — "no patient content reaches the
  trace store" — is proven about the only door that exists, not observed
  across a running system. It becomes an observed property the first time an
  extraction actually emits.
- **No span has ever reached a real Langfuse.** `OtelSpanSink` is written and
  type-checked but never exercised against a live OTLP endpoint; the
  emission-boundary tests use an in-test recording sink. What is proven is
  what the boundary *emits*, not that Langfuse ingests it. The
  `/api/public/otel` wiring — endpoint, project keys from OpenBao, the
  `RedactingSpanExporter` in front — lands with whichever issue first boots
  the tier.
- **The OpenBao seeding path was not run.** `langfuse_secrets.sh --seed` and
  `--export` need a live dev OpenBao; the script's argv, key list and
  refuse-to-overwrite behaviour are reviewed, not executed. The key list is
  asserted against the compose file by test, so the two cannot drift silently.
- **The probe never called anything.** `build_dev_clients` is asserted to wire
  `langfuse`/`langfuse-clickhouse` when `INTAKE_LANGFUSE_HEALTH_URL` is set
  and to leave them SKIPPED otherwise. No HTTP request was made.
- **The CI job is not wired.** The acceptance says "CI job"; `.github/**` is
  outside this branch's scope. `make langfuse-experiment` is the runnable
  gate and is what a workflow step should call — one line, no arguments. Until
  someone adds that step, the gate runs locally only. **This is the one part
  of the acceptance that is not delivered**, and INT-175 should not close on
  it silently.
- **Hashed-content mode does not exist**, by the decision at the top of this
  file. If review disagrees and wants files/08 §3's wording implemented
  literally, that is a different issue with a different threat argument.
- **No `k>=10` / k-anonymity check on queue contents.** files/09 §5 puts that
  on the learning loop's aggregates; queue items are per-session pointers and
  do not aggregate, so nothing here needed it. Worth re-checking when the
  console renders a queue.
- **Tenant isolation is not enforced here.** `QueueItem` carries `tenant_id`
  and nothing checks it: files/08 §0b F1 is explicit that `tenant_id` is a
  label and not an RLS boundary, and the fix is the per-request DB role in
  `services/api/admin`, not a check in this module. Recorded so nobody reads
  the presence of the field as a control.
- **Integration lane not run for this issue.** `make check-integration` needs
  the docker dev tier; nothing in this change touches it.
- **Invariant 15 is satisfied for what we own, and partially for Langfuse
  itself — say which.** The monitoring contract asks for `/healthz`,
  `/readyz`, `/metrics` and `/version`. Langfuse is a third-party container,
  not a `services/` package, so it does not mount
  `packages/intake_platform/health`: it serves `/api/public/health` (used by
  the probe) and `/api/public/ready` (used by the container healthcheck), and
  it exposes **no Prometheus `/metrics` and no `/version`**. Those two are
  genuinely absent and cannot be added without patching the image. What
  covers the gap is that the four metrics in the catalogue are emitted by
  *our* boundary rather than by Langfuse, which is the half that matters for
  HB-L6; the image's own version travels as the pinned tag in the compose
  file and the registry row. An SLO file and a probe are present.
- **`.cache/deid-tr-ner-v1` was copied into this worktree** (258 MB, from a
  sibling) so `tests/security/test_deid_ner.py` could run. Without it four
  tests fail on a fresh worktree — a pre-existing environment gap, unrelated
  to this change, recorded so the green run above is reproducible.
