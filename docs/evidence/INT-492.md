# INT-492: question progress and micro-interactions behind a flag

GitHub #839. Owner request, 4 Oct 2026: "explore this w subagents of designer for the blob and question count and other parts … together with other provided kobra and other websites for ui and motion animation enhancements", with [spaceui.one](https://www.spaceui.one/) as the primary reference. INT-491 takes the orb; this issue takes the question count and the micro-interactions around it.

The research and the component → screen map are `docs/design/library-patterns.md` §7. Every licence was read from its raw file; every pattern was rebuilt natively, and no code was copied from any source (§7.1 holds the sha256s).

## Stacked on

`int-492-progress-micro` is cut from `origin/int-473-detent-sheet` (#808, the top of the mobile stack), because the typed screen, the chip chrome and the motion guards it changes are on that stack and not yet on `main`. Merge after #808.

## What changed

Everything is behind one build flag, **`progressMicro`, off by default** (`lib/flags.ts`, pure; `lib/featureFlags.ts`, the one Expo-bound reader; `app.config.ts` copies the build variable `INTAKE_FLAGS` into `extra.flags`, and app.json cannot switch one on).

- **The "Soru N / M" capsule** (`components/QuestionProgress.tsx`, rules in `lib/intake/progressCapsule.ts`).
  - A solid capsule holding one segment per section of the flow (the HPI dimensions, medicines and allergies, the history block, the closing note), each as wide as its share of the questions. The filled length is exactly the old bar's fraction at every question; a section change is the next segment becoming current. More than six sections fall back to one continuous track.
  - The count is "Soru 3 / 9" as one non-breaking atom (U+00A0 throughout), never grouped, in two weights.
  - It draws inside the one existing progressbar, so the value a reader hears ("Soru 3, toplam 9") is the same string in both looks; nothing in it announces itself.
  - It swaps with the step, instantly: the question's 120 ms fade stays the step's one animated element (ADR-033 §2, C9).
  - It is solid on the capture-protected intake (INT-477): opaque theme fills, no material.
- **Answer chips** (`components/ChipSlot.tsx`, rule `chipSlot` in `lib/controlChrome.ts`): the check slot is reserved in both states, a ring when empty and a tinted disc with the check when selected, so a tap never widens a chip or reflows the chips after it. Instant (ADR-033 §4). The selection tick (ADR-038 A2) is unchanged; intake chips get no press scale (Q-37.2).
- **The press response** (`components/PressScale.tsx`, `lib/motion/native/pressScale.ts`, numbers in `lib/motion/micro.ts`): ADR-037 P1, ratified, on the typed steps' actions and the review's "Gönder" only: 0.97 under the finger on the app's one critically damped spring (`PRESS_SPRING = BUBBLE_SPRING`), the instant opacity step kept, the commit on release unchanged. Absent under Reduce Motion and on RED. The motion guard's spring allow-list gains this one module, which is the guard change ADR-037's table names.
- **The loading wait** (`components/DialogueGate.tsx`): the voice probe's status row sits in a filled capsule; under Reduce Motion it shows a still "•••" glyph (`ellipsis`, a new registry symbol) instead of the platform spinner.
- **Approval needed, development builds only:** `progressNumberRoll` (`lib/motion/native/numberRoll.ts`). A changed digit rises 8 pt under the 120 ms fade, on a timing (no spring), only for a forward step of one (`rollGranted`, Astryx's stepper rule), static under Reduce Motion and on RED, hidden from the reader. `resolveFlags` drops it from every release build, and it needs `progressMicro` too.

No copy changes: every visible line is an existing key. No RED file, consent screen, instrument step or gate is touched.
