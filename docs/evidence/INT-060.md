## What was built

`make clips VOICE=<voice_id>` and the `intake-clips` CLI behind it. It walks
every compiled clip manifest under `packages/protocols/dist`, synthesises each
scripted string through a TTS gateway, trims the silence off both ends, stores
the Opus clip in MinIO **under the compiler's own clip id**, and prints a
coverage report per pack. A pack with a missing clip exits 1.

New package `packages/voice-clips` (`intake-voice-clips`, 393 statements):

| module | what it owns |
|---|---|
| `errors.py` | `ClipCacheError` — one base for every refusal |
| `audio.py` | RIFF reader, silence trim, Ogg/Opus encode, read-back bound check |
| `gateway.py` | `TtsGateway` seam, `HttpTtsGateway`, `RecordedTtsGateway`, `assert_speakable_tr` |
| `cache.py` | manifest model + loader, `clip_object_key`, `ClipObjectStore`, `ClipCache` |
| `build.py` | `build_clip_cache`, `clip_coverage`, `assert_clip_coverage`, `render_coverage`, `run_clip_build` |
| `cli.py` | `intake-clips` |

## Key parity with the compiler — how it is proved, twice

The Talker looks a clip up by the `clip_id` the compiler minted. A builder that
re-derived it under a different Unicode normalisation would produce a cache
that misses on every lookup — and a cache miss is not an error, so every
scripted turn would silently become a dynamic-TTS turn.

**The builder therefore carries no hasher at all.** `clip_object_key(entry)` is
`f"clips/{entry.voice}/{entry.clip_id}"`, the id taken verbatim off the
manifest row. Three tests hold that:

1. `test_stored_keys_are_exactly_the_compiler_manifest_clip_ids` — compiles the
   fixture pack with `compile_bundle`, builds the cache, and asserts the set of
   object keys equals `{f"clips/{VOICE}/{row.entry.clip_id}" for row in bundle.clip_manifest}`.
   The comparison is against the compiler's own in-memory manifest, not a
   re-read of the JSON, so nothing in the middle can launder a mismatch.
2. `test_the_builder_never_hashes_anything_itself` — an AST scan over every
   source in the package: no `hashlib` import, no `sha*` attribute access.
3. `test_the_builder_runs_no_normaliser_of_its_own` — the same scan for
   `expand_tr`, `assert_round_trip`, `turkish_cardinal` and any import of
   `tr_orthography`. Expansion happens once, in the compiler.

## Silence trim — the INT-240 finding, and the bounds pinned

INT-240 measured one-word RED imperatives coming back from the FreyaTTS lane
wrapped in ~1.2 s of silence at each end. Under CLAUDE.md invariant 21 the RED
script is pre-positioned on the device and fired over the data channel, so
there is no runtime moment in which that padding could be shaved — the clip is
played exactly as stored. Build time is the only correct place.

| constant | value | why |
|---|---|---|
| `SILENCE_FLOOR_DBFS` | −50.0 | low on purpose; a high floor eats a breathy word onset, and eating a word is invariant 10 |
| `LEAD_PAD_MS` | 20 | kept in front of the first above-floor sample so the attack survives |
| `TRAIL_PAD_MS` | 40 | kept behind the last one so the release survives |
| `MAX_LEAD_SILENCE_MS` | **40** | asserted on the decoded stored clip |
| `MAX_TRAIL_SILENCE_MS` | **60** | asserted on the decoded stored clip |

Measured on the INT-240 shape (1.2 s + 0.6 s speech + 1.2 s, 24 kHz mono): 3000
ms in, **659.6 ms out, 19.9 ms lead, 24.5 ms trail** — comfortably inside both
bounds, with the residual lead equal to the pad rather than to encoder priming.

The bounds are checked by `encode_clip` itself on a **decode of its own
output**, not on an intermediate buffer: encoder priming and container granule
handling both add samples in front of the audio, so the decoded clip is the
only honest place to measure what the patient will hear. Four tests:

- `test_the_bounds_are_pinned_and_leave_room_for_the_pads` — the constants, and
  that each pad is strictly under its bound.
- `test_the_int240_shape_comes_back_inside_the_bounds` — on `EncodedClip` *and*
  on an independent `decode_opus` + `silence_edges_ms` of the stored bytes.
- `test_no_speech_is_trimmed_away` — the count of above-floor samples after the
  round trip is ≥ the count before. Invariant 10: the clip is the whole script.
- `test_the_bound_guard_fires_when_the_clip_misses_it` — the guard is real, not
  decorative: with `max_lead_ms=0.0` it raises `ClipSilenceBoundError`. The
  bounds are parameters *only* so this test can prove that; the defaults are the
  pinned constants and nothing in the builder passes others.

## The mock / recorded-fixture path — CI never dials a model

ADR-006: every external speech call goes through an adapter interface with
recorded fixtures for tests. `TtsGateway` is a `Protocol` with one method,
`synthesise(*, text_tr, voice_id) -> SynthesisedSpeech`, and two
implementations:

- **`HttpTtsGateway`** — `POST {endpoint}/synthesize` with `{"text", "voice_id"}`,
  16-bit PCM RIFF/WAVE back. Same shape as the dev bridges in
  docs/runbooks/team-gpu-server.md. Tests drive it through
  `httpx.MockTransport`; no socket is opened.
- **`RecordedTtsGateway`** — one JSON document per scripted string under a
  recording root, named by the compiler's own `text_hash`:
  `{"voice_id", "text_tr", "body_base64"}`, where the body is the recorded
  RIFF/WAVE response. It replays through the *same* `wav_to_speech` parser the
  HTTP adapter uses, so the recorded path exercises the real parse.

Selection is `tts_gateway_from_env()`: exactly one of `INTAKE_TTS_ENDPOINT` or
`INTAKE_TTS_RECORDED_DIR`, neither with a default. This follows the
`INTAKE_CLAMD_HOST` precedent rather than the `MINIO_ENDPOINT` one — a guessed
scanner is a scan that did not happen, and a guessed TTS is a clip nobody
synthesised. Both set at once is *also* refused: an ambiguous source for the
audio a patient hears is not a preference to resolve quietly.

**Neither GPU lane is a dependency.** 8803 (FreyaTTS) and 8805 (VoxCPM2, on the
unmerged INT-240 branch) are reachable through this adapter and nothing assumes
either is up: an unreachable endpoint is `TtsUnavailableError`, a non-2xx is
`TtsRefusedError`, and an absent configuration is `TtsNotConfiguredError`
before any socket is opened.

**No audio fixture is committed.** There is no recorded Turkish speech in this
repository, and committing a synthetic tone under the name "recording" would be
a lie about provenance. `tests/voice/clip_harness.py` builds explicitly
synthetic WAVs into `tmp_path` and says so in its header.

## Invariant 22 — the builder refuses, it never normalises

`assert_speakable_tr` rejects any character in Unicode category `N` — not only
ASCII digits, because Arabic-Indic digits and vulgar fractions reach a TTS
normaliser exactly as a `5` does. It has no rewrite path at all.

The gate runs **over the whole manifest before any string is synthesised**, so
a pack carrying an unexpanded dose is refused before the model is dialled once
— not after the first eleven clips are already in the bucket.
`test_a_row_that_still_carries_a_digit_is_refused_before_synthesis` asserts the
recording gateway logged zero calls. `HttpTtsGateway.synthesise` carries the
same check as defence in depth
(`test_it_refuses_a_numeral_before_dialling`), and
`test_ordinary_turkish_number_words_pass` is the near-miss negative control:
`"Günde beş miligram alınız."` builds normally.

## Invariant 3 — the distinction, stated where someone will read it

The module header of `voice_clips/audio.py` states it explicitly and at length:
invariant 3 governs *patient* audio; a protocol clip is the agent's own
synthesised voice reading a scripted Turkish string that is already committed
to this repository in plain text, produced at build time with no session, no
microphone and no capture path anywhere in the process (files/03 §4.6 invariant
9: "clips in MinIO are synthetic agent speech, never patient audio"). The
header ends with the sentence that matters for whoever reads it next: *do not
reach for this module to persist anything that came out of a patient's mouth —
it is a cache of scripts, not a recording store.*

### The INT-090 audio-retention guard was amended, and it got stronger

`tests/voice/test_audio_retention_guard.py` bans audio-I/O imports and
`audio/*` literals under `packages/` and `services/`. Its own text named this
case in advance: *"the clip cache (agent-voice TTS output, files/03 §4.2) is
the only anticipated candidate"*. The change:

- **Tightened**: `av`, `opuslib`, `pyogg`, `miniaudio`, `ffmpeg`,
  `imageio_ffmpeg` added to `AUDIO_IO_MODULES`. Each is a codec route that
  previously slipped past every name on the list.
- **Granted, narrowly**: a new per-file `ALLOWED_AUDIO_IMPORTS` with exactly one
  entry — `voice_clips/audio.py` may import `soundfile`, and nothing else may —
  and one `ALLOWED_AUDIO_LITERALS` entry so `voice_clips/cache.py` can name
  `audio/ogg` on the object-store put.
- **Pinned by equality**: `test_the_allow_list_is_empty` became
  `test_the_allow_lists_hold_exactly_the_clip_cache_grant`, asserting both maps
  equal their one entry, so a second file or a second encoder cannot be added
  without editing that assertion. Two further tests check the granted paths
  exist and that the grant does not leak to the rest of the clip package.

Net effect: six more libraries banned repo-wide, one file allowed one encoder.

## Licence — soundfile, and why PyAV was rejected

The licence audit was run against the raw blobs, per files/03 §4.9.0 rule 3.

**Adopted — `soundfile` 0.14.0** (libsndfile 1.2.2), the Opus encoder:

| blob | sha256 | finding |
|---|---|---|
| `soundfile-0.14.0.dist-info/LICENSE` | `0dd2e411fed553ba891845077e5a32c5b726d1bbc46ff31a2118ae1ccf816752` | BSD-3-Clause (soundfile's own code) |
| `_soundfile_data/COPYING` | `ad01ea5cd2755f6048383c8d54c88459cd6fcb17757c5c8892f8c5ea060f6140` | LGPL-2.1 (bundled libsndfile) |
| `licensing/license_notes.md` | `35630e1f59b5c54b0bcbe2ec173bcf5a63b727a6e2f7834ca6d35a1af91a2b5f` | libopus / libogg / libFLAC BSD-3-Clause; libmp3lame / libmpg123 LGPL |

No GPL anywhere, and the wheel ships the licence blobs for what it bundles.
Verified 29 Aug 2026. It is a build-time encoder for agent speech and never on
the PHI path.

**Rejected — PyAV 18.1.0**, which was the first candidate and is *not* on the
INT-090 ban list, so it would have been the path of least resistance. Its own
`LICENSE.txt` is BSD-3-Clause, but the binary wheel's `libavcodec` is
link-edited against `libx264`/`libx265` (**GPL-2.0-or-later**) — verified from
the artefact: `avcodec_configuration()` shows `--enable-libx264 --enable-libx265`
with **no** `--enable-gpl`, a state upstream FFmpeg's `configure` refuses to
produce, reached via `PyAV-Org/pyav-ffmpeg`'s `patches/ffmpeg.patch` moving both
out of `EXTERNAL_LIBRARY_GPL_LIST`. `avcodec_license()` self-reports "LGPL
version 3 or later"; `otool -L`/`DT_NEEDED` and 16 undefined `x264_*`/`x265_*`
symbols say the link is real. The wheel ships **no** licence blob for any
bundled binary. Recorded in `packages/voice-clips/pyproject.toml` so it is not
re-proposed. Nothing in this builder needs H.264 or H.265; the exposure would
have been presence-in-artefact, and the cheaper answer was a different encoder.

refused rather than getting a clip that no longer says what the pack says.

## What was refused rather than invented

- **No committed audio fixture.** There is no real Turkish TTS output to record
  here, and a synthetic tone filed as a "recording" would misrepresent its
  provenance. Test audio is generated into `tmp_path` and labelled synthetic.
- **No resampling.** A sample rate outside Opus's input set is refused, not
  quietly converted — an unexpected rate means the endpoint is not one of the
  pinned models (files/03 §4.9.1 rows 10–12), and converting it would hide that.
- **No dependency on either GPU lane.** 8803/8805 are configuration, never an
  assumption; INT-240 is unmerged and nothing here waits on it.
- **No second normaliser.** A numeral is refused with a message pointing at the
  compiler; the builder has no expansion code and a test proves it.
- **No weakening of the two import boundaries** that red run 3 exposed. The
  code moved instead.

## Deviations and findings handed on

1. **The command is `intake-clips`, not `protocols clips`.** CLAUDE.md names
   `make clips VOICE=<id>` and that is exactly what the Makefile provides; the
   subcommand lives on its own console script because `packages/protocols` may
   not import an HTTP or object-store client (red run 3).
2. **`packages/voice-clips` is a new workspace package.** files/03 §2 lists
   "clip cache build" under `services/workers`, which does not exist and whose
   creation would pull in the whole invariant-15 monitoring contract
   (`/healthz`, `/readyz`, `/metrics`, `/version`, an SLO file and a synthetic
   probe — `tests/platform/test_health_contract.py` enumerates every directory
   under `services/`). A build-time CLI is not a service. When the Celery worker
   tier lands it can call `run_clip_build` directly; the package needs no change
   for that.
3. **The acoustic half of the files/03 §4.9.6 gate is not built here** —
   synthesise → transcribe with an *independent* ASR → diff against the intended
   expansion. `protocols/compile/tr_orthography.py`'s header says it "belongs to
   `make clips`", and it is genuinely the right home, but it is not in INT-060's
   acceptance and it needs the row-2 ASR weights this repository does not carry
   offline. Recorded here as the next issue's work rather than stubbed; the
   textual half of the gate (no numeral reaches TTS) *is* enforced, twice.
4. **`make protocols-compile` still refuses on the real pack tree** — every pack
   is L0 and `packages/protocols/base/life_threat.yaml` is absent (HB-C1). That
   is the pre-existing honest state, unchanged by this issue:
   `git diff origin/main -- packages/protocols` is empty, and the 807 compiler
   tests are green. The end-to-end run above therefore used the committed
   synthetic fixture pack.
5. **The clip bucket has no lifecycle policy yet.** Clips are keyed by content
   hash, so a retired pack version's clips are orphaned rather than overwritten.
   They contain no patient data and are not a retention class, but the bucket
   will grow monotonically until someone sweeps it — a sizing note for the infra
   issue, not a defect here.
