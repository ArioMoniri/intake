# INT-501 — http-cache-semantics lifted before its scanner exception expires

GitHub #853 · Sec-Row `cicd` · phase P1 · 16 Oct 2026

Three time-boxed scanner exceptions expire on 1–2 Nov 2026:

- node-forge 1.4.0 (trivy and osv), which expires on 1 Nov.
- braces 3.0.3 (trivy and osv), which expires on 2 Nov.
- http-cache-semantics 4.2.0 (osv only), which expires on 2 Nov.

When an exception expires, the required `vulnerabilities` job turns red on
every PR. The issue asked for each package to be upgraded so that its
exception is no longer needed.

On 16 Oct 2026, one of the three could be upgraded. http-cache-semantics
4.3.0 is outside its advisory's range, and this PR raises it to that version.
node-forge and braces still had no release that clears their advisory, so
nothing was forced. On the orchestrator's decision, they were split to INT-508
(GitHub #865), and the renewal is offered to the owner as a patch.

## How the scanners were run

These are the job's own versions and invocations. Each run used a
`git archive` export of the tree, with no `node_modules` and no `.venv`, which
matches the job's checkout.

- **trivy 0.70.0.** trivy-action v0.36.0 installs this version. The binary
  came from `trivy_0.70.0_macOS-ARM64.tar.gz` on the GitHub release. Its
  sha256 is `68e543c51dcc96e1c344053a4fde9660cf602c25565d9f09dc17dd41e13b838a`,
  the same value as the release's `trivy_0.70.0_checksums.txt`.
  - Command: `trivy fs . --severity CRITICAL,HIGH --exit-code 1 --ignorefile .trivyignore.yaml`
  - It ran with an empty `DOCKER_CONFIG` and a fresh cache directory.
  - DB: version 2, UpdatedAt 2026-10-16 01:13:54 UTC.
- **osv-scanner 2.5.1.** osv-scanner-action v2.5.1 uses this version.
  - Command: `osv-scanner -r ./`

To run "without the exceptions", the export had the named rows removed from
`.trivyignore.yaml` and `osv-scanner.toml`. Only the scan copy changed. The
committed files were not touched.

## What upstream offers (16 Oct 2026)

Sources: npm, the OSV API (`api.osv.dev/v1/vulns/<id>`) and the upstream
GitHub repositories.

| package | advisory (OSV range) | newest release | upstream fix | can a parent drop it? |
|---|---|---|---|---|
| http-cache-semantics | GHSA-ch52-4w7c-c8xp / CVE-2026-93748, `last_affected: 4.2.0` | **4.3.0** (4 Oct 2026) | n/a: 4.3.0 is outside the range | not needed |
| node-forge | GHSA-86w9-cpqp-85rv / CVE-2026-85393, `last_affected: 1.4.0` | 1.4.0 (24 Mar 2026) | digitalbazaar/forge#1152, open and unmerged; issue #1149 open | no |
| braces | GHSA-vfj7-8cjw-p6xm / CVE-2026-93687, `last_affected: 3.0.3` | 3.0.3 (21 May 2024) | micromatch/braces #78, #79, #82, #87 and #88, all open and unmerged | no |

Why no parent can drop node-forge or braces:

- **node-forge.** All 52 @expo/cli releases from 57.0.0 to 58.1.9 (the latest,
  canaries excluded) depend on node-forge, at `^1.3.3` or `^1.4.0`. Both ranges
  resolve to 1.4.0. @expo/code-signing-certificates 0.0.7, the latest, needs
  `^1.4.0`. `expo` itself depends on @expo/cli.
- **braces.** micromatch 4.0.8, the newest release, needs braces `^3.0.3`.
  All 11 metro-file-map releases from 0.84.0 to 0.87.1 need micromatch
  `^4.0.4`. Metro uses metro-file-map as its file crawler. The lockfile also
  reaches micromatch through @expo/metro-file-map 57.0.2. 57.0.4 has dropped
  micromatch, but metro-file-map has not, so a bump would not remove braces.

An override to a fork or a git ref would clear the scanners, but it would
swap a reviewed release for unreviewed code. It was not done.

### What 4.3.0 does and does not change

This clearance comes from the advisory's recorded range. No max-stale code
was fixed:

- The diff from 4.2.0 to 4.3.0 (index.js, 85 lines) changes how a
  `Vary: *` field and inherited request properties are matched, and adds a
  `status()` accessor. It does not touch the max-stale handling the advisory
  names.
- The maintainer closed the report (kornelski/http-cache-semantics#56) as not
  a bug, citing RFC 9111 §7.3. The rebuttal was passed to the GitHub advisory
  database (github/advisory-database#10139) and included in a dispute filed
  with MITRE. Neither had been resolved by 16 Oct.
- If the record is widened to cover 4.3.0, osv-scanner reports it again. The
  reachability statement in the old exception still holds: the package is
  reached only by `expo start --tunnel` on a developer machine.

## What changed

1. **One `pnpm.overrides` floor**, `http-cache-semantics@<4.3.0 → ^4.3.0`,
   shaped like the INT-500 floors. The only copy sits under @expo/ngrok 4.1.3
   → got 11.8.6 → cacheable-request 7.0.4. That chain declares `^4.0.0`, so
   4.3.0 is inside its range.
2. **The lockfile.** `pnpm install --lockfile-only` (pnpm 9.15.9) changed 5
   lines and deleted 4: the override, the package entry and two snapshot lines.
   The new integrity string is the `npm view http-cache-semantics@4.3.0
   dist.integrity` value, `sha512-M5t5LlJpS1UHMjvw…`.
3. **Pin tests** in `tests/ci/test_security_gates.py`:
   - `FIXED_VERSIONS` gains `http-cache-semantics: (4, 3, 0)`.
   - `OVERRIDE_FLOORS` gains the new floor.
   - New `test_every_override_floor_is_its_fixed_version`: each selector's
     upper bound and each floor equal the package's fixed version.
   - Its near miss, `test_near_miss_an_override_one_release_short_is_caught`:
     a selector `<4.2.0`, which would leave 4.2.0 unrewritten, is refused. So
     is a floor `^4.2.0`.
4. **No exception file changes in this PR.** The exception files are
   owner-only, so the removal is an owner patch (below). Until it is applied,
   the http-cache-semantics osv entry matches nothing: osv filters 3 records
   on this tree, not 4.

## Owner patches

Both are in `~/.claude/projects/-Users-ario-Downloads-previsit/issue-drafts/`.

- **`owner-501-remove-exceptions.patch` + `.msg`.**
  - Removes the http-cache-semantics entry from `osv-scanner.toml`.
  - Lowers `MAX_OSV_SUPPRESSIONS` from 4 to 3.
  - Drops the entry from `OSV_NO_FIX_ROWS`.
  - Adds `GHSA-ch52-4w7c-c8xp` and `CVE-2026-93748` to `ADVISORY_IDS`, so the
    no-suppression sweep refuses the entry if it ever returns. The toml
    comment therefore leaves the id unnamed.
  - `git apply --check` passes on this branch. Applied to an export of it,
    `tests/ci/test_security_gates.py` gives `63 passed`.
- **`owner-508-renew-exceptions.patch` + `.msg`.** This one is an owner
  decision for INT-508 and applies after the 501 patch.
  - Moves the node-forge and braces `expired_at` / `ignoreUntil` to
    2026-12-31 in both files. Each statement says why the row was renewed and
    links the open upstream fix.
  - The pin tests bound both expiries at 31 Dec 2026. A new test ties the
    braces trivy row's expiry to its osv entry.
  - No row is added, and neither pin moves. With both patches applied, ruff
    is clean and `tests/ci/test_security_gates.py` gives `64 passed`.
