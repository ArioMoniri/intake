## What the tests pin

**The tier.** Its own compose file — `infra/docker-compose.siem.yml` — and a
test asserting `infra/docker-compose.dev.yml` contains none of `wazuh`, `falco`
or `siem`. INT-202 set that precedent and INT-175 followed it; this is the third
tier to keep out of the shared file. Every service profile-gated behind `siem`,
every image tag-pinned, every published port on `127.0.0.1`, every service with
a healthcheck, every bind-mount source present in the repo, no credential
literal and no `${X:-default}` on a secret.

**Licences, from the raw blob.** Three registry rows with `licence_verified_at`,
`licence_blob_url` and `licence_blob_sha256`, and a test that fails if any of
the three is missing or if the Wazuh row records a one-word licence.

**The rules.** Every Wazuh rule id inside the documented 100000–119999 user
range (outside it, a rule silently *replaces* a vendor rule); ids unique; every
rule declaring exactly one of the three acceptance signal groups; all three
signals actually covered; no `frequency`/`timeframe`/`ignore` correlation
directive anywhere; no dollar-paren interpolation in any description. Falco
rules: unique names, a closed priority enum, and no `proc.cmdline`, `evt.args`,
`evt.buffer` or `fd.name` in any output string. Every refusal has its own
negative-control test that mutates the shipped file and asserts the loader
raises — including a near-miss control proving the unmutated file loads.

**ossec.conf.** Three ingest sources, all `json` so fields are decoded rather
than regex-scraped out of a line that may hold patient text; no mail relay; no
vendor reporting (`update_check` and `vulnerability-detection` both off —
Wazuh calls `cti.wazuh.com` otherwise, from inside the PHI network); no
rotation window.

**The adversarial PHI proof.** This is the half of the issue that matters most,
because a SIEM is the one component with permission to read every log line,
every file name and every command line on the PHI path — files/10 §9
`incident-response` names "[I] PHI pasted into tickets or chat during the
response" as the threat, and the alert payload is what gets pasted.

Fourteen tests plant the Turkish symptom sentence
`Göğsümde iki gündür şiddetli bir ağrı var ve nefes almakta zorlanıyorum.`
(borrowed verbatim from `tests/observability/test_langfuse_gate.py`, so the two
PHI gates agree on what narrative looks like) at every seam that could carry it,
and assert it does not appear in the serialised alert:

| planted in | vector | result |
|---|---|---|
| Falco `output` | the log line | not read; the normaliser projects onto a closed key set |
| Falco `output_fields["fd.name"]` | **a filename**, `Ayse-Yilmaz-göğüs-ağrısı-anamnez.txt` | path truncated to `/data/uploads` + sha256 digest |
| Falco `output_fields["proc.cmdline"]` | a command line holding a filename | not read |
| Falco `output_fields["container.name"]` | operator-chosen text | not read |
| Falco `hostname` | an identifier field | fails the identifier guard, dropped and counted |
| Wazuh `full_log` | the raw decoded line | not read |
| Wazuh `data` | our own decoded fields | not read |
| Wazuh `rule.description` | **the rule's own prose** — Wazuh expands a field reference into it at alert time | never read; the name is resolved from the committed XML by id |
| Wazuh `syscheck.path` | a filename | truncated + digested |
| *every string in a Falco event at once* | belt and braces | nothing survives |

Two further tests make the guarantee structural rather than behavioural:
`SecurityAlert` has no `body`/`full_log`/`output`/`message`/`cmdline`/`payload`/
`content`/`transcript`/`request` field and no `user`/`username`/`srcuser` field,
and a model validator refuses narrative in *any* string field, so a future
caller constructing one by hand hits the same wall the normaliser does.

The path scrubber is the interesting case, because the brief requires alerts to
*carry* paths. `/usr/bin/bash` survives whole; a path is kept component by
component for as long as each component is an identifier and truncated at the
first that is not, with the sha256 of the full original path attached so two
alerts about the same file still correlate. A component that is
identifier-shaped but that `intake_platform.redaction.redact_text` would change
— `hasta-100000001XX-rapor.pdf`, a valid TC Kimlik checksum inside an ASCII
filename — also truncates. Overlong components truncate. Depth survives,
because it is a number.

**The monitoring contract (invariant 15).** `docs/slo/siem.yaml` with one
objective over the scrub boundary; its SLI references only catalogued metrics;
three new `siem_*` families in `observability/metrics_catalog.yaml`; three
registry rows with probes the runner implements, and `INTAKE_FALCO_HEALTH_URL`
wired in `services/probes` so the `falco` row is not a fiction.

## Licence findings, per image (invariant 19)

Every blob fetched from `raw.githubusercontent.com` at a **dereferenced** commit
sha — the Wazuh tags are annotated, and an undereferenced ref sha 404s, which is
worth writing down because a 404 silently becomes "no licence" if nobody checks.

**`wazuh/wazuh-manager:4.14.7` — GPL-2.0-only, and four findings rather than
one word.** Blob `@a42268a2` (tag v4.14.7), 475 lines, sha256 `9136fd9e…`.

1. **GPL-2.0-*only*, not "or later".** The text is "under the terms of the GNU
   General Public License (version 2) as published by the FSF". A badge reading
   "GPL-2.0" hides the `-only`, and `-only` is the stricter grant.
2. **An OpenSSL linking exception**, stated twice — in the preamble and as the
   standard per-file exception paragraph — because GPLv2 and the historic
   OpenSSL licence are otherwise incompatible.
3. **An extended derivative-work interpretation** that is broader than stock
   GPLv2: four triggers including "Links to a library or executes a program that
   does any of the above" and "Includes/integrates Wazuh into a proprietary
   executable installer", with "This list is not exclusive". It also scopes
   itself — "These restrictions only apply if you actually redistribute Wazuh
   (or parts of it)". **We self-host and redistribute nothing, so nothing is
   triggered.** Recorded rather than assumed, because "ship it to a hospital as
   an appliance" is a decision someone could take without re-reading a licence.
4. **The grant covers data files.** "Note that this license applies to the
   source code, as well as **decoders, rules and any other data file** included
   with Wazuh." A ruleset derived from Wazuh's shipped decoders or rules is a
   GPLv2 work. `infra/security/wazuh/rules/intake_rules.xml` is written from
   scratch against our own json fields, copies no vendor rule text, and uses
   only user-range ids — so the question does not arise, deliberately.

Heritage: "Based on work Copyright (C) 2003 - 2013 Trend Micro, Inc." — Wazuh is
an OSSEC fork, so an OSSEC-era licence question is a Wazuh licence question.

**`wazuh/wazuh-indexer:4.14.7` — Apache-2.0.** Blob `@2dee7e9c`, file
`LICENSE.txt` (not `LICENSE`), 201 lines, sha256 `c71d239d…`. Stock Apache-2.0,
no trailing copyright line, no addendum, no field-of-use restriction. The load-
bearing fact is the ancestry: it is a fork of **OpenSearch** (Apache-2.0), not of
Elasticsearch (SSPL / Elastic-2.0). Assuming the wrong ancestor would have put a
source-available licence on the PHI path.

**`falcosecurity/falco:0.44.1` — Apache-2.0.** Blob `@f1ac5eb1`, 202 lines,
sha256 `908a8e97…`, "Copyright 2019 The Falco Authors", no rider (the single
"addendum" hit is line 120 of the standard appendix). **The ruleset is a
separate repository and a separate blob** and was read separately —
`falcosecurity/rules@b4437c49` (tag `falco-rules-4.0.0`), 202 lines, sha256
`61e9bb15…`, also stock Apache-2.0, "Copyright 2022 The Falco Authors". It
matters because our rules extend that ruleset's macros and lists, and a rules
repo relicensing would not show up in the engine's LICENSE.

Neither Apache row is on the CI licence allow-list problem list; the GPL-2.0-only
row is copyleft, which is precedented on this stack (`minio` is AGPL-3.0-only and
already registered) and is a self-hosting question rather than a distribution one.

## What was NOT exercised, and why

**The tier did not boot. It was not shrunk until it did.**

`scripts/security/siem_up.sh --run` on this host:

```

  wazuh rules       12
  falco rules       6
  retention         90 days
  host              BLOCKED — this host cannot run the SIEM tier and the tier is not
                    shrunk to fit: HB-I1 (disk): 14 GiB free, 80 GiB needed;
                    HB-I2 (container memory): not reported, 22 GiB needed

```

| half | state |
|---|---|
| compose tier, rulesets, ossec.conf, Falco config, scrub boundary, console feed, CLI, scripts | **executed, 124 tests** |
| a running manager, indexer and agent; real ingest; `wazuh-logtest` against the shipped rules; Falco's own `--dry-run` rule parse | **NOT run.** `blocked:host-capacity` against **HB-I1** (free 80–100 GB of disk; 14 GiB free here) and **HB-I2** (raise Docker's RAM allocation; "the security + observability tiers alone need 22 GB"). files/05 sizes Wazuh alone at "12 GB + a part-time SRE" |
| Falco's kernel driver | **NOT run**, and would not run even with HB-I1/HB-I2 closed on this machine: modern eBPF needs a host kernel the laptop's container runtime does not expose. It runs on a Linux host, which is where the tier is meant to live |
| the k8s audit ingest | **NOT run.** There is no cluster — INT-201 stands it up with its audit policy. The `localfile` stanza and the four rules are here so that issue mounts a path rather than editing a manager |
| **detection coverage as an SLO** — is the manager still receiving events at all | **not written.** It needs a synthetic event injected on a schedule and observed coming out (files/10 §6), which needs the tier running. `docs/slo/siem.yaml` says so in the file rather than substituting an objective nothing measures; the three probe rows carry liveness meanwhile |
| the HTTP surface the console will call | **not built.** There is no `/admin` route table and no privileged role plane yet (INT-180, INT-189, INT-192). Adding an admin route now, under dev-bearer auth, would be the parallel-authorization-plane defect files/08 §0b F1 names. The feed is a module with a wire format and a content hash; INT-192 mounts it |

Two decisions that look like shrinking and are not:

- **No Wazuh dashboard.** files/10 §7 puts the dashboards in the console's
  Security module, and a second web console over the alert store is exactly
  files/08 §0b F1's parallel authorization plane, where `tenant_id` is a label
  and not an RLS boundary. Dropping it also does not make the tier fit — the
  indexer's JVM alone exceeds what is available.
- **No `falcosidekick`.** Falco writes JSON to a volume the manager's
  logcollector reads. One file, two containers, no forwarder image to license
  and no port between them.

## Values refused rather than invented, with their asks

**A retention window for the SIEM alert store.** files/06 §3's retention matrix
has rows for audio, lane windows, notes, tokens, audit, telemetry and 5651
traffic logs and **no row for SIEM alert storage**; files/10 §6's "30 d hot /
1 y cold" is the application logging pipeline, not the alert store. An alert
store outlives the crypto-shredding it should be subject to, which makes this a
KVKK-7 / DEST-2017 question rather than an ops preference — the same shape as
HB-I8(a), and owned by the same issue, **INT-212** (retention & destruction
policy), whose policy-as-code the engine runs.

So nothing sets one: no `<rotation>` in `ossec.conf`, no index lifecycle policy
on the indexer, no default for `INTAKE_SIEM_RETENTION_DAYS` anywhere, and the
deploy refuses:

```
$ scripts/security/siem_up.sh --run          # with the variable unset
refused: No retention window for the SIEM alert store. files/06 §3's retention
matrix has no row for it and files/10 states none, so this is a KVKK-7 /
DEST-2017 question rather than an ops preference: it belongs to INT-212
(retention & destruction policy). Set INTAKE_SIEM_RETENTION_DAYS once someone
has answered it. Until then nothing expires, which loses no evidence.
exit 2
```

The failure mode of the refusal is that the store keeps everything, which loses
no evidence — the same posture INT-202 took with pgBackRest expiry.

**A `files/HUMAN_BLOCKERS.md` row is owed for this ask and was not written**: this
iteration was scoped not to edit that file. The ask is one sentence for the
owner and counsel via INT-212 — *how long does the SIEM alert store keep an
alert, and does that answer differ from the audit chain's?* — and it belongs
next to HB-I8, which asks the same question about backup copies.

**No correlation threshold.** files/10 §7 names the auth signals — failed logins
and OTP anomalies per phone/IP/ASN, impossible travel, new-device logins, token
reuse — and states a number for none of them. The Wazuh rules therefore classify
single events and carry no `frequency`/`timeframe` pair; a test refuses the file
if one appears. Rate detection belongs to the metric alerts in files/08 §5,
where the numbers that *do* exist (break-glass > 3 / 30 d, access-review age
past 100 days) are written down.

## Judgement calls, named rather than buried

Two ladders had to be joined and neither join is stated anywhere in files/:

- **Wazuh level → SEV.** Levels are Wazuh's published scale (15 "severe attack",
  12–14 high-importance security events, 7–11 warnings, 0–6 notifications and
  user errors); SEV1–SEV4 are `docs/security/incident-runbook.md`'s. The table
  maps each level to the rung whose *stated definition* matches, in one place
  (`intake_platform.siem.rules.WAZUH_LEVEL_SEVERITY`) so the console and the
  pager cannot disagree.
- **Falco priority → SEV**, the same way, over the syslog priority enum.

Neither is a detection threshold — no alert fires or does not fire because of
them — but both are choices, and a reviewer should see them as choices.

A third: **an unrecognised rule keeps its id and loses its name.** Falco loads
the stock ruleset too, and a rules file is editable on the host, so a rule name
that did not come from a file in this repository is not a name we can vouch for.
Wazuh's case is sharper — it expands a field reference into a description at
alert time. The cost is that a stock Wazuh rule reaches the console as an id
with a severity and no prose; the alternative was to let a vendor string that
may contain decoded event data render as a rule name.
