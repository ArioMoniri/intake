# INT-321 — Intake asks its mode up front; "Sıranız geldi" → "Bitirdim"

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile

## Problem (owner report)
The intake "directly goes to written mode" and carried "so many Hastanedeyim /
Sıranız geldi / Bitirdi buttons" so a patient "doesn't know what to and when to
click what." The `Hastanedeyim` control was a mode SWITCH (Hızlı↔Detaylı)
mislabelled as a location status, and it sat — with the `Sıranız geldi`
checkpoint chip — on top of every typed question, competing with the question's
own CTA (one-question-per-turn undermined). INT-295 had already fought the same
row for overflow.

## Change
- The **mode is asked once, up front** (`ModeChoice`, before either lane), and
  recorded on the note as `modeChosen`. Two calm doors: "Hastanedeyim"
  (ayrıntılı) and "Kısa tutalım" (brief). A default value is never a silent
  choice — the chooser shows until a choice is recorded.
- The per-question **`ModeBar` is deleted** (component + its `modeBar.spec.ts`).
- The clinic-interruptible checkpoint (02 §34) survives, **relabelled from
  "Sıranız geldi" to the plain first-person "Bitirdim"**, moved off the
  per-question row into a quiet top-right chip shown only in the ayrıntılı flow
  once something is answered (nothing to keep before that).
- The 02 §33 deferral notice, which lived on the old row, is preserved in the
  step content when a third party is present.

Register (invariant 2, files/00 §2): `siz` throughout; warmth in verb mood
(`-elim`/`-alım`), never the pronoun; card labels are short; sublabels are
descriptive (no bare short imperative), so no `PROSE_REGISTER_FINDINGS` entry is
needed. No numeral reaches patient copy (invariant 22 posture).
