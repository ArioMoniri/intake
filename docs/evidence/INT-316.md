# Evidence — INT-316 · A paired row has no flex contract

**Date: 4 September 2026.** Reference device 320 dp (the narrowest phone
`apps/mobile/e2e/shares.spec.ts:302` already commits this repo to; `app.json` is
portrait-only with `supportsTablet: false`).

## 1. What is wrong

`ListRow.tsx:190` declares the entire contract as `labels: { flex: 1, gap: 2 }`.
There is no `minWidth` on the label column and nothing at all on the trailing
slot, so Yoga hands the label whatever remains after an unshrinkable pill.
`SectionPanel.tsx` hand-rolls the same anatomy — same gap, same 56, same
`flex: 1` column — and inherited the same collapse, in the row whose column
holds the least bounded text the tree renders: the patient's own words.

## 2. Red run

The failing state is geometric, so it was derived rather than clicked, then
confirmed against the one rendering that exists — the simulator screenshot that
prompted this issue, in which `Sesli görüşme` came down the screen one letter at
a time and `Temel` broke as Tem/el.

Available width at 320 dp: **246 dp** for a normal row, 222 inset, 198 with an
icon well. For the reported row, `Sesli görüşme` beside `Metin hazırlanıyor`:

| scale | required | fits? |
|---|---|---|
| 0.9 | 232 | beside |
| **1.0** | **252** | **no room** |

**The row stops fitting at the OS default text size**, with no accessibility
setting touched. An earlier pass in this same fleet assumed a 360 dp reference
and reported the failure one to three steps higher; that assumption was wrong
and both of its headline numbers are withdrawn here rather than carried forward.

Mutation results against the committed rule (each run in `node` on a scratch
file, all ten rows × five pill states × the 0.50–2.00 sweep):

| mutation | effect |
|---|---|
| drop the geometry term | near-misses (a), (c), (d) fail |
| drop the scale ceiling | the `Araştırma` ceiling test fails |
| always stack | near-miss (b) fails on twenty cases |
| `minWidth → 0` (today's contract) | the floor tests fail |

## 3. Green run

`pairedRow.ts` and `pairedRow.test.ts` were written and run in a scratch mirror
outside the repository: **18/18 pass**, `tsc --noEmit` strict clean, prettier
clean at printWidth 100, no placeholder-gate hits. Clamp equality asserted
rather than described — `pairedRowMetrics(shape, 3.0)` deep-equals `2.0`, and
`0.1` equals `0.5`.

## 4. What has NOT been run, and why

**`make check` has not been run for this change, and no exit code is claimed
for it.** The owner has ruled that nothing may execute on the development
machine, and the GPU server has no container runtime and is currently
unreachable. The integrated result — these 24 patches applied together against
`main` — is therefore **unverified locally**, and GitHub CI is the gate: this
issue is not `done` until `check-ts` is green on the pull request.

What *was* verified without running anything heavy: every one of the 24 patch
anchors was counted programmatically against the real files on `main` and
occurs exactly once, and the four e2e gates the change could redden
(`appearance.spec.ts`, `a11y.spec.ts`, `overflow.spec.ts`, `shares.spec.ts`)
were read directly, with every hazard either avoided or patched in the same
change.

## 5. Two corrections recorded rather than quietly fixed

**The design pass read the wrong tree.** The analysis lanes read
`/Users/ario/Downloads/previsit` (`main`) while the session worktree carries a
different, smaller `components/`. Every anchor was re-verified against `main`
before anything was applied.

**"A layout rule in a `.tsx` is unprovable" is false.** `vitest.config.ts`
includes `e2e/**/*.spec.ts`, and source-scanning a `.tsx` from an e2e spec is
how this repo already proves component wiring. The rule was untested, not
untestable, and the missing `ListRow` wiring gate is added here.

## 6. Dropped from the design, with reasons

- **`PairedRow.tsx`**, a renderer component: after the `ListRow` refit it is a
  second renderer of one shape with no call site and strictly less capability
  (no icon well). It would also redden two gates through its **prose** —
  `appearance.spec.ts:344` tests `f.source.includes("numberOfLines")` with no
  comment stripping, and `a11y.spec.ts:729` matches `/<Text[\s/>]/` on raw
  source. `pairedRow.ts` therefore states its guarantee as a type rather than
  naming the thing it forbids.
- **Dropping the icon well above 1.6**: deleting a leading anchor is a design
  change nobody rendered. The well is scaled *and counted* instead —
  `shares.tsx:115` genuinely carries both an icon and a trailing state caption,
  so the premise that no row has both was wrong.
- **Turkish copy** was not touched. Where the only real fix is shorter wording,
  that is the copy owner's call under PolicyGuard and the B1 requirement.
