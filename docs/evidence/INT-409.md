# INT-409 — The visits list uses the real date, not a pinned TODAY_FIXTURE, in every build

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile · **GitHub:** #688 ·
**Labels:** area:mobile, risk:clinical · **Depends on:** INT-370 (merged) ·
**Found by:** INT-179's close-out (PR #687)

## Acceptance (verbatim)
- "\"today\" comes from an injectable clock (the device date in the app's time zone, Europe/Istanbul for date boundaries); tests inject a fixed clock; no build contains a pinned date"
- "a test fails if any source under `apps/mobile/src` (outside tests and fixtures) pins a calendar date constant used as \"now\", with a near-miss control"

## Problem
`apps/mobile/src/app/(tabs)/visits/index.tsx:38` bound `TODAY_FIXTURE` to
`"2026-08-27"`, and the screen read it five times: the calendar's opening
month, its pre-selected day, the upcoming/past split, the Geçmiş list and the
calendar's today marker. Nothing guarded it by `__DEV__`, so every build used
it. The release export of main (`2f75900f`, `expo export --platform ios`)
carries the literal once; the export of this branch carries it zero times.

For a real patient this date was simply wrong. A visit booked for next week,
opened after 27 August 2026, sat under "Yaklaşan" or "Geçmiş" according to a
day that had already passed. The calendar also marked a day that was not today.

A second reading of "today" had the same class of defect: the records screen
(`records.tsx`, `OtpRecords`) took `new Date().toISOString().slice(0, 10)`, the
**UTC** day. From 00:00 to 03:00 in Istanbul that is yesterday. So for three
hours every night the records screen and Vizitlerim could disagree about whether
the same visit was past. Both now read the same clock and the same zone.

## Change
- **`src/lib/clock.ts` (new, pure, node-tested).**
  - `Clock = () => Date` is the injection seam, and `deviceClock` is the
    device's own time.
  - `isoDateIn(instant, timeZone = APP_TIME_ZONE)` gives the ISO day that an
    instant falls on in a zone. It uses `Intl.DateTimeFormat(...).formatToParts`,
    the same Intl surface `lib/calendar.ts` and `VisitCard` already format with.
  - `todayIso(clock)` takes the clock explicitly, so no caller can forget it.
  - `APP_TIME_ZONE = "Europe/Istanbul"` is the zone the server anchors visit
    times in (`intake_platform/doctor_link.py` `TZ_NAME`). The mobile app had
    no clock or time-zone helper to reuse; that server anchor is Python, so the
    zone name is shared and the code is not.
- **`src/app/(tabs)/visits/index.tsx`.** The constant is gone. The screen's
  default export takes `{ clock = deviceClock }`, and the injection seam is on
  the screen itself. The screen computes `const today = todayIso(clock)` once
  per render, and all five readings use `today`.
- **`src/app/(tabs)/records.tsx`.** `pickUploadVisit(visits, todayIso(deviceClock))`
  replaces the UTC slice.

## Where the tests live, and why not the named path
The issue names `apps/mobile/src/app/(tabs)/visits/visits.test.ts`. A test
file cannot live there. expo-router builds its routes from a `require.context`
over `src/app`, and its regex (`node_modules/expo-router/_ctx.ios.js`) matches
every `.ts`/`.tsx` except `+api`, `+html` and `+middleware`. A `.test.ts` under
`src/app` is therefore a route, and Metro bundles it together with vitest.

This was measured, not assumed. A nine-line vitest file planted at exactly that
path makes the production export fail:

```
$ expo export --platform ios --output-dir <scratch> --no-bytecode
SyntaxError: …/vite/dist/node/module-runner.js: … Invalid call at line 1079: import(filepath)
exit=1
```

The probe was deleted and the export went green again. The tests therefore
live in the two places mobile vitest already collects from:

- `apps/mobile/src/lib/clock.test.ts` covers the clock, the Istanbul day
  boundaries, and the screen's four readings of "today" driven by fixed clocks.
- `apps/mobile/e2e/pinnedToday.spec.ts` holds the tree guard, its controls and
  near misses, and the two screens' wiring.

The backlog row lists these two paths.

## The guard (`e2e/pinnedToday.spec.ts`)
The guard reads the TypeScript syntax tree (`typescript` is already mobile's
devDependency) rather than grepping text. A date in a comment, or a visit's own
`date:` field, can therefore never be mistaken for "now".

- **A pinned date** is any of these:
  - an ISO-day string;
  - `new Date(…)`, `Date.UTC(…)` or `Date.parse(…)` over literals only;
  - a const bound to one of the above;
  - either branch of `?:`, `&&`, `||` or `??` that yields one;
  - an arrow that always returns one, i.e. a stuck clock.
- **Used as now** means the date lands in one of two places:
  - a slot named with the word `today`, `now` or `clock`: a variable, property,
    JSX attribute, parameter or destructuring default, or assignment target.
    Words are split on `_` and camelCase, so `unknown` and `known` do not match;
  - an argument, at a parameter so named, of any function declared in the tree.
    The tree's own signatures supply the names (`splitVisits`,
    `pastVisitsRecentFirst`, `initialMonth`, `initialSelectedDay`,
    `buildCalendarGrid`, `pickUploadVisit`, `todayIso`). The guard derives them
    and does not list them, and it asserts the derivation is not empty.
- **Scope.** The guard covers the 194 `.ts`/`.tsx` files under `src`, with tests
  excluded, because a test injects a fixed clock by design. Fixtures need no
  exclusion: the synthetic seed's dates are visit and record dates, never
  "now", and the scan passes over it.
- **Controls (each must fail).** Nine planted shapes:
  - the finding's own `const TODAY_FIXTURE = "2026-08-27"`;
  - an innocently named const handed to `splitVisits`;
  - a literal handed to `initialMonth`;
  - a JSX `todayIso` attribute, in both forms;
  - a stuck clock, written three ways;
  - a pinned date behind `??`, `?:` and `&&`;
  - a pinned destructuring default;
  - a `todayIso` property;
  - an assignment to `.today`.
- **Near misses (each must pass).**
  - `todayIso(clock)` itself;
  - a today computed at run time, including from `Date.UTC(year, month, day)`
    and behind `??`;
  - the weekday-header anchor `Date.UTC(2024, 0, 1)`, which is not now;
  - a `1900-01-01` bound handed to a function with no today parameter;
  - a visit's `date:` field;
  - a date in a comment;
  - `unknownDate` and `known`.

## Outside the acceptance (recorded, not built here)
- **Not verified on a device.** Hermes implements `Intl.DateTimeFormat` with
  `timeZone` and `formatToParts` on both platforms, and the web target uses the
  browser's Intl. This PR ran no device or simulator build.
- **A screen left open across midnight.** `today` is recomputed on every
  render, so the split follows the clock. The calendar's opening month and
  pre-selected day are initial state, as before INT-409, and do not jump while
  the patient is looking at them.
