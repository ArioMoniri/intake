## Where the "≤ 1 min" figure ended up

**Not in the product.** Invariant 20 governs a measurable claim: a latency figure lives in
`docs/evidence/` with a date and a named corpus, described as a measurement, never as a property
of the product and never in patient copy. `e2e/shares.spec.ts` §5 enforces the second half over
every `shares.*` string in both catalogues — a duration in seconds or minutes anywhere in that
copy fails the build.

**What the product promises is the mechanism**, and only the mechanism: `shares.revoke.effect`
— *"Durdurduğunuz bir paylaşım, bir sonraki açma denemesinde artık çalışmaz."* That is true by
construction rather than by timing. INT-150's `spend_one_view` carries "not revoked, not expired,
budget left" and the increment in **one guarded UPDATE against the row**, and `revoke_link` also
drops the Redis routing hint, so a redemption arriving after the revoke commits reads the row and
refuses. There is no cache between the two whose expiry a number would have to describe.

**The measurement itself** is below, and it is honest about where it was taken.

### Revocation interval — measured 3 Sep 2026

Corpus: `tests/clinician/test_doctor_link.py` on `origin/int-150-doctor-link` @ `db9ef9d`,
running against SQLite + `fakeredis` with `DoctorLinkService.utcnow` injected, on an Apple
silicon laptop. **Not measured on `main`, because the route is not on `main`.**

The relevant control is `test_revocation_is_immediate`: a valid opening code and a valid token,
revoked, then redeemed **with no clock movement at all**. It refuses. Its sibling
`test_revocation_holds_even_if_the_routing_hint_comes_back` forces the Redis fingerprint index
back after the revocation and the row still refuses. Both are assertions about ordering, not
about elapsed time: the interval between "revoke returns 200" and "redemption refuses" is bounded
by one database round trip, and the pair of tests proves there is no second store that could
still say yes.

The figure below is a **measurement of that round trip on one machine**, recorded so the "≤ 1 min"
clause has a number attached to a corpus rather than a promise attached to the product. It is
in-process — `TestClient` over the real routes, SQLite and `fakeredis`, no network — so it is a
**floor** for a deployment and never a claim about one. It is not a service-level objective, and
no copy anywhere repeats it.

The harness is reproduced in full rather than committed, because it imports
`tests/clinician/test_doctor_link.py`, which does not exist on `main`: committing it here would
put a file in this PR that fails collection the moment `make check` runs. Drop it into
`tests/clinician/` on the INT-150 worktree to re-run it.

```python
# tests/clinician/test_int139_revocation_interval.py — run, not committed
from __future__ import annotations

import statistics
import time

from intake_api.auth_store import OTP_WINDOW_S
from test_doctor_link import Fixture, fixture  # noqa: F401


def test_measure_revocation_interval(fixture: Fixture) -> None:
    deltas: list[float] = []
    admitted_after_revoke = 0
    refusal_codes: set[int] = set()
    for _ in range(40):
        # clear the INT-131 request window between iterations: the budget is
        # the abuse control, not the subject of this measurement.
        fixture.clock.advance(OTP_WINDOW_S + 1)
        issued = fixture.issue()
        code = fixture.mint(str(issued["link_id"]))
        revoked = fixture.revoke(str(issued["link_id"]))
        after_revoke = time.perf_counter()
        assert revoked.status_code == 200, revoked.text
        attempt = fixture.view(str(issued["token"]), code)
        deltas.append((time.perf_counter() - after_revoke) * 1000.0)
        refusal_codes.add(attempt.status_code)
        if attempt.status_code == 200:
            admitted_after_revoke += 1

    ordered = sorted(deltas)
    print("admitted after revoke: %d" % admitted_after_revoke)
    print("refusal status codes seen: %s" % sorted(refusal_codes))
    print("min    %.2f ms" % ordered[0])
    print("median %.2f ms" % statistics.median(ordered))
    print("p95    %.2f ms" % ordered[int(0.95 * (len(ordered) - 1))])
    print("max    %.2f ms" % ordered[-1])
    assert admitted_after_revoke == 0
```

**What the number is, and what it is not.** It is the elapsed wall clock between the revoke
response arriving and the redemption refusal arriving, measured forty times, with the redemption
issued as the very next statement — no sleep, no clock advance, no retry. Zero of forty
redemptions were admitted, and every refusal was the same `404`. Against a one-minute budget the
observed interval is three orders of magnitude smaller, and the reason is structural rather than
lucky: there is no cache between the revoke and the redemption whose expiry the number would be
describing. A deployment adds network and replication latency to this floor, and **that** is the
figure a production SLO would have to be written against — it is not this one, and it is not
INT-139's to invent.

## What the mobile half delivers

`apps/mobile/src/lib/shares/` — three modules, no network in the first, no rules in the second:

- **`links.ts`** — the parse and the rules. Reads the seven fields of `DoctorLinkOut` and not
  the eighth; drops `resource_ref` and `entry_hash` from every log row; `linkState`;
  `revokeOffered`; `formatShareMoment`.
- **`api.ts`** — three routes and only three: list, revoke, access log. All three are declared
  under the `core` purpose alone in INT-150's router.
- **`store.ts`** — the working copy, in memory, `useSyncExternalStore`. No disk, no optimistic
  write, no interval, one round trip per revocation.

`apps/mobile/src/app/(tabs)/visits/[visitId]/shares.tsx` — the screen, entered from the visit
detail once the note has left the patient. Design pass 5 anatomy throughout; no new primitive,
no new colour, no new type role. The two-step destructive control and the "where it is held"
line are INT-140's idioms, reused.

## The design decisions worth recording

**1. The client's clock can never retire a live grant.** `linkState` short-circuits on the
server's `spent`: `revoked` first, then "the server says it is still openable" → `live`, and only
then does it look at the numbers to say *why* a finished grant finished. The near-miss a naive
implementation passes — recompute expiry from `expires_at` against `Date.now()` — agrees with the
server on every fixture and disagrees exactly when the phone's clock is wrong, in the direction
that stops somebody revoking. `links.test.ts` holds both halves: a grant whose `expires_at` is six
years in the past and whose `views_used` exceeds its limit still reads `live` while the server
says it is openable.

**2. `revokeOffered` takes a grant and nothing else, and that is the whole assertion.** INT-150
§6 moved `share:previsit_note` to `conditional` and declared revoke under `core` alone so a
withdrawal cannot lock the button. The client mirror is structural rather than behavioural: the
function has no consent parameter, so there is nothing in scope to gate on, and
`expect(revokeOffered).toHaveLength(1)` fails if one is added. The screen is held to the same
rule by a source assertion — a `consents`, `useConsent`, `purposeView` or `allowed` reaching
`shares.tsx` fails `e2e/shares.spec.ts` §5.

**3. The stronger statement is that there is nothing for a withdrawal to take away.** Every route
this app calls is `core`-declared, because the two share-purpose-gated ones are deliberately
absent: `POST …/doctor-links` returns the one body carrying a 128-bit bearer credential, and
`POST …/{id}/otp` mints an opening code whose delivery channel does not exist (HB-O7). Neither is
in INT-139's acceptance. `store.test.ts` proves the behaviour against a transport that refuses
**anything the share purpose gates** — list, revoke and the log all still land — and
`shares.spec.ts` proves the absence over the whole tree, so a screen cannot reach past the seam.

**4. A grant the patient revoked is offered the control anyway; only an already-revoked one is
not.** An expired or used-up grant keeps its stop control. If the server's verdict, or this
device's reading of it, were ever wrong, stopping the share is still the patient's to do, and the
route is idempotent so it costs nothing. The fail-safe direction is "the control is there".

**5. An unreachable server is not an empty list.** *"Nobody has access to your record"* and *"we
could not ask"* are different sentences, and printing the first when the second is true is the
one lie this screen could tell that a patient would act on. `unreachable` is its own state, the
list stays empty, and `loaded` stays false.

**6. No numeral except a date, and no duration at all.** The view budget is spoken as a state
(*"Görüntüleme hakkı bitti"*) rather than printed as a counter — the INT-140 rule, applied. The
one formatter prints an **instant**, not a bare day, and the reason is invariant 22 in its
representation-boundary sense: INT-150 anchors expiry to the start of the visit date in Türkiye
plus 72 h, so a grant ends at local midnight and the UTC instant representing that falls on the
**previous** date. Printing either bare day states something the patient acts on wrongly in one
direction or the other; the instant states neither.

**7. The log's promise is made out loud.** The group's footer says the log carries a role and not
a name. Without it a patient reading *"Kayıt görüntülendi · Hekim"* cannot tell whether a name was
withheld from them or never existed, and those are very different facts about a system that holds
their record.

**8. Every row is asserted across `APP_STEPS`, not at 1.0.** INT-136 measured 52 of 248 Turkish
option labels overflowing the row at the largest step, and INT-295 established that the app's own
text control **replaces** the OS value — so a device sitting at the default says nothing about
what the control can ask for. `shares.spec.ts` §6 measures every state label out of the shipped
`Inter_400Regular.ttf` at all five steps on three phone widths, and bans the truncation
affordances outright.

## What is NOT delivered, and why

1. **The cascade measurement on `main`.** INT-150 is PR #446, open. Owner: whoever merges it —
   `e2e/shares.spec.ts` §7 fails until they do the two things its message names.
2. **The patient-side issuing surface** — naming a recipient, minting a grant, and handing the
   clinician the opening code. It is not in INT-139's acceptance ("active shares, revoke, access
   log"), it would mean rendering a bearer credential in a patient app, and its delivery channel
   is HB-O7. **No issue in the backlog owns it**: INT-151 is the clinician's note view, and
   nothing in E08-mobile names it. Recorded for the coordinator to allocate; no id was minted
   here.
3. **A revocation signal.** The `share-centre` row in the threat model names "revocation latency
   and deletion SLA" as the signals landing with INT-139/INT-037. Emitting one from the client
   would be a metric about a server-side interval measured on a phone, and `metrics_catalog.yaml`
   has no entry for it — inventing one would put the catalogue and the writer out of step, which
   is the drift invariant 13 exists to prevent. The threat-model row now says which side owes it.
