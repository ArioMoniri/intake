# INT-591 — a release build offers no voice consent it cannot use

GitHub #993 · Sec-Row: `mobile` · branch `int-591-release-voice-consents`, stacked on
`int-588-release-copy-truth`. The legal lane's recommendation (D25) from the INT-588 review,
30 Oct 2026.

## 1. The defect

A release build has no voice: intake.tsx gates the voice lane and dictation on `__DEV__`, and
INT-421 strips the voice lanes from the production profile. Yet İzinleriniz offered the `voice`
and `lane:affect` consents there. Granting either recorded special-category consent evidence for
a feature that cannot run (KVKK m.4 proportionality) and offered a choice that changes nothing.

## 2. What changed

- `apps/mobile/src/lib/buildCopy.ts`: `consentActions(view, mode)` says what the consent detail
  offers in this build — `grant` (the ledger's `grantable`, except for `voice` and `lane:affect`
  in a release build), `withdraw` (the ledger's `withdrawable`, never gated on the build:
  withdrawal must always be possible, files/06 §2), and `note` (the line shown in place of a grant
  the build does not offer). `voiceGroupNoteKey(mode)` gives the group line in release.
- `me/consents/[purpose].tsx`: the grant button, the note and the withdraw control come from
  `consentActions(view, currentBuildMode())`.
- `components/ConsentList.tsx`: the voice group shows the release line under its title (used by
  İzinleriniz and the first-run consent screen alike). The rows still open their text; a toggle
  on a granted row still withdraws.
- Copy (tr first, en mirror, same order): `consent.group.voice.release` — "Bu sürümde sesli
  görüşme yok; bu izinler kullanılmaz." / "This version has no voice sessions; these permissions
  are not used."
- No consent text, data category, retention, closed purpose list or server snapshot changes.
  `lane:linguistic` is untouched: it reads text, not voice, and has no served text anyway.
