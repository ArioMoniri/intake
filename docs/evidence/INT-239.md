## What changed

**Entry.** `voiceIntakeReducer` now has exactly three phases — `gate`,
`dialogue`, `steps` — and a ready voice lane goes straight from the probe
into the conversation. The offer screen, its two primary buttons and the
one-shot record → transcribe → extract → confirm path are deleted:
`components/VoiceFirstIntake.tsx` is gone, replaced by the much smaller
`components/DialogueGate.tsx` (probe + entry copy + the quiet "Yazarak
devam edin"), and `prefillForPack` went with it because nothing else used
it. `lib/voice.ts` keeps every helper the dialogue still calls. A test
enumerates the reducer's reachable phases so a fourth one cannot creep back
in, and a copy test asserts `voiceFirst.title` / `voiceFirst.start` /
`voiceFirst.cancel` / `dialogue.start` are absent from both catalogs.

Typed intake stays reachable in three places: the gate's secondary line,
the dialogue's own "Yazarak devam edin", and the always-present composer
inside the conversation — plus every failure path.

**Depth.** Twenty-two answer-gated follow-ups across the ten department
packs, each gated with the same `askIf` data predicate the DSL's `ask_if`
mirrors. Seven packs carry a level-two gate (a gate on a question that is
itself gated). Pack sizes and opening (all-gates-closed) flows:

Ten departments are pinned by `DIVERGENCE` in `questions.test.ts` with the
exact symmetric difference of the two asked sets; three of them (Kardiyoloji,
Göğüs, Gastroenteroloji) diverge in **both** directions, so neither flow is
a prefix of the other.

**One gate layer, three surfaces.** `applicableQuestions` was already the
typed StepFlow's rule; INT-239 routes the spoken dialogue (`stream.ts`
`advance`) and the realtime section panel through the same predicate, so
the conversation, the note panel and the typed steps ask exactly the same
set. Only CONFIRMED answers open a gate — a pending suggestion is not an
answer (invariant 1 posture, and the Kleene rule of files/13 §9.2, where
UNKNOWN does not open a gate). A suggestion that lands for a still-closed
gate is kept, not discarded, and becomes that question's quick confirm turn
the moment the gate opens; `confirm_pending` refuses a question the flow
does not ask, so the note can never gain an answer to an unasked question.

**Progress.** The typed steps no longer print `x / 9`. The row shows the
answered count plus one honest line — "Yanıtlarınıza göre birkaç soru daha
gelebilir." — whenever a gate could still open, and the dots fill by
answered-ness rather than by position. The dialogue's section strip
denominator is now the applicable set, so it grows visibly when an answer
opens a gate.

**Vocal path.** Entry is the conversation; mic permission is requested by
the dialogue session on its first clip (unchanged); clip pre-warm now
ensures the FIRST question's clip on its own before fanning the rest out in
parallel, so the opening turn is not queued behind twelve other syntheses;
barge-in (`player.pause()` before dispatch, same JS tick) and the
completion rule (all applicable answered → review; only genuinely
unanswered → typed steps) are untouched.

## Refused judgment — for the pack owners, not for this tier

Every gate added here asks for a further detail of something the patient
already named. The following were considered and deliberately NOT invented,
because each would require a clinician to decide that a question must be
asked *because a symptom might be dangerous* — that is the sourced chain's
work (L0 scaffolds + compiler, INT-057/INT-041, with `source:
{guideline_id, version, date, url, retrieved_on}` against a committed
snapshot and CODEOWNER review), never a dev fixture:

1. **Chest pain → exertional/radiation red-flag probe.** Which combination
   of character, radiation and autonomic symptoms should arm a probe is a
   rules-engine decision (invariant 1). The dev pack asks the dimensions
   and stops.
2. **Breathlessness severity thresholds.** No functional-class question
   (NYHA-shaped "how much activity brings it on"), because the option
   boundaries are a clinical scale, not a description.
3. **Fever + duration / height cut-offs.** `fever_pattern` asks *when* the
   temperature rises, in words. No numeric reading is asked and none is
   offered (invariant 22); any threshold belongs to a sourced rule.
4. **Back or neck pain → weakness, bladder or bowel change.** The cauda
   equina battery is a red-flag set with a defined action; `ortho_spread`
   and `ortho_spread_feel` deliberately ask only about tingling and
   numbness where the pain travels, and name no consequence.
5. **Headache → thunderclap onset, first-and-worst, systemic features.**
   Onset speed is already asked neutrally by `onset`; deciding which onset
   pattern arms a probe is sourced work.
6. **Sputum or urine blood, sudden painless vision loss, nocturnal
   diarrhoea, unintended weight loss.** These are alarm features; where an
   existing pack chip already mentions one (e.g. `pulmo_assoc`
   `weight_loss`) it stays a plain multi-select item with no follow-up
   gated on it, because a gate there would encode urgency.
7. **Pregnancy / LMP and immunosuppression as universal class-1
   gatekeepers** (files/13 §14.13). Correct, and out of scope for a dev
   fixture: they need the compiler assertion that each precedes every step
   whose gate references them.
8. **Safeguarding, substance use, sexual and reproductive history.** files/13
   §13 puts these behind `delivery: text_first | text_only` with no
   extraction attempted for safeguarding. The dev tier has no `delivery`
   field, so no such question was added at all rather than adding one that
   would be spoken aloud.

`skip_if` was **not** mirrored. Every structurally-obvious dev-tier gate is
naturally "ask when X", and adding an unused field would be a placeholder
(invariant 17). The compiled packs carry `skip_if` as a `GuardExpr` string
anyway; `AskIf` mirrors the shape discipline (pure data, JSON round-trips),
not the grammar.
