## The exact grant surface minted

JWT HS256, claims exactly `{iss, sub, jti, iat, nbf, exp, video}`, and
`video` exactly:

```json
{
  "room": "intake-<canonical session uuid>",
  "roomJoin": true,
  "canPublish": true,
  "canSubscribe": true,
  "canPublishData": false,
  "canPublishSources": ["microphone"]
}
```

`canPublishData` is an **explicit false** because livekit-server defaults an
absent `canPublishData` to true. TTL is capped at 600 s (`ttl_s` may only
shrink it). No roomCreate/roomList/roomRecord/roomAdmin/ingressAdmin/
recorder/agent/hidden/canUpdateOwnMetadata; no claims-level sip/agent/
inference/observability/roomConfig/metadata/attributes.

- minted token → `{"code":"unauthenticated","msg":"permissions denied"}` —

  token signature is invalid`.

## How the audio-write guard scans

`tests/voice/test_audio_retention_guard.py`, three layers under INT-036's
policy-level guard (tests/legal/test_retention_engine.py — merged via #251
mid-iteration; origin/main was merged back in and the combined suites run
green: no code shared, docstrings cross-reference, the AST scan sweeps the
new retention engine cleanly):

1. **Code (AST, INT-025 house style):** every `*.py` under `packages/` and
   `services/` (tests/venv/build excluded) is parsed; findings are (a) any
   import of an audio-I/O library (`wave`, `aifc`, `sunau`, `soundfile`,
   `pydub`, `audiofile`, `audioread`, `torchaudio`, `librosa`, `pyaudio`,
   `sounddevice`, `scipy.io.wavfile` — dotted prefixes matched), (b) any
   string literal ending in an audio extension (.wav .mp3 .ogg .oga .opus
   .flac .m4a .aac .pcm .amr .aiff .aif .wma .webm .mka .caf — a filename or
   object key someone could write), (c) any literal starting `audio/` (an
   object-store content type). The per-file allow-list is empty and a test
   pins it empty; the anticipated future entry is the protocol clip cache
   (agent TTS output, not patient audio), which must arrive with its own
   review. A filesystem sweep also asserts no audio-extension *file* exists
   under packages/, services/ or infra/.
2. **LiveKit config:** parses `infra/livekit/livekit-dev.yaml` — no
   `redis`/`egress`/`ingress`/`recording`/`webhook` keys (with no redis bus,
   egress/ingress workers cannot even register: recording is structurally
   impossible, not merely off), rooms ephemeral (`empty_timeout` ≤ 600,
   `departure_timeout` ≤ 60, auto-create, ≤ 4 participants), audio/opus the
   only codec, no keys in the committed file, TURN embedded UDP-only.
3. **Compose:** the `livekit` service is profile-gated (clamav precedent),
   tag-pinned, loopback-only ports, mounts exactly the config file `:ro`
   (nothing writable — no volume to record onto), keys from env with a
   dev-only-labelled default; no service in the dev tier matches
   egress/ingress/recorder; no volume string anywhere smells of
   record/audio/media.
