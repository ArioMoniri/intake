# INT-485 — admin oauth2-proxy logs no staff email or client IP

GitHub #830. Sec-Row: `admin-console`. Invariant 6.

## Acceptance (verbatim, docs/backlog/issues.yaml)

> 1. the admin oauth2-proxy service in infra/staging/compose.yaml sets OAUTH2_PROXY_REQUEST_LOGGING and OAUTH2_PROXY_AUTH_LOGGING to "false", with a comment saying why, the same as INT-481's oauth2-proxy-grafana; start-up and error lines are still written
> 2. tests/infra/test_staging_admin_tier.py::TestLoginGate pins both, with a near-miss that the default (both absent), either one alone, or either set to "true" fails the same check; the red and green runs are recorded in docs/evidence/INT-485.md; nothing is deployed from the PR

## The defect

INT-421's admin login gate (`oauth2-proxy` in `infra/staging/compose.yaml`) kept oauth2-proxy's
default request and auth logs. In v7.15.4 both switches default to on
(`pkg/apis/options/logging.go`, read at tag v7.15.4 through the GitHub contents API):

- `flagSet.Bool("auth-logging", true, ...)` and `flagSet.Bool("request-logging", true, ...)`;
- `pkg/logger/logger.go`: both default line formats begin `{{.Client}} - {{.RequestID}} -
  {{.Username}}`, and the request line also carries `{{.RequestURI}}`;
- `pkg/apis/options/load.go`: `v.SetEnvPrefix("OAUTH2_PROXY")` with `AutomaticEnv()`, so
  `OAUTH2_PROXY_REQUEST_LOGGING` and `OAUTH2_PROXY_AUTH_LOGGING` are the two switches.

As a result, every console request wrote the signed-in staff email and the client IP into the host's
json-file container logs.

## The change

- `infra/staging/compose.yaml`, service `oauth2-proxy`: `OAUTH2_PROXY_REQUEST_LOGGING: "false"` and
  `OAUTH2_PROXY_AUTH_LOGGING: "false"`, with a comment saying why. Standard logging (start-up and
  error lines, format `[{{.Timestamp}}] [{{.File}}] {{.Message}}`) stays on.
- This is the same pair INT-481 sets on `oauth2-proxy-grafana` (branch
  `int-481-observability-stack`). That gate runs the same image,
  `quay.io/oauth2-proxy/oauth2-proxy:v7.15.4@sha256:b1b2021f…2ded`, also in `--alpha-config`
  mode. INT-481 ran that binary with both switches off: it started, logged its "OAuthProxy
  configured …" line, and wrote no request line (docs/evidence/INT-481.md on that branch). This
  PR does not run the binary again.
- `tests/infra/test_staging_admin_tier.py::TestLoginGate` pins both switches. Its near-miss runs
  the same check on the service's own environment and expects it to fail:
  - with both keys removed (the default);
  - with only one key set to `"false"`;
  - with either key set to `"true"`.
- `docs/security/threat-model.md`, `admin-console` row: the control and the test are recorded.

## Limits, stated rather than hidden

- Nothing is deployed from this PR; the merge queue deploys. Until then the host's gate keeps
  logging both lines.
- Lines written before the deploy are in the old container's json-file log (`max-size 10m`,
  `max-file 3`). The environment change makes compose recreate the container. Docker removes a
  container's json-file log together with the container. Whether the old container was removed
  on the host is to be checked at deploy; this PR did not verify it.
- Caddy's own logs are out of scope. The Caddyfile declares no access `log` directive.
