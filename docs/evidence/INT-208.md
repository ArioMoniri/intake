## What the tests pin

- Capability fallback matrix: Expo Go (`storeClient`) → `expo_go_stub` on
  both platforms; dev/standalone build → `healthkit` / `health_connect`;
  web/unknown → `unsupported`. Native import failure → `needs_dev_build`;
  Health Connect zero grants → `permission_denied`; HealthKit failed
  authorization request → `permission_denied` (Apple hides read denial by
  design — a denied read yields empty data, stated in the adapter comment).
- Formatting (invariant-22 display discipline): `useGrouping:false`
  (`12345 adım`, never `12.345`), number+unit one non-breaking atom (NBSP,
  no plain space after a digit), locale decimals (`6,4 saat` / `6.4 h`),
  en-dash ranges (`58–64 atım/dk`), absent data stays absent. lib/health
  imports no voice/speech/TTS module (source-fact test).
- Note attach: `attachHealth` stores/replaces the block; `device_health`
  section is labelled (`review.section.health`), last, scope-off excludes
  it from `sentSections` without blocking send; a sent note is frozen.
- Consent gating: `healthConsentOn` true only with the explicit `health`
  consent; i18n tr/en key parity holds (existing suite).

## Corrections — 2 Sep 2026, re-verified against `main`

Recorded on re-opening `int-200-health-connectors` five days after the merge. The merge is a
no-op: resolving all fifteen conflicts in main's favour yields `origin/main`'s exact tree
(`409e0431`), because every file above is already on `main`. What follows is what this file
claimed that has since stopped being true, and what is now true that it could not have known.

1. **"`device_health` … last" is no longer true, and `note.ts` asserts it twice.** When this
   was written the block was the final section. INT-282 now inserts a `measurements` block
   *before* it (boy, kilo, pain score) and INT-236's environment deferral — with INT-256 as a
   second consumer — appends a `deferred` section *after* it. Two comments in
   `apps/mobile/src/lib/intake/note.ts` each claim their section is "always the last"; both
   cannot be right, and the `deferred` one is. The **behaviour** is correct and deliberate —
   the patient's own words stay first, machine-attached and machine-derived blocks last — so
   this is a stale claim, not a defect. The suite does not catch it because the ordering
   assertion calls `buildNote(state.answers, ayse, state.healthLines)` with no `deferred`
   argument, so it never sees the two sections together.

2. **Device-local was the right call and it is now *declared*, not merely absent.** The
   original scope note reasoned that health metrics are a new personal-data category and
   server persistence needs the human — the same test INT-170 applied to the candidate
   overlay lane, where a server-side store of unconfirmed inferences would itself have been
   the stop-and-ask. Device-local needs no human decision *and* leaves the forbidden state
   with no storage to live in. INT-224 then found the other half: a store declaration derived
   from the schema alone understates what this product processes, precisely because
   invariant 3 and this issue's device-local choice both mean there is no column to derive
   from. Health reads are therefore one of the four rows in `OFF_SCHEMA_FLOWS`
   (`packages/intake_platform/src/intake_platform/store/facts.py`) as `health_platform_reads`
   — `persisted=False`, `active=True`, `recipients=REC_ON_DEVICE` → `Sharing.NONE`, sourced to
   `healthKitConnector.ts` — and the three Android health permissions plus
   `NSHealthShareUsageDescription` are classified back to that flow id, so a permission added
   without an inventory row fails the gate rather than defaulting to "not shared".
   **Re-verified true after this merge**, along with the invariant-6 posture: `lib/health`
   and `HealthSection.tsx` contain no `console.*`, no `fetch`, no storage and no analytics
   call, so there is nothing to redact because nothing is emitted.

3. **The licence rows stand; the pin moved and the background-delivery trap is answered.**
   `files/00_STATE.md` §2 recommends `@kingstinct/react-native-healthkit` **14.0.2** and warns
   that its config plugin *enables background delivery by default*. `package.json` pins
   `^14.1.0` — the version whose LICENSE blob was verified upstream above — and `app.json`
   sets `"background": false` and `"NSHealthUpdateUsageDescription": false` explicitly, so the
   warning is answered rather than inherited. No change to the licence verification itself.

4. **A gap this issue does not close, named rather than quietly filled.** `00_STATE` §2 records
   that iOS 27's `HKHealthStore.earliestAuthorizedSampleDate(for:)` makes a limited-history
   grant the only distinguishable third authorization state, that data before that date must
   be treated as *unknown* rather than absent, and that no React Native module exposes it. The
   capability ladder shipped here has two states where iOS 27 has three. Nothing in this
   surface computes a baseline, so nothing is wrong today — but it is a gap, and it belongs to
   its own issue rather than to a retro-edit of this one.

5. **The run figures above are dated measurements.** "11 files / 109 tests" and "14 files /
   181 passed" were true on 28 Aug against that day's tree; the mobile suite has grown
   several times over since. They are recorded as measurements with a date, never as
   properties of the product (invariant 20).
