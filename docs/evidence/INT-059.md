Reading the life-threat file into `RedFlagRule` needs a name translation,
and it is done in the open in `translate_life_threat_rule` rather than by
editing the file: that document spells the predicate `gate:` and the
provenance block `evidence:`, while the DSL uses `when:`/`source:` — the
file's own `TODO.schema_reconciliation` block records exactly this
conflict as open. The translator maps the two key names, drops annotation
the DSL does not model (`age_band`, `excluded_criteria`, the `golden_*`
blocks, `audio`, `carry_child`, …), and rewrites `.` → `__` in the
`tense_anchor` **only**, because `SlotKey` admits no dot while the `when`
grammar does. Predicate text, levels, registers, tenses, routes and every
Turkish string pass through byte-for-byte, and the `action_script_edited`
mutation below proves that an edit to any of them reaches the goldens.

A mutation counts as detected in either of two ways, both legitimate: the
rule set **refuses to build** (schema or validator refusal — the earlier
line of defence) or the built set **evaluates a golden differently** from
its record.

Two findings worth keeping, because they are properties of the design
rather than of the test:

1. **Any edit to the base RED's `when` is caught at build time, before the
   goldens run.** `red_gate_narrowed_one_arm` and
   `comparison_flipped_equality` both surface as
   `tightened 'when' must be a top-level disjunction with one disjunct
   structurally identical to the parent`. That is files/12 §4 layer 2
   working exactly as intended: the child's `tighten_rule` pins the
   parent's predicate verbatim, so the parent cannot drift without the
   child noticing. `red_gate_narrowed_arms_dropped` was added afterwards
   to prove the goldens *themselves* also catch the under-trigger
   direction, on a rule (`rf.chest_pain_cardiac_features`) with no such
   build-time tripwire — 5 goldens fail there.
2. **`LT-01-N` alone does not catch the gate loosening.** The file's own
   near miss is dated three days back, and the rule is `tense: now`, so
   the temporal guard blocks it regardless of the gate. The loosening is
   caught by the *same-day* near misses this corpus adds
   (`miss/c1-karakter`, `miss/c1-yayilim`, `miss/c1-diakritik`,
   `miss/c1-kill-switch`). Worth knowing before anyone treats the four
   `golden_negative` blocks in the YAML as sufficient on their own.
3. **The route axis needed pinning separately, and nearly did not get
   it.** `RulesTriageResult` carries register and location but *not* route
   — route lives on the rule. The first draft of `GoldenCase` documented a
   route assertion it did not actually make. `route` is now an explicit
   field on every RED golden, checked against the winning rule, and
   `route_axis_changed` (EMERGENCY_NOW → SAME_DAY_ACIL) proves it bites:
   27 goldens fail. Before that assertion existed the same mutation was
   invisible to the whole suite — which is the argument for
   `test_all_three_red_axes_have_a_mutation` existing at all.

## Deviations and open items

   verify the goldens run in `make safety`; verifying showed the target is
   not there — the Makefile has no `safety` rule and the `.PHONY` list

   lanes inside `make check-py`, and both were run green above. The
   Makefile's own header says `check-golden` is expected to "join the
   check fan-out with INT-041/INT-059", so adding a `safety` / `check-golden`
   target is arguably in this issue's remit — but the Makefile is outside
   the file boundary set for this task, so it was **not** modified. This is
   the one piece of the scope left undone, deliberately and visibly.
2. **No cluster or deep pack exists to write goldens against** — see the
   headroom table. The acceptance's "clusters+deep" is blocked on
   INT-044…052 / INT-061+, not on test effort.
3. **No numeric threshold exists in merged content**, so the
   boundary-value family covers temporal windows only. When HB-C2/HB-C7
   land real thresholds, `temporal_boundaries` gains a numeric sibling
   built the same way (boundary, one inside, one outside).
4. The four `golden_positive` / `golden_negative` blocks in
   `base.life_threat.yaml` are prose, not executable fixtures. This suite
   re-expresses LT-01-P, LT-01-N, LT-02-P and LT-02-N as real cases
   (`arm/c1-lt01p`, `miss/lt01n`, `arm/c2-lt02p`, `miss/lt02n-dispne`)

   directly belongs to INT-041, not here.
