## 4. GATED — law, patient safety or Apple; not waivable by permission

### G1 · Real-patient hosting in Türkiye

**Why it is gated.**
- **KVKK m.6** (6698, as amended by 7499, RG 32487, in force 01.06.2024) makes health data a special category.
- **KVKK m.9** and the Yurt Dışına Aktarım Yönetmeliği (RG 32598, 10.07.2024) allow a transfer abroad only on an adequacy decision or a safeguard. For a standard contract, that means notifying the Board within five working days.
- The project's own settled rule is that the PHI path is self-hosted in-country: D11, invariant 19, files/00 §0b. us-east-1 is synthetic-only by owner decision (memory of 26 Sep; HB-I5, HB-L11).

**Fastest path:**
1. **The GPU.** The owner buys one 96 GB RTX PRO 6000 for the pilot rack (HB-I4: ~1.2 kW, fits any rack). Alternatively, he signs a capacity contract with a Türkiye-located GPU provider that names the SKU (HB-I5). The "Herkes İçin GPU" programme (Presidential Circular 2026/9, RG 33344, HB-A4) is a candidate source.
2. **Counsel's opinion.** Turkish counsel gives a written opinion on any non-TR control plane (HB-L11). The media tier may sit in AWS İstanbul Local Zone only on that opinion.
3. **The deploy.** Run the INT-421 deploy and smoke on that host. us-east-1 stays synthetic.

**Who:** the owner and Turkish counsel.
**Sources:** the KVKK text, https://www.kvkk.gov.tr/Icerik/6649/Personal-Data-Protection-Law (answered 200 on 16 Oct); the transfer regulation, RG 32598, and 7499, RG 32487, as recorded in files/06 rows KVKK-4/5/6 and KVKK-8/9.

### G4 · Medical-device status of the triage features

**Why it is gated.**
- **Device law.** The Tıbbi Cihaz Yönetmeliği (RG 31499 mükerrer, 02.06.2021) aligns Türkiye with MDR 2017/745. Under Annex VIII Rule 11 and MDCG 2019-11 Rev.1, automated urgency advice to a patient is a device function; the blueprint's position is Class IIb.
- **Clinical investigation.** Any device clinical investigation needs a KAEK decision and then TİTCK permission before the first participant: Tıbbi Cihaz Klinik Araştırmaları Yönetmeliği, RG 31890, 08.07.2022, and 3359 Ek m.10.
- **Invariant 18 and INT-117.** `device_functions` stays off without a CE certificate or an investigation approval id.

**Fastest path, two tracks:**
- **(a) Stage A, which needs no regulator:**
  1. Build INT-117: no automated patient-facing urgency advice, static 112 text at fixed points, RED rules run in shadow, and the clinician sees patient-reported data.

## 5. Proposed issues — engineering gaps with no issue yet

The coordinator mints the ids; none was minted here.

**P1 — The patient's send reaches the clinic.** Sec-Row `review-send`.
- **Problem.** "Gönder" on the review screen only marks the note `sent` on the phone (`apps/mobile/src/lib/intake/offline/sync.ts`: no note-sync client ships). The share centre and Doctor Link then call `/v1/visits/{local id}/note/…`, an id the server never saw, so the server refuses (F07, F08, F11).
- **What to build.** Send the built note with `PUT /v1/visits/{server id}/note` and `status: "sent"`, carrying exactly the scoped-on section ids. Resolve the server visit first with `ensureServerVisit(create: true)`. Keep the local→server id map in the session, and use it for every `/v1/visits/*` call (shares, issue-link, records). Show "sent" only when the server answers 200.
- **Failure behaviour.** A refused share consent is worded, not swallowed. Offline sends queue in the INT-142 sealed store and never mark the note sent early.
- **Tests:** a send with consent creates exactly one share; a send without consent creates none and the phone does not show "sent"; a Doctor Link issued after a send succeeds against the server id; a near miss that uses the local id is refused.

**P2 — The synthetic host follows main.** Sec-Row `cicd`.
- **Problem.** The host runs `1785dd58` from 2 Oct, 15 merges behind, including the INT-378 Keycloak provider that staff sign-in needs (F16, F36). Nothing deploys main.
- **What to build.** A deploy job on the AWS runner that, after each green merge to main (or nightly, whichever the owner picks), runs `infra/staging/deploy.sh` over SSM for that sha, then `smoke.sh`.
