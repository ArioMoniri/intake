## Addendum, 28 Oct 2026: zod under @expo/cli

CI's trivy DB (run on PR #966 after the bumps) added a fifth row my local scan had not
seen: zod 3.25.76, CVE-2023-54404 (osv: GHSA-mrhx-c7xc-m3w5, 8.2), fixed only in 4.6.6.
Checked: zod is in pnpm-lock.yaml only under @expo/cli 57.0.19 (importer apps/mobile via
expo 57.0.17); @expo/cli 57.0.19 and the newest 58.1.16 both declare `zod: ^3.25.76`; and
3.25.76 is the newest 3.x on npm. So no in-range release clears it, and a pnpm override to
4.6.6 would force a major version into the Expo toolchain untested. @expo/cli uses zod to
validate the repository's own app config and dev-server inputs at build time; it is not in
either `expo export` bundle and no server image installs npm packages.

The exception rows (trivy and osv, expiring 2026-12-31 together, both pins 3 → 4, plus
`test_the_zod_rows_are_scoped_and_expire_together`) are owner-only files and ship as
`issue-drafts/owner-573-zod-exception.patch`, checked with `git apply --check` against
this branch. Until the owner commits it, #966's vulnerabilities job stays red on that one
row only.
