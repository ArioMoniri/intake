## What the tests pin

`tests/infra/test_restore_drill.py`, 72 tests in nine classes:

- **pgBackRest / PITR** — the shipped config parses; `repo1-cipher-type` is
  `aes-256-cbc` so the *repository* (manifests, backups and WAL) is ciphertext,
  which is what files/10 §3 means by "encrypted with separate keys" and is not
  the same thing as an encrypted volume; the passphrase and both S3 keys are
  absent from the file and arrive as `PGBACKREST_REPO1_*` from OpenBao;
  `archive-async=y` is what makes it point-in-time rather than snapshot; the
  restore step really is `--type=time --target=…`.
- **A credential-shaped-literal scan** over the conf, the replication plan,
  the compose tier and the drill script.
- **Replication** — the plan replicates exactly the two buckets the platform
  writes (`intake-docs`, `intake-audit-worm`, from `services/api` defaults and
  `DocumentStore.ensure_buckets`) plus the pgBackRest repository bucket, and
  nothing else; the audit replica is created `--with-lock`, because MinIO
  enables object-lock **only at bucket creation** and a replica made without it
  silently voids the WORM guarantee; deletions and delete-markers are never
  replicated, which is the whole ransomware defence.
- **PHI safety** — `assert_restore_target_outside_workspace` refuses a resolved
  path inside the repo, including `infra/../.cache/restore`; no drill step
  contains `select *`, `pg_dump`, or the words transcript / note_text / tckn /
  phone / full_name; the evidence skeleton has exactly twelve fields, none of
  which an identifier could occupy.
- **Host preflight** — a typed `DrillBlocked` naming HB-I1 and/or HB-I2, and a
  test for each of the four disk × memory combinations.
- **The compose tier** — every service behind the `backup` profile, every image
  tag-pinned (including inline `FROM` lines), every published port on
  `127.0.0.1`, a healthcheck on every long-running service and `restart: "no"`
  on the one-shots, every bind-mount source present, and
  `infra/docker-compose.dev.yml` provably unmentioned by any of it.
- **Entry points** — the script is executable and strict bash; its `--dry-run`
  path is **actually executed by the test** and exits 0; a structural check
  that the pre-`run_drill()` half of the script contains no reference to a
  container runtime, so a dry run cannot become a wet one; and `--run` without
  a retention window exits non-zero naming HB-I8.
- **Negative controls** (near-misses of a valid fixture, so a negative cannot
  pass for the wrong reason) — unencrypted repository, passphrase in the file,
  access key in the file, no `[global]`, two stanzas, archiving off,
  retention 0, replicated deletions, replicated delete-markers, an invented
  `expiry_days`, an empty plan, an unreplicated repository bucket.
- **The CLI and the evidence writer** — including that `parse_row_counts`
  drops anything that is not a bare identifier and an integer, so a psql error
  string carrying a fragment of a row cannot reach the evidence file.

**The execution half of the drill did not run. It was not shrunk to fit.**

                              HB-I2 (container memory): 0 GiB allocated, the drill needs 22 GiB

and without a retention window, before it even gets that far:

```

  PGBACKREST_REPO1_RETENTION_FULL once the owner answers
  files/HUMAN_BLOCKERS.md HB-I8 — a guessed window is not a default.
make: *** [backup-drill] Error 2
```

So, precisely:

| half | state |
|---|---|
| pgBackRest repository configuration, encryption, PITR archiving | **written and config-tested**; not executed |
| MinIO replication plan and the rendered `mc` commands | **written and config-tested**; not applied |
| the compose tier (`postgres-pitr`, `pgbackrest`, `minio-dr`, `mc`) | **written and statically validated**; never built or started |
| the drill's plan, refusals, host preflight, evidence shape | **executed, 72 tests** |
| `--dry-run` end to end through the shell script | **executed in CI** |
| `--run`: stanza-create → backup → expire → PITR restore → counts → replica check → teardown → evidence file | **NOT run.** `blocked:host-capacity` against **HB-I1** and **HB-I2** |
| a measured RTO number, and an RPO demonstrated by recovering to a non-boundary moment | **NOT produced.** Follows the line above |
| the quarterly scheduled workflow | **NOT added** — `.github/**` is out of scope for this PR. `make backup-drill-ci` is the hook it calls, and `docs/runbooks/restore-drill.md` carries the cron snippet and the `runs-on: [self-hosted, tr-dc]` constraint (HB-I7) |

The honest statement of coverage: **the backup configuration is proven; the
restore is not.** A green restore that never ran would be the worse artefact —
files/10 §9 names the threat as *"[Nc] restores never exercised, discovered
during the incident"*, and a passing test that never restored anything is that
threat wearing a badge.

## Values refused rather than invented, with their asks

New blocker row **HB-I8** in `files/HUMAN_BLOCKERS.md` §4 (owner + counsel via
INT-212), two questions:

1. **Backup retention.** *How many full backups does the pgBackRest repository
   keep, and for how long is the WAL archive retained?* files/10 §3 states
   **RPO 15 min** and **RTO 4 h** and states no retention; `06 §3`'s matrix has
   rows for audio, notes, Doctor Link tokens, audit, telemetry and 5651 traffic
   logs and **no row for backup copies**. This is a KVKK-7 / DEST-2017
   question, not an ops preference — a backup outlives the crypto-shredding it
   is supposed to be subject to, and INT-036 and INT-212 need the same number.
   Fail-closed shape: `pgbackrest.conf` sets no `repo1-retention-full` (so the
   repository expires nothing and loses nothing) and the drill refuses to plan
   or run without `PGBACKREST_REPO1_RETENTION_FULL`.
2. **The second location.** files/10 §3 says *"a second location in Türkiye"*
   and no file names a site, a provider or a region — HB-I5 records that no
   in-country provider is contracted at all. Fail-closed shape:
   `INTAKE_DR_S3_ENDPOINT` has no default anywhere, the DR object store gets no
   `observability/registry.yaml` row, and the local `minio-dr` container is
   labelled in the compose file as a stand-in that exercises the configuration
   only.

**RPO 15 min and RTO 4 h were not invented** — both are stated in files/10 §3
and in the INT-202 acceptance, and they are the only two numeric budgets in
the code (`RPO_BUDGET_S`, `RTO_BUDGET_S`). The preflight's two capacity bounds
are quoted from the blockers themselves: 80 GiB is the lower end of HB-I1's own
"Free 80–100 GB", 22 GiB is HB-I2's own "the security + observability tiers
alone need 22 GB". No third figure appears anywhere in this change.

A row is also owed in `docs/backlog/blockers.md` cross-referencing HB-I8;
`docs/backlog/**` is out of scope for this PR, so it is named here instead.

## Deviations

1. **The dev compose file was not appended to at all.** The brief allowed an
   append; nothing needed one once the backup tier became a standalone overlay
   with its own profile, and zero edits to the hot file is the stronger form of
   the same instruction.
2. **`postgres-pitr` is a separate cluster, not an override of the dev
   `postgres`.** Overriding it would mean either editing the shared file or
   defining a `postgres` key in the overlay — and a `profiles:` key merged onto
   `postgres` would stop the shared dev tier from starting under `-f dev -f
   backup`. In production the same `pgbackrest.conf` mounts on the real primary
   (INT-201); here it is the drill's own primary, and the drill exercises the
   full cycle against it.
3. **`--emit-replication` replaced a `sed` filter.** The first version of
   `run_drill()` piped the human-readable plan through `sed` to recover the
   `mc` commands — which also picked up the `mc ls` verification step and would
   have run it before `mc alias set`. The CLI now emits the commands directly.
4. **A pgBackRest apt version is not pinned** in the two inline builds
   (`apt-get install pgbackrest` on `pgvector/pgvector:pg16`). Pinning a Debian
   package version that can be withdrawn from the archive trades one fragility
   for another; the durable answer is the internal Harbor registry with a signed
   image (INT-201, files/10 §8), and the images here are never built on a host
   that runs the drill anyway.
