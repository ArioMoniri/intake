## 2. What changed

No server code changes. The client speaks the existing notes, consents and doctor-link routes.

**The note-sync client** — `apps/mobile/src/lib/intake/delivery/`:
- `payload.ts` builds the `NotePut` body from the same `buildNote` the review screen renders:
  every section with its rendered title and an explicit scope (shared AND withheld, INT-304),
  `status: "sent"`. A body outside the server's own bounds (`Line` ≤ 2000, `Title` ≤ 200, ≤ 100
  lines, ≥ 1 section — counted in code points, as pydantic counts) is refused before it leaves.
- `outbox.ts` is the state machine: `queued` (exponential backoff 2 s → 15 min cap, honouring
  Retry-After, never dropped), `awaiting_consent` (never retried on its own), `refused` (a 4xx;
  never retried on its own, only by the patient's "Tekrar deneyin"), `delivered` (terminal; the
  note text is dropped from the item). `reopenable` says when a note may go back to a draft: only
  where nothing can have reached the server.
- `transport.ts` PUTs through the injected `authedFetch`. Only a 2xx whose body confirms
  `status: "sent"` is a delivery. 408, 429 and 5xx retry; 403 on a `share:` scope asks for
  consent; 403 on `core`, 401, 404, 400/409/422 and any other 4xx are refusals with their reason.
- `engine.ts` orders one attempt: a share consent withdrawn on this phone parks the note with no
  network; the consent queue is flushed first, so the note never overtakes its grant or a
  withdrawal; the server visit is found or created once (records `ensureServerVisit`, the same
  matching rule the documents use) and remembered; then the PUT.
- `persistence.ts` seals each item through the INT-142 `DraftBackend` (AES-256-GCM, DEK in the
  Keychain/Keystore) under an `outbox__` prefix, so sign-out's crypto-shred removes it with the
  drafts; kiosk mode keeps it in memory only (INT-143).
- `store.ts` runs it: restore from disk at sign-in, one backoff timer, a pass on every patient
  action. `native.ts` binds the real dependencies and runs a pass when the app returns to the
  foreground; `session.tsx` reaches it only through a lazy `import()`.
- The server's PUT is a replace in one transaction that rolls back on any refusal, so a retry
  after a lost answer leaves one live share and a refusal leaves nothing (pinned in
  `tests/api/test_note_delivery.py`). The server's field-level encryption and consent checks are
  untouched.

**The share consent** — `lib/consent/`:
- `api.ts` reads the `share` text from `GET /v1/consents` (it never becomes an İzinleriniz row).
- `ledger.ts` gains a share slot: the text, and what this phone did in this session
  (`unknown` → `granted` | `withdrawn`). `grantShare` refuses without a loaded text (invariant 18),
  binds the version and hash shown, queues one grant op and returns a branded `ShareGrantReceipt`
  — the only thing the outbox accepts. It is asked, and recorded, at every send (share.tr.md:
  "Paylaşım onayı, notunuzu gönderirken ayrıca istenir"). `withdrawShare` queues one withdraw op;
  a `core` withdrawal takes the share down locally too, as the server cascades.
- `store.ts`: `grantShareLocal`, `withdrawShareLocal` (true once the server has it),
  `consentQueueClear`, `shareStanding`. `flushConsentQueue` is now single-flight: the outbox
  flushes before every send, often while a grant's own flush is in flight, and two passes over the
  same head would push it twice and then shift twice, dropping the op behind it unsent.

**The screens.**
- `components/NoteDelivery.tsx` (on Review & send, once the note is frozen and until the server
  confirms it): the confirm step renders the docs/legal share text — body, version, binding —
  and "Okudum, kabul ediyorum"; with no text there is no grant action. "Notu düzenleyin" takes the
  note back to a draft. Then the queued, refused (with its sentence and a retry) or
  waiting-for-consent states. Nothing on it says "gönderildi".
- `review.tsx`: `frozen` (Gönder pressed) and `sent` (delivered) are now different; the sent
  branch — `review.sentInfo`, the status ladder, the CSAT question — opens only on `sent`. The
  send CTA is unchanged: one dispatch, no condition, no network on the screen. The route renders
  the share text now, so it takes the motion `legal` class (`lib/motion/transitions.ts`).
- `visits/[visitId]/index.tsx`: `effectiveStatus` takes the delivery; a note sent but not
  confirmed is still "Taslak".
- `components/ShareConsentControl.tsx` on the share centre: a two-step withdrawal of the share
  consent, shown done only once the server has it; any queued note is held first. It reads only
  the standing, never a consent text, and sits apart from the stop control (INT-150 §6).
- `issue-link.tsx` and `shares.tsx` address the server visit the note was delivered to.

**Doctor Link and the step-up seam** — `lib/shares/`:
- `stepUp.ts`: `StepUpTier` (`otp_session` | `passkey`), a branded `StepUpProof`, a `StepUp`
  interface, `otpSessionStepUp(hasSession)`, and `authorizeIssue(standing, stepUp)`, which refuses
  `consent` before any network when this phone has seen the share consent withdrawn and `session`
  without a session. `sessionStepUp.ts` is today's tier: an OTP session in token custody. INT-582
  (D36) swaps that one export for a passkey `StepUp`.
- `issue.ts`: `issueDoctorLink(visitId, recipient, proof: StepUpProof)`; new reasons `consent`
  (403 `consent_required`) and `session`. Revocation is INT-139's unchanged route.

**Other files.** `lib/records/api.ts`: `RecordsApiError.status` (additive) so a 4xx on visit
creation is an answer and a 5xx a retry. `lib/intake/offline/sync.ts`: the comment no longer says
no note-sync client ships. `e2e/a11y.spec.ts`: the outbox's backoff timer is registered as
NOT_A_TIME_LIMIT (it delays a request and takes nothing from the patient).

## 8. Legal review, round 1 — B1 fixed, N3 and N5 taken

The independent legal review of this branch (29 Oct 2026) returned one BLOCK and notes. The rest
of its findings (re-share after a withdrawal, the sign-out warning, the share-expiry anchor, the
`notShared` copy, N1/N2 for counsel) go to a follow-up issue the orchestrator files.

**B1 — a share consent given for one note could release another after a withdrawal (KVKK
m.4/5/6).** The share standing is one flag for every note: `grantShare` set it back to `granted`,
and the engine checked only that flag. A core withdrawal never told the outbox; only the share
centre's control parked queued notes, and it parked queued ones only, so "Tekrar deneyin" resent a
refused note with no receipt. Scenario: note C queued → core withdrawn → core re-granted → note B
sent → C went out on B's grant; after a restart the in-memory withdrawal op was gone and C still
went. Fix, three locks:

1. **The outbox hears every withdrawal.** The runtime subscribes to the consent ledger
   (`watchConsent: subscribeToLedger`); whenever a new share withdrawal instant appears — the share
   centre, a core withdrawal on İzinleriniz or the first-run screen, any future screen — every
   unsent note is parked in memory at once (before any await) and then sealed to disk.
2. **Refused notes are parked too** (`holdForConsent`), with the refusal cleared, so a retry cannot
   resend one.
3. **Each note is bound to its own grant.** A receipt names the note it was given for
   (`visitId`, `atIso`); the outbox queues and releases a note only on a receipt for that note, and
   records the binding (version, hash, instant) with the sealed item. Parking unbinds it. The ledger
   records the instant of every withdrawal (`share.withdrawnAt`, also set by a core withdrawal),
   and the engine refuses a note whose grant predates it, even if the standing is `granted` again —
   the second lock on the same door. A stored note that could still leave but carries no valid
   grant is restored parked, never sendable.

The share slot moved from `ledger.ts` into `lib/consent/shareConsent.ts` (re-exported from the
ledger) so both stay under the 500-line rule.

**N5 — a refused consent op stalled the queue.** `pushConsentOp` now answers `landed`, `wait`
(offline, 5xx, 401/408/429) or `refused` (any other 4xx). A refused op is dropped instead of being
held at the head, where it stalled every op behind it — a later withdrawal included — and a
refused grant is undone (`dropRefusedHead`), so the patient is asked again rather than shown a
consent the server never recorded. `delivery.queued` no longer says "Bağlantı kurulunca", which
reads as the Doctor Link: "Sunucuya ulaşılınca kendiliğinden gönderilir."

**N3 — declining as easy as agreeing.** The confirm step's two answers are the same control side
by side: "Okudum, kabul ediyorum" and "Şimdi değil". "Şimdi değil" records nothing and leaves the
note unsent on the phone ("Notunuz gönderilmedi; yalnızca bu telefonda duruyor."), with the text
one tap away ("Paylaşım onayını okuyun"). Editing the note is a separate action below them.

**Tests added:** `src/lib/intake/delivery/consentBinding.test.ts` runs the real consent store
against the real outbox — (a) `withdrawLocal("core")` parks every queued and refused note, and
