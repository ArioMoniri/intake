defect, so the relationship is stated here rather than left implicit.

| artefact | what it is | after INT-084 |

| `intake_api.note` (new, this issue) | the **composer of record**: `NoteSources → AttributedNote → {SOAP, PDF, FHIR Bundle}`, over the files/04 §5 `PreVisitNote` vocabulary. | **authoritative.** It is the only thing in the repository that constructs a `PreVisitNote`. |

issue): a **vocabulary gate** in `tests/engine/test_note_golden.py`

- the composer's attributable sections are exactly the files/04 §5 note keys minus `triage` and
  `data_gaps`, and
- INT-197's share-scope literal `intake_api.schemas.SectionId`
  (`chief_complaint | hpi | medications`) is a **subset** of those note keys — so the share ledger
  and the composer address the same things.

**Drift found and recorded rather than fixed** (it needs a spec decision, not a code change):
`buildNote` emits two section ids that are not files/04 §5 note keys — `device_health` (INT-208's
attached device summary) and `deferred` (02 §33's `eksik: ortam uygun değildi` block). The second
has an obvious home — files/04 §5 `data_gaps`, which is exactly files/12 §2's *"never asked"*
semantics — but choosing it is a spec amendment, and the first has no home at all. Both belong to
whoever owns INT-137 (review & send) or a files/04 §5 amendment; neither is an engine defect and
neither was invented here.

## What the design does, clause by clause

### "every fact carries source span" — structural, not procedural

The guarantee is a property of the types, so a renderer never has to remember to check it.

- `clinical_schemas.provenance.SourceSpan` — a half-open `[start, end)` interval into one named
  source (`utterance | typed | document | record`), with `page` for documents. Offsets, not text:
  the quoted words already live in the note line.
- `SpanSet = Annotated[tuple[SourceSpan, ...], Field(min_length=1)]`.
- `Attributed[T]` (PEP 695 generic pydantic model) — `value` + **required, non-empty** `spans`.
  Omitting the field is a `mypy --strict` error; passing `()` is a `ValidationError`.
- `NoteFact` — the render unit: section, dotted `field_ref`, rendered `text`, and the same
  required `SpanSet`.
- `NoteSources` — the composer's **entire input surface**, every content field of which is
  `Attributed[...]` (or a nested `*Sources` model all of whose fields are). There is no seam
  through which unattributed content can enter a note, and a test walks the model fields and
  asserts it rather than trusting review.
- `AttributedNote` validator — refuses a fact in a non-attributable section, refuses a note that
  carries content in a section no fact accounts for, and requires facts in note-section order.
- `RenderedLine.kind is FACT` **iff** `line.fact is not None`; the renderers emit a content line
  only from a `NoteFact`. Chain: *line → fact → span*, with no gap.

Near-miss negative controls, all present: `spans=()` on both carriers; a span with `end <= start`
and with `end < start`; a `page` on a non-document span; a `NoteFact` claiming `section="triage"`;
an `AttributedNote` whose note has content and whose fact list is empty.

`data_gaps` is the deliberate exception and carries **no** span, because files/12 §2 makes a gap an
*absence* — *"it now renders as 'never asked'"*, never *"elicited and absent"*. Tests assert a gap
produces no fact, never enters `hpi.negatives`, and renders in its own block; and that an
**elicited** negative is a normal fact with a span.

### "fixed legal disclaimer text … rendered on note+PDF" — the mechanism, failing closed

`intake_api.note.strings` declares a **key set and no copy**, exactly like `intake_api.dsar.strings`
(INT-037):

- `previsit_note.disclaimer` — the files/06 §7 note/PDF footer. Required on every note.
- `previsit_note.screening_ai_label` — files/06 §7 also fixes the label that must accompany a
  wellbeing signal. Required **exactly when a score is rendered**, so the gate is on the content
  rather than on the caller's memory. This is not scope creep: a note printing a screening score
  without its label would be a legal defect on the same page as the disclaimer.

`load_note_strings()` reads them through `intake_platform.legal.LegalStringsCatalog` (INT-037's
hash-bound loader), and `render_soap()` re-checks them so a caller who assembled a `LegalStrings`
some other way still cannot produce a note. Both the SOAP text and the PDF carry the strings and
record `legal_strings_version` + `legal_strings_sha256`, so a rendered note says which bytes it
showed. A moved file refuses to re-render an already-issued document (`LegalStringsChangedError`).

Today `docs/legal/strings.yaml` is absent, so **every render refuses** — asserted directly by
`test_the_repository_has_no_fixed_strings_file_yet` and
`test_rendering_fails_closed_with_the_strings_file_absent`. A further test greps every module in
the note package and asserts none of them contains the words the files/06 §7 sentence is built
from. See §"Blocked".

### The renderers

- **SOAP** (`render.py`) — files/03 §11's split: `S` = patient-reported (chief complaint, HPI,
  pertinent ROS, PMH, medications, allergies, family/social, screening); `O` = measured or imported
  (konuşma özellikleri — files/03 §4.7.6 puts it here and **never** under screening — and imported
  objective); `A` and `P` rendered **present and empty** so a clinician can see the slot was left
  for them; then `considerations` (patterns, not diagnoses — its own block, deliberately not under
  `A`), `suggested_focus_questions`, `patient_confirmed_sections`, `triage`, `llm_candidates`,
  `data_gaps`, `sources`, `legal`.
  **Headings are the files/04 §5 technical ids, not Turkish prose.** The INT-033 document mapper
  made the same choice for the same reason (*"human headings belong to the renderers … not the
  exchange layer"*), and here it is also invariant 5: the clinician-facing Turkish headings belong
  to the clinician view (INT-151) with its own `tr` catalogue. The only Turkish on the page is the
  patient's own words and the bound legal strings — no clinician copy was invented.
- **PDF** (`document.py`) — reuses `intake_platform.pdf` for byte-level plumbing only, which that
  module's docstring explicitly reserves for this issue. Deterministic bytes;
  `escape_unencodable=True` for the same reason INT-037 chose it (a clinician who receives nothing
  is worse off than one who receives a page naming the one character the encoding could not draw;
  the character is named `[U+…]`, never transliterated). Title is the existing
  `mappers.codes.DOCUMENT_TITLE_TR`, not a new string.
- **FHIR** (`fhir.py`) — a deliberate delegation to INT-033's
  `previsit_note_to_document_bundle`, not a second mapper. Two mappers for one note would be two
  answers to *"what did the clinician receive"*.

### Invariant 1 — the note is not a second route to a level

Four independent barriers:

1. `compose_note(triage: RulesTriageResult, ...)` — typed, and re-checked at runtime so an
   `LlmCandidateTriage` cannot be laundered in by a caller who ignored the type.
2. `AttributedNote` carries the `RulesTriageResult` **beside** the note and its validator asserts
   `note.triage.level is rules_triage.level` and `note.triage.rules == rules_triage.rules`. The
   only level the note can hold is the one it was handed. (This is also where the RED three axes
   survive: `register` and `location` are required with no default under invariant 21 and files/04
   §5's `NoteTriage` has nowhere to put them.)
3. `triage` is not an attributable section at all, so no fact can claim it.
4. A candidate flag whose text is a level word (`RED`/`YELLOW`/`GREEN`/`YELLOW_REVIEW`) is refused
   outright rather than rendered.

Rendering: candidates appear only under an `llm_candidates` header, each line prefixed
`llm_candidate:`, and a test asserts no level token appears in a candidate line while the rules
level does appear in the triage block. The golden bundle pins that no candidate text and no
`YELLOW_REVIEW` reaches the FHIR wire.

### Invariant 20 — no accuracy claims

`intake_platform.legal.claims.scan_text` (INT-224's single vocabulary, reused rather than copied) is
run over every rendered note and over every source file in the note package: zero hits for the
`performance` and `satisfaction` groups. INT-083's extraction emits a `confidence`; a test asserts
there is no field for it anywhere on `NoteSources`, `AttributedNote`, `NoteFact` or `PreVisitNote`,
so a confidence number cannot become a property of the product by being rendered next to a finding.

### Invariant 22 — numbers at a representation boundary

`intake_platform.llm.units.render_quantity` (INT-083's single renderer) is reused; a float is
converted through `Decimal(str(v))` first so no binary artefact reaches the page. An AST test walks
the note package and asserts no format spec contains a grouping separator, so a second renderer
cannot appear later. Number + unit is joined with one non-breaking space (`NBSP`), asserted on the
speech-measure line. An absent `severity_nrs` renders as absent, never as `0`. `Üre 45 mg/dL` rides
through `imported_objective` byte-for-byte — the note carries the magnitude and printed unit it was
given and converts nothing (the resolution decision belongs to ingestion, INT-083's `units`, and is
not re-litigated at render).

### Invariants 6 and 4

The note package imports no logging and no network client (AST test), emits no log record while
rendering all three scenarios (caplog test), and declares **no route** (`APIRouter` absent). This
issue therefore adds **no new egress**: nothing composed here leaves the service. The share paths
that do — INT-197's `POST/GET .../note` (consent scope + hash-chained audit, already in place) and
INT-150's Doctor Link — are unchanged and out of this issue's fence. See §"Not done" for what that
leaves open.

## Blocked — and the ask

**`docs/legal/strings.yaml` does not exist.** `docs/legal/` holds only `accessibility-statement.md`
and `store/`. The files/06 §7 wording the acceptance quotes is therefore **not renderable today**,
and under CLAUDE.md invariant 18 and the stop-and-ask list ("anything touching consent texts …
legal texts") an agent may not author it. Per HUMAN_BLOCKERS.md rule 2, the mechanism is built, the
gate is wired, it fails closed, and the content stays empty.

This is the **same blocker INT-037 already hit** — `intake_platform.legal.strings` names it in its
own docstring (*"the strings are INT-210's human deliverable, awaiting counsel"*) and
`intake_api/dsar/strings.py` repeats it. **HB-L22** is the closest existing row (*"Draft the four
breach-notice texts … These are legal texts, which under invariant 18 render only from
`docs/legal/` with hash binding, and CLAUDE.md's stop-and-ask list reserves them explicitly"*) but
it is scoped to breach notices, not to files/06 §7's fixed copy. **No existing row covers this
one**, so a new row is needed rather than a re-ask:

> **HB-L24 (proposed)** — *Author `docs/legal/strings.yaml`, or confirm INT-210 owns it and INT-084
> stays `awaiting-human` on that.* The two keys this issue needs are
> `previsit_note.disclaimer` (the files/06 §7 note/PDF footer) and
> `previsit_note.screening_ai_label` (the files/06 §7 wellbeing AI label); INT-037 additionally
> needs the nine `dsar_export.*` keys it already declares.
> **The one sentence:** *"Do you author the files/06 §7 fixed strings into
> `docs/legal/strings.yaml` under INT-210 — and is the note footer verbatim the §7 sentence, or a
> variant counsel wants for the clinician-facing document?"*
> **Owner:** Turkish counsel (the wording) + owner (the issue split).
> **Blocks:** the *rendering* of INT-084's disclaimer — and only that. The composer, the
> provenance, all three renderers, the goldens and every gate are built, tested and failing closed.
> Also blocks INT-037's export document for the same reason, which is why the row is one row.

I did not add the row to `files/HUMAN_BLOCKERS.md` or `docs/backlog/blockers.md`: both are outside

## Not done, and why

- **No new API route.** The acceptance is a composer plus renderers; the delivery surface is
  INT-150 (Doctor Link: token, OTP, expiry, view limit, revoke, watermark, access log). Adding an
  egress here would have meant a consent scope, an audit entry and a schemathesis surface that
  INT-150's acceptance already owns. Asserted rather than asserted-by-omission: a test proves the
  package declares no `APIRouter`.
- **Per-page watermark stamping.** The document model carries a `Watermark(recipient, issued_at)`
  and renders it into the document header — the "watermark-ready" half. Repeating the stamp on
  every page needs a page-aware hook in `intake_platform.pdf`, which is outside this issue's file
  fence (`packages/intake_platform/**` was not editable here). INT-150 needs that hook; it is one
  parameter on `render_text_pdf`.
- **files/10 §9 `sec_row: notes`.** There is no `notes` row in the §9 table today (the closest is
  the LLM05 *"XSS tests on note rendering"* line and the Doctor Link row). `files/**` is outside
  this issue's fence, so the row could not be added. Invariant 16 requires the PR to link it — the
  row needs writing by whoever can edit `files/10`, and its content is straightforward from this
  issue: threats *note fabrication, unattributed assertion, legal-text drift, level laundering*;
  controls *type-level provenance, hash-bound legal strings, rules-only level, no egress in the
  composer*; signals *render refusals on missing legal strings*; tests
  *tests/engine/test_note_golden.py*.
- **`docs/PROGRESS.md`, `docs/backlog/issues.yaml` status, the GitHub issue.** All outside the
  fence for this session; no git command was run.
