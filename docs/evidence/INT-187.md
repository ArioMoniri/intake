**What GitHub says today, recorded rather than assumed:** `main` has no branch protection and no
ruleset (`protected: false`, rules `[]`), so GitHub enforces **none** of the twelve PR-triggered
gates; the page says so. The gates are the repository's own: every job in `ci.yml` and
`security.yml` that runs on a pull request (`sign-and-attest` runs on `v*` tags only and is not a
PR gate). The one release, `deid-tr-ner-v1`, is not a `v*` tag, so its signing state is
`not_applicable` — the sign job never ran for it.

**"Eval gates"** (files/08 §9: triage goldens, PolicyGuard suite, runtime invariants, protocol
goldens) run inside `check-py`; they are shown as that gate's result per ref, not as a second
list that could disagree with CI.

## Where the freeze is enforced

`infra/staging/deploy.sh` — the only deploy path in the repository — runs
`require_release_not_frozen` after `build_api_image` / `stamp_sbom` and **before the first
`compose up`**. That runs `python -m intake_api.admin.release_gate` in a one-off container of the
image just built, on the project network, with the api's environment:

- exit 0 → the deploy continues; the gate's lines are logged (e.g. `note error_budget_not_configured`
  on staging, which declares no Prometheus);
- exit 3 → `die "deploys are frozen or the freeze cannot be read: nothing was restarted …"`;
- anything else → `die "the release gate did not run (exit N) …"`.

`ENFORCEMENT_POINTS` in the composite lists `infra/staging/deploy.sh: enforced` and
`argo_cd_sync: not_deployed`, and `tests/infra/test_staging_release_freeze.py` holds the list
against the script.

## The decisions

**Asymmetric, as files/08 §8.2 decided it.** The T1 row names "deploy freeze": one `sre_oncall`
or `clinical_lead` (and `platform_owner`, per the INT-188/INT-182 precedent), no approver. Lifting
is the dangerous direction, so it is T2: requested by `platform_owner` or `platform_admin` (§2.1:
"infrastructure"), approved by `platform_owner` or `qms_owner` (§9: "a release-gate role, not a
courtesy"). `sre_oncall` is on neither side of a T2 ceremony (§2.1 scope: "T1 safe-direction
actions"). The RBAC matrix holds all five routes.

**Not an Unleash flag.** The brief said "a flag (INT-188 flags mechanism)". What is reused from
INT-188 is its governance — the closed change-reason set, the mandatory explanation, the
four-eyes service — not the generic store: Unleash API tokens flip flags with no audit row and CI
runners hold them (files/08 §3, invariant 34), and a freeze the pipeline itself can lift is not a
freeze. The record lives in the deployment's own Redis, like INT-182's kill switch, written only
by `/admin` behind the registry and the write-ahead audit.

**Never written means not frozen; unreadable means refused.** A deployment that never froze has
no record, and deploys proceed — the normal state. A record the gate cannot read refuses the
deploy. **An exhausted budget freezes on its own**, whatever the manual freeze says; a tier that
declares no Prometheus has no budget to exhaust and the gate says so on every run rather than
passing silently; an SLO with no series is *unmeasured*, not within budget.

**The GitHub read stays in the collector.** INT-351 decided the console never holds the token and
never dials GitHub; the CI/CD source extends the same collector, token reader and egress-guarded
transport, and exports catalogued series. Run actors, commit messages, PR titles and users never
become labels.

**Deploy state is this API's own `/version`, read in process** — no new egress to a peer host
(an allow-list change is tier-3), no guessed environment list.

## What stays open (why the row is `awaiting-human`)

**The rollback button (4-eyes).** files/08 describes rollback as moving an Argo CD Application to
an earlier revision. There is no Argo CD, no Rollout and no cluster to run one on (the siting
question HB-I13 asks for the edge tier); the one deploy path is an operator running `deploy.sh`
over SSM, which the console cannot command. A two-key ceremony whose approval changes nothing is
not a control (the `admin.models.benchmark.run` precedent), so the button is rendered **disabled
with that reason** and no route pretends otherwise. The canary tile states "not deployed" — the
truthful state. The owner's one-sentence ask is in `docs/backlog/blockers.md` ("INT-187"); the HB
row for the CD tier is the coordinator's to allocate.
