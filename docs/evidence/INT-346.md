`730e9288`.

## 1. How the baseline was taken

Actions billing was blocked from 2026-09-08 to 2026-09-26. Every run in that
window ended in seconds with no steps and no logs (`BlobNotFound`), so
the merges to `main` in that window were never gated. `main`'s last run is
2026-09-08, and it is a billing failure, not a verdict.

Neither `ci.yml` nor `security.yml` declares `workflow_dispatch`, so
`gh workflow run --ref main` is not available. `main` is gated on `push` only.
The baseline was therefore read from today's `pull_request` runs. Those runs
test the PR's merge with `main` HEAD, and PR #545 changes only the backlog, so
its run is the closest thing to a run on `main` itself:

| PR | ci run | security run |
|---|---|---|
| #545 (backlog only) | 36243542866 | 36243542701 |
| #521 INT-325 | 36242862009 | 36242862047 |
| #520 INT-324 | 36242395954 | 36242395907 |
| #522 INT-326 | 36243193191 | 36243193093 |

All four show the same failing set, which is what makes it `main`'s set.
`check-py` stops at `ruff`, the first line of the target, so the CI logs hide
everything after it. The rest of `make check-py` was run locally, line by line,
without stopping at the first failure. That run found the pytest failures in §3.

Classification key: **(a)** already on `main` · **(b)** caused by a PR branch
· **(c)** PR metadata gate (title, `Closes #`, Sec-Row), not a code defect ·
**(d)** infra or runner.

## 3. Fixed failures — log excerpt, cause, fix, red run, green run

### F1 — ruff (check-py stops here on every PR)

```
S105 Possible hardcoded password assigned to: "TOKEN_CLAIM"
  --> scripts/dev/record_experience_fixture.py:73:15
E501 Line too long (101 > 100)
   --> scripts/dev/record_security_fixture.py:169:101
Found 2 errors.
make: *** [Makefile:47: check-py] Error 1
```

**Cause.** Commits 1c88d6b7 (INT-186) and 3aec5e72 (INT-192) landed without CI.
`TOKEN_CLAIM = "token_claim"` is the only permitted tenant scope, the literal
`apps/admin-web/src/experience/module.ts` checks. It is not a credential.
S105 reads it as one only because of the word in the name.

**Fix.** Rename the constant to `TENANT_SCOPE_SOURCE`, keeping the same value,
and rewrap the long string at a word boundary. The `tests/**` ignore list in
`pyproject.toml` was not touched, and no `noqa` was added. The re-recorded
experience and security fixtures differ from the committed ones only in their
timestamps and one pre-existing SDS-01 row. The `tenant_scope` value and the
CrowdSec reason string come out byte-identical, and the fixtures were not
re-committed.

- **Red run:** `uv run ruff check .` → exit 1, the two findings above (the
  same as CI).
- **Green run:** `uv run ruff check .` → `All checks passed!` exit 0;
  `uv run ruff format --check .` → exit 0.

### F2 — osv-scanner: vitest GHSA-82fw-gwwq-j7x9

```
| https://osv.dev/GHSA-82fw-gwwq-j7x9 | 5.9 | npm | @vitest/mocker | 3.2.7 | 4.1.11 | pnpm-lock.yaml |
| https://osv.dev/GHSA-82fw-gwwq-j7x9 | 5.9 | npm | vitest         | 3.2.7 | 4.1.11 | pnpm-lock.yaml |
Exit code: 1
```

**Cause.** The advisory (path traversal through a redirect mock in
`@vitest/mocker`) was published on 2026-09-08, the day the outage began. The
affected range is `>=2.1.0 <4.1.11`, so no 3.x release is fixed.

**Fix.** `vitest` goes from `^3.2.6` to `^4.1.11` (root and `apps/mobile`), and
`@vitest/coverage-v8` goes from `^3.2.6` to `^4.1.11` (`clinical-schemas`,
`embed-sdk`). The lockfile was regenerated with `pnpm install`. Every new
transitive package passes `scripts/ci/check_licenses.py`.

INT-310's lockfile floor in `tests/ci/test_security_gates.py` is tightened to
match, never loosened. `FIXED_VERSIONS["vitest"]` rises from 3.2.6 to 4.1.11,
`@vitest/mocker` joins at 4.1.11, and `GHSA-82fw-gwwq-j7x9` joins
`ADVISORY_IDS`, so a suppression file that names it fails. The advisory is
cleared by upgrading, not by an osv or trivy ignore row. Both suppression pins
are unchanged.

Vitest 4 dropped `coverage.extension`. `packages/clinical-schemas` sets
`include: ["src/**"]`, and that directory also holds the Python package, so v4
tried to parse the `.py` and `.pyc` files as JavaScript and excluded them with
errors. `include` is now `["src/**/*.ts"]`, which is the set v3 measured with
its default extension filter. The thresholds (85/85/85/85) are unchanged, and
the measured coverage is 100 % (7/7 statements, 6/6 branches).

- **Red run:** `osv-scanner scan -L <main's pnpm-lock.yaml>` (osv-scanner
  2.5.1, the version CI pins) → the two rows above, `Total 2 packages affected`.
  With main's lockfile in place,
  `pytest tests/ci/test_security_gates.py::test_every_advisory_is_cleared_by_a_resolved_version`
  → 1 failed:
  `vitest@3.2.7 is below the fixed version 4.1.11 — the advisory is back`.
- **Green run:** `osv-scanner scan -L pnpm-lock.yaml -L uv.lock` →
  `No issues found`, exit 0. `trivy fs --severity CRITICAL,HIGH` over both
  lockfiles → 0. `check_licenses.py` → `OK`.

### F4 — orphaned catalogue keys `lang.tr` / `lang.en`

```
AssertionError: 2 catalogue keys are never referenced: ['lang.en', 'lang.tr'].
```

**Cause.** Commit 17889808 (INT-301) replaced the Me tab's
`LANGUAGE_LABEL = {tr: "lang.tr", en: "lang.en"}` with endonyms read from the
locale registry (`toChoices`). Nothing reads the two keys any more.

**Fix.** The gate's own docstring prescribes this: "mechanical drift … an

shrinks and no set grows.

### F5 — a hard-coded English sentence in `envelope.ts`

```
AssertionError: user-visible strings outside the catalogue: {'lib/intake/offline/envelope.ts': ["message='draft could not be decrypted'"]}
```

**Cause.** Commit 192d945d (INT-142) gave `DraftDecryptError` an English
sentence as its default `message`. It is not rendered to the patient. The app's
own convention for errors that can reach a crash report is
`RecordsApiError`'s: *"the kind IS the message — codes, never narrative"*.

**Fix.** `DraftDecryptError` now takes a `DraftDecryptKind`
(`"not_an_envelope" | "undecryptable"`) and uses it as its message, following
that convention. The three throw sites pass codes. `HARDCODED_EXEMPT` is
unchanged. The new type is exported from the barrel.

- **Red run:** a new test in `envelope.test.ts`, "names a failed open by a
  code, never narrative", fails with `expected undefined to be
  'undecryptable'`: 1 failed, 8 passed.
- **Green run:** `vitest run src/lib/intake/offline` → 25 passed.
  `test_no_user_visible_string_is_hardcoded_outside_the_catalogue` passes.

## 4. Not fixed here: each needs a human decision

These are left red on purpose. Every fix for them either grows a
recorded-findings or classification set, or changes patient-facing copy, or
chooses a new supply-chain source. None of those is this issue's to take.

**F6 — `chooser`, `chooser.test` and `direction` in `lib/i18n/` (INT-301).**
`NON_CATALOGUE_MODULES` is a named set on purpose. Its comment says *"a new
file has to be classified consciously"*. Classifying these three modules would
settle the failure, but `direction.ts` contains the `"rtl"` token. The file
only escapes `test_no_rtl_affordance_is_claimed_before_the_audit` because that
scan skips `lib/i18n/`. Move it out and that gate fails instead.
`components/Themed.tsx` already applies its layout direction app-wide. INT-253
plans RTL for P3 behind an audit. **Question for the owner:** is INT-301's RTL
direction mechanism sanctioned ahead of INT-253's RTL audit? If yes, name the
three modules in `NON_CATALOGUE_MODULES` with that reason. If no, remove the
direction wiring until the audit.

**F7 — four short-imperative prose strings (INT-143 kiosk, INT-311 shares).**
Two ways out exist, and both are register decisions. The first is recording the
four strings in `PROSE_REGISTER_FINDINGS` alongside their 34 siblings, which is
the practice so far. The second is rewriting the copy, but `-iniz` trips
`test_no_short_in_flow_control_uses_the_doubled_polite_form`, and any other
rewording is a patient-copy change. **Question for the copy owner, through the
clinical-reviewer:** should `kiosk.exit.body`, `kiosk.lock.body`,
`kiosk.pin.hint` and `shares.issue.recipient.hint` be recorded as findings
alongside the existing 34?

**F9 — `check-integration` cannot pull MinIO.**

```

make: *** [Makefile:42: check-integration] Error 1
```

public under its own name. That breaks `infra/docker-compose.dev.yml`, which CI
uses, and also `docker-compose.langfuse.yml` and `docker-compose.backup.yml`,
which it does not. No integration test ran, so failures past `compose up` are
