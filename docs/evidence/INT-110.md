### Why "read-only" is a type property and not a rule

Three independent layers, because each alone has a hole.

1. **Type-level.** `LaneContext` is a frozen record of a window and some ids: no engine, no
   Work submitter, no sink, no store, and **no callable member at all**. `LaneObservation`
   has exactly four fields — `interaction`, `markers`, `confidence`,
   `dropped_frames_in_window` — and no carrier for a slot value, a triage result, a candidate
   flag or a priority. This is the posture INT-091 took for RED preemption and INT-172 took
   for learning proposals: the forbidden thing is not rejected, it *cannot be written down*.
2. **Reachability.** An AST walk over the package asserts no module imports the Work queue,
   the engine FSM, the Talker, `protocols`, `intake_api`, `intake_platform.db`,
   `intake_platform.store` or `sqlalchemy`; none imports a network or process module
   (invariant 13); and none contains a write-capable call. Each gate has a negative control
   that feeds it a breaching source and asserts it reports.
3. **Routing.** `ObserverStateBuilder` is the only writer, and it refuses rather than filters:
   an M3 observation raises (files/03 §4.7.4 — the sealed research store, and `ObserverState`
   is not it), an `InteractionState` field from a lane outside M1 raises (invariant 22), and
   `affect` markers raise because §4.7.5 gives that lane *"closed InteractionState only — no
   label, no score, no text"*.

The acceptance says **(compile-time)**, so the claim is checked by a compiler.
`tests/lanes/fixtures/writing_lane.py` is a specimen lane that tries all four ways to write —
reach the engine through the context, mutate the window, read a slot-update carrier off an
observation, and satisfy `Observer` with an `observe` that returns a `TriageResult` — and

### Why "never delays speech" is structural before it is measured

`ObserverScheduler.offer` is what the speech path calls, once per frame, and it is an
ordinary function; `pump` is the lane tasks' own entry point and is the **only** coroutine on
the class. This is the same split `work_queue.py` uses for ADR-009, and the test asserts the
coroutine set is exactly `{"pump"}`. `ConsentProbe.granted` is synchronous for the same
reason: it is read on the offer path.

Measured on INT-091's virtual clock, with a **real** `TalkerSession` turn (the doubles are
loaded from `tests/voice/talker_harness.py` rather than re-derived, so the property is proved
about the Talker and not about a copy of it): a turn with lanes stalled **30 s**, a turn with
lanes stalled **an hour**, and a turn with **no lanes at all** produce byte-identical
`elapsed_ms`. A lane that merely overruns its deadline is raced against its own budget on the
injected clock, cancelled, and its window discarded — `observer.finished == 0` and the pump
returns at the deadline, not at the stall.

### Backpressure and the metric

`WindowBuffer` is bounded twice: by `max_queued_frames`, and by invariant 3's 60-second
ceiling on held audio — so the ceiling does not depend on somebody having sized the depth
correctly. A full buffer sheds the frame at `offer`, counts it in `DropLedger` under
`(lane, reason)`, and reports it to the lane on the next window as
`dropped_frames_in_window`, which files/03 §4.8 property 3 requires so a degraded session
replays *as degraded*.

**No Prometheus family is constructed.** Invariant 13 says every emitted series exists in
`observability/metrics_catalog.yaml`, the catalogue holds no lane row, and that file is
outside this change's ownership — so the framework counts in process and names the series it
would emit, exactly as `work_queue.py` did. A test asserts the package builds no
`Counter`/`Gauge`/`Histogram`, and another pins the names, so promoting it later is a
one-line edit against a test that already says what the name must be.

### Per-lane consent, and the one thing this issue could not decide

files/06 §2's purpose list is closed and holds **two** lane purposes. So:

- `lane:affect` and `lane:linguistic` resolve, and a lane whose scope is not granted is never
  registered — `offer` cannot reach it and `pump` has nothing to run. The scope is re-read at
  **every window**, not once per session, because KVKK-6 is a rule about every lane *read*; a
  grant that disappears between windows stops the lane and zeroizes its buffer (files/06 §2.2).
- `lane:acoustic` is refused **by name**. files/06 §2.4 removed it from the purpose list on
  25 Aug 2026 and made it an investigational-device ICF: *"a device you may not place on the
  market is not made lawful by a toggle."* Its gate is `StudyGate`, and the consent probe is
  never asked.
- `asr_quality` and `engagement` **cannot be registered at all** — see the blocker below.

### `acoustic`

`StudyAssertion` has four required fields with no defaults, so an incomplete assertion does
not construct; the suite removes each of the four on its own, because a conjunction tested
only all-present and all-absent is three untested conjuncts. `StudyGate` shuts when the live
protocol version differs from the approved one (TCKAY m.11 makes an amendment a fresh
submission), including when the amendment arrives **mid-session** — the gate is re-read at the
next window and the lane stops with its buffer zeroized. And a fully asserted, admitted
acoustic lane still never reaches `ObserverState`: `recorded_in_state` is false for M3 always,
and the builder has no route for it.

### Containment

A lane that raises, or that returns an observation breaching its module boundary, is
**disabled** — buffer zeroized, drop counted, no second window — rather than obeyed or allowed
to take the pump down with it. The type and AST gates make the second case near-impossible;
the runtime still fails closed.

### Frame lifetime

The runtime decodes each frame once and offers it to every admitted lane, so the scheduler
reference-counts holders and zeroizes a frame when the **last** lane finishes with it. A lane
zeroizing on its own would blank another lane's window mid-read — a correctness bug wearing a
safety argument. Frames carry `bytearray` rather than `bytes` precisely so the bytes can be
overwritten in place; an immutable `bytes` can only be dropped, and "dropped" is a claim about
the allocator, not about the memory. Lanes read the window through **read-only** memoryviews.

### What is deliberately not here

- **mlock, core dumps, swap, ptrace.** Invariants 16–19 and 28, files/10 §3. Those are
  process-level controls on the worker that hosts the lanes; a lane package able to call
  `mlock` would need exactly the process capability invariant 13 denies it. `buffer.py` says
  so in its own docstring rather than implying coverage it does not have.
- **Any lane.** INT-111…115 own their models, their evidence and their approvals.
- **`LaneSignal` emission into the hash-chained event log** (files/03 §4.8) and
  `lane_signal_replay_determinism` (inv. 20). The recorded shape already exists as
  `clinical_schemas.observers.LaneSignal` (INT-031); wiring it to the event log needs a lane
  that produces one, so it lands with INT-112.
- **`must_ask_invariance` (inv. 21)** — that is INT-094's invariant suite, and it needs lanes
  to enable and disable.

## Blocked — needs a human

**`asr_quality` and `engagement` have no consent purpose, and two blueprint files disagree
about whether they should.**

- files/03 §4.7: *"Each lane is a separate consent purpose and can be disabled per tenant or
  patient without affecting intake."*
- files/06 §2 lists the purposes **exactly**, and the lane purposes in it are `lane:affect`
  and `lane:linguistic`. There is no `lane:asr_quality` and no `lane:engagement`, and §2.1's
  "what every lane text must say" covers `voice`, `lane:affect` and `lane:linguistic` only.
- INT-038's registry is the closed list, and it matches files/06.

Under CLAUDE.md — *never invent a value to unblock yourself*, and *build the mechanism, wire
the gate, make it fail closed, leave the content empty* — the framework refuses to mint a
scope. `consent_scope_for(Lane.ASR_QUALITY)` and `consent_scope_for(Lane.ENGAGEMENT)` raise
`LaneConsentUndeclaredError`, `ObserverScheduler.register` returns
`REFUSED_NO_CONSENT_SCOPE`, and the lane is never added — so it cannot be reached by `offer`
or run by `pump`. `tests/lanes/test_isolation.py` asserts exactly that, parametrised over both
lanes.

**Consequence: INT-113 (`asr_quality`) and INT-114 (`engagement`) cannot be enabled until this
is answered.** They can be *built* — the framework is complete for them — but a registration
will be refused.

There is no existing `files/HUMAN_BLOCKERS.md` row for this (checked: no row mentions
`asr_quality`, `engagement` or a lane scope), so a new one is needed. Proposed row, for the
regulatory & legal group:

> **HB-L23** — **Decide the consent purposes for the `asr_quality` and `engagement` observer
> lanes, or rule that they ride an existing purpose.** files/03 §4.7 says every lane is its own
> consent purpose; files/06 §2's list is closed and names two lane purposes. INT-110's
> framework fails closed on the two lanes that have none, so they cannot be registered. The
> one sentence needed: *does each of `asr_quality` and `engagement` get its own `lane:*`
> purpose with its own §2.1 text, or does each ride `voice` / `core`?* — owner: counsel +
> owner; blocks INT-113, INT-114.

Recording the disagreement itself as a `state-sync` finding: **files/03 §4.7's "each lane is a
separate consent purpose" and files/06 §2's closed two-purpose list cannot both be true.**
files/06 is the legal authority and INT-038 already implements it, so the framework followed
files/06 and refused the gap rather than closing it.

### A note on `tests/lanes` having no `conftest.py`

`tests/voice/test_clip_manifest.py`, `tests/voice/test_clip_cache_builder.py` and
`tests/research/test_export_gates.py` each do `from conftest import …` — a top-level module
named `conftest`. A `tests/lanes/conftest.py` therefore wins or loses that name depending on
the order the directories are named on the command line, and an early draft of this change
broke `pytest tests/voice tests/engine tests/lanes` that way while leaving the full run green.
The Talker doubles are loaded instead by explicit `spec_from_file_location` under their own
module name, with no `sys.path` mutation and no second `conftest`, and all four orderings were
re-checked.

(`pytest tests/research tests/voice` collides on that same pattern **today, without this
change** — pre-existing, reported not fixed, since both directories are outside this change's
ownership.)
