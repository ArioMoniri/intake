## What this issue is, and what it deliberately is not

**No clinical content was authored.** No threshold, no red-flag level, no patient copy. Every
Turkish string in the suite is synthetic (files/04 §7). INT-043 is `awaiting-human` (HB-C1)
and nothing here needs it.

**No lane model is wired, and one of them cannot be.** `affect` is INT-111, `linguistic`
INT-112, `asr_quality` INT-113, `engagement` INT-114, `acoustic` INT-115. For `acoustic` the
slot is not merely unfilled but **empty on purpose**: files/00 §2 records an exhaustive search
that found **no Turkish vocal biomarker model at all**, D14 dropped Kintsugi DAM because we
cannot be the legal manufacturer of an orphaned Class IIb model with no design history file,
and HB-C11 records that the `affect` lane's cheapest available win (160 s of labelled Turkish)
has not been collected either. This change therefore builds the mechanism, wires the gate,
makes it fail closed and leaves the content empty (CLAUDE.md invariant 17).

**Nothing measures time on the speech path.** `LaneRuntime` has no clock. A stopwatch in that
class would itself be a step taken on the path the invariant says the lanes must not touch;
the latency property is measured from the *Talker's* clock, in the test.

## Invariant 11, clause by clause

### 1. "read-only: they write `ObserverState` only, never slots or triage" — the mechanism

Four locks stack. Each closes a different door, and no one of them is the whole answer.

**(a) A lane is handed nothing it could write through.** `LaneContext` is a frozen, slotted
dataclass with exactly four fields — `{lane, session_id, window, is_cancelled}` — and `window`
is a `LaneWindow{window_id, frames, sampling_rate_hz, dropped_frames, duration_s}`. There is no
engine, no `WorkSubmitter`, no store and no callable that reaches one. This is INT-092's
`ReadOnlyContext` move applied one layer further out, and the test asserts the two field sets
rather than sampling them.

**(b) A lane's answer has no field a slot value or a level could occupy.** `LaneObservation`
is a `FrozenModel` (`extra="forbid"`), so `LaneObservation(triage_update=…)`,
`(slot_updates=…)`, `(level=…)` and `(candidate_flags=…)` are each a `ValidationError` at
runtime **and** an "unexpected keyword argument" under `mypy --strict`. That is the
compile-time half the acceptance asks for.

**(c) The open part of the payload is closed to both too.** `markers` is `dict[str, float]`.
A triage level is the string `"RED"`; a slot value is Turkish text or a coded term. Neither
fits in a float, so the escape hatch an open map usually leaves is not there — and this is
not a rule anyone has to remember, it is the annotation. `_observation(markers={"triage":
"RED"})` and `{"chest_pain": "evet"}` both raise.

**(d) `triage_update` and `slot_updates` exist, as read-only constants.** This is INT-172's
`CandidateRedFlag` shape, copied rather than reinvented: a `ClassVar` (which pydantic excludes
from the field set, so it is not a constructor argument either) behind a property with **no
setter**. `LaneObservation.triage_update.fset is None`, so the assignment does not type-check;
and at runtime the frozen model refuses it one step earlier still, so a caller who got past
`mypy` cannot land the write anyway. The test asserts both the missing setter and the refusal,
then asserts the value is unchanged.

**(e) The static lock: there is no path, not merely no call.** An AST scan over every module
in `observers/` fails on an import of `intake_voice_runtime.clinical_agent`,
`intake_voice_runtime.talker`, `clinical_schemas.triage` or `protocols`, and on the names
`IntakeEngine`, `BackendAgent`, `RulesTriageResult`, `TriageLevel`, `StateContext`,
`StateEffect`. The same scan, with a different list, lands files/10 §9.1 **invariant 13**'s
static half: no observer module imports `httpx`, `aiohttp`, `requests`, `socket`, `ssl`,
`urllib`, `websockets` or `livekit`, so a lane has no capability to open the second audio
transport files/03 §4.7.2 eliminated.

**And the destination is decided once, at admission, not per observation.** Each admitted lane
gets a `LaneSink` built from its declared `ObserverField`: an `ObserverState` lane's sink is
`store.apply(spec, …)`; `acoustic`'s is `sealed_store.record(admission, …)`, bound to the
admission that permitted it. A destination re-decided at delivery time would be a place where
an acoustic band could take a wrong turn.

**Two destinations are deliberately not `ObserverState`:**

- `affect` is `M1_INTERNAL`. files/10 §9.1 invariant 22: nothing but the closed
  `InteractionState` crosses the M1 boundary. `ObserverState` has no `affect` field — asserted
  — so the store writes nothing, and withdrawing the lane drops nothing, because the emotion
  inference existed inside M1 and died there.
- `acoustic` is `SEALED_RESEARCH`. files/03 §4.7.4 gives that output one home. Handing one to
  `ObserverStore` raises `SealedDestinationRefused` rather than being quietly ignored: a silent
  no-op there would look like it had worked.

`ObserverStore`'s public surface is exactly `{state, apply, drop}` — asserted by introspection,
so a writer added later shows up as a failing test.

### 2. "never sit on the speech critical path" — the fake-clock test, and its numbers

**The structural half.** The ingress is an ordinary function. `LaneRuntime.offer`, `withdraw`,
`close`, `depth` and `dropped` are all non-coroutines (asserted with `inspect`), so there is
nothing on the audio path for the Talker to await even by accident. This is the same proof
`tests/voice/test_talker_never_awaits.py` makes about `WorkSubmitter`, reused one layer out.
The lanes' own work lives in `pump()`, which the Backend worker drives — exactly as INT-092's
`run_pending` drives the Work queue.

**The measured half**, on `tests/voice/talker_harness.py`'s virtual clock. One scripted turn,
against two lanes stalled by four different amounts:

| lanes | turn latency (virtual ms) |
|---|---|
| no lane runtime at all | **32.0** |
| lanes admitted, 0 s stall | **32.0** |
| lanes admitted, **30 s** stall | **32.0** |
| lanes admitted, 3 600 s stall | **32.0** |

All four are equal, and `> 0` — the turn really did speak. 32.0 ms is the harness's playback
charge for the scripted clip (`RecordingSink` charges 1 ms per byte of a 32-byte clip); the
number is the harness's, and what matters is that the four agree.

**The measurement is not vacuous, and the suite proves that too.** A positive control awaits
the *same* 30 s stall on the turn's own path — `await runtime.pump()` immediately before
`await session.take_turn(...)` — and the elapsed virtual time is **30 032.0 ms** — the stall plus the same turn. So the
equality above is a property of where the lanes sit, not an artefact of the fake clock.

No test sleeps. `FakeClock` advances only when every task is parked, and only to the earliest
waiter, so a lane parked at 30 s can never come due before a turn parked at 32 ms.

### 3. "frames dropped under load with metric"

`LaneBudget{window_s, frame_ms}` gives each lane a ring of `capacity = window_s * 1000 /
frame_ms` frames. Frame `capacity + 1` **evicts and zeroes the oldest**, counts the drop, and
keeps the newest window — which is the contiguous one, and the one a real-time lane wants.
Measured in the test with a ten-frame budget and twenty-five frames offered: depth 10, dropped
15, and the window's last frame is frame 24, not frame 9.

The count travels two ways, because files/03 §4.7.6 says it is *"a tracked metric that is also
a recorded field on every lane signal"*:

- `lane.dropped_frames{lane}` — catalogued and **live** in `observability/metrics_catalog.yaml`,
  declared in `intake_voice_runtime.metrics` so the INT-025 AST scanner finds it. One label,
  the closed `Lane` enumeration. No session id, no window id, no frame content (invariant 6).
- `LaneObservation.dropped_frames_in_window`, so replaying a degraded session reproduces the
  *degraded* decision (files/03 §4.8 property 3).

`offer` consumes **zero** virtual time for fifty frames, asserted; and a lane stalled 30 s
mid-observation does not slow the next 39 `offer` calls, which simply drop.

**Invariant 3 and the 60-second ceiling.** `LaneBudget` refuses `window_s > 60.0` by
construction — `MAX_WINDOW_SECONDS` is asserted to be 60.0, and every shipped lane budget is
checked against it (one second for the four event/transcript lanes, thirty for `acoustic`,
whose gate needs ≥ 30.0 s contiguous single-speaker audio). The ring owns `bytearray` frames
and hands the objects themselves to the window rather than copies, so `zeroize()` reaches the
only bytes that exist. It runs on every trigger files/06 §3 names that this module can reach:
after the lane returns, after a lane **faults**, on eviction, on withdrawal and on close. Four
tests hold a reference to the ring's own buffer across each of those and assert it is all
zeroes afterwards. Page-locking those pages is a platform control (files/10 §9.1 invariants 17
and 28, node and container checks) and is not re-implemented here.

### 4. Per-lane consent — one evaluator, and absence rather than idleness

`consented_lanes` takes `ConsentDecision` values — the output of
`intake_platform.consent.consent_state`, which is the function the API's `ensure_consent`
calls and the only place staleness, withdrawal, the age axis and the default-on purposes are
resolved. The lane framework **computes no `allowed` of its own**, holds no ledger and has no
fallback, so there is no second answer to keep in step with the first (invariant 4).

Silence is a refusal, not a default: a scope with no decision does not admit its lane, because
the default-on question already has an answer inside the evaluator and guessing it here would
be the second evaluator this module exists to avoid.

**A refused lane is absent, not idle**, and the suite proves it four ways:

- it is not a member of `runtime.lanes`;
- it has no ring — `depth()` and `dropped()` raise `LookupError` rather than answering `0`,
  because `0` is what an idle lane would answer;
- `offer` fans out to admitted rings only, so nothing accumulates for it;
- it has **no metric child**: `lane_dropped_frames_total{lane="engagement"}` is absent from the
  exposition, not zero. That is the sharpest available difference between refused and idle.

Withdrawal mid-session (files/06 §2.2) removes the lane, zeroizes its buffered frames and drops
its live `ObserverState` entries in one call; a subsequent `pump()` runs nothing. Already-emitted
signals are **not** deleted here — tombstoning them belongs to the hash-chained event log
(files/03 §4.8), and deleting one would break the chain.

**Which purpose each lane runs under is declared, and only where files/06 §2 declares it.**
`lane:affect` and `lane:linguistic` are the two lane purposes in that closed list; both are
validated through `resolve_scope` **at import**, so a typo or a de-listed purpose fails at
import rather than at the first session. `lane:acoustic` is not in the map at all, and the
registry refuses it by name (files/06 §2.4: an ICF, not a toggle) — asserted.

That leaves `asr_quality` and `engagement`, and it is the one place this issue refuses to
proceed. See "Findings" below: `LaneRuntime.admit` raises `LaneConsentUndeclared` for them
rather than attaching them to a lawful basis nobody chose (**HB-L22**, raised here;
INT-113/INT-114 are marked `awaiting-human`).

### 5. `acoustic` fails closed, on the registry INT-230 already built

`AcousticAssertion{study_id, protocol_version, icf_version, approval_date}` — all four
required, **none defaulted**, asserted field by field over `dataclasses.fields`. A default here
would be an assertion nobody made, which is exactly the failure files/08 §3 describes: *"if
they are config, then whoever edits the deploy config mints a clinical investigation."* The
three id-shaped fields are validated against `intake_platform.research.STUDY_FIELD_SHAPE` — the
registry's own shape, not a second one — and a refused value is never echoed (invariant 6).

`admit_acoustic(assertion, registry=…, on=…)` resolves through
`intake_platform.research.StudyRegistry`, so **the ethics ids come from the one register**
rather than from a second one declared here. `on` is keyword-only with no default: an approval
window is only meaningful against a date. The gate closes in five places:

| gate | refusal |
|---|---|
| the study is not registered | `UnknownStudyError` (the registry's) |
| the approval has not started | `StudyApprovalNotYetInForceError` (the registry's) |
| the approval has ended | `StudyApprovalLapsedError` — **the day after, with no grace day** (files/10 §9 invariant 35) |
| the asserted `approval_date` is not the registered one | `ApprovalDateMismatchError` |
| the asserted `protocol_version` is not the registered one | `ProtocolAmendedError` — TCKAY m.11 makes an amendment a **fresh submission**, so an assertion against the previous protocol is not stale, it is unapproved |
| the register cannot vouch for the asserted ICF version | `IcfVersionUnrecordedError` |

**Today the gate refuses every assertion, twice over, and both refusals are correct.**
`study_registry.yaml` holds no study — HB-L1 (the qualifying site is unnamed, so no KAEK
submission has been made) and HB-R1 (the decision and its ids do not exist) — so
`UnknownStudyError` fires first, asserted against the shipped registry. And `StudyRecord`
carries no `icf_version`: see finding 1.

**The ICF check is a real comparison, not a permanent refusal**, and the suite shows that from
both sides. A test-only subclass carrying `icf_version: str` opens the gate and returns an
`AcousticAdmission`; the same registry refuses a *different* asserted version; and a near-miss
subclass carrying the field under the wrong type (`icf_version: int`) refuses too, because a
number next to the name vouches for nothing.

**Even admitted, the band never reaches `ObserverState`.** `acoustic` is only built when a
`StudyAdmission` *and* a `SealedResearchStore` both exist — files/03 §4.7.4 gives that output
exactly one destination, and on this branch there is no implementation of that Protocol, because
the sealed store, its key, its retention clock and its access log are INT-115's. So in every
configuration this branch can build, the acoustic lane is **absent**: unreachable, not merely
unrendered, and with no shadow mode. The test with an in-test sealed store proves the wiring is
real and that `linguistic_markers`, `asr_quality` and `engagement` all stay empty while it runs.

### Invariant 29 — one intended-purpose statement per module

Each lane declares its MDCG 2019-11 §3.4 module (`M1 interaction_signals`,
`M2 clinical_signals`, `M3 acoustic`), and `INTENDED_PURPOSE` carries the statement for each,
quoted verbatim from files/03 §4.7.1's table. A lane with a module that has no statement fails
the test. These are regulatory strings, quoted, never composed here.

### Invariant 6 — nothing a lane reads reaches a log

The suite offers frames whose bytes are a synthetic Turkish sentence, then pumps, faults,
withdraws and closes with `caplog` at DEBUG, and sweeps **every** captured record — the rendered
message *and* every attribute of every record — for that sentence and for the session id. The
sweep decodes escapes first (`.encode("ascii", "backslashreplace").decode("unicode_escape")`),
because `json.dumps` with `ensure_ascii=True` would hide `göğsümde` behind `göğ…` and
a raw substring search would miss it. The lane framework logs a lane value, a count and an
exception **class name** — never a message, which could quote input.

## Findings — where the blueprints disagree, and what was refused rather than invented

These matter more than the code, so they are written down rather than worked around.

**1. `StudyRecord` has no `icf_version`, and invariant 23 needs one.** files/08 §3 specifies the
Study Registry record as `{study_id, protocol_version, ICF_version, approval_date,
approval_valid_until, atadek_no, titck_permit_no, insurance_ref, site_id, PI}` plus document
hashes of the approval letters. INT-230 implemented the subset a research *export* needs, which
does not include the ICF version. So of invariant 11's four assertions, the register can vouch
for three. Rather than declare a second source of ethics ids — which is exactly the mistake
files/08 §3 was written to prevent — `admit_acoustic` reads the field through the model's own
`model_fields` and refuses with `IcfVersionUnrecordedError` when it is not there. The day the
registry gains the field, the check starts comparing with no edit here. **The field belongs to
whoever owns the study-registry admin surface (INT-117/INT-218), not to this issue**, and adding
it changes HB-R1's ask (a fifth value from the KAEK decision letter), which is a human's
decision to make. Recorded rather than reached across for: `packages/intake_platform/.../research/`
is another agent's module in this session.

**2. files/03 §4.7 and files/06 §2 disagree about how many lane consent purposes there are, and
two lanes fall in the gap.** files/03 §4.7: *"Each lane is a separate consent purpose and can be
disabled per tenant or patient without affecting intake."* files/06 §2: *"Purposes exactly:
`core`, `voice`, `wellbeing`, `lane:affect`, `lane:linguistic`, `documents`, …"* — a closed list
with two lane purposes — and §2.1's *"what every lane text must say"* writes texts for `voice`,
`lane:affect` and `lane:linguistic` and for nothing else. `acoustic` is resolved (files/06 §2.4
turned it into an ICF, and `resolve_scope("lane:acoustic")` refuses by name). `asr_quality` and
`engagement` are not resolved anywhere. Choosing a purpose for them would be choosing a lawful
basis, which rule 1 forbids, so `LaneRuntime.admit` raises `LaneConsentUndeclared` for both.
**HB-L22** is raised with the one sentence counsel must answer, `docs/backlog/blockers.md`
carries the row, and INT-113/INT-114 are marked `awaiting-human`. Neither lane exists yet, so
nothing regresses — but the framework will not build them, which is the point.

**3. INT-092's reading of files/03 §4.3 versus files/12 §7.4 holds, and the lanes sit in the
concurrent half.** files/03 §4.7 is explicit that the lanes are *not* in the FIFO Work queue:
*"Psychiatric and affect analysis must **not** wait in that queue — it runs continuously in
**parallel observer lanes**"*, merging back *"at section boundaries as a normal
`wellbeing_signal` Work item (so slot/note writes stay serialised)"*. So INT-092's resolution —
"one Work in flight" means one *slot-writing* Work — is not merely compatible with this issue,
it is what makes it possible: reading files/03 §4.3 literally would put a RED behind a lane
window as well as behind a `parse_document`. **files/03 §4.3's sentence should still be amended
in place**, as INT-092 already recorded.

**4. `wellbeing_signal` is the merge Work type files/03 §4.7 names, and `WorkType` has no such
member.** The lanes' aggregates are supposed to reach the Backend Agent at section boundaries as
a normal Work item; the enum has three members (`extract_slots`, `plan_follow_ups`,
`parse_document`). This is the same gap INT-092 recorded as finding 2 — five of eight named Work
types are absent — reaching this issue from the other side. Nothing here is blocked by it: the
`ObserverState` store is the destination invariant 11 names, and the merge into the engine is a
separate step that belongs with the lane that has something to merge (INT-111/INT-112). It is
recorded because a reader looking for the merge will not find it.

**5. `LaneSignal` is defined and nothing emits one.** `clinical_schemas.observers.LaneSignal`
(INT-031) is files/03 §4.8's recorded shape, and three of its fields — `model_ref`,
`model_sha256`, `consent_version` — cannot be filled by this issue: there is no model to pin
(files/00 §2: no Turkish vocal biomarker model exists; D14 dropped DAM) and the consent texts are
unauthored (INT-210). Emitting a signal with an invented `model_id@revision` would be exactly the
plausible-looking value rule 1 forbids, so the framework writes `ObserverState` — which is what
invariant 11 requires — and the hash-chained signal log lands with the first lane that has a
pinned model. Invariant 20 (`lane_signal_replay_determinism`) therefore has nothing to replay
yet, and is not claimed.

**6. The AGC/AEC collision (files/00 §2) is a client-side gate this framework cannot enforce.**
files/00 records it as a 🔴 finding: the lanes need AGC and NS off while AEC stays on, the
assertion is per-session and platform-level, *"'AGC disabled' is a per-session runtime assertion,
never a build-time guarantee"*, and **the lane must not run when the assertion fails or when the
output route is the loudspeaker**. That gate lives in `apps/mobile`'s audio session, not here.
`LaneRuntime.admit` takes the lanes it is given, so when that assertion lands it belongs as a
third admission condition beside consent and the study — recorded now so it is added rather than
rediscovered.
