# INT-371: Intake flow — Bitirdim finishes to review, the open hint shows once, typed-to-handoff proven

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** intake-typed · **GitHub:** #605
**Slice:** S4 of INT-354 (#560): int-demo `20aca9e2`, plus the `speech.ts` aside hunk of
`b2301f8e`. See `docs/evidence/INT-354.md` (commit table rows 14 and 16). It follows INT-321,
which delivered only the relabel. **Depends on:** INT-321 and INT-339 (both merged).

## Acceptance (verbatim)
- "Bitirdim ends the dialogue and lands on review; the open-invite hint shows once per session;
  the typed → handoff path is covered by a test"
- "the `a11y.dialogue.finishHint` register finding is recorded and routed to clinical-reviewer"

## Problem
INT-321 relabelled the dialogue bar's button from "Sıranız geldi" to "Bitirdim" (`voiceFirst.stop`)
and left it a per-turn stop:
- it called `session.finishListening()`;
- it rendered only while `turn.phase === "listening"`;
- with a silent microphone (the simulator's, or a denied permission) it did nothing.

So a patient who had said enough could not leave the conversation. Separately, both lanes
repeated their "kendi sözlerinizle" invitation on every open question. The spoken lane appended
`dialogue.openInvite` to every open turn, and the typed lane put `intake.open.hint` over every open
answer field. The owner reported that it read as noise.

## Change
- **`DialogueIntake.tsx`**: the bar has one Bitirdim, rendered in every phase. It is a
  `SecondaryButton` with `hint={t("a11y.dialogue.finishHint")}` whose handler `finishToReview`
  leaves the session and replaces the screen with `/(tabs)/visits/<id>/review`. Every answer
  commits at its own confirm, so nothing is lost. The per-turn "done speaking" stays on the
  pulsing listening bubble (`finishListening`).
- **`lib/dialogue/speech.ts`** (the `b2301f8e` aside hunk): an open question adds no spoken
  aside. It is asked as exactly the scripted question.
- **`lib/intake/openHint.ts`** (new, pure) with `StepFlow` in `intake.tsx`: `intake.open.hint`
  is shown once per session, at the first open question the patient meets. A later open step
  keeps the same text as its answer field's `accessibilityHint`, and keeps
  `intake.open.orChoose` below it.
- **i18n**: `a11y.dialogue.finishHint` is new in tr ("Görüşmeyi bitirip özeti görmek için iki kez
  dokunun."), the source of truth, and mirrored in en. `dialogue.openInvite` is removed from both
  catalogues, because nothing renders it any more (below).

### Adapted to main
- **INT-339 (merged while this slice was open).** Its MOTION-10 guard
  (`src/lib/motion/transients.test.ts`, "completion navigation is never chained to an
  animation") requires every review navigation in the dialogue to sit in a synchronous handler.
  The commit's `const finishToReview = async () => { await session.leave(); router.replace(…) }`
  fails it:
  ```
  × completion navigation is never chained to an animation
  AssertionError: src/components/DialogueIntake.tsx @7221: expected true to be false
  ```
  The handler is now synchronous: `void session.leave(); router.replace(…)`. `leave()` stops the
  barge-in watch, the playback and the pending work before its first await. The recording
  discard and the clip clear then finish on their own, which is what the hook's own unmount
  cleanup already does (`void stopAndDiscardRecording()`).
- **Once per session, not step one.** The commit showed the hint when `stepIndex === 0`. A
  voice→typed hand-off resumes at the first **unanswered** step, which can be any step (proved in
  `typedFlow.test.ts`), so after a hand-off the commit would never show the hint. The rule now pins
  the hint to the first open question this session meets. A session here is one mount of the
  typed flow.
- **`dialogue.openInvite` retired.** With no aside, its only reader is gone, and the release
  gate forbids an orphan key. The key leaves tr and en, as build-source `dea9bb8a` did. The
  `speech.test.ts` assertions that pinned its shape (one sentence, no "?") are replaced by one
  that pins its absence, so no test is lost. The key's list entry in the dialogue-copy test goes
  with it.
- **Register finding, recorded, not rewritten.** `a11y.dialogue.finishHint` uses the short
  imperative of every sibling `a11y.*Hint`. It is added to `PROSE_REGISTER_FINDINGS` in
  `tests/release/test_i18n_complete.py`, as `dea9bb8a` first did. A lone `-iniz` would trip
  `test_no_short_in_flow_control_uses_the_doubled_polite_form` and split the register
  mid-screen. **Routed to clinical-reviewer.**
- INT-362 (`AnnouncedText`, PR #600) is not on `main`, so there is nothing to adapt to.
