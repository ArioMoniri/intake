# Evidence — INT-173 · Canary/rollback controller on guardrail KPIs (5/25/100)

## Acceptance (verbatim from docs/backlog/issues.yaml)

- [x] "auto-rollback on acceptance -5, safety blocks +50 percent, completion -5, CSAT -0.3;
  simulated dip test"

Delivered by `services/learning/src/intake_learning/canary.py` (the controller) and
`tests/learning/test_canary_rollback.py` (the test the issue names). The controller:

1. **Advances a rollout through 5 % → 25 % → 100 %** (`CANARY_STAGES`, `run_canary`),
   evaluating the guardrail KPIs at each stage and promoting only a healthy one.
2. **Auto-rolls-back** the moment a guardrail regresses past its threshold *relative to the
   pre-canary baseline*: acceptance −5 pts, safety blocks +50 %, completion −5 pts, CSAT −0.3
   (`evaluate_window`, `_first_breach`).
3. **Simulated dip test**: synthetic KPI streams drive one guardrail past its threshold at a
   stage and assert a rollback; a healthy stream promotes to completion. Deterministic — pure
   functions, no wall-clock and no network.

sec_row: `learning-loops` (docs/security/threat-model.md "## `learning-loops` — proposal-only
learning"). That row already listed "canary and rollback" as a control and forward-referenced
"Rollbacks land with INT-173"; this PR fills in that half — the `learning_rollbacks_total`
signal, the `canary_rollback` test, and a Controls note that the controller is pure rule and
applies nothing (invariant 12).

## The numbers and their units come from the blueprint, not this issue

The one-line acceptance abbreviates; files/09 §4 "Path to production" states the guardrails in
full, and files/09 §6 states the test's shape:

> "canary 5 % → 25 % → 100 % with automatic rollback if guardrail KPIs move (acceptance −5
> pts, safety blocks +50 %, completion −5 pts, CSAT −0.3)"
> "`canary_rollback`: simulated KPI dip triggers rollback within one evaluation window."

So the units are the blueprint's and are pinned in the module, not invented (invariant 17):

| guardrail | KPI (observability/metrics_catalog.yaml) | unit used | trip |
|---|---|---|---|
| acceptance | `note.acceptance_rate` (ratio, target ">= 70 %") | percentage points, [0,100] | drop ≥ 5.0 pts |
| safety blocks | `policyguard.blocks_total` (counter) | blocks **per session** (a rate) | rise ≥ 1.5× baseline |
| completion | `session.completion_rate` (ratio, target ">= 80 %") | percentage points, [0,100] | drop ≥ 5.0 pts |
| CSAT | `csat.score` (score 1–5, target ">= 4.3") | mean score, [1,5] | drop ≥ 0.3 |

Two unit choices, both stated in the module docstring and defensible from the catalogue:
- acceptance/completion are read as **percentages** (the ratio ×100), because the blueprint
  says "−5 **pts**" and both catalogue targets are written in percent (">= 70 %", ">= 80 %").
  "−5 pts" is then a literal `5.0`.
- safety blocks is a **rate**, not the raw counter: `policyguard.blocks_total` cannot be
  compared across a 5 % and a 25 % cohort, so the guardrail is a per-session rate and "+50 %"
  is a *relative* rise (×1.5). From a zero baseline no ratio exists, so the safe reading is
  that introducing PolicyGuard blocks where there were none is a regression (fail closed).

## Invariants touched (named individually)

- **Invariant 12 (learning is proposal-only).** The controller reverts a rollout's exposure
  but applies nothing and cannot reach a clinical value: it is pure rule (snapshots in, a
  decision out), imports only stdlib + `prometheus_client`, and `proposal_scope`'s gates now
  cover `canary.py` with the rest of the package (import-closure reaches no forbidden module;
  no writer; no SQL; allow-listed imports). It never touches red-flag levels, instruments,
  consent texts, the Talker tool list, PolicyGuard or profile routing.
- **Invariant 15 (monitoring contract).** The one new metric, `learning_rollbacks_total`
  `{guardrail,stage}`, is added to `observability/metrics_catalog.yaml`; the catalogue
  completeness gate recognises it and its labels pass the PHI-risk label denylist.
- **Invariant 17 (no placeholders / no invented values).** Thresholds are the blueprint's
  exact numbers; baselines are always a caller-supplied snapshot, never fabricated; an absent
  or non-finite KPI fails closed (does not promote) rather than defaulting to a number.
- **Invariant 6 (no PHI in logs/metrics).** The rollback counter's labels are two closed
  enumerations (`guardrail` ∈ the `Guardrail` set; `stage` ∈ 5/25/100) — never a pack, a
  clinic or a cohort. The controller logs nothing.
