## The defect

`assert_restore_target_outside_workspace` compared

```python
resolved = Path(target).resolve()
root = Path(repo_root).resolve()
if resolved == root or root in resolved.parents:
```

Both names carried `.resolve()`, so the *variables* were symmetric — but the
comparison was not. `resolve()` follows links, and a checkout's own children
can be links. When `.cache` inside the worktree is a symlink out of it,
`(REPO / ".cache" / "restore").resolve()` lands in the link's destination and
the containment test answers "outside". `git status` answers "inside": the
path sits under the worktree root, so a restored cluster there is one
`git add -A` from being committed and one `make check` from being scanned.
That is the invariant-3 property the guard exists to hold, and the symlink
quietly permitted its violation.

The comparison the issue describes as "a real path and a symbolic one" is
exactly this: the guard tested where the bytes land, and workspace membership
is a question about the path, not about its destination.

## How it was found

Not by this issue. INT-180 hit two failing restore-drill PHI-safety tests on
its branch, was told they might mean a widened guard, and established that
they did not: the cause was a `.cache` **symlink** committed by
interruption-recovery saves. Removing the symlink passed 5/5; restoring it
reproduced the failure. `docs/evidence/INT-180.md` records that reasoning and
files the finding rather than fixing it. The guard was still wrong, which is
what this issue fixes.

## The fix

Read **both** sides **both** ways and refuse on containment under any pairing:

```python
def _readings(path: Path) -> tuple[Path, ...]:
    absolute = Path(os.path.abspath(path))
    real = Path(path).resolve()
    return (absolute,) if absolute == real else (absolute, real)
```

`os.path.abspath` is git's reading — it collapses `..` textually and follows
no link, so a symlinked child of the checkout stays under the checkout.
`resolve()` is where the bytes land. The two disagree exactly when a link is
involved, and the old guard consulted only the second.

The workspace root is read both ways for the same reason: either side can be
the symbolic half. A checkout named `/tmp/wt` (with `/tmp` → `/private/tmp`)
whose target is spelled `/private/tmp/wt/.cache/restore` is caught by the
lexical target against the resolved root, and by no other pairing.

Accepting therefore requires every reading to agree the target is outside, so
an ambiguous spelling fails closed. That costs an operator one rewrite; the
other way round costs a patient's data on the workspace floor.

Minimal by construction: 4 comparisons instead of 1, one new import (`os`),
no new dependency, no behaviour change for any path that contains no link —
where `abspath == resolve`, `_readings` returns one element and the check
reduces to the original single comparison.

## Mutation check

A guard that passes both before and after the fix is not a guard. Each half of
the reading was removed in turn and the class re-run. The file was restored
from a copy each time, never with `git checkout`.

| Mutation | Result | Which clause it breaks |

Both halves are load-bearing and neither is redundant.

## Clause by clause

**1 — the workspace side is resolved too.**
`test_the_workspace_side_is_resolved_too` puts the link on the *root* and the
real path on the *target*, with the target's own parent a link out, so no
single-sided reading answers it: it fails under `resolved_only` and under
`lexical_only` and passes only with both. Its two other assertions check the
plain spellings in both directions, which the old guard already got right and
which must not regress.

**2 — the case that produced it is the regression test.**
`test_a_symlinked_cache_inside_the_worktree_is_still_inside` builds a
worktree whose `.cache` is a symlink to a model store outside it — the shape
this repository's own fresh-worktree deid-model workflow creates and the one
INT-180's interruption-recovery saves committed. The test asserts the old
reading explicitly (`target.resolve() == model_store / "restore"`) before
asserting the refusal, so it states what it defends against rather than only
that it passes. `test_any_symlinked_directory_inside_the_workspace_is_refused`
makes the same point for `infra/volumes`, so the rule is about links and not
about the name `.cache`.

**3 — the near-miss control passes unchanged.**
`test_near_miss_a_genuinely_external_target_is_still_accepted` accepts: a
sibling directory; the model store the workspace links to (outside the
workspace — only paths *spelled through* the link are inside it); a sibling
whose name merely starts with the workspace's own name, which a string-prefix
"fix" would wrongly refuse; and `/restore`, the container volume the drill
actually restores into.
`test_near_miss_an_upward_escape_that_genuinely_leaves_is_accepted` accepts
`workspace/infra/../../restore`, while the pre-existing
`test_a_relative_target_that_escapes_upward_is_still_checked` still refuses
`REPO/infra/../.cache/restore`. So `..` is read as a path and not as
punctuation. All four pass before the fix and after it, and all fail against
`refuse_everything`. The drill still has somewhere to restore to.

**4 — no restore ever writes patient data inside the repository.**
`test_no_restore_writes_patient_data_inside_the_repository` states the
property over the shape that produced the bug: with `.cache` symlinked out,
every location git can see inside the checkout is refused — the root itself,
`workspace/restore`, `.cache/restore`, `infra/../.cache/restore`, and
`.cache/../restore` — while `/restore` is accepted against both that workspace
and this one. It also asserts no step of the real `plan_restore_drill` output
names a path inside any checkout, so the property is checked against the plan
the drill runs and not only against the guard in isolation.

`.cache/../restore` is the one ambiguous spelling: `git status` reads it as
`workspace/restore` and the kernel walks it out through the link. It is
refused, which is the fail-closed answer; an operator who meant the other one
can spell it without the link.
