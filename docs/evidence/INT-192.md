## What was built, and why it is a projection and not a second copy

`apps/admin-web/src/security/module.ts` turns the `GET /admin/security`
composite into exactly what the page paints and decides nothing the server did
not already decide — the same discipline as the models (INT-183), compliance
(INT-189), protocols (INT-184), safety (INT-185) and experience (INT-186)
modules. It performs no mutation and opens no socket; the routes that read a
security source flow through the INT-180 admin shell's audited, RBAC/ABAC,
four-eyes routes, which this file never re-implements (invariant 4). Nothing
here writes to the audit chain — its status is read-only on this surface
(invariant 4).

`apps/admin-web/e2e/fixtures/security.payload.json` is recorded from the real
sources by `scripts/dev/record_security_fixture.py` (added to
`make admin-fixtures`), never hand-mocked — a hand-written mock is a second,
hand-kept copy of the SIEM feed, the verifier's outcomes and the metric ids
that keeps passing on the day any of them changes and the console stops matching
them (invariant 17). Every field is read from a real source at record time:

| surface | real source |
|---|---|
| SIEM summaries | `intake_platform.siem.feed.load_console_feed` (INT-205); signal/severity enums `intake_platform.siem.Signal`/`Severity`; metric ids `siem_alerts_ingested_total` / `siem_alerts_refused_total` resolved in `observability/metrics_catalog.yaml` (invariant 15) |
| egress denials | metric `sec.egress_denied_total` (INT-018), resolved in the catalog; the paging target is read from the catalog entry, not copied |
| audit-chain status | `intake_platform.audit_verifier.job.run_daily_verification` over `InMemoryAuditStore()` with a no-anchor witness; outcome enum `VerifierOutcome`; metric `sec.audit_chain_ok` |
| pen-test tracker | metrics `sec.vulns_open` / `sec.vuln_age_days` resolved in the catalog; the SLA (critical 72 h / high 7 d / medium 30 d) from files/10 §7; findings genuinely empty |

The SIEM feed, the egress scrape and the audit verifier are each called (or
resolved) for real, so the recorded empty/fail-closed states are the platform's
own, not shapes guessed here. The SIEM detector reasons distinguish Wazuh/Falco
(share the `load_console_feed` path; stream not mounted) from CrowdSec (edge
bouncer; no console feed loader in this repo — its scenarios are committed under
`infra/security/edge/crowdsec`).

### The refusals (the near-miss negative controls)

The module is a projection, but a stale tab, a cached response or a tampered
body must not buy the page a property the server would never have served. Each
refusal is paired in the spec with a near-miss — the case one clause away from
firing:

| refusal | invariant / finding | near-miss control |
|---|---|---|
| `SiemSummaryWithoutFeed` | INT-205 feed contract; invariant 17 | a total, or a per-detector count, shown while the feed is not configured |
| `UnknownSecuritySignal` | sealed `Signal` enum | a signal outside the enum |
| `UnknownSeverity` | sealed `Severity` ladder | a severity outside SEV1..SEV4 |
| `UnknownDetectorSource` | the acceptance's three detectors | a detector source (e.g. `splunk`) off the set |
| `EgressCountWithoutScrape` | invariant 17; files/10 §5 | a denial count presented as observed while the scrape is unavailable |

## No value invented

Rule 1 of `files/HUMAN_BLOCKERS.md` — never invent a value to unblock yourself.
Nothing was invented here; the fail-closed states are the delivered states:

- **The audit-chain anchor is absent because HB-I8 is open** — no anchor
  publisher destination is named (a second organisation's object store or a
  KEP/e-imza TSP). The verifier reports `anchor_missing` and the console renders
  exactly that, refusing to paint a green attestation without it. **No new
  HUMAN_BLOCKERS.md row was minted** — HB-I8 already records this, and minting a
  numbered artefact is the collision the loop forbids.
- **The SIEM feed and the egress scrape are not wired in this repo**, so both
  render their honest not-configured / source-unavailable states. These are
  infrastructure deployments (INT-205 tier boot, a metrics scrape), not values a
  human must supply for the console clause to be delivered.
- **No pen-test has been conducted** (files/10 §7: first external pen-test
  before the P2 pilot), so the tracker is genuinely empty.

The issue title mentions "vulns vs SLA, rotations, drills, integrity" — the
**verbatim acceptance** is the four clauses above, and those are what is
delivered (invariant 17: "scope is delivered exactly as the issue's acceptance
says"). Rotations and drills are title-only, out of the acceptance, and their
metrics (`sec.secret_rotation_due_days`, `sec.restore_drill_age_days`) are
catalogued `planned` for a later Ops/Overview surface; "vulns vs SLA" is
delivered as the pen-test tracker's SLA columns, and "integrity" as the
audit-chain status.
