# INT-537 — the app grants the core consent that visits and notes require

GitHub #904 · Sec-Row: `consent` · branch `int-537-core-consent-control` · stacked on INT-529
(PR #911, `bb717aff`), whose synthetic core text is what the app renders on the synthetic host.
Found by the INT-529 legal author as finding F2 (`docs/evidence/INT-529.md` §10).

## 1. The defect

| where | what it said | what the server does |
|---|---|---|
| `apps/mobile/src/lib/consent/purposes.ts` | `core` was `ui: "info"`, basis copy `consent.basis.service` ("Bu, hizmetin kendisidir; ayrı bir düğmesi yoktur") | `consent/registry.py`: `core` is `EXPLICIT_CONSENT`, default off |
| `ledger.ts` `grant` / `withdraw` / `viewOf` | refused every `info` purpose in both directions | `POST /v1/consents/grant {scope: core}` records a hash-bound grant (INT-232) |
| `services/api` `visits.py`, `notes.py` | — | every visit and note route declares `require_scopes("core")`; without it, 403 `{error: consent_required, scope: core}` |

So a signed-in account with no `core` row could not start a visit on the synthetic host, and
nothing in the app could create the row.

## 2. What changed

**Consent control (the existing İzinleriniz flow, reused).**
- `purposes.ts`: `core` is a `toggle` on `consent.basis.explicit`. The `info` UI class is gone,
  because no purpose uses it any more. Its two strings (`consent.basis.service`,
  `consent.state.service`) were deleted from both catalogues, because the orphan gate requires it and
  because "ayrı bir düğmesi yoktur" would now be false next to a button.
- `core.cascadeChildren` is every other purpose. This mirrors `dependents_of("core")`. The synthetic
  core text tells the patient the same: "Bütün öteki izinleriniz ve açık paylaşım bağlantılarınız da
  kapanır".
- `ledger.ts`: `grant` and `withdraw` treat `core` like any açık rıza purpose. Without a loaded text
  there is no grant (invariant 18). A grant binds the version and SHA-256 of the text shown. One
  withdraw op is queued, for the root, and the server re-derives the cascade.
  - The local cascade spares a default-on child that has no explicit decision. The server's
    `_cascade` revokes rows only, so its snapshot keeps that child `default_on`. Without the spare,
    the device would show a state that the next snapshot undoes.
- `ConsentList.tsx`, `(auth)/consent.tsx`, `me/consents/index.tsx` and `[purpose].tsx`: the `info`
  pill and branches are removed. A `core` change mirrors into the session like any other purpose
  (the `key !== "core"` exclusions are gone).
- The detail screen is unchanged. Its legal copy is the loader's `body`, with version and hash
  (invariant 18). On the synthetic host that is `docs/legal/synthetic/consents/core.tr.md`, whose
  first line is "Sentetik test metni: …".

**Visit start (the app's own visit-creation screen).**
- `lib/consent/gate.ts` (new, pure): `coreGate(ledger)` returns open only on an honoured `core` grant.
  When the grant is stale (the text moved), it returns shut and says so. It reads `core` and nothing
  else (files/02 §7).
- `lib/consent/store.ts`: `ledgerSeededFor(accountId)`. The screen refuses only on this account's own
  ledger. An unseeded ledger is a fresh one, and would refuse a dev account that holds core.
- `app/(tabs)/visits/new.tsx`: it seeds the ledger for the account. While the gate is shut, the form
  is replaced by a `GuidanceBlock` and one `PrimaryButton`, which opens
  `/(tabs)/me/consents/core`. `save()` returns before `addVisit` while the gate is shut. Granting
  happens next to the text, on the consent screen. Back on this screen, the form returns.
- `lib/records/api.ts` and `app/(tabs)/records.tsx`: a 403 `consent_required` whose scope is `core`
  is now its own kind, `core_consent`, shown as `records.err.coreConsent`. Before this, a document
  upload whose server visit was refused for `core` told the patient their document consent was off.

**New copy** (tr first, en mirror, same order; chrome only, no legal text):

| key | tr |
|---|---|
| `visits.new.core.kicker` | İzin gerekli |
| `visits.new.core.title` | Vizit eklemek için temel hizmet izni gerekir |
| `visits.new.core.body` | Bu izin olmadan ön görüşme yapılamaz. İzin metnini okuyup karar verebilirsiniz. İzni istediğiniz an geri çekebilirsiniz. |
| `visits.new.core.staleBody` | Temel hizmet izninin metni güncellendi. Vizit eklemek için yeni metni okuyup yeniden onay vermeniz gerekir. |
| `visits.new.core.cta` | İzin metnini okuyun |
| `records.err.coreConsent` | Temel hizmet izniniz kapalı görünüyor. İzinlerinizi Profilim sayfasından açabilirsiniz. |

- **Register.** The prose keys (`body`, `staleBody`) carry no imperative. They use
  "-ebilirsiniz", "vermeniz gerekir" and "-amaz", so they need no entry in
  `PROSE_REGISTER_FINDINGS` and add no lone `-iniz` imperative. The one imperative is the short
  in-flow button `İzin metnini okuyun` (`-in`).
- **Length.** Every sentence is at most 11 words, under the B1 bound.
- **Agreement with the text.** "Bu izin olmadan ön görüşme yapılamaz" follows the core text's
  "Onay vermezseniz: Ön görüşme yapılamaz". "İzni istediğiniz an geri çekebilirsiniz" follows its
  "Geri çekme". The copy states nothing the text does not.
- **No accuracy claim.** There is no performance figure anywhere.

**Server.** No change. The grant, withdraw and snapshot routes (INT-232), the guard (INT-038) and
the synthetic index (INT-529) already did everything the acceptance asks for on the server.
`tests/api/test_core_consent_visit_start.py` pins it end to end on the synthetic stack
configuration.

## 7. Findings for the reviewer

- **G1, chrome next to the core text (F1, INT-536, not fixed here).** The core detail screen shows
  `consent.who.core` above the text. It says "Anlattıklarınızı yalnızca siz ve onay verdiğiniz hekim
  görür". The synthetic core text also names two things the row does not:
  - clinic staff see an ids-only alert on an emergency sign;
  - processing runs on AWS in the US.

  The basis row is now honest (`consent.basis.explicit`), and that half of F1 is closed by this
  change. The who-row is INT-536's scope: one issue per PR. Before this change it sat next to a text
  that could not be granted; now it sits next to a grant button, which makes INT-536 more urgent.
- **G2, the session mirror after a restart.** The legacy `consents.*` session mirror is seeded from
  the account and never reconciled from the server snapshot, so after a restart it can disagree with
  the ledger. The records screen gates on `consents.documents` and has this gap. The visit gate here
  reads the ledger, which the snapshot reconciles, so it does not. This is pre-existing and recorded
  only.
- **G3, learning purposes under a core withdrawal.** The text says "Bütün öteki izinleriniz … da
  kapanır". The server leaves an undecided default-on learning purpose `default_on`, because it has
  no row to revoke. Those two purposes are not açık rıza under 2026/347 (INT-529 §3.1), so "izin" in
  the text arguably does not cover them. The app mirrors the server. Whether the text should say so
  is the legal lane's call.
