# Evidence — INT-298 · PolicyGuard refuses a locale it has no signed lexicon for, at the type level

Date: **3 September 2026**. Branch `int-298-policyguard-locale`, off `origin/main` at `6e893b8`.
Dependency INT-296 is `done` and merged; this issue builds on its registry and adds no second one.

## What the issue is, in one paragraph

CLAUDE.md invariant 2 names a mechanism and a **content**, and the content is
Turkish: the diagnosis, treatment and prognosis vocabulary; the B1 word bound,
chosen against Turkish scripted copy; the sentence splitter that knows *Dr.*
and *Uzm.*; the interrogative particle; and the `siz` register with its
`-in`/`-iniz` split and INT-248's morphology. None of it transfers. A guard
running those arms over Arabic would return **no findings on anything**, and no
findings is not neutral — downstream it reads as *checked*. So the guard is now
built from a language's signed lexicon, and a language with none has no guard.

## Acceptance, line by line

- [x] **"the guard is constructed per locale and cannot be constructed without a
  signed lexicon for it"** — `PolicyGuard.__init__` is
  `(*, lexicon: SignedGuardLexicon, profile, form_of_address=SIZ)`. It has **no
  `locale` parameter at all**: a language reaches the guard only as the lexicon
  somebody signed for it. `policy_guard_for(locale=…)` is the one route from a
  locale to a guard, and it cannot return without one.
- [x] **"the refusal is type-level rather than a runtime check … asserted against
  the module's own parsed source"** — six structural assertions, listed below.
  The strongest is that `policy_guard.py` **imports no `re` and compiles no
  pattern**: there is no Turkish vocabulary inside the guard for a foreign
  locale to fall back onto, so the failure is not merely refused, it is absent.
- [x] **"the lexicon carries the same sign-off shape the packs use … and an
  unsigned lexicon compiles to nothing rather than to an empty term list"** —
  the lexicon carries `protocols.compile.life_threat.ClinicalSignoff`, the
  packs' **own type**, so the two shapes cannot drift; `compile_guard_lexicon`
  **raises** on four separate conditions and never returns a lexicon with empty
  arms; and `GuardArms.__post_init__` refuses to hold an empty arm, so the
  object a permissive compiler would have returned cannot be built either. Read
  *Two sign-off blocks* below for which block is the gate and why — it is the
  one judgement in this change and it is stated rather than buried.
- [x] **"no lexicon is authored by this issue: only `tr` ships signed"** — the
  Turkish arms were **moved, not written**: the 198-line block is byte-identical
  to `origin/main`, comments and all (`diff` rc=0, below). The table holds one
  entry, `guard_lexicons/` holds one module, and both are pinned by test.

## Two sign-off blocks, two questions, never one flag

INT-296's shape, one layer in. The distinction is load-bearing, so it is stated
in the module docstring, in the code, and here.

`clinical_signoff` — **HB-C19**, and the gate. *"Who signs the clinical text for
that language, and do they read it."* Its own `blocks` column reads *"Every
locale except `tr` running an intake"*, which is the register of record stating
that Turkish's answer is settled. Nothing is invented: the value is not restated
here at all, it is **read back from INT-296's registry**, and a lexicon that
claims a sign-off the registry does not hold is refused.

`pack_signoff` — **HB-C1**, carried and **empty**. All five fields are `null` for
Turkish, exactly as they are on `base.life_threat.yaml`, which states the rule
for them in terms: *"Do not fill these in on behalf of a clinician; the whole
value of the field is that it is a person's name."* No licence number exists
anywhere in this repository and `docs/evidence/INT-244.md` records that
`reviewer_name` is deliberately held in the blocker ledger rather than written
into a sign-off block. The gap is therefore **carried, visible and pinned**:
`SignedGuardLexicon.pack_signoff_missing` names all five fields, and
`test_the_turkish_pack_signoff_is_unfilled_and_is_not_this_issues_to_fill`
fails the build if anybody fills one in passing (perturbation D, below).

**Why the gate is HB-C19's block and not HB-C1's**, which is the one judgement
made here: a guard only ever *restricts* what the product says. Refusing to run
the Turkish arms over Turkish because no physician has counter-signed a regex
would delete invariant 2's enforcement — a refusal that fails **open**, at the
microphone, and the alternative (filling the block) is a forged signature.
Running the Turkish arms over a language they were not written for is the
direction that fails open silently, and that is the one made unrepresentable.
See *What was refused* for the finding this leaves open.

## The six structural assertions

Behaviour is not enough here: a permissive constructor merely unused today is
called tomorrow, and the review that would have caught it reads a diff, not a
test run. Each is asserted against the modules' own `ast` parse.

1. `PolicyGuard.__init__` takes `lexicon`, takes **no** locale-shaped parameter
   (`locale`, `lang`, `language`, `locale_code`, `bcp47`, `tag`), and gives
   `lexicon` no default.
2. Any function in `policy_guard.py` that names a locale must call
   `guard_lexicon_for` — it may not return without turning that locale into a
   lexicon.
3. `policy_guard.py` imports no `re` and calls no `.compile(` — the guard holds
   no vocabulary of its own.
4. No module under `services/`, `packages/` or `apps/` constructs `PolicyGuard`
   directly; every shipped construction goes through the factory.
5. No function in the lexicon modules defaults a `locale`, a `lexicon`, an
   `arms` or a sign-off — INT-296's rule applied to the fields that decide
   whether a guard exists at all.
6. `SignedGuardLexicon` cannot be constructed outside `compile_guard_lexicon`
   (a module-private sentinel), and cannot be re-pointed at another language
   afterwards (`__setattr__` refuses).

## What was refused, and what is now visible that was not

**Refused: filling HB-C1's five fields for the Turkish guard lexicon.** No
licence number exists anywhere in this repository, `base.life_threat.yaml`
forbids filling the block on a clinician's behalf, and INT-244 records that the
physician of record's name is deliberately held in the ledger rather than
written into a sign-off. A forged signature is worse than an open blocker by
exactly the margin this constitution exists to protect.

**Refused: authoring a lexicon for any language, Turkish included.** Growing the
vocabulary is a clinical review under CLAUDE.md's clinical-content rules, and
authoring a second language's is HB-C19's task. Nothing was added and nothing
was tuned; a diff of the arms is empty.

**Refused: minting an issue id or a blocker id** for the finding below. Ids move
under concurrent merges, so it is reported for the coordinator to allocate.

**New finding, reported not filed.** The Turkish PolicyGuard arms are unsigned
under HB-C1's shape — they were authored by engineers, are enforced on every
patient-facing sentence, and no named clinician has read them. That was true
before this change and is unchanged by it; what is new is that it is now
*visible in the type* (`pack_signoff_missing` returns all five fields) and
*pinned by test* instead of being nowhere at all. One sentence would close it —
**which named, licensed clinician signs the Turkish PolicyGuard lexicon, and at
which commit** — and it belongs beside HB-C19 in the clinical section. It is not
a build blocker: the guard runs today exactly as it ran yesterday.

## What was not done, and why

- **No metric gained a `locale` label.** Invariant 13 holds
  `observability/metrics_catalog.yaml` complete against files/08 §4, and INT-296
  recorded that a new `locale`-labelled family would mean inventing a spec id.
  `policyguard_blocks_total` keeps its two labels.
- **`TalkerConfig` gained no `locale` field.** The session builds its guard from
  `DEFAULT_LOCALE` at one visible line, which is honest while the registry holds
  exactly one locale; threading `SessionLocale` through the Talker is INT-297…302's,
  and doing it here would have been a second issue in one PR.
- **Nothing under `packages/protocols/**` was touched**, so no CODEOWNER
  clinical review is triggered and no golden test moved.
