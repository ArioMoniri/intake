# INT-255 — the eleven life-threat delivery annotations, modelled

INT-254 closed four of the twenty-one errors the blueprint life-threat
document produced and pinned the remaining thirteen open, deliberately. This
issue closes those thirteen — **by modelling each field, never by loosening
`extra: forbid` anywhere in the chain**, which would have emptied the residue
list silently and passed.

## Why none of these is a plain optional field

The acceptance's second bullet is the whole issue, so it is worth saying what
"no default" actually means here in a way that can be checked.

`register` was already modelled `RedRegister | None = None` with a validator
that makes it **required on every RED** — the repo's existing shape for
"required with no permitted default". Every field added here follows it: the
type-level default is `None`, never `False` and never a value, and where the
field binds, a validator refuses the absence rather than filling it.
`test_no_delivery_annotation_carries_an_engineer_chosen_default` asserts
`model_fields[field].default is None` for all six rule-level fields, so the
option cannot be quietly taken later.

**`audio` is the interesting one.** files/02 §5.3's register table *fixes* the
audio profile per register — ALERT is "spoken with urgent prosody, alert
sound", CALM is "spoken softly, no alert sound", SILENT is "no audio, ever",
DEFERRED_CLINICIAN is none. So a written `audio` block is a **restatement**
of the register, not an independent choice, and the question "what does an
omitted block mean?" has a blueprint answer rather than an engineer's one.
`REGISTER_AUDIO` transcribes that table, `RedFlagRule.resolved_audio` reads
it, and any disagreement between a written block and its register is refused.

`test_the_register_audio_table_is_the_blueprint_table` re-writes the table
independently in the test and compares, so the implementation cannot drift
into being its own source of truth.

The near-miss controls for it are all one field from the exemplar:

- CALM with `alert_sound: true` — the paediatric airway case acquiring the
  alarm files/04 §8.1 rule 6 forbids;
- CALM with `prosody: urgent` — no alert sound, but still the delivery that
  agitates the child;
- SILENT that speaks — "no audio, ever" is the whole row;
- ALERT quietened — disagreement in the *safe* direction is still
  disagreement, because the register is what the runtime reads.

**`suppress_attention_interrupt` is not derivable from the register**, and
this is the reason it is a separate field rather than folded away: exemplar 3
(CALM) sets it and exemplar 4 (SILENT) does not, so no register-level rule
produces both. The blueprint's own division does: under SILENT and
DEFERRED_CLINICIAN there is no takeover to suppress, so the field is
meaningless; under ALERT and CALM there is one, so a rule that has *declared
alarm to be the harm* (`distress_sensitive: true`) must write the answer. The
negative control is one field away — the same rule with
`distress_sensitive: false` needs nothing, because for an ordinary RED the
interrupt is files/02 §5's own behaviour ("RED is the only interruption") and
not a silence.

**`subject_is_child` had a hole that the cross-check closes.** On its own,
"absent means undeclared" would let a paediatric rule simply omit the field
and thereby pass the ALERT check. `age_band` is already required on
`LifeThreatRule`, so the two together close it: a rule that says it is
paediatric must say its subject is a child, and `RedFlagRule` then refuses
ALERT. `age_band: both` is deliberately not covered — the subject of a rule
that also fires on adults is not necessarily a child.

## The crisis path — HB-C8, and what "fail closed" means here

HUMAN_BLOCKERS rule 2: build the mechanism, wire the gate, make it fail
closed, leave the content empty. Applied to files/04 §4.2's four defects:

- **Defect 2 (abandonment) and defect 3 (the consent hole) are structural**
  and are enforced in the type: `consent_independent: true` requires
  `offline_draft_path: forbidden` (files/04 §8.2
  `crisis_items_have_no_offline_draft_path`) and a non-null
  `abandonment_handler` (files/04 §8.2 `abandonment_handler_is_defined`).
- **Defect 1 (no responder — a named clinic inbox with a stated SLA and a
  documented out-of-hours path) and defect 4 (means restriction and safety
  planning) are policy nobody has written.** So the compiler refuses to emit
  *any* consent-independent rule, with `CRISIS_PATH_POLICY_MISSING`, however
  completely sourced and however completely signed —
  `test_a_signed_sourced_crisis_rule_is_still_refused` proves exactly that
  case. There is no flag, no `dev_only`, no demo mode:
  `test_no_bypass_exists_for_the_crisis_gate` asserts the absence
  structurally rather than trusting that somebody would notice.

**Why no `crisis_escalation_policy.yaml` was created.** The HB-I7 precedent
(a declaration file with zero pools) was considered and rejected here:
inventing a YAML schema for a clinical escalation policy inside
`packages/protocols` would be *designing the missing thing*, which
HUMAN_BLOCKERS rule 2 names as the way a blocker becomes a defect. The two
open defects are a clinic-operations policy and a clinical intervention
protocol, owned by "clinician + owner" on the HB-C8 row — not protocol data.
The refusal cites them by name so that closing HB-C8 has an obvious landing
site.

**No crisis number was populated.** `CRISIS_NUMBERS_TR` transcribes the
files/04 §4.1 table and nothing else; the field carries structured integers
and no text, and the words a patient hears still come from
`action_tr_ref: strings.crisis.*` in docs/legal/strings.yaml under
PolicyGuard. 182 is refused with a message that says why — it is the MHRS
*appointment* line, one digit from 183, which is real. The near-miss set is
`[182, 188, 155, 911, 988]`, with `test_the_permitted_numbers_are_accepted`
as the control that the gate does not simply refuse everything.

Invariant 22 is checked directly:
`test_numbers_are_not_turkish_text_and_never_reach_the_clip_manifest` asserts
that neither the number list nor an action `note` appears in
`protocols.validator._tr_texts`, which is what the clip manifest and the
Turkish-orthography expander read.

## The interlock — what still keeps the document out of a bundle

```
$ uv run protocols compile --pack specialty.kardiyoloji --voice sentetik-ses \
    --life-threat files/protocols/base.life_threat.yaml
compile: refused to emit specialty.kardiyoloji (6 reasons)
  LIFE_THREAT_SET_NOT_SERVED base.life_threat: the life-threat set declares served: false — L0 / awaiting-clinical-review …
  CLINICAL_SIGNOFF_INCOMPLETE base.life_threat: … (HUMAN_BLOCKERS HB-C1): missing reviewer_name, reviewer_licence_no, reviewer_specialty, signed_commit, signed_on …
  PAEDIATRIC_SIGNOFF_MISSING base.life_threat: a rule with age_band paediatric needs a paediatrician's signature separately (HB-C1) …
  DRAFT_RULE_NOT_SERVED rf.paediatric_airway_obstruction: … NO CLINICAL SOURCE YET …
  DRAFT_RULE_NOT_SERVED rf.crisis_disclosure_signposting: … TWO gaps, both blocking …
  UNKNOWN_PACK cluster.medical: specialty.kardiyoloji extends 'cluster.medical', which is not in the registry
```

The document **loads**. The loader no longer raises; the compiler reports
serve interlocks instead, which is the state the acceptance describes.

Read precisely, so that "HB-C1 is the only thing" is not overclaimed:

- The three HB-C1 refusals are the sign-off interlock.
- The two `DRAFT_RULE_NOT_SERVED` refusals are **pre-existing** — files/04
  §8.1 rule 3 working as intended on the two exemplars that carry a
  `source_gap` instead of an invented citation. INT-254 recorded them the
  same way.
- `UNKNOWN_PACK cluster.medical` is about the *target* pack, not the
  life-threat document, and predates this issue.
- **Neither gate added on this issue fires on the blueprint.** Both are
  placed after the draft-rule check, so a rule already refused for its source
  gap is not refused twice — and both are live for the case that matters, a
  rule that is sourced, signed and would otherwise be served.

`test_the_unsigned_blueprint_document_cannot_reach_a_served_bundle` is the
requested proof: the blueprint document is passed to `compile_bundle` and all
three HB-C1 codes come back.

A second lock was added while the shape was in hand:
`test_a_served_life_threat_set_may_not_still_declare_what_is_missing`. Setting
`served: true` on a document that still carries its what-is-missing block is a
one-line edit, and it is *the* one-line edit that would put an unfinished
universal rule set in front of a patient. It now fails at load. The near-miss
control — the same document with the block removed — loads, so the interlock
binds the block and not the flag.

## What remains blocked, and why that is correct rather than incomplete

**HB-C1 — the `clinical_signoff` block.** All six fields are still `null` and
nothing here filled one in. The document now loads and still cannot be
emitted; that is the whole design. The row's ask is unchanged: a physician of
record signs the PR under CODEOWNERS, and a paediatrician signs
`paediatric_reviewer_name` separately, because the airway exemplar is not an
adult rule with a smaller patient in it.

**HB-C8 — the files/04 §4.2 escalation policy.** Two of its four defects are
now enforced in the type; the other two have no artefact and the compiler
refuses the whole path for them. This is Rule 2 satisfied rather than worked
around: the mechanism exists, the gate is wired, it fails closed, and the
content is empty. It is *not* a closure — a bypass, a `dev_only` flag or a
default responder would have been the way to convert this blocker into a
defect, and a test asserts none exists.

**HB-C9 — the ON_SITE companion-separation question.** The field that records
it exists, and an action still carrying one cannot be emitted. The clinician
decision itself (what, if anything, to tell a carer in advance about Tebliğ
MADDE 9(1)) is untouched.

**HB-C3 — the paediatric rule set.** `subject_is_child` and `carry_child` are
modelled and cross-checked; the rules that would use them still do not exist,
and the one exemplar is still `draft_needs_source`.

No new human blocker was raised. The fields were ours to design; the content
each carries was already blocked, and still is.
