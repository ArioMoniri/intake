# INT-255 — the eleven life-threat delivery annotations, modelled

INT-254 closed eight of the twenty-one validation errors the blueprint
life-threat document produced and enumerated the thirteen it left open. This
issue models the rest. **The document now loads.** Loading is not serving,
and what still refuses is named below — all of it a human blocker, none of it
a schema gap.

## The reproduction

```
$ uv run python -c "load_life_threat_set(files/protocols/base.life_threat.yaml)"
```

**Before: 13 validation errors. After: it loads.**

| | before | after |
|---|---|---|
| `rules.2.rule.{subject_is_child,suppress_attention_interrupt,audio}` | 3 | 0 |
| `rules.2.rule.action.ON_SITE.{carry_child,open_question}` | 2 | 0 |
| `rules.3.rule.{audio,consent_independent,offline_draft_path,abandonment_handler}` | 4 | 0 |
| `rules.3.rule.action.{REMOTE.numbers,ON_SITE.note}` | 2 | 0 |

| **total** | **13** | **0** |

## The rule the whole issue turns on

The acceptance states it: *"a default chosen by an engineer here is the
failure invariant 21 names, so each field is modelled with no default or is
not modelled at all"*. That is not a style preference — files/02 §5.3 says a
full-screen red alarm delivered to the parent standing next to a child with
stridor *"produces the deterioration the alert exists to prevent"*. The alert
would be correct, timely, and harmful.

So every field below is one of three things, never a fourth:

1. **Required** — the three legs of `audio`, once the block is written.
2. **Three-valued** — `None` means NOT STATED, distinct from `False`, and a
   validator refuses "not stated" exactly where the blueprint requires a
   decision (`subject_is_child`, `suppress_attention_interrupt`,
   `consent_independent`).
3. **A closed set** — `prosody`, `offline_draft_path`, `abandonment_handler`,
   `numbers`: enums whose members are copied from a blueprint table, so the
   unwritable values (182, an `allowed` offline path) are unwritable in the
   type rather than caught by a lint.

No field was given a plausible default and no clinical content was authored.
The two `draft_needs_source` exemplars are untouched, `evidence: null` in
both, and every Turkish string in the document is byte-identical.

## What the compiler now refuses

**Schema (the document does not load):**

1. An `audio` block missing any of `spoken`, `prosody`, `alert_sound` — a
   partial block is refused, and `prosody: null` must be *written* where
   nothing is spoken.
2. `spoken: true` with no prosody, or `spoken: false` with one.
3. An `audio` block that contradicts its register: `SILENT` or
   `DEFERRED_CLINICIAN` with any audio at all; `CALM` with an alert sound.
4. A `distress_sensitive` rule, a rule whose `subject_is_child`, or a
   `consent_independent` rule in the **ALERT** register.
5. A `distress_sensitive` rule in a register that still takes the screen
   (ALERT/CALM) that does not **state** `suppress_attention_interrupt`; and
   `suppress_attention_interrupt: false` under SILENT/DEFERRED_CLINICIAN,
   which have no interrupt to run.
6. `consent_independent: true` without `offline_draft_path: forbidden`,
   without an `abandonment_handler`, or with `notify_clinic: never`.
7. Any `offline_draft_path` but `forbidden`; any `abandonment_handler` but
   `server_side_on_answer`.
8. Any crisis number outside the closed files/04 §4.1 set — **182 does not
   parse**, nor 988, nor an arbitrary integer.
9. `carry_child: true` on a rule whose `subject_is_child` is not true.
10. Under **ON_SITE**: `show_112: true`; a `112` in `numbers`; a `primary` or
    `secondary` action code naming 112.
11. Under REMOTE: `112` in `numbers` while `show_112` is false — the two
    carriers of one affordance disagreeing.
12. An `age_band: paediatric` rule that does not state `subject_is_child`;
    and `subject_is_child: true` on a rule whose `age_band` does not reach a
    paediatrician's signature (HB-C1).
13. A `goldens_index` naming a rule that does not exist, quoting a golden id
    the rule does not carry, or omitting a rule that carries goldens.
14. `served: true` on a document still carrying a what-is-missing block.

**Compiler refusals (the document loads; the pack is not emitted):**

15. `CRISIS_ESCALATION_POLICY_ABSENT` — a `consent_independent` rule is never
    compiled into a served pack while the files/04 §4.2 escalation policy
    does not exist (HB-C8).
16. `ACTION_OPEN_QUESTION` — a rule whose action branch carries an
    `open_question` is never compiled into a served pack (HB-C9).
17. `ON_SITE_OFFERS_112`, re-checked on the **compiled** action for all three
    carriers, so a rule built by `model_construct` (an emitter, a future op)
    cannot route round the schema.

## ON_SITE: absence, not de-emphasis

files/02 §5.3: *"The `112'yi ara` affordance is not rendered under `ON_SITE`
at all. Not de-emphasised, not below the fold — absent."*

`numbers` is what made this urgent. Before it, the affordance had one carrier
(`show_112`) and one gate. With a number list, an author can turn the button
off and leave `112` in the list — which is precisely de-emphasis, and would
have passed. So the ON_SITE branch refuses the number **regardless of the
flag**, and the same pass closes the third carrier: an action **code** naming
112.

INT-254 recorded that third one as open, reasoning that closing it needed an
enumerated action-code set which no blueprint writes down. That reasoning was
one step too pessimistic: it does not need the set, only a refusal of the one
token invariant 21 forbids. `CALL_112` under ON_SITE is now a validation
error. Nothing in the corpus used it there — checked before the refusal was
added — so no pack, fixture or golden changed.

**The test that proves absence** is
`test_the_on_site_action_has_no_112_carrier_of_any_kind`. It does not assert
a flag. It serialises the whole ON_SITE branch and asserts that **no field of
it carries `112` in any form** — not the flag, not the number list, not an
action code, not a Turkish string — while the same branch still carries a
non-112 action code and the 183 social-services number, so the assertion is
about the affordance and not about ON_SITE being empty.

## The near-miss negatives

A golden that only proves the happy path is the failure mode this repo has
already hit, so every check above has a control that must go on passing:

| the check | its near miss |
|---|---|
| audio/register consistency | `test_the_alert_register_still_carries_an_alert_sound` — ALERT is the row of the same table that *does* alarm |
| the audio block at all | `test_a_rule_without_an_audio_block_still_validates` — exemplars 1 and 2 carry none |
| `suppress_attention_interrupt` required | `test_the_interrupt_decision_may_be_written_either_way` — the DSL requires the decision **stated**, not a particular value; picking `true` for every rule is the same engineering default the field exists to prevent |
| … scoped to distress-sensitive | `test_a_rule_that_is_not_distress_sensitive_need_not_state_the_interrupt` |
| ALERT refusals | `test_an_adult_rule_that_is_not_distress_sensitive_may_be_alert` — ALERT is the *default* for adults where alarm aids action |
| `carry_child` | `test_carry_child_is_accepted_when_the_subject_is_a_child` |
| the crisis legs | `test_the_crisis_shape_validates_when_every_leg_is_written` — exemplar 4's own shape |
| the closed number set | `test_the_sourced_crisis_numbers_are_admitted[112/183/191]` — a ban, not a set, would pass every 182 test |
| ON_SITE 112 | `test_on_site_still_admits_a_non_112_code_and_a_non_112_number` — 183 is unaffected by the patient standing in the building |
| the ON_SITE compiler refusals | `test_an_on_site_action_with_no_112_carrier_raises_no_such_refusal` |
| the crisis compile gate | `test_a_rule_without_the_crisis_path_is_not_refused_for_it` — the signed fixture is servable and must stay so |
| `goldens_index` | `test_a_document_without_a_goldens_index_is_still_loadable` — the committed compiler fixture has none |
| the pending block | `test_a_served_set_with_no_pending_block_is_not_refused_for_that` — removing the block lifts the refusal, so the check is about the block and not about `served` |
| `subject_is_child` required | `test_an_adult_rule_need_not_state_subject_is_child` |

**And the control that makes the empty residue mean anything.** The
acceptance is explicit that the list may shrink *"only as fields are
modelled — never by loosening `extra: forbid` anywhere in the chain, which
would empty it silently and pass"*.
`test_extra_forbid_still_binds_every_level_of_the_document` injects one
unknown key at each of eight levels — document, rule, REMOTE action, UNKNOWN
branch, evidence block, golden case, the new `audio` block, a `goldens_index`
row — and asserts each is still refused by name. Without it, `assert
INT_254_RESIDUE == ()` is satisfied by exactly the change it is meant to
catch.

`input_value` repr contains the payload — so eight checks were green before
any of them could work. Every match was rewritten onto the validator's own
sentence (`"spoken audio carries a prosody"`, `"Input should be 112, 183 or
191"`, `"number list carries no 112"`) and the run above is the corrected
one: 58 failures, one per new case, none passing by accident.

- `test_the_blueprint_life_threat_document_loads` failed on the real

### The one existing test that changed, and why

`test_refuses_a_paediatric_rule_without_a_paediatrician_signature` builds a
synthetic `age_band: paediatric` rule that carried `register: ALERT` and no
`subject_is_child`. Both are now refused, and the fixture states
`subject_is_child: true` with `register: CALM`. That is the new rule working
on the first paediatric rule it met, not a test bent to fit: a synthetic
paediatric rule in the ALERT register is the exact shape files/02 §5.3 exists
to prevent.

`tests/safety/triage_goldens_corpus.py` grew its two projection lists. It
projects the document onto a fixed set of field names, so a field the DSL
gains and the projection does not is silently dropped — the safety suite
would evaluate the crisis rule without its crisis path and the airway rule
without its suppressed interrupt. The new test above pins the two readings
equal so this cannot drift again.

## Clinical content: none authored

Every one of the eleven annotations is a **mechanism**. The content each
carries is blocked, and on whom:

| annotation | content still missing | named human |
|---|---|---|
| `subject_is_child`, `carry_child` | the paediatric rule set — fever under 3 months, lethargy/poor feeding, breathing difficulty in parent-reportable form, non-blanching rash, dehydration, ingestion, and the age-band boundaries themselves | **a paediatrician** (HB-C3) |
| `audio`, `suppress_attention_interrupt` | which registers and interrupt decisions the ~30 unwritten rules take; and the airway rule's own trigger set is still `draft_needs_source` | **physician of record** for the set (HB-C1); the paediatrician for this rule (HB-C3) |
| `consent_independent`, `offline_draft_path`, `abandonment_handler` | the files/04 §4.2 escalation policy — responder, abandonment handler, consent-independent path, means restriction, safety planning | **clinician + owner** (HB-C8) |
| `numbers` | nothing outside 112 is authorised for this rule, and the crisis lexicon behind its gate does not exist and must be clinician-authored | **clinician** (HB-C8; files/04 §4.1) |
| `open_question` | what, if anything, the proxy and paediatric flows say in advance about companion separation at the kırmızı-alan door (Tebliğ MADDE 9(1)) | **clinician / ClinicalAuthor** (HB-C9) |
| `note`, `goldens_index`, the pending block | nothing clinical — they carry what the document already says | — |

The whole set additionally cannot leave L0 until the `clinical_signoff` block
is signed by a **physician of record**, with a **paediatrician separately**
for the airway rule (HB-C1, INT-043). No new human blocker was raised: the
fields were ours to design and the content was already blocked.

The literal `TODO: <what> requires clinical sign-off` form was not needed on
this issue. No structurally-required clinical value was reached — the fields
added are delivery mechanism, and the four places the document already uses
that form are untouched.

## What this issue deliberately did NOT do

- **It did not enumerate `ActionCode`.** INT-254's residual is closed for the
  112 case only, by refusing one token under one location. The open
  SCREAMING_SNAKE set stands, because no blueprint writes it down.
- **It did not touch `base.life_threat`'s clinical content**, its two
  `draft_needs_source` rules, or the `clinical_signoff` block.
- **It did not add a bypass** to the HB-C8 gate. There is no flag, no dev
  mode, no per-tenant escape: when the escalation policy exists, a human
  edits `_crisis_path_refusals`. HUMAN_BLOCKERS rule 2.
- **It did not force `suppress_attention_interrupt: true`** on
  distress-sensitive rules. Whether a given rule suppresses the interrupt is
  clinical; the DSL requires the decision to be written.

## Two landings merged in, and why neither bites

`origin/main` moved while this issue was interrupted, and two of its landings
are adjacent enough to be worth ruling out rather than assuming:

- **INT-081 (the IntakeEngine FSM).** Its evidence records that the files/13
  §9.5 `GuardExpr` function whitelist (`age_years`, `any`, `days_since`,
  `mode`) is deliberately **not** implemented and that a gate reaching for it
  is refused at build. None of the eleven annotations is a gate or an
  expression — they are declarative fields on `RedFlagRule`, `LocationAction`
  and `LifeThreatSet`, and no validator added here evaluates a predicate. The
  one place the airway exemplar looks like it calls a function,
  `subject.age_years < 18`, is a **dotted slot reference** in the document's
  own `gate:` (→ `when:`), parsed by the triage `when` grammar that INT-254
  unified with `tense_anchor` — not a GuardExpr call. The same evidence's
  `retire_if`/`skip_if` finding is likewise untouched: `skip_if` lives on
  `Slot`, and nothing here reads it.
- **INT-258 (overlay composition), which found that tightening never worked.**
  `protocols.compile.overlay` mentions none of the eleven fields, and it
  cannot: `base.life_threat` is a **sibling set outside the inheritance
  chain** (invariant 7, files/12 §1), so no overlay reaches these rules —
  `RefusalCode.LIFE_THREAT_SET_EXTENDED` already refuses the attempt. The
  annotations are carried on the rule, not composed onto it.

`tests/engine` (52 new FSM cases) and the whole `tests/protocols` +
`tests/safety` trees pass together on the merged tree.
