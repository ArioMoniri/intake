# Evidence — INT-375 · The protocol compiler refuses a gate that reads a later slot (files/13 §9.5)

Branch: `int-375-compiler-ask-order`, cut from `origin/main` at `d03df3a3` and fast-forwarded to
`4bca2ad5` before the backlog row was added. GitHub #609. Sec-Row: `protocol-registry`.

Found by the PR #582 near-twin sweep (docs/evidence/verification/reorder-op-582.md §A-13 on that
branch): files/13 §9.5 lists stratified acyclicity among the five CI-blocking compiler checks, and
nothing implemented it.

## 1. The defect

files/13 §9.5: "a gate on step *S* may reference only slots owned by steps of strictly lower
`(priority, order)`". The engine sorts its plan by `(priority_class, order, id)` (§9.1), re-reads
every gate on every turn (§9.2), and an unasked slot reads Unknown, which does not open a gate.
So a gate that reads a later slot does not drop its question. The engine passes the question over
at its own place and asks it once the later slot is answered, which is out of the frozen plan
order. PR #582 reproduced this with a real `IntakeEngine` on the kadın hastalıkları ve doğum chain.
There, four obstetric alarm questions were passed over at their plan positions and asked only
after `gebelik_durumu`, the slot their gates read, had been answered.

The only guards were the specialty generator's `reorder` op and a review-chain test, both on the
unmerged PR #582. A served pack, an overlay, a hospital `reorder` or a `must_ask` tightening could
put a forward gate back, and nothing would refuse it.

## 2. The rule

`packages/protocols/src/protocols/gates.py` (INT-355's module) gains three pure functions:

- `ask_ranks(slots)` gives every `(section_id, key, slot)` in merged order the rank
  `(MUST_ASK_CLASS=5 if must_ask else DETAIL_CLASS=7, order)`. This is the engine's sort key without
  the id tiebreak, which never decides because `order` is unique. `order` counts across sections,
  as `build_plan` does.
- `gates_reading_later_slots(slots)` returns one `LaterSlotRead` for every `ask_if`/`skip_if` read
  of a slot whose rank is not strictly lower than the gated slot's rank. A gate that reads its own
  slot is caught. Two spellings of one slot count as one read. The function does not judge a name
  that does not resolve (INT-355's `GATE_REF_*`) or a gate outside the grammar (the emitter's
  `GATE_NOT_PROJECTABLE`).
- `LaterSlotRead.describe()` returns ids and ranks only. It never includes the gate text or a
  question.

`packages/protocols/src/protocols/compile/resolve.py` runs the check inside `resolve_protocol`.
That is the resolver `protocols compile`, `compile_bundle` and every served bundle go through.
The check runs after the chain is merged and every op is applied, so a `reorder` op or a
`set_attr must_ask` counts. The refusal is `RefusalCode.GATE_READS_LATER_SLOT`:

- the subject is `<pack>:<section>.<slot>`, where `<pack>` is the pack whose declaration of the
  gated slot the merge kept (`_merge_chain` replaces a re-declared slot whole) or whose `add_slot`
  op added it;
- the message names the field, the slot the gate reads and both ranks, and cites files/13 §9.5.

If any op failed to apply, or two ops conflict, the check does not run. The order left behind is
not the one the author wrote, and the compile already refuses for the op.

The check only refuses. It never reorders, never changes `must_ask`, and never reads a red-flag
`when`, `tense_anchor` or `base.life_threat` (invariants 1 and 7). The validator is unchanged, so
chain validation still reports 0 findings.

## 5. Tests and their near-miss controls

- **Forward gate refused.** A specialty slot gated on a slot the same section declares after it
  is refused. The subject is `specialty.sentetik_sira:sorular.sure`, the message names
  `sorular.yeni`, and the gate text does not appear.
- **The same gate after a `reorder` op is admitted** and compiles. The Questionnaire carries the
  op's order.
- **Gate on a base slot is admitted** and compiles.
- **Near-miss pair.** On the pure check and again through the resolver, a gate reading the
  immediately preceding slot passes. With the gate slot moved one position later, directly after
  its reader, it is refused.
- **The PR #582 shape.** A child re-declares a parent slot and gates it on a slot the child adds.
  The re-declared slot keeps the parent's position, so the gate is refused, and the refusal names
  the child.
- **Attribution.** A gate the parent wrote is attributed to the parent. A gate on a slot added by
  a cluster's `add_slot` op is attributed to the cluster in a three-pack chain, not to the pack
  being compiled.
- **Priority class.** A must-ask reader gated on an earlier DETAIL slot is found. The control, a
  DETAIL reader gated on a later must-ask slot, passes. A `set_attr must_ask` tightening on a gated
  slot whose gate slot is DETAIL is refused. Its control, tightening the gate slot as well,
  compiles.
- `skip_if`, a gate reading itself, a gate slot in a later section, several later reads in one
  gate (each reported once, sorted), and names left to INT-355 or the emitter.
- **An order the ops did not produce is not judged.** A non-permutation `reorder` is refused only
  as `VALIDATION_FINDING`.
- **Engine.** `ask_ranks` equals `(int(step.priority), step.order)` for every step `build_plan`
  makes. A document the check passes is asked in plan order through a real `IntakeEngine`. A
  document it refuses is asked out of order: the gated question is deferred, not dropped. A
  must-ask step gated on a DETAIL slot is asked after it.

## 6. Every pack on main

`tests/protocols/test_gate_ask_order_packs.py` resolves each pack with `resolve_protocol` and reads
its `GATE_READS_LATER_SLOT` refusals. Every pack is L0 and refuses anyway, so a spy on the
resolver's call to the check asserts that the check ran for every pack. An early exit, or ops
that did not apply, would otherwise pass vacuously.

report-only. Any other forward gate, in any candidate, fails, and the six cannot grow. The pin is
a subset rather than an equality so that main stays green whichever of #582 and this PR merges
first. #582's own `test_no_gate_reads_a_slot_the_chain_asks_after_it` then enforces emptiness,

  termination, clip and delivery coverage) are not part of this issue.
