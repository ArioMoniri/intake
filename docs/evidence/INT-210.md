## 1. What this issue is, and what it deliberately is not

The title names twenty-one documents: five aydınlatma metinleri, eleven açık rıza texts,
a gizlilik politikası, kullanım koşulları, a KVKK başvuru formu and a çerez politikası —
plus, because invariant 18's second sentence puts them in the same tree under the same
rule, the files/06 §7 fixed strings.

Every one of them is human legal work. CLAUDE.md's rule for exactly this situation is not
"write a draft and mark it provisional":

> An open blocker is not permission to build around it: **build the mechanism, wire the
> gate, make it fail closed, leave the content empty.**

So this PR ships the binding, the summary contract, the sign-off gate and the acceptance
record, with `docs/legal/documents.yaml` holding `documents: []`. Every id in the required
set refuses today. That empty-but-gated state is the deliverable, and `docs/legal/COUNSEL_BRIEF.md`
§5 already argued why the alternative is worse: a plausible Turkish draft would load, would
hash, would bind to real acceptances, and once merged would be indistinguishable from
counsel's own words. Invariant 17 forbids it, and its sole carve-out is reserved for a
clinical value in a `draft_needs_source` rule — which a consent text is not.

## 3. What was built

### 3.1 `intake_platform.legal.documents` — the closed required set

Twenty-one rows, and **two of the three lists are not this module's to own**:

| kind | rows | where the list comes from |
|---|---|---|
| `AYDINLATMA` | 5 | `consent.registry.CHANNELS` — files/06 §1's KVKK-10 + AYD-2018 row names app, kiosk, clinician, admin, web |
| `ACIK_RIZA` | 11 | `consent.registry.purpose_ids()`, path from `consent.texts.text_filename()` |
| `GIZLILIK`, `KULLANIM_KOSULLARI`, `KVKK_BASVURU`, `CEREZ` | 4 | the issue title |
| `FIXED_STRINGS` | 1 | files/06 §7 + invariant 18's second sentence |

Deriving the first two rather than restating them is the point: a purpose added to
files/06 §2 gains a required legal document without anyone remembering to add it here, and
an açık rıza text can never be signed in this index while absent from the loader the
consent guard actually reads — the two bind the same file.

`lane:acoustic` has **no** row and must never be given one. files/06 §2.4 makes it an
investigational-device ICF under TCKAY with its own required content list and its own
approval chain; it is not a `{version, text_hash}`. The consent registry rejects it by name
for the same reason, and a test pins the absence.

### 3.2 `intake_platform.legal.document_index` — the loader, and the four refusals

`docs/legal/documents.yaml` is the version of the set. One row per document:
`{id, version, sha256, summary_sha256, counsel: {signed_by, signed_on, evidence}}`.

The refusal order is the design, not an implementation detail:

1. **no index, or no row for this id** → `LegalDocumentMissingError`. The set is declared
   before it is authored, so an absent document is an absence the code already knows the
   shape of.
2. **no counsel sign-off** → `LegalDocumentUnsignedError`, checked **before the bytes are
   read**. A document nobody signed does not become servable by having a correct hash. A
   block missing any of the three facts is not partially signed; it is unsigned. A block
   whose `evidence` points anywhere but `docs/evidence/INT-210.md` refuses by name, because
   the acceptance says the sign-off is *recorded in the evidence file*.
3. **bytes that do not hash to the signed value** → `LegalDocumentHashMismatchError`, for
   the document and for its plain-language summary alike.
4. **a performance claim** → `LegalDocumentInvalidError`. Invariant 20's CI gate scans
   `docs/legal` between merges; this refuses at render, so a claim cannot reach a patient
   in the window between the two. The pattern groups are read from
   `legal.claims.SCANNED_TREES`, not copied — `claims.py` exists precisely so a second copy
   cannot turn the gate into a habit.

Nothing is cached. Every lookup re-reads the file, which is the "rendered in-app from
source" clause made structural rather than promised: a document edited under a live process
stops rendering rather than serving bytes nobody approved. `render()` is `entry()` — there
is deliberately no second path that could serve a cached or unsigned copy.

### 3.3 `record_acceptance` — the acceptance evidence

Written into the invariant-4 hash-chained audit log:

```
action        legal_document.accepted
resource_ref  legal_document:<id>@<version>/sha256:<64 hex>
scope ref     basis:KVKK-10          (an aydınlatma discharges an obligation; it is not
                                      a patient consent scope — the shape ADMIN_BASIS_REF
                                      uses for KVKK-12)
```

Ids and digests only, never a word of the copy (invariant 6), and a test asserts no fixture
string reaches any audit field. The channel must be one of the five; a sixth would claim an
aydınlatma surface that does not exist.

The refusal is structural rather than a check at the call site: `record_acceptance` takes a
`LegalDocument`, and a `LegalDocument` can only come out of `entry()`. An unsigned or moved
document therefore has **no acceptance path at all**, rather than one somebody could forget
to guard.

**No migration and no new table.** The açık rıza half already stores its acceptance in
`consents.{version, text_hash}` (INT-038, migration `0002_int038_consent_binding`); the rest
rides the audit chain, which is the store invariant 4 already names. Nothing here persists a
new category of personal data, so nothing here needed a new inventory annotation.

## 5. The four near-miss negative controls

A gate is only proven by the case that nearly passes. Each of these is a different way to
fake this one.

| control | fixture | result |
|---|---|---|
| **the bytes moved** | a signed row whose `sha256` differs from the file by one trailing space | `LegalDocumentHashMismatchError` |
| **nobody signed it** | file present, hash correct, summary bound, `counsel:` absent | `LegalDocumentUnsignedError` |
| **a fixed string moved by one glyph** | `strings.yaml` signed, then `basligi` → `baslığı` | `LegalDocumentHashMismatchError` |
| **the positive control** | well-formed, summarised, signed | **served** — `available() == ("gizlilik",)` |

The fourth is not decoration. A gate that refuses everything proves as little as one that
refuses nothing, and today's committed tree refuses everything for a legitimate reason;
without the positive control this suite could not tell the two apart.

Alongside them: a summary whose hash moved, a document with no summary at all, a partial
sign-off in each of its four shapes, a sign-off pointing at the wrong file, a duplicate
index row, an index row for a document outside the closed set, an index with no version, an
empty body, a non-UTF-8 body, and a performance claim in the document and in the summary.

## 9. What was deliberately left empty, and what was deliberately not built

**Left empty — all of it content, none of it mechanism:**

- every one of the twenty-one documents, and every plain-language summary;
- `docs/legal/documents.yaml`'s `documents:` list, and therefore every hash and every version;
- every `counsel:` block;
- §8 of this file above the ask.

**Not built, with the reason:**

- **An HTTP route for the ten non-consent documents.** Every marker in
  `intake_api.consent_guard` is bound to a path prefix, so a `/v1/legal` route would require
  widening the INT-038 route-table scan — a change to a security marker, made for a surface
  that would serve an empty list for as long as the set is unsigned. The render primitive is
  built, tested and transport-agnostic; wiring it is mechanical once there is a document to
  serve. Recorded here rather than done silently.
- **A mobile screen.** Same reason, one layer up. The açık rıza texts already render through
  `ConsentList.tsx`; the other ten have nothing to render.
- **A migration or a new table.** Acceptance evidence rides the existing hash-chained audit
  log; the açık rıza half already has its columns from INT-038. No new category of personal
  data is persisted, so CLAUDE.md's stop-and-ask on that point is not engaged.
- **A PolicyGuard pass over the summaries.** PolicyGuard lives in the protocols /
  voice-runtime lane and its rules (one question per turn, no diagnosis language) are written
  for conversational turns, not for statutory copy whose wording is prescribed. Invariant 2
  still governs the *content* of the summaries, and it is stated as a constraint on the
  drafter in clause 4 above rather than enforced by a gate this issue would have had to
  invent.
- **Any resolution of the two defects `COUNSEL_BRIEF.md` §2.9 records** — `satisfaction`'s
  basis disagreeing between the registry and the storage annotations, and its retention
  disagreeing between the column annotation and the retention class. Both are real, both are
  outside this issue's acceptance, and neither was papered over here.
