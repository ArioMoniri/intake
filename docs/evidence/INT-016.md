## What the tests pin

- `entry_hash` = SHA-256 over canonical JSON (sorted keys, no whitespace,
  ASCII) of the entry minus `entry_hash`; genesis `prev_hash` is 64 zeros. The
  test re-implements the hash independently so the wire format is pinned, not
  the module's own helper.
- Editing a middle entry → verifier names the exact `seq` (flip row 3 of 5 →
  `first_bad_seq == 3`). Editing an entry *and* recomputing its hash moves the
  break to the next link (`seq 4`), never hides it.
- Truncate-and-re-append fork: the forged store verifies as internally
  consistent (that is the attack) and the honest writer's **running head**
  still catches it; plain rollback likewise.
- `export_worm()` is a self-verifying JSON-lines bundle (entries + one head
  record); `verify_worm_export()` checks it with no store — and rejects an
  edited line, a dropped line (named by `seq`), a chopped-off head record,
  wrong-typed head fields, a forged entry count, and non-JSON garbage.
- Invariant 6 at the boundary: the field set is closed (frozen dataclass) and
  every caller value must be id-shaped; free text is refused with the field
  named and the value never echoed into the error.
- Edge cases: empty chain, single entry, writer restart resuming from the
  stored tail, naive (non-UTC-aware) clocks refused.
- `run_daily_verifier(store)` is pure and already accepts an
  `expected_head` so the integration slice adds transport, not logic.
