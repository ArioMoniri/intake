## What the tests pin

- `entry_hash` = SHA-256 over canonical JSON (sorted keys, no whitespace,
  ASCII) of the entry minus `entry_hash`; genesis `prev_hash` is 64 zeros. The
  test re-implements the hash independently so the wire format is pinned, not
  the module's own helper.
- Editing a middle entry → verifier names the exact `seq` (flip row 3 of 5 →
  `first_bad_seq == 3`). Editing an entry *and* recomputing its hash moves the
  break to the next link (`seq 4`), never hides it.
- Truncate-and-re-append fork: the forged store verifies as internally
  consistent (that is the attack) and the honest writer's **running head**
  still catches it; plain rollback likewise.
- `export_worm()` is a self-verifying JSON-lines bundle (entries + one head
  record); `verify_worm_export()` checks it with no store — and rejects an
  edited line, a dropped line (named by `seq`), a chopped-off head record,
  wrong-typed head fields, a forged entry count, and non-JSON garbage.
- Invariant 6 at the boundary: the field set is closed (frozen dataclass) and
  every caller value must be id-shaped; free text is refused with the field
  named and the value never echoed into the error.
- Edge cases: empty chain, single entry, writer restart resuming from the
  stored tail, naive (non-UTC-aware) clocks refused.
- `run_daily_verifier(store)` is pure and already accepts an
  `expected_head` so the integration slice adds transport, not logic.

## The five tamper cases, and what each one actually costs the attacker

| # | attack | detected? | how | test |
|---|---|---|---|---|
| 1 | mutate one entry | **yes, by position** | recomputed `entry_hash` ≠ stored | `test_case1_mutated_entry_is_named_by_its_exact_seq` (`first_bad_seq == 3`) |
| 2 | delete one middle entry | **yes, by position** | `seq` at position *n* ≠ *n+1* | `test_case2_deleted_middle_entry_is_named_by_the_missing_seq` (`== 3`) |
| 3 | swap two adjacent entries | **yes, by position** | same `seq` check, at the first displaced row | `test_case3_reordered_pair_is_named_by_the_first_out_of_place_seq` (`== 2`) |
| 4 | truncate the tail | **yes — but no position** | anchored head ≠ recomputed head | `test_case4_truncated_tail_is_caught_by_the_anchor_and_names_no_position` |
| 5 | edit a row **and re-forge the chain forward** | **only with an anchor** | anchored head ≠ recomputed head | `test_case5_full_reforge_is_invisible_locally_and_caught_only_by_the_anchor` |

Rows 4 and 5 are the honest part and the reason the job is shaped the way it
is. After a truncation or a full re-forge the store is a **flawless chain** —
that is the whole attack — so no entry can be blamed and a self-contained walk
returns green. `test_case5` asserts that green explicitly before asserting the
anchored run catches it, and `test_a_full_reforge_defeats_the_self_contained_walk_by_design`
does the same at the `verify_entries` level. A design that claimed to detect
either without an external witness would be claiming something impossible.

Consequence, and it is the load-bearing decision in this slice: **a run with no
anchor is a refusal, not a pass.** `VerifierOutcome.ANCHOR_MISSING`,
`sec_audit_chain_ok` **0**, exit **3**
(`test_no_anchor_is_a_refusal_not_a_pass`). A malformed anchor is refused
rather than compared, because an anchor that can never match is
indistinguishable from a chain that is always broken.

Two further properties worth naming: a **broken chain is never copied to WORM**
(`test_case1...`, and the integration `test_a_broken_chain_writes_nothing...`)
— object lock means a forged history archived once could not be withdrawn for
ten years; and the report itself carries no entry content
(`test_the_report_carries_no_entry_content`, `test_cli_prints_no_entry_content`
— invariant 6 applies to the verifier's own output).

## What enforces WORM, honestly

**In dev and CI: MinIO's S3 Object Lock in COMPLIANCE mode**, applied by the
server, not by our code. `DocumentStore.ensure_buckets` creates the audit
bucket with `object_lock=True` and a default COMPLIANCE retention of 3650 days
(files/10 §3: object lock, 10-year retention for hospital tenants), and a
pre-existing bucket without the lock is a typed `WormMisconfiguredError` —
MinIO enables object lock only at bucket creation, so there is no honest
in-place upgrade. The guarantee is asserted **from the server**: deleting a
locked object version before retention expiry raises `S3Error`, a versionless
delete leaves only a delete marker, and an overwrite stacks a new version while
the original bytes stay readable (`test_document_store_integration.py`,
`test_audit_verifier_integration.py`).

**In production: nothing, because nothing is configured.** No production object
store exists in this repo, and files/08 §6 records the choice as open —
MinIO's newest Docker Hub tag is ~12 months stale and **Garage, the named
fallback, implements no S3 Object Lock at all**, which would void the guarantee
*silently*: the bucket would accept every write and refuse no deletion. files/10
§3 (d) says that decision closes **before P1**. It is an open human decision,
now recorded as **HB-I9**; this slice does not assume an answer.

## The patient-visible access-log view model

`intake_platform/access_log.py`. A projection from audit entries, not a route
and not copy: routes belong to INT-139 / INT-150 / INT-037, and Turkish strings
belong to the app where `tr` keys are the source of truth (invariant 5), so
rows carry a closed `AccessCategory` enum rather than a rendered sentence.

Four properties, each with a test:

1. **Scoped by construction** — only entries naming one of `patient_refs`; an
   empty scope yields an empty log, so the failure direction is "shows
   nothing", never "shows someone else's".
2. **Role, never identity** (files/10 §3: *actor role (not name)*) — the chain
   records an actor **id**, so the resolver is an argument. `DEFAULT_ROLE_OF`
   maps only the `svc-` service convention and returns `UNKNOWN` for
   everything else; the raw actor id never reaches a row.
3. **Nothing silently dropped** — every in-scope entry becomes exactly one row;
   an unrecognised action becomes `OTHER`, never an omission. An action
   containing a `share` segment classifies as `RECORD_SHARED` even if nobody
   mapped it, because understating a share is the one error that matters here.
4. **No PHI** — the row field set is closed and pinned by a test; near-miss
   names (`api.noteworthy.read`, `API.NOTE.READ`) fall to `OTHER` rather than
   being absorbed by a sloppy prefix rule.

All 39 audit action names constructed under `packages/` and `services/` today
are pinned to a category (a snapshot in the test, deliberately not a repo scan
— a scan across ~80 concurrent branches is a merge-conflict machine, and the
property that matters is that a *rename* is caught).

## Invariant and contract checks

- **inv. 4** — the log is the evidence the invariant holds; the verifier is what
  makes it evidence rather than a claim.
- **inv. 6** — the audit entry field set stays closed; the verifier's report and
  the access-log row both narrow it and add no carrier; two tests assert the
  printed and serialised forms are free of entry content.
- **inv. 13** — `sec_audit_chain_ok` promoted `planned` → live in
  `observability/metrics_catalog.yaml`; `tests/observability` green in both
  directions (a live entry must be observably emitted).
- **inv. 15** — no new service, so no new `/healthz` + `docs/slo/<service>.yaml`
  + probe obligation. The verifier is a job in `intake_platform`, following the
  `backup/` and `siem/` precedent.
- **inv. 17** — no TODO/FIXME, no skipped or xfail test, no empty `pass` body,
  no commented-out code; mocks live only in tests.
- `make audit-verify` is deliberately **not** part of `make check`: it needs a
  live chain and an external anchor, and a gate that passes because neither
  exists is precisely the verifier this issue exists to avoid.
