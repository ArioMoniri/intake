The orchestrator's brief widened the acceptance; each item is met:
the push is a non-blocking signal into the Talker's own loop and no Backend
coroutine calls into the Talker (structural tests); each RED is delivered
exactly once whichever route sees it first (deduped by work id with the

## The defect, as it was measured

On `1ba358ff` (INT-521 head) with only the two new test files added, the
mid-silence case run to its end: the onset answer is given, Layer B evaluates
1.5 s later and says RED, three seconds pass with no turn, then the patient's
next turn. Printed by a scratch driver over the suite's own helpers:

```
residency_tr  sink 5 ms          delivered_between_turns=False script_started_after_evaluation_ms=3054.9999999999995 triggers=1 next_turn_raised=['e2e_budget', 'stop_budget']
residency_tr  slow sink 2000 ms  delivered_between_turns=False script_started_after_evaluation_ms=5050.0 triggers=1 next_turn_raised=['e2e_budget', 'stop_budget']
typed         sink 5 ms          delivered_between_turns=False script_started_after_evaluation_ms=3050.0 triggers=1 next_turn_raised=['e2e_budget', 'stop_budget']
```

Nothing reached the device until the patient spoke again. The next turn
delivered it 3 s late and raised `RedPathViolation` with both budgets, measured
from the evaluation as INT-521 built it. With a sink whose cancel takes 2 s
(a live SFU tearing the room down over HTTP), the trigger waited for the cancel
too: 5 s.

## The design

**The push.** `talker/red_push.py` (new):

- `RedPush` is Layer B's half: a Protocol with one member, `push(result)`,
  which is not awaitable. Layer B can post a RED and do nothing else: it
  cannot call into the Talker, hand it a coroutine, or wait on it.
- `RedMailbox` implements it. `push` refuses anything that is not
  `priority: preempt` over a `RulesTriageResult` at `RED` (`PreemptRefused`),
  appends under a `threading.Lock` and asks the Talker's loop to wake through
  `call_soon_threadsafe`. Layer B's pump may run on a worker thread; the post
  touches nothing the loop owns. A loop that has closed keeps the RED posted for
  the next loop that takes. `take()` parks on an `asyncio.Event` bound to the
  running loop (rebound when the loop changes) and returns every posted RED;
  the event is cleared only while nothing is posted, under the post's lock, so
  a stale wake-up cannot spin and a fresh one cannot be lost.

**Layer B** (`clinical_agent/work_queue.py`). `BackendAgent.red_push`. In
`_finish`, a `preempt` result that passed the preempt gate is settled, the
queue sealed where its register stops the intake, and then posted. A post that
raises is logged with ids and the error class only and costs the RED nothing:
it is settled and the next turn's drain delivers it.

**The Talker** (`talker/session.py`). `TalkerSession.red_mailbox`, and:

- `watch_reds()`: the Talker's own between-turn loop. It awaits
  `mailbox.take()` and, for each RED, the same provenance gate
  (`accept_result` → `authorise_preempt`) and the same path
  (`deliver_preempt`) a drained RED takes. It refuses to start without both
  the mailbox and the RED path (`RedPathNotWired`). It has no caller to raise
  to, so a provenance refusal and a `RedPathViolation` are logged by work id
  (and the violation counted by the path) and the watch serves the next RED. A
  refused RED is not marked seen, so the turn's drain meets it and raises.
- `ensure_red_watch()`: starts the watch on the running loop once per loop.
  `take_turn` calls it on entry, so every session that has taken a turn is
  watching; a worker can call it at session start. `stop_red_watch()` cancels
  it, and `VoiceSessionRouter.end()` — the runtime's one session-end hook —
  calls it, so an ended session leaves no task parked on its mailbox (a
  pending task collected with its session is a "Task was destroyed but it is
  pending" error log).
- Exactly once: `_reds_seen` holds the work ids handed to the path by either
  route. A RED is settled once and seen twice (pushed and drained); the second
  sighting is dropped. Same-route repeats cannot occur within a session (the
  queue dedupes content-addressed submissions), and `RedPreemption`'s own replay
  rules (INT-453) are unchanged for a direct `trigger`.
- The stop latch moved before the path's first await: `deliver_preempt` sets
  `red_stopped` for a stopping register before it awaits the cancel and the
  trigger, so a turn that resumes while they are in flight asks nothing.
- A turn in flight: after Layer B's speech and after the step's question,
  `take_turn` checks the latch. A RED that cut either returns
  `INTAKE_STOPPED`; a question cut mid-playback is reported as emitted and is
  not recorded as asked (the ask ledger is not told).

**The bounded stop** (`talker/red_path.py`; INT-520 item 1, INT-534's last
line). The cancel runs as its own task and the path waits for it only until
`STOP_BUDGET_MS` after the evaluation, on the session clock (a fake clock
measures the same bound production enforces). Past that the trigger goes, the
outcome carries `stop_overran: true` and `stopped_at_ms: null`, the stop is a
`STOP_BUDGET` violation, and the cancel keeps running (held by the path) until
the agent's audio has stopped. A RED already past its stop budget does not
wait at all. Order is unchanged otherwise: clinician route, stop, trigger.

**Composition** (`composition.py`). Wherever a `RedWiring` binds the RED path,
one `RedMailbox` is handed to both the `BackendAgent` (`red_push`) and the
`TalkerSession` (`red_mailbox`). No RED path, no mailbox.

**The metric.** `preempt_red_violations_total{violation}` counts each
violation the path raises, by the closed `RedViolation` value, from the take
-turn route and the watch alike (a replay counts only its new device
violations). Catalogued (`owner: voice-runtime`, `status: live`). No alert is
added: `infra/observability/safety-rules.yaml` is pinned by
`tests/safety/test_red_acknowledgement_sla.py` and no alert reads the RED
latency series either (see *Residuals*).

### Why invariant 9 still holds

- **Six tools.** The surface is the registry's six names; `watch_reds` and
  `ensure_red_watch` are not tools. `assert_six_tool_surface` over the composed
  session (both profiles) still passes.
- **The Talker never awaits Backend Work.** The watch awaits the mailbox's
  event, which Layer B sets by a synchronous post, and the RED path; it never
  awaits a Work, a pump or the evaluation. A turn awaits neither the watch nor
  Layer B (starting the watch is a synchronous `create_task`). Measured: with
  Layer B stalled 10 s or 30 s, the turn that carries the onset answer costs
  the same with the watch running and without it; INT-521's
  `test_the_talker_never_awaits_the_evaluation` (30 s stall) still passes.
- **No Backend coroutine calls into the Talker.** `RedPush` has one member and
  it is not a coroutine; neither `red_push.py` nor `work_queue.py` imports
  `talker.session` or names `TalkerSession` (AST test).
- **Only a rules-engine RED preempts.** The queue still derives `preempt` only
  from a `RulesTriageResult` at `RED` and posts only after its preempt gate;
  the mailbox re-checks the shape and refuses a YELLOW, a GREEN, and a result
  built around the validator (an LLM candidate or a YELLOW dressed as
  `preempt`); the Talker re-runs `authorise_preempt` against the session's
  pinned rules before the path, and refuses a RED naming any other rule.
- **Backend speech still waits for a window.** Only a RED takes the push; it is
  the one result the insertion window never governed.

### Invariant 21

The trigger is the same `RedTriggerMessage` over the same `RedDataChannel`;
the push is an in-process signal between the two layers and carries no audio.
On voice the only media call is still the cancel; typed's canceller is the
no-outbound-audio one. Register and location are the rule's and the session's.
