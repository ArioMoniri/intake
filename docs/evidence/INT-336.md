## ADR-033 status
Q5 (a scale of at most 1.06 on the orb) is open, and its fail-closed default is opacity-only. This
PR ships that default: `OrbVisual.scale` is the literal type `1`, `motion.orb` has no scale key, and
the listening state stays visible through its halo's opacity (`orb.haloBreathLow`, the verifier's
proposed value). A yes to Q5 adds the scale tokens and one animated `transform` on the orb. Nothing
else changes.

## Problem
- The dialogue said "whose turn is it" with three different devices: a core `Animated.loop` pulse
  (`PulseDot`) in the listening and speaking bubbles, and three `ActivityIndicator` spinners in the
  preparing bubble, the transcribing bubble and the settling row. With ask-ahead, two spinners could
  spin at once while the patient was still interacting (motion-verification.md §2.1 #8), which
  breaks 02 §5.2a rule 8 and gives SC 2.2.2 a weak exemption.
- The pulse ran on the JS-driven `Animated` API, so a stalled JS thread would stop it.
- Nothing reflected the patient's own voice back to them while the microphone was open.

## Change
- **Tokens** (`src/lib/theme.ts`), each with its first consumer here: `duration.fast` (90),
  `easing.linear`, `loop.breathePeriodMs` / `speakPeriodMs` / `shimmerPeriodMs` (4000 / 1600 / 1400),
  `level.*` and `orb.*` (opacities only). `loop.pulsePeriodMs` left with the pulse.
- **Pure policy** `src/lib/motion/orb.ts` (no React Native, Reanimated or clock):
  - `orbStateFor`: the precedence list of intake spec §4.2, from events only (lane, turn phase,
    playback, voice muted, transport, and a presented RED's `yields.orb` from INT-333);
  - `orbVisual` (opacity-only, still under reduce-motion); `orbTransition` (0 to hidden, a 120 ms fade
    in, 90 ms speaking→listening, out-eased, delay 0, 0 under reduce-motion); `workRing` (a static
    modifier);
  - the level pipeline `normalizeLevel`, `smoothLevel`, `quantizeLevel` and `levelSamplerPlan`
    (listening only, never under reduce-motion, `level.sampleMs` apart).
- **Device half:**
  - `src/lib/motion/native/useLevelSampler.ts`: the one timer. It samples the recorder's metering at
    the plan's rate and writes a Reanimated shared value only when the 0.05 step changes. It sets no
    React state. It is classified in BK13's `NOT_A_TIME_LIMIT` ("a meter; it limits nothing").
  - `src/components/PresenceOrb.tsx`: draws the orb (halo, level halo, work ring, core, retry core)
    on the UI thread. It is hidden from accessibility, has `pointerEvents="none"` and is not
    pressable. It calls `useReducedMotion` and `loopingDecorationEnabled` itself (BK14), and reads
    loop periods from `motion.loop` (BK15). A state change freezes the running value and reaches the
    next rest from there, so it holds and never resets.
- **Dialogue** (`src/components/DialogueIntake.tsx`): the orb leads the glass bar's first row beside
  `SectionStrip` (intake spec §4.1 placement). The pulse is gone, and the bubbles' dots are still.
  The three spinners are gone, and their captions stay as static text. The orb's state is computed
  once, by `orbStateFor`. This dev lane has no media transport and no RED channel, so it passes
  `transport: "connected"` and `red: null`; the LiveKit lane feeds both.
- **Session** (`src/lib/dialogue/useDialogueSession.ts`): `readLevel()` returns the recorder's
  current metering, a scalar. Nothing is stored or sent.
- **Guards** (`e2e/motion.spec.ts`):
  - a MOTION-7 block: no spinner and no core loop in the dialogue; the orb's state comes only from
    `orbStateFor`; the orb is hidden and not pressable; the sampler is the only timer, under src/lib,
    writing a shared value and never React state;
  - the MOTION-6 pins move from the dialogue to the orb;
  - the MOTION-4 pinned list gains `src/lib/motion/orb.ts`, because it reads a RED's yield. The
    detector found it, which is the pin doing its job.
- **Proposal doc:** `docs/design/motion/enhancements.md` (the motion lead's proposals beyond the rows;
  see the PR body). It decides nothing and adds no token.

## Device evidence: PENDING
**Pending: the owner's two reference devices** (still unnamed; see INT-330). This needs a release
build on iOS and Android, recorded here with the device, OS, build and date:
1. **JS-thread stall.** During a listening turn, block the JS thread for about two seconds (for
   example with a dev-menu busy loop in a release-like profile build). The orb's halo keeps
   breathing and the core keeps its state, because both run in UI-thread shared values.
2. **Render count.** Wrap `DialogueIntake` in a React Profiler, or count renders with a
   commit hook, across a ten-second listen with speech. The count must stay flat: the level reaches
   the orb only through `useLevelSampler`'s shared-value writes, and the orb's state changes only
   on turn events. The source guards hold both properties today; the device run measures them.
3. Also check: speaking→listening on barge-in lands within 90 ms of the audio stopping; reduce-motion
   (OS and in-app) makes the orb still, with no halo movement.

Nothing in this PR is a device measurement (invariant 20: a measurement is recorded with a device
and a date, never stated as a property of the product).

## Not in this PR
- **Loops hold during transients** (the arbiter's `ambient` state, INT-334): INT-337 wires the
  dialogue to the arbiter and passes the hold to the orb.
- The LiveKit lane's `transport` and RED inputs: that lane feeds `orbStateFor` when its UI lands
  (INT-135).

- **17**: every token has a consumer here, and no scale token ships.
- **8**: tests added; the MOTION-6 pins moved rather than dropped.
