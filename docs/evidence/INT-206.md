  defaulted: a `location` nobody has chosen would make the residency claim in
  files/06 §5 unfalsifiable, and a `provider` is also the DPA counterparty.
  **It also rules one row OUT, and this is a correction to the obvious reading
  of the blocker file.** HB-I5 records that no in-country provider is under
  contract, and it is tempting to file the TR-DC runner behind it — but HB-I5 is
  about **GPU** supply, and a CI runner needs CPU. files/00_STATE.md §2 records
  the AWS İstanbul Local Zone as GA since May 2026 with C7i/M7i/R7i, EBS, VPC,

  and the spend are, and treating HB-I5 as the blocker would postpone a choice

- `intake_platform.ci.pools` — the schema and label resolution. A pool must be
  `ephemeral: true` (a persistent runner keeps a workspace between jobs, and a
  workspace that outlives a job is how one repository's checkout reaches the
  next one) and `phi_path: false` (there is no CI job that may touch patient
  data); both are refused at load, not at review. `resolve_runs_on` fails closed

  re-derive the wrong blocker.
- `intake_platform.ci.heartbeat` + `intake_probes.probes.runner_heartbeat` +
  the `ci-runners` row in `observability/registry.yaml` — files/08 §6's CI row,
  probe `runner heartbeat`, fallback "GitHub-hosted runners (no PHI in CI
  ever)". With zero pools the probe returns a typed `Skipped` naming HB-I7:
  visible in every sweep, never counted healthy. Reporting an empty set as
  healthy is how a monitor tells you a service is fine when it does not exist.

**The policy half — six surfaces, each able to fail.**

`intake_platform.ci`, declared in `infra/ci/no-phi-policy.yaml`, run by
`make ci-policy` and by `tests/infra/test_ci_no_phi.py`:

| surface | what fails |
|---|---|
| fixtures | an identifier-shaped value in a scanned tree that is not inside a declared synthetic corpus — **and a declared corpus whose bytes no longer hash to the reviewed sha256** |
| env | an identifier in a variable's value **or its name** (`PATIENT_05XX-XXX-XX-XX=` is a phone number in the runner's process table) |
| logs | a `run:` step that names a declared corpus, i.e. prints it into a job log retained 30 d hot / 1 y cold |
| artefacts | an `upload-artifact` path outside `artefact_paths` (today: empty), and always when the path is a declared corpus |
| cache | an `actions/cache` path outside `cache_paths` (today: the pinned de-id NER artefact, and nothing else) |
| runners | a `runs-on` that resolves to neither a known GitHub-hosted label nor a declared pool |

Plus, on the workflow itself: an unpinned `uses:`, an undeclared `secrets.*`
reference, a missing `permissions:` block and a blanket `write-all`.

Three design points worth stating, because each was a decision rather than a default:

1. **The detectors are `intake_platform.deid`'s pattern tier, reached through
   its public `analyze`.** One definition of "identifier-shaped" in this repo,
   not two — the half that drifts is always the one nobody runs against real
   data. Two deliberate narrowings: dates are not findings here (a fixture tree
   is full of timestamps, and a noisy gate acquires an allow-list), and the NER
   tier is out of scope (a gate that needs a 5.7 GB artefact does not run on a
   laptop).
2. **A corpus declaration is pinned by sha256.** Pattern-scanning fixtures
   proves only that we can author clean fixtures — files/10 §3 makes exactly
   this point about the fixture-only scan, which is why invariant 36 moves the
   *runtime* one. The hash is what turns the declaration into a control: a new
   identifier can only reach CI's fixture inputs through a reviewed diff. All
   four declared hashes were computed from the committed bytes; the two vendored
   ones match `tests/fixtures/deid/vendor/ATTRIBUTION.md` independently.
3. **Findings carry digests, never values.** This runs in a job whose stdout is
   a retained log. A no-PHI gate that printed the PHI it found would be the leak
   it exists to prevent, and there is a test that drives the CLI over a planted
   fixture and asserts the identifier is absent from stdout and stderr while its
   digest is present.

## Scope boundary against INT-019 — read this before wiring anything

**INT-019 (`security.yml CI job: full gate set + signing`, status `doing`) owns
`make security` and, in its own acceptance, "PHI-pattern scan of fixtures" and
"planted PHI … fails".** Neither exists on `main`, so there was nothing here to
extend — but they exist on an unmerged branch, and pretending otherwise would
just move the collision to merge day. Inspected at `origin/int-19-secgates2`:

- `scripts/ci/phi_scan.sh` — a shell scan over `git ls-files -- tests/fixtures
  docs` for checksum-valid TCKN, TR mobile and TR IBAN, reporting file, line and
  category with content withheld. Stdlib/shell on purpose, so it runs on the
  bare `gates` runner without `uv`.
- `scripts/ci/phi_scan_allow.txt` — a **prefix** allow-list, itself pinned
  "may only shrink" by `tests/ci/test_security_gates.py`. Today it blesses
  `tests/fixtures/deid/` wholesale, plus `tests/fixtures/logs/app_lines.txt`
  and two `docs/evidence/` files.
- `make security` — an eleven-step gate set with the PHI scan among them.

**Where the two overlap is exactly one surface: fixtures.** The other five —
env, logs, artefacts, cache, runners — have no counterpart there. On the
overlapping surface the constructions differ in a way worth deciding
deliberately rather than merging by accident:

| | INT-019 `phi_scan.sh` | INT-206 `intake_platform.ci` fixtures surface |
|---|---|---|
| scope | `tests/fixtures` **and `docs/`** | `tests/fixtures` (`scanned_trees`) |
| detectors | its own three regexes + `tckn_check.py` | `intake_platform.deid`'s pattern tier via `analyze` (adds EMAIL) |
| how a file is excused | a **path prefix** in an allow-list that may only shrink | a **per-file declaration** carrying origin, provenance, licence and a **sha256** |
| runs where | the bare `gates` runner, no `uv` | needs pydantic + pyyaml, so a job with `uv sync` |

The prefix form blesses a directory wholesale: a new file dropped into
`tests/fixtures/deid/` inherits the exemption silently. The sha256 form cannot —
editing a declared corpus fails the gate until someone re-reads it and updates
the hash. The prefix form is also the cheaper one to run, and it covers `docs/`,
which this policy does not.

**Recommendation for whoever merges second: keep both scopes, one mechanism.**
`phi_scan.sh` keeps `docs/` (nothing here covers it) and drops
`tests/fixtures` to the declared corpora, or `scanned_trees` grows to include
`docs/` and `phi_scan.sh` loses the fixture sweep. Two scanners disagreeing
about which fixture is excused is worse than either alone. This PR adds neither
`make security` nor anything under `.github/workflows/`; it adds `make
ci-policy` and one library entry point,
`intake_platform.ci.run_ci_policy(repo_root, env=…)`, for INT-019 to call.

**One concrete consequence, handled here.** `phi_scan.sh` scans `docs/`, and the
first draft of this evidence file quoted the eleven-digit run id from the
GitHub-environment test — which is checksum-valid, and would have failed INT-019
the day it merged. The literal is removed; it lives in the test, which that scan
does not read. Note separately that `docs/PROGRESS.md` line 464 already carries a
TR-mobile-shaped string **on `main`** (INT-145's entry, not this change), so
INT-019 will need either an allow-list row or an edit there.

## Prepared but UNAPPLIED — the `.github/workflows/ci.yml` change

`.github/workflows/**` is owner territory and this session is blocked from
writing there. Nothing below has been applied.

**It is not needed for the acceptance.** The fixture, log, artefact, cache and
runner surfaces are already enforced in CI as the workflow stands, because
`tests/infra/test_ci_no_phi.py` is collected by `make check-py`, which the
`check-py` job runs. The one surface a test cannot reach from outside the job is
the runner's own environment, and that is what this diff adds.

Apply verbatim:

```diff
--- a/.github/workflows/ci.yml
+++ b/.github/workflows/ci.yml
@@ -30,6 +30,11 @@ jobs:
         env:
           GH_TOKEN: ${{ github.token }}
       - run: make check-py
+      # INT-206: the no-PHI-in-CI policy over the six surfaces a patient-shaped
+      # value can reach CI through. check-py already collects the same policy
+      # through tests/infra; this step adds --scan-environment, the one surface
+      # a test cannot see — the runner's own environment.
+      - run: make ci-policy
 
   check-ts:
     runs-on: ubuntu-latest
```

Verified to apply: `git apply --check` against a copy of the committed
`.github/workflows/ci.yml` returns 0. The hunk is not hand-counted.

It goes in `check-py` rather than in `gates` because `gates` deliberately runs
on the bare runner with no `uv` (see the comment on the `sec_row` step), and
this policy needs pydantic and pyyaml. Moving it to `gates` would mean adding
`setup-uv` plus a sync to a job whose whole point is that it is cheap.

**One residual risk the owner should know before applying it,** because it was
measured rather than reasoned about. `--scan-environment` scans the runner's own
variables, and one integer in a hundred passes the TC Kimlik checksum;
`GITHUB_RUN_ID` is an eleven-digit integer that changes every run. The first
draft of the test that pins a realistic GitHub environment failed on exactly
that: the eleven-digit run id invented for the test happens to satisfy the TC
Kimlik checksum. The literal lives in the test and is deliberately not quoted
here, for the reason given in the INT-019 section above — `phi_scan.sh` scans
`docs/`. Left unhandled it would have been a ~1 % flake rate in the owner's CI,
on a value that is not a person.
`_is_platform_serial` now skips a value that is *entirely decimal digits* in a
variable GitHub reserves for itself (`GITHUB_`, `RUNNER_`). That is a narrowing
rather than an allow-list: GitHub refuses to let a workflow, action or step set a
variable in those namespaces, so nothing can be smuggled in through one, and
anything non-numeric in them — `GITHUB_HEAD_REF`, which carries an author-chosen
branch name — is still scanned. Three tests hold that boundary.

apply and why. A test holds that wording, because the wrong blocker cited
confidently is how a decision stays parked for a reason that was never true.
