### 2.1 `pack: duration=omit`

**Corrected after verification (§8, H-1 and M-1).** `omit` removes the cluster/specialty
`ziyaret_baglami.sikayet_suresi` only. base.intake's `must_ask` `hpi.onset_date` ("Bu şikâyetiniz ne
zaman başladı?") and `hpi.duration` ("Şikâyetiniz başladığından beri ne kadar sürüyor?") are still
asked, and no pack can suppress them (`SUPPRESS_MUST_ASK`). `omit` is **refused**
(`DURATION_OMIT_RULE_READS_SLOT`) while any red-flag rule of base.life_threat, the parent chain or
the candidate itself, draft or signed, reads `sikayet_suresi` in `when` or as `tense_anchor`. Every
cluster stub and every generated stub anchors on it, so **today `omit` is refused under every
cluster and for every cluster candidate**. That is the true state, not a regression. The compiler
refuses such a suppression for an overlay only; the chain-pack refusal is INT-382 (#629). Moving a
stub's anchor is red-flag semantics and stays with the clinician (INT-383, #630). The text below
describes what `omit` emits once no rule reads the slot, which only a test simulation reaches today.

- `PACK_KEYS` gains `duration`, and its only value is `omit`. `duration=omitted`, `duration=Omit`,
  `duration=`, `duration=keep` and the spelling `duration_omit=true` are refused.
- Under `omit`, `ziyaret_baglami` carries `basvuru_nedeni` only.
- `duration=omit` beside `duration_ask` or `duration_follow_up` is refused as contradictory: an
  omitted slot has no ask.
- Under `omit`, a gate (`ask_if` or `skip_if`) that reads `sikayet_suresi` is refused as reading an
  undeclared slot. The id stays reserved, so no item can take it.
- **Chain finding, handled in the generator.** `_merge_chain` keeps a parent's slot when a child
  leaves it out, and every cluster candidate declares `ziyaret_baglami.sikayet_suresi`. Leaving the
  slot out of a specialty candidate would therefore change nothing the patient hears: the cluster's
  duration question would still resolve into the chain. When the parent cluster declares the slot,
  the candidate also carries the DSL's own `suppress_slot` op (files/12 §3.1) on
  `/sections/ziyaret_baglami/slots/sikayet_suresi`. This is the same approach as #582's `reorder`
  op. The slot is `required: false` and not `must_ask`, so the validator's `SUPPRESS_MUST_ASK`
  refusal (files/12 §3.2) does not apply. Legality is not safety: the verification measured that a
  rule reading the suppressed slot is then served and never fires (§8, H-1), hence the refusal
  above. A cluster candidate needs no op, because base.intake declares no duration slot. A test
  resolves base → `cluster.medical` → generated branch with and without `omit`, with every stub
  anchored elsewhere as a simulation. `validate_packs` returns no findings, the ops apply cleanly,
  the merged `ziyaret_baglami` holds `sikayet_suresi` exactly when `omit` is absent, and
  `hpi.onset_date` and `hpi.duration` stay in both. The committed `cluster.medical` is refused.

### 2.2 `gen: type=code; options=<id>|<id>…`

- `SLOT_TYPES` gains `code`, and `GEN_KEYS` gains `options`.
- **Vocabulary source.** `CODE_OPTIONS` in the generator maps each option id to the label and to
  the base.intake code slot whose `choices_tr` carries that label **verbatim**. No committed
  valueset registry exists (a base code slot carries `valueset: vs.<slot>` and its labels in
  `choices_tr`, nothing else), so the labels are taken from base's own code slots. No Turkish was
  written. A test reads base.intake and asserts every label at its named slot. It also checks that
  every id is snake_case ASCII, that no label carries a digit (invariant 22) and that no two ids
  share a label.

  | ids | labels from |
  |---|---|
  | `evet`, `hayir`, `bilmiyorum` | `meds_allergies.anticoagulant_use` |
  | `emin_degilim` | `pmh_fh_sh.pregnancy_status` |
  | `biraktim`, `hic_kullanmadim` | `pmh_fh_sh.smoking_status` |
  | `hic`, `ara_sira`, `duzenli` | `pmh_fh_sh.alcohol_use` |
  | `daha_kotu`, `ayni`, `daha_iyi` | `hpi.trajectory` |
  | `sabahlari`, `aksamlari`, `geceleri`, `belli_bir_saati_yok` | `hpi.timing_pattern` |

  `subject_role`'s labels are left out. They name who is speaking, and base already spells that
  valueset's own code (`'kendim'`). The id spelling follows base's gate literals (`'hayir'`).
- **Emitted shape**, as for base's code slots: `type: code`, `valueset: vs.<slot>` (base names every
  code valueset after its slot) and `choices_tr: {tr: [labels in option order]}`. The pack
  validates as a `ProtocolPack` and loads through `load_pack`.
- **Refusals**, each a per-item warning that keeps the item out of the pack, as the generator's
  other per-item refusals do:
  - `type=code` with no options, or an empty `options=`;
  - `options` on any other type ("contradict");
  - an id outside the vocabulary. This is refused as `CODE_OPTION_NOT_IN_VOCABULARY` with
    "clinician wording needed (HB-C1)". It covers a new word (`aniden`), the label instead of the id
    (`hayır`) and a case change (`Evet`);
  - an id listed twice;
  - fewer than two options;
  - no `slot=`, because the valueset is named after the slot and a positional `soru_N` id would
    rename it whenever an item is added;
  - the misspelled key `option=`, as an unknown key.
- `build_pack` applies the same check, so a caller that skips the parser cannot emit a code slot
  without options.
- Near-miss control: `options=evet|hayir` (two) is accepted.

### 2.3 `gen: skip_if=<expr>`

- `GEN_KEYS` gains `skip_if`. It is emitted as the DSL's `skip_if` (files/03 §5), which the engine
  reads as its retire gate (`IntakePlan.retired`, TRUE only).
- The parsing and the earlier-slot rule are the same as for `ask_if`: one shared `_gate_problem`
  applies the gate's slot names (INT-355 resolution) to the fixed slots, base.intake and the
  items before this one. Since the verification (§8, L-1) the names come from the DSL's own
  parser, `protocols.triage.expr.parse_when` + `referenced_slots`, not a regex, so a bare,
  negated or `in` read counts, and a gate outside the grammar is refused. The refusal names the
  case:
  - `reads itself`;
  - `reads later slot(s)`. This is the in-pack form of INT-375's ordering rule; the forward
    reference used to be reported as "undeclared";
  - `reads undeclared slot(s)`.

  The messages change only for gates that were already refused. The regenerate-all run below prints
  the same log as before.
- `gate_reads` now unions `ask_if` and `skip_if`, so a `skip_if` counts in #582's `reorder` op
  exactly as an `ask_if` does. A test moves a re-declared parent slot after its new gate slot. Its
  near-miss control is a new slot gated the same way, which needs no reorder.
- **One gate per item.** `ask_if` together with `skip_if` is refused. The FHIR emitter projects
  both into one `enableBehavior` and refuses most such pairs (`GATE_NOT_PROJECTABLE`, files/03 §6),
  and a single gate can always express the pair.
- **Q1.** `skip_if` or `code` on Q1 is refused. Q1 fills the fixed, required `basvuru_nedeni`,
  which would silently drop either key.

## 6. Recorded for the clinician and the protocol owner (nothing decided here)

- **Where to use the three keys** is the clinician's decision (HB-C1; paediatric HB-C3; turn budget
  HB-C5). No proposal uses them in this PR.
- **Labels outside the vocabulary.** Nothing is refused today, because no proposal uses `type=code`.
  The only enumerated answer set the verifications named outside base's labels is wave 7's
  `baslangic_sekli` ("aniden" / "yavaş yavaş", noroloji). base.intake carries neither label, so
  a `code` form of it would be refused as `CODE_OPTION_NOT_IN_VOCABULARY` until a clinician words
  the labels (HB-C1). The vaccinations set asked for in cluster-wave-b §A.1 Q14 (evet / hayır /
  bilmiyorum) is fully in the vocabulary.
- **`tense_anchor` under `duration=omit`** (corrected, §8 M-4). The draft stub rule (and a parent
  cluster's stub) keeps `tense_anchor: sikayet_suresi`. Nothing validates a signed rule's anchor
  either: the verification's signed simulation compiled a rule anchored on a suppressed slot, and it
  is served and never fires (`rule_truth` UNKNOWN). The generator therefore refuses `omit` while any
  stub keeps that anchor (§2.1). It does not re-anchor the stub: the physician sets each anchor when
  authoring the trigger (HB-C1, HB-C2; INT-383, #630).
- **Whether a report or recall visit asks base HPI timing** is a base/visit-type decision (HB-C1,
  HB-C5), which `duration=omit` cannot express: base.intake's `must_ask` `hpi.onset_date` and
  `hpi.duration` are asked under every pack.
- **Valueset members.** As for base's own code slots, the pack carries the valueset id and the
  labels, and no committed file lists a valueset's member codes. The extraction schema receives
  them at composition (`valuesets=`). A generated code slot is in the same position as base's. The
  option ids are generator-internal (`CODE_OPTIONS` is the only id↔label map); a future valueset
  registry for `vs.<slot>` must be derived from the proposal's `options=` so ids and labels cannot
  drift (§8, N-1).
- **`skip_if` fails safe** (§8, N-2). The engine retires an item only on a TRUE `skip_if`, so an
  unanswered or unclear gate slot asks the item; an `ask_if` on UNKNOWN does not ask. For alarm
  items gated on a status, prefer `skip_if` (for HB-C1).
