# INT-396: Backlog rows match what merged — status reconciliation and a drift guard

**Epic:** platform · **Phase:** P1 · **Sec-Row:** — · **GitHub:** #655

## Problem
On 27 Sep 2026 `docs/backlog/issues.yaml` disagreed with what had merged, in three ways:

- rows still read `todo` or `doing` although a merged `INT-xxx:` PR had closed their
  GitHub issue and their evidence file existed (the issue names INT-330, INT-331, INT-335,
  INT-341, INT-344, INT-345, INT-353, INT-355 and INT-357 among them);
- 85 `done` rows carried no `evidence:` key, while 2 `todo` rows (INT-122, INT-138) did;
- 82 ids had more than one GitHub issue (INT-019 #17/#222, INT-138 #108/#457, …).

Nothing stopped the drift, so it grew with every merge.

## Change
- `scripts/backlog/reconcile.py`: the CLI. It is read-only by default and `--apply` writes
  `issues.yaml`. It fetches `gh pr list --state merged --limit 1000` and
  `gh issue list --state all`, or reads the same JSON through `--prs-json` and `--issues-json`.
  `--format markdown` prints the tables below.
- `scripts/backlog/reconcile_lib.py`: the pure half. It parses PR links and blocker records,
  makes the per-row decision, and applies the line edit. It does no I/O. The split keeps
  both files under the 500-line limit.
- `scripts/backlog/backlog_lib.py`: `status_violations()` and `evidence_path()`. These are
  the consistency rule, shared by the reconciler and the new test.
- `scripts/backlog/sync_issues.py`: `owned_issue_numbers()` is extracted from `build_plan`
  unchanged, so the reconciler uses the sync's own id→issue mapping and cannot drift from
  it. The rule is the 7-character title prefix, last match wins. Because gh lists newest
  first, **the sync owns the oldest issue carrying an id**.
- `tests/backlog/test_status_consistency.py`: the drift guard.
- `tests/backlog/test_reconcile.py`: 22 hermetic cases for the decision, the parsers and
  `--apply`.
- `docs/backlog/issues.yaml`: the 101 edits `reconcile.py --apply` made (table below),
  plus this issue's own row, INT-396. It is `done` with this file as its evidence, epic
  `E00-governance` (the backlog-machinery epic of INT-001…004), P1, `area:platform`, and no
  `sec_row`.
- The three pinned counts go from 303 to 304 for that row, with the reason given beside
  each: `tests/backlog/test_schema.py`, `tests/backlog/test_sync_dryrun.py` and
  `tests/smoke/test_make_check.py`.
- `files/11_ISSUE_BACKLOG.md`: regenerated.

## The rules (none of them guesses)
| row today | recommendation |
|---|---|
| `todo` / `doing` / `blocked` | `done` + `evidence:` **only** when all five hold: a merged PR titled `INT-xxx:` says `Closes #n` for the issue the sync owns; that issue is closed; `docs/evidence/INT-xxx.md` exists; the file marks no clause `PENDING` or `NOT MET`; and no blockers.md row or section and no open HUMAN_BLOCKERS row names the id. Otherwise the row is left as it is and reported. |
| `awaiting-human` | keeps its status. The blockers that name it are listed. If none does, the row is reported. |
| `done` without `evidence:` | gains `evidence:` when the file exists. Otherwise it is listed and no file is written. |
| `todo` with `evidence:` | keeps `todo` and loses the key. The status is the row's recorded decision, and the file stays. |

Four near-miss controls say what the rules do **not** count as closure:

- a PR that says only `Refs`;
- a PR titled with another id;
- a PR that closes a *duplicate* issue while the owned one stays open (INT-020's `core` slice);
- an owned issue reopened after the merge (INT-210 #152).

### The PENDING guard, and why it exists
The first dry run had one more rule-shaped hole. INT-330's PR #553 closed #529, but the
row's fourth acceptance line reads *"device measurement of push/pop timing on the owner's two
reference devices recorded in the evidence file"*, and `docs/evidence/INT-330.md` says
`## Device measurement: PENDING`. INT-341 has the same shape: *"before/after screenshots for
the calendar and the composer send button"*, with `## Before/after screenshots: PENDING
(owner device step)`. A closed issue is not a delivered acceptance, so the reconciler now
reads the evidence file. Across `docs/evidence/INT-*.md`, capitals `PENDING` / `NOT MET`
appear in exactly four files: INT-330, INT-341, INT-210 (awaiting-human, kept) and INT-091
(done, where it is a code identifier). It is case-sensitive because the lower-case word is
ordinary prose. INT-353's *"HB-C1 stays open"* is about a different row and must not hold it.

### Rows hand-checked against their PR bodies
- **INT-122, INT-138** (`todo`, `evidence:` removed). Both rows' own comments say
  `status: todo` *"on the INT-121 / INT-136 / INT-140 precedent"*, and both PRs say *"The
  issue stays `todo`"* (#460, #458). The status is the recorded decision. The key is the
  inconsistency, so the key goes and the status stays. Both comments still point at the
  evidence file.
- **INT-329** (→ `done`). Its evidence discusses an `awaiting-human` line, but #577 rescoped
  that line out to INT-358 (#576). The row's current acceptance is three engineering lines,
  all met.
- **INT-345, INT-353** (→ `done`). Each evidence file mentions a human dependency of
  *another* row: the SMS vendor and attestation, and HB-C1. Neither is in its own acceptance.
- The 14 rows that became `done` are exactly the stale rows the issue lists, minus INT-330
  and INT-341, plus INT-179, INT-324, INT-325, INT-326, INT-328, INT-329 and INT-346. Every one had its sync-owned issue
  closed by the PR named.
