What only the live server could prove, and did:

- `ensure_buckets` provisions the audit bucket with object-lock and a default
  COMPLIANCE retention a real `get_object_lock_config` reads back; a bucket
  pre-created *without* the lock raises the typed `WormMisconfiguredError`
  (MinIO cannot enable the lock after creation — no silent downgrade).
- put → presign → `httpx.GET` roundtrip serves the exact bytes with the right
  content type, and a 1-second-TTL URL returns **403** after expiry.
- WORM: deleting the stored audit-bundle *version* before retention expiry is
  refused by the server (`S3Error`). A versionless delete only writes a
  delete marker and an overwrite only stacks a new version — the original
  version was re-read intact after both, so the written bytes are
  indestructible until retention lapses.

Fresh `int034-*` bucket names per run; the docs-side buckets are drained and
removed, the WORM bucket by definition cannot be (retention 1 day in the
test, deliberately short because COMPLIANCE can never be shortened later; the
dev `miniodata` volume is disposable).

## What the unit tests pin (fake client, zero network)

- Keys are `<prefix>/<tenant>/<pseudonym>/<uuid4hex>` — no filename parameter
  exists at all (`inspect.signature` is asserted), so a patient-named upload
  cannot leak its name into a key (invariant 6).
- 20 MB cap (boundary accepted, cap+1 refused), pdf/jpeg/png allow-list,
  sha256 recomputed server-side; refusals echo neither the offending value
  nor either digest, and store nothing, and audit nothing.
- Nothing serves unscanned: default scanner raises `NoScanConfiguredError`
  (object stays in `quarantine/`), INFECTED verdicts move the object to
  `infected/` and raise, `presigned_get` refuses any ref that is not
  CLEAN + `clean/`-prefixed + in the documents bucket — including refs whose
  state field lies.
- `DevNullScanner` is unconstructible without
  `INTAKE_DEV_ALLOW_UNSCANNED=explicit-yes` (exact phrase; `yes`/`true`/`1`
  refused) and refuses prod outright even with the phrase.
- Presign TTLs: default 300 s, ceiling 15 min inclusive, above-ceiling and
  ≤ 0 refused (not clamped) with no URL minted and no audit entry.
- Every mutating op appends exactly one hash-chained entry with the right
  action (`document.stored` / `document.released` / `document.rejected` /
  `document.presigned` / `audit.worm_copied`) and no payload: entries are
  asserted to contain no digest, no URL/`X-Amz` material, no content type;
  the chain verifies after every scenario (invariants 4 + 6).
- `as_object_storage(Minio(...))` pins under mypy --strict that the real
  client still satisfies the injected-client protocol.
- Docs bucket and audit bucket may never be the same bucket (WORM retention
  on patient documents would break KVKK-7 erasure) — typed constructor
  refusal.

## Acceptance mapping, honestly

- **short-TTL signed URLs** — done (300 s default, 15 min hard ceiling,
  refuse-not-clamp, per-share audit; live 403 after expiry).
- **object-lock on audit bucket** — done (COMPLIANCE default retention,
  configurable days, typed misconfiguration on any pre-existing/refused-lock
  bucket; live delete-refusal proven).
- **bucket policies least-privilege** — dev-tier posture: MinIO buckets deny
  anonymous access unless a policy grants it and the store never sets any
  policy; access is root-credential-only in the dev compose. Per-service
  MinIO users/policies (svc-api read-write docs, svc-audit-writer write-only
  audit) are an infra concern that lands with the prod residency issues —
  there is no per-service identity in the dev compose to scope yet.
- **server-side encryption** — the `sse` slot is plumbed through
  `put_object` end to end, but dev MinIO has no KMS/KES, so no SSE mode can
  be honestly enabled or tested here; enabling SSE-KMS rides the prod
  residency/KMS infra issue. Documents remain covered at rest today by the
  field-level envelope encryption path only where they transit the DB
  (INT-014); object-store SSE is deferred, stated plainly.

## Deferrals (mechanism landed, content elsewhere — none faked)

- ClamAV itself is **INT-120**: the `Scanner` protocol + quarantine→clean/
  infected promotion is the wiring point it plugs into; until it lands,
  nothing serves (fail closed), and the only bypass is the env-gated
  `DevNullScanner`.
- Presigned *uploads* land in `quarantine/` and stay unservable; their scan
  pass belongs to the INT-120 worker because the bytes never transit this
  process.
- The docs bucket's object storage is dev-tier MinIO; production residency
  (in-country storage, KES-backed SSE, per-service credentials) lands with
  the infra issues. files/10 §2's open MinIO/Garage decision is noted there —
  Garage lacks object-lock, which this issue's WORM tests would catch.
- Backlog `tests:` names `tests/data/test_signed_urls.py` — delivered as the
  signed-URL contract suite; the wider store behaviour lives in
  `tests/security/test_document_store.py` (+ `_integration`), matching the
  `documents` sec-row.
