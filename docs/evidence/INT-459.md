## 2. Change

**Tokens: `app/native-tokens.css`.** One set of names, with a value per theme from
`prefers-color-scheme`:

- system fonts (SF Pro, SF Pro Rounded for gauge figures, SF Mono);
- Apple-like neutrals, tuned until every pair passes AA (§3);
- the radius and spacing scale and the glass recipe;
- two springs.

The sheet redefines every token that `console.css` and `refresh.css` set per theme, so neither
earlier value leaks through.

**Springs.** Each spring is the step response of a damped spring, sampled at 25 points into a
CSS `linear()` curve. The curve is computed, not copied.

- **smooth:** ζ = 1, ω = 9.2 (critically damped, no overshoot).
- **snappy:** ζ = 0.82, ω = 8.2 (peaks at 1.011).

The formulas are x(t) = 1 − e^(−ωt)(1 + ωt) for ζ = 1, and
x(t) = 1 − e^(−ζωt)(cos ω_d t + (ζω/ω_d) sin ω_d t) otherwise, with ω_d = ω√(1 − ζ²).

**Shell: `app/native-shell.css` and `src/ops/nav.tsx`.**

- **Sidebar.** `ConsoleNav` keeps its signature, its `aria-current="page"` marking, and every
  href. It now renders:
  - a mark;
  - the pages under three visible group names (İzleme / Hizmetler / Yönetim), each with a
    symbol;
  - a second `nav` with a Türkçe/English switch that keeps the page.

  On a wide screen this is a floating glass sidebar. Under 1024 px the same markup becomes a
  floating glass capsule tab bar at the bottom.
- **Top bar.** The page header is a sticky glass toolbar with the title and subtitle. The
  glass is a `::before` layer, so the bar never becomes the containing block of the fixed
  sidebar inside it.
- **Glass.** It appears only on `.console-nav` and `.page-head::before`. Each turns solid
  under:
  - `prefers-reduced-transparency: reduce`;
  - `prefers-contrast: more`, which also draws an edge;
  - `@supports not (backdrop-filter)`.

**Content: `app/native-content.css`.** Everything here sits on solid fills.

- **Cards.** A hairline and a soft shadow, with no coloured top stripe.
- **Inspector lists.** The term sits left and the value right, with a hairline between terms.
  A term with several values keeps them in the value column. Before, CI/CD's "unmeasured SLOs"
  zig-zagged across both columns.
- **Tables.** Inset tables with rounded row hover.
- **Gauge.** Rounded figures and no glow.
- **Settings.** The four-eyes forms become settings cards:
  - fields in macOS proportions and a native `select`;
  - an accent checkbox;
  - the capsule primary button at the trailing edge.

  They are not animated (§3).
- **States.**
  - A page with no header (refused or unavailable) is a centred state view, with a symbol
    above the reason.
  - An unknown tile is an inset empty state with a "?" symbol. It still shows its word, its
    reason and no figure (invariant 17).
  - Notices and form results carry a symbol.

## 3. Tests

**`e2e/native.spec.ts`** (new, 31 tests):

- **Tokens.** Both themes define every required token and every colour, and the layer
  redefines every per-theme token of the earlier sheets.
  - **Near-miss:** a dark block missing `--muted` is caught.
- **Contrast.** In both themes:
  - text (`--ink`, `--muted`, the four states, `--accent`) is ≥ 4.5:1 on `--bg`, `--surface`,
    `--surface-2`, `--row-hover` and `--field`;
  - the accent button's label is ≥ 4.5:1, rest and pressed;
  - chrome text over glass is ≥ 4.5:1, composited at the 86 % tint over every backdrop that
    can scroll beneath it: every surface and data colour, plus a blurred line of text;
  - the solid fallback and the selected row are ≥ 4.5:1;
  - the focus ring is ≥ 3:1 on every surface.
  - **Near-misses:** Apple's own dark systemBlue under white text fails AA (3.65:1), so the
    fill is darker. A 70 % glass fails over the light red.
- **Glass.**
  - The only backdrop filters are on `.console-nav` and `.page-head::before`.
  - Each uses the chrome tint mixed with transparency.
  - No content selector has a translucent fill.
  - Each glass surface turns solid under all three fallbacks.
  - **Near-miss:** a planted glass `.tile` is caught.
- **Motion.**
  - Both springs are `linear()` curves from 0 to 1, with at least 16 stops, overshoot of at
    most 1.05, and smooth is monotone.
  - Every transition and animation in the layer runs on a spring.
  - Every moving rule in **all five** sheets is matched, in jsdom, against the rendered Voice
    and CI/CD pages. None may match a form, anything inside one, a button, input, select or
    textarea, or anything holding one.
  - **Near-miss:** INT-450's `.grid > .tile` entrance matches the four-eyes forms.
- **Text and CSP.** No case transform, ellipsis or break-all (Turkish casing). No `@import`,
  `url(` or origin. The layout imports the five sheets in order.

  - the layer centres a header-less page;

## 8. Follow-up: the loading state, admitted by one CSP hash (owner decision, 3 Oct 2026)

> **Withdrawn on the refresh branch (17 Oct 2026, §10).** The D26 row this section relied on was
> recorded only on the #784 branch; `main` has no D26 and D-row allocation belongs to the
> orchestrator. The refresh therefore drops `app/loading.tsx`, the skeleton (`LoadingView`, the
> bones, the `--skeleton` token and their Astryx/beUI credits) and the `style-src-attr
> 'unsafe-hashes'` relaxation, and restores main's CSP and docs. `e2e/states.spec.ts` keeps the
> guard that no route has a `loading` file, with the streamed `style="display:none"` as its
> near-miss. The text below is the record of what was built on 3 Oct.

**Decision.** The owner approved restoring the route-level loading state and admitting React's
streamed segment style through the CSP by its hash: never `unsafe-inline`, and
`'unsafe-hashes'` only where it is required.

**Why `'unsafe-hashes'` is required.** In CSP Level 3 a hash source matches an inline `<style>`
element. It matches a style *attribute* only when the same source list also carries
`'unsafe-hashes'`. React writes the parked segment as an attribute, so the keyword cannot be
avoided. It is confined to `style-src-attr`, beside the single hash. `style-src` is unchanged
(`'self' 'nonce-…'`), so a `<style>` element with the same text is still refused.

**What changed.**

- **`src/ops/csp.ts`** adds `style-src-attr 'unsafe-hashes' 'sha256-…'`. The hash is computed
  when the module loads, from `STREAMED_SEGMENT_STYLE = "display:none"` with `node:crypto`. The
  proxy runs on the Node.js runtime in Next.js 16.
- **`app/loading.tsx`** renders `LoadingView` from **`src/ui/states.tsx`**, which contains:
  - a muted sidebar outline;
  - the top bar, with `Yükleniyor` and one `role="status"` line in tr and en;
  - a row of four card skeletons.
  - The page is marked `aria-busy`. Every bone is `aria-hidden`, and there is no figure, link or
    `style=`.
- **`app/native-content.css`**: the bones breathe. Opacity goes from 1 to 0.45 on
  `--spring-smooth`, alternating. Reduced motion stops it through the existing global rule.
  - They hold no form or control, so the critical-control motion test still passes.
- **INT-450's motion pin** in `e2e/accessibility.spec.ts` now names two repeating motions: the
  blocked-badge halo and the loading bones. A new test holds `breathe` to opacity only, so it has
  no transform, no size and no position.
- **`proxy.ts`**: its header comment is updated. No code changed.

**Tests.**

- **`e2e/states.spec.ts`**: the "keep `loading.*` out" spec is replaced by two blocks.
  - **The skeleton (5 tests).** The route file renders the view. It is one `main`, marked busy,
    in tr and en. It has no digit, no link and no `style=`. Every bone is inside
    `aria-hidden`. axe reports zero violations.
  - **The hash path (6 tests).** The streamed value is **derived**, never written out:
    - React's own `renderToPipeableStream` streams the late-chart tree. Every `style="…"` in the
      output is collected, and there is exactly one value.
    - The policy admits it, and `style-src-attr` equals `'unsafe-hashes'` plus the hash of that
      value, computed in the spec.
    - The renderer Next.js ships (`next/dist/compiled/next-server/app-page{,-turbo}.runtime.prod.js`)
      is scanned for fixed `style="property:value"` literals. They must equal the streamed set, so
      a React upgrade that changes the string fails CI.
    - The only `unsafe-*` in the policy is `style-src-attr 'unsafe-hashes'`. There is no
      `unsafe-inline`, `style-src` is unchanged, and development carries the same directive.
  - **Near-misses.** These are all refused:
    - `color:red` and `display:block`;
    - the value with a trailing `;`, with a leading space, in upper case, with a space after the
      colon, and with `!important`;
    - a `<style>` element holding the same text (a nonce'd one still runs);
    - the policy with `'unsafe-hashes'` removed, which shows why the keyword is there.
- **`e2e/support/csp.ts`** (new) is the CSP Level 3 matching rule for a style attribute and a
  `<style>` element.
- **`e2e/ops.spec.ts`** and **`e2e/accessibility.spec.ts`**: "no `unsafe-*`" becomes "the one
  `unsafe-*` is `style-src-attr 'unsafe-hashes'`".

    explicit.

- bulk or auto approval, which would undermine four-eyes;
