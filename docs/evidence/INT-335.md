# INT-335 — Reanimated hygiene gates, before the first Reanimated consumer

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile · **GitHub:** #534 · **Depends on:** INT-331 (merged)
**Spec:** `docs/design/motion/motion-verification.md` §2.2, §2.3 and §4 MOTION-6,
with CI notes C-2, C-3 and C-5, and the Reanimated rules in
`intake-voice-motion-spec.md` §3.2 (P0) and §3.4 (all on branch `merge-305`,
not yet on `main` when this was written).

## Problem
- **C-3.** BK14 (`e2e/a11y.spec.ts`) found loops by the text `Animated.loop`,
  and only in `src/app` and `src/components`. A Reanimated `withRepeat` loop,
  or any loop in `src/lib`, was invisible to it, so the presence orb
  (MOTION-7) could have shipped an ungated loop past the SC 2.2.2 gate.
  "Gated" meant only that the words `loopingDecorationEnabled` and
  `useReducedMotion` appeared somewhere in the file, from any module.
- **C-2.** BK15 read the `duration:` literals of `DialogueIntake.tsx` and
  demanded at least one. Removing `PulseDot` (MOTION-7) would have failed it,
  and a 100 ms fade added beside the pulse would have broken its minimum. The
  pulse's period was a literal `700` written twice in the component.
- No guard kept Reanimated's riskier tools out of `src` before its first
  consumer: layout transitions, springs, `runOnJS`, animated layout
  properties, or CSS transitions with their own timing.

## Change
- `apps/mobile/src/lib/theme.ts`: `export type Bezier`; `motion.easing.out`
  `[0.23, 1, 0.32, 1]` and `motion.easing.breath` `[0.37, 0, 0.63, 1]`;
  `motion.loop.pulsePeriodMs` `1400` (a FULL period). The values are exactly
  the §2.2 table. Each lands with its first consumer, as §2.2's "Lands in"
  column says: `easing.out` in `fade.ts`, `easing.breath` and
  `loop.pulsePeriodMs` in `PulseDot`. No other §2.2 token is added.
- New pure `apps/mobile/src/lib/motion/fade.ts` (no react-native or
  Reanimated import):
  - `fadeSpec({ reduce })`: `{ property: "opacity", durationMs, delayMs: 0, easing: motion.easing.out }`,
    with `durationMs = motionMs(reduce, motion.duration.fade)`.
  - `enterFor({ reduce })`: that spec, or `undefined` under reduce-motion, so
    a mount registers no layout animation and the element is simply there.
  - `cssFade({ reduce })`: `transitionProperty: "opacity"`,
    `transitionDuration: "120ms" | "0ms"`, `transitionDelay: "0ms"`, and the
    same fade as the `transition` shorthand.
  - `cubicBezierCss(curve)`: `cubic-bezier(x1, y1, x2, y2)`.
- `apps/mobile/src/components/DialogueIntake.tsx` (`PulseDot`): each half of
  the loop is `motion.loop.pulsePeriodMs / 2` (700 ms, as before) with
  `easing: Easing.bezier(...motion.easing.breath)`. The period is unchanged.
  The curve was the core default, `Easing.inOut(Easing.ease)`
  (`cubic-bezier(0.42, 0, 0.58, 1)`), and is now the breath token
  (`0.37, 0, 0.63, 1`, ease-in-out sine), a near-identical symmetric curve.
  The reduce-motion gate is untouched.
- New `apps/mobile/e2e/motionSource.ts`: the helpers both spec files share,
  so BK14/BK15 and `motion.spec.ts` cannot disagree about which files loop.
  - `code(source)` strips comments, so a doc comment explaining why a file
    does not loop does not count as a loop.
  - `loops(source)` recognises `Animated.loop`, `withRepeat` (any mention, so
    an aliased import still counts) and `animationIterationCount` (a
    Reanimated CSS animation).
  - `literalDurations(source)` returns every `duration:` / `…Duration:` /
    `.duration(…)` value that is a number written in the file. A token halved
    (`/ 2`) is still the token. A name bound to a number literal in the same
    file is still a literal. A value computed by a policy function
    (`t.durationMs`) is not flagged, because the policy module owns and tests
    its own numbers.
  - `animatedStyleKeys(source)` / `animatable(key)`: the small
    object-literal reader behind the animated-styles scan. It lives here so
    `motion.spec.ts` stays under 400 lines.

  - BK15 moves out of "criteria the app satisfies by not having the feature"
    (it is met by speed, not by absence) into its own describe, as "every loop
    period comes from motion.loop, and every half-period exceeds 167 ms".
    Every `motion.loop` token's half must exceed 167 ms. Every looping file
    must read a `motion.loop` token and write no literal duration.
  - BK13 is unchanged and green.
- `apps/mobile/e2e/motion.spec.ts`, appended to INT-331's file:
  - "no file that loops carries a literal duration": seven samples (five
    caught, two accepted), then the whole app.
  - "app-authored animated styles touch only opacity and transform": every
    object a `useAnimatedStyle` worklet returns; a shared value, an
    `Animated.Value` or an interpolation of one, wherever a `style={…}` names
    it; every frame of a CSS `animationName` or `Keyframe`; and a custom
    layout animation's `initialValues`/`animations`. The only live site today
    is `PulseDot`'s opacity, and the test fails if the scan finds nothing.
  - "no LinearTransition, Layout animation, withSpring or runOnJS in src":
    covers `LinearTransition` and the other Reanimated layout transitions,
    Reanimated's `Layout`, a `layout={…}` prop, and React Native's own
    layout-animation API (Reanimated's `LayoutAnimationConfig`, which MOTION-8
    needs, stays allowed). It also covers `withSpring`, core
    `Animated.spring` and `.springify()`, and `runOnJS` with its Reanimated 4
    successor `scheduleOnRN`. The scan runs over all of `src`, tests included.
  - "Reanimated CSS transitions take their duration from cssFade": no file
    except `src/lib/motion/fade.ts` writes a CSS transition key
    (`transition`, `transitionProperty|Duration|TimingFunction|Delay|Behavior`).
    `fade.ts` reads `motion.duration.fade` and writes no literal duration.

  The forbidden names are assembled from parts, as in INT-331's guards.

### What goes beyond the spec's text
- **A CSS animation's iteration count counts as a loop.** It is the third way
  Reanimated can repeat, and SC 2.2.2 does not care which API repeats.
- **BK14 reads `src/lib` as well as screens and components.** C-3 names
  `PresenceOrb.tsx`, and the orb calling both functions itself satisfies this.
  A loop helper in `src/lib` would now have to be gated where it lives, not
  only where it is called.
- **The spring and JS-hop bans include their aliases:** core `Animated.spring`,
  `.springify()` and `scheduleOnRN`. Without them, the ban has a one-word
  bypass.
- **No `kind` parameter.** The system spec's `fadeSpec(kind, p)` kept a kind
  because it had an exit duration. Exits are instant (§2.1 #3), so every fade
  has one shape, and a kind would have been a parameter nothing reads.
- **`cssFade` carries the curve in the `transition` shorthand.** Reanimated's
  native normaliser accepts only a keyword for a `transitionTimingFunction`
  string (`react-native-reanimated/src/css/native/normalization/common/settings.ts`),
  and parses a `cubic-bezier(…)` only from the shorthand
  (`…/transition/shorthand.ts`). A pure module cannot construct Reanimated's
  easing object. The longhands are kept beside the shorthand so the duration
  is readable without parsing, and the test pins that they agree.
- **`enterFor` returns a pure description** (`FadeSpec | undefined`), not a
  Reanimated `FadeIn`, because importing Reanimated would break the
  node-only vitest (§2.3). The builder that turns it into `FadeIn` lands with
  its first consumer in `src/lib/motion/native/` (MOTION-7/8).
