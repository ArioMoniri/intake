## Red/green record

The structural suite was authored alongside the drafts (content files, not
TDD-shaped code — stated plainly). There is therefore no failing-feature-first
red run to record, and inventing one would be a worse record than none. What
the gate actually asks for — proof that the suite can fail — is supplied by a
planted mutation instead, which for a content pack is the stronger form: it
fails the assertion that matters rather than an assertion about code that did
not exist yet.

**Red run** — the real field, planted, and the suite catches it:

```
plant  served: false → served: true   (red_flags.yaml, the real field)
pytest test_packs_are_unservable_while_unsigned → FAILED  (1 failed)
```

**Green run** — reverted, and the whole suite passes:

```
revert
pytest tests/protocols → 11 passed
```

Also caught live during authoring (evidence the gates bite): the slot-reference
tokenizer flagged quoted enum literals (fixed), and an earlier draft's
`derived_slots` placement broke the YAML — the parse test caught it.
