# Evidence — INT-314 · The four spoken fields become per-locale maps, and the clamp that stood in for them is removed

Epic E03-protocols · phase P1 · `sec_row: protocol-registry` · depends on INT-297 (done).

`confirm_tr`, `action_tr`, `do_nots_tr` and `ask_one_tr` become maps keyed by locale on
the same schema as INT-297's five, with `tr` required. They are the *action* half of a
red-flag script, so this is where CLAUDE.md invariant 10 — *"scripted protocol questions,
red-flag action scripts and validated instruments are spoken verbatim from `text_tr`"* —
stops holding for only half of a RED rule. `action_tr` is the field that closes it.

INT-297 left them fail-closed rather than ignored: `protocols.pack_locale.selectable_locales`
clamped any pack carrying one of the four to `tr`. **This issue removes that clamp**, and
the removal is the third acceptance clause, not a side effect.

**The headline is §6: every one of the 58 authored spoken fields in the tree — authored
bytes and `expand_tr` expansion both — is unchanged, stated as comparator output.**

### 2a. The consumers that had to move, and how each announced itself

INT-297 §1 recorded that a locale-map migration's real risk is a *consumer* that keeps
type-checking. Four consumers of these four fields exist outside the DSL, and this time
none of them failed silently:

1. `clinical_agent/plan.py` — `EngineStep.confirm_tr` is `str | None`, so a dict raises a
   pydantic `ValidationError`. Loud.
2. `tests/safety/adversarial_corpus.py::_red_script_lines` reads the life-threat YAML raw
   to build the RED-register controls. It would have found **zero** action lines — and it
   raises `AssertionError` rather than returning an empty corpus, which is the check that
   caught it. That guard was already there; it earned its keep here.
3. `tests/safety/triage_goldens_corpus.py::_check_action` compares `action.action_tr`
   against the expected Turkish sentence. Now compares the `tr` entry, deliberately: a
   golden that compared *maps* would still pass if the map gained a locale saying
   something else.
4. `emit_clips` / `validator` — both already iterate, so both were mechanical.

## 3. The clamp: removed, and what now proves the second locale

`pack_locale.MONOLINGUAL_SPOKEN_FIELDS` and the `common &= {DEFAULT_LOCALE}` line are
**deleted**, not emptied. Two tests hold that shut from opposite sides:

* `test_the_monolingual_clamp_is_gone_from_the_module` asserts the name is absent from
  the module and from its `__all__`. A condition that can no longer fire is a restriction
  a later reader cannot tell from a live one, so the acceptance asks for removal and the
  test asserts removal rather than inertness.
* `test_a_pack_carrying_all_four_fields_in_a_second_locale_is_now_selectable` builds a
  pack carrying `ask_tr`, `follow_up_tr`, `confirm_tr`, `why_tr`, `action_tr`,
  `do_nots_tr` and `ask_one_tr` in `tr` **and** `de`, and asserts
  `selectable_locales(pack) == {tr, de}`. With one locale registered a clamp to that one
  locale is invisible, so the registry is widened for the duration of that test only —
  `monkeypatch.setattr` on `protocols.locale_text.KNOWN_LOCALES`, reverted at teardown.
  No language is offered by this issue; the mechanism is what is being shown.
* Its near-miss, `test_dropping_one_of_the_four_in_the_second_locale_takes_it_back_out`,
  removes the `de` entry from **each** of the four in turn and asserts the answer falls
  back to `{tr}` every time. Removing the clamp did not remove the rule it stood in for:
  it made the rule apply to these four fields instead of standing in front of them.

## 4. Invariant 21, and the one place a locale could have reached it

Acceptance clause 4 says nothing here may let a locale change which action resolves for a
location. Two things make that true, and only one of them is new.

**The routing fields never moved.** `primary`, `secondary`, `show_112`, `numbers`,
`notify_staff_immediate`, `carry_child`, and the UNKNOWN branch's `on_yes` / `on_no` /
`on_no_answer` are single-valued and stay single-valued. `register` and `location` are
still required with no permitted default; the ON_SITE 112 interlock
(`_on_site_never_offers_112`, `ON_SITE_OFFERS_112` over the number list, the primary and
the secondary action codes) is untouched.
`test_a_locale_may_not_change_which_action_resolves_for_a_location` asserts a per-locale
value is **refused** for seven of those fields — it passed at red, which is the point: the
test exists to show the migration left them alone.

**The one field where text and routing meet.** `ask_one_tr` is text, so it moved; but its
answer picks ON_SITE or REMOTE. files/04 §8.2's `unknown_location_asks_exactly_one_question`
was checked against one string; it is now checked against **every entry in the map**, in
`unknown_question_refusals`. A language in which that question asked two things in one
breath would be a language in which nobody knows which one the patient answered — a locale
deciding which action resolves.

The limit of that is stated in the code and in the test rather than implied:
`_question_count` counts question marks, which is language-neutral, and then recognises a
comma-joined second interrogative by its Turkish suffix (*-mi/-mı/-mu/-mü*), which is
Turkish morphology and detects nothing in a language it was not written for. Running the
gate per locale extends the mark count to every language and **takes nothing away from
Turkish**. Naming another language's interrogative detector belongs with registering that
language at all (HB-O5, HB-C19), and no second language is registered.

Under ON_SITE the 112 affordance is still absent rather than de-emphasised, and the RED
script is still pre-positioned and triggered over the data channel: neither is touched by
a field's shape.
