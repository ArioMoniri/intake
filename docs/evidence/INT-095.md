## What this issue actually had to do first

docs/evidence/INT-094.md finding 1: *"The Layer A ↔ Layer B loop does not close on this
tree, at three joints … **A composed session cannot take one turn carrying a
transcript** … INT-095 cannot ship without all three, because there is no turn to
smoke-test."*

So the first two thirds of this work is the loop, and the adapters are the last third.
INT-094 asserted each joint so that wiring it makes a test fail; two of those assertions are
**struck** below and rewritten in their positive form, and the third — the one that says the
queue carries no transcript — is **kept**, because keeping it is the whole content of the
data-boundary decision.

## (a) The three joints, and whether the queue is still PHI-free

### Joint 1 — no module registered an `extract_slots` state handler

`services/voice-runtime/src/intake_voice_runtime/extraction/handler.py` is the body INT-083
owed: take the transcript, `run_extraction`, `engine.apply_extraction(**as_engine_call())`,
return an empty `StateEffect`. Four statements of substance, because everything interesting
already existed — INT-083's nonce-fenced boundary and schema-constrained call, INT-081's
reconcile-behind.

Registration is **not** the queue's and **not** the handler's. It is
`intake_voice_runtime/composition.py`, the one place in `services/` that calls
`register_state`, and a test pins that file list to exactly one entry. A `BackendAgent` built
by hand still raises `UnregisteredWorkType` — INT-092's fail-closed design is untouched, and
`test_a_bare_backend_agent_still_refuses_the_first_transcript` keeps saying so.

Four things the handler deliberately does not do, each for a reason stated in the file:

- **no `mark_asked`** (see joint 2 — this is how the losing reading is made unreachable);
- **no `speech_tr`** — `ExtractionResult` has no such field precisely so files/03 §4.9.6's
  numeric-pairing rule cannot be broken from here, and inventing a Turkish acknowledgement
  would be patient copy nobody signed off;
- **no `triage_update`** — running `packages/protocols/triage` from the handler is another
  issue's scope; invariant 1 is untouched in the safe direction, because an extraction
  cannot mint a level at all;
- **no widening of the declared slot set** — it is the Work's own step plus
  `EngineSnapshot.awaiting`, which is exactly the set `IntakeEngine._bind` will accept. A
  ref outside it could not bind, so offering it to the model would be inviting an answer the
  engine is about to drop.

### Joint 2 — `mark_asked` had no caller, and "asked" had two meanings

Settled in section (b).

### Joint 3 — `WorkRequest` had no transcript channel, and still has none

**The route: a per-session, in-memory, content-addressed vault**
(`intake_voice_runtime/transcript.py`). `submit_utterance` deposits the transcript and gets
back `sha256(text)` — the value `input_hash` already carried — and the state handler takes it
out by that digest. Two asymmetric ports: Layer A holds `TranscriptDeposit`, which has no
reader, and Layer B holds `TranscriptSource`, which has no writer, so the Talker cannot read
back a transcript it deposited.

**Is the queue still PHI-free? Yes, byte for byte.** No field was added to `WorkRequest` or
`WorkRecord`, no log line changed, no metric label changed.
`test_the_work_request_still_has_no_transcript_channel` is kept rather than struck, and two
more assertions were added around it: the record's `repr` does not contain the transcript,
and `input_hash` equals `SessionTranscripts.digest(text)`.

**The boundary crossing moved *earlier*, which is a gain.** The vault stores `PatientData`,
so INT-083's refusal of a planted control token now fires at deposit — **before** a Work
exists — and `test_the_boundary_refuses_an_injection_before_any_work_exists` asserts the
state lane is still empty afterwards. A handler cannot be handed a bare `str` at all: the
parameter type is the boundary type.

**Invariant 6, swept decoded.** `test_no_log_record_carries_the_decoded_transcript` drives a
real turn at `DEBUG`, joins every record's message *and* `json.dumps(record.__dict__)`, then
runs `.encode("utf-8").decode("unicode_escape")` over the join before asserting — because
JSON escaping is exactly how an escaped Turkish sentence hides from a substring check.

**What it costs, stated rather than hidden** (all three are in the module docstring):

1. **A Work is no longer replayable from its record alone.** A restart re-submitting the same
   transcript derives the same `work_id` (files/12 §7.5) but finds an empty vault, so the
   Work fails `TranscriptNotHeld` rather than extracting nothing. That is the fail-closed
   direction: an extraction that bound no slots is indistinguishable from a patient who said
   nothing. `test_a_work_whose_transcript_was_never_deposited_fails_closed` asserts the
   record carries `TranscriptNotHeld` and the slot stays unbound.
2. **The handler needs two objects rather than one.** The vault is bound at composition time;
   the take is the first statement the handler runs.
3. **It is process memory, so it cannot be wiped the way audio is.** Invariant 3 is about
   *audio* buffers and does not reach here; what applies is invariant 6 (nothing rendered,
   nothing logged) and files/10 §3's envelope encryption, which binds when a transcript is
   *persisted*. Nothing here persists: a process-local dict, never serialised, and `take`
   removes the entry as it hands it over. The vault is a bounded FIFO (16), so Layer-B
   starvation becomes a *visible* failed Work rather than an unbounded pile of patient text.

## (b) Which reading of "asked" — and how the other became impossible

**Spoken wins.** files/03 §4.5 marks a step when the answer arrives; INT-081's `mark_asked`
marks it `ASKED_PENDING` when it is spoken. Three reasons, in order of force:

1. **`ASKED_PENDING` is the ask-ahead bookkeeping state** (files/13 §9.3; ADR-011). Its whole
   purpose is that the frontier moves on *after the question goes out*. Marking at answer
   time leaves the step on the frontier for the entire time the patient is answering it — so
   the Talker asks it a second time. This was not hypothetical: the composed loop on `main`
   asked every question twice, and nothing caught it because nothing had marked anything.
   `test_a_step_is_never_asked_twice_across_three_turns` is the assertion that would have.
2. **The engine already refuses to bind to an unasked question.** `_bind` skips a ref that is
   not `ASKED_PENDING`, and its docstring says *"nothing binds to a question that was not
   asked"*. Marking at answer time makes that check a no-op ordering trick — mark then bind,
   inside one call — and lets an answer bind to a question that was never spoken.
3. **Invariant 10 makes it Layer A's fact.** A step is asked when its `text_tr` reached the
   patient. Layer A is the only component that witnesses that.

**How the other reading is now unreachable.** The engine write has exactly one producer, and
three tests pin it:

- `intake_voice_runtime/extraction/handler.py` contains no call to `mark_asked`
  (`test_the_extraction_handler_holds_no_call_to_mark_asked`);
- exactly one module in `services/` and `packages/` calls it, and it is
  `clinical_agent/work_queue.py` (`test_exactly_one_module_calls_mark_asked`, and INT-094's
  own assertion rewritten to the same list);
- the call site is `BackendAgent._apply_asked_notes`, fed only by `AskLedger.note_asked`,
  which is called only from `TalkerSession._note_asked`, which is called only after
  `speak_step` returns.

**Why the note travels instead of the lock.** `mark_asked` is a Layer-B write and the Talker
holds a read-only `EngineSnapshotSource`. The engine lock is held across a whole state
handler — an LLM call — so taking it on the speech path would break invariant 9's second
clause *inside the Talker*. So `note_asked` takes only the cheap `_queue_lock` and returns;
`run_pending` applies the notes under the engine lock **before either lane runs**, which is
load-bearing: files/13 §9.3 binds nothing to a step that is not `ASKED_PENDING`, so the
other order would drop every answer.

**The acknowledgement is eventual, so the turn holds rather than re-asking.** A new
`TurnHold.AWAITING_ASK_ACK`: if the snapshot still offers the step the Talker last spoke, *at
the same version it was offered at*, the mark has not landed and the question waits one pump.
The version comparison is what keeps a legitimately re-offered step (files/09 §3's
contradicted confirm re-opens the full ask) from holding forever. A refused note — a step the
frontier no longer offers — is recorded in `BackendAgent.refused_asks` and logged with the
step id (a protocol identifier, never patient text), not forced.

**One more thing had to move with it.** Once the frontier advances after a question is
spoken, `take_turn` can no longer attribute an incoming transcript to `protocol_next()` —
that is now the *next* question. It attributes to `_asked_step`, the step actually spoken,
and `submit_utterance` carries that step's own `engine_version` back (files/12 §7.2's
"tell a legitimate ask-ahead answer from one bound to an invalidated step" only works if the
version is the one the question was offered at).
`test_the_transcript_binds_to_the_step_that_was_spoken` asserts the turn *reports* step 2
while the Work it submitted names step 1.

the path: the TTS lane speaks the question, its WAV goes to the ASR lane, the transcription
goes through the **real** `ExtractSlotsHandler` to the extraction lane, and the engine
reconciles.

This is the acceptance line that is **not** fully satisfiable today, and the mechanism that
says so rather than papering over it. `intake_voice_runtime/adapters/pins.py` resolves a

|---|---|---|---|

| **2** ASR shadow/fallback | `turkmedstt/whisper-large-v3-turkish-medical` | `license: "UNVERIFIED (card tag apache-2.0, no blob)"`, no provenance block | `LicenceNotVerified` · **HB-I10** |
| **7** Talker LLM | `Qwen/Qwen3.5-9B` | `license: "Apache-2.0 (LICENSE blob verified @c202236)"` — **in prose**; no `licence_verified_at`, no blob url, no blob sha256, no `weights_sha256`, and `c202236` is an abbreviated revision the registry's own 40-hex pattern would reject | `LicenceNotVerified` · **HB-I10** |
| **10 · 11** TTS clip + dynamic | `openbmb/VoxCPM2` | the full INT-243 block: revision, two weight hashes, `licence_verified_at`, blob url, blob sha256, and a note recording that the weights repo has no LICENSE at any revision so the grant was read from the vendor source repo | **pinned and verified** |

**Named asks, both filed:**

- **HB-I10** — read the raw LICENSE blob at a pinned revision and hash the mirrored weight
  files for rows 2 and 7, so their registry rows carry `model_id@revision` + `weights_sha256`
  + `licence_verified_at` + the blob url and sha. Three values per row, none of them
  derivable from this laptop. Row 7 is the sharper case: somebody *did* read that blob, and
  the row does not record which bytes they read, so an auditor cannot re-check it — invariant
  19's *"recorded with `licence_verified_at` in the model registry"* is not satisfied by a
  sentence in a `license` string.
- **HB-I11** — is row 1 obtained, mirrored, hashed and served (NeMo/Riva is a serving runtime
  nothing in this repo runs), or is the row withdrawn and row 2 promoted? That is a stack
  decision with a Q9 consequence, because row 2's own evidence is *3 speakers, 120 clips,
  synthetic-TTS training data*.

**Nothing was invented to get past either.** `resolve_pin` hands out a `ModelPin` whose
`model_id`/`revision`/`licence_verified_at` may be `None`, and each `None` is a *finding*
rather than a default. `require_phi_path_pin` is where they bite; a dev/synthetic lane builds
and records the unverified pin it is running, which is what the registry's `host` fields
already say in prose, made mechanical. A span for an unpinned row carries
`<component>@unpinned` — deliberately not hash-shaped, so an auditor sees a gap rather than a
value they might try to look up.

`unverified_rows()` returns `(1, 2, 7)` and a test pins it, so the list cannot quietly grow.

## Preemptive generation — the LLM only

`talker/speculation.py`. `PreemptiveGeneration` takes **one** collaborator, a text producer,
and has no parameter, attribute or method through which a `SpeechSynthesizer`, a `ClipStore`
or an `AudioSink` could reach it — asserted by introspection over the constructor signature
*and* over the instance's attributes, so a field added later fails the test. What it produces
is a `Speculation`: a step id and a string, frozen, with no `audio`, no `clip_id`, no
`frames`. There is no expression that makes this class produce sound.

Three states, one rule: `speculate` → buffered → `confirm_end_of_utterance` → released;
`resume_speech` → **discarded, never stored**, because a speculation generated against a
partial utterance the patient then continued answers something they did not finish saying
(files/13 §11.3's discipline, applied to speech).

`TalkerSession.observe_duplex` drives it and the gate is genuinely three-valued: speaking →
discard; silence past the adaptive floor → confirm; silence *below* the floor → hold the
buffer, because that is files/03 §4.4b's handover gap, *"a turn boundary, never silence and
never an answer"*. `patient_holds_floor` could not be reused for this — its
`patient_speaking` conjunct makes a session nobody has spoken in indistinguishable from a
completed turn, which is right for asking the first question and wrong for confirming an end
of utterance.

**A release still passes invariant 10.** `take_turn` hands a released speculation to
`speak_step(step, paraphrase=…)`, which routes it through `SpeechRouter.text_for` — so a
speculation for a **scripted** step raises `ParaphraseNotPermittedError` rather than being
spoken, and a speculation for a different step is dropped rather than spoken. Both asserted.

## No PHI-path egress — and the gate that improved the design

The fourth acceptance line, from both ends:

- `test_the_allow_list_names_no_external_model_or_speech_vendor` walks both tiers of
  `infra/security/egress-allowlist.yaml` against `VENDOR_LLM_DOMAINS` (imported, not
  restated) and then **runs** `assert_dev_only_vendors(allowlist)` rather than reimplementing
  invariant 19's own check;
- `test_the_phi_tier_reaches_no_model_host_at_all` — the `phi_path` tier carries no
  `model_weights` purpose at all;
- `test_a_call_to_an_unlisted_host_is_still_refused` — INT-018's default deny, decided
  through the real `EgressPolicy`.

**And the adapters refuse a public host outright.** `refuse_external_host` permits loopback,
private/link-local addresses and cluster-internal names, and refuses everything else. It is
default deny, deliberately **not** a vendor blocklist.

**That design is the CI gate's doing, and the gate was right.** The first draft named the
four vendors files/03 §1 deletes. `scripts/ci/assert_no_vendor_calls.sh` failed the build:

```
FAIL: live vendor endpoint referenced outside files/ (the historical record):
./services/voice-runtime/src/intake_voice_runtime/adapters/speech.py:91:    {…four vendor hosts…}
./tests/voice/adapters/test_residency_contracts.py:701:            HttpTranscriber(endpoint="…")
```

A blocklist of four vendors is one a fifth walks past, and writing those hostnames down is
exactly what that gate exists to prevent. The replacement is strictly stronger and the module
now spells no vendor hostname at all. Two notes for whoever hits this next: the gate also
scans `.hypothesis/constants/`, which caches string literals from source files, so a stale
cache keeps failing after the source is fixed — clear it; and the tests use RFC 2606/5737
reserved names, because a test that spells a vendor host to prove it is denied is the one
place they come back.

**The most valuable failure is the first one, and it is a finding rather than a bug.** Twelve
of those failures share one cause: the composition root could not build at all, because

```

   (files/03 §4.9.1 row 7) carries no model_id@revision provenance block, so there is
```

The first design made *any* pin a hard requirement and the tree does not have one for row 7.
Backfilling it would have meant inventing a revision and two weight hashes — the plausible
number Rule 1 forbids — so the refusal was split instead: `PinNotRegistered` for a row with
no registry entry, `LicenceNotVerified` for one with no dated blob reading, `PinNotPinned`
for one whose licence *is* verified and whose provenance block is absent. Section (d) is that
split, and HB-I10/HB-I11 are the asks it produced.

Two of the other failures were my own tests being wrong rather than the code
(`assert "mark_asked" not in handler` matched the module's own *docstring*; a
`pytest.raises(ValueError)` against a `RuntimeError` subclass), and both are recorded because
a green obtained by editing a test deserves to be visible.
