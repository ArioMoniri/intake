## What changed

- `RedactingSpanExporter` wraps whatever exporter `setup_otel` attaches —
  there is no code path that exports an unredacted span. Every string
  surface (name, attributes incl. sequences, event names + attributes,
  status description) passes `redact_text`.
- Collector: `transform/redact` gains `trace_statements` (span + spanevent
  contexts) and `metric_statements` (datapoint context) with the same
  TCKN/PHONE/IBAN patterns, and is wired into the traces and metrics
  pipelines.
- Same documented caveat as the log layer: patterns catch identifiers, not
  free-text names — the closed attribute allow-list and the deid gateway
  (INT-015) own those surfaces.
