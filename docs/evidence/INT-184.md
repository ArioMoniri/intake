## Acceptance, verbatim — one line, one artefact

- **"branch x maturity matrix"** → `renderCoverageMatrix` in `apps/admin-web/src/protocols/module.ts` paints one row per taxonomy branch against its resolution status and pack maturity (DIRECT/CLUSTER served L1+, else the L0 draft named but not counted, else EXCLUDED). The data is `protocols.taxonomy.coverage` run over the real taxonomy + pack tree, recorded into `apps/admin-web/e2e/fixtures/protocols.payload.json` by `scripts/dev/record_protocols_fixture.py`. Tests: `branch x maturity matrix > …` (6 cases, incl. the invariant-13 refusal `L0CountedAsCoverage`).
- **"approve/reject with 4-eyes"** → `renderReviewQueue` computes an approve and a reject `Control` per proposal row: approve is enabled only when the server's verdict is approvable AND the viewer is not the author AND the evidence bundle is complete; the author may neither approve nor reject their own proposal. A tampered body that asserts an author-approvable or evidence-incomplete-approvable row is refused (`SelfApprovalWouldBeRendered`, `IncompleteEvidenceApprovable`); a change outside the proposal-only vocabulary, or a candidate flag above `YELLOW_REVIEW`, is refused (`ForbiddenProposalTarget`). Tests: `approve/reject with 4-eyes > …` (8 cases).
- **"clip coverage per voice"** → `renderClipCoverage` paints one row per spoken voice under `residency_tr` (VoxCPM2 primary, Freya session-start fallback per files/03 §4.9.1 rows 10-12); `typed` carries no clips ever (`ClipsUnderTypedProfile`), counts are non-grouped atoms (invariant 22), and counts that do not reconcile are refused (`InconsistentClipCounts`). Tests: `clip coverage per voice > …` (4 cases).

## The one decision that shapes it

Like the Models (INT-183) and Compliance (INT-189) modules, **the console renders the source, it does not keep one.** The three surfaces are pure, typed projections of real data, recorded into one composite fixture by `scripts/dev/record_protocols_fixture.py` so the spec asserts against what the sources actually say rather than a hand mock (invariant 13, invariant 17):

- coverage ← `protocols.taxonomy.coverage(load_registry(...), load_taxonomy(...))`
- the review queue's vocabulary ← `intake_learning.proposals.PROPOSAL_TARGETS`; its unmet checks ← `intake_learning.evidence.REQUIRED_CHECKS`
- clip voices ← `intake_voice_runtime.profiles.VoiceProfile` + the files/03 §4.9.1 TTS registry components

The recorded state is the honest current state: **92 branches, 91 MISSING and Acil Tıp EXCLUDED, because the whole pack tree is L0 today** (91 generated drafts, no cluster packs) — which is exactly the state invariant 13's matrix exists to surface. The review queue is a **genuine empty list** (there is no persisted proposal store; the PR-bot opens PRs and a CODEOWNER clinician approves), and every evidence bundle is incomplete today because its producers (INT-153/059/116/173/175) are later issues — so no proposal can currently be approvable, which the module renders honestly. The four-eyes / approve-reject / forbidden-target mechanism is exercised with near-miss rows constructed inline in the spec, the same convention `compliance.spec.ts` uses for its emptyable surfaces.

## Invariants touched — named individually

- **Invariant 13** (branch → L1+/cluster; L0 never served): the matrix is `coverage()` verbatim; `L0CountedAsCoverage` refuses any row that renders an L0 pack as coverage or a non-resolving row that names a served pack. Tested.
- **Invariant 12** (learning is proposal-only): the review queue approves/rejects PROPOSALS from the closed `PROPOSAL_TARGETS` vocabulary and never edits a red-flag level, instrument, consent text, Talker tool or routing; `ForbiddenProposalTarget` refuses anything else. The actual apply flows through the PR + CODEOWNER path, not this console. Tested.
- **Invariant 1** (LLM-derived flags cap at `YELLOW_REVIEW`): a candidate flag carrying any other level is refused. Tested.
- **Invariant 4** (four-eyes + audit on every admin action): approve/reject are two-person controls (an author may not approve or reject their own proposal); `SelfApprovalWouldBeRendered` refuses a payload that contradicts that. The mutation, its audit and the four-eyes ceremony are the INT-180 shell's `FourEyesService` + audited routes, reused, not re-implemented.
- **Invariant 6** (no PHI/PII): every surface is ids, counts and closed-enum values — branch ids, pack ids, proposal targets, actor ids, clip ids. No transcript, no free text.
- **Invariant 22** (numbers as guarded atoms): clip counts render with `useGrouping:false`, no separator a reader could misread. Tested.
- **Invariant 17** (no placeholders / real data or a genuine empty state): every field is projected from a real source; the empty review queue and zero clip coverage are the honest current state, each with a note explaining why. No demo/lorem data outside the fixture.
- **Invariant 20** (no accuracy claims): no sensitivity/WER/accuracy figure appears; the only numbers are coverage counts and clip counts.
