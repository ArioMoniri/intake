# Evidence — INT-318 · Acıbadem appointments read source, `/v1/visits/sync` and the phone-first login it feeds

GitHub #603 · epic E10-connectors · phase P1 · Sec-Row `connectors` · slice **S2** of INT-354
(int-demo → main). Depends on INT-160 (connector framework) and INT-131 (OTP tier).

After OTP verification, a signed-in patient's app sends its own verified phone to
`POST /v1/visits/sync` and gets back that patient's upcoming visits from the hospital's
appointments feed. The connector mechanism below carried from int-demo unchanged. The server
route was **rebuilt**. On int-demo it built its source row in code: three `dev-…` binding refs
that named no signed agreement and no recorded approval, a plaintext approval granted whenever
the base URL said `http`, and `core` standing in for the read's purpose. Two environment
variables made it live, whatever `infra/connectors/sources.yaml` said (audit 2026-09-26 **F06**,
§6 item 8). On main the row comes from that file and from nowhere else. The file ships with
`sources: []`, so the route answers `unavailable`.

### The rebuilt route (`services/api/src/intake_api/visits_acibadem.py`)

- **The registry is the only way in.** `acibadem_client_from_registry(settings.clinical_sources_path)`
  loads the file through the connector's own schema. The client is built only when exactly one row
  names the `acibadem-appointments` adapter. It is not built for zero rows (as shipped), for two
  rows, for an unreadable file, or for a row the schema refuses: `http` without a recorded
  plaintext decision, a purpose outside the closed INT-038 registry, or a hostname where a private
  literal belongs. OpenBao is asked only once a row exists, and the credential is read there by
  the row's `credential_ref` (invariant 14). `INTAKE_CLINICAL_SOURCES` may point the API at another
  registry file. Nothing else can supply a row, and the int-demo variables are no longer read
  anywhere.
- **The row's purpose.** `core` is enforced at the door by `require_scopes`, as on every
  `/v1/visits` route. The read itself then clears the purpose the **row** names through
  `ensure_consent`, which includes staleness and the INT-223 age gate. The audit entry names that
  purpose.
- **The row's tenant.** A row serves only the tenant it is registered for.
- **Carried hardening:** `require_scopes`; a hash-chained `api.visit.acibadem.sync` audit entry
  holding ids only; `resolve_identity`, whose ambiguous result is terminal for a shared handset;
  the ownership re-check through `OtpAuthService.pseudonym_for` before the feed is touched.
- **Fail closed, never a 500.** No row, a row for another tenant, the `INTAKE_ALLOW_LAN_SOURCE`
  gate off, or a credential OpenBao does not hold all answer `unavailable`, and nothing is sent. A
  dropped link, a timeout or a non-200 from the hospital answers `upstream_unavailable`. Both are
  200 with no visits.

  lists was put back, and every one was caught.
- **Stand-in scope:** `assert ['READ_SCOPE'] == []`, which is the module-level `"core"` constant.
- **Core alone:** `assert 200 == 403`. A row registered for another purpose was read on `core`
  alone.
- **Another tenant's row:** the feed was read for a patient outside the row's tenant (`no_upcoming`
  where `unavailable` was expected).
- **Runtime gate off:** `500 Internal Server Error`. `EgressDenied` escaped the route.
- **Wiring from the file:** the int-demo route never reads the registry (`None is not None`, and

## 4. What the owner must register for a live hospital feed

The mechanism is complete and wired, and it refuses until all of the following exist. None of it
is an engineer's to supply.

1. **One row in `infra/connectors/sources.yaml`**, in the shape the file's own comment gives:
   - `adapter_id: acibadem-appointments`;
   - the hospital host's RFC 1918 `address` and `port`, with `protocol` and `base_path`;
   - `tenant_id`: the tenant whose patients it serves. For the phone-first login that is the
     consumer tenant the OTP tier creates accounts in;
   - `consent_scope`: a purpose from the closed INT-038 registry. Reading a hospital record is not
     yet one of them. Adding it needs its Turkish açık rıza text and counsel's signature
     (**HB-L27**);
   - `dpa_ref`: the executed DPA (**HB-A15**);
   - `approval_ref`: the recorded tier-3 approval (**HB-A15**);
   - for `http`, `plaintext_approval`: the recorded decision to carry TC Kimlik numbers, mobile
     numbers and names unencrypted;
   - `credential_ref`: an OpenBao path under `connectors/`.
   Which interfaces the partner really exposes is still unverified (**HB-A5**).
2. **The API key in OpenBao** at that `credential_ref`, under the key `api_key`.
3. **`INTAKE_ALLOW_LAN_SOURCE=explicit-yes`** on the API host. This is the operator's runtime half
   of the double default-deny.
4. Then, as its own change, lift the mobile `if (__DEV__)` gate on `syncVisits`, so release builds
   call the route.
