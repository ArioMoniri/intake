# Evidence — INT-318 · The Acıbadem connector reaches the app: a logged-in patient's own upcoming visit on "Bugün"

Epic E11-connectors · phase P2 · `sec_row: connector-read` · depends on the INT-160/161
connector framework and INT-131 (OTP tier).

The one missing piece between a working OTP login and the "Bugün" (Today) screen showing a
real visit: `POST /v1/visits/sync` resolves the signed-in patient's **own** verified phone to
their Acıbadem appointment record and returns the upcoming visits the app renders.

The route existed as a demo skeleton (`b2301f8`, mobile + backend); this issue **hardens it to
gate-passing** and adds the tests it shipped without (its local hooks were skipped). Four defects
are closed, each an invariant:

1. **Consent (invariant 4) is now declared and enforced.** `require_scopes("core")` on the route
   (INT-038) replaces an ad-hoc `SELECT` on the consent table, so the read now goes through the
   one `ensure_consent` evaluator — which means text **staleness** (INT-038) and the **age/guardian**
   gate (INT-223) apply, and the INT-038 route-scan (`unguarded_data_routes`) stops flagging
   `POST /v1/visits/sync` as an undeclared data route. `core` is a **dev-tier stand-in**: the
   canonical purpose for "read a patient's hospital record" is not in the closed `06 §2` registry
   and `docs/legal/` binds no text for it (HB-L27). The mechanism gates and audits correctly; the
   purpose is awaiting-human.
2. **The disclosure is audited (invariant 4).** The feed read now appends a hash-chained
   `api.visit.acibadem.sync` entry (`scope:core`, ids only — the resolved hospital-side
   `patient_number`, never the name or phone — invariant 6). The skeleton wrote none.
3. **The shared-handset leak is closed.** The skeleton took `next(u for u … if u.msisdn == phone)`
   — the **first** phone match. A number shared by two patients (ordinary in Türkiye; the measured
   feed has one) would have shown the first patient's visits to the second. Identity now goes
   through the connector's `resolve_identity`, whose `refused_ambiguous` is terminal: a shared
   handset the feed cannot disambiguate returns a clean "couldn't identify you", never a guess.
4. **Ownership (invariant 14) is unchanged in intent, cleaner in form.** The submitted phone must
   tokenize to the caller's own pseudonym (the same normalisation + tokenisation the OTP tier keyed
   the account by, now via `OtpAuthService.pseudonym_for` rather than reaching into `_tokenizer`),
   so a patient can never learn another patient's visits by submitting their number, and the raw
   phone reaches no app table.

The client is injected (`state.acibadem`), so the unit lane drives it over an `httpx.MockTransport`
and never dials the network; production builds it from `ACIBADEM_BASE_URL` + `ACIBADEM_API_KEY`
(no in-code default) and the read still clears the `LanSourcePolicy` runtime gate
(`INTAKE_ALLOW_LAN_SOURCE=explicit-yes`). Two packaging defects the skeleton left were also fixed:
`intake_connectors` had no `py.typed` marker (so `services/api` importing it was `import-untyped`
under `mypy --strict`), and `services/api` imported it without declaring the dependency.

* `test_matched_phone_returns_its_own_upcoming_visits` — single feed match (FATMA KAYA, the
  synthetic analog of the live single-match case) → the 2021 row filtered, both 2026-09-05 visits
  returned earliest-first (`13:00 Kardiyoloji`, `13:05 Kadın Hastalıkları ve Doğum`), distinct ids,
  display name `Fatma Kaya`.
* `test_patient_a_cannot_read_b_by_submitting_bs_phone` — **A submits B's number → `not_your_number`,
  and the request counter proves the feed was never consulted** (`feed.calls == []`).
* `test_shared_handset_is_a_clean_refusal` — a number two patients share, neither with a TC →
  `ambiguous`, no visits, no name; the directory was read once and no per-patient fetch followed.
* `test_unknown_number_returns_empty_not_error` — a valid mobile absent from the feed → `no_appointment`, `[]`.
* `test_only_past_visits_returns_empty` — all rows in the past → `no_upcoming`, `[]`.
* `test_absent_core_consent_is_refused_before_the_feed` — no `core` grant → `403 {consent_required, core}`,
  feed untouched.
