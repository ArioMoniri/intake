## 7 · The capture session (route d, coordinator's decision of 29 Oct 2026)

Nothing server-side runs on the Mac. Only the simulator and the build tooling do.

1. Wait until the host carries the build-6 sha (the coordinator's message). The capture API
   runs whatever image the public API runs, and refuses an image that is not a pinned
   synthetic release.
2. `make asc-capture-api-up PORT=<free port>` prints
   `capture_api: up 127.0.0.1:<port> intake-staging/api:<sha>`.
3. `make asc-capture-forward PORT=<same>` (leave it open). The Mac's :8000 is now the
   capture API.
4. Run a development build of the same sha on the iPhone 17 Pro Max simulator (iOS 26.5).
   Create a fresh account through phone sign-in with the dev OTP peek, using a synthetic
   number. Never the owner's number, and never a dev fixture account: the fixture carries a
   real hospital name. Walk the frames with typed answers from the served pack. The new-visit
   form requires a hospital (`visits.ts`), so enter the generic facility type
   "Aile sağlığı merkezi", never a proper name.
   - A Release build cannot be used here. `apiBase.ts` refuses an http or loopback base, and
     App Attest does not run in the Simulator.
   - This app has no expo-dev-client, so a Debug build shows no launcher and no gear.
   - A Debug build cannot run on an embedded bundle without Metro. Tried on 29 Oct: Expo's dev
     runtime stops at "Cannot create devtools websocket connections in embedded
     environments". So the JavaScript comes from Metro on the build sha, for the capture
     window only.
5. `make asc-capture LOCALE=tr APP_SHA=<sha> [VISIT=<id>]`, then `LOCALE=en-US`. Each shot is
   checked against the must-not-show list, and `provenance.yaml` records the hashes.
6. `make asc-capture-api-down` prints `capture_api: down` and removes the container, the
   network, `intake_capture` and Redis index 7.
7. After the legal lane promotes the captions: `make asc-frames`, then fill the manifest's
   file lists.
