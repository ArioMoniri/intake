## Content-freedom, and how I tried to break it

"No PHI in a push" is normally implemented as a denylist scan, which fails
the moment somebody interpolates a value nobody thought to forbid. The
property enforced here is the complement, and it is airtight in a way a
denylist cannot be:

**Every notification body is a constant, and every token of a rendered
payload must already appear in the committed template corpus.** `render()`
takes a `ReminderKind` and a `Locale` — two closed enums — and returns
committed text. There is no format string, no `%s`, and no parameter through
which a slot value, a branch label, a clinician name or a document title
could arrive. `assert_content_free()` proves the closure on the way out of
the dispatcher, so a template that later grows an interpolation slot fails at
dispatch rather than in review.

Two structural consequences, both deliberate:

- Timing lives in the *template*, not in the body: "tomorrow" and "coming up"
  are different templates, so the choice among them depends on the reminder
  kind alone and never on anything clinical.
- The deep link is a `DeepLinkRoute` enum member with no identifier in it. A
  link to `/visits/<uuid>` would put a linkable reference on a lock screen
  (files/10 §4: no PHI in push notifications *or deep links*).

### What I attacked it with

| attack | result |
|---|---|
| The body a well-meaning engineer writes — "Kardiyoloji viziteniz yarın saat 14:00." | Caught. `kardiyoloji` and the numeral `14` are both outside the corpus (a numeral in a body is data too). |
| **The adversarial patient**: her branch is `Kadın Hastalıkları ve Doğum`, whose word "ve" also appears in generic copy ("… uygulamayı açın **ve** kaldığınız yerden …") | The scan stays silent on "ve" — a word present for every patient carries no information about any one of them — and still reports the branch on "Kadın" alone. Both directions are pinned; a scan that fired on "ve" would fire on every message and be switched off within a week. |
| A branch whose tokens are *all* generic, so no token is evidence | Caught by the whole-phrase check: the phrase itself is the disclosure. |
| Turkish casing — `KADIN` | Caught. `"KADIN".lower()` is `"kadin"` in Python and `"kadın"` in Turkish; `folding.fold` maps `İ→i` and `I→ı` before lowering, so the shouted form does not slip past. |
| The **whole wire payload**, not just the body: `SealedMessage.as_wire()` serialised to JSON, for every kind | Nothing leaks. The field list is enumerated by hand rather than reflected, so a field added upstream cannot silently join the payload. |
| The **log lines** the dispatcher emits, for every kind | No body, no title, and not even the tokenized recipient handle — a pseudonym in a log line is still an identifier (invariant 6). |
| A `ContentLeak` exception message | Names the template and a *count*, never the offending words: those words are by hypothesis the patient's data, and a leak detector that logs the leak is not a detector. |
| The mobile app assembling its own body | Refused by test: no `expo-notifications`, no `scheduleNotificationAsync` anywhere under `apps/mobile/src`. A client that schedules its own reminder builds it from the visit, the branch and the slots it has to hand — which is the disclosure. |

## The İYS gate

The requirement is not "check before sending"; it is that the code be
**unable** to send a marketing-class message without a recorded İYS consent.
Four independent locks, each sufficient on its own:

1. **No commercial template exists.** Every catalogue entry is
   `TRANSACTIONAL`, and the builder takes a `ReminderKind` — an enum with no
   commercial member. There is nothing to send.
2. **Type lock.** `IysConsentRecord` is an ABC with abstract members and
   **no concrete subclass anywhere under `packages/` or `services/`** (an AST
   scan asserts this, so a future adapter is a reviewed change rather than a
   silent one). `IysConsentRecord()` raises `TypeError`, so no value of the
   type exists to pass and `seal_commercial(...)` cannot be *written*, let
   alone reached. `mypy --strict` rejects the call too.
3. **Registry lock.** The only implementation, `UnconfiguredIysRegistry`,
   raises on every lookup — it does not answer "no record", because a false
   negative and an honest one must not look alike.
4. **Flag lock.** `commercial_messaging` joins `SAFETY_FLAG_DEFAULTS` at
   `False`, where a call-site default cannot open it.

The dispatcher's own entry point is the fifth thing worth naming: `send()`
takes a `ReminderKind`, so there is no argument that could carry a campaign
through it. A test proves the gate is the *record* and not an accident of the
catalogue — given a fixture record and an open flag (both of which exist only
inside the test file), sealing works and is tagged `COMMERCIAL`.

**The İYS record shape is deliberately not invented — this is the ask.**
files/06 §1 names the obligation and no file in the tree names a field: there
is no İYS integration contract, no `iys_id`, no consent-date format, no
*hizmet sağlayıcı* code. So the type declares what any record must be able to
answer — a registry reference and a recorded-at instant — and stops.

## Quiet hours: no window is shipped, and why

files/10 §9 names the control ("content-free pushes, quiet hours, opt-out")
and **no file in the tree names an hour**. Writing 22:00–08:00 would be a
value chosen once by an engineer for every future patient with no diff that
makes it look wrong — precisely what HUMAN_BLOCKERS rule 1 forbids. So the
baseline window is `None` by default and the dispatcher **refuses**
(`REFUSED_QUIET_HOURS_UNSET`) rather than guessing. A reminder is a
convenience; not sending one is the safe direction, and the mechanism is
built, wired and failing closed exactly as rule 2 requires.

The patient's own window and the baseline **union**, never intersect: a
patient who adds a quiet afternoon gets it; a patient whose window says
nothing about the night does not thereby unlock the night. The clock is
Türkiye's fixed +03 (the one jurisdiction this product encodes, mirroring
INT-223's `jurisdiction_tr_only`) — evaluating a local window in UTC would
wake a third of the country three hours early, and a per-patient timezone
column would collect a location signal to solve a problem we do not have.

The app offers three preset windows and pre-selects none. Presets are an
affordance, not a default, and they keep free numeric entry out of the screen
(invariant 22).

## Opt-out, and what I can and cannot say about the law

**What I actually read**: files/06 §1, row `6563-İYS` — *"Appointment/service
messages are non-commercial; **any** marketing message requires İYS-registered
consent; sender records kept."* That tells me service messages sit outside
the *consent* requirement. It does **not** tell me there is a statutory
opt-out right for them, and I have **not** read the Ticari Elektronik
İletiler Yönetmeliği (RG 29417, 15.07.2015) itself, so I am not citing it for
anything — including for a permitted sending-hours window, which is one of
the asks below.

So the position taken here is a **product choice, stated as one**: opt-out
suppresses every class this dispatcher can send, transactional included. It
is pinned by test so it cannot be quietly narrowed to marketing later.

The duties that genuinely cannot be opted out of — a KVKK m.12 breach notice
to the data subject, a KVKK m.13 answer to a rights request — are **not
reminders and do not route through this dispatcher** (they belong to INT-214
and INT-037 respectively). That is why no "statutory, ignores opt-out"
message class exists here: a bypass nobody can reach is still a bypass
somebody can widen.

## The blocked live path

**No push or SMS vendor is contracted.** Per CLAUDE.md there is therefore no
fake sender: `UnconfiguredTransport` is what the app wires and it raises
`TransportUnconfigured`; the dispatcher reports
`BLOCKED_TRANSPORT_UNCONFIGURED` rather than crashing, because "no vendor is
contracted" is a state of the world a scheduler should record.
`RecordedTransport` replays committed responses from
`tests/fixtures/notifications/` for the test lane and refuses to invent one
that was never recorded — the same recorded-fixture posture the TTS gateway
takes. The recorded files are the port's own receipt shape, not any vendor's
wire format; a real vendor's responses replace them with the adapter
unchanged.

## New persisted data (invariant 18)

One new table, `notification_preferences`, migrated in
`migrations/versions/0005_int141_notification_prefs.py` with RLS ENABLED and
FORCED, the same `app.tenant_id` GUC policy every tenant-scoped table carries,
`SELECT/INSERT/UPDATE` for `app_rw` and **no DELETE grant** (the row leaves
through the retention engine's crypto-shred path with the record it
configures).

Every column carries the inventory annotation. Category
`operational_metadata` — a delivery preference is not health data and the
VERBİS export must not file it as such. Basis `KVKK m.5/2-c` (the reminder is
part of the service the patient configured, and the register is what makes
the refusal exercisable). Retention: files/06 §3 has **no row** for a
notification preference, so rather than invent a clock the column rides the
matrix's existing record clock, and says so in the annotation.

What the row does **not** hold: no device token, no push handle, no phone
number, no timezone, no free text (invariant 14). Two integers, a flag and a
timestamp. Delivery addressing belongs to the transport and the vendor
contract that does not exist.

## Why the routes carry a marker instead of a consent scope

`/v1/me/notifications` declares the new `notification_preference` marker,
caged to its own prefix, rather than `require_scopes("core")`. Gate a
message-refusal register on a consent scope and you build a state in which the
patient who withdrew `core` can no longer reach the switch that stops the
messages — the same trap the DSAR routes documented, and the reason a right of
refusal has to be exercisable at any time. A test pins that a patient who has
withdrawn `core` can still read and set the preference.

Nothing else relaxes: patient-only (`require_patient`, clinic admin gets 403),
own row only, every read and change appended to the hash-chained audit
against `basis:6563-IYS` with a patient ref and nothing else. The route-table
scan still refuses silence, and a near-miss control proves the marker cannot
be borrowed outside its prefix (`/v1/me/notificationsish` and `/v1/sneaky` are
both still reported as undeclared).
