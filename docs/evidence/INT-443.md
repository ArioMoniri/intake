# INT-443 — ElevenLabs as the hosted TTS provider, default on the synthetic AWS host

GitHub #753 · Sec-Row `cloud-clipgen` · ADR-035 (amended) · split row 8 of INT-428 · branch `int-443-elevenlabs-hosted-tts`, stacked on INT-442 (#751 underneath) and on #734 (INT-424, the v2 profiles)

## Goal

Acceptance, verbatim (GitHub #753):

> - An ElevenLabs adapter in the hosted TTS lane that speaks catalogue or scripted text only, using the v2 profiles and eleven_multilingual_v2. The cache is keyed by profile@version.
> - It is the default TTS on the synthetic host once its key and egress row exist. The mobile client plays it gaplessly, and voice-e2e confirms the lane.

The coordinator added the George-on-AWS checklist from INT-428:

1. mount the route on the synthetic non-prod environment on purpose, and keep it unmountable on PHI;
2. read the key from OpenBao;
3. ship the catalogue;
4. size the budget to a session and stop charging cache hits;
5. give the cache a persistent, pre-baked directory;
6. the egress row is INT-442's owner commit;
7. `require_patient` stays as it is.

## What landed

- **The adapter.** `intake_hosted_lanes.elevenlabs.ElevenLabsHostedTts` lives in the synthetic image's package and is a `voice_clips` `TtsGateway`. Before the wire it refuses, in order:
  - a numeral or markup (`assert_speakable_tr`: invariant 22 and INT-424);
  - any text off the server's catalogue (`admits` is required, with no default);
  - a `red` profile (invariant 21);
  - a profile tuned for another model;
  - a voice id that is not an opaque token.
- **The request** is ADR-028's clip-gen request: `eleven_multilingual_v2`, the vendor normaliser off, the v2 profile's `voice_settings`, raw PCM back.
  - It goes through `guarded_client` under `hosted_model_inference` on `NON_PERSONAL` data, and through the INT-442 proxy.
  - The host is read off the allow-list row `elevenlabs-api` and is never written in code.
  - The key comes from OpenBao `secret/model-lanes/providers/elevenlabs` through the vault. `ClipVendor.ELEVENLABS` sits beside `ProviderId`, so the key vault can hold it, but it is not a model lane.
- **Failures are classed:**
  - `HostedTtsRefused` is a pre-wire refusal. It never falls back.
  - `HostedTtsUnavailable` covers no key, egress denied, unreachable, a non-2xx and a malformed body. Here a fallback may serve.
  - Every failure is a code: the input, the key and the vendor body are never in a message or an exception chain.
- **On the synthetic host it is the George route's lane** (`intake_api.hosted_clip_lane`). `george_wiring_from_env` builds it when the image's baked `synthetic` class and the compose's `INTAKE_HOSTED_TTS=elevenlabs` are both present:
  - the key store is OpenBao (`SecretsProvider`);
  - the cache is `INTAKE_HOSTED_TTS_CACHE_DIR`;
  - the fallback is the self-hosted TTS, only when both an endpoint and a fallback voice are set.
  - Without the allow-list row the lane is unconfigured, and the route answers 503.
- **The mount rule** (`george_route_mountable`): never in prod; mounted in dev; otherwise mounted only on the synthetic deployment that declares the lane. A PHI deployment never mounts it, whatever it declares.
  - `INTAKE_DEV_GEORGE_TTS` is not the switch on AWS, because INT-325 refuses to boot with any `INTAKE_DEV_*` outside dev.
  - The rule matches INT-421's `is_dev_env`, so a merge with #723 keeps both.
- **The catalogue.** No pack compiles on today's tree (HB-C1), and the dialogue does not speak pack `text_tr` anyway: it speaks `speech.ts` over the i18n question catalogue.
  - `apps/mobile/src/lib/dialogue/scriptedCatalogue.ts` enumerates exactly that composition: every spoken question, plus every confirmation with no value or one option. That is 319 rows and 26 193 characters, all `routine`. A text any guard would refuse is left out.
  - `scriptedCatalogue.test.ts` holds the committed `scriptedCatalogue.tr.json` byte-equal to the code.
  - The server loads it next to the compiled manifests and validates it as a whole. A numeral, markup, a RED or unknown context, a duplicate, an extra key or another locale refuses the file.
  - The image ships that one file of `apps/` and nothing else.
- **The cache and the lane record.**
  - Clips are keyed `delivery.<context>@v<version>/<clip_text_hash>`. With INT-424 merged that is `delivery.routine@v2`.
  - They are written atomically onto the `george-clips` volume. The image creates the mount point for uid 10001.
  - A fallback clip lives under `self_hosted/…`, so the vendor is tried again on the next request.
  - Each response says `X-Clip-Lane: elevenlabs | self_hosted` alongside `X-George-Cache`, and `api_clip_lane_total{lane,cache}` counts it. The metric is catalogued.
- **The budget.**
  - Charged: a cache miss and a refusal.
  - Free: a hit, which dials nothing.
  - The burst is 60: thirty questions in a detailed intake, each pre-warmed with its confirmation. The refill stays 0.5/s.
- **The pre-bake and the probe** (`python -m intake_api.george_prebake`) use the route's own wiring and cache:
  - `plan` dials nothing.
  - `apply --max-characters N` refuses a spend beyond `N`.
  - `probe` speaks one question clip and names its lane. It is `smoke.sh` step 7, where an unconfigured lane is reported, not failed.
  - RED rows are never baked.
  - `make clips` cannot do this job: it is INT-060's MinIO path keyed by compiled clip ids, and no pack compiles.
- **ADR-035 amended.** The amendment records three things:
  - the clip vendor is not a model lane;
  - the dated-snapshot rule cannot hold for a vendor that publishes no snapshots, and is stated rather than waived. Content-addressed, pre-baked, versioned clips stand in for the pin;
  - the AI/ML reviewer is asked to confirm or refuse.

## Deploy and smoke

**Not deployed. The synthetic host still runs `1785dd58` (INT-428), and `/dev/voice/george-clip` answers 404 there.**

- **The artefact.** `int-443-deploy` was a local merge of this branch with #723 (`49e3ebba`, the INT-421 admin tier the host already runs). It was never pushed. It shipped by the INT-421 path: `git archive`, then S3 `onvizit-deploy-artefacts-235229001983`, a 30-minute presigned URL, an SSM bash heredoc, and finally `init.sh`, `deploy.sh` and `smoke.sh`.
- **The first artefact (`1e138dd2`) failed at `init.sh`, before anything started.** The merge left the api service with two `volumes:` keys: INT-421's JWKS mount and INT-443's `george-clips`. Docker compose refused to parse the file. Nothing was built and no container was restarted; the stack kept serving `1785dd58`. The corrected merge (`92ce49d9`, one `volumes:` list) passes a strict duplicate-key YAML load.
- **The corrected artefact was not shipped: the permission classifier refused its upload ("Auto-Mode Bypass").** The refusal was reported, not routed around. Deploying is the owner's or coordinator's step.
- **Host state left behind.** Each attempt moved the previous tree aside, so `/opt/intake` now holds the unparseable `1e138dd2` tree. The tree the running stack was deployed from is the earliest `/opt/intake.prev-<UTC timestamp>`. Restore it before any re-run of `deploy.sh` (after a reboot, for instance):
  `ls -d /opt/intake.prev-* && rm -rf /opt/intake && mv /opt/intake.prev-<earliest> /opt/intake`
- **What was proved on the host.** On 3 Oct 2026 the synthetic proxy config was booted in a throwaway container, on the same digest, on an internal network, with the API image as the client:
  - `example.com` and `pypi.org` through the proxy were both refused with `403` (`TCP_DENIED/403` in the CONNECT log);
  - a direct connection failed with `ConnectError`;
  - the listener answered a TCP connect, while `squid -k check` failed with `no pid_filename configured`. That is why the healthcheck is a TCP connect.
- **ElevenLabs serving on AWS: no.** Three things stand between this change and a served clip:
  1. the owner's egress commit (the `elevenlabs-api` row and the files that move with it);
  2. a deploy of the merged tree, which the classifier refused me;
  3. the pre-bake (`george_prebake plan`, then `apply --max-characters N`). The vendor bills by character: the full catalogue is 26 193 characters.

  After those, `smoke.sh` step 8 speaks one question clip and prints its lane (`lane=elevenlabs cache=…`).

## Findings

- **No compiled clip manifest can exist on today's tree** (HB-C1), so INT-326's catalogue was always empty off the developer laptop. The app's generated catalogue is what makes the route serve anything there.
- **`INTAKE_DEV_*` cannot configure a non-dev host.** INT-325 refuses the boot when one is present. The checklist's `INTAKE_DEV_GEORGE_TTS=explicit-yes` would have stopped the API on AWS.
- **Instrument items.** The mobile sends no delivery context today, so the server reads `routine`. An instrument item pinned `instrument` would therefore get 422 and fall back. The current catalogue has no instrument row, because no shipped question carries one yet. The pack is HB-C1, and two instruments are licence-BLOCKED (HB-L2, HB-L3).
