## Problem

`services/voice-runtime/src/intake_voice_runtime/talker/red_path.py`, `RedPreemption.trigger`, had
two lines that addressed a different rule:

- `script_id_for(rule_ids[0], location)`
- `RedTriggerMessage(rule_id=rule_ids[0], register=triage.register, …)`

The cause is that the two values follow different orders:

- `RulesTriageResult.rules` is ordered by severity and then id.
- The engine's winner is ordered by severity, then register restrictiveness, then id (files/02 §5.3).
  The winner's register is the `register` the result carries.

Take two RED rules of equal acuity, `rf.a` (ALERT) and `rf.b` (SILENT). The wire carried SILENT
beside `rf.a`'s ALERT script. An alarm script under the register whose whole point is "no audio,
ever" is the mechanism-of-harm case §5.3 exists to prevent.

## Change

- **`protocols.triage.winning_red_rule(fired)`** is the engine's own winner selection, made public:
  - it considers only the RED-level rules;
  - the highest severity wins, then `_winning_red`'s register precedence, then the id;
  - it raises `TriageEngineError` when no KIRMIZI rule is among them.

  `evaluate_triage` now calls it, so there is one implementation and no copy to drift from.
- **`MappingRedScriptIndex.rules`** holds the pack's red-flag rules by id, as
  `RedScriptIndex.rule_for(rule_id)`. They come from the same pack the scripts come from.
- **`RedPreemption._script_rule`**:
  - One fired rule is its own winner, so the existing behaviour is unchanged.
  - With several fired rules, it asks `winning_red_rule` over the pack's own rules. It then requires
    the winner's register to equal the register the result carries.
  - A fired rule the pack does not hold, a pack with no RED rule among them, or a register
    disagreement makes the script **unaddressable**. The trigger is not published, the intake still
    stops and the clinician is still told. Nothing is guessed.
- The trigger now carries the winner's `rule_id` and the winner's `script_id` for the result's
  location. The device renders that rule's own `text_tr` through that script id. `rule_ids` on the
  outcome and the clinician notification still lists every fired rule.
