## 2. What the blueprint actually defines — read this before the table

`files/04 §6` is the source of record for the simulator. Its "starter set (40)"
is a **list of examples, not a roster**, and it names exactly three IM
scenarios:

| id | line, verbatim from `files/04 §6` |
|---|---|
| IM-02 | `IM-02 uncontrolled HTN with headache (YELLOW)` |
| IM-09 | `IM-09 passive SI on PHQ-9 (YELLOW + safety script)` |
| IM-14 | `IM-14 companion reporting for father with dementia` |

`files/10 §9` cites `IM-14` once more, as the test for the companion / guardian
profiles row. **There is no definition anywhere in `files/` for IM-01,
IM-03…IM-08 or IM-10…IM-13.** Those eleven ids are carried as *mechanism*
scenarios: each names a property the blueprint does write down elsewhere, and
each carries `blueprint_line=None` with a `mechanism_ref`, so a reader can tell
a transcription from a mechanism without leaving `tests/sim/scenarios.py`. No
clinical presentation was invented to fill a gap.
`test_a_scenario_with_no_blueprint_line_says_so_and_names_its_mechanism` pins
the count at eleven, and
`test_the_blueprint_line_is_actually_in_files_04` re-reads `files/04` at test
time so a transcription cannot drift from its source.

## 3. What is blocked, and how the gate fails closed

`files/04 §6` makes a scenario's *hidden truth* its symptoms, medications and
red flags, and its *expected output* a triage level. **None of that exists in
this repository.** Every red-flag family in `packages/protocols` is
`status: draft_needs_source`; the triage engine refuses a draft rule outright
(`DraftRuleError`), so no real pack can drive a simulated session at all.

`Scenario.clinical_truth()` therefore **raises `ClinicalContentBlocked` for all
fourteen scenarios** — the mechanism is built, the gate is wired, the gate fails
closed, the content is left empty (HUMAN_BLOCKERS Rule 2). There is no
`dev_only` flag, no demo mode and no placeholder rule set. The `ClinicalTruth`
type exists so the shape is fixed before the content arrives; no instance of it
is constructed anywhere in the repository.

| blocker | what it gates here | scenarios |
|---|---|---|
| **HB-C1** | `base.life_threat` sign-off — no pack may be promoted past L0 | all 14 |
| **HB-C2** | the ~30 missing adult rules — no real RED/YELLOW rule to fire | all 14 |
| **HB-C7** | every `TODO: threshold requires clinical sign-off` in the tree | all 14 |
| **HB-C5** | the fast-mode turn budget is an open clinical decision, so the simulator asserts **no** turn budget | IM-01 |
| **HB-C8** | the `04 §4.2` escalation policy — the crisis path has no responder, no abandonment handler, no safety plan | IM-09 |
| **HB-L2** | C-SSRS electronic sublicence — the instrument cannot compile into a pack | IM-09 |
| **HB-C3** | the paediatric rule set does not exist at all | IM-14 |
| **HB-C9** | the `ON_SITE` companion-separation question — what a carer is told in advance | IM-14 |

`test_every_blocker_id_exists_in_human_blockers` reads `files/HUMAN_BLOCKERS.md`
at test time, so a blocker id cannot rot.

## 4. Design decisions

**The simulator lives in `tests/sim/`, not in `packages/intake_sim/` or
`services/voice-runtime/src/.../sim/`.** Three reasons, in order of weight:

1. **CLAUDE.md invariant 17 — "mocks live in tests only."** A patient simulator
   *is* a mock patient. Putting one inside `services/voice-runtime/src` would
   ship a synthetic-patient generator on the PHI-path service — the "demo mode"
   seam HUMAN_BLOCKERS Rule 2 names explicitly.
2. **It is the established pattern in this repository.**
   `tests/voice/talker_harness.py` and `tests/safety/synthetic_triage.py` are
   exactly this: importable sibling modules under a test directory, which
   pytest puts on `sys.path` when it collects that directory.
3. A new `packages/intake_sim` workspace member would need `pyproject.toml`
   edits (workspace members, mypy `files`, the root dependency list) and a
   `uv sync` — both outside this issue's file ownership, and `uv sync` cannot
   run in this container at all (torch is unreachable through the proxy).

**No ADR was written.** Nothing here is an architecture change: the simulator
adds no component, no port, no boundary and no dependency. It drives the
existing ones.

**It drives the real components, not re-implementations.** The synthetic pack
under `tests/sim/fixtures/tree` is resolved by the **production compiler**
(`protocols.cli.load_registry` → `protocols.compile.resolve.resolve_protocol`)
against the committed operational template, and driven through the real
`IntakeEngine`, the real `TalkerSession` and the real `evaluate_triage`. The
only doubles are the speech egress ports and the Layer-B extraction, both of
which are recorded fixtures. The signed life-threat set is the committed
INT-041 fixture, reused rather than copied.

**Everything is synthetic** — `files/04 §7`: *"packs and goldens contain
synthetic data only; simulator transcripts are synthetic."* Every id, slot,
choice, rule and Turkish string in `tests/sim/fixtures` is invented and carries
no clinical meaning.

## 8. Findings

**F1 — an abandoned `must_ask` question is recorded, but the Talker cannot see
it.** INT-081 dropped `UNCLEAR` from the frontier to resolve the §9.2 / §11.1 /
§9.5 conflict. IM-06 confirms that is *not* silent for a clinician-mandated
slot: after two clarifications `oyku.seyir` is `UNCLEAR`, it appears in
`data_gaps`, and `must_ask_coverage` reports it **obliged and outstanding**
with the ratio falling to `0.8333`. Both reach the note, which is written by
Layer B. **But `EngineSnapshot` carries only `version`, `next_step`, `awaiting`
and `invalidated`** — no `data_gaps`, no coverage — so Layer A, which reads
nothing else, has no way to know a mandated question was abandoned and nothing
in the conversation can react to it. Pinned by
`test_the_engine_snapshot_the_talker_reads_does_not_show_the_gap`. Whether the
conversation *should* react (a wrap-up prompt, a typed fallback, a clinician
flag) is a clinical decision, not an engineering one — it belongs with HB-C5's
turn-budget question, and is left open rather than designed here.

**F2 — a section holding an abandoned `must_ask` still reports `section_done`.**
`files/03 §5` defines the field as "nothing offered and nothing awaiting", and
an `UNCLEAR` step is neither, so `oyku` reports done in IM-06 with a mandated
question unanswered. That is the definition working as written; it is recorded
because a consumer reading `section_done` alone would draw the wrong
conclusion. `must_ask_coverage` is the compensating control and it is correct.
Pinned by `test_the_section_holding_the_abandoned_must_ask_still_reports_done`.

**F3 — the IntakeEngine has no path to `DECLINED` or `CONTESTED`.**
`files/13 §9.3` names seven answer states and `coverage.COVERED_STATES` counts
`DECLINED` and `CONTESTED` as covering, but `apply_extraction` can only produce
`ASKED_PRESENT`, `ASKED_ABSENT`, `UNCLEAR` and (via invalidation)
`NOT_ASKED`. A patient who declines leaves the slot in `ASKED_PENDING`
permanently — visible as an outstanding obligation and as `awaiting` on the
snapshot, which is the *safe* direction, but not the state the blueprint names,
and the coverage rule that a decline "counts as covered because making the
metric penalise a refusal would put it in tension with consent" is currently
unreachable. No bypass was added; IM-11 pins the actual behaviour.

**F4 — `files/13 §9.5`'s "every turn strictly decreases the work remaining" is
false turn-by-turn.** A clarification turn takes one step out of `NOT_ASKED`
and puts one re-entry into the queue: a wash, not a decrease. IM-06's measured
sequence is `[9, 8, 7, 6, 6, 6, 5, 4, 3, 2, 1, 0]`. What actually holds — and
what the suite asserts for every scenario — is that the measure is
**non-increasing**, that no slot is asked more than `1 + MAX_CLARIFICATION_
ATTEMPTS` times, and that every scenario terminates because the frontier
emptied rather than because the runaway guard tripped. Pinned by
`test_the_strict_decrease_of_files_13_9_5_does_not_hold_every_turn`.

**F5 — the simulator asks no instrument item, because the engine plans slots
and not questionnaire items.** `build_plan` walks section slots only;
`ResolvedSection.questionnaires` is carried and never turned into a step. That
is INT-116's scope, not a defect here, but it means "instrument items are
spoken verbatim" (invariant 10) is asserted at the *pack* level in this suite
(`allow_paraphrase: false` on the instrument, its voice block and every item)
and not yet at the runtime level. Recorded so it is not later discovered as a
coverage hole.

**F6 — no turn budget is asserted anywhere.** `files/02 §2`'s ≤ 18-turn budget
collides with its own content list and is an open clinical decision (HB-C5), so
`MAX_TURNS = 200` in the driver is a **runaway guard**, documented as such, and
the suite asserts every scenario ended on `Termination.FRONTIER_EMPTY` rather
than on the guard. No number here is a clinical claim.

## 11. Not done, and why

- **No clinical expectation of any kind.** Blocked as in §3; the gate raises.
- **No instrument item is driven through the runtime** (F5) — INT-116.
- **No overlay *pack* is activated** — the eight patient overlays are INT-056;
  personas carry overlay *references* and the suite asserts
  `protocol.overlays == ()` so the absence is explicit.
- **No latency assertion.** The fake-clock latency harness is
  `make runtime-sim` (INT-094); this suite asserts state, not time.
- **`make check-py` was not run end to end** in this container: it begins with
  `uv run ruff check .` over the whole tree and then runs lanes that need the
  pinned de-identification NER artefact, which cannot be downloaded here (the
  proxy blocks it, as it blocks torch). `tests/security/test_deid_ner.py` fails
  for that reason on this branch **before** any change in this issue. The
  simulator's own lanes, `tests/engine`, ruff, ruff format and `mypy --strict`
  were all run and are green.
