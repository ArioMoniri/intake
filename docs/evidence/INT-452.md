## 3. What was built

- **`scripts/backlog/roadmap_snapshot.py`, run as `make roadmap-snapshot`.**
  It is the only step that calls GitHub, and it only reads: `gh pr list`
  (open, then merged titles), `gh issue list` (open), `git rev-parse
  origin/main`, and `git show <ref>:docs/backlog/issues.yaml` for each open
  PR's branch. A listing that reaches its `--limit` is refused, never silently
  truncated. It writes `docs/backlog/github_snapshot.json` with sorted keys and
  a stable order. Its `row_floor` is the previous floor united with every id
  that has a row now. `FloorShrank` refuses, and nothing is written, when a
  previous floor id has lost its row. All commands go through an injected
  runner, so the tests use a fake one.
- **`scripts/backlog/roadmap_lib.py`** (the pure model: parsing, owners,
  states), **`scripts/backlog/roadmap_render.py`** (pure markdown) and
  **`scripts/backlog/render_roadmap.py`** (file I/O only) render the section of
  `files/05_ROADMAP.md` between the `BEGIN/END generated live status` markers.
  The section has a phase summary (rows, done, in flight, blocked, todo,
  withdrawn, open PRs with no row on main, open issues with no row anywhere).
  Each phase has an epic table and every remaining row in file order, with its
  PR and branch, its blocker record and its owner. Then come the rowless PRs,
  the PRs that name no id, the issues with no row anywhere, and the drift. The
  rest of files/05 is untouched, and a one-paragraph note in its header points
  at the section.
- **Owner rule** (`roadmap_lib` docstring). A blocked item is owned by the
  `who` of its blockers.md row, else its open HUMAN_BLOCKERS row, else an open
  HB id in its own YAML block, else its `approval:*`/`blocked:*` label. If none
  of those exists, the owner is "owner — no blocker record names it", which is
  reported as drift. Any other item is owned by the agent role its area label
  implies (the reviewer subagent `.claude/agents/` requires), plus the human
  sign-off that an `approval:*`, `gpu` or `live-smoke` label adds.
- **files/11** gains an `owner` column taken from the row's labels alone, so it
  still depends on issues.yaml only. **`render_backlog.py` now also re-renders
  the roadmap**, and its `--check` covers both. The habitual
  `make backlog-render` therefore keeps both current.
- **The CI check is pytest, which CI already runs.**
  `tests/backlog/test_roadmap.py::test_committed_roadmap_matches_the_generator`
  fails when the committed section differs from the generator output. Its near
  miss is a one-character hand edit, which fails, then passes once restored.
  `test_rendering_never_calls_github` replaces `subprocess.run` and `Popen`
  with functions that raise, and rendering still succeeds. No `.github/**`
  change and no owner patch was needed.
- **The three pins became one derived check.**
  `backlog_lib.row_floor_violations(ids, floor)` checks three things. Ids are
  unique. Every id in the snapshot's `row_floor` still has a row: a row is
  withdrawn, never removed. The floor holds at least `ROW_FLOOR_MINIMUM` (343)
  ids. `test_sync_dryrun` now asserts `len(actions) == len(rows)` and that the
  id sets are equal. `test_make_check` keeps the 175-blueprint lower bound plus
  the floor check. A new row needs no edit to any test, so rows stop colliding
  there. The floor can only rise, through the snapshot step, so a lost row
  still fails CI.
- **Scans.** `tests/infra/test_object_store_image.py` and
  `tests/infra/test_keycloak_realm_import.py` already exempt files/11, because
  it renders backlog titles. They now blank only the generated section of
  files/05 (`roadmap_lib.blank_generated_section`, which keeps line numbers),
  because INT-347's title names the withdrawn image. The hand-written rest of
  files/05 is still scanned.
