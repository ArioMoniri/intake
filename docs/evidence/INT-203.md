renderer, the edge log boundary, and the whole prod-egress-proxy half, all decided with a
local resolver stub and recorded fixtures with no container anywhere (§6, §7).

## 1. What this is, and what it deliberately is not

Four components, one policy file:

```
internet
  └─ traefik v3.3.7            TLS, ACME, the router, the access log
       ├─ intake-waf           Coraza wasm middleware + OWASP CRS 4.0.0 (embedded)
       └─ intake-headers       HSTS, nosniff, frameDeny, no Server banner
  → api (network `app`, internal: true)

crowdsec v1.6.8                reads Traefik's access log; local scenarios only
egress proxy (INT-018)         unchanged in shape, hardened here (§6)
cert-manager                   the cluster half of the same TLS policy
```

`infra/security/edge/edge-policy.yaml` is the only file anyone edits.
`scripts/security/render_edge_conf.py` (`make edge-conf`) renders Traefik's static config,
its dynamic config, the CrowdSec scenarios and acquisition, and the cert-manager manifest.
`--check` fails on a stale render, which is also what fails when somebody edits a generated
file instead of the policy. This is INT-018's arrangement, extended from two enforcement
points to five.

**Not a fourth implementation of the egress control.** files/10 §4 records the same bypass
three times — INT-018's vendor list, INT-160's tenant dimension, INT-161's token endpoint,
*"the same egress bypass in a third form"* — and INT-121's title is that a security control
implemented twice will diverge. Everything in `tests/infra/test_edge_egress.py` runs through
`intake_platform.egress` and the one rendered squid config. What this issue adds to that
control is in §6, and it is two fixes, not a copy.

## 3. Clause 1 — "WAF blocks OWASP CRS suite"

### 3.1 Why this is not asserted from a config file

The clause is trivially fakeable two ways, and both look identical from a YAML file:

* **blocks nothing** — one wide exclusion (`ARGS` instead of `ARGS:json.text_tr`, `/` instead
  of one route), or the anomaly threshold raised until the alerts stopped;
* **blocks everything** — which for *this* product is the more likely accident, because the
  traffic it exists to carry is Turkish clinical free text and that text is full of the
  tokens a signature reads as an attack: `Ali'nin` (an apostrophe mid-word), `1x1 sabah/akşam`
  (a dose string), `<acil servise gidin>` (patients type angle brackets), `1=1 gibi`
  ("about the same"), `göğüs & sırt ağrısı`.

So the ruleset runs and the corpus is decided against it.

### 3.2 The ruleset is pinned by hash, because it lives inside a binary

The WAF is `coraza-http-wasm` v0.3.0 loaded by Traefik with `experimental.localPlugins` — no
plugin-catalogue call at boot. The OWASP CRS ships **inside** that module, so "which ruleset is
deployed" is answered by a hash, not by a directory listing. `make edge-plugin` verifies the
archive **before** unpacking and the module after, and refuses on a mismatch:

```
archive b96680b46e61287faae243e360db5de34e4f315e2a8ee105fedddc176e79b1e7
module  b59fd2266c03699da2de9d6d281ffc2a3e791eb6646069d2b9744543ccd90b1c
licence c71d239df91726fc519c6eb72d318ec65820627232b2f796219e87dcf35d0ab4  (Apache-2.0)
```

The CRS version in the policy is `4.0.0` because the running engine reports
`OWASP_CRS/4.0.0` in every rule line. That is a measurement, not a card tag (files/03 §4.9.0
rule 3). Licences for all three projects — Traefik MIT, the middleware Apache-2.0, the CRS
Apache-2.0 — were read from raw blobs at pinned commits and recorded in
`observability/registry.yaml`; the CrowdSec blob's commit `f209766e` cross-checks against the
running container's own build string.

### 3.3 The corpus

`tests/fixtures/waf/corpus.yaml`, twelve cases, both verdicts, decided by
`tests/infra/test_edge_stack_integration.py` against the booted tier:

| case | family | expect | got |
|---|---|---|---|
| `sqli_in_query_string` | sqli (942) | blocked | 403 |
| `sqli_in_turkish_utterance_field` | sqli (942), **in the JSON body** | blocked | 403 |
| `xss_script_tag` | xss (941) | blocked | 403 |
| `lfi_traversal` | lfi (930) | blocked | 403 |
| `rce_shell_metacharacters` | rce (932) | blocked | 403 |
| `scanner_user_agent` | scanner (913) | blocked | 403 |
| `protocol_restricted_file_extension` | protocol (920440) | blocked | 403 |
| `chest_pain_with_apostrophe_and_angle_brackets` | — | passed | 200 |
| `dose_string_that_looks_like_an_expression` | — | passed | 200 |
| `ampersand_between_symptom_words` | — | passed | 200 |
| `turkish_word_that_contains_a_sql_keyword` | — | passed | 200 |
| `quoted_family_history_with_dashes` | — | passed | 200 |

The second row is the one that matters on this API: an allow-list of hosts does nothing about
an injection inside `{"text_tr": "…"}`, so `SecRequestBodyAccess` and the JSON body processor
are on and the body is scanned. `test_the_negative_controls_are_actually_clinical_turkish`
holds the passing cases to carrying both a tripwire token and real Turkish diacritics, so a

## 5. Clause 2 — "CrowdSec scenarios on", and the bug that phrase hides

Three scenarios, rendered from the policy, each tied to a files/10 §7 signal:

| scenario | signal | bucket |
|---|---|---|
| `intake/waf-block-burst` | WAF/CrowdSec blocks | 6 × 403 from one address |
| `intake/auth-failure-burst` | failed logins and OTP anomalies per IP | 15 × 401/429 |
| `intake/not-found-sweep` | volumetric and bot traffic | 25 × 404 |

**The bug, found by booting it.** The renderer first emitted all three as documents of one
`scenarios/intake.yaml`, which is valid YAML and valid CrowdSec. `cscli scenarios list` then
showed **one** scenario. CrowdSec's local inventory keys on the file, so two of the three
were silently absent — a tier reporting "scenarios on" while running a third of them, and a
config-file test would have passed on all three. The renderer now emits one file per
scenario, `orphan_scenarios()` deletes files the policy no longer declares (the direction a
write-only renderer never notices), and the integration test asserts the count in both
directions.

Behaviour is decided with `cscli explain`, which runs acquisition, both parser stages and the
scenarios over a file — deterministic, offline, and it gives the near-miss control for free:
a burst of `403` lines reaches `intake/waf-block-burst`; one `200` line, same pipeline, one
field different, reaches no scenario at all.

**CrowdSec's central API is off** (`online_client: {}` plus `DISABLE_ONLINE_API`), and that
is a policy decision, not a convenience. The community blocklist works by sending the
addresses that triggered your scenarios to CrowdSec SAS; files/10 §1 counts a third-party
reputation service receiving our client addresses as a transfer nobody consented to, and a
patient's mobile IP is personal data. Every parser and scenario this tier runs is in this
repository, which is also why the hub is never contacted from a host that is not on the
egress allow-list.

### 5.1 The second finding: the WAF is a PHI channel

This is the one worth reading. Here is a **real line** the booted tier wrote, captured into
`tests/fixtures/waf/coraza-blocks.log`:

```
[id "942100"] [msg "SQL Injection Attack Detected via libinjection"]
[data "Matched Data: sUEv, found within ARGS:json.text_tr: Göğsümde şiddetli ağrı var'
       UNION SELECT null,version(),null-- ve nefes darlığı"]
[uri "/v1/intake/utterance"] [unique_id "PBQUwiXcobicrCsgOXl"]
```

`ARGS:json.text_tr` is the patient's utterance. CRS rules carry `logdata`, so **every** rule
match quotes the matched argument back, and on this API that argument is the reason a person
is seeing a doctor. `[uri …]` carries whatever the query string held. Shipping that line to
the SIEM trades an injection *attempt* for a disclosure that **succeeds**, is durable, and
looks exactly like a security control working (CLAUDE.md invariant 6).

The answer is not redaction. A filter that misses once has leaked, and this filter would be
run over attacker-chosen text. `intake_platform.edge.logs.EdgeEvent` is a **closed record with
no field a sentence could occupy** — the same discipline `TransferRecord` already applies to
the egress register:

```
EdgeEvent(rule_id=942100, rule_class=SQLI, severity='critical',
          crs_version='4.0.0', anomaly_score=None, unique_id='PBQUwiXcobicrCsgOXl',
          blocked=False)
```

The parser reads five keys and never looks up `data`, `msg`, `logdata`, `uri`, `hostname` or
`client` at all; the attack family comes from the CRS *file name*, which is a constant of the
ruleset. A line it does not understand is dropped rather than shipped, because an unparsed
line is the raw line. And the near-miss control is asserted too — a scrubber that drops
everything is exactly as useful as one that drops nothing, so the event must still carry the
rule id, the family, the score and the block verdict.

Two more layers of the same rule: Traefik's access log is `defaultMode: drop` with eight
named fields, none of them a path (`test_a_blocked_clinical_request_leaves_no_clinical_text_in_the_access_log`
sends the leaking request and greps the log); and the CrowdSec parser extracts exactly two
values from a request, the client address and the status, because a bucket key becomes part of
every alert the bucket raises.

## 6. Clause 3 — "certs automated" — and the prod egress proxy

### 6.1 Certificates

One policy renders both deployment shapes, which is the point: a renewal window that differs
between Traefik's ACME client and cert-manager expires a certificate in exactly one of them.
`tlsChallenge` (no inbound HTTP listener, no DNS credential), `EC256`, `renewBefore` 30 days
— Let's Encrypt's own advice, and below it a failed renewal leaves no room for a human to
notice `sec.cert_expiry_days` falling. The schema refuses a staging ACME directory, which
issues certificates no browser trusts and renews them forever while the dashboard reads
"issued". The ACME account email is an environment variable with no default, sourced from
OpenBao (invariant 14); the resolver file carries no address.

`test_naming_a_domain_renders_a_certificate_that_matches_the_policy` decides the *behaviour*
of the renderer with domains present, which the shipped policy cannot exercise (§8).

### 6.2 Two fixes to the shared egress control

**(a) The proxy's rebinding window.** files/10 §4 asks this tier to *"resolve once and pin,
re-validating on connect"*. squid evaluates its `dst` ACL against its IP cache, whose default
positive TTL is **six hours** — a name can be authorised against one answer and connected to
against another. The in-process guard cannot cover it, because behind a proxy the process
deliberately does not resolve at all (that is what lets the hostname reach the CONNECT line
squid matches on). `ipcache_size 0`, `fqdncache_size 0`, one-second TTLs and `dns_defnames
off` make the ACL check and the connect share one lookup per request. Rendered from the same
generator, so the two enforcement points still cannot drift.

**(b) The fourth shape of the bypass.** ADR-025 catalogued four; INT-160 and INT-161 each
found another. The next one is not a new call site — it is a *configuration*: a personal-data
transport pointed at the forward proxy. That is the one arrangement in which **neither**
enforcement point resolves, because the process hands the job to the proxy and the proxy's
allow-list has no connector rows and an empty PHI tier. It looks like an ops setting rather
than like a change to a security boundary, which is exactly why it would be made. Refused at
construction now, with the reason in the exception. The near-miss control matters here as
much as anywhere: a package or model pull *may* still use the proxy, and
`test_a_non_personal_call_may_still_use_the_proxy` asserts the hostname survives to the
CONNECT line, so the rule does not disable the tier it is guarding.

One existing test moved as a result:
`tests/security/test_egress_allowlist.py::test_a_wrong_purpose_is_still_refused_behind_the_proxy`
used a PHI data class to reach the purpose check; it now uses `NON_PERSONAL`, and a new test
beside it asserts the earlier refusal for both personal classes. The refusal moved earlier,
which is strictly stronger.

### 6.3 No fourth call site bypasses the proxy

Every construction of `guarded_client`/`guarded_transport` outside the module and its tests
was enumerated: `intake_connectors.sender` builds two (the FHIR push and the SMART token
exchange), and both pass no `proxy=`, so both resolve and pin in process today.
`intake_platform.ehrbase` mentions the transport in a docstring as the seam a deployment
would pass; it constructs none. There is no third.

## 7. The constraint that arrived mid-iteration, and what it does to the acceptance

Between the green run in §4 and this section the owner imposed a hard constraint: **no
Docker may run on the local machine at all.** Every `intake-*` container was stopped,
including the edge tier from §4. The obvious alternative turned out not to be one — the GPU
server has **no container runtime either**, being itself a pod, so nested containers are not
available; it has `apt-get`, and installing system packages on a box several other people
use, to make one issue pass, is not a decision an agent takes.

**What that does to the three clauses is not "they regress" — it is "they become
unverifiable here".** The distinction matters and this file will not blur it:

* The tier was **measured** on 3 Sep 2026 and the run is recorded above with its date, its
  versions and its hashes. That is a measurement of one stack on one day, which is how this
  repository states every such thing (invariant 20's discipline, applied to a security
  control rather than to a model).
* It **cannot be re-run** anywhere sanctioned, so it cannot be a gate, and a clause whose
  gate cannot run is not a clause anyone should tick.

The tempting move at this point is the one invariant 17 exists to forbid: assert that
`edge-policy.yaml` sets `SecRuleEngine On` and that `@owasp_crs/*.conf` appears in the
rendered directives, and call *"WAF blocks OWASP CRS suite"* met. **That assertion is
compatible with a WAF that returns 403 to every request**, including all five Turkish
clinical turns in the corpus, which would take the product off the air while the test stayed
green. It is also compatible with one that blocks nothing, if an exclusion were ever written
wide. The corpus exists precisely because configuration cannot answer this question, so no
clause is claimed from configuration.

**Nothing is mocked and nothing is skipped.**
`tests/infra/test_edge_stack_integration.py` is committed, marked `integration`, boots its
own tier, and **fails** — naming `make edge-plugin` — when the artefact is absent. It does
not `pytest.skip`, because a WAF suite that silently does not run is worse than no suite.
The day there is somewhere to run it, it runs unchanged.
