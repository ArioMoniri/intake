## What changed, finding by finding

| # | Fix | Where |
|---|---|---|
| F1 | The watch is no longer a handler wrapper. The Work queue takes a `StateWatch` (two members, `before_work` and `after_work`, each handed the engine alone; nothing they return is read; neither is awaitable). `_execute_state` runs the first look, then the Work (`_run_state`: handler, rules-engine determination, `_finish` with the clinician route, the settle and the RED push), then the second look in a `finally`. A look that raises is caught by the queue, counted (`work_watch_faults_total{step}`, catalogued, paged by `ClinicItemWatchFailed`) and logged by ids (session, work, step, error class); the Work keeps its own outcome and its evaluation, and `_evaluation_owed` is only ever set by an evaluation fault, as before. `for_protocol` checks the session id with `require_id` before it builds a watch; every other id an item carries comes from the DSL-validated protocol or the decision register. Both roots register the bare handlers and hand the watch to `BackendAgent(watch=...)`. | `clinical_agent/work_queue.py`, `clinical_agent/clinic_items.py`, `composition.py`, `metrics.py` |
| F2 | The item is raised only after the Work has settled (F1's second look), so it is behind the RED, never in front of it. The audit row is no longer written by the route: `ClinicItemNotifier` puts the entry (an in-memory append, as before) and puts the row in a `ClinicItemAuditOutbox` — bounded (1024 rows, an engineering bound), an append under a lock that never waits. Its worker (`pump`, on its own thread) appends each row in order; a row the chain refuses is counted and logged by ids and the next row goes on; a full outbox refuses the row and counts it (`clinic_inbox_item_unaudited_total`, error `audit_outbox_full`). `AuditChain` now serialises its writers with a lock across the read-head / INSERT / move-head step (and `verify`, `export_worm`, `head` read under it). | `safety_inbox.py` (voice runtime), `intake_platform/audit.py` |
| F3 | `SafetyInbox.queue` orders the open entries RED-family first (RED, on-site, visit transitions), then clinic items, each oldest first; answered entries follow, newest answer first. | `intake_platform/safety_inbox/service.py` |
| F4 | `_ASKED` beside `_UNASKED` sorts every `AnswerState`; `for_protocol` refuses (`ClinicItemWiringError`) while a state is in neither or both, and a test pins the seven members, so ADR-040's `NOT_ASKED_PROXY` cannot arrive unsorted and quietly read as asked. | `clinical_agent/clinic_items.py` |
| F5 | `ClinicInboxItemUnaudited` pages on `increase(clinic_inbox_item_unaudited_total[5m]) > 0`, and `ClinicItemWatchFailed` on the new counter; both have runbook sections. The route-failure counter was already paged (`ClinicInboxItemRouteFailed`). | `infra/observability/safety-rules.yaml`, `docs/runbooks/red-acknowledgement.md`, `observability/metrics_catalog.yaml` |
| F8 | `ProxyScreenRule.readings` reads `(slot, literal)` pairs from CD-01's `raised_when` (`<slot> is '<value>'`); a `raised_when` stating none is refused. `names_reading(ref, literal)` checks the pair. The watch accepts the screen's `skip_if` only as one `==` of CD-01's slot to CD-01's literal (either way round); another literal, `!=`, a negation, a second condition, a slot-to-slot comparison or an unresolved slot is refused at composition. | `packages/protocols/src/protocols/clinic_items.py`, `clinical_agent/clinic_items.py` |
| F9 | `InboxEntry` keeps `slot_refs` and `decision_ids` (ids only, shapes `SLOT_REF_SHAPE` and `DECISION_ID_SHAPE`, shared with `ClinicItem`). A clinic item entry must carry both; every other kind carries neither. The notifier passes them, and the console row shows them (empty lists on a RED row). | `intake_platform/safety_inbox/model.py`, `safety_inbox.py`, `intake_api/admin/safety_queue.py` |
| F11 | INT-525.md:56 now says why the age is unknown: nothing collects a date of birth (INT-223 shuts the guardian-link path and records no DOB), instead of "INT-223 refuses every under-18 subject". | `docs/evidence/INT-525.md` |
| F12 | The corpus says what it does: `()` asserts no item, `None` leaves items unchecked. | `tests/safety/triage_goldens_corpus.py` |

### The data-inventory question (F9)

The Safety inbox lives in Redis (`RedisSafetyInboxStore`), not in a
SQLAlchemy table, so `tests/data/test_inventory.py` does not cover it and no
annotation is required by a schema test. The two fields are the same category
the entry already holds in `rule_ids`: protocol identifiers (`chest_pain.character`,
`CD-04`), never an answer or a value. The kind already says which chest-pain
item it is; the slot ids say which of the seven slots. No new category of
personal data is persisted, so this is not a stop-and-ask.

An entry stored before this change with a clinic-item kind would now fail the
model and the store fails closed (`SafetyInboxUnavailable`). None exists: #931
and #932 are unmerged and no production builder constructs
`ClinicItemNotifier`.

## Invariants

- **1** — a watch is handed the engine only and its return value is never
  read; `StateEffect` still has no priority; the K2 Work's `triage_update` is
  the rules engine's (asserted against `evaluate_triage` in every new test).
- **4** — every item still owes exactly one audit row; a row that is refused
  or cannot be queued is counted and now pages.
- **6** — log lines carry the session id, work id, entry id, step, kind and
  error class only; the new F1 test asserts no transcript reaches a log line.
- **9** — no new awaitable member (`StateWatch`, `ClinicItemRoute`,
  `ClinicItemAuditOutbox.put`); the Talker's tools are untouched; only a
  rules-engine RED takes preempt; the RED reaches the device inside 150/300 ms
  of its evaluation with the watch faulting on the same Work.
- **13** — `work_watch_faults_total` is catalogued; both new alerts read
  catalogued series.

## Residuals

- **F10** (not in this branch's brief): a route that fails on the session's
  close Work has no later Work to retry on. It is paged
  (`ClinicInboxItemRouteFailed`) and the runbook's step 2 tells the clinic by
  session id, as before. The production route is now two in-memory appends,
  so a failure there is a defect.
- The audit outbox's worker is started by whatever builder wires
  `ClinicItemNotifier` (INT-515's host worker); no production builder does
  yet, as for the RED's `SafetyInboxOutbox` pump. A stopped worker shows as a
  full outbox (1024 rows), which pages as unaudited; there is no pending-age
  gauge for the rows.
- Noticed, not changed: `clinic_red_notification_unaudited_total` (the API's
  RED notification rows, INT-475) has no alert either.
- F6 and F7 (the CD-08 recipient role and named inbox; proxy goldens in the
