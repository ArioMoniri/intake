## What landed

- `infra/docker-compose.obs.yml` — project `intake-obs`, every service gated
  behind `profiles: ["obs"]`: prometheus (INT-021 burn-rate rules mounted
  read-only, scraping the collector on 8888/8889), grafana (datasource +
  dashboard provisioning as code, anonymous off, sign-up off, admin password
  from env with a clearly-marked dev default), loki + tempo, the INT-011
  otel-collector config reused verbatim plus an obs overlay, unleash with
  its own postgres, keycloak (dev mode, realm import), glitchtip
  (web/worker/one-shot migrate with its own postgres+redis, no host ports on
  any backing store). All ports loopback; all images tag-pinned and each tag
  verified to exist via `docker manifest inspect` before pinning.
- `infra/observability/otel-collector.obs.yaml` — overlay loaded after the
  base file (confmap merge): container-network endpoints, health_check
  extension, exporters to Loki (native OTLP), Tempo and the Prometheus
  exporter. Every pipeline restates `transform/redact`;
  `test_collector_overlay_keeps_redaction_in_every_pipeline` pins that
  because confmap REPLACES lists — an overlay that forgot the processor
  would silently drop redaction (inv. 6).
- `infra/observability/{prometheus.yml,loki-config.yaml,tempo.yaml}` and
  `infra/observability/grafana/provisioning/**` — datasource uids are
  cross-checked against the dashboard's references by the compose test.
- `infra/keycloak/dev-realm.json` — realm `intake-dev`, clients `api`
  (bearer-only) and `admin-web` (public, PKCE, localhost redirects only),
  roles admin/clinician/ops, one synthetic user per role
  (`Synthetic <Role> (Dev Fixture)`, `.invalid` mail, `dev-only-<role>`
  passwords). A committed dev fixture by design; the realm displayName says
  so in-product.
- `packages/intake_platform/src/intake_platform/flags.py` — OpenFeature-
  shaped facade with zero new dependencies: `FlagProvider` protocol,
  `InMemoryProvider` (the default; dict-seeded), `UnleashProvider`
  constructed only when `INTAKE_UNLEASH_URL` is set (httpx, 200 ms budget,
  fail-CLOSED to in-memory defaults on any error/timeout/malformed payload).
  Safety flags `device_functions`/`s2s`/`learning_apply`/
  `satisfaction_prompts` pre-declared False, outrank call-site defaults,
  and flip only on an explicit boolean `enabled` in the payload. Reads are
  logged name/value/provider; ctx is never logged and never transmitted.
- `packages/intake_platform/src/intake_platform/errors.py` —
  `setup_error_reporting()` activates only with `INTAKE_GLITCHTIP_DSN` set
  AND the `error_reporting` flag on; sentry-sdk (GlitchTip's protocol) is an
  optional import guarded like the OTLP exporter in otel.py — absent SDK is
  a logged no-op. `scrub_event` (pure function) drops request bodies and
  user, redacts message/logentry/exception/breadcrumb strings via
  `redact_text`, drops frame locals, and whitelists extra/tags to
  `ALLOWED_LOG_ATTRIBUTES`. `include_local_variables=False` forced
  (files/10 §3's pcm-buffer defect) and asserted by test.
- Makefile: appended `obs` / `obs-down` (existing targets untouched);
  pyproject: mypy override for the optional `sentry_sdk` import.

## Decisions and deviations

- **No promtail, no Loki docker driver.** The issue offered either; both
  create a second, UNREDACTED path into Loki (container stdout bypasses the
  collector's transform/redact chokepoint) and promtail additionally wants
  the docker socket. App logs already flow OTLP → collector → Loki after
  redaction. Simpler AND the only variant consistent with inv. 6.
- **openfeature-sdk not added.** It is pure Python (Apache-2.0) but ships a
  full evaluation-API surface (clients, hooks, evaluation details) that
  nothing here uses; the part of the contract we need — the provider shape
  with swappable backends — is ~150 lines against httpx, which is already a
  platform dependency. Same interface shape, zero new supply chain.
- **Collector repacked onto pinned alpine via `dockerfile_inline`.** The
  upstream contrib image is distroless: no shell or HTTP client, so no
  honest healthcheck is possible in-image (the HAPI Java-probe precedent
  from the dev compose does not transfer — there is no interpreter at all).
  Both FROM lines are tag-pinned and the compose test validates FROM pins
  exactly like `image:` pins.
- Unleash can only *explicitly* enable a safety flag (asserted code path);
  the production authority for those flags remains the gated-capability
  service of files/10 §0b (inv. 34/48) — this facade is rollout plumbing
  and fails closed.

## Honest scope

- The stack runs via `make obs` locally; **CI never boots it** — the compose
  file, realm export, provisioning and collector overlay are validated
  statically (parse, profile gating, pins, loopback binds, healthchecks,
  mount-source existence, datasource-uid cross-checks).
- Grafana provisioning is verified by config tests; a live click-through
  (dashboard renders, datasources healthy) is a dev action after `make obs`.
- sentry-sdk is not installed in this repo's environment; the activation
  path is exercised through an injected module object (mock lives in tests
  only), so the suite is skip-free either way (inv. 17).
- `error_reporting` stays off until a service sets the DSN and turns the
  flag on — nothing starts reporting as a side effect of this landing.
