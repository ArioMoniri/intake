## 1. What this is, and what it deliberately is not

A connector send is a **share of clinical data to another organisation**, so invariants 4,
6, 13, 14, 16 and 19 are all on the same path. This issue builds the framework —
`packages/connectors`, import package `intake_connectors` — and no adapter: the FHIR/SMART
adapter is INT-161 and the HBYS/HL7v2 kit INT-162. The only adapter in the tree is a
fixture one under `tests/`, which is what keeps invariant 17's *"mocks live in tests only"*
true for this seam.

The shipped destination registry, `infra/connectors/destinations.yaml`, holds **zero rows**,
so the framework refuses every send today. That is the fail-closed state, not a gap:
building the mechanism, wiring the gate and leaving the content empty is exactly what
invariant 17 prescribes when the content is a human's to supply. See §7.

## 3. The two design questions, answered rather than assumed

### 3.1 Idempotency — what the key is derived from, and who is trusted

The key is **derived, never generated**:

```
ik-<sha256(tenant_id \x1f endpoint_id \x1f resource_ref \x1f sha256(payload))>
```

so a retry of the same note to the same destination is recognisably the same request; an
**edited** note is a new key (a genuine second share, correctly not deduplicated); the same
note to a **second** hospital is a new key (each destination gets its own delivery); and the
same note under a **different tenant** is a new key. Consent is deliberately *not* in the
derivation: consent decides whether a share may happen at all, and re-granting a withdrawn
scope does not make an unchanged record a different record. Each of those four is a test
(`test_the_idempotency_key_is_derived_from_what_is_sent_and_where`,
`test_an_edited_note_is_a_new_share_and_is_sent`).

The key travels on the wire as `Idempotency-Key` so a receiver that implements idempotency
*can* deduplicate. **It is not trusted to.** "We sent it twice and the hospital
deduplicated" is not a guarantee this system can make on a hospital's behalf, so the
authority is local — `PushLedger`. A key settled `delivered` is never re-sent, whatever the
receiver does; a second `send()` returns the stored receipt and the transport is not
entered at all.

What happens when the receiver is not trustworthy on this point is the part with teeth.
Every registry row carries `receiver_idempotency` with **no default** — the row does not
load without it — and it takes one of two values:

| outcome | `honoured_per_dpa` | `not_declared` |
|---|---|---|
| 2xx | `delivered` (terminal) | `delivered` (terminal) |
| 4xx / redirect | `rejected` (terminal — the same bytes will be refused again) | same |
| egress denial, connect error, missing credential, unloadable mTLS material | `failed`, ledger `failed_retryable` (nothing left the process) | same |
| **timeout, dropped connection, 5xx, 408/429** | `unresolved`, ledger **`failed_retryable`** | `unresolved`, ledger **`needs_human`** |

The last row is the decision. Auto-retrying into a receiver that may not deduplicate risks
a **duplicate clinical record in a hospital system**, which is worse than a push that
visibly did not complete. So an undeclared receiver parks; a second `send()` raises
`ReplayRefused` rather than guessing (`test_an_ambiguous_outcome_against_an_undeclared_receiver_parks_for_a_human`,
`test_the_same_ambiguity_is_retryable_when_the_dpa_declares_the_key_honoured`).

### 3.2 Receipts — written before the send

There is no third option, and this repo takes **write-ahead**.

A receipt written *after* delivery cannot record a push that left the building and never
came back. A receipt written *before* can claim an attempt that never left. Invariant 4
says every share of clinical data is audited, so the failure that matters is the first one:
an unrecorded share is an unauditable disclosure that nobody can even discover, because
nothing points at it. An over-recorded attempt is a reconciliation task.

The cost is paid in the open rather than hidden. The write-ahead row says `attempted` and
**never** `delivered`; the outcome is a second state transition and a **second** hash-chained
audit entry (`connector.push_attempted` then `connector.push_delivered` /
`push_rejected` / `push_failed` / `push_unresolved`). A process that dies in between leaves
an open receipt and an `in_flight` key, both visible
(`connector_receipts_unresolved_total`, `ReceiptStore.open_count()`) and neither resolved by
guessing — asserted by driving a `KeyboardInterrupt` out of the transport
(`test_a_crash_between_the_attempt_and_the_outcome_leaves_an_open_receipt`).

This is the same shape INT-137 took when it refused to mark a data-subject request
`COMPLETED` at the moment of delivery: *what we know* is a separate record from *the claim
that it worked*.

## 4. ADR-025's five bypasses, and how each is closed here

ADR-025 names five. A connector is the component most likely to reach all of them, so each
is driven through the connector path as its own test in
`tests/connectors/test_framework.py`.

| # | ADR-025 bypass | How the connector path closes it | Test |
|---|---|---|---|
| 1 | literal IPs and private / link-local / metadata ranges | `ConnectorDestination.host` refuses an IP literal in the **schema**, and again in `AllowlistEntry`, and a third time in `EgressPolicy.check`. A single unqualified label (`openbao`, `unleash`) is refused too — that is how an internal service is addressed | `test_the_schema_refuses_every_shape_that_is_not_a_public_hostname` |
| 2 | a hostname that *resolves* into one of those ranges | the INT-018 `EgressPolicy.authorize` resolves after the allow-list check and refuses the answer; the connector reaches it through the same object | `test_a_host_that_resolves_into_a_denied_range_is_refused` |
| 3 | a second resolution between check and connect (DNS rebinding) | resolve-once-and-pin, unchanged: the request is aimed at the pinned address with SNI still naming the host, and a split answer fails closed on the denied member rather than picking the good one | `test_the_request_is_aimed_at_the_pinned_address_not_the_name`, `test_a_split_dns_answer_fails_closed_rather_than_picking_the_good_one` |
| 4 | a redirect to a host nobody checked | `guarded_client(..., follow_redirects=False)`; a 3xx settles as `rejected` with `http_302`, and even a followed hop would be re-authorised per hop | `test_a_redirect_is_not_followed` |
| 5 | **the right host addressed for the wrong reason** | two layers. The *purpose* layer is INT-018's: a connector declares `CLINICAL_RECORD_PUSH` + `DataClass.PHI`, and a row serving another purpose refuses. The *tenant* layer is new and is the form the bypass actually takes here — a host that is contracted, approved and on a list, **for a different hospital**. `DestinationRegistry.resolve` refuses a tenant naming another tenant's `endpoint_id` and does not disclose that the id exists elsewhere | `test_the_right_host_for_the_wrong_tenant_is_the_fifth_bypass_and_is_closed`, `test_a_tenant_cannot_address_another_tenants_endpoint` |

A sixth thing the connector adds, which is not a bypass of the list but of the *reason* the
list is empty: a registry row is a `phi_allowed` entry, so the INT-018 runtime double gate
still applies — without `INTAKE_ALLOW_PHI_EGRESS=explicit-yes` every push is denied
(`test_the_phi_runtime_gate_still_applies_to_a_registered_destination`).

### Why a second list, and why it does not violate ADR-025

ADR-025's rule is *one list, two enforcers* — its danger is two lists that **disagree**.
The connector registry is a second list of a different kind (per-tenant data, registered
out-of-band against one executed DPA) enforced by **one engine**:
`ConnectorDestination.egress_entry()` returns the very `AllowlistEntry` type the vendor file
validates, so there is one implementation of what an entry means. A hospital endpoint may
not be in the vendor file at all — it would then be reachable by every process that loads
that file, for every tenant, which is bypass 5 installed as configuration rather than
exploited. `tests/security/test_egress_allowlist.py` now asserts that direction:
`test_a_connector_push_purpose_never_appears_in_the_vendor_allowlist`.

That test file's `test_every_purpose_in_the_vocabulary_is_used_by_the_shipped_allowlist` was
amended, and the amendment is a **tightening**: the exempt purpose is named in
`NON_VENDOR_PURPOSES` (so the "no dead members" rule stays intact) and gains a companion
test that it must be *absent* rather than merely optional.

## 5. Invariants held, one line each

- **4 — consent + audit.** `ConsentGate` is a constructor argument with no default, so an
  unconsented share cannot be expressed. A refusal is itself recorded: a `refused` receipt
  and a `connector.push_refused` chain entry, because a guard that ran silently is not
  evidence that it ran (`test_a_refused_push_still_leaves_an_audited_receipt`). Both the
  attempt and the outcome append to the INT-016 hash chain, and the suite verifies the
  chain after a delivery.
- **6 — no PHI anywhere it should not be.** The **response body is never read**: the sender
  uses `client.send(request, stream=True)` and closes without consuming, so a hospital's
  error text (FHIR `OperationOutcome` diagnostics routinely echo the submitted resource)
  cannot become a log line, a receipt field or an exception. An adapter is given headers
  and a status and nothing else. `ClinicalPayload` and `OutboundCall` render as a size and
  a digest. A `Location` header reaches a receipt only if it is id-shaped; anything else is
  dropped. Two sweeps assert this over `caplog` and over `repr(receipt)`.
- **13 — metrics.** `connector_push_total{endpoint,outcome}`,
  `connector_push_duration_seconds{endpoint}` and
  `connector_receipts_unresolved_total{endpoint}` were added to
  `observability/metrics_catalog.yaml` before they were constructed. Labels are a registry
  id and a closed receipt state, so nothing a receiver or a patient supplies can widen the
  cardinality. No new *service* lands, so no `docs/slo/` file is due.
- **14 — secrets.** The row holds an OpenBao **path** under `connectors/` and nothing else;
  the material is read at send time. `CredentialMissing` names no path, because an error
  string travels further than the code that raised it, and a path in a log is a map of the
  secret store. `TlsMaterial` overrides `__repr__` *and* `__str__` together — overriding
  only `__repr__` leaves `f"{material}"` printing the key, which is the call site that
  leaks it. The fixture credentials are deliberately low-entropy and unstructured: INT-139
  tripped the INT-019 gitleaks gate with a fixture that merely *looked* like a token, and
  the fix for that is a boring fixture, never an allow-list entry. **This happened here
  too**: the first commit was refused because the mTLS fixture was wrapped in
  `-----BEGIN PRIVATE KEY-----` armour, which is the right refusal — a scanner cannot tell
  a fixture from a leak. The armour was removed rather than the rule; the one test that
  needs loadable material mints a throwaway key pair in-process.
- **16 — threat row.** `docs/security/threat-model.md`'s `connectors` section had *"land
  with INT-160"* in both its Signals and its Tests lines; both are now filled in with the
  series and the test names that exist.
- **17 — no placeholders.** `scripts/ci/no_placeholders.sh` green over the staged tree.
  Nothing is invented: the registry is empty rather than seeded, and `auth_mode` has exactly
  one member (`mtls`) rather than a speculative `smart_backend` that INT-161 will add.
- **19 — no new dependency.** The package depends only on `intake-platform`, `pydantic`,
  `httpx`, `pyyaml` and `prometheus-client`, all already in the lock. `cryptography` is used
  in `tests/connectors/test_credentials_and_tls.py` to mint a throwaway key pair in-process;
  it is already a declared dependency of `intake-platform` (INT-017), and minting the key at
  test time is what keeps a private key out of the repository.

**mTLS** (in the title, not in the acceptance line, and built anyway): `mtls_context`
materialises the OpenBao-held certificate and key into a `0700` directory and `0600` files
for the length of one `ssl.SSLContext.load_cert_chain` — Python's `ssl` has no in-memory
API — then overwrites them with zeros and unlinks in a `finally`, so a *failed* load cleans
up exactly like a success. Both paths are asserted, including that the key does not appear
in the `SSLError`.

**No live call anywhere.** Every transport is `httpx.MockTransport` and every resolver is a
table. `scripts/ci/assert_no_vendor_calls.sh` green.

## 7. What is NOT met, and what a human must supply

Every acceptance clause is met — as a mechanism, with the content empty, which is the state
invariant 17 prescribes. What does not exist is any **destination**, and it is not an
agent's to invent. A row costs five recorded human facts:

| field | what it asserts | who |
|---|---|---|
| `dpa_ref` | an executed data-processing agreement with the receiving hospital, naming this interface | owner + counsel |
| `approval_ref` | the recorded tier-3 approval that registered the endpoint (files/10 §8: two humans, different organisations, write-ahead audit, pages) | `platform_owner` |
| `credential_ref` | an OpenBao path under `connectors/` that already holds the application credential | owner (OpenBao) |
| `client_cert_ref` | an OpenBao path holding the mTLS client material | owner (OpenBao) |
| `receiver_idempotency` | whether that hospital's agreement states it honours an `Idempotency-Key` — **no default**, because silence is not consent | owner, from the receiver |

**HB-A5** already records the nearest existing ask (*"Ask Acıbadem Teknoloji A.Ş. what
interfaces it actually exposes… do not size the P2 connector or promise a payload shape
before this happens"*) and it covers the *adapter* half. The five facts above are a
distinct ask — a destination, not a payload shape — and no HUMAN_BLOCKERS row covers them.
**No blocker id was minted here**: id allocation is the coordinator's, and five agents in
one night have already collided by predicting their own. The row's content is written out
above so the coordinator can file it verbatim under whichever id is free.

Nothing is blocked from working in the meantime: the mechanism ships wired, tested and
refusing.
