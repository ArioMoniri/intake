## What is delivered, and what fails closed

Every clause of the acceptance is delivered as a **pure, node-tested mechanism**
wired into the app. Two device capabilities the feature consumes are NOT
available in the Expo managed workflow, and both **fail closed** rather than
being faked (CLAUDE.md invariant 17, HUMAN_BLOCKERS.md Rule 2):

1. **MDM managed-app-configuration read** (iOS `com.apple.configuration.managed`,
   Android `RestrictionsManager`) — where a clinic provisions the kiosk PIN.
   No Expo module reads it, so `readKioskProvisioning()` returns null and the
   device is treated as a normal phone: kiosk mode **cannot be armed**, and no
   PIN is invented.
2. **Lockdown / guided-access state** (iOS `UIAccessibilityIsGuidedAccessEnabled`,
   Android lock-task state) — so `probeLockdown()` reports `needs_dev_build`,
   which `tamperDetected()` treats as a tamper: a provisioned kiosk **never
   silently runs unlocked**.

Both are the dev-build native layer gated on **HB-A3** (Apple/Google developer
accounts + EAS dev build → "every mobile issue that produces a real build") and
filed by **files/10 §4.7** ("Attestation and pinning have no off-the-shelf
path … file it as its own issue"). No new HUMAN_BLOCKERS id was minted: the
native layer is HB-A3 + the §4.7 issue, and no per-clinic PIN value is a named
human's to supply into this repo. This is the same honest fail-closed shape as
`lib/auth/integrity.ts` (`needs_dev_build`) and INT-142's transport-injected
sync.

### Acceptance, clause by clause

1. **no persistence.** `kioskSuppressesPersistence(kioskActive)`
   (`src/lib/kiosk/kioskState.ts`) gates the offline-draft mirror in
   `src/lib/session.tsx`: while kiosk mode is active the persist effect returns
   before writing anything, so no draft or answer reaches disk (invariant 3
   reinforced for the typed draft, invariant 6 no ids in logs). Entering kiosk
   mode also crypto-shreds anything already at rest (reusing INT-142's
   `shredDrafts`). Proved by `kioskState.test.ts` "no persistence in kiosk
   mode" and the session source-slice in `e2e/kiosk.spec.ts`.
2. **wipe on idle/background.** `KIOSK_IDLE_WIPE_MS = 60_000` and
   `mustWipeOn("idle"|"background")` define the two triggers;
   `nativeKiosk.ts::watchKiosk` owns the 60 s idle timer and the AppState
   background listener, calling `session.wipeSession()` (clears notes + local
   visits + crypto-shreds drafts). Background additionally flags a tamper. The
   timer lives in the `.ts` adapter on purpose — `e2e/a11y.spec.ts` BK13 pins
   that no `.tsx` under app/ or components/ owns a timer but otp.tsx.
3. **tamper alert.** `tamperDetected(lockdown)` returns true for anything but a
   confirmed `locked` — unlocked, unknown, or unprobeable — so there is no
   "assume fine" branch. `KioskGate` renders a large-type alert (announced via
   `live="assertive"`) and blocks; recovery requires BOTH a correct PIN and a
   restored lockdown (`kioskReducer` "recover"). Proved by
   `kioskState.test.ts` "tamper detection fails closed" and the reducer tests.
4. **large-type layout.** `kioskFontScale(base)` floors the kiosk surface at
   `LARGE_TEXT_SCALE` (1.6 — the same threshold at which screens change FORM),
   rising with the OS/app setting; INT-136 measured 52/248 Turkish labels
   overflowing at the largest step, so screens already survive this size. The
   gate screen sets its PIN field from `scaledSize("title", kioskFontScale(...))`
   with `allowFontScaling={false}` (SC 1.4.4), blocks screen capture
   (`useClinicalScreenPrivacy`) and reveals no prior-patient data (privacy).
5. **clinic PIN (title + task).** `verifyClinicPin(entered, provisioning)`
   verifies against the MDM-provisioned **salted, iterated SHA-256 hash** — the
   clear PIN is never stored on the device or in this repo — and **fails closed
   when nothing is provisioned**, so kiosk mode can be neither armed nor left
   without a real PIN, and never on a guessed value. Both edges (arm / disarm)
   go through the reducer, and disarm is staff-only.

## Files

- `apps/mobile/src/lib/kiosk/kioskState.ts` — pure policy: constants, PIN
  hash/verify, provisioning decode, tamper rule, large-type floor,
  no-persistence decision, the lifecycle reducer.
- `apps/mobile/src/lib/kiosk/index.ts` — barrel (PURE re-exports only; the
  native adapter is reached lazily, never re-exported).
- `apps/mobile/src/lib/kiosk/nativeKiosk.ts` — the device half (lazy import):
  managed-config read, lockdown probe, the idle timer + AppState listener. Both
  reads fail closed in the managed runtime.
- `apps/mobile/src/components/KioskGate.tsx` — the gate: pass-through on a
  normal phone; PIN entry / tamper alert / large-type privacy layout on a
  provisioned kiosk.
- `apps/mobile/src/lib/session.tsx` — `kioskActive`, `setKioskActive`,
  `wipeSession`; the persist effect is gated on `kioskSuppressesPersistence`.
- `apps/mobile/src/app/_layout.tsx` — mounts `KioskGate` around the app.
- `apps/mobile/src/lib/i18n/tr.ts` + `en.ts` — kiosk strings (tr is the source
  of truth; the one patient-facing line is `siz`, ≤ B1; staff PIN copy plainer).
- Tests: `apps/mobile/src/lib/kiosk/kioskState.test.ts`,
  `apps/mobile/e2e/kiosk.spec.ts`.
- `docs/security/threat-model.md` — the `kiosk` section's Signals/Tests updated
  to what actually landed.
