# Evidence — INT-262 · Research extracts: differencing gate across the register

## Acceptance (verbatim from docs/backlog/issues.yaml)

One acceptance line, four clauses, each with the artefact that satisfies it:

- [x] "the export gate reads the register for prior extracts of the same study+spec and
  refuses an overlapping window" — `ResearchExportGate._check_differencing`
  (`packages/intake_platform/src/intake_platform/research/extract.py`) reads
  `self._register.for_study(study.study_id)`, filters to the same `spec_name`, and counts
  register rows whose stored `[window_start, window_end)` intersects the requested cohort
  window (half-open: `window_start < prior_end and prior_start < window_end`). Called from
  `build()` after the retention gate and before any patient row is read.
- [x] "unless the study's registry row states an explicit query budget" — a new optional
  `query_budget: QueryBudget | None` on `StudyRecord`
  (`.../research/studies.py`). When a study states a `QueryBudget`, overlap is permitted up
  to `max_overlapping_extracts` and the request beyond it refuses `QUERY_BUDGET_EXHAUSTED`.
- [x] "the budget has no default and an absent one fails closed" — `query_budget` is `None`
  when unstated, and `_check_differencing` refuses `OVERLAPPING_WINDOW_UNBUDGETED` on any
  overlap for such a study. Inside `QueryBudget`, `max_overlapping_extracts` is required
  (`Field(ge=1)`, no default) — no agent invents how many overlapping requests a study may
  make (invariant 17; HB-R1). The shipped `study_registry.yaml` documents the optional field
  and its fail-closed absence.
- [x] "golden test differences two extracts and proves the second is refused" —
  `tests/research/test_differencing_gate.py::test_a_second_extract_over_an_overlapping_window_is_refused`
  serves a wide-window extract, then requests the same spec over a window wholly inside it
  (the classic differencing pair) and asserts the second raises `ResearchExportRefused` with
  reason `OVERLAPPING_WINDOW_UNBUDGETED`, and that the refused request left no register row.

sec_row: `learning-loops`. The `docs/security/threat-model.md` `learning-loops` section is
extended here with the differencing threat, the INT-262 control, the two new refusal-reason
signal classes, and the golden test. files/10 §9 "Learning loops" row (threat

## What this closes, stated narrowly

INT-230's k gate holds for ONE extract: every quasi-identifier combination carries at least
k subjects. It does not compare a new request against the extracts already served, so an
investigator who takes the same spec over a wide window and then a narrower one *differences*
the two and recovers the excluded cells — at any k. INT-230 stated this gap in its own
evidence rather than papering over it; INT-262 is the policy that reads the register the k
gate already populated.

The one parameter is not an engineering choice. How much overlap and how many requests a
study may make is an ethics-committee decision (HB-R1). So the budget has **no default** and
an absent one **fails closed**: a study that states no `query_budget` refuses every
overlapping window. A study that states one permits overlap up to its explicit count. This
is the same fail-closed posture as INT-230's `research_extracts` retention row and the empty
study registry — the mechanism ships, the number is left to the human, and the gate refuses
until it is supplied.

## Invariants touched

- **Invariant 4 (consent scope + hash-chained audit):** unchanged. A differencing refusal is
  recorded through the existing `_record_refusal` → `ConsentAudit.record` path as
  `research.extract.refused.<reason>`, carrying only the reason class and the study ref; the
  served path still audits `research.extract.served`. `test_an_overlap_refusal_is_audited_
  with_a_reason_class` asserts the chain verifies and the window is not in it.
- **Invariant 6 (no PHI/PII in logs):** the two new `ResearchExportRefused` messages and the
  audit action carry no window, no cohort size and no count; `test_the_refusal_names_no_window
  _and_no_cohort` and the audit test pin this.
- **Invariant 12 (learning is proposal-only):** unchanged — this is an export guardrail that
  only *refuses*; it modifies no red-flag level, instrument, consent text, Talker tool or
  routing. The package's AST import/narrative/query gates (`test_export_gates.py`) still pass:
  the new code imports nothing outside the allow-list, binds no narrative name, and composes
  no query.
- **Invariant 14 (records/extracts are data, never instructions):** the register rows read by
  the gate are treated purely as `(spec_name, window_start, window_end)` facts to compare;
  nothing in a row is executed or interpreted.
- **Invariant 17 (no placeholders / no invented values):** `max_overlapping_extracts` has no
  default and the study `query_budget` is `None` (fail closed) until a human states it;
  `test_the_query_budget_count_has_no_default` and
  `test_the_research_package_states_no_overlap_default` enforce that no permissive default is
  introduced.
- **Invariant 35 (study assertion lifecycle, no grace):** unchanged and still in force — the
  differencing check runs after `_resolve_study`, so a lapsed or not-yet-in-force approval
  still refuses first.

## Human blocker

HB-R1 (open): the study registry ships empty, so no real extract is served and no real query
budget exists. The differencing gate, like the rest of INT-230's pipeline, is delivered
fail-closed against synthetic fixtures; the ethics-committee query-budget value for a real
study is authored by the owner + counsel into `study_registry.yaml` when a study is
registered. This issue builds the mechanism and leaves the content empty (HUMAN_BLOCKERS.md
rule 2).
