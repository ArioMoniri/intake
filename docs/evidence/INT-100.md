## 1. What was built

`services/voice-runtime/src/intake_voice_runtime/resilience/` has three modules. Each one
follows one rule.

| module | rule |
|---|---|
| `breaker.py` | **One breaker per vendor component, shared across sessions.** It is the three-state machine: closed, then open after `failure_threshold` *consecutive* failures, then half open once `open_ms` has passed on the **injected** clock, with one trial at a time. `close_after` clean trials close it. `BreakerBoard` holds one breaker per component, with a default policy plus per-vendor overrides. |
| `order.py` | **The failover order is read from `observability/registry.yaml`.** The walk starts at the entry component and follows each row's `fallback: component:<x>`. Rows with `self_hosted_now: false` are skipped and the walk continues through them. An `in-process:` fallback ends the walk. On the PHI path a lane that is not self-hostable raises `CloudFailoverRefused`, and a lane not cleared for PHI raises `LaneOffPhiPath`. The chain is **refused, not truncated**. Off the PHI path, self-hosted lanes are stably partitioned first. The checks live in `FailoverOrder.__post_init__`, so they hold for every order object, whichever function built it. |
| `failover.py` | **`FailoverSynthesizer` *is* a `SpeechSynthesizer`.** It tries the ordered lanes under their breakers within one 2 000 ms budget. Each attempt gets its **share of what is left as the wire timeout**: the remaining time divided by the lanes whose breaker would admit a call. The session's position in the order is **sticky**. When no lane is left it raises `SpeechLanesExhausted`, whose message carries component ids and outcomes and never the sentence. |

Wiring touches four existing files, each minimally:

- `talker/session.py`: a new `_emit` helper is used by `speak_step` and `_speak_backend`. It catches `SpeechLanesExhausted`, calls `fall_back_to_typed(SPEECH_LANES_EXHAUSTED)`, and re-emits **the same verbatim string** on the screen in the same turn. A session with no screen raises `KillSwitchNotArmed`, chained to the exhaustion. It is loud rather than silent.
- `typed/switch.py`: `LaneSwitchReason.SPEECH_LANES_EXHAUSTED`. This is the fourth route into typed, and the blueprint names it: files/03 §4.9.4 row 11 (*"then to row 12 for the rest of the session, then to `typed`"*) and row 7 (*"repeated failure routes to `typed`"*). `tests/voice/test_typed_parity.py` pins the closed set, now four members, with the citation.
- `adapters/speech.py`: `HttpSpeechSynthesizer.synthesize(..., timeout_s=None)` puts the per-attempt timeout on the request. httpx applies it to the connect and the read. `RecordedSpeechSynthesizer` accepts the argument and has no wire to bound.
- `metrics.py`: three new families, catalogued `live` in `observability/metrics_catalog.yaml` (inv. 13):
  - `vendor_breaker_state{component,state}` (one-hot gauge)
  - `vendor_breaker_transitions_total{component,from_state,to_state}`
  - `vendor_failovers_total{from_component,to_component}`, where `to_component="typed"` means no speech lane was left

  Label values are registry component names, the closed breaker states, or `typed`. None is a session id or text (inv. 6).

Nothing above the `SpeechSynthesizer` port changed. `SpeechRouter`, the metering decorator
and `composition.build_residency_tr_session(synthesizer=…)` take the ladder unchanged.

### Where the defaults come from (no invented numbers)

| value | source |
|---|---|
| deadline 2 000 ms | INT-024 / INT-100 acceptance; pinned equal to `intake_platform.chaos.FALLBACK_DEADLINE_S × 1000` by a test |
| `open_ms` 30 000 | files/03 §4.5b anti-flap: *"never change state more than once per 30 s"* |
| `failure_threshold` 2 | files/03 §4.5b T3: *"two consecutive `request_repeat_or_clarify` on the same step"* before the channel is given up |
| chaos endpoint latencies 0.14 s / 0.52 s | files/03 §4.9.1 row 11 (measured TTFT) and row 12 (*"hard architectural floor"*) |

### Decisions recorded here

1. **Sticky per session, shared per vendor.** §4.9.4 row 11 says *"for the rest of the session"*, and §4.9.1 row 11 says *"two voices mid-session breaks voice identity"*. So a session never climbs back to an earlier lane, even after its vendor recovers. The breaker is shared, so a *new* session skips a vendor that is known to be dead without dialling it.
2. **A registry that names a cloud fallback on the PHI path is refused, not skipped.** Skipping would hide the defect until the day the primary died.
3. **Not lane failures:** a numeral in the text (inv. 22 is refused before any lane or breaker is touched, because it is the caller's defect) and an attempt the budget left no time for (`OUT_OF_TIME` blames no breaker).
4. **The bound is measured server side**, where INT-091 and INT-093 measure theirs. It runs from the turn's start to the moment the device is handed the first frame or the sentence. The ports are synchronous, as every speech port in this service is. The bound therefore rests on each adapter honouring the timeout it is handed on the wire. `HttpSpeechSynthesizer` puts that timeout on the request, and the chaos endpoint holds the far side of the wire to it.
5. **Scope: speech *egress* lanes.** The Talker is handed transcripts, not audio, so the lanes it can fail over are TTS lanes (§4.9.1 rows 11 → 12). The ASR row-1 → row-2 fallback (§4.9.4 row 1) lives in the media plane. It has one registry lane today: row 1 has no registry row (HB-I11) and row 2's fallback is `none`. `breaker.py` and `order.py` are keyed by component and bind to it unchanged.

### Near-miss negative controls (behavioural red runs)

A red run caused only by a missing module proves little on its own. So each load-bearing line
was mutated after green, the two suites were re-run, and the file was restored from a backup
copy (never `git checkout`):

| # | mutation | caught by | result |
|---|---|---|---|
| M1 | no budget split: each attempt gets all remaining time | hung-primary / hung-lanes chaos tests; budget-share unit tests | 4 failed, 61 passed |
| M2 | `FailoverOrder` stops refusing a non-self-hostable lane on the PHI path | cloud-fallback chaos test; two invariant-19 unit tests | 3 failed, 62 passed |
| M3 | the session no longer catches `SpeechLanesExhausted` | three typed chaos tests; three session unit tests | 6 failed, 59 passed |
| M4 | the ladder rewinds to the primary on every call (not sticky) | "stays on the fallback voice" chaos test; two ladder tests | 3 failed, 62 passed |
| M5 | the breaker opens one failure late (`>` for `>=`) | the next-session chaos test; nine breaker/ladder tests | 10 failed, 55 passed |

M1 matters for more than arithmetic. Without the split, a hung primary spends the whole
budget. A healthy fallback is then never tried, and the patient loses their voice for no
reason. `test_a_hung_primary_cannot_spend_the_fallbacks_time` is the scenario that shows it.

## 3. Green run

`uv run pytest tests/chaos/test_vendor_failover.py tests/voice/test_vendor_resilience.py` → **65 passed**
(11 chaos + 54 unit), plus `test_typed_parity.py::TestKillSwitch` green.

Chaos timings, all on the harness's virtual clock with no sleep. The Backend is stalled
underneath every chaos turn.

| scenario (turn 2, after a healthy turn 1) | patient gets | at (from turn start) |
|---|---|---|
| primary **dies in flight** 200 ms into the call | next lane (`freya-tts`) audio | **720 ms** (200 + 520) |
| primary **hung** (accepts, never answers) | next lane audio: primary abandoned at its 1 000 ms share | **1 520 ms** |
| both lanes **killed** (connect refused) | the question on the **screen**, verbatim; session `typed`, `modality_degraded` | **0 ms** |
| both lanes **hung** | the question on the screen, each lane held exactly 1.0 s on the wire | **2 000 ms** (= bound) |
| next session after the kill (breaker open, threshold 1) | `freya-tts` audio; primary not dialled (`SKIPPED_OPEN`) | **520 ms** |
| invariant 9: same kill turn with the Backend stalled 0 s / 10 s / 10 000 s | identical audible and turn latencies | 720 ms each |

The chaos order is `failover_order(COMPONENT_OF[TTS_DYNAMIC])` read from the real registry,
which gives `("voxcpm2-tts", "freya-tts")`. Each lane is the real `HttpSpeechSynthesizer`
behind `httpx.MockTransport`, so no socket is opened and no model is dialled.
