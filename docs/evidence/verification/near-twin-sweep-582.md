## Method

1. **Chains.** The sweep covers 91 chains: base, then the cluster candidate the branch `extends`, then the specialty candidate. Chains were merged as `protocols.compile.resolve._merge_chain` merges them:
   - a child slot with the parent's id, in the same section, replaces the parent slot;
   - any other id is a separate question.

   Only slots with an `ask_tr` count. Base's red-flag probe slots and instrument slots have no ask text yet (HB-C1). Their overlap with medical `son_gunlerde_ates` and `istemsiz_kilo_kaybi` and with women's health `gebelikte_kanama` is cluster-wave-a §A's NOTE for the base owner, and is not counted again here. A chain has 52 to 75 askable slots, and 196,504 slot pairs were scored across the 91 chains.
2. **Normalisation for Turkish.**
   - Case folding is Turkish-aware (İ→i, I→ı), and circumflexes are folded (â→a).
   - The text is tokenised on letters.
   - A stoplist removes question particles (mı/mi/mu/mü), existence verbs (var, oldu, oluyor), recall-window words (son, günlerde, zamanlarda, aylarda), addressee words (çocuğunuz…, bebeğiniz…) and generic verbs (fark ettiniz, hissediyor, kullanıyor).
   - Stems are the first four letters of each remaining token (F4). A fixed-prefix stem copes with suffix chains, such as ateş/ateşiniz or kanama/kanıyor.
3. **Pre-filter.** A pair is a candidate if any one of these holds:
   - **L1:** `difflib.SequenceMatcher` ratio ≥ **0.60** on the normalised content text;
   - **L2:** F4-stem Jaccard ≥ **0.40**, with at least **2** shared stems;
   - **C:** at least one shared construct concept from a lexicon of **71** concepts written as Turkish stem prefixes. Examples: FEVER *ateş, titre*; BLEED *kana, kanı, lekelen*; PREG *hamile, gebe*; URINE *idrar, çiş, işeme, ıslak, bez*; VERTIGO *dönme, döndüğ, denge*; FUNCTION *işleri, günlük yaşam*; REASON *getiren, randevunuz*; DURATION *ne zamandır, ne kadar sür*. Six concepts too broad to decide alone (PAIN, MED, HEAD, TOOTH, EYE, FAMILY) never make a candidate by themselves.

   The result is **1,604** unique candidates, one per pair of ids and texts, merged across chains. By rule: C alone 1,382; L1 99; L1+L2 39; L1+C 29; L2 21; L2+C 17; L1+L2+C 17.
4. **Recall.**
   - The lexicon was tuned on a check set: the 35 pairs that earlier reviews named (the §F rows still open, the §F overlap lists, the 582 review NOTE, the wave 1–3 base twins).
   - The first pass (L1, L2 and C gated at Jaccard ≥ 0.20 or ratio ≥ 0.45) gave 630 candidates and missed six of them. They included `onceki_psikoterapi` against `onceki_ruh_sagligi_destegi` and `son_adet_tarihi` against `lmp_date`, which share one construct word and little else.
   - C was therefore made sufficient on its own. The lexicon was also corrected for Turkish false friends: *gör* matches *görüşme*, *boy* matches *boyunca*, *dön* matches *dönem*, *aşı* matches *aşırı*, *karın* matches *karıncalanma*, and *bez* matches *tiroit bezi*. The final pre-filter catches **35 of 35**.
   - This is a floor, not an independent recall estimate, because the check set shaped the lexicon. So a second, independent pass was run: targeted construct searches over every branch and cluster ask (medicines, allergy, course, location, chronic-disease umbrellas, pregnancy, LMP, onset, treatments tried, immunosuppression, anticoagulant, support, substance). They were compared with the base and cluster slots of the same chain.
   - The second pass added **43 pairs** the pre-filter had missed: 38 OVERLAP and 5 DISTINCT. Most are medicine items (MED is excluded as too generic) and umbrella items whose other members are not named.
5. **Judgement.** Every candidate was read with both texts, both types and both gates. The rules:
   - **SAME** means the same construct, polarity, type and recall window, and only the wording differs. Merging under one id loses nothing.
   - **OVERLAP** means the same construct, with a bounded difference in one of these:
     - recall window or threshold;
     - subject (the child against the answerer);
     - type or answer form (for example code against boolean, date against duration, or boolean against degree);
     - polarity;
     - scope, where one item contains the other explicitly (an "A or B" item against an A item, or an umbrella whose examples name the other item).

     Merging would change what is recorded, so the clinician decides.
   - **DISTINCT** means a related but different fact. These count as DISTINCT:
     - a different construct;
     - a named symptom's duration against the complaint's duration (a different referent, which coincides only when that symptom is the complaint);
     - a named site against "any" (hand surgery against any surgery; breast lump against a lump in the complaint area);
     - a specific pattern or context attached to a general symptom (fever with headache; bleeding after intercourse; tiredness that limits daily tasks);
     - a gated follow-on detail of the other slot.

     One exception applies: where the named referent is the clinic's defining complaint (pain in algoloji, weight in obezite), it is the complaint, and the pair is OVERLAP (T35, T40).
   - A type that differs only because an item has no `gen:` line (`soru_N` defaults to `string`) is not a type difference. The PR #582 rebinds treated it the same way.
6. **Counting unit.**
   - A row is one pair of slot ids. Where the same pair recurs across chains with the same verdict, it is one row that lists its chains. Pairs involving the fixed slots (`basvuru_nedeni`, `sikayet_suresi`) are one row per id pair, because their texts vary by branch.
   - A row marked ×2 or ×3 counts as two or three pairs.
   - The 81 pairs where one slot's `ask_if` reads the other are gated follow-on details. All 81 were read and are DISTINCT.
   - The 97 fixed-slot rows that are not twins pair the reason or duration ask with an unrelated item, mostly through the REASON and DURATION concepts. All 97 were read and are DISTINCT.
