# INT-428 — hosted model lanes for the synthetic deployment, switchable from the admin panel, with a GPU switch-over

GitHub #724 · Sec-Row `llm-boundary` · ADR-035 · branch `int-428-hosted-lanes`

## Goal

The owner's decision of 2 Oct 2026 (chat, verbatim):

> "use openai or similar provider let api to be set from admin panel and let to switch for gpu models"

It was extended the same day: each lane picks a provider and a model, and a
typed `role → (provider, model)` resolver is exposed for INT-430. It was then
narrowed by two binding reviews:

- **Medical review, finding 12:**
  - hosted and mock lanes are unrepresentable for real PHI, with no DPA branch;
  - a swap is gated on red-flag extraction goldens and the negation set for the exact model version;
  - the model is frozen per session;
  - the synthetic flag is immutable;
  - synthetic or hosted runs never count as evidence.
- **AI/ML review:**
  - hosted lanes belong to a deployment, not a tenant;
  - the resolver returns attested registry components only;
  - an identity probe and a per-call model check;
  - dated snapshots only;
  - one outcome class for refusals;
  - no mock in the admin console.

## The resolver interface (for INT-430)

```python
# intake_platform.model_lanes (router.py)
class ModelResolver(Protocol):
    def resolve(self, role: str, *, tenant_id: str | None) -> ModelAssignment: ...


@dataclass(frozen=True)
class ModelAssignment:
    role: ModelRole  # .id ("llm.council.chair"), .lane (Lane.LLM)
    available: bool
    reason: str  # closed code
    route: LaneRoute | None  # .kind: RouteKind.SELF_HOSTED | HOSTED; .provider: ProviderId | None
    model: ModelRef | None  # source, provider, model_id, version, wire, sha256, component, key
    data_class: TenantDataClass
    fallback: bool = False
    egress_data_class: DataClass | None = None
    qualified: bool = False
    # .provider -> "self_hosted" | "<provider id>" | None ; .clinical_evidence -> bool


class SessionLanes:  # frozen per session
    def __init__(self, router: LaneRouter, *, tenant_id: str | None) -> None: ...
    def resolve(self, role: str | ModelRole | Lane) -> ModelAssignment: ...
```

`LaneRouter` implements `ModelResolver`. An `available` assignment has already
cleared the guard, both kill switches, the deployment, the allow-list row and
the key, the model allow-list or attestation, and the identity check.

## Decisions and what was not done

- **The egress allow-list row was not added: the permission classifier refused the edit.** The file is hook-protected, and its escape hatch is `ALLOW_PROTECTED=1` "only with an ADR". ADR-035 was written first, and the edit was attempted under that hatch, as the INT-018 precedent did.
  - The classifier refused it. The refusal was reported, not routed around.
  - The code fails closed without the row: the provider loads as unlisted, and every hosted lane reads `hosted_egress_not_listed`.
  - `hosted_model_inference` is in the egress tests' "awaiting the owner" set, the INT-329 precedent. The row and the purpose's removal from that set land together.
  - The row to add, under `tiers.dev` (the host is the provider's API host on its `openai.com` domain):
    ```yaml
    - name: openai-api
      host: api.<the provider's openai.com API host>
      port: 443
      protocol: https
      purpose_id: hosted_model_inference
      purpose: hosted LLM, ASR and TTS lanes for synthetic tenants only (ADR-035)
      phi_allowed: false
      basis: no-personal-data; synthetic deployment only (ADR-035)
    ```
  - The same human then:
    - regenerates `infra/security/squid/squid.conf` with `scripts/security/render_egress_proxy_conf.py`;
    - gives `scripts/ci/assert_no_vendor_calls.sh` an exception for exactly that (file, host) pair. That is a CI security gate change, and the human's call.
- **The OpenBao grant is in this change.** It was first reverted under LOOP.md's guardrail ("never touch … OpenBao policies"), then restored at the coordinator's explicit request: the console route and the owner's terminal route must both work. This is a security-relevant change and is flagged for review. What changed:
  - `configure_openbao` enables a KV v2 engine at `secret/`.
  - `infra/staging/openbao/intake-api-policy.hcl` grants the API token exactly `create, update, read` on `secret/data/model-lanes/*` and `read, list, delete` on `secret/metadata/model-lanes/*`.
  - `tests/infra/test_staging_compose.py` now pins those two paths and nothing wider.
- **Three routes, one record.** The admin console ceremony, the owner's terminal (`scripts/ops/put_provider_key.sh`, `make put-key PROVIDER=…`) and every deploy (`deploy.sh` → `infra/staging/load_provider_key.sh --if-present`) all end in `secret/model-lanes/providers/<provider>`.
  - The SSM SecureString names are the coordinator's: `/intake/staging/openai_api_key` and `/intake/staging/elevenlabs_api_key` (us-east-1).
  - The key is never an argv element, never in the SSM command text, never printed. Only "set · …last4" or "not set" is reported.
  - A parameter that exists wins at the next deploy.
  - Tests are in `tests/infra/test_put_provider_key.py`: a fake `aws` records every argv and file, and the suite checks the no-argv rule, the redaction, the near miss on the last four, and the host half's names.
  - The terminal route is an operator action outside the console's four eyes. Its record is CloudTrail.
- **Not into the API environment.** The coordinator asked for the keys to go into the API env as well (`TTS_ELEVENLABS_API_KEY` and the OpenAI variable). That was not done. Invariant 14 keeps secrets in OpenBao, the router reads the key from there, and nothing on the staging API reads either variable: the George route is dev-only, and ElevenLabs is not yet a lane.
- **No new third-party dependency.** The adapter is plain `httpx`, with no vendor SDK. `packages/hosted-lanes` is a first-party workspace member, so there is no licence to verify.
- **The model ids are dated snapshots, by the provider's published names:**
  - `gpt-4o-mini-2024-07-18` (structured outputs);
  - `gpt-4o-mini-transcribe-2025-12-15` and `gpt-4o-mini-tts-2025-12-15` (the provider's audio-model update of 15 Dec 2025).
  - None was exercised live, and none is pinned in files/03 §4.9.1: they are hosted catalogue values, which ADR-035 keeps out of the self-hosting registry.
- **Self-hosted ASR has no attested model.** `whisper-tr-medical` carries no model_id, revision or sha256 in the registry, so the ASR lane has nothing selectable until it is pinned. This is a registry change, not a console one.
- **Interpretation, `tts` is not gated:** it speaks scripted, verbatim text and extracts nothing. The swap gate covers `llm` and `asr`.
- **Split rows for the coordinator to allocate.** These are AI/ML items not in this change:
  1. extraction clients (`extraction/gateway.py`, `records/lab_extraction.py`) built only via `guarded_transport`. This needs a second, internal-model egress policy (the ADR-026 shape), because self-hosted hosts resolve to private ranges;
  2. `GET /identity` on the GPU servers (`model_id`, `revision`, `weights_manifest_sha256`). Until then no self-hosted lane is healthy through the router;
  3. a per-lane drift canary that quarantines on drift;
  4. recording keys that carry provider, model@revision and decoding parameters;
  5. a CI lint for schema keywords a lane cannot enforce;
  6. an egress route for the synthetic host (a forward proxy rendered from the allow-list; the API's networks are internal);
  7. the mobile release build calling the lanes. Voice is `__DEV__`-only today (INT-421).

## Owner steps to switch a hosted lane on

Each step is a human's.

1. **Add the egress row.** Apply the allow-list row above under ADR-035 (`ALLOW_PROTECTED=1`).
   - In the same change, remove `hosted_model_inference` from `PURPOSES_AWAITING_THE_OWNER` in `tests/security/test_egress_allowlist.py`.
   - Regenerate `infra/security/squid/squid.conf`.
   - Add the INT-001 gate exception for exactly that file and host.
2. **Give the synthetic host a route to the provider.** Its API networks are internal, so it needs a forward proxy rendered from the allow-list (split row 6). Then set `INTAKE_EGRESS_PROXY_URL`.
3. **On the synthetic host's OpenBao:**
   - enable a KV v2 engine at `secret/`;
   - grant the API token `create, update, read` on `secret/data/model-lanes/*` and `read, list, delete` on `secret/metadata/model-lanes/*`.
4. **Enter the key.** In the console go to **Model lanes**, then the provider row, then "Set key". A `platform_owner` or `platform_admin` enters it and gives a reason.
   - A second human approves under the Approve control. That human is `platform_owner`, `qms_owner` or `compliance_officer`, on a distinct credential and session.
   - Approve is disabled on the page until step-up is wired (`step_up_unwired`, as in the CI/CD and Voice modules), so today the second key is the API route `POST /admin/model-lanes/keys/pending/<id>/approve` with a fresh `assertion_id`.
   - The console then shows "set · …last4".
5. **Switch the lane.** Use the lane row's "Switch" with route `hosted:openai` and the model.
   - `tts` can switch at once.
   - `llm` and `asr` need a green qualification row for that exact snapshot first. Its golden set and sensitivity floor are a physician's decision, and the runs are `make eval-live`.
   - A second human approves, as in step 4.
6. **Fill the prices.** Put the owner-filled unit prices and the openai budgets in `infra/costs/unit-prices.yaml` (INT-439 carries a sourced price book).
7. **Revert when the GPU is back.** "Switch to GPU / self-hosted" is one key, and refuses until the GPU's `/identity` proves the attested model (split row 2).
