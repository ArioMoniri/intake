**The cycle (`intake-aws-ci-runner.service` → `cycle.sh`, as root, unsandboxed).**
1. Run the guards: layout, disk, access (ACL deny, then proved as `ghrunner`)
   and net (iptables owner-match chain `INTAKE-AWS-CI-OUT`: 15 v4 and 11 v6

2. Make a fresh runner tree from the verified distribution.
3. Register with `--ephemeral --replace --disableupdate`.
4. Run `systemctl start --wait intake-aws-ci-job.service`, which takes one job.
5. Clean up: every container, volume, network and build cache; any image whose
   tags have no registry digest of the same repository; stray `ghrunner`
   processes; and the runner tree, workspace, home and temp. Then loop.

## The registrar (added after the owner placed the admin token)

The runner stays ephemeral, as INT-206 requires. A persistent runner was
considered and refused: the pool schema rejects it, and the session classifier
refused relaxing that rule. Instead, the supervisor mints a fresh registration
token before every registration.

**How it works.**
- `cycle.sh` `registrar_token`, running as root, reads the owner's fine-grained
  token (this repository only, Administration: read and write) from the SSM
  SecureString `/intake/staging/gh_runner_admin_pat`, using the instance role.
- The token goes to `curl` as an `Authorization` header on stdin (`-H @-`). It
  is never an argument, never printed, and unset immediately.
- Only the minted registration token leaves the function, and it reaches
  `config.sh` through `ACTIONS_RUNNER_INPUT_TOKEN`.
- The one-hour hand-over token (`scripts/ci/aws_runner.sh token`) is the
  fallback. It is deleted as soon as the registrar works.
- The old `registrar` hand-over subcommand is gone: the admin token is the
  owner's to place in SSM.

- Root can read the parameter, which is 158 characters long.
- `ghrunner`, inside the job sandbox, gets **blocked** on all three routes:
  - `aws ssm get-parameter` (no credentials: the metadata service is rejected);
  - TCP to 169.254.169.254;
  - listing `/etc/intake-aws-ci-runner`.
- **The parameter does not hold a token.** Its value is 16 whitespace-separated
  words of prose, and no word has the shape of a fine-grained (`github_pat_…`)
  or classic (`ghp_…`) token.
- The registrar therefore refuses, and the supervisor registers with the
  one-hour fallback. For this PR's verification that fallback was refreshed
  from the laptop every 40 minutes.
- The owner has to overwrite the parameter with the raw token. From the next
  registration on, no laptop is involved.

## Limits, stated rather than hidden

- **Registration depends on the admin token in SSM.**
  - If it is missing, malformed or revoked, and no one-hour fallback is present,
    the supervisor stays offline and retries every 30 s.
  - It never registers any other way.
- **One runner, so jobs run one at a time.** check-py alone took 40 min on this
  host (INT-426). A pool of two or three was considered and not built:
  - check-integration publishes fixed host-loopback ports (5432, 8200, 9000,
    3310, 8091, 8092);
  - its compose project is named after the checkout directory.
  So two runners would collide whenever two PRs reach that job at once, and
  the disk and CPU headroom does not change that.
- **The image store is kept between jobs, for Docker Hub's anonymous pull
  limit.**
  - Containers, volumes, networks and build cache go after every job, and so
    does any image not backed by a registry digest.
  - A job that deliberately bind-mounts the data root through Docker could still
    alter a cached layer. Code that can do that already runs on this runner, and
    fork pull requests do not run workflows in this private repository.
- **The heartbeat.**
  - The `ci-runners` probe now reports a missing heartbeat (Failed) for
    `intake-aws-ci`, rather than Skipped.
  - No collector reads the GitHub runners API into the sweep yet.
  - `self_hosted_now` stays false in the registry until something beats.
- **Residency.** This pool is in us-east-1, not Türkiye. The TR-DC pool of
  files/06 §5 stays open under HB-I7 and HB-L11. That is safe only because no
  PHI is ever in CI, which the six-surface policy enforces.
