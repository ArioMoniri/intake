# INT-386: Typed lane, note, patient summary and FHIR narrative quantities use the locale decimal separator

**Epic:** E07-records · **Phase:** P1 · **Sec-Row:** records · **GitHub:** #638
**Follows:** INT-385 (PR #637), whose evidence recorded these renderers under "Not in scope".
INT-096 first recorded them as finding F2.

## Problem
CLAUDE.md invariant 22: *"Numbers never cross a representation boundary unguarded. …
`useGrouping:false` for every clinical quantity; number + unit is one non-breaking atom."*

INT-385 made record quantities write the reader's decimal point (`tr` comma). Four other text
renderers kept a private copy of the rule. Each one wrote `Decimal`'s own `str()`, which uses a
full stop, for a Turkish reader:

| Surface | Function (on `main`) | Wrote for 72.5 kg / 38.50 °C |
|---|---|---|
| Typed profile's numeric rail | `typed.render.render_measure`, `numeric_rail` | `38.50 °C` |
| Clinician note, self-reported measures | `note.composer._measure_line` | `weight: 72.5 kg` |
| Patient summary, measures card | `summary.builder._measure_text` | `72.5 kg` |
| FHIR document narrative, measurements | `clinical_schemas.mappers.document._section_lines` | `<p>weight: 72.5 kg</p>` |
| FHIR document narrative, speech measures | `clinical_schemas.mappers.document._konusma_lines` | `f0_mean_hz: 142.5 Hz` |
| Clinician note, speech measures (SOAP and PDF) | `note.render._konusma_lines` | `f0_mean_hz: 142.5` |

(In the output, the space inside each atom is U+00A0.) A Turkish reader takes `72.5` as grouping. After
INT-385, a note could show a record line with a comma (`Kreatinin 12,5 mg/dL`) above a
self-reported measure with a full stop. The last row is not one of the four renderers the issue
names. It is the clinician note's second quantity renderer, which the acceptance ("every
clinical quantity in the … clinician note") covers. It prints the same speech measures that
the FHIR narrative prints, so it is fixed here too, so that the two faces of one note agree.

## Change
**One renderer, moved one layer down.** INT-385's renderer lived in
`intake_platform.records.numbers`. The FHIR mapper is in `clinical-schemas`, and that package
depends on pydantic alone. `intake_platform` depends on `clinical-schemas`, so the mapper could
not import the renderer without a cycle. The renderer's five objects moved, unchanged, to a new
module, `packages/clinical-schemas/src/clinical_schemas/quantity.py`: `render_quantity`,
`quantity_atom`, `NBSP`, `DECIMAL_SEPARATORS` and `QuantityLocaleUnknown`. Their bodies are byte
for byte what INT-385 merged. `intake_platform.records.numbers` imports them and keeps them in
`__all__`, so `intake_platform.records.render_quantity is clinical_schemas.quantity.render_quantity`
(a test asserts all five identities). No caller of the records package changed.

`clinical_schemas.quantity` adds `float_magnitude(value: float) -> Decimal`. The speech measures
(`KonusmaOzellikleri`) are `float` fields. `Decimal(4.1)` is the binary expansion
`4.0999999999999996447286321199499070644378662109375`, so the helper reads the digits Python
prints (`repr`). It refuses NaN and infinities with a message that does not echo the value.

**Each surface writes through it, with its reader's locale:**
- `typed/render.py`: `render_measure(value, unit, *, locale)` and
  `numeric_rail(values, facts, *, locale)`. `locale` is keyword-only with no default, as in
  INT-385. The private `NBSP` is gone, and `typed.render.NBSP` now re-exports the shared one.
  The "recorded defect" paragraph in the module docstring is replaced with a description of
  the single renderer.
- `note/composer.py`: `_measure_line(value, *, locale)`. `compose` passes `meta.language`.
- `note/render.py`: `_konusma_lines` writes each speech measure with
  `render_quantity(float_magnitude(...), locale=note.meta.language)`. The unit stays in the
  key, as it always has on this face.
- `summary/builder.py`: `_measure_text(item, *, locale)`. `build_patient_summary` passes the
  note's `meta.language`. `PatientSummaryCopy` has no locale of its own, and its copy is Turkish.
- `mappers/document.py`: a new `_measure_line(item, *, locale)` and
  `_konusma_lines(block, *, locale)`. `_section_lines` takes the locale from `meta.language`,
  which is "the document's language".

`NoteMeta.language` is `Literal["tr"]`, so every note, summary and FHIR narrative is written
with a comma today. The typed rail takes the session locale from its caller. The locale
registry holds only `tr` (`intake_platform.locale.registry`), and a session locale with no
recorded decimal point raises `QuantityLocaleUnknown` rather than being guessed.

**Unchanged.**
- FHIR structured values. `valueQuantity.value` is still a JSON number and `.unit` the unit
  string. Screening scores and `severity_nrs` are integers and never pass through the renderer.
- Every `text_tr`, instrument item, scripted prompt and copy string. No file under
  `packages/protocols`, `packages/voice-clips`, `talker/` or `docs/legal` changed.
- The protocol compiler's numeral expansion path.
- `apps/mobile`. The shared fixture's `rows` are unchanged, and only its `about` string grew;
  the app test reads `rows` alone.

**Two edge behaviours inherited from `quantity_atom`, recorded so nothing moves unseen.**
No test pinned either one, and no current producer reaches either one.
1. The typed rail used to write a blank or whitespace unit as `number` + U+00A0 + the blank
   string. It now writes the number alone, and it strips surrounding whitespace from a unit,
   which is INT-385's rule. Slot units are authored in packs, and none is blank.
2. A magnitude whose `str()` uses exponent form is now written positionally. That covers a
   `Decimal` such as `1E+3`, which the note, the summary and the FHIR narrative printed as
   `1E+3` and now write as `1000` (the typed rail already did this), and a speech-measure float
   printed as `1e-05`, which is now `0,00001`. That is INT-385's no-exponent rule. The stepper
   writes whole centimetres and kilograms, and real speech rates, F0 values and latencies never
   print that way.

## Found, not fixed
1. **A rule's `evidence` string still prints a full stop.** The clinician reads
   `triage.rules[].evidence` in the note and in the FHIR narrative (`rule <id>: <evidence>`).
   `packages/protocols/triage` writes it, and `test_numeric_carrier` pins `38.50` in it. It is
   not one of this issue's renderers, and a change under `packages/protocols` needs its own
   golden, `make safety` and CODEOWNER review (CLAUDE.md), so it needs its own issue.
2. **Open-map values are carried as written.** `reference_ranges.*`, `smoking.*` and
   `alcohol.*` in the narrative, and the OLDCARTS free text, are `JsonValue` or `str` fields
   that hold whatever their producer wrote. A string such as `3.5-5.5` is a range, and the
   invariant says a range is a signal to stop, not something to parse again. A bare JSON
   number placed in one of those maps would still print with a full stop. No producer writes
   one today.

Neither finding had an id minted here.
