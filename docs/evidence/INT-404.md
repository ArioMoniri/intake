# INT-404: Triage rule evidence strings render quantities with the locale decimal separator

**Epic:** E03-protocols · **Phase:** P1 · **Sec-Row:** triage · **GitHub:** #673
**Found by:** INT-386 (PR #657), evidence §8 "Found, not fixed" finding 1.
**Depends on:** INT-386, whose PR #657 moved the shared renderer to `clinical_schemas.quantity`.
The work was written on #657's branch while #657 was open. It was rebased onto `main` once #657
merged (`f0564e93`), and every gate below was re-run on the rebased tree ("Rebased onto `main`").

## Acceptance (verbatim, GitHub #673)
1. *"a rule's evidence line renders every quantity through the shared locale renderer
   (`clinical_schemas.quantity`): tr comma, `useGrouping:false`, number + unit as one
   non-breaking atom. The rule's thresholds and semantics are untouched (the stored comparison
   value stays numeric)"*
2. *"golden tests with a near-miss (a full stop in tr fails); `make safety` green; CODEOWNER
   review"*

## Problem
CLAUDE.md invariant 22: *"Numbers never cross a representation boundary unguarded. …
`useGrouping:false` for every clinical quantity; number + unit is one non-breaking atom."*

`triage.rules[].evidence` answers *which slot values satisfied the rule* (files/04 §5). It is
**generated, not authored**. `packages/protocols/src/protocols/triage/engine.py` builds it in
`_evidence` → `_render_value`: every slot the rule's `when` references, plus the tense anchor,
sorted, as `slot=value` pairs joined by `"; "`, with a contested slot's values joined by `"|"`.
A `Decimal` is written with `format(value, "f")`, which uses a full stop. Nothing about the rule
YAML reaches this line except the slot names in `when`.

The engine wrote that line once, as text, and every clinician face printed it unchanged:

| Face | Code on `main` | Wrote for a reading of 38.50 |
|---|---|---|
| SOAP note and PDF text layer | `note.render.document_lines` | `  [rf.x] …; sentetik.olcum=38.50` |
| FHIR document, triage narrative | `mappers.document._section_lines` | `<p>rule rf.x: …; sentetik.olcum=38.50</p>` |
| FHIR document, RiskAssessment `reasonCode.text` | `mappers.document._note_triage_resources` | `…; sentetik.olcum=38.50` |

`NoteMeta.language` is `Literal["tr"]`, so every one of these is read by a Turkish reader, who
takes a full stop as grouping. The line also carried no unit, even for a quantity slot.

## Change
**The engine records the reading in parts, and each face writes the parts for its reader.**

- `clinical_schemas.triage` gains `EvidenceSlot {slot, values: tuple[JsonValue, ...], unit}`, and
  `RuleFire` gains `evidence_slots: tuple[EvidenceSlot, ...] = ()`.
  - A number stays a number: the clinical carrier's `Decimal`, tagged on the wire (`"~d38.50"`)
    like every other `JsonValue`, so the declared scale survives JSON.
  - `RuleFire.evidence` stays a required string (the files/04 §5 shape). Its description now
    says what it is: the engine's own record of the reading, written for no reader.
- `protocols.triage.engine._rule_fire` builds both fields from one reading.
  - `evidence` is **byte for byte** what `main` wrote. The goldens below assert it for all nine
    readings.
  - The carrier's validator decodes the wire form, so the engine hands it
    `encode_json_value(value)`. A patient's string that begins with the decimal tag stays that
    string, which the `etiket-benzeri-metin` golden checks.
- `protocols.triage.context.TriageContext` gains `units: dict[str, str] = {}`: the declared unit
  of each quantity slot (files/03 §6 `unit:`), keyed like `answers`. It is evidence only. No
  predicate reads it, and a test asserts that level, acuity, fired rules and the engine's text
  are equal with and without it.
- A new module, `clinical_schemas.rule_evidence`, holds `render_rule_evidence(rule, *, locale)`.
  - It writes each part through `clinical_schemas.quantity.quantity_atom`: the reader's decimal
    point, no grouping, and one U+00A0 to the unit.
    - An `int` goes through `Decimal(int)`.
    - A `float` goes through `float_magnitude` (printed digits; NaN and inf are refused).
    - `bool` is checked before `int`, and `true`, `false`, `null` and strings are written as
      JSON writes them. A string is never given a unit and never re-read as a number
      (files/03 §4.9.6).
  - Inside a list or a map, items are separated by `;` when the reader's decimal point is `,`,
    so the Turkish `[1,5;"a"]` holds two items.
  - A fire with no parts (a FHIR import through `from_r4`, or a hand-built value) is carried as
    written.
  - `locale` is keyword-only with no default. An unknown locale raises `QuantityLocaleUnknown`
    on every line, including one with no number. The message does not echo the locale.
  - It is a separate module, not part of `triage.py`, because the TTS path imports
    `clinical_schemas.triage` and must not load a screen renderer. INT-386's runtime boundary
    test now lists it among the screen renderers, and it passes for all six TTS-path modules.
- **Each face writes for its reader:**
  - `note/render.py`: `document_lines` writes `render_rule_evidence(rule, locale=note.meta.language)`.
    The SOAP text and the PDF share it.
  - `mappers/document.py`: the triage narrative and the RiskAssessment's `reasonCode.text` both
    use `meta.language`. `_note_triage_resources` takes a required `locale`.
- `schemas/openapi.json` and `src/generated/models.ts` were regenerated with
  `make schemas-codegen`: `EvidenceSlot` is new, and `RuleFire.evidence_slots` is optional. No
  event schema carries `RuleFire`, so `schemas/events/` is unchanged.

**Unchanged.**
- No rule's threshold, level, `when`, `tense`, route, register, action or `text_tr`. No file
  under `packages/protocols/base`, `specialty`, `review` or `files/protocols` changed.
- `evaluate_triage`'s signature, the merge, the RED axes and the action scripts.
- The engine's `evidence` text, byte for byte.
- `packages/protocols` imports no text renderer (a static test).
- The standalone exchange mapper `to_r4.triage_to_risk_assessment` still writes the engine's
  text. See "Found, not fixed" 1.

**Authored text.** There is none on this path. The evidence line is generated, and no rule YAML
carries evidence text, so no clinical text was edited, and there is no hard-typed number in
authored text to hand to the owner.

**Data.** `evidence_slots` holds the same slot values that `evidence` already held as text, inside
the same note and triage documents, so it adds no new category of personal data, no column and no
recipient. The field is part of a JSON document whose column already carries its inventory
annotation.

## Found, not fixed
1. **The standalone exchange mapper still writes the engine's text.**
   `mappers.to_r4.triage_to_risk_assessment` puts `rule.evidence` into `reasonCode.text`. It has
   no reader locale (it maps a bare `RulesTriageResult`) and no production caller; the document
   bundle, which is the production path, is fixed here. Its tests pin an exact round trip through
   `from_r4`, and the structured parts do not cross FHIR in either mapper. Whether a bare exchange
   resource should carry a reader's line, and in which locale, is a decision for the mapper's
   owner, so it needs its own issue.
2. **Nothing in production fills `TriageContext.units` yet.** No production code builds a
   `TriageContext`. Today only the test simulator (`tests/sim/driver.py`) builds one, and
   `evaluate_triage` has no production caller. When one is written, it should pass each quantity
   slot's `Slot.unit`. Without units, the line still carries the reader's decimal point and no
   grouping. It only lacks the unit, as every evidence line did before this change.

Neither finding had an id minted here.
