### Regression tests (`tests/protocols/test_gen_specialty_packs.py`, +48 cases)

These tests read the committed review candidates along each `extends` chain:

- `test_a_rebound_branch_slot_takes_its_cluster_id` runs once per applied rebind (31 rows; 37
  before the six reverts that followed the review). Each row is `(slug, question number, old
  id, new id)`. It checks these things:
  - the branch declares the cluster id and not the old id;
  - the proposal's question with that number carries the new id, and the candidate's slot of
    that id asks that question's text, so two rebound ids swapped inside one pack fail;
  - the cluster declares that id, or holds it in its proposal (the dental airway item);
  - the two slots have the same type;
  - no `ask_if` in the branch still reads the old id.
- `test_a_near_duplicate_left_to_the_clinician_keeps_its_own_id` runs once per reverted rebind
  (6 rows: ic Q4 and Q5, KBB Q5 and Q7, AMATEM Q6, klinik psikoloji Q8). Each item keeps its
  pre-PR id, which carries that question's text, and the branch does not declare the cluster id,
  until the clinician decides (HB-C1).
- `test_committed_candidates_equal_the_generator_output` regenerates every generated review
  candidate (88 specialty, 8 cluster) into a temporary directory and compares bytes. The three
  hand-authored candidates are skipped, as the generator skips them.
- `test_no_chain_asks_one_text_under_two_ids` is a general check over all 91 chains: no branch
