linked file, for both `review/cluster` and `review/specialty`.

### Regression tests (`tests/protocols/test_gen_specialty_packs.py`, +47 cases)

These tests read the committed review candidates along each `extends` chain:

- `test_a_rebound_branch_slot_takes_its_cluster_id` runs once per applied rebind (37 rows). It
  checks four things:
  - the branch declares the cluster id and not the old id;
  - the cluster declares that id, or holds it in its proposal (the dental airway item);
  - the two slots have the same type;
  - no `ask_if` in the branch still reads the old id.
- `test_no_chain_asks_one_text_under_two_ids` is a general check over all 91 chains: no branch
  slot asks a cluster slot's exact text under another id.
- `test_no_chain_declares_one_slot_id_with_two_types` is also general: one id has one type in a
  chain (the `kemik_ilaci` defect, wave 8 §E-3).
- `test_the_chest_indrawing_twins_carry_the_cluster_text` and
  `test_substance_items_are_gated_to_self_report` cover the two text and gate alignments.
- `test_opposite_polarity_twins_keep_their_own_ids` is the near-miss control. The four
  hydration twins must not take a cluster id until the paediatrician fixes one polarity.
