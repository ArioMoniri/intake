## The dependency boundary

The recorders imported `intake_learning` (proposal targets, evidence checks) and
`intake_voice_runtime` (PolicyGuard's `ViolationClass`). The API depends on neither, and neither
edge should exist: one puts the Talker, the other the learning pipeline, inside the API's import
closure. Building the security route surfaced a third: `intake_platform.audit_verifier` registers
`sec_audit_chain_ok` when it is imported, and an importing API process would export that gauge at 0
— which `infra/observability/security-rules.yaml` (`sec_audit_chain_ok == 0`) reads as a broken
chain.

**Choice: a narrow typed interface in `packages/`.** `intake_platform.admin.console_vocab` holds
the four closed sets as `Final` tuples — `POLICYGUARD_CLASSES`, `PROPOSAL_TARGET_NAMES`,
`EVIDENCE_CHECK_NAMES`, `AUDIT_VERIFIER_OUTCOMES` — in the one package all four services already
depend on. The API builders use it, and the recorders reach it through the builders.
`tests/admin/test_console_vocab.py` imports each owner (the test lane may) and holds every copy
equal to it, in order, so an owner that adds, drops or renames a member fails the Python lane until
the console moves with it. A second test runs the API's import closure in a fresh interpreter and
asserts none of the three modules loads, with a near miss proving the probe sees one when it is
imported.

**Why not the alternatives.** Serving only what the API owns would have meant shipping the review
queue and the PolicyGuard section without their closed sets, and the view-models refuse rows
against exactly those sets. Making the owners import the interface would edit PolicyGuard and the
learning pipeline, both invariant-12 surfaces, for a console read. The cost of the chosen route is
one copy per set, and the parity test makes that copy fail loudly rather than drift.

**ADR.** No new package, service or dependency edge: the API's dependency set is unchanged. Not
filed as an ADR; flagged to the orchestrator in case it is wanted.

## Contract changes, and why

1. **No admin body carries a 64-hex value.** INT-180's
   `test_no_admin_response_carries_a_chain_hash` holds that HB-I12 publishes the chain head outside
   the `platform_admin` blast radius this console sits in. INT-192's security view-model was
   written against a recording and carried `local_head`, `anchor_head` and `entry_count`; served,
   it broke that rule. The audit-chain section is now the verifier's verdict only (`outcome`, `ok`,
   `anchor_available`, `reason`); the builder reads no chain; the view-model refuses a section that
   carries a head key or any 64-hex value (`ChainHeadOnConsole`, replacing `AuditHeadMalformed`).
   `test_security_console.py` holds the builder's verdict equal to `run_daily_verification`'s with
   no anchor.
2. **The cost config digest is 128 bits.** `config_identity` returns the first 32 hex of the price
   file's sha256, and the wire key is `config.sha256_prefix`, for the same rule. The access review's
   section digests are 128 bits for the same reason.
3. **PolicyGuard and egress counts carry their source.** `policyguard_classes` and
   `egress_denials` gain `window`, `source_available` and `source_reason`; a count is `null` while
   unread, and the safety view-model refuses a count (a zero included) with no scrape behind it
   (`PolicyGuardCountWithoutScrape`), as the security one already did for egress.
4. **The anchor blocker is HB-I12.** INT-192's copy named HB-I8 (backup retention). The new copy
   and notes say HB-I12. `intake_platform/audit_verifier/job.py`'s docstring still says HB-I8; it
   is not this issue's file and is left as found.

The four fixtures were re-recorded through the builders: protocols changed only its date, the cost
pair only the digest, safety and security the fields above.

## Found and not changed

`intake_platform.siem.load_console_feed` increments `siem_alerts_ingested_total` per alert each
time it is called (through `normalise_alert`). INT-205 built it as the console's feed, so every
Security page read re-counts the stream once one is mounted. No stream is mounted anywhere today,
so nothing is counted yet; the fix belongs to INT-205's module, not this issue.
