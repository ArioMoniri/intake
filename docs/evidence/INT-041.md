# INT-041 — Compiler: FHIR Questionnaire + openEHR bindings + Pydantic + TS + clip manifest, deterministic

Branch `int-41-compiler`. Acceptance (docs/backlog/issues.yaml, verbatim):

> two runs produce identical hashes; resolved-protocol hash pinned per session; compile artifacts under packages/protocols/dist
>

## What was built

`packages/protocols/src/protocols/compile/` and `packages/protocols/src/protocols/bindings/`, plus a `compile` subcommand inside the existing `protocols` CLI (alongside `coverage` from INT-042 and `generate-l0` from INT-057 — one CLI, one namespace).

The five files/03 §6 outputs, all deterministic:

| output | artefact |
|---|---|
| (a) FHIR R4 `Questionnaire` (items, `enableWhen`, ValueSets) | `questionnaire.json` |
| (b) openEHR operational-template bindings (archetype path per slot) | `openehr_bindings.json` |
| (c) Pydantic slot schemas for the engine | `slots.py` |
| (d) TypeScript types for the app | `slots.ts` |
| (e) clip manifest (`text_hash → clip_id` per voice) | `clips.<voice>.json` |
| — the files/12 §8 `questionnaire_definition` row | `manifest.json` |

URIs are consumed from the INT-033 namespace (`clinical_schemas.mappers.codes`: `PROTOCOL_CANONICAL_PREFIX`, `EXT_PROTOCOL_HASH`) rather than minted here. The one new canonical, `urn:intake:fhir:ValueSet:`, follows that module's own `urn:intake:fhir:<ResourceType>:<name>` shape.

## Invariant 22 — the compiler is where numbers stop

files/03 §4.9.6 moves Turkish normalisation into the compiler *"so that no TTS in any profile ever sees a numeral"*, because both candidate models ship a Turkish-hostile normaliser (Freya does not know the comma → `2.5 mg` reads as *"yirmi beş"*, a silent 10× dose error; VoxCPM2 routes Turkish to its English branch → `15 mg` reads as *"fifteen mg"*).

`protocols.compile.tr_orthography` expands digits, unit symbols and drug names to Turkish orthography **before** a clip-manifest entry is keyed, so the clip cache and the TTS request agree byte-for-byte. It fails closed on every form §4.9.6 names as a demonstrated corruption — `1/2`, `3x1`, `140/90`, a period used as the decimal separator — rather than guessing; doses are authored with the `tam` / `yarım` / `çeyrek` chips instead. `µ` U+00B5 is folded from `μ` U+03BC before lookup.

**Round-trip gate, textual half — implemented.** `assert_round_trip` inverts every replacement back to its source token and fails the build otherwise. It runs over the compiler's own replacements rather than over free text, because ordinary Turkish prose contains number words: `bir renk` is "a colour", not "1 colour". The fractional part is read digit-by-digit (`2,25` → *iki virgül iki beş*) because the grouped reading is ambiguous and therefore not invertible — an unauditable expansion is not a gate.

**Round-trip gate, acoustic half — not implemented, and not faked.** §4.9.6 also asks for synthesise → transcribe with an *independent* ASR → diff. That needs TTS and ASR weights this repository does not carry and cannot obtain offline (HB-I1 disk, HB-I4/HB-I5 GPU), and diffing against the same model that generated the audio tests nothing. It belongs to `make clips VOICE=<id>`, which does not exist yet. Recorded here rather than stubbed.

`DRUG_ORTHOGRAPHY` is **empty**. No committed source in this repository states a Turkish drug-name orthography table and a plausible invented one is HUMAN_BLOCKERS Rule 1's worked failure. The lexicon is wired in and injectable (`expand_tr(..., drugs=...)`, the same shape as `instrument_licence(registry=...)`), and `test_a_drug_name_expands_and_inverts_when_the_lexicon_is_filled` proves the mechanism against a synthetic table — so filling it later is data entry, not a code change.

## The committed openEHR template

`packages/protocols/openehr/previsit_intake.v1.opt`, sha256 `c72247abe50eb675629af368653ee1f174ef4d0efeb0df8726ceba6b8b33dcfa`, pinned in `protocols.bindings.openehr.OPT_SHA256` and asserted by `test_opt_is_pinned` (files/12 §8.1). `load_opt` verifies the digest **before** parsing, so the XML handed to the parser is always the committed artefact.

It is deliberately shallow, and the file says so in its own header. It carries the composition and the archetype **roots** files/03 §7 names — and no `atNNNN` node. Leaf-node binding is archetype-internal content that no committed source in this repository states; inventing an at-code would produce a binding table that resolves against a fabrication, which is the exact failure HUMAN_BLOCKERS Rule 1 exists to prevent. A slot whose leaf path is not authored therefore carries `openehr_deferred_reason`, which the compiler **requires** — files/12 §8 mirrors the same rule as a CHECK constraint so that absence is a recorded decision rather than an oversight. That satisfies ADR-002's "the archetype-path annotation is compiler-enforced from INT-041".

Two things are stated in the file rather than left to inference: `COMPOSITION.intake_previsit` and `EVALUATION.triage_outcome` are LOCAL archetypes (files/03 §7 marks the latter "custom" and names no CKM composition archetype at all), and `CLUSTER.provenance` is **absent** because a CLUSTER is not a CONTENT_ITEM and no committed source states which structure hosts it. CKM reconciliation of the remaining ids, and any resulting `.vN` bump, is INT-032's (P3).

## What was refused rather than invented

- **No at-code / leaf archetype path.** See above.
- **No drug-orthography entries.** Empty lexicon, wired and injectable.
- **No clinical value of any kind** — no threshold, cut-off, age band or dose. Every Turkish string in the fixtures is synthetic and marked as such (files/04 §7).
- **No FHIR extension URL.** `EXT_PROTOCOL_HASH` is consumed from INT-033. The one new canonical is a ValueSet URI in INT-033's own `urn:intake:` namespace, which claims no domain.
- **No guideline id.** The fixtures cite `SYN-GUIDE-A/B` at `example.invalid`.
- **No default voice id.** `--voice` is required; a default would be a value chosen once by an engineer for every future build (files/03 §4.9.1 row 10 keys the clip cache by `sha256(text_tr, voice_id)`).
- **No default RED register or location action.** Both are refusals.
- **No bypass of any kind** around the served/unserved interlock.

## Schema reconciliation (ADR-024)

`files/protocols/base.life_threat.yaml` carried an open item — *"`gate:` vs `when:`, `evidence:` vs `source:` … decide before the compiler is written"*. Decided and recorded in `docs/adr/ADR-024-life-threat-schema-reconciliation.md`: `when` / `source` are canonical everywhere (they are also the names the deny-suffix list and the CI gate `every_red_rule_has_a_source_block` already use); the life-threat document keeps its on-disk spelling and the loader normalises it. Writing both spellings on one rule is a load error.

## Deviations and findings handed on

1. **`packages/protocols/base/life_threat.yaml` does not exist yet** (the allow-list in `scripts/ci/no_placeholders_allow.txt` already anticipates the path). `protocols compile` on the real tree therefore refuses with "life-threat set not readable", which is honest but weak. Authoring that file is INT-043's, under clinician sign-off; the compiler is complete and demonstrated against fixtures.
2. **Loading the blueprint exemplar file needs four INT-040 schema changes**, found by pointing the loader at `files/protocols/base.life_threat.yaml`. Not made here, because they are INT-040 semantics that INT-043 must decide with a clinician in the room:
   - `RedFlagRule.tense_anchor` is `^[a-z][a-z0-9_]*$`, but every exemplar writes a dotted `chest_pain.onset_at`;
   - `RedFlagRule.status` is required, and the two active exemplars omit it;
   - `SourceBlock` has no `note:` field, and exemplar 1 uses one;
   - `LocationAction` has no `secondary:` field, and exemplar 1 uses `NEAREST_ACIL_ADDRESS_AS_TEXT`.
3. **`validator._tr_texts` dereferences `action.unknown` unguarded** (validator.py:351) and raises `AttributeError` on a structurally incomplete RED action. Worked around by ordering (RED-axis integrity is checked before validation) rather than by editing INT-040's validator, which another agent is live in.
4. **Two DSL fields were added**, both blueprint-named and both optional so no existing pack breaks: `Slot.openehr_path` / `Slot.openehr_deferred_reason` (ADR-002 "every protocol slot keeps an openEHR archetype-path annotation … compiler-enforced from INT-041"; files/12 §8) and `ProtocolPack.supersedes` (files/12 §3.4's named escape hatch for an overlay conflict).
5. **`enableWhen` projection is narrow and fails closed.** Supported: `<slot> (==|!=|>|>=|<|<=) <literal>` joined by top-level `&&` / `||`; `skip_if` is the same grammar inverted under De Morgan. `meds.any(class == DMARD)` (the files/03 §6 example) does **not** project and is a build failure. Silently dropping a gate would show a consumer a question the protocol says to hide, so the alternative was worse; if the grammar proves too narrow for INT-043 the fix is to widen it deliberately, with a test.
6. **`check-golden` was not added** to the `make check` fan-out. The Makefile header attributes it to INT-041/INT-059 jointly, and the goldens live in `tests/safety`, which another agent is live in. Only `protocols-compile` was added, minimally.
