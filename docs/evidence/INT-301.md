# INT-301 — Language choice at first run and inside a visit, the switch that does not lose the session, and right-to-left

> **Issue.** `docs/backlog/issues.yaml` INT-301 (P1, `E08-mobile`, `sec_row: mobile`; `depends_on: [INT-296]`).
> Labels `area:mobile`, `area:a11y`, `area:i18n`.

This issue builds the mobile chooser on top of INT-296's session-locale registry (the mechanism that holds exactly `tr`, with UI-completeness and clinical sign-off as two separate fields and a resolver with no fallback) and INT-300's per-locale, fail-closed registries. It adds **no locale**: with only `tr` registered every chooser is ABSENT, which is the honest state until HB-O5 names a second language and HB-C19 signs its clinical text.

## Acceptance criteria (verbatim) × artefact

1. *"the chooser lists only locales the registry reports complete AND signed for the pack in play, shows each language in its own name and script, and is reachable both at first run and from the Me screen without ending a visit in progress"*
   - `apps/mobile/src/lib/i18n/chooser.ts` — `appLocaleChooser` (complete UI catalogue) and `intakeLocaleChooser({ packSignedLocales })` (complete AND signed, narrowed to the pack in play); `toChoices` carries each language's **endonym** (its own name/script, from the registry) plus its writing direction.
   - `apps/mobile/src/app/(tabs)/me/index.tsx` — the Me-screen language row, reachable during a visit (a tab), derives from `offerableAppLocales()` (INT-296) mapped through `present(toChoices(…))` and labels each pill with `choice.endonym`.
   - `apps/mobile/src/app/(auth)/welcome.tsx` — `FirstRunLanguage` reaches the same chooser at first run.
   - Tests: `chooser.test.ts` ("shows a language in its own endonym", "narrows to the pack in play"), `e2e/locale.spec.ts` ("the chooser is reachable, and reads the registry").

2. *"switching mid-visit re-renders the surface and does NOT re-ask what has been answered: answers are values, not strings … and a switch while a red-flag script is in flight is refused with the same explicit refusal barge-in uses"*
   - Answers are already **values**: `apps/mobile/src/lib/intake/note.ts` `Answer.values: string[]` (coded), rendered to text through `t()` keyed by locale — so a switch changes only presentation. `apps/mobile/src/lib/session.tsx` `switchLocale` changes the language and **nothing else** (it never calls `setNotes`/`updateNote`), so the session is kept.
   - The RED refusal: `chooser.ts` `chooseFromChooser(target, { redScriptInFlight })` throws the same `RedScriptInFlight` that INT-296's `offerLocaleSwitch` throws and that barge-in's refusal uses (invariant 21). The chooser's switch path (`me/index.tsx` `pickLanguage`, `welcome.tsx` `pick`) goes through it.
   - Tests: `chooser.test.ts` ("refuses during a red-flag script with the same refusal barge-in uses", "records a clear choice as a patient act …"), `locale.spec.ts` ("switching keeps the session").

3. *"right-to-left is a layout property rather than a per-screen fix: the shared anatomy from the five design passes is direction-aware, and the enlarged text steps hold in both directions - the defect INT-295 found at the DEFAULT text size is the reason this is asserted rather than assumed"*
   - `apps/mobile/src/lib/i18n/direction.ts` — `localeDirection(code)` derives direction from the locale's **script** (an explicit `-Arab`/`-Latn` subtag wins; `ku` = Kurmanji is Latin/LTR by design). `tr` is `ltr`.
   - `apps/mobile/src/components/Themed.tsx` — the shared anatomy is direction-aware in ONE place: `Screen` sets the container `direction` (Yoga flips every `flexDirection: "row"` beneath it) and `AppText` sets `writingDirection`. No other screen or component sets a layout direction.
   - Enlarged steps hold in both directions: the type scale (`scaledSize`, `theme.ts`) takes no direction argument, and the chooser rows `flexWrap: "wrap"` (they reflow rather than pin an edge), so they hold once the row flips — the INT-295 class of defect.
   - Tests: `locale.spec.ts` ("right-to-left is a layout property, not a per-screen fix": direction in the shared anatomy only, no `textAlign: left|right` / `row-reverse` leak, direction-agnostic type steps).

4. *"no locale is added to the chooser by this issue: with only `tr` registered the chooser is absent rather than a one-item list, because a chooser with one choice teaches a patient the feature does not work"*
   - `chooser.ts` `present()` drops a would-be one-item chooser to `[]`; the Me row renders only when `languageChoices.length > 0` and `FirstRunLanguage` returns `null` when empty.
   - `chooser.ts` adds no locale literal (asserted on the module's own source).
   - Tests: `chooser.test.ts` ("the real build" — `appLocaleChooser()`/`intakeLocaleChooser()` are `[]`; "adds no second locale of its own"; "present — the absent-when-one rule").

- **5** — `tr` remains the source of truth and the default; the chooser is additive and fails closed. No `t(key, "tr")` literal added (INT-296's per-string-locale scan stays green); no catalogue key added, so `en`↔`tr` parity is untouched.
- **6** — no PHI/PII in logs: `chooseFromChooser` / `toChoices` refuse an unknown code through INT-296's `registration()` refusal, which echoes nothing a caller supplied (test: "does not echo patient input in the red-script refusal").
- **17** — zero fabricated locale: the registry still holds exactly `tr`, every chooser renders empty, and `chooser.ts` contains no second-language literal (asserted). No numbered artefact (ADR/HB/alembic) minted.
- **21** — a language switch is unreachable while a red-flag script is in flight; the refusal reuses `RedScriptInFlight`, and the RED path is untouched.
- **2** — patient copy: no new patient-facing string; the chooser shows registry endonyms (`Türkçe`), which are language names, not prose.

## Security & monitoring posture (`sec_row: mobile`)

Mirrors INT-295 (the sibling `sec_row: mobile` design/a11y issue): no new §9 row is added, because INT-301 introduces no new threat surface. The chooser is **client-only presentation** — no network call, no telemetry, no new metric (`observability/metrics_catalog.yaml` untouched), and **no new persisted data**. The session locale as a KVKK category is INT-296's field and is tracked as **HB-L25**, which blocks *enabling a second locale*, not this mechanism. No new PHI egress path: the change adds no outbound call of any kind.

## Coverage

New pure module `chooser.ts` and `direction.ts` are exercised by 19 unit tests (every branch: endonym mapping, the <2 gate, app vs intake, pack-in-play narrowing, the RED guard, unknown-code refusal); the wiring is pinned by 11 source-slice tests. Mobile is a vitest package (no numeric coverage threshold in the constitution's list, which governs api/protocols/triage/schemas/voice-runtime); no threshold is lowered.

## Blockers

None blocks the acceptance. Making the chooser non-empty (a real second language) is the pre-existing chain, none minted here: HB-O5 (which languages, in what order) → HB-C19 (a signing clinician who reads it) → HB-L23 / HB-L24 / HB-L25 (legal text, instrument licence, KVKK category) → INT-300's licence work for that language's speech models. The mechanism ships, the gate is wired, it fails closed, the content is left empty.
