## What was built, and why it is a projection and not a second copy

`apps/admin-web/src/experience/module.ts` turns the `GET /admin/experience`
composite into exactly what the page paints and decides nothing the server did
not already decide — the same discipline as the models (INT-183), compliance
(INT-189), protocols (INT-184) and safety (INT-185) modules. It performs no
mutation and opens no socket: survey cadence (INT-242) and the aggregate reads
flow through the INT-180 admin shell's audited, RBAC/ABAC, four-eyes routes,
which this file never re-implements (invariant 4).

`apps/admin-web/e2e/fixtures/experience.payload.json` is recorded from the real
sources by `scripts/dev/record_experience_fixture.py` (added to
`make admin-fixtures`), never hand-mocked — a hand-written mock is a second,
hand-kept copy of the rollups, the reason enum, the k floor and the SDS-01
columns that keeps passing on the day any of them changes and the console stops
matching them (invariant 17). Every field is read from a real source at record
time:

| surface | real source |
|---|---|
| CSAT (score dist + reason counts) | `intake_metrics.rollups.roll_up_csat`, metric ids `csat.score`/`csat.reason` resolved in `observability/metrics_catalog.yaml` (invariant 15), reason enum `clinical_schemas.events.CsatReason` |
| NPS (promoter/passive/detractor split) | `intake_metrics.rollups.roll_up_nps`, metric `nps.monthly` |
| clinician pulse | `intake_metrics.rollups.roll_up_pulse`, metric `clinician.pulse` |
| k-anonymity floor | `intake_metrics.rollups.MIN_COHORT` (= `intake_platform.analytics.K_ANONYMITY_FLOOR` = 10) |
| SDS-01 export | `intake_metrics.sds01.sds01_table` over the real `intake_platform.wait_times.WAIT_SOURCES`; column set `intake_metrics.sds01.SDS01_COLUMNS`, pinned in the recorder |

Each satisfaction surface is produced by calling the **real** rollup over an
empty response set, so its empty state — `n = 0`, `suppressed = True`, every
figure `None` — is the platform's own, not a shape guessed here. The SDS-01
rows come from the real serialiser for one stated example window, so every
`status` (`no_observations` for the one observable interval,
`source_unavailable` for the four whose instants this repo does not yet record)
is one the serialiser produced.

### The refusals (the near-miss negative controls)

The module is a projection, but a stale tab, a cached response or a tampered
body must not buy the page a property the server would never have served. Each
refusal is paired in the spec with a near-miss — the case one clause away from
firing:

| refusal | invariant / finding | near-miss control |
|---|---|---|
| `SuppressedCohortLeaked` | files/06 §8; files/08 §0c F9 | a mean / NPS / distribution shown for a cohort below the k=10 floor |
| `SatisfactionFigureLeaked` | invariant 6 | a distribution key that is not id-shaped (the transcript reappearing) |
| `UnknownCsatReason` | sealed `CsatReason` | a reason outside the enum |
| `SatisfactionTargetRendered` | invariant 20 | `csat.score`'s catalogue target (>= 4.3) rendered beside the figure as a verdict |
| `ExperienceFilterEnabled` | files/08 §0c F9; invariant 18 | a branch/profile/clinic dimension asserted `available: true` |
| `TenantFromQuery` | files/08 §8 rule (a), the F9 IDOR | tenant scope taken from a query param, or a tenant filter dimension |
| `SdsColumnForbidden` | files/08 §0c F9 | a `clinic`/`branch` column added to the export |
| `SdsRowArityMismatch` | invariant 17 | a row whose width ≠ the column count |
| `UnsafeExportCell` | invariant 47; files/08 §0c F13 | a cell leading with `=HYPERLINK(...)` |

### Invariants touched, named individually

- **4 (audit + authz reused):** no route added; the module reuses the INT-180
  shell's audited RBAC/ABAC/four-eyes routes and re-implements none of them.
- **6 (no PHI; aggregates/ids):** the rollups carry counts and scores only;
  `csat.v1`'s optional free text is dropped at the rollup boundary
  (`CsatPoint` has no text member), a non-id-shaped distribution key is refused,
  and a `clinician_ref` never reaches an aggregate.
- **15 (metrics catalogued):** the recorder resolves every metric id in
  `metrics_catalog.yaml` and raises on a miss.
- **17 (recorded fixtures + genuine empty states, no fabricated data):** the
  fixture is recorded from real sources; every satisfaction figure is a genuine
  empty state; the SDS-01 rows are the serialiser's real output.
- **18 (data-inventory decision):** the branch/profile/clinic filter is not
  invented — adding the dimension is a stop-and-ask, failed closed.
- **20 (no accuracy/performance claim):** a figure names its cohort and window;
  a target beside it is refused. No sensitivity/accuracy figure appears.
- **22 (numbers cross a boundary guarded):** counts render with
  `useGrouping:false` as one atom.
- **47 (export injection guard):** an SDS-01 cell that would evaluate in a
  spreadsheet is refused.

## Values refused, with the ask

Rule 1 of `files/HUMAN_BLOCKERS.md` — never invent a value to unblock yourself.

**A branch/profile/clinic dimension on the experience aggregate.** SDS-01's own
analysis is branch-level (files/01 §4, files/03 §19), and the console spec asks
to filter by branch/profile/clinic (files/08 §151). The aggregates carry none of
these dimensions, and lifting one in is (a) exactly files/08 §0c F9's
re-identification shape — branch × narrow window × small clinic identifies
individuals — and (b) a new personal-data field decision under invariant 18. Not
added; the filter mechanism ships and fails closed instead.

This is the **same ask already recorded** as the third refused value in
`docs/evidence/INT-241.md`:

> **Ask — Owner + compliance_officer:** *"May wait-time observations carry the
> visit's branch id so the SDS-01 export can be branch-level, given branch ×
> narrow window × small clinic is F9's re-identification case?"*

extended by INT-186 to the satisfaction rollups and to the `profile` dimension.
`docs/backlog/blockers.md` carries it under INT-186. **No new HUMAN_BLOCKERS.md
row and no ADR id was minted** — INT-241's evidence states one does not exist,
and minting one is exactly the numbered-artefact collision the loop forbids.
