# INT-500 — lockfile advisories since 4 Oct, upgraded rather than ignored

GitHub #851 · Sec-Row `cicd` · phase P0 · 16 Oct 2026

The required `vulnerabilities` job (security.yml: trivy fs, then
osv-scanner) went red on main 3afc5a29. Every PR's run of that job failed, so
the merge queue stopped. The tree had not changed. Trivy's database had gained
four advisories published since 4 Oct 2026, and each one has a fixed release.
This PR upgrades all four, plus the one extra package osv-scanner reported. It
adds no trivy or osv exception.

The issue body names the row `supply-chain`, but docs/security/threat-model.md
has no `## \`supply-chain\`` heading, so the sec_row linkage gate would refuse
it. The row is `cicd` ("pipeline, artefacts and gate integrity"), as it was
for INT-429, the previous vulnerabilities-gate unblock.

## How the scanners were run

These are the job's own versions and invocations, run from the worktree root
with no `node_modules` and no `.venv`. That matches the job's checkout, which
installs nothing.

- **trivy 0.70.0.** trivy-action v0.36.0 installs this version. The binary is
  `trivy_0.70.0_macOS-ARM64.tar.gz` from the GitHub release. Its sha256 is
  `68e543c51dcc96e1c344053a4fde9660cf602c25565d9f09dc17dd41e13b838a`, which
  matches the release's `trivy_0.70.0_checksums.txt`. The Homebrew trivy
  (0.74.0) was not used.
  Command: `trivy fs . --severity CRITICAL,HIGH --exit-code 1 --ignorefile .trivyignore.yaml`.
  It ran with an empty `DOCKER_CONFIG`, so the DB pull does not stall on the
  dead Docker Desktop credential helper. DB: version 2, UpdatedAt
  2026-10-15 19:09:25 UTC.
- **osv-scanner 2.5.1.** osv-scanner-action v2.5.1 uses this version, and the
  local binary reports `osv-scanner version: 2.5.1`.
  Command: `osv-scanner -r ./`.

## What changed

1. **Three `pnpm.overrides` floors**, shaped like the existing
   vite/uuid/brace-expansion/fast-uri floors:
   `shell-quote@<1.11.0 → ^1.11.0`, `compression@<1.8.2 → ^1.8.2`,
   `source-map-js@<1.2.2 → ^1.2.2`. All three are transitive:
   - shell-quote: react-native 0.86.3 → react-devtools-core 6.1.5
     (apps/mobile). It resolves to **1.12.0**, the newest 1.x.
   - compression: @expo/cli 57.0.19's dev server (apps/mobile). It resolves
     to **1.8.2**. Its new release adds `destroy` 1.2.0, which was already in
     the tree.
   - source-map-js: postcss 8.5.23 and 8.5.26 (next's CSS pipeline and the
     mobile toolchain), and magicast 0.5.5 under @vitest/coverage-v8. It
     resolves to **1.2.2**.
2. **next 16.3.6 → 16.3.8**, admin-web's exact direct pin. `@next/env` and the
   eight `@next/swc-*` platform packages move with it. admin-web sets
   `images: { unoptimized: true }` (apps/admin-web/next.config.ts), so the
   Image Optimization endpoint named in CVE-2026-94483 is not in use. It is
   upgraded anyway: a fix exists, and the gate counts versions.
3. **mako 1.4.1 → 1.4.3** via `uv lock --upgrade-package mako`. uv picked the
   newest release. Only that package moved (3 lines). The wheel's sha256
   (`723296007c870bfd…`) matches uv.lock.
4. **The lockfile.** `pnpm install --lockfile-only` (pnpm 9.15.9, the
   `packageManager` pin) wrote it: 59 insertions, 57 deletions. Every changed
   integrity string matches `npm view <pkg>@<ver> dist.integrity`. The one
   unrelated hunk drops `bufferutil` and `utf-8-validate` from
   `@react-native/metro-config`'s transitivePeerDependencies. That is pnpm's
   own normalisation from the same resolve, as INT-429 saw.
5. **No suppression.** `.trivyignore.yaml` and `osv-scanner.toml` are
   untouched. The INT-310 sweep `test_no_suppression_file_names_any_of_the_eight_advisories`
   now also checks all fifteen INT-500 ids, and the suppression count pins
   are unchanged (trivy 3, osv 4).
