## What this issue is

It is the issue that checks what the other five claimed. INT-081 built the FSM, INT-092 the
Work queue, INT-093 the RED path, INT-110 the lane framework, INT-083 the extraction Work —
each proved against its own ports, and each proof is good. **None of them ran the pieces
together.** So this suite is written against a composed `Stack`: one real `IntakeEngine`, one
real `BackendAgent`, one real `TalkerSession` and one real `RedPreemption`, on one virtual
clock. Everything that could already be proved inside a unit is left where it is; what is
added is the composition, and the list of things the composition cannot hold.

Three deliverables:

1. `tests/voice/test_invariants.py` — files/03 §4.6 invariants 1-11 against the composed
   stack, RT-01…RT-08, and an **honesty ledger** that classifies every invariant as
   end-to-end or unit-only and may only shrink.
2. `intake_voice_runtime.simulator` + `make runtime-sim SCENARIO=<id> PROFILE=<p>` — the
   fake-clock latency harness, reporting per-turn budgets per profile.
3. The findings below, which are the most valuable output and are written as **assertions**
   rather than prose wherever a mechanical form exists.

### Which "1-11"

"Runtime invariants 1-11" is **files/03 §4.6**, whose section is titled exactly that and
whose eleven rows are: non-blocking · fixed tool surface · single preemption · RED latency ·
FIFO+single-in-flight+serialised · idempotent delivery · verbatim scripted · profile parity ·
no raw audio · observability-not-control · lanes off the critical path. CLAUDE.md numbers a
different 1-22 and the two collide on every index — CLAUDE.md 1 is triage provenance where
files/03 §4.6 1 is non-blocking, and so on. The suite names both for every class. This
ambiguity is a documentation defect worth fixing in files/11's issue title.

## (a) Which invariants are held end-to-end, and which only in their own unit

The ledger is executable — `UNIT_ONLY` and `END_TO_END` in the test module, asserted to
partition 1-11 exactly, with `UNIT_ONLY` documented as may-only-shrink.

| files/03 §4.6 | CLAUDE.md | status | how, and what the composed form adds |
|---|---|---|---|
| **1** non-blocking | 9 | **end-to-end** | Ten seconds and one **hour** of Backend stall produce the same composed turn latency (32.0 ms). INT-092 proved it at the queue; the composed form is what would catch a queue that took the engine lock in `submit` and stalled the *Talker* rather than itself. A permanent positive control moves the same interval onto the turn's own path and shows the full 32 000 ms, so the assertion cannot pass against a clock that never moves. |
| **2** fixed tool surface | 9 | **end-to-end** | A whole turn against a **watched** engine touches `snapshot` and nothing else — INT-091's registry test proves the six names exist, this proves a live turn calls nothing beyond them. |
| **3** single preemption | 1, 9 | **end-to-end** | A rules RED returned by a handler travels the real queue, is derived (never requested) into `priority: preempt`, and arrives at the real Talker. An LLM candidate on the same handler does not, and `LlmCandidateTriage` cannot spell the level. |
| **4** RED latency | 21 | **unit-only** | INT-093 measured stop 40 ms / e2e 90 ms and proved three ways that the path touches no media transport. Re-measuring here would prove nothing; the composed additions are that a RED which *travelled the queue* stops the intake, and that the composed session's synthesizer, clip store and media plane stay untouched. The **budget** stays INT-093's. |
| **5** FIFO + single in flight + serialised | 9 | **end-to-end** | RT-05 through `TalkerSession.submit_utterance` rather than through the queue's own API: submission order preserved, exactly one state Work in flight at every handler entry, and the final slot **and** answer-state vectors identical to a sequential run. |
| **6** idempotent delivery | 9 | **end-to-end** | The same transcript twice yields one Work (content-addressed `work_id`); a delivered result is spoken once across three further drains, counted at the **sink** rather than in the scheduler's own bookkeeping. |
| **7** verbatim scripted | 10 | **end-to-end** | The engine's `text_tr` reaches the synthesizer byte-identical, through the real router and the real PolicyGuard, and a scripted step is never offered with paraphrase permission. |
| **8** profile parity | 19 | **unit-only, and currently vacuous — see finding 4** | Two of the three profiles §4.6 names were deleted. Parity over the two that exist passes, and it passes *because `typed` has no code path of its own*: `VoiceProfile` reaches exactly one place in the runtime, a PolicyGuard metric label. The harness asserts the two runs are identical, which is the test that will fail on the day INT-096 gives `typed` a path — that is the point of writing it now. |
| **9** no raw audio | 3 | **end-to-end** | A composed session that has taken a turn with a transcript retains zero bytes-like attributes, and the queue record holds the hash and not the text. The crash/swap/core half is INT-090's `audio_retention_guard` and stays there. |
| **10** observability, not control | 6 | **end-to-end — after building the table it names** | See finding 3: the fixed tr/en table did not exist, so this invariant had a free string on both sides of it and was untestable. It is now a closed `ActivityLabel` enum total over `WorkType`, and `BackendAgent.activity` derives the rail's chip from Work types rather than from handlers. |
| **11** lanes off the critical path | 11 | **end-to-end** | The acceptance's own figure — lanes stalled **30 s** — against the composed stack, with the engine and queue live underneath and a permanent positive control showing the same 30 s on the turn's own path. INT-110's hour-long version stays where it is. |

**Two are unit-only and both for good reasons**: 4 because re-measuring INT-093 would be
duplication, 8 because there is nothing yet to have parity *between*.

## (b) RT-0x that cannot be expressed against the shipped code

### RT-06 — cannot be expressed at all, and the backlog already agrees

files/04 §6: *"RT-06 `s2s_cloud` model attempts a diagnostic sentence — output-transcript
monitor catches it, retraction turn is spoken, incident logged; scenario must also pass in
`cascade_fast` where PolicyGuard blocks before TTS."*

Both profiles were deleted by the all-self-hosted constraint (CLAUDE.md invariant 19;
files/00 §0b; files/02 §8.1's profile-stack correction), and
`tests/voice/test_voice_runtime_service.py` already fails the build on either name appearing
in runtime **code** — which it did, when the first draft of `simulator/scenarios.py` carried
them as string literals. The record may name them; the runtime may not.

The scenario is **about** a profile with no text before audio: an output-transcript monitor
exists because there is no text to guard *before* the audio. `residency_tr` has text before
audio and PolicyGuard runs on it, so substituting `residency_tr` would not be a weaker RT-06,
it would be a different test wearing its name. The backlog reached the same conclusion from
the other side — **INT-098 is `withdrawn`: "Replaced by a test that proves no S2S/cloud
profile can be constructed."**

So RT-06 keeps its row, carries `withdrawn=<reason>` instead of a profile list, and
`require_runnable()` raises. `make runtime-sim SCENARIO=RT-06 PROFILE=residency_tr` exits 2
with the reason. A model validator makes "runnable **or** withdrawn" total: a scenario cannot
be both (which would let a withdrawn one quietly run on a substitute) and cannot be neither
(which would let it vanish).

### RT-01 — half expressible, and the other half fails closed on purpose

*"…speak the document result only at a pause."* A document result is `DeliveryClass.CLINICAL_INFO`,
and files/12 §6 states a deadline ladder for **`triage_yellow` only**. `DeliveryDeadlines`
leaves `clinical_info` and `routine` unset, so the shipped default raises
`DeadlinesNotConfiguredError` at enqueue rather than guessing how long a document result may
wait before it interrupts a patient. That is asserted as its own test
(`test_the_shipped_default_refuses_a_document_result_rather_than_guessing`), and the ladder
is then proved to work against a table the **test** supplies, clearly labelled as such. The
ask is INT-091's, not re-raised here.

Everything else in RT-01 is expressible and passes: two documents parse concurrently without
head-of-line blocking the state lane, forty seconds of patient speech never stalls the turn,
and the result lands at the pause and not before.

### RT-03 — the chip needed a table built before it could be asserted

*"rail shows 'güncelleniyor' chip"*. See finding 3. Before this issue there was no fixed
table, so any assertion about the chip would have been an assertion about a free string.

### RT-08 — expressible; one clause is true by absence and stays that way

*"backchannel suppressed, turn detector holds, no question asked until they return."* The
hold is built (finding 2). The suppression clause is asserted structurally rather than
behaviourally: the Talker's speech surface is closed — the clip cache and the synthesizer —
and a held turn reaches neither, so there is no agent backchannel to suppress. **Agent
backchannels and ack styles are INT-099's acceptance**, and building them here would be two
issues in one PR.

### RT-02, RT-04, RT-05, RT-07 — expressible, and RT-07 gains its missing half

RT-07 as written in files/04 §6 has a hole files/12 §6 names outright: it *"only ever
asserted that YELLOW does **not** preempt, never that it is **ever** spoken"*. Both halves are
asserted, plus the case files/12 §6 was written for — a YELLOW the patient never yields to
expires past the 90 s terminal **with its note flag written**, and the turn hold does not
become a new way to lose one (`test_a_held_turn_still_walks_the_ladder_rather_than_swallowing_it`).

## Findings — recorded rather than worked around

### 1. The Layer A ↔ Layer B loop does not close on this tree, at three joints

This is the headline. Each joint is asserted so that wiring one makes the test fail and the
finding is struck rather than quietly becoming false (`TestTheLoopThatDoesNotClose`).

**(i) No module under `services/` registers an `extract_slots` state handler.** INT-092
recorded that the production handler was INT-083's; INT-083 built `run_extraction` and
`ExtractionResult.as_engine_call()` and registered nothing. Consequence, reproduced against a
bare `BackendAgent`:

```
$ uv run python - <<'PY'   # abridged; the assertion form is in the suite
...
frontier: ['oyku.birinci']
protocol_next: step_id='oyku.birinci' kind=scripted text_tr='Sentetik belirtiniz var mi?' …
TURN RAISED: UnregisteredWorkType no handler registered for 'extract_slots'; refusing to
             queue Work that could never run (fail closed)
```

**A composed session cannot take one turn carrying a transcript.** The behaviour is correct —
refusing beats silently dropping clinical Work — but the loop is open.

**(ii) `IntakeEngine.mark_asked` has no caller outside tests.** And `apply_extraction`
ignores an update for a step that is not `ASKED_PENDING`, so with no caller every answer would
be dropped. There is also a semantic split worth settling before someone wires it: files/03
§4.5 says *"the engine marks n as `answered_pending`"* **when the answer arrives**; INT-081's
`mark_asked` marks a step `ASKED_PENDING` **when it is spoken**. Both are defensible, they are
different events, and the Talker holds a read-only `EngineSnapshotSource` — so the natural
caller is the state handler, inside the engine lock, from `WorkRequest.step_id`. The suite's
`Stack` does exactly that and says so.

**(iii) `WorkRequest` has no transcript channel.** INT-092 finding 3, still open. The queue's
PHI-free-by-construction property depends on it, so the route is a **data-boundary** decision
(invariant 14), not a field.

**Nothing here is fixed in this issue** — a transcript route and a production handler are
INT-083's acceptance, and CLAUDE.md is explicit that scope is what the acceptance says. But
**INT-095 (`Profile residency_tr with real self-hosted adapters + on-hardware smoke`) cannot
ship without all three**, because there is no turn to smoke-test.

### 2. The Talker asked its next question over an open patient turn

There was no turn-hold anywhere. `take_turn` read `self.duplex` for the insertion scheduler
and then spoke the next step unconditionally, so RT-08 had nothing to assert against. That is
the mirror of the defect files/03 §4.4b names — *"a handover gap must be treated as a turn
boundary, never as silence and never as an answer — this is the failure mode that silently
corrupts data rather than visibly breaking"* — because asking over a patient who is mid-aside
binds their next words to a question they did not hear.

Built: `DuplexState.patient_holds_floor(policy)` and `TurnHold`. Two details are load-bearing.

- **The floor is the adaptive pair, not a constant.** files/03 §4.2/§4.5b: *"150 ms when
  measured uplink jitter p95 < 30 ms, and 250 ms otherwise"* — §4.5.2 keeps the drop
  conditional precisely so as not to *"cut patients off in the waiting room"*. So
  `TurnYieldPolicy` carries the measured figure and derives the floor; a session nothing has
  measured sits **on** the threshold and takes the 250 ms branch, because §4.2's condition is
  *measured*, and unmeasured is the *otherwise*.
- **`DuplexState` needed `patient_speaking`.** Without it, "zero milliseconds of silence"
  at session start — nobody has spoken at all — is indistinguishable from a patient
  mid-sentence, and the Talker would never ask its first question. Mutation A plants exactly
  that and seven tests catch it.

A held turn is **not** a skipped turn: results are still drained, the insertion scheduler
still ticks, and a protected item past its terminal still writes its note flag. Mutation J
plants the opposite and two tests catch it.

### 3. Invariant 10 named a fixed tr/en table that did not exist

files/03 §4.6 invariant 10: *"Work activity labels are from a **fixed tr/en table**; no
session ids, prompts, or reasoning reach the client."* `InlinePayload.activity_label_tr` was a
free-text field with no table, no producer, and no consumer — an invariant with a free string
on both sides of it, which cannot be tested at all. A grep of the whole tree for an
activity-label table returns nothing.

Now: `ActivityLabel`, a closed enumeration of label **ids** total over `WorkType`, and
`BackendAgent.activity` deriving the rail's chip from the Work types that are queued or
running rather than from a handler. Two consequences the tests pin:

- an id cannot carry a session id, a prompt or a chain of reasoning — the invariant is held
  by the type rather than by review;
- **one label per type, not one per Work.** A count would publish queue depth to the patient.
  Mutation F planted the count and initially survived; two tests were added and it now fails.

The tr/en rendering stays in `apps/mobile/src/lib/i18n`, where every other user-visible string
lives and where the i18n completeness gate can see it. **No Turkish copy is authored here.**

### 4. Profile parity is currently vacuous, and the harness says so

`VoiceProfile` reaches exactly **one** place in the runtime — a PolicyGuard metric label.
`typed` has no code path. So files/03 §4.6 invariant 8 passes today because there is nothing
to differ. The harness asserts the two profile runs are byte-identical
(`test_a_scenario_run_is_identical_under_both_profiles`) with a comment naming INT-096 as the
issue that will make it fail. Recorded rather than claimed as coverage.

### 5. The blueprint publishes two different p95s for `residency_tr`, and the app shipped one

- files/02 §8.1: *"`residency_tr` … p95 **OPEN — to be measured**. Deliberately unset … We
  will publish a p95 when we have measured one."*
- files/03 §4.4: *"p95 ≈ **1684–2364 ms**; may BEAT the displaced cloud stack."*
- `apps/mobile/src/lib/dialogue/tts.ts` committed `TURN_ROUND_TRIP_BUDGET_MS = 1684` — the
  low end of the §4.4 band — as its per-turn ceiling (INT-249).

`published_budget()` returns the §8.1 answer (OPEN, with the sentence that says why),
because §8.1 is the product-NFR section and the one a tender would quote.
`RESIDENCY_TR_P95_BAND_MS` records the §4.4 band so the disagreement is visible, and a test
pins the app constant to the band's low end so the three cannot drift apart silently.
**Not resolved here**: which figure is the NFR is a product decision.

### 6. files/03 §4.5's only per-leg budget table belongs to a deleted profile

The section is headed *"Latency budgets (p50, `cascade_fast`)"*. files/02 §8.1 says the cloud
tables are *"kept only for the arithmetic they contain, relabelled — not as live profiles"*,
so the harness exposes that arithmetic as `displaced_baseline_dynamic(network)`, named for
what it is, and **never** as a budget for a profile we run. Mutation G makes
`published_budget` fall back to it and two tests fail.

The harness deliberately does **not** re-derive §4.5's p50 leg sum: the section states its own
totals are inconsistent (*"its own floor makes the budget impossible"*), and inventing a
reconciliation would be publishing arithmetic nobody wrote. What it does check is the
blueprint's own worked lever: 2055 ms itemised mid-LTE p95, minus the 141 ms vendor hop,
equals 1914 ms — files/02 §8.1's *"under 2000 without touching a single model"*.

### 7. `typed` has no published per-turn budget, and the harness refuses rather than reusing one

files/02 §8.1 publishes no latency NFR for `typed`. Reusing `residency_tr`'s would invent an
NFR for a modality whose whole point is that it does not stream. `published_budget` raises
`BudgetNotPublished` with that sentence and the report prints it. Mutation H makes `typed`
inherit and two tests fail. Two further refusals are in the same shape: hospital guest wifi
(*"publish no NFR — force cellular"*, an instruction rather than a gap) and a scripted row
with no named network profile (*"a latency NFR without a measurement point and a named
network profile is unfalsifiable"*).
