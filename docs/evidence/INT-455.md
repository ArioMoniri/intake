# Evidence: INT-455 · `expand_tr` refuses a numeral with an apostrophe suffix

**Epic:** E03-protocols · **Phase:** P1 · **Sec-Row:** clinical-content · **GitHub:** #778 ·
**Depends on:** INT-041, INT-314 · **Found by:** INT-432 decision CD-24, finding G1

## Problem

`files/protocols/base.life_threat.yaml`, rule `rf.chest_pain_cardiac_features`: the REMOTE
`action_tr` is `Hemen **112**'yi arayın.` `protocols.compile.tr_orthography.expand_tr` raised
`TrExpansionError` on the token `**112**'yi`, and on `112'yi` without emphasis. A numeral
followed by an apostrophe suffix matched none of the expander's numeric shapes. `112 Acil Çağrı
Merkezi'ni` and `112 ambulansıyla` were never affected, because there the numeral is its own
token.

Invariant 22 makes the compiler the only place a numeral can become words. So the clip emitter
turned the refusal into `TR_EXPANSION_FAILED`, and **the most time-critical RED script in the
product had no clip.** INT-314 had already recorded these refusals in its byte-identity
baseline (`docs/evidence/INT-314.md` §6, "three of the 68 expansions are refusals"). It
recorded them as unchanged content, not as a defect, and no issue owned them.

## Decision: fix the expander, not the RED text

`base.life_threat` is a sibling set (invariant 7), and its action text is clinical content.
Rewording it would need the clinical-review path. The defect is in the expander, so the fix
is engineering. **No byte of `base.life_threat.yaml` changes.** The RED register, route,
location, `show_112` and the verbatim obligation (invariant 10) are all untouched. The only
change is that the spoken form now exists:

| rule | field | authored (unchanged) | expanded — before | expanded — after |
|---|---|---|---|---|
| `rf.chest_pain_cardiac_features` (KIRMIZI, ALERT) | REMOTE `action_tr` | `Hemen **112**'yi arayın.` | refused | `Hemen **yüz on ikiyi** arayın.` |
| `rf.chest_pain_no_cardiac_history` (SARI, CALM) | REMOTE `do_nots_tr[0]` | `… beklemeyin — 112'yi arayın.` | refused | `… beklemeyin — yüz on ikiyi arayın.` |
| `rf.paediatric_airway_obstruction` (KIRMIZI, CALM) | REMOTE `action_tr` | `… Hemen **112**'yi arayın.` | refused | `… Hemen **yüz on ikiyi** arayın.` |

## Sources (orthography, not clinical content)

- **TDK Yazım Kılavuzu, Kesme İşareti** — https://tdk.gov.tr/icerik/yazim-kurallari/kesme-isareti/,
  retrieved 2026-10-03. Verbatim: *"Sayılara getirilen ekleri ayırmak için konur: 1985’te,
  8’inci madde, 2’nci kat; 7,65’lik, 9,65’lik, 657’yle vb."* The apostrophe exists only
  because the number is in digits. In words the suffix joins the last word (*yüz on ikiyi*).
  TDK's own examples use U+2019, so both apostrophes are accepted. Four of the examples are
  test vectors. The decimal ones (`7,65’lik`) stay refused (see below).
- **TDK Güncel Türkçe Sözlük**, `https://sozluk.gov.tr/gts?ara=<word>`, retrieved 2026-10-03.
  Each cardinal word in the expander's lexicon was queried for its `taki` field, which records
  the consonant change before a vowel. Results: `dört` → `"dü"`. Empty or null for every other
  word: `sıfır bir iki üç beş altı yedi sekiz dokuz on yirmi otuz kırk elli altmış yetmiş
  seksen doksan yüz bin milyon milyar`. So `dört` is the only cardinal that softens (*dördü,
  dördüncü*), and `üçü` and `kırkı` keep their consonant.
- **TDK Yazım Kılavuzu, Büyük / Küçük Ünlü Uyumu**:
  https://tdk.gov.tr/icerik/yazim-kurallari/buyuk-unlu-uyumu/ and `…/kucuk-unlu-uyumu/`,
  retrieved 2026-10-03.
  - Both pages list `-ken`, `-yor`, `-gil`, `-leyin` and `-mtırak` as suffixes that do not
    follow harmony. None of them is a suffix a numeral takes in a protocol script, so none is
    special-cased (see *Fail-closed edges*).
  - Küçük Ünlü Uyumu, verbatim: *"-ki aitlik eki yalnızca birkaç örnekte küçük ünlü uyumuna
    uyar"*. `-ki` is the one invariant suffix the expander does handle (*kırktaki*,
    *1985'teki*), because it follows a locative on a number.

## Change

- **`tr_orthography.py`.**
  - A token `<digits>['’]<lower-case Turkish letters>` expands as the cardinal with the suffix
    joined to its last word: `_SUFFIXED_RE`, `_inflect`.
  - The suffix is checked against the spoken word, never glued on blind:
    - **vowel harmony** across the whole suffix, two-way `a/e` and four-way `ı/i/u/ü`. The
      first suffix vowel agrees with the word's last vowel, and every later vowel agrees with
      the one before it, so `3'üncu` and `8'incı` are refused. The exception is the invariant
      `-ki`, after which harmony restarts (`40'takiler` → *kırktakiler*). Two vowels in a row
      (`112'yiı`) are refused, and so is a suffix starting with `ğ` (`2'ğe`);
    - **buffer consonants**: after a vowel-final word the suffix may not start with a vowel
      (`112'i`), and after a consonant-final word it may not start with `y n s ş` (`5'yi`);
    - **d/t and c/ç assimilation** after TDK's voiceless set *fıstıkçı şahap*: `5'de` and
      `100'te` are refused;
    - **`dört → dörd-`** before a vowel only (`4'ü` → *dördü*, `4'te` → *dörtte*);
    - **a unit symbol written as a suffix** is refused (`5'min` would be *beşmin*). Suffix
      letters are limited to the Turkish alphabet, so `q`, `w` and `x` are out.

    Any mismatch is a `TrExpansionError`. The message names the token, the word and the rule,
    and never contains patient data, because the input is authored protocol text.
  - Markdown emphasis `*`/`**` is now decoration, like a bracket (`_LEADING`/`_TRAILING`).
    Emphasis closed between the digits and the apostrophe (`**112**'yi`) moves to after the
    suffix (`_split_decoration`). In words the suffix is part of the word, so `**yüz on
    ikiyi**` is correct and `**yüz on iki**yi` would split the word. A token with no digit is
    still appended byte-for-byte, so `**dik`, `rahat**` and every other prose token are
    unchanged. The sweep below and the INT-297 baseline confirm this.
  - The apostrophe of a suffixed numeral folds to U+0027 **inside that token only**.
    `Acil Servis’e` keeps its bytes, which a test asserts.
  - **Round trip.** `_contract_suffixed` splits the last word at the cardinal word or softened
    stem it starts with, and recovers `112'yi`. The split is unique because no cardinal is a
    prefix of another, which a test asserts. It then **re-inflects** the result, so only the
    canonical spelling inverts: a tampered `dördte`, `yüz on ikiyu` or `yüz on üçü` fails the
    gate instead of reading back.
- **`emit_clips.py`.** The red-flag/life-threat walk inside `_sources` was extracted as a
  public `rule_sources(rules, locale)`, with no behaviour change: the 29 emitter and identity
  tests pass unchanged after the extraction. The new headline test can then drive the
  **real**, unsigned life-threat set through the same walk and the same `rows_from` a served
  bundle runs. A second walk written in the test would drift the first time a spoken field
  is added.
- **`tests/fixtures/protocols/int314_tr_content_baseline.json`.** Exactly three `expanded`
  values move from `!tr-expansion-refused: …` to the expansions in the table above. Every
  `authored` value and every other entry is byte-identical. The update was scripted: it
  asserted that the diff against the current tree was exactly those three refusal entries,
  replaced them **in file order, one occurrence at a time**, and asserted that the result
  equals the current tree. A first attempt with a global string replace was caught by that
  assertion. Rules 0 and 2 carry byte-identical refusal messages, so a global replace would
  have written rule 0's expansion into rule 2. The INT-297 baselines (content and served
  bundle) do not move. The bundle tests compile against the synthetic signed life-threat
  fixture, which has no suffixed numeral.

## Fail-closed edges, deliberately left refused

- **A decimal with a suffix** (`2,5'i`, TDK's `7,65’lik`). The expander reads the fraction
  digit by digit (*iki virgül beş*) so that it can be inverted. The author's suffix was chosen
  for whatever reading they had in mind, and that reading may differ: `2,50'si` is *elli-si*
  to the author but *sıfır-sı* to the expander. The token stays refused.
- **A fraction, an upper-case suffix, a bare apostrophe, a suffix with no vowel.** All refused.
- **Suffixes TDK lists as non-harmonising, other than `-ki`** (`-ken`, `-gil`, `-leyin`,
  `-mtırak`, `-yor`). These get no special case. They are accepted only when their fixed vowel
  happens to agree with the word, and then the result is correct Turkish (`5'ken` →
  *beşken*). They are refused when it does not (`6'ken`), and `-yor` is always refused. The
  same applies to `-sız/-siz` after a consonant, which the buffer rule refuses. None of these
  occurs on a numeral in any pack. A refusal is loud at compile time, and the author writes
  the number in words.

    `docs/security/threat-model.md` now names this suite.
