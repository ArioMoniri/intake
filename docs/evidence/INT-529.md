## 6. The mechanism

- `packages/intake_platform/src/intake_platform/legal/synthetic.py`: `DeploymentDataClass`,
  which is ADR-035's `TenantDataClass` read by ADR-035's own `deployment_data_class`
  (`synthetic` for the exact literal only, else `real_phi`), so the hosted lanes and the legal
  texts share one reader; `SyntheticLegalIndex` (refuses any class but synthetic; the index must declare
  `data_class: synthetic`; ids limited to the sixteen; paths from `REQUIRED_DOCUMENTS`; sha256
  and front-matter version bound to the row; the visible marker on the first body line; the
  invariant-20 scan at render; `awaiting_human` rows refuse as missing);
  `SyntheticConsentTextCatalog` (the consent guard's catalog on a synthetic deployment);
  `refuse_legal_paths_for` (the boot pairing rule).
- `consent/texts.py`: `SYNTHETIC_MARKER`, `carries_synthetic_marker` (Turkish case folding),
  `synthetic_marker_is_visible`; the real-tenant `ConsentTextCatalog` refuses any file that
  carries the marker.
- `services/api`: `ApiSettings.deployment_data_class`; `from_env` refuses the synthetic class
  outside an explicit `dev` or `staging` and defaults the legal root to the synthetic tree for
  it; `__post_init__` refuses a real class on the synthetic tree and a synthetic class off it;
  `state.consent_catalog_for` builds the one catalog both the guard and the embed wiring use.
- `infra/staging/Dockerfile.api` bakes `INTAKE_DEPLOYMENT_DATA_CLASS=synthetic` (one line,
  shared with INT-428); `infra/staging/compose.yaml` never sets it (test).
