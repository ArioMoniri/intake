## The design, in the order the decisions matter

### 1. The source registry — three artefacts, one fact

`packages/intake_platform/src/intake_platform/wait_times.py` holds `WAIT_SOURCES`:
one row per files/08 §4 group G interval INT-241 enumerates, each naming its start
instant, its end instant, whether **this repo records both**, which end is missing
when it does not, and the issue that would land it where one claims it.

Three things are then held against that single fact, in both directions:

| artefact | rule | enforced by |
|---|---|---|
| `observability/metrics_catalog.yaml` | `status: live` iff `observable`, `planned` otherwise | `test_catalogue_status_matches_source_availability` |
| `intake_metrics.metrics.WAIT_FAMILIES` | a Prometheus family exists iff `observable` | `test_only_observable_kinds_have_a_family` |
| `record_wait` / `publish_wait` | raise `WaitSourceUnavailableError` for a non-observable kind | `test_recording_an_unobservable_kind_fails_closed`, `test_an_unobservable_kind_cannot_be_published` |

The point of the coupling is the day an instant lands: flipping `observable` to
`True` fails the catalogue test until the row is promoted, and promoting the row
without a family fails `test_live_entries_are_emitted_and_planned_entries_are_not`
(INT-025). Nobody has to remember.

### 2. Why four of five are not emitted

Verified by reading the tree, not assumed:

| id | missing instant | what would land it |
|---|---|---|
| `wait.time_to_first_question_s` | **both.** `sessions.started_at` has no writer outside the test harness (`services/api/src/intake_api/store.py:135` creates sessions at `CREATED`), and the Talker holds the turn in memory and writes no lifecycle row | **no backlog issue claims the intake lifecycle instants** — see the ask below |
| `wait.note_ready_after_wrapup_s` | **the start.** `notes.created_at` exists; nothing anywhere transitions a session to `COMPLETED`, so `sessions.completed_at` is never written | same ask |
| `wait.doctor_link_first_open_h` | **the end.** `shares.created_at` exists; there is no clinician-facing share-redemption route and no share-access row | **INT-150** ("every open audited and visible to patient") |
| `wait.checkin_to_seen_min` | **both.** `packages/connectors/` does not exist | **INT-163** ("Check-in: … + checkin_to_seen metric", P2, depends on INT-160) |

`wait.answer_latency_s` is group G's sixth id. INT-241's acceptance does not name
it and files/08 calls it "context for design", so it is deliberately left out of
the registry and stays `planned` rather than being swept in.

### 3. Small buckets — suppression, and the part usually missed

The floor is **imported**, not redefined: `intake_metrics.wait_rollups.MIN_COHORT
is intake_metrics.rollups.MIN_COHORT` (pinned by test). Two copies of a
k-anonymity floor is one floor that gets lowered by accident.

Four rules, each with a test:

1. **Cohort below the floor → nothing but `n`.** No mean, no breakdown. A
   five-observation mean re-identifies as readily as a five-observation list.
2. **Complementary suppression on the breakdown.** A per-`document_type`
   breakdown publishes only when **every** cell clears the floor. With ten pdf
   observations and three png, the total clears and the pdf cell clears — and
   publishing both hands the reader the png cell by subtraction, so the **whole
   breakdown** is withheld and only the total survives
   (`test_the_breakdown_is_suppressed_whole_when_one_cell_is_below_the_floor`).
   A partly-labelled set is refused for the same reason: its unlabelled remainder
   is itself a derivable cell.
3. **No minimum and no maximum, at any cohort size.** They are not aggregates —
   each is one patient's actual wait wearing a summary's clothes. `WaitRollup`
   has nowhere to put one, pinned by a field-set assertion.
4. **Never observed raw into Prometheus.** A histogram scraped after a single
   observation exposes that patient's exact duration through `_sum` over
   `_count`. So the only path into a wait family is `publish_wait`, which rolls
   up first and returns without publishing unless the floor and the breakdown
   both clear. A suppressed cohort publishes **nothing** — not a zero.

Beyond suppression, the aggregate honours the refusal: `wait_observations`
excludes every patient whose `learning:service_improvement` consent is absent,
withdrawn or stale (files/06 §2 — the de-identified-aggregate purpose, "an opt-out
purpose whose refusal costs no feature"), decided by `is_scope_allowed`, the same
platform evaluator `ensure_consent` wraps.

### 4. What the export does and does not have

`GET /v1/admin/experience/wait-times.csv`, columns pinned by test:
`metric_id, unit, window_start, window_end, measured_at, n, mean, status, note`.

- **Every row is a measurement of a named cohort over a stated window
  (invariant 20).** The window bounds and the measurement instant are columns,
  not a caption — a caption is what gets dropped when two rows are pasted into a
  slide. No `target` column, and `test_the_export_states_no_target_beside_a_figure`
  asserts the body carries no "target", "SLA", "within", "breach", "good" or
  "bad": files/08 §4 G states a target for two group G ids, and rendering one
  beside a measurement is how a measurement becomes a claim.
- **No clinic, branch, clinician or patient column.** files/08 §0c F9 names
  branch-level slicing of an operational aggregate, filtered to one small clinic
  on one day, as the thing that identifies individuals. SDS-01's own analysis
  *is* branch-level, so this is a stated gap rather than an oversight — see the
  ask below.
- **A suppressed row is marked, never omitted.** A missing row reads as "no
  wait"; the truth is "no measurement". `status` separates `published`,
  `suppressed_below_k`, `no_observations` and `source_unavailable`, and the
  `note` column carries the missing instant for the last of these.
- **Invariant 47.** Every cell runs through
  `intake_platform.export_safety.sanitise_cell`. That function moved out of
  `intake_api.dsar.export` to the platform in this branch: a second export needing
  the same guard must not get a second copy of it. `intake_api.dsar.export`
  re-exports the name it always exported, behaviour unchanged, and
  `test_the_export_uses_the_one_committed_injection_guard` asserts identity
  between the two call sites. Near-miss negative control:
  `test_the_export_neutralises_a_formula_lead_in_a_registry_note` feeds a hostile
  `=HYPERLINK(...)` through the real table builder and asserts the cell comes out
  apostrophe-prefixed.

### 5. The admin surface

`GET /v1/admin/experience/wait-times` (JSON) and `…/wait-times.csv`.

- **Tenant scope from the principal, never the query string** (files/08 §8 rule
  (a), the F9 IDOR). There is no `tenant` parameter to pass, asserted against the
  emitted OpenAPI.
- **Consent declared through the one path.** Both routes carry
  `require_scopes("learning:service_improvement")`, so a subject principal is
  checked by `ensure_consent` like any other route and `unguarded_data_routes`
  stays empty. A console principal has no patient row, so the guard defers to the
  record-level control — and here that control is the aggregate itself (§3).
- **Admin-only**, via a new `require_admin` symmetric with the existing
  `require_patient`; a patient token gets 403.
- **The window is required and has no default.** A default reporting period would
  be a value chosen once by an engineer for every future reader, and invariant 20
  makes the window part of what a figure means. `Cohort` owns the forward-range
  rule; the route translates its refusal into a 422 rather than re-implementing it.

### 6. The one wiring: `records_processing`

`intake_api.documents.ingest_content` already begins and ends the scan-and-promote
pipeline inside one handler, so `measure_ms()` around `gateway.ingest(...)` is a
real interval rather than an inferred one. The observation is written in the same
transaction as the ingest — a rolled-back ingest leaves no wait behind — and only
on the clean path: a rejection is not a wait a patient sat through, and counting
it would flatter the figure.

`document_type` is the **existing** closed ingest allow-list
(`ALLOWED_CONTENT_TYPES` = pdf/jpeg/png) renamed to a label value.
`test_the_document_kind_map_covers_the_ingest_allow_list_exactly` holds the map
total, so a newly allowed content type fails the build rather than landing in an
unlabelled bucket. It is deliberately **not** a clinical document taxonomy (lab
report / discharge summary / prescription): this repo has none, and inventing one
here would be a value chosen once for every future reader.

## Values refused, with the ask

Rule 1 of files/HUMAN_BLOCKERS.md — never invent a value to unblock yourself.
Three were needed and none was invented.

1. **Histogram bucket boundaries.** files/08 §4 G states a target for two of its
   six ids (`<= 3 s`, `<= 60 s`) and a bucket boundary for **none**. A boundary
   chosen here would be read as a service level somebody set by every console
   that renders it. `WAIT_BUCKETS = prometheus_client.Histogram.DEFAULT_BUCKETS`
   — the library's own default, i.e. an explicit non-choice — and
   `test_the_buckets_are_the_library_defaults_because_the_blueprint_states_none`
   pins it so that a later editorial choice appears as a visible diff.
   **Ask — Owner:** *"What bucket boundaries, if any, should the group G wait
   histograms report against, and is there a wait-time SLA per tenant?"*
   Marked `awaiting-human`; no HUMAN_BLOCKERS.md row exists for it and this
   branch does not edit that file.

2. **A wait-time SLA or target rendered in the product.** None exists in the
   blueprint beyond the two group G targets, which are catalogue metadata. No
   target reaches the export, the API response or a metric help string.
   **Ask — Owner:** same sentence as above.

3. **A branch dimension for the SDS-01 export.** SDS-01 (`files/01 §4`,
   `files/03 §19`) is branch-level; the observation carries no branch, because a
   visit's branch lives in an encrypted `Slot` row rather than a column, and
   lifting it into an operational aggregate is (a) exactly files/08 §0c F9's
   re-identification shape and (b) a new personal-data field decision under
   invariant 18. Not added.
   **Ask — Owner + compliance_officer:** *"May wait-time observations carry the
   visit's branch id so the SDS-01 export can be branch-level, given branch ×
   narrow window × small clinic is F9's re-identification case?"*

4. **The four unmeasurable intervals.** No fake, no default, no "0". They fail
   closed at the writer and are catalogued `planned`. Two name their owning
   issue (INT-150, INT-163); two have none.
   **Ask — Owner:** *"Which issue owns writing the intake lifecycle instants —
   `sessions.started_at`, the first question reaching the patient, and
   `sessions.completed_at` — so `wait.time_to_first_question_s` and
   `wait.note_ready_after_wrapup_s` become measurable?"*
