## Platform facts (read from the library source that ships: react-native 0.86.3)
These are what "measured" can mean without a device. They are the reason the app owns the fade.
The device timing is the pending step below.

- **iOS** (`node_modules/react-native/React/Fabric/Mounting/ComponentViews/Modal/RCTModalHostViewComponentView.mm`):
  - `animationConfiguration` maps `Fade` to `(YES, UIModalTransitionStyleCrossDissolve)` and `None`
    to `(NO, UIModalTransitionStyleCoverVertical)` (lines 61–71).
  - Presentation and dismissal both pass `animated:_shouldAnimatePresentation` (lines 174–175 and
    194–195), set from that tuple (line 290). So `"none"` presents and dismisses unanimated.
  - Nothing in the file sets a duration. The cross-dissolve's length is UIKit's own, and React
    Native exposes no prop for it. The legacy view (`React/Views/RCTModalHostView.m`, lines 181
    and 202–203) has the same mapping.
  - On dismissal the host restores VoiceOver's focus to the element that had it at presentation
    (`saveAccessibilityFocusedView` / `restoreAccessibilityFocusedView`, lines 232–247).
- **Android** (`node_modules/react-native/ReactAndroid/src/main/…/views/modal/ReactModalHostView.kt`
  and `res/views/modal/`):
  - `"fade"` builds the dialog with `Theme_FullScreenDialogAnimatedFade`. Any other value builds
    it with `Theme_FullScreenDialog`, which has no `windowAnimationStyle` (`.kt` lines 268–272,
    `values/themes.xml`).
  - The fade's `catalyst_fade_in.xml` and `catalyst_fade_out.xml` run for
    `@android:integer/config_shortAnimTime`. That is 200 ms in AOSP; the device's own resource
    decides. No Android SDK is installed here, so the 200 ms is AOSP's published value, not a local
    read.
  - The `animationType` setter sets `createNewDialog = true` (`.kt` lines 97–101). Changing the
    type while the sheet is showing rebuilds the dialog. So the spec's first plan, switching the
    type to `"none"` one render before `visible=false`, would itself make the Android sheet flash.
    A type that is `"none"` from the start needs no switch.
  - The modal host restores no accessibility focus on dismissal (no focus handling in the `.kt`).
- **Both** (`Libraries/Modal/Modal.js`): the Modal renders its children only while shown. On iOS
  it keeps them until the native `onDismiss`, then unmounts them (lines 277–284 and 318–327). So
  the content mounts afresh on every open, and its entrance runs each time.

**Conclusion.** Neither platform fade fits 120 ms. iOS's length is not the app's to set, and
Android's is 200 ms in AOSP. So the app owns the sheet: `animationType` is always `"none"`, and the
content enters with the one fade. `transitions.test.ts` pins every fact above that the policy rests
on, reading these same files, so a React Native upgrade that changes one sends the sheet back to be
measured.

**ADR-033 §1** says platform-owned motion, the RN `Modal` included, "is configured, never rebuilt".
This change does not rebuild the platform transition. It configures it to `"none"`, and the
motion that remains is the app's one fade, inside the budget. That is what the row's acceptance
("owned at ≤ 120 ms if the platform exceeds it") and the verification's P15 and §2.1 #16 direct.
The ADR is Proposed; when it is ratified, its Modal line could name this case. Nothing here depends
on its open questions (Q1–Q5).

## Change
- `apps/mobile/src/lib/motion/transitions.ts` (pure):
  - `modalTransition({ reduce })` returns `{ animationType: "none", enter, exitMs: 0 }`. `enter`
    is `enterFor({ reduce })`: 120 ms opacity, delay 0, `easing.out`, or `undefined` under
    reduce-motion. It is built on the kept primitive `modalAnimation`, always asking it for the
    still answer (C-7). `animationType` and `exitMs` are literal types, so an owned modal that
    moves does not compile.
  - `SHEET_CLOSE_REASONS = ["user", "privacy", "red"]` and `sheetClose(reason, { reduce })`
    return the transition the sheet opened with: `"none"` and 0 ms for every reason at every
    setting. The type already in place before `visible` turns false is `"none"` (C12), and it stays
    that way while a third party is flagged, because it never changes.
- `apps/mobile/src/lib/motion/sheetOnRed.ts` (pure, new): `closesSheetOnRed(presentation, context)`
  returns INT-333's own yield, `redFirstPaint(…).yields.closeModals`. It is keyed on the
  presentation mode, never on "a RED arrived" (S-6). ALERT, CALM and SILENT close the sheet;
  DEFERRED_CLINICIAN closes nothing.
  - It is a separate module on purpose. It is on the RED path, so the MOTION-4 guard pins it with
    the other RED surface files and scans it for animation, haptic, Modal and router use.
    `transitions.ts` names the fade, which that scan forbids.
- `apps/mobile/src/lib/a11y/motion.ts`: `modalAnimation` gains an overload,
  `(reduceMotion: true): "none"`, so the policy keeps the literal type without a cast. Its
  behaviour and its tests (`a11y/motion.test.ts`) are unchanged.
- `apps/mobile/src/components/SectionPanel.tsx`:
  - `SectionSheet` takes `animationType={transition.animationType}`, an expression, so BK18 still
    holds.
  - The backdrop and the panel sit in ONE Reanimated `Animated.View` with
    `entering={enteringFor(transition.enter)}` and no `exiting`: one animated element, and nothing
    of the sheet outlives its close.
  - A new `opener` prop. In an effect keyed on `visible`, with no timer or frame, a true→false
    change sends accessibility focus to the opener
    (`AccessibilityInfo.sendAccessibilityEvent(target, "focus")`, as `KioskGate` does). The first
    mount moves nothing.
  - `SectionStrip` takes `ref` and gives it to its `Pressable`.
  - The Modal's other props are unchanged.
- `apps/mobile/src/components/DialogueIntake.tsx`: `const stripRef = useRef<View>(null)`, given to
  `<SectionStrip ref>` and `<SectionSheet opener>`. Nothing else in the dialogue changes.
- `apps/mobile/e2e/sheetSource.ts` (new): the MOTION-9 detectors (`sheetFindings`,
  `modalTypeFindings`, and small JSX readers).
  - `e2e/motionSource.ts` now exports its existing `closeOf` and `endOfString`, so the detectors do
    not duplicate them.
- `apps/mobile/e2e/motion.spec.ts`:
  - a MOTION-9 block;
  - `src/lib/motion/sheetOnRed.ts` added to the pinned RED surface files, since the MOTION-4 pin
    is exact.

## Device verification: PENDING
**Pending: the owner's two reference devices** (still unnamed; see `docs/evidence/INT-330.md`).
Nothing in this PR is a device measurement. On an iOS release build and an Android release build,
record the device, OS, build and date here:
- **Enter:** from the strip tap to the sheet fully opaque is ≤ 120 ms after the first frame, with
  no platform fade before it. It runs on every open, not only the first. Under reduce-motion (the
  OS setting, or the app's Görünüm switch) the sheet is simply there.
- **Close is 0 ms:** measured through the close control, a backdrop tap and Android back, at both
  reduce-motion settings. The sheet is gone on the frame after the commit, and on iOS the recents
  snapshot does not show it. Every close takes this one path (`visible` → false, type `"none"`, no
  exit).
  - A privacy close and a RED close cannot be fired on a device yet. The privacy triggers do not
    exist (see "Not in this PR"), and no RED reaches the UI before INT-135. When they land, their
    PRs repeat this measurement for their own trigger, and INT-338's row closes on this one.
- **Focus:** with VoiceOver and with TalkBack, open the sheet from the strip, close it each of the
  three ways, and check that focus lands on the strip.
- **One element:** the backdrop and the panel fade together, and the Reanimated entrance inside the
  Modal actually runs on both platforms.

## Not in this PR
- **The privacy triggers.** The "gizle" control and the third-party auto-hide (02 §5.2a rule 6)
  exist nowhere in the app, and no backlog row owns them: `docs/backlog/issues.yaml` has no row
  for either. This PR makes any close instant, so whatever issue builds them inherits a 0 ms close.
  No INT id is minted here.
- **The RED consumer.** INT-135's RED layer calls `closesSheetOnRed` and then closes the sheet.
  Until then no RED reaches the dialogue.
- **The arbiter.** INT-334 (PR #697) is not on this base, and INT-337 wires it. The acceptance
  names no arbiter behaviour, and the sheet's entrance is one element.
