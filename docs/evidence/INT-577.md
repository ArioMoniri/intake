## What INT-577 built

**The device budget counts the proven key (row 12).** The per-device window was keyed by
`sha256(payload.device_id)`, and `device_id` is the client's own claim even in `app-attest` mode,
where only `key_id` is proven. One attested key rotating that string met no bound. The window is
now keyed by an HMAC of INT-578's binding material: the App Attest key id when the call proved
one, and the install id only in `dev-unattested`, which only the dev tier accepts.

**The address is a keyed hash (row 13).** `auth:otp:w:ip:<raw address>` became
`auth:otp:w:ip:<HMAC>`, under the OTP pepper with its own domain
(`OtpPepper.rate_key("ip", address)`). It is keyed because an IPv4 address has 2³² values and a
plain hash of one is reversed by enumeration.

**Tenant and global caps, and the kill switch (rows 14, 16, 17).** New `intake_api.sms_spend`.
The gate (`AuthStore.otp_request_decision`) takes extra budgets beside the per-caller ones, each
a rolling window with its own length, and says which budget refused:

| budget | key | window | cap | refusal |
|---|---|---|---|---|
| tenant | `auth:otp:w:tenant:<tenant id>` | 1 h | 120 | 429 `otp_limited`, rolls on |
| global hour | `auth:otp:w:global_hour:all` | 1 h | 120 | 429 `otp_limited`, rolls on |
| global day | `auth:otp:w:global_day:all` | 24 h | 1000 | **latches the kill switch**; 503 `otp_delivery_unavailable` |

The kill switch is one Redis document, `auth:otp:kill` (reason and instant). It is read **first**,
before any budget is spent or code minted. Engaged: every request answers the generic 503 and
nothing is sent. Unreadable (Redis error) or unparseable: the same, because a switch that cannot be
read may be on. The day cap engages it with reason `day_cap` and appends
`sms.spend.kill_switch.engaged` (actor `system:sms-spend`, ids only) to the hash chain. A day
window rolling over does **not** release it. An operator on the host releases it, or engages it by
hand, with `python -m intake_api.sms_spend status|engage|release` inside the API container; engage
and release are appended to the chain (actor `operator:host`). The runbook is
`docs/runbooks/sms-abuse.md`. Engaging is one act and only ever makes the system safer; releasing
is deliberate (files/10 §2, asymmetric authority). The admin console has no release button: a
four-eyes ceremony for it is a console change, and the command keeps the release behind the same
SSM access as every other host operation.

**Exponential resend backoff (row 15).** With `backoff=True` (the phone tier; the Doctor Link
tier keeps INT-131's flat gate) the wait after a number's k-th code in the rolling window is
`60 s × 2^(k−1)`: 60 s after the first, 120 s after the second, and the per-number budget after
the third. A backoff refusal is weighed with the budgets, so the caller is told the longer true
wait, never only the shorter one. The 202's `resend_after_s` is that number's next wait. Inside
an hour it can only move the third code, since the budget is 3; what it buys is that a resend
loop cannot run at the cooldown's pace.

**+90 mobile only (row 18).** No code changed: `normalise_tr_phone` already admits only
`(+90|90|0)?5\d{9}`. Every class the owner named is pinned as a 422 that costs no budget and
sends nothing, with a Turkish mobile as the near miss: premium (`+90 900…`, `0900…`), shared
cost (`+90 850…`), landline (`0 212…`, `+90 312…`), short codes (`4444`, `444 1 234`,
`+90 444 12 34`), a foreign mobile, a foreign premium number, an international network (`+882`),
one digit long, one digit short, and a non-5XX range.

**The signals (row 20).** `sec_otp_requests_total{outcome}` and `sec_otp_abuse_blocks{dimension}`
(files/08 §4 ids, promoted from `planned` to live with closed labels: `REQUEST_OUTCOMES`,
`BLOCK_DIMENSIONS`), `sms_spend_kill_switch_engaged` (gauge) and
`sms_spend_kill_switch_trips_total{reason}`, all catalogued. In
`infra/observability/security-rules.yaml`, group `sms-abuse`:

- `SmsSpendKillSwitchEngaged` pages on `max(sms_spend_kill_switch_engaged) == 1`;
- `OtpRequestSpike` raises a ticket when the last hour's requests are over 3 × the day's hourly
  rate **and** over 20.

The ops console (`GET /admin/ops`, `intake.admin.ops.v1`) gains an `sms` tile from three fixed
queries: requests in the last hour and the last day, the baseline per hour, `spike`, and
`kill_switch_engaged`. Its spike test is `sms_spend.is_spike`, the definition the alert carries;
a test ties the alert's numbers to `SPIKE_FACTOR` and `SPIKE_FLOOR_PER_HOUR`. Without Prometheus
the tile is `unknown` with every figure null, like every other tile.

**The admin console (palette B) and this tile.** The tile is in the API document. Rendering it in
`apps/admin-web` is the admin console's own change, made over the API as agreed. No admin-web
file changed here. The page's payload guard ignores a tile it does not know, and `noTarget` sees
no `target` key in it.

## Security review fix (28 Oct 2026): the release is audited first

The orchestrator's review found one blocker here (B2). The operator command released the switch
and then appended `sms.spend.kill_switch.released`; when the audit store was down the append
raised after sending had already resumed, with no row saying who resumed it. `main` now appends
the row first and releases only when the append succeeded (`_release_audited`). A failed append
leaves the switch engaged, exits 1, and is logged by its exception type only. A switch that is
already released writes no row. Engaging keeps its order (switch, then row): stopping spend comes
first, and an engaged switch without its row fails safe.

Red (`uv run pytest tests/security/test_sms_pumping.py -k release`):

```

    E   AssertionError: assert None is not None            <- the switch was released before the row
2 failed, 3 passed, 33 deselected
```

Green: `tests/security/test_sms_pumping.py` `38 passed`. The near misses: with the audit store
up the same release appends then releases; releasing a released switch writes nothing.

## What this does not stop

- **The carrier half** (row 19): a 5XX prefix no operator has allocated still gets its SMS until
  the BTK list is supplied. The budgets and the caps bound what that costs.
- **Spend in money.** The caps count SMS, not lira. The vendor's own price and any per-account
  limit in the Netgsm panel are outside this repository; the runbook names the panel's usage
  report as the second source an operator reads.
- **Enumeration through the 429s.** A per-number refusal still answers differently from an
  admission. INT-579 makes those answers identical.
