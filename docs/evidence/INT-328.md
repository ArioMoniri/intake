# Evidence: INT-328 · release builds use a configured https API base and never probe the LAN

Production audit 2026-09-26, findings **F01**, **F17** and **F29**.

## 1. The defect

`apps/mobile/src/lib/auth/api.ts` `apiBase()` walked `configuredServiceCandidates(8000)` from
`lib/dev/expoHosts.ts` in **every** build. That walk is the Metro `hostUri` plus
`extra.asrHosts` (`127.0.0.1`, `172.20.10.3`), always over plain `http`. A store build has no
`hostUri`, so it probed loopback and a hotspot LAN address, found nothing and threw `network`.
The patient then saw "Sunucuya ulaşılamadı. Bağlantınızı kontrol edin.", which blames their
connection for a build that simply had no server. `lib/dialogue/clips.ts` repeated the same
walk for the dev George clip route.

- **F17:** declaring `NSLocalNetworkUsageDescription` puts the iOS local-network prompt in front of
  a store-build patient. On main, app.json does not declare it, but `int-demo` does.
- **F29:** `extra.asrHosts` and `extra.ttsLanes` can carry duplicates. On main they are unique; on
  `int-demo` both lists are doubled.

## 2. The change

**One typed resolver.** `src/lib/auth/apiBase.ts` is pure and node-testable, with no expo import
and no lib/dev import.
- **Release (`!__DEV__`):** the base comes only from build-time `extra.apiBaseUrl`.
  - It must be `https://` on a public DNS name.
  - Anything else throws `ApiBaseUnconfigured`: a subclass of `AuthApiError` with kind
    `unconfigured` and a reason of `unset`, `insecure`, `malformed` or `not_public`. The error
    message is the kind only and never carries the configured value.
  - `not_public` covers loopback, IPv4/IPv6 literals, single-label names, and `.local`,
    `.localhost`, `.home.arpa` and `.internal`.
  - The dev walk is never called.
- **Dev:** the LAN walk, exactly as before. A configured base is ignored.

**Expo binding.** `src/lib/auth/expoApiBase.ts` reads `__DEV__` and `extra.apiBaseUrl`. It reaches
`lib/dev/expoHosts` only through a lazy `await import()`, which the resolver invokes only when
`isDev`. `api.ts` and `clips.ts` both resolve through `buildApiBase()`, and neither keeps a walk
of its own.

**Errors.** `AuthApiError` moved to `src/lib/auth/errors.ts` so the pure resolver can throw it.
`api.ts` re-exports it, so no caller changed its import.

**UI.**
- `(auth)/phone.tsx` and `(auth)/otp.tsx` map `unconfigured` to a new key,
  `auth.error.unconfigured`.
- tr source: "Uygulamanın bu sürümü henüz hizmete bağlı değil. Lütfen uygulamayı güncelleyip
  yeniden deneyin."
- en mirror: "This version of the app is not connected to the service yet. Please update the app
  and try again."
- The copy uses the siz register and contains no numerals. It follows the pattern of the existing
  `auth.error.attestation` line and is distinct from the `network` copy.

**Config.** `apps/mobile/app.config.ts` is a new dynamic config over app.json.
- **F01:** `extra.apiBaseUrl` is filled only from the EAS variable **`EXPO_PUBLIC_API_BASE_URL`**.
  app.json cannot supply it, and no hostname is committed. The production FQDN is a human decision
  (**HB-I14**), so until the variable is set the value is empty and the app fails closed with the
  copy above.
- **F17:** when `EAS_BUILD_PROFILE=production`, `NSLocalNetworkUsageDescription` and
  `NSBonjourServices` are removed from `ios.infoPlist`. Every other profile keeps exactly what
  app.json declares.
- **F29:** `asrHosts` and `ttsLanes` are deduplicated, keeping first-seen order.

**Not changed.** The dev-only ASR (8802), extract (8804) and TTS-lane discovery in `voice.ts`,
`extract.ts`, `useDialogueSession.ts` and `clips.ts` still use lib/dev. Those are the dev voice
lanes, not the API base.

## 6. For the owner

- **Before a store build**, set the EAS environment variable `EXPO_PUBLIC_API_BASE_URL` to the
  production https base (HB-I14). Until then a release build shows `auth.error.unconfigured` and
  sends nothing.
- **Consolidation with `int-demo`:**
  - Its app.json declares `NSLocalNetworkUsageDescription` and doubles `asrHosts`/`ttsLanes`.
    `app.config.ts` neutralises both for the production profile.
  - Its `api.ts` adds a type-only `@/lib/dev/accounts` import. The graph test skips `import type`
    because the compiler erases it.
  - Any release/preview build that reached the API over LAN `http` will now fail closed by design.
