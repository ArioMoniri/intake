## The column limits, derived from 26.7.4's schema

- **Method.**
  - The 78 `model/jpa/src/main/resources/META-INF/jpa-changelog-*.xml` files were fetched raw
    at `aa9fe3f`.
  - They were replayed in `jpa-changelog-master.xml` order (the authz master inlined), following
    `createTable`, `addColumn`, `modifyDataType`, `renameColumn`, `dropColumn` and
    `renameTable`.
  - A change inside a changeSet restricted to a vendor (db2, oracle) was kept apart from the
    generic type.
  - No generic `<sql>` changes a column type.
- **The replayed files are the bytes that run.** The 78 files are byte-identical to the
  `META-INF/jpa-changelog-*.xml` inside the distribution's
  `lib/lib/main/org.keycloak.keycloak-model-jpa-26.7.4.jar` (`diff -r` clean).
- **Which field lands in which column** was read from the 26.7.4 sources:
  - `RealmEntity` has `@Column(name="DISPLAY_NAME")`.
  - `RealmAdapter.setOTPPolicy` writes the realm columns.
  - `RealmAdapter.setWebAuthnPolicy` writes realm attributes, with lists comma-joined.
  - `UserAttributeEntity.setValue` moves a value over 255 characters to `LONG_VALUE`.
- **Each limit in the test cites the changelog line that gives the column its final type.**
  The ones the realm reaches:
  - `AUTHENTICATION_FLOW.DESCRIPTION` NVARCHAR(255): `jpa-changelog-2.5.0.xml:74`.
  - `KEYCLOAK_ROLE.DESCRIPTION` NVARCHAR(255): `:102`.
  - `CLIENT.DESCRIPTION` NVARCHAR(255): `:78`.
  - `AUTHENTICATION_FLOW.PROVIDER_ID` and `AUTHENTICATION_EXECUTION.AUTHENTICATOR`
    VARCHAR(**36**): `1.4.0.xml:47` and `1.3.0.xml:64`. A custom authenticator id, such as
    #643's 29-character `intake-webauthn-session-notes`, must fit 36.
  - `REALM.OTP_POLICY_ALG` and `OTP_POLICY_TYPE` VARCHAR(36).
  - Config, attribute and component values are CLOB or NCLOB, so they have no limit.
- **New on this version.** 26.7.0 moved the realm display name out of `REALM_ATTRIBUTE` (NCLOB)
  into `REALM.DISPLAY_NAME`, NVARCHAR(255), in changeSet
  `26.7.0-45292-realm-display-name-add-column` (`jpa-changelog-26.7.0.xml:34`). The realm's
  display name is 165 characters.
- **Measure.** Length is counted in UTF-16 code units (Java `String.length`). That is never fewer
  than the characters H2 and PostgreSQL count.

## A second import break the upgrade brings

The first 26.7.4 start with `main`'s compose layout failed before any column was written:

```
ERROR: Failed to start server in (development) mode
ERROR: File name / realm name mismatch. dev-realm.json, contains realm intake-dev. File name should be intake-dev-realm.json
kc exit=1
```

- **Cause.** `DirImportProvider.importRealm`
  (`model/storage-services/src/main/java/org/keycloak/exportimport/dir/DirImportProvider.java`,
  lines 137 and 146–148 at 26.7.4) reads `<name>-realm.json` and refuses it unless the realm
  inside is `<name>`.
- **When it arrived.** The check is absent at 26.1.4 and 26.1.5 and present at 26.2.0 through
  26.7.4 (checked by fetching the file at each tag).
- **Consequence.** Bumping the image alone would have left `make obs` unable to start.
- **Fix.** Compose now mounts the unchanged repository file at
  `/opt/keycloak/data/import/intake-dev-realm.json`. The test holds it there, with the 26.1.4
  file name as the near-miss.

  - a 256-character flow description;

    where `len()` would not;
  - a role description, client description, client name or display name of 256;

    of 37;

  - Exactly 255 gives no violation, and 256 gives the one exact message, citing
    `jpa-changelog-2.5.0.xml:74`.
  - 5 000 characters in an NCLOB column is admitted.
  - A hashed credential value is not measured.
- **Tables (4).**
  - Every field names a known column.
  - No field is both stored and not stored.
  - Every source is a `jpa-changelog-*.xml:<line>`.
  - Every committed string path is classified.

  - Compose equals the digest pin.
  - The pin shape needs both tag and digest. The near-misses are a tag alone and a digest alone.
  - No tracked file outside the dated records names another Keycloak image. The repository name
