## The decisions, and the one disagreement

**Four-eyes is asymmetric, as files/08 decided it — not on every lever.** The brief for this issue
read "kill switch … 4-eyes: request + a second approver … a single approver cannot flip it".
files/08 §0c F17 and §8.2 (and files/10 §2 "Asymmetric authority") settle the opposite for the
kill switch: it moves a tenant to the *safer* transport, so it is **tier 1 — one `sre_oncall` or
`clinical_lead`, audited, no approver** — because a second key at 03:00 on the safe direction is an
availability control on a safety control. `DangerousAction.__post_init__` already makes a two-key
safe action unconstructible. So this issue implements the spec: engaging is one key
(`test_one_sre_pulls_it_alone_and_no_ceremony_opens`), and **everything that moves toward voice —
release, default-profile switch, canary weight — is tier 2 and one person cannot do it**
(`TestOnePersonCannotMoveTowardVoice`: self-approval refused and metered, a second tab on the same
credential refused, `sre_oncall` cannot request, a distinct second human applies it).
`platform_owner` may also take the safe direction alone, following INT-188's
`SAFETY_FLAG_DISABLE_ROLES` precedent.

**Who requests and who approves** is read off files/08 §2.1, not invented: T2 requesters are the
all-tenant roles accountable for the clinical channel (`platform_owner`, `clinical_lead`); the
second key may also be `qms_owner` (IEC 62304 change control). `sre_oncall`'s §2.1 scope is "T1
safe-direction actions"; `platform_admin` has "no clinical surfaces"; `tenant_admin` is the
adversary §0c F8 names. The RBAC matrix (`tests/admin/test_rbac_matrix.py`) holds all nine routes.

**The control lives in Redis, not Unleash.** files/08 §3/§6 and invariant 34 keep the kill switch
out of the generic flag store (Unleash tokens flip flags with no audit row). The only writer is
`services/api/admin`, behind the registry and the write-ahead audit. No Alembic revision was minted
(parallel branches collide on them); the `services/gated-capability` of files/08 §10 does not exist
yet and this store is the part of it the voice path needs.

**An unconfigured tenant is `typed`.** Voice is enabled per tenant by a tier-2 profile switch,
never by the absence of a row — so a Redis that loses its keys falls every tenant to the keyboard,
not to voice. A control the runtime cannot read starts the session typed and is counted; a speech
worker without the store is not ready. On the poll, an unreadable control moves nothing: a live
session keeps the state it was routed under (flipping every live patient on a Redis blip is an
action on patients driven by an infrastructure error), and the failure is counted.

**An approval binds to what it approved.** The ceremony carries the record revision; approval is
refused (`voice_control_changed`) if the control moved since — a kill switch pulled mid-ceremony
cannot be silently undone by approving the stale request — and the refusal does not spend the
ceremony (`test_an_approval_after_the_control_moved_is_refused`).

**The canary did not exist in the runtime**; it is built as part of the control: a profile plus an
integer weight 0..100, default 0, routed by a deterministic hash of tenant + session id (a replay
routes the same way), refused for a profile that does not exist or for the default profile.

## Acceptance → tests

- **"per-profile metrics"** — `GET /admin/voice` tiles: sessions by profile × route reason, turn
  latency p50/p95 per profile (`voice.round_trip_ms`), ASR/TTS error ratio per component
  (`voice_speech_calls_total`), failovers and breaker states (INT-100's `vendor_failovers_total`,
  `vendor_breaker_state`), kill-switch activity. Every query names catalogued series
  (`test_every_query_references_only_catalogued_series`); each tile fails closed to unknown on its
  own (`TestUnknownPerTile`); a profile label outside the two turns its tile unknown. Turn latency is
  **unknown today** — nothing emits `voice.round_trip_ms` yet (catalogued `planned`), and the tile
  says so rather than showing a number nobody measured.
- **"kill switch flips tenant to typed without deploy (test)"** —
  `TestKillSwitchWithoutDeploy` drives the admin route and the runtime's session-start path over one
  shared store: the next session on the **same router instance** is typed with reason
  `kill_switch`; another tenant is untouched; a live voice session is moved to typed by the watch
  loop within INT-100's 2 000 ms budget on a fake clock (poll 1 000 ms, held `< 2 000` by the
  router's constructor); the route counter reflects it.
- **"profile switch" / "canary weights" (title)** — `TestOnlyProfilesThatExist`: any profile other
  than `residency_tr`/`typed` is refused before a ceremony opens; weights `-1, 101, 50.5, "50",
  true, null` refused, `0, 1, 100` accepted; a canary of the default refused.

## Owner configuration — what makes it live

- **`INTAKE_VOICE_CONTROL_REDIS_URL`** set to the **same** Redis in the API and the voice runtime.
  Unset: the voice writes answer 503 and a speech worker is not ready. Redis persistence (AOF) is
  the owner's call; losing the keys falls every tenant to typed, never to voice.
- **Console admission** is unchanged and still owner-blocked: Keycloak OIDC
  (`INTAKE_ADMIN_OIDC_ISSUER`, `…_AUDIENCE`, `…_JWKS_PATH`) and the IP allow-list (HB-A16).
- **Approving a tier-2 request from the page** needs a WebAuthn step-up ceremony in the console,
  which does not exist yet (files/08 §2.3); the API's approve routes take the assertion id. The page
  shows the approve button disabled with that reason.
- **Turn latency** stays unknown until an emitter for `voice.round_trip_ms` lands.

## Found on the way (reported, not fixed here)

`apps/admin-web/src/ops/load.ts` `errorCode()` reads `detail.error`, but the API's exception
handler returns a flat `{"error": code}`; so a 403 `source_ip_refused` renders as
`role_not_permitted` and a 503 `admin_console_unconfigured` as `api_unreachable` on every console
page. The voice form handler reads both shapes.
