# Evidence — INT-382 · The compiler refuses a `suppress_slot`, in any layer, that removes a slot a red-flag rule reads

Branch: `int-382-rule-slot-removal`, cut from `origin/main` at `1d43b71b` and merged with `main`
at `ca3096b9`. GitHub #629. Sec-Row: `protocol-registry`.
Found by the PR #628 verification, `docs/evidence/verification/generator-capabilities-628.md` H-1
(on the `int-379-generator-capabilities` branch).

## 1. The defect

A red flag fires only on TRUE (files/12 §1.1). A rule whose slot no longer exists reads Unknown
for the whole session, so it never fires. The closed op set makes deleting a rule unrepresentable
(files/12 §3.1), but a `suppress_slot` of the slot the rule reads removes the flag all the same,
without naming it. CLAUDE.md invariant 7 forbids that in every layer.

INT-258 refused it for overlays only (`OVERLAY_REMOVES_RULE_SLOT`, `compile/overlay.py`). The
PR #628 verifier measured the same op in a chain pack (cluster to specialty) under all eight
clusters. It compiled, and the rule anchored on the removed slot was served and never fired. The
red run below reproduces that (§4, RED 2: 15 chain cases compile), and adds one case the verifier
did not list. An overlay that suppresses a slot a `base.life_threat` rule reads also compiled,
because the overlay composer never sees the sibling set.

## 2. The check

`packages/protocols/src/protocols/compile/rule_reads.py`, called once from `resolve_protocol`
(the resolver behind `protocols compile`, `compile_bundle` and every served bundle):

- **When it runs:** after the chain is merged and every op of every layer, overlays included, is
  applied. What is judged is the document that would be served, so the removing layer and the order
  no longer matter. If two ops conflict or an op fails to apply, the check does not run. That
  document is not the one the author wrote, and the compile already refuses for the op. PR #620
  (INT-375) uses the same rule for its ask-order check.
- **Which rules:** every pack rule after overlay composition, and every `base.life_threat` rule.
- **Which fields:** `when` (every reference `protocols.triage.expr.referenced_slots` returns, the
  engine's own reference set) and `tense_anchor` (the engine unions it into that set, files/12
  §2.4). No other `RedFlagRule` field names a slot. The action block names locations and action
  codes.
- **Spellings:** a reference is declared when it names a merged slot as `<section>.<slot>` or as
  bare `<slot>`. Those are the two spellings `when` and `tense_anchor` use. A bare read survives
  while another section still declares that key (pinned by a near-miss test).
- **Drafts count.** A `draft_needs_source` rule is signed with the reads it has, so a draft
  anchored on a removed slot is refused now, beside its `DRAFT_RULE_NOT_SERVED`, not served dead
  after sign-off. A draft `when` in the invariant-17 pending form reads no slot. Its
  `tense_anchor` still does. This is the H-1 case exactly: every cluster and specialty stub
  anchors on `sikayet_suresi`.
- **Unreadable predicates:** when any slot is suppressed, a rule whose `when` is outside the
  closed grammar is refused as `VALIDATION_FINDING`. Its reads cannot be listed, so the suppression
  cannot be shown to leave it intact (INT-258's reasoning).

| refusal | subject | message names |
|---|---|---|
| `RULE_READS_REMOVED_SLOT` (new) | `<rule_id>:<slot_ref>` | the rule kind (pack or `base.life_threat`), the field(s) that read the slot, and every suppressing `<pack_id><pointer>`. Ids only, never the predicate text |
| `OVERLAY_REMOVES_RULE_SLOT` (unchanged) | `<overlay_id><pointer>` | as INT-258 wrote it |

**The overlay refusal is unchanged.** `compose_overlay_rules` and its tests are untouched apart
from sharing the pointer-to-names helper (`pointer_slot_names`, which moved to `rule_reads.py`
unchanged). Through `resolve_protocol`, an overlay removing a slot a parsed pack rule reads still
reports exactly one line, `OVERLAY_REMOVES_RULE_SLOT` (pinned). The new check skips a fault the
composer has already named. It does not skip two cases the composer never names: a
`base.life_threat` rule, and a draft in the pending form (see §7).

## 7. Mutations and an observation

13 mutations on `cp` backups of `rule_reads.py` / `resolve.py`, each restored from its backup
after the run (`cmp` clean at the end; `git checkout` never used). **13/13 killed**: life-threat
rules not passed; `tense_anchor` not read; `when` refs dropped; overlay dedupe removed; the
pending form read as unparseable; drafts deduped like parsed rules; life-threat deduped as if the
composer saw it; the check run on an unfinished merge; unreadable predicates waved through; an
unreadable predicate refused with no suppression; the composer-unreadable dedupe removed; bare
names not declared; overlay suppressions not passed.

One equivalent mutant exists: dropping the qualified spelling from the declared set. A qualified
read can only be missing if its own slot was suppressed. A second writer of that pointer is an
`OVERLAY_CONFLICT` (files/12 §3.4), so no reachable document re-declares it. The spelling is kept
because it states the rule.

Observation, pre-existing, not changed here: the overlay composer parses a draft's pending-form
`when` as a grammar error. So an overlay that suppresses any slot at all is refused with one
`VALIDATION_FINDING` per draft rule in the chain (15 on the `base.intake` chains). That fails
closed, but it is noisy, and it never names the anchor, which is why the new check names it. The
issue requires the overlay behaviour unchanged, so this is recorded, not fixed.
