# Evidence: INT-361 · the OTP boxes accept a pasted or autofilled code (WCAG 2.2 SC 3.3.8)

Found by the INT-226 conformance report (PR #583), row SC 3.3.8, "Does Not Support" (manual item
MC-16).

## 1. The defect

`apps/mobile/src/app/(auth)/otp.tsx` rendered six boxes, and each one was capped at one character
with `maxLength={1}`. iOS and Android apply that cap before `onChangeText` sees the text, and the
handler kept only the last digit it received. So none of these could fill the code:

- a paste;
- the iOS "From Messages" suggestion. The screen declared `textContentType="oneTimeCode"`, but the
  cap cut the suggested code down to its first digit;
- Android SMS-code autofill. The screen declared no `autoComplete` hint.

Sign-in therefore required transcribing six digits from the SMS. SC 3.3.8 treats that as a
cognitive function test with no mechanism to complete it.

## 2. The change

- **`src/lib/auth/phone.ts`:** `enterOtp(digits, index, text)`, a pure function next to
  `OTP_LENGTH` and `isCompleteOtp`. It turns one box's new text into the six registers and the
  box to focus next.
  - Only digits count, so spaces, dashes, newlines and words in a copied message are dropped.
  - A whole code fills all six boxes starting from the first, whichever box received it.
    Digits after the sixth are dropped.
  - A shorter run of digits fills forward from the box that received it and stops at the last
    box.
  - Typing one digit is unchanged: that box only, then focus moves to the next box.
  - A digit typed next to the one already in a box replaces it.
  - A code pasted next to an existing digit fills all six. The old digit is removed from the edge
    where the caret put it, but only when what remains is one digit or a whole code.
  - Text with no new digit changes nothing and moves no focus. Clearing a box empties that box
    only.
  - Focus moves to the box after the last one written, or stays on the last box once the code is
    whole. Nothing is submitted: the patient still presses "Giriş yapın". The function is pure and
    writes nothing to any log.
- **`src/app/(auth)/otp.tsx`:**
  - `maxLength={1}` removed. The registers still hold one digit each, because `value={digit}` is
    driven by `enterOtp`.
  - `onChangeText` calls `enterOtp(digits, index, value)`.
  - `autoComplete` is `"sms-otp"` on Android (native SMS-code autofill) and `"one-time-code"` on
    web. `textContentType="oneTimeCode"` is kept for iOS, where React Native ignores
    `autoComplete` once a content type is set.
  - `secureTextEntry`, the accessible name ("Doğrulama kodu hanesi: n"), the error announcement
    and the resend cooldown are unchanged. There are no new catalog strings.
- **`e2e/auth.spec.ts`:** the old pin `maxLength={1}` asserted the defect. The test keeps its name
  (the INT-226 report cites it) and now asserts the opposite: no field cap, `value={digit}`, and
  the distributor wired in.

## 3. Tests

- **`src/lib/auth/phone.test.ts`**, 18 new tests.
  - Pure distribution cases:
    - a whole code pasted into box 0, 1, 3 and 5;
    - a whole code replacing a half-typed one;
    - spaces, dashes, a label and a trailing newline;
    - more than six digits, including a copied SMS body;
    - letters alone, and a letter next to a digit;
    - a code pasted either side of an existing digit;
    - a short run, and a short run clipped at the last box;
    - typing one digit, and typing next to an existing digit;
    - clearing a box;
    - the input array is never mutated.
  - **Invariant 6:** every `console` method is spied on while `enterOtp` runs through seven paste,
    type and clear paths, and none is called.
- **`e2e/a11y.spec.ts`**, 12 new tests.
  - **SC 3.3.8** (6), read by the spec's own JSX opening-tag scanner:
    - one `TextInput` inside `digits.map(`, so every property applies to all six boxes;
    - `textContentType="oneTimeCode"`, with an `autoComplete` whose literals include both
      `sms-otp` and `one-time-code`;
    - no `maxLength`;
    - `onChangeText` calls `enterOtp(digits, index, …)`, imported from `@/lib/auth/phone`;
    - the accessible name is unchanged;
    - `secureTextEntry` is kept.
  - **Invariant 6** (6):
    - the scan covers the screen, the distributor and the verify client;
    - `otp.tsx`, `phone.ts` and `api.ts` contain no `console.`;
    - no module on the entry path imports a telemetry, metrics, analytics or logger module;
    - the code planted in every limb of a crash event does not appear in the envelope bytes
      `buildCrashReport` and `buildEnvelopeBody` produce. The limbs are the exception value,
      message, frame vars and context line, a network breadcrumb URL and body, a user-input
      breadcrumb, tags, `extra` and `request`.
    - **Near-miss control:** the legitimate `errorCode`, `screen_id` and `exceptionType` of the
      same event do survive, so an empty report cannot pass.

The invariant-6 tests in `a11y.spec.ts` passed before the change too. The code already reached no
sink; these tests now hold that line. The console-spy test in `phone.test.ts` failed in the red run
only because `enterOtp` did not exist yet.

## 7. Not proven here, and for the owner

- **Device behaviour needs a device run.** Nothing here shows that iOS offers the "From Messages"
  code in a `secureTextEntry` box, or that Android's SMS-code autofill fires on the `sms-otp`
  hint. That is the INT-226 report's manual item MC-16, audited on hardware as DA-07. The source
  now declares every hint the platforms read, and the distributor handles whatever text they
  insert.
- **The conformance report is not updated here.** The SC 3.3.8 row and the BK26 remark about the
  failed `oneTimeCode` mitigation live in `docs/compliance/accessibility-conformance.yaml` on PR
  #583, which is not on `main` yet. Once both PRs land, the row can cite
  `apps/mobile/e2e/a11y.spec.ts::SC 3.3.8 — …` and move from "Does Not Support" to "Supports"
  (pending DA-07).
- **The backlog row is not changed here.** The INT-361 row lands with PR #590, which is not on
  `main` yet, so `docs/backlog/issues.yaml` and `files/11` are untouched.
