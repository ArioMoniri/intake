# INT-540 — the onset anchor always resolves, so K2 cannot stay silent

GitHub #913 · Sec-Row `clinical-core` · phase P0 · 16 Oct 2026 · Stacked on
INT-522 (#915, `64e6aef7`), which contains INT-521 (#910), INT-518 (#908) and
INT-441 (#907)

From the INT-522 clinical review, findings F1 and F2.
`chest_pain.onset_at` is the tense anchor of `rf.chest_pain_cardiac_features`
(KIRMIZI_K2) and its SARI sibling. After INT-522 a closed choice bound its
CD-05 day. An answer that fit no choice could still leave the anchor
`ASKED_PENDING` for the whole session.

- **F1.** The extraction instructions never said when to set
  `clarification_needed`. For "bilmiyorum" or a narrative the model could
  return no slot and no flag. The engine binds nothing and queues nothing on
  that, so the anchor stayed pending, read Unknown, and K2 never fired. The
  same happened if the session was abandoned mid-clarification.
- **F2.** CD-04 (active, verified, not built) makes "bilmiyorum" and "emin
  değilim" UNCLEAR at once and asks the slot's `follow_up_tr` once. For a tense
  anchor, CD-05 resolves UNCLEAR to the reference day. The build waited for
  the engine's generic two follow-ups. It also trusted a choice the model
  guessed over the patient's hedge.

**Acceptance, from the issue and the orchestrator's brief:**

- "Build CD-04's answer states exactly as decided (no re-decision; anything
  CD-04 leaves open stays in the invariant-17 TODO form under
  draft_needs_source …). Its hedge list is CD-04's own, read from the
  decision, not hard-coded." — **met.** See *What CD-04 decides, and what is
  built*. CD-04's two open items stay its own literals, and the table refuses
  them if they stop being open. No surface is written in the module, and a
  test reads the module source to pin that.
- "The extraction contract defines clarification_needed precisely (schema
  instructions + parse), and a model output with no slot and no flag for an
  asked tense anchor is treated per CD-04 (not silently pending)." — **met.**
  Instruction rule 8 defines the flag (`PROMPT_VERSION` `extraction.v2`).
  `ExtractionResult.outcome_of` gives every declared slot one reading:
  `CLARIFY`, `BOUND`, `REFUSED` or `SILENT`. For an asked anchor, anything
  but `BOUND` without a hedge is UNCLEAR at once.
- "A pending tense anchor cannot outlive the session: on abandonment / session
  end / max follow-ups the anchor resolves per CD-05/CD-04 and triage is
  evaluated (rules engine only, invariant 1), RED delivered via the existing
  path if it fires." — **met.** Spent follow-ups: the engine records UNCLEAR
  at CD-04's bound. Session end and abandonment: a new state-lane Work,
  `close_session`, is queued behind the last answers by `SessionStack.close()`
  and by `VoiceSessionRouter.end()`. The queue's existing before/after compare
  runs the rules engine. A RED takes the existing path: `preempt` derived,
  clinician route told as it settles, seal, data-channel trigger on the next
  drain.
- "Follow-up bound for a tense anchor: CD-04's decided once-only follow-up …
  a single named constant read from the decision, so the amendment changes
  data, not code." — **met.** It is `CD-04.value.unclear_follow_up_tr_asks: 1`,
  read by `protocols.answer_states` and handed to the engine as a per-step
  bound. Tables saying 0 and 2 change the session with no code change (tests
  below).
- "Tests on both profiles … each ends with the anchor resolved and K2
  evaluated; near misses …; fake clock." — **met**, see *Tests*.
- "make safety and make runtime-sim (both profiles, PARITY=1) green; goldens
  updated with a near-miss negative control …; coverage floors held." —
  **met**, see *Gates*.

## What CD-04 decides, and what is built

CD-04 has status `active`, verifier `agree`, and D18 scope: simulated-patient
stress testing only. Its decision for this anchor:

- A hedged or qualified answer to a scripted red-flag question is UNCLEAR or
  PRESENT_QUALIFIED, never ASKED_ABSENT.
- "UNCLEAR reads Unknown and triggers the slot's follow_up_tr once."
- The `bilmiyorum` entry says: "for a tense anchor the answer is recorded
  UNCLEAR and the anchor is resolved by CD-05's more-acute rule".
- `unresolved_after_follow_up` for `chest_pain.onset_at` says: "the anchor is
  also resolved by CD-05's more-acute rule".
- "An unmatched hedge is UNCLEAR."
- The matcher tests hedge entries longest first, and plain negatives last.

| CD-04 says | Built as | Where |
|---|---|---|
| The fourteen entries: surface, answer state, qualifier, slots, status | `AnswerStateTable`, read through the clinical-decisions register (provenance-checked). Each entry is split into whole words after NFC, a Turkish lower-case fold (dotted and dotless I) and punctuation-to-space. There is no diacritic fold and no substring match. | `packages/protocols/src/protocols/answer_states.py` (new) |
| `match_order`: hedge entries, longest surface first | entries sorted longest first; the first entry that applies to the slot and whose words occur in the answer wins | same |
| `*` entries read on any scripted slot; the rest read per slot | `HedgeEntry.applies_to`. A PRESENT_QUALIFIED entry on `*` is refused. `SessionAnchors` refuses a table that gives a tense anchor a PRESENT_QUALIFIED reading. | same; `clinical_agent/anchors.py` |
| The two draft entries (near-faint, black stool): the UNCLEAR floor; the upgrade is the open literal | basis `draft_unclear_floor`; the table refuses a draft entry above the floor, or one whose upgrade is no longer the invariant-17 literal | `answer_states.py` |
| "triggers the slot's follow_up_tr once" | `unclear_follow_up_tr_asks: 1`, a machine-readable restatement added to CD-04.yaml (no value changed; the md twin says so). The engine takes it as the anchor's clarification bound. | `CD-04.yaml`, `fsm.py`, `composition.py` |
| `unclear_evaluates_as: unknown`, `present_qualified_evaluates_as: present`, `unmatched_hedge: UNCLEAR`, `plain_negative_to_scripted_question: ASKED_ABSENT` | required as written. Any other value is refused when the table is built. | `answer_states.py` |
| A hedge on the anchor is UNCLEAR, reads Unknown, and gets one follow-up | for a Work answering the asked anchor (its question or its follow-up), a CD-04 UNCLEAR reading withholds any choice the model recorded and asks the clarification. | still UNCLEAR after the follow-up → CD-05's more-acute rule | the engine records UNCLEAR at the bound. INT-522's `SessionTriage` already reads an UNCLEAR anchor as CD-05's reference day, so that Work is evaluated. | `fsm.py` (bound), `live_triage.py` (unchanged) |

What is recorded: `SessionAnchors.unclear` keeps each UNCLEAR reading of an
anchor in order, with its cause (`hedge`, `no_choice`, `session_closed`), the
CD-04 qualifier for a hedge, and the decision id. Its repr shows neither the
qualifier nor the surface (invariant 6). `SessionAnchors.record` still carries
CD-05's `unresolved_answer` resolution once evaluated.

**Scope held to the anchor.** CD-04 also covers the non-anchor scripted slots:
its PRESENT_QUALIFIED readings, its once-only follow-up for the CD-01 feature
slots, and the CD-08 inbox item. This issue builds the table whole but applies
it at runtime to the CD-05 tense anchors only. Every other slot keeps files/13
§11.1's two clarifications and the model's own flag. See *Residuals*.

## Left to the D18 lane (not decided here)

1. **INT-519 item 5** (open on #885): should the first explicit hedge resolve
   the anchor at once? The build follows CD-04's decided once-only follow-up.
   The amendment is one number, `unclear_follow_up_tr_asks`; a table that says
   0 resolves the first hedge on that Work (tested).
   - The reviewer's recommendation splits by kind: at once for an explicit
     hedge, one follow-up for an off-choice informative answer such as "dün
     akşam". That split needs a second number in CD-04 and a few lines to
     read it. Today one number governs both kinds.
2. **INT-519 item 6**: CD-05's final resolution of the twelve-to-seventy-two
   hour band. It is unchanged and still CD-05's open literal.
3. **INT-519 item 7**: the tie-break for a narrative straddling two bands. It
   is not built. The model either records one authored choice or none. With
   none, the answer is UNCLEAR, gets the follow-up, and then CD-05's more-acute
   day.
4. **New, surfaced by this build. A hedge and a choice in one answer**, for
   example "emin değilim, galiba üç günden önceydi". Built per CD-04's matcher
   (hedge entries are tested first): UNCLEAR, so the follow-up is asked. This
   is never less acute than the choice. The D18 lane should confirm CD-04
   meant this for a tense anchor.
5. **New. A plain negative to the onset question** ("yok", "olmadı"). CD-04
   makes a plain negative ASKED_ABSENT. A date anchor has no absent value, and
   CD-05 makes an answer that fits no choice UNCLEAR. Built: UNCLEAR (CD-05).
   Please confirm.
6. **New. An anchor never asked when the session ends**, for example a session
   that ended between `chest_pain.present = yes` and the onset question. It is
   not resolved, because nothing binds to a question that was not asked
   (files/13 §9.6). K2 cannot fire, and must-ask coverage reports the gap.
   Should CD-05's more-acute rule reach it?
7. **Asked and never answered at session end** is resolved as CD-05's
   unresolved answer, because the issue's acceptance requires it. The D18 lane
   may want CD-05 to say so in its own words.

CD-04's own open items are unchanged. They are the two
`present_qualified_upgrade` literals (near-faint, black stool) under
`draft_needs_source`, and a test asserts both are still open.

## The defect, as it was measured

On `64e6aef7` (INT-522's head), with the base tree's voice runtime and its
INT-521/522 test helpers swapped back in. The setup is both profiles, the
committed `base.intake` with the active `base.life_threat` rules, and
character "baskı". The model is a table keyed by what the patient said. It
records nothing for "Bilmiyorum." and sets no flag (a scratch probe over
INT-522's helpers):

```
residency_tr  bilmiyorum, no slot, no flag    onset=ASKED_PENDING  follow_ups=[]  level=GREEN/YESIL  clinic=[]
residency_tr  asked, then the session ended   onset=ASKED_PENDING  follow_ups=[]  level=GREEN/YESIL  clinic=[]
typed         bilmiyorum, no slot, no flag    onset=ASKED_PENDING  follow_ups=[]  level=GREEN/YESIL  clinic=[]
typed         asked, then the session ended   onset=ASKED_PENDING  follow_ups=[]  level=GREEN/YESIL  clinic=[]
```

No follow-up was asked and the anchor stayed pending. On the base the
session had no end at which anything could resolve it. K2's `when` held on
