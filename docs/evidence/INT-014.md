## What the tests pin

- **Per-field, per-tenant**: every field gets its own AES-256-GCM DEK; the DEK
  is wrapped by the tenant's KEK; a field encrypted for tenant A fails
  authentication under tenant B (TamperError, not silence).
- **Tamper detection**: a flipped ciphertext byte, a bent nonce, or a changed
  AAD each raise TamperError (GCM tag verified on all three surfaces).
- **Rotation = rewrap**: after KEK rotation the wrapped DEK changes and the
  version bumps while **the ciphertext bytes are untouched** (asserted); a
  not-yet-rewrapped field still decrypts — rotation never orphans data ahead
  of the rewrap job.
- **Crypto-shred = hard delete**: destroying the tenant KEK makes every field
  CryptoShredError-unrecoverable while other tenants are untouched. On
  Transit, destroy is the explicit two-step (deletion_allowed → DELETE),
  proven live in the integration lane. This is the mechanism KVKK-7's hard
  delete and the DSAR delete flow (INT-037) will call.
- **File-KEK provider** (acceptance verbatim) keeps the unit lane
  docker-free with the identical cipher code path; the Transit provider's
  HTTP contract (version parsing from `vault:vN:`, missing-key → shred error,
  the destroy two-step) is additionally unit-covered over httpx.MockTransport
  so coverage does not depend on the integration lane.
