## Delivery semantics (honest statement)

Redis streams with consumer groups deliver **at least once** — a crash
between handling and XACK redelivers via XAUTOCLAIM. The bus therefore
provides exactly-once **side effects** on at-least-once **delivery**: the
handler runs behind an idempotency key (event id + handler name), so a
redelivered message finds the done marker and is acknowledged without
re-executing (test-pinned with a counting handler and a client wrapper whose
first XACK raises). Limits, stated plainly: the done marker lives 24 h, so a
redelivery delayed past that window would re-execute; a crash inside the
gap between the handler's side effect completing and the done-marker write
re-executes on redelivery (the handler itself must tolerate that residual
window or write its effect transactionally); and the guarantee is per
(event id, handler) — two handlers on the same stream each run once by
design. Retries are requeued onto a group-local retry stream because a
re-add onto the source stream would fan the failure out to every other
consumer group as a duplicate delivery.

## fakeredis coverage

fakeredis 2.37.1 implements the full command set the bus uses — XADD,
XREADGROUP, XACK, XPENDING, XAUTOCLAIM (3-element Redis-7 reply), XINFO
GROUPS, exclusive XRANGE — verified by probe before the tests were written,
so the entire lane is unit-lane fakeredis and **no test needed the
integration mark**; infra/docker-compose.dev.yml already pins redis:7.4-alpine
and needed no change. One behavioural finding: fakeredis's XINFO GROUPS
`lag` miscounts (2 for 3 undelivered entries; -1 on an empty stream), and on
real Redis `lag` goes nil after XDEL/trimming — so `record_lag` never reads
it, counting entries past `last-delivered-id` directly (exclusive XRANGE)
plus the pending count, which is exact on both implementations and
naturally excludes trimmed entries.

## Dependencies and inventory

No new dependencies: `redis` is already a runtime dependency of
intake-platform and `fakeredis[lua]` already sits in the dev group (INT-131).
No new persisted field concept (invariant 18): the bus transports the
INT-031 event payloads, which are id-shaped by schema; the DLQ carries the
same typed payload plus a closed reason code, and the publish boundary
re-validates every payload so nothing outside those schemas can enter a
stream.
