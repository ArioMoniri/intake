# Evidence — INT-093 · RED preemption path: stop ≤ 150 ms, e2e ≤ 300 ms (fake clocks)

## Acceptance (verbatim from docs/backlog/issues.yaml)

  measured on fake clock"

Tests: `tests/voice/test_red_preemption.py`. sec_row: **`triage`**
(docs/security/threat-model.md "## `triage` — deterministic RED/YELLOW only"). That row
names **"the preemption path"** among its assets, **"[T] manipulation … a missed RED
(patient safety, the highest-consequence failure in the product)"** among its threats,
**"preemption path tested"** and **"RED three axes with no default register/location"**
among its controls, **"preemption latency"** among its signals — and its Tests line already
says *"preemption timing with INT-093"*. This issue is that line.

Module: `services/voice-runtime/src/intake_voice_runtime/talker/red_path.py`.

## What this issue is, and what it deliberately is not

**No clinical content was authored.** Every rule id, script id and Turkish string in the
suite is synthetic (files/04 §7). The RED scripts themselves are *pre-positioned device
content* that INT-043 (`awaiting-human`, HB-C1) blocks, and this path never needs one: it
addresses a script **by id** and asserts the id travelled. `RedScript.tsx` was deliberately
not created — INT-259's design excluded it as needing its own goldens and CODEOWNER review.

**Nothing was re-implemented.** The Work queue's RED seal is files/12 §7.1 and INT-092
built it; a second seal here would be a second reading of one rule, and the two would
drift. `test_the_queue_seals_itself_and_the_path_does_not_re_seal` asserts the module
mentions neither. The two preempt gates are INT-091's and are called, not copied.

**The HMAC attestation of files/12 §5 is not here, and it has no issue.** See finding 1.

## The clock model, stated plainly

One **virtual monotonic clock** — `tests/voice/talker_harness.py::FakeClock`, milliseconds
— shared by every participant: the runtime, the transport and the device. It advances only
when every task is parked, so the whole suite runs in **zero wall time** and **no test
sleeps**. The two legs the server cannot observe are *charged*, not measured, and both
figures come from the blueprint rather than from what made an assertion pass:

| leg | charged | source |
|---|---|---|
| downlink one-way, data channel | **25 ms** | files/03 §4.6 inv. 4 — *"one downlink one-way (~10–25 ms)"*; the upper end is used |
| device output, local script start | **25 ms** | files/03 §4.6 inv. 4 / §4.5.1 — *"25 ms device output"* |
| jitter buffer | **not charged** | 165 ms is a **media** cost. The RED path does not use the media transport — that is the whole reason inv. 4 was rewritten |

So this is a **simulation of the arithmetic files/03 §4.6 invariant 4 writes down**, run
rather than believed. It is not a measurement of a phone; the on-hardware figure is
INT-095's `make live-smoke`, and no accuracy or performance claim is made anywhere outside
this file (CLAUDE.md invariant 20).

### (a) What was measured

Both stamps are read off that clock. `evaluated_at_ms` is the **rules-engine
determination** — files/02 §8.2 measures *"≤ 300 ms from rule evaluation"*, and the path
requires the caller to supply it: stamping `now()` at the moment Layer A noticed would
silently discount the Layer B hop from the very budget being policed.
`test_the_stop_is_measured_from_rule_evaluation_and_holds_the_budget` fires the RED a
virtual minute into the session, so a path measuring from zero reads wrong rather than
reading the same.

| figure | definition | measured | budget |
|---|---|---|---|
| **stop** | rule evaluation → the outbound audio path cancelled | **40.0 ms** (cancel charged 40 ms) | ≤ **150 ms** |
| **e2e** | rule evaluation → the pre-positioned script started on the device | **90.0 ms** = 40 + 25 + 25 | ≤ **300 ms** |
| **stop, worst case** | the stop charged its entire budget | **150.0 ms** | ≤ 150 ms |
| **e2e, worst case** | that stop **plus** the blueprint's worst-case transport | **200.0 ms** — 100 ms of margin | ≤ 300 ms |

`test_the_blueprint_worst_case_transport_still_fits_both_budgets` is the headline: charge
the stop its whole 150 ms and the trigger the blueprint's own worst case, and e2e still
lands at 200 ms with a third of the budget unspent. That margin is the point of
pre-positioning: the same RED down the audio path would not have had its clip's *first
sample scheduled* by 206 ms (§4.5.1), before the cancel that must precede it.

**RT-02 is run, not paraphrased.** files/04 §7: *"RED rule fires while the agent is
mid-sentence — playback cut ≤ 150 ms, RED script spoken, UI interrupt ≤ 300 ms."*
`test_rt02_a_red_mid_sentence_cuts_the_playback_it_found` starts 400 virtual ms of agent
speech, fires the RED 100 ms in, and asserts the playback landed in `interrupted` and not
in `completed` — the cut is **observed**, not asserted — with both budgets held.

**One honest limit, stated rather than hidden.** The stop measured here is the
**server-side** stop: rule evaluation to the moment the outbound audio path was cancelled.
The device's own flush of already-buffered audio (up to the 165 ms jitter buffer) is
patient-perceived and is **on-hardware evidence, not something a fake clock can assert**.
It belongs to INT-095. Claiming the 150 ms as patient-perceived from this suite would be
exactly the accuracy claim invariant 20 forbids.

### (b) What happens when a budget is missed

It **fails loudly and still delivers**, and the second half is the design decision.

Raising at the first breach was the obvious implementation and it is wrong: it would
abandon the patient in order to police a number, and the number exists for the patient.
So the path always runs to completion and then raises `RedPathViolation`, which carries
the whole `RedPreemptionOutcome` — every stamp, the script id, whether the clinician was
told. `RedViolation` has four members and each is raised the same way:

| violation | raised when |
|---|---|
| `STOP_BUDGET` | cancel completed more than 150 ms after rule evaluation |
| `E2E_BUDGET` | the script started more than 300 ms after rule evaluation |
| `SERVER_SIDE_SPEECH` | the RED result carried `speech_tr` (see below) |
| `SCRIPT_UNADDRESSABLE` | no pre-positioned script for this rule at this location |

Every one of those tests asserts **both** halves: the violation was raised **and**
`len(channel.published) == 1` and `len(clinic.notifications) == 1`. Mutation D — raise at
the breach instead of after the delivery — is caught by exactly those assertions.
`test_a_clean_delivery_raises_nothing` is the negative control that stops the whole class
being satisfied by a path that always raises.

`SCRIPT_UNADDRESSABLE` is the one that costs the patient something, and it is deliberate.
The script id is **resolved** from a `RedScriptIndex` supplied with the session's pinned
pack — never derived. A derived id (`f"{rule_id}.{location}"`) would compile, would look
right, and would address **the wrong words on the device** the moment the compiler's naming
rule and the runtime's guess diverged. So a missing entry stops the intake and tells the
clinician, publishes nothing, and raises. Mutation F (derive instead of resolve) is caught.
`MappingRedScriptIndex` is empty by default: an unwired session addresses nothing.

Metric: `preempt.red_latency_ms` moves `planned → live`, emitted from `red_path` on the
e2e figure. Only patient-facing registers observe it — a `DEFERRED_CLINICIAN` RED has no
patient-facing latency and a zero would flatter the p99 that pages (files/08 §5).
`voice.barge_in_stop_ms` was deliberately **not** reused for the stop leg: that series is
the *patient's* barge-in, and folding a second cause into it would make its ≤ 150 ms target
unreadable for both. files/08 §4 C names exactly one id for this path, so exactly one
family is emitted (CLAUDE.md invariant 13).

### (c) How a SILENT or DEFERRED_CLINICIAN RED is prevented from speaking

**First, structurally: nothing on this path can speak, in any register.** The controller's
constructor takes `{canceller, channel, clinic, scripts, clock}` — no `SpeechSynthesizer`,
no `ClipStore`, no `AudioSink`, no `SpeechRouter`. `PlaybackCanceller` has exactly one
member, `cancel`, which stops the media plane and carries nothing through it. So "SILENT
must not speak" is not a rule someone remembered; there is no expression this module could
write that would produce audio. That is CLAUDE.md invariant 22's first clause on this path
too: no numeral reaches a TTS model because nothing reaches one.

**Second, the register travels verbatim.** `register` and `location` come off the
`RulesTriageResult` — which already refuses a RED missing either (invariant 21, INT-031) —
and go onto the wire unchanged, so the device renders the register the clinician authored.
`test_a_silent_red_stops_and_renders_but_carries_its_register_verbatim` asserts the
published message is `SILENT` and that `synthesize`, `fetch` and `play` appear nowhere in
the media plane's call log.

**Third, the one remaining way a RED could have been spoken server-side is closed loudly.**
A `BackendResult` at `priority=preempt` whose `Presentation` carries `speech_tr` is a Work
asking the server to speak a RED. Invariant 21 says the words are pre-positioned, so that
string has no route — and a string with no route is dropped silently unless something
refuses it (invariant 17). It is `RedViolation.SERVER_SIDE_SPEECH`: the RED is still
delivered, the speech is still never spoken, and the defect is raised rather than absorbed.

**Fourth, the register table is total and has no default.** files/02 §5.3's binding
authoring rule — *"a default would be chosen once, by an engineer, for all future rules —
which is how the paediatric airway case gets an alarm"* — applies to the *delivery*
decision as much as to the pack. `REGISTER_DELIVERY` is a `Mapping[RedRegister,
RedDelivery]`, total over the enum, each row carrying the blueprint sentence it is:

| register | stops the intake | triggers the device | reaches the clinician |
|---|---|---|---|
| `ALERT` | yes | yes | yes |
| `CALM` | yes | yes | yes |
| `SILENT` | yes | yes | yes |
| `DEFERRED_CLINICIAN` | **no** | **no** | yes |

Two readings behind that table, both derived rather than chosen:

- **`SILENT` still stops and still renders.** *"Screen only … the guidance appears in the
  flow of the session"*, and *"No audio, ever"*. Stopping the agent's own audio is the only
  sound-affecting act the register admits and it can only produce **silence**, which is
  what the register asks for. The guidance still has to reach the patient — a safeguarding
  or crisis RED that renders nothing is the missed RED the `triage` threat row names.
- **`DEFERRED_CLINICIAN` does neither.** *"Patient screen unchanged. Finding routes to the
  clinician only … findings where patient-facing alarm has **no useful patient action**"* —
  and it is *"exactly what `device_functions=off` requires"* (files/02 §5.3; files/03
  §15b), where triage computes in shadow and the session runs to completion. Cutting the
  agent off mid-sentence for a finding with no patient action would be a patient-facing
  alarm with no action, which is the harm the register exists to prevent; and stopping the
  intake would be a device function in a mode where device functions are off.
  `test_a_deferred_clinician_red_leaves_the_session_running` pins it.

**Clinician notification has no false row**, so it is not a column: `notify_clinic: always`
on every RED (files/protocols/base.life_threat.yaml; files/04 §4.2).
`test_every_register_reaches_the_clinician` loops the enum.

`test_an_unmapped_register_raises_rather_than_defaulting` is the negative control: it
thins one row out of the table and asserts a `KeyError`. Without it,
`REGISTER_DELIVERY.get(register, ALERT_ROW)` would pass every other test in the class —
that is mutation G, and it is caught.

### (d) Proof the path touches no media transport

files/03 §4.6 invariant 4 asks for this specifically: *"the test changes too: it must
assert the RED path touches no media transport, not merely that the deadline was met."*
Three independent proofs, because each fails differently.

1. **It cannot name the audio path.** `test_the_module_imports_nothing_on_the_audio_path`
   AST-scans `red_path.py` for `talker.speech`, `talker.clips`, `SpeechRouter`,
   `SpeechSynthesizer`, `ClipStore`, `ClipCatalogue`, `AudioSink`;
   `test_the_module_names_no_method_that_moves_audio` scans every `ast.Attribute` for
   `play`, `synthesize`, `fetch`, `speak`, `text_for`. `cancel` is deliberately absent from
   that list — it *stops* the media plane, it does not carry anything through it.
2. **It is not handed one.** `test_the_controller_is_handed_no_media_port` pins the
   dataclass's init fields to exactly `{canceller, channel, clinic, scripts, clock}`. A port
   parameter is how a media path gets into a class; adding one fails here (mutation J).
3. **At runtime it calls nothing else.** The `MediaPlane` double records **every** call and
   also carries `synthesize` and `fetch`, which raise. So the proof is made against an
   object that *could* be misused rather than one that is missing the methods.
   `test_at_runtime_the_only_media_call_is_the_cancel` asserts `calls == ["cancel"]` and
   `played == []`.

And the case the invariant exists for: `test_a_red_renders_with_the_media_plane_already_gone`
makes `cancel` raise, and asserts the RED **still publishes and still starts on the device**,
with `media_plane_unreachable=True` recorded and **no violation**. A cancel that cannot run
means there was nothing playing to stop; that is a reason the RED renders, not a reason to
drop it.

**The wire carries identifiers and axes only**, which is also how INT-255's ON_SITE work
survives. `RedTriggerMessage.model_fields` is exactly `{kind, rule_id, register, location,
script_id}` — the 112 affordance's three carriers (`show_112`, `numbers`, the action code)
all live on `LocationAction`, which is in the pack **on the device**. The preemption path
cannot reintroduce the affordance because the message has nowhere to put one
(`test_the_wire_has_no_carrier_for_the_112_affordance`, mutation M), and an ON_SITE trigger
serialises with no `112` in it in any form. Its near-miss control is
`test_the_location_selects_the_script_and_nothing_else`: the same rule under REMOTE and
ON_SITE resolves two *different* pre-positioned scripts, so the ON_SITE assertion is about
the affordance and not about the message being empty.

**The two readings of one message are pinned to each other.** `apps/mobile/src/lib/livekit/
red.ts` is the only consumer, and a serialiser drifting from its decoder is how a RED
silently stops rendering. `test_the_message_serialises_to_exactly_the_keys_the_client_
destructures` reads the destructuring statement out of the client source and asserts the
server's `model_dump(by_alias=True)` keys equal it; `test_the_id_shape_is_the_client_id_shape`
reads the client's `ID_SHAPE` regex literal and asserts the server refuses the same four
malformed ids. Neither restates the client; both read it.

**Invariant 6.** The wire carries no `RuleFire.evidence` — *"which slot values satisfied the
rule"* is patient material. `RedNotification`'s field set is asserted exactly
(`{work_id, rule_ids, register, location, evaluated_at_ms, patient_facing}`); mutation N
adds an `evidence` field and is caught.

## Ordering: one deliberate rearrangement of files/03 §4.3

§4.3 says: *"On RED: cancel playback ≤ 150 ms, play the cached RED script, emit
`emergency_interrupt`, notify clinic if connected."* The path runs the clinician
notification **first**. `ClinicNotifier` has **no awaitable member** — the same structural
trick ADR-009 uses on `WorkSubmitter` — so running it first costs the stop nothing on the
clock, and it buys the one guarantee worth buying: a RED reaches a human even if the media
plane, the data channel and both budgets fail in the same instant. The ordering constraint
§4.6 inv. 4 actually *states* — *"cancelling the in-flight playback has to happen first"* —
is about the cancel relative to the **script**, and it is honoured.

## Idempotency

`test_the_same_work_id_triggers_the_device_exactly_once`: files/03 §4.6 invariant 6 and
files/12 §7.5 — a re-derived RED carries the same content-addressed `work_id`, so replay
is a no-op that returns the recorded outcome. `test_a_different_red_is_not_deduped_against_
the_first` is its control. Mutation E is caught.

   not a process-level readiness check.** `app.py` names three unwired bindings

   served at all (INT-043, HB-C1), so there is nothing to produce from.
