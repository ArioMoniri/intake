## What was built

Three new modules under `services/voice-runtime/src/intake_voice_runtime/talker/`, plus
the wiring in `session.py`.

### `red_path.py` (new) — the timed path

`RedPreemption.trigger(result, accepted_at_ms=…)` runs one authorised RED and returns a
`RedPreemptOutcome` carrying both measurements. It has exactly **two egress ports**, and
neither is media:

- `PlaybackStop` — a Protocol whose only member is `cancel()`. Deliberately narrower than
  `ports.AudioSink`, so the path is *statically* unable to play, synthesise or fetch a byte
  of audio. An `AudioSink` satisfies it structurally, which is how `TalkerSession` wires it
  with no adapter while the RED path still cannot reach `play`.
- `RedDataChannel` — `trigger(message)`. It carries the *trigger*, never the script.

Order is the blueprint's: files/03 §4.6 invariant 4 says *"cancelling the in-flight
playback has to happen first"*, so the stop is awaited, `stop_ms` is stamped, then the
trigger is sent and `script_start_ms` is stamped. Both are measured from the moment the
session **accepted** the result, not from the call.

`STOP_BUDGET_MS = 150.0` and `E2E_BUDGET_MS = 300.0` are the blueprint's own numbers, and
a test asserts they are.

**A late RED still fires.** `within_stop_budget` / `within_e2e_budget` are reported;
nothing withholds an emergency instruction for being slow. Refusals run the other way — an
unauthorised RED, or one whose pre-positioned script cannot be resolved, raises *before*
anything is cut off or sent. Every refusal, including the script resolution, is therefore
settled **before** the stop rather than between the stop and the send: a RED that cannot be
delivered must not cut the patient off for nothing, and all of it is pure computation with
no `await` in it, so it costs nothing on the clock. The three script refusals each assert
`stop.cancels == 0` as well as `channel.sent == []`.

### `red_script.py` (new) — the pre-positioned script, named rather than carried

`RedScriptRef` is an identity (`script_id`), a binding (`script_hash`), the two axes, and
the two affordance facts the device needs. **The runtime never holds the script's
Turkish.** Three invariants become structural because of that:

- **Invariant 10 (verbatim).** There is no string on this path to paraphrase and no code
  that could rewrite one. `script_hash` (sha256 over the compiled action object) refuses a
  bundled device copy that has drifted from the pack.
- **Invariant 22 (no numeral).** `script_ref_for_action()` sees the compiler's own action
  object and refuses a bare numeral in *any* Turkish carrier it holds (`action_tr`,
  `do_nots_tr`, `why_tr`, `ask_one_tr`). The ref it returns carries none of them. The
  `action_tr_ref` form carries no text at all — that text lives in `docs/legal/strings.yaml`
  under PolicyGuard with clinician sign-off — so there is nothing to walk and the hash
  covers the reference the device resolves.
- **Invariant 21 (ON_SITE).** `protocols.dsl.RedFlagAction` already refuses an `ON_SITE`
  action offering 112. `RedScriptRef` refuses it **again**, because *"absent, not
  de-emphasised"* is the one affordance rule that must not depend on a single validator.

`script_id_for()` derives the device's lookup key rather than minting one, for the same
reason `work_key` is derived (files/12 §7.5): the app bundle and the runtime compute it
from the same two facts, so they agree without a registry to keep in step. A ref whose
`script_id` is not the derived key is refused — a hand-written id resolves to nothing on
the bundle, which is a silent no-op at the worst possible moment.

### `orthography.py` (new) — `assert_no_numeral`, moved out of `speech.py`

The check is unchanged; it moved so that the RED path can use it **without acquiring a
route to a synthesiser**. `speech.py` imports and re-exports it, so every existing caller
(including `clips.py` and `tests/voice/test_clip_player.py`) is untouched. One
implementation, imported by both, is the only version of this that cannot drift.

### Changed

- `preemption.py` — one **optional** field, `Presentation.red_script: RedScriptRef | None`.
  Optional on purpose: making it required would have broken `tests/voice/test_work_queue.py`
  (a file this issue may not edit) and, more importantly, a non-RED result has no script.
  The **RED path** requires it and raises `RedScriptUnavailable` without it. The module
  docstring's claim that INT-093 owns the files/12 §5 HMAC attestor is corrected — see
  "Deliberately not built", below.
- `session.py` — `red_channel: RedDataChannel | None` wires a `RedPreemption`;
  `accept_result` stamps the clock at acceptance; `fire_preempts()` runs the pending REDs;
  `take_turn` calls it **before the insertion tick and before the next step is spoken**.
  That ordering *is* invariant 9's exception, and it is the only place in the turn where
  something does not wait for a safe window. `TurnOutcome.red_preempts` reports the count.
- `tests/voice/talker_harness.py` — one keyword-only `red_channel=None` pass-through on
  `build_session`. Purely additive; every existing caller is unchanged.

## The two numbers, and the fake-clock method

**No wall clock is read anywhere in this suite.** `FakeClock` is virtual monotonic time:
`sleep` parks a future on a heap and the driver advances the clock only when every task is
parked, so a measured latency is a property of the code under test rather than of the
machine running it. INT-264 is this repo's worked example of what a wall-clock latency
assertion costs in CI.

Each double charges its own virtual cost: `RecordingPlaybackStop(delay_ms=…)` for the stop
and `RecordingDataChannel(delay_ms=…)` for the downlink. The numbers below are what the
code under test measured on that clock, in zero wall time — they are **measurements of
this test configuration**, not properties of the product, and no figure here is a
performance claim about a real network (CLAUDE.md invariant 20).

| test | injected stop | injected channel | `stop_ms` | `script_start_ms` | budgets |
|---|---|---|---|---|---|
| `…stop_is_measured_and_within_the_150_ms_budget` | 40 ms | 25 ms | **40.0** | 65.0 | both met |
| `…end_to_end_script_start_is_measured_and_within_the_300_ms_budget` | 120 ms | 25 ms | **120.0** | **145.0** | both met |
| `…the_stop_happens_before_the_script_is_triggered` | 60 ms | 30 ms | 60.0 | 90.0 | stop strictly precedes trigger |
| `…a_slow_stop_breaks_the_budget_assertion` | 400 ms | 0 ms | **400.0** | 400.0 | stop budget **breached** |
| `…a_slow_data_channel_breaks_the_end_to_end_assertion` | 100 ms | 350 ms | 100.0 | **450.0** | stop met, e2e **breached** |
| `…the_budget_runs_from_acceptance_not_from_the_trigger_call` | 0 ms | 0 ms + 400 ms wait before the call | **400.0** | **400.0** | both **breached** |

### The measurement is real

Every green budget assertion goes through one helper, `_assert_within_budget(outcome)`.
Three tests drive an over-budget outcome through **that same helper** and assert it
**raises** `AssertionError` (`pytest.raises(AssertionError, match="playback stop took")`
and `…match="script start took"`). A timing test that would still pass with the timing code
deleted proves nothing; these controls are what make the six green rows above evidence.

`…the_budget_runs_from_acceptance_not_from_the_trigger_call` is the third control and the
sharpest: the clock is advanced 400 ms *between* acceptance and the trigger, with both
doubles at zero delay, and both budgets breach. A `stop_ms` that were hardcoded, or
measured from the call instead of from acceptance, fails it.

`…an_over_budget_red_still_fires` asserts the other direction: the 900 ms case still
cancels playback once and still sends exactly one trigger.

## The register × location matrix (CLAUDE.md invariant 21; files/02 §5.3)

"Preempt" is not one behaviour. `red_delivery(register, profile)` reads
`protocols.dsl.REGISTER_AUDIO` — files/02 §5.3's Audio column, already committed — and
adds the one fact that table does not carry: whether the patient's device presents anything
at all. All twelve cells are exercised by
`test_the_register_and_location_matrix_resolves_for_every_cell`.

| register | files/02 §5.3 Audio column | playback stopped | patient script triggered | derived from |
|---|---|---|---|---|
| `ALERT` | *"spoken with urgent prosody, alert sound"* | **yes** | yes | `REGISTER_AUDIO[ALERT].spoken` |
| `CALM` | *"spoken softly, no alert sound"* | **yes** | yes | `REGISTER_AUDIO[CALM].spoken` |
| `SILENT` | *"No audio, ever"* | **no** | yes, `audible=False` | `spoken=False` + *"the guidance appears in the flow of the session"* |
| `DEFERRED_CLINICIAN` | *"None"* | **no** | **no** | *"Patient screen unchanged. Finding routes to the clinician only."* |

**Why `SILENT` stops no playback.** files/02 §5.3 gives it *"Screen only. No headline, no
colour change, no takeover — the guidance appears in the flow of the session"* and *"No
audio, ever"*. Cutting the agent off mid-sentence is itself an audible event, and this is
the register for the room containing the perpetrator (`13 §13`), the C-SSRS positive and
the third-party-present session. The session continues; the guidance appears on screen.
This is a **reading of the two table cells together**, not a new clinical decision, and it
is stated here so a clinician reviewing this file can contradict it in one line if it is
wrong. The mechanism does not change either way — only the boolean does.

**Why `DEFERRED_CLINICIAN` does nothing on Layer A.** *"Patient screen unchanged"* means
there is nothing to send to the patient's device, and the data channel goes to the
patient's device. The clinician route, the visit-card state, the clinic inbox entry with
its SLA and the +30 minute follow-back are the **unconditional server-side effects** of
files/02 §5.3 (*"must fire from the server on the session record, not from a client that is
no longer running"*), which are not the Talker's to run. `RedPreemptOutcome` therefore
claims nothing about them.

| location | 112 affordance | staff notification | script kind |
|---|---|---|---|
| `REMOTE` | rendered (`show_112` from the compiled action) | as authored | `ACTION` |
| `ON_SITE` | **absent** — refused on the ref *and* on `protocols.dsl.RedFlagAction` | **automatic** (`notify_staff_immediate`) | `ACTION` |
| `UNKNOWN` | **not rendered** until the one question is answered | — | `LOCATION_QUESTION` |

`UNKNOWN` is modelled as a different *kind*, not a weaker action, because files/02 §5.3
Axis 3 says *"Ask exactly one question … and branch on the answer. Never guess"* — an action
with weaker content is how the guess gets made.

**Profile parity.** Under `typed` there is no audio port at all (ADR-010; invariant 19), so
no register is audible on it and nothing is ever cut off — asserted by
`test_the_typed_profile_has_no_audible_red_and_stops_no_playback`.

## "The RED path touches no media transport" — asserted structurally

files/03 §4.6 invariant 4's own words: *"the test changes too: it must assert the RED path
touches no media transport, not merely that the deadline was met."* Four assertions, three
of them static:

1. **Import closure** (`test_the_red_path_import_closure_contains_no_media_module`). Every
   `intake_voice_runtime` module statically reachable from `red_path` and `red_script` is
   enumerated by walking each file's AST, and the closure is asserted disjoint from
   `{talker.speech, talker.clips, talker.insertion, talker.session}`. This is what the
   `orthography.py` move exists to make true.
2. **Imported names** (`test_the_red_path_imports_no_media_name`). Neither module imports
   `AudioSink`, `ClipStore`, `ClipCatalogue`, `SpeechSynthesizer`, `SpeechRouter`,
   `SpokenSpeech` or `clip_id_for`.
3. **Called attributes** (`test_the_red_path_calls_no_synthesis_or_playback_method`).
   Neither module contains a call to `.play`, `.speak`, `.synthesize` or `.fetch`.
4. **Behavioural** (`test_a_red_through_a_wired_session_asks_the_sink_to_play_nothing`). A
   full RED through a wired `TalkerSession` leaves `sink.played`, `clip_store.served` and
   `synthesizer.requests` all empty, and sends exactly one data-channel trigger.

`test_the_script_ref_and_the_trigger_carry_no_patient_text` closes the last gap: the
serialised `RedTrigger` contains none of the action's Turkish. That is also why the trigger
is safe to count and time without invariant 6 becoming a question — it is ids and closed
enumerations only.

## Deliberately not built, and why

**The files/12 §5 HMAC attestor is not INT-093's, and `preemption.py` now says so.**
INT-091's docstring and evidence handed it to this issue. That was a mis-assignment and it
is corrected rather than silently inherited: files/12 §5's own import-boundary rule is that
*"no module under `extraction/`, `observers/` or `talker/` transitively imports the
attestor"*, and its signing key is fetched *"from OpenBao by the rules-engine subsystem
alone"*. It therefore cannot live in `talker/**` — the only tree this issue may write — and
it is not in this issue's acceptance. **It needs its own issue** against
`packages/protocols/triage`, covering: the HMAC-SHA256 over `(session_id, ek4, disposition,
sorted rule_ids, inputs_hash, protocol_hash, life_threat_version, engine_version,
issued_at, nonce, key_id)`; verification of session, `inputs_hash`, `protocol_hash`, a 5 s
`issued_at` window and nonce novelty; the import-boundary test; and the seven-way mutation
test (bare / well-formed / replayed / rule-swap / reordered / stale / nonce-reuse) with
`safety.forged_triage_total`. **Nothing here pretends to be it**, and nothing here is
weakened in its absence: both gates that can be built today refuse by default, and the
timed path runs both again before it interrupts anyone.

**No metric is emitted.** `preempt.red_latency_ms` is catalogued in
`observability/metrics_catalog.yaml` (files/08 §4) at `status: planned`. Emitting it needs a
declaration in `services/voice-runtime/src/intake_voice_runtime/metrics.py` and the
catalogue row flipped to `live` in the same change — and **both files are being edited
concurrently by another agent for INT-110**, so this issue emits nothing rather than an
uncatalogued series (CLAUDE.md invariant 13) or a conflicting edit. The measurement is on
`RedPreemptOutcome` and on `TalkerSession.red_outcomes`, which is what a caller records.
**Follow-up:** wire `preempt.red_latency_ms` to `RedPreemptOutcome.script_start_ms` once
