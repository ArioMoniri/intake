# INT-341: Press-opacity tokens

**Epic:** E08-mobile · **Phase:** P3 · **Sec-Row:** mobile · **GitHub:** #540
**Spec:** `docs/design/motion/motion-verification.md` §3 S-9, §2.2 (`press.*`) and §4 MOTION-12
(on branch `merge-305`, not yet on `main` when this was written). **Depends on:** INT-330 (merged, PR #553).

## Problem
- Pressables set their own pressed and disabled opacity as literals. On `main` there were
  10 such sites in 6 files, using three different values for the same event:
  - rows used 0.7;
  - buttons and segments used 0.85;
  - the two buttons in `Themed.tsx` dimmed to 0.5 when disabled, but the composer's
    icon-only send button dimmed to 0.4.
- S-9: the rejected P16 proposal would have set `pressRetentionOffset: 16`. React Native's
  default is `{top: 20, left: 20, right: 20, bottom: 30}`
  (`react-native/Libraries/Pressability/Pressability.js`), so 16 would shrink the
  retention area and cancel more presses under a tremor.

## Change
- `apps/mobile/src/lib/theme.ts` adds `motion.press = { opacity: 0.85, rowOpacity: 0.7, disabledOpacity: 0.5 }`,
  which is the §2.2 table minus `retentionOffset`. Its first runtime consumers land in this
  same change, per invariant 17.
- All 10 literal sites now read the tokens. Feedback is still the `pressed` style
  callback's plain opacity, with no `Animated` and no timing, so it stays instant.

  | Site | Before | After |
  |---|---|---|
  | `Themed.tsx` `PrimaryButton` | `disabled ? 0.5 : pressed ? 0.85 : 1` | `disabledOpacity` / `opacity` |
  | `Themed.tsx` `SecondaryButton` | `disabled ? 0.5 : pressed ? 0.85 : 1` | `disabledOpacity` / `opacity` |
  | `DialogueIntake.tsx` composer send | `empty ? 0.4 : pressed ? 0.85 : 1` | `disabledOpacity` (**0.4 → 0.5**) / `opacity` |
  | `DialogueIntake.tsx` speaking bubble (barge-in) | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `DialogueIntake.tsx` listening bubble | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `ListRow.tsx` | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `SectionPanel.tsx` strip | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `SectionPanel.tsx` confirm row | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `SwitchRow.tsx` | `pressed ? 0.7 : 1` | `rowOpacity` |
  | `Segmented.tsx` | `pressed ? 0.85 : 1` | `opacity` |

- No Pressable sets `pressRetentionOffset`, so the platform default applies.
- Two comments that named the old numbers ("the 0.5 opacity" and "0.4 opacity") now name
  the token role instead.

### The VisitCalendar normalisation (0.6 → 0.7) is not on `main`
The spec counts 13 sites, including `VisitCalendar.tsx:165,211` (pressed 0.6) and `:262`
(0.85). That component is not on `main`. It exists only on the unmerged branches
`origin/int-visits-calendar` and `origin/int-demo*` (commit 148a7dbd). There is nothing to
normalise here. The new guard scans the whole of `src/`, so when that branch is rebased onto
this one, its three sites fail
"every Pressable takes its pressed and disabled opacity from motion.press" until they read
`motion.press.rowOpacity` / `motion.press.opacity`. The normalisation is enforced for whenever
the component lands.

### Scope note: the static hairline
The issue's acceptance line says "no opacity literal remains in src". The spec's acceptance,
which is authoritative, says "no pressed or disabled opacity literal". One non-state opacity
remains: `Themed.tsx` `styles.hairline` `opacity: 0.9`, the divider's resting tone. It is
never switched by a press or a disabled flag. The guard lists it in `STATIC_OPACITY` in
`e2e/motion.spec.ts`, keyed by file and value, and that list may only shrink. Any other
fractional opacity outside `theme.ts` fails the guard.

## Tests (TDD)
- New file `apps/mobile/e2e/motion.spec.ts`, describe "MOTION-12 — press feedback comes from motion.press".
  Its helper header (`MOBILE`, `walk`, `Source`, `TREE`, `APP_SOURCE`) is byte-identical to
  INT-331's (PR #570, which also creates this file), so whichever merges second resolves by
  appending one describe block.
  - "every Pressable takes its pressed and disabled opacity from motion.press" checks three
    things:
    1. No fractional `opacity` or `activeOpacity` literal appears anywhere in the app source
       outside `src/lib/theme.ts`, except the static list. This covers ternaries,
       multi-line values, `pressed && { opacity: … }` and `TouchableOpacity`.
    2. Every state-switched opacity inside a `({ pressed }) =>` style callback reads
       `motion.press.*`, so routing a number through a local name also fails.
    3. It is not vacuous. The detectors are first run on five offending shapes and one clean
       one. The scan must find at least 10 sites across the six components. The disabled
       readers are pinned to the composer send and both `Themed` buttons.
  - "no Pressable narrows the platform's press-retention default": no app source sets
    `pressRetentionOffset`. Three samples cover the prop, an object key and a spread. A
    `hitSlop` sample checks that the detector does not match `hitSlop`.
- Added to `apps/mobile/src/lib/theme.test.ts`: "the disabled opacity stays distinguishable
  from the pressed opacity". It pins the reconciled values and requires:
  - `0 < disabledOpacity < rowOpacity`, and `disabledOpacity < opacity`;
  - both pressed values `< 1`.

  So a press is visible and never as dim as a disabled control.
