# INT-317 — previsit output store + hospital read-back

Epic E10-connectors · phase P1 · `sec_row: connectors` (docs/security/threat-model.md)
· legal `KVKK-12` · relates to INT-160 (the same disclosure, outbound).

Owner directive, verbatim:

> after the previsit is done write output version of json which is worked on in a sql in
> the data folder under intake and the acibadem side will then send a request there to get
> the previsit details of json for that patient with the same structure

## What this issue had to decide first

**Reversing the arrow changes which control is load-bearing.** INT-160 built the framework
for pushing clinical records to a hospital, and every gate on that path fires because *we*
decided to send: the consent check is a send-time gate the sender owns. Here the trigger is
the hospital's. Nothing in our process decides when the disclosure happens, so the whole of
invariant 4 has to live on the request itself — a consent scope checked per patient per
fetch, and an audit entry written before the answer. There was no existing gate to reuse.

**A hospital fetch is a share, and it is not the share the patient already gave.**
files/06 §2 makes `share` a parameterised family precisely so a share consent names its
recipient; the bare `share` id is not grantable. `share:previsit_note` is the patient
handing one note to one clinician through a link they can revoke inside 72 h. Handing the
whole finished previsit to a hospital information system that will keep it under its own
retention is a different disclosure to a different recipient, and answering the second with
a grant given for the first is the bundled consent §2 forbids. So the scope is
`share:previsit_output` — a second parameter of the same family, which needs no new text
file (a `share:<qualifier>` scope binds to the `share` family text) and no registry change.
A test asserts the dev-seeded note grant does **not** unlock it.

**The retention of the copy the hospital keeps is not ours to state, and it is not the
same question as the row's own retention.** Two separate answers were needed and only one
of them was available:

- *the row in our database* rides the files/06 §3 **record** clock, and that is a reading
  of the matrix rather than a new period. It is a projection of the note it derives from,
  in the same database, under the same tenant, reached by the same DSAR erasure and the
  same crypto-shred. A derived copy that outlived the record it derives from would be the
  invention here, not this. (`RET_PREVISIT_OUTPUT`, argued in `db/inventory.py`.)
- *the copy the hospital holds after a fetch* has no answer in this repository at all.
  files/06 §3 governs what INTAKE holds; in the hospital deployment the hospital is the
  controller of what it holds (`KvkkRole.PROCESSOR`, files/06 §1), so the period is a term
  of an agreement. It was **not invented**. `retention_ref` is a required field on every
  recipient row, the loader refuses a row without it, and the registry has zero rows.

**Where completion is, in the code that exists.** There is no session-completion route in
this slice; `sessions.status` is never advanced past `created` by the API. What actually
ends a previsit is the patient sending the note (files/02 §5.1 — sending is their call), so
that is where the output is produced. A draft save produces nothing, and a save that takes
the note back to draft revokes the share, which closes the read-back. This is recorded
rather than papered over: when a real completion event lands, the hook moves and the table
does not.

## Design decisions and why

**1. A table, not a second read of `notes`.** `notes.payload` is the working artefact — it
is rewritten in place on every save and its shape is the review screen's. The output is the
finished thing, and it carries three facts the note has nowhere to put: the
`schema_version` a receiver branches on (a first-class column, because a version you cannot
query is a version you cannot migrate on), the `completed_at` instant the previsit actually
ended, and a `payload_sha256` the receiver can dedupe on without decrypting anything.
`UNIQUE (tenant_id, session_id)` keeps the finished previsit singular; who read it is the
audit chain's job, not this table's.

**2. The hospital's patient number has no carrier anywhere.** It is a direct identifier, so
invariant 14 applies with no exception: it travels in the POST body (never a path or query
— the Doctor Link rule, asserted over the live route table), it is resolved through
`Tokenizer.pseudonym` against `patients.pseudonym`, it is echoed back into the response
from the *request* so the receiver can join, and no column of `previsit_outputs` holds it.
A malformed one is refused by the app-wide 422 handler, which strips `input`/`ctx`. Four
tests, one per surface.

`Tokenizer` grew one public property, `key_ids`. A pseudonym carries the generation it was
signed under, so a lookup *by identifier* has to try every configured key or a rotation
silently turns existing patients into unknown ones — a fail-closed 404 that looks exactly
like a patient we have never seen.

**3. Scope is read from the share and copied nowhere.** The stored document holds every
section; the serving path filters by `shares.scope_sections`. One home for what is shared,
which is why a re-scope needs no second row kept in step and why a fetch can never widen
what was sent. Same rule the Doctor Link view obeys.

**4. Invariant 1 is carried in the type, because the receiver is not us.**
`PreVisitOutput.triage` is a union discriminated on `source` with exactly two members: the
rules-engine result (rules-only by construction, already refusing a non-GREEN level naming
no fired rule) and an explicit `TriageNotEvaluated`. `LlmCandidateTriage` is deliberately
not a member. Neither is `None`: an omitted `triage` beside a list of candidate flags reads
as GREEN to any receiver that has ever seen a GREEN document, which is the same laundering
by a quieter route. This slice runs no rules engine on the note path, so the served document
says `not_evaluated` in as many words, and the writer does not fill the field in by guessing.

**5. Invariant 22, and what is deliberately absent.** `OutputMeasurement` binds magnitude
and unit into one object, so a receiver cannot pair them wrongly, and the magnitude rides
`clinical_schemas.common.JsonValue` — the shared carrier INT-309/ADR-029 owns. No second
encoding is defined here. `measurements` is empty today because the note sections are prose;
a magnitude parsed out of a line would be a number this system invented.

**6. The order of the gates is the disclosure policy.** Approved reader → tokenization key →
patient → **consent** → stored output → live share. Consent runs before the output lookup on
purpose: an unconsented caller must not be able to learn whether a previsit exists. "No
stored previsit", "never sent", "taken back to draft" and "share expired" all answer the
same 404 — the distinction is not the hospital's to learn.

## What is blocked, and what is not

**Not blocked:** the mechanism. Both halves ship, wired and tested.

**Blocked, three times over, and all three are the fail-closed state rather than gaps:**

1. `infra/previsit_output/recipients.yaml` holds **zero rows** — no DPA is executed for a
   read interface, no tier-3 approval registers a reader, and no retention clause exists to
   name. Every fetch answers 503 `previsit_output_recipient_unregistered`. **HB-A18**, and
   it is the inbound half of **HB-A15**'s pair.
2. `share:previsit_output` has **no docs/legal text and no seeded grant**. `docs/legal/` is
   empty (**HB-L27**), so `grant_consent` refuses every new grant and nothing can consent to
   this. The unit lane opens it by writing the same unbound row shape the dev fixture seeds,
   which is exactly what the guard will treat as stale the moment the `share` text lands.
3. **There is no machine principal in `services/api` at all** — **HB-A18**. The read-back
   reuses `require_admin`, the same door `notes.read_note`'s clinic-admin branch uses, and
   inherits its limit: it resolves through the two-account dev bearer today and INT-180's
   human OIDC console tomorrow, and Acıbadem's HBYS is neither. No scheme was invented.

## What the inbound side has to provide

Defined here as an interface rather than assumed, because `packages/connectors` and the
login/match path are another agent's:

> A patient row for a hospital-tenant patient must carry
> `Tokenizer.pseudonym(patient_number)` as its `patients.pseudonym`, under a key id in the
> same tokenizer key set this API is configured with.

That is the whole contract. It stores no identifier, needs no mapping table, and it is what
`tests/api/test_previsit_output.py::bind_patient_number` exercises.

## Cross-branch note

INT-309/ADR-029's tagged-string Decimal codec is **not on `main`** and therefore not on this
branch. `OutputMeasurement.magnitude` is typed `clinical_schemas.common.JsonValue`, the
shared alias the codec attaches to, so this document inherits the wire form with no edit
when that branch merges — and no second encoding was defined in the meantime. No Decimal
reaches the column today (`measurements` is always empty on the note path), so nothing has
lost its scale; the sequencing matters before a path that populates it lands.
