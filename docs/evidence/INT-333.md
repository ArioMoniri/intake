# INT-333 — Motion: RED contract — zero motion, first paint as a root layer never behind a navigator, no haptic

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** triage · **GitHub:** #532 · **Labels:** area:mobile, risk:clinical
**Spec:** `docs/design/motion/motion-verification.md` §4 MOTION-4, §3 S-1, S-5, S-6; ADR-033 §5
(PR #571, **Proposed**); files/02 §5.3; CLAUDE.md invariant 21.

## Acceptance (verbatim, docs/backlog/issues.yaml)
1. "every register × location × reduce-motion combination renders RED with 0 ms entrance, 0 ms delay and no loop; RED exit is 0 ms and no register auto-dismisses"
2. "ALERT and CALM paint first as a root layer above the navigators, never as a push or a modal; SILENT renders in flow; DEFERRED_CLINICIAN is invisible to the motion layer"
3. "ON_SITE never mounts a 112 control even transiently (invariant 21); no RED register permits a haptic"
4. "a guard pins the list of RED surface files and forbids any animation API, haptics, Modal or router call on their first-paint path"

## ADR-033 status and what this ships while it is Proposed
ADR-033 is not ratified. Each open question that touches this contract ships in the fail-closed
default the ADR records for it:
- **Q1** (root layer, owner): the ADR's meanwhile clause is "INT-333 builds the root-layer
  contract and no RED is ever drawn as a push or a modal". That is acceptance line 2, so this
  PR is that default and not a pre-emption of the answer.
- **Q2** (ALERT haptic, ClinicalAuthor): never. `RedMotion.haptic` is the literal type `false`.
- **Q3** (SILENT and screen readers): not decided here. The contract carries no announcement
  field; INT-135 wires accessibility.
- **Q4** (UNKNOWN and 112, ClinicalAuthor): withheld until the location question is answered.
  This is also files/02 §5.3's own action table ("112'yi ara … UNKNOWN: not rendered until the
  one question is answered"). `src/lib/livekit/red.ts` is **not** changed: its `show112` stays
  the pack's authorisation, clamped for ON_SITE, and `livekit/red.test.ts` › "keeps 112 under
  UNKNOWN" still passes. The motion contract decides *when* a 112 control may mount; the pack
  can narrow that and never widen it.
- **Q5** (orb scale): not touched.

## Problem
- No RED surface exists yet (INT-135 is `todo`), so nothing said how a RED moves, where it
  paints or what the rest of the screen does when it arrives. S-1 showed that a RED drawn as a
  native-stack push can wait behind an in-flight transition (react-native-screens'
  `setPushViewControllers` defers it), and an RN `Modal` is a UIKit presentation that animates
  and waits the same way.
- S-6: any "on a red event" hook that closes a sheet makes a visible change for a
  DEFERRED_CLINICIAN finding that must not reach the patient's screen.
- S-5: an UNKNOWN location that mounted 112 and then heard "I am in the hospital" would remove
  a 112 control the patient had already seen, which is the mount-then-hide that invariant 21's
  ON_SITE rule exists to prevent.
- Nothing pinned which files are on the RED path, so a future RED screen could import a fade,
  a haptic, a `Modal` or a router call with no test noticing.

## Change
- New pure module `apps/mobile/src/lib/motion/red.ts`. It imports only the RED types from
  `../livekit/red`.
  - `RED_REGISTERS` and `RED_LOCATIONS`: tuples typed against the schema unions.
  - `redPresentationMode(register)`: ALERT and CALM → `rootLayer`; SILENT → `inFlow`;
    DEFERRED_CLINICIAN → `none`.
  - `RedMotion`: every field is a literal type (`enterMs: 0`, `delayMs: 0`, `exitMs: 0`,
    `loop: false`, `flash: false`, `stagger: false`, `autoDismissMs: null`,
    `dismissByGesture: false`, `haptic: false`, actions on press with `feedbackMs: 0` and no
    long-press). A RED that moves does not compile.
  - `redAffordances(presentation, answer)`: DEFERRED_CLINICIAN and ON_SITE mount nothing;
    REMOTE mounts 112 when the pack authorises it; UNKNOWN mounts only the location question
    until it is answered, then 112 only on "not in hospital" with the pack's authorisation.
  - `redFirstPaint(presentation, { reduce })`: the mode, the motion, the yields and the
    first-frame affordances, decided synchronously from the presentation alone. The yields are
    keyed on the mode: `rootLayer` and `inFlow` snap transients, stop the ambient loop and close
    modals (the orb unmounts or goes to idle); `none` changes nothing.
- New `apps/mobile/e2e/redSurface.ts`: the detector for RED surface files (holds the contract,
  reads a presentation, handles the `red` event, or paints with the RED-reserved colour) and
  the first-paint scan (animation APIs and modules, haptics, `Modal` / `animationType`, router
  and navigation calls). The names it scans for are assembled from parts.
- `apps/mobile/e2e/motion.spec.ts`: a MOTION-4 block pinning the six files on the RED path today
  (`src/lib/livekit/{events,index,red,session,types}.ts` and `src/lib/motion/red.ts`). The pin
  is exact, so the RED UI's files (INT-135) are found and must be named, which puts them under
  the same scan. It also holds that `session.ts`'s `handleData` decodes, resolves and emits in
  one synchronous pass.
- Nothing else changes: no component, route, token or dependency. `session.test.ts` › "renders
  with the media plane torn down" is untouched and green.

## Not in this PR
- **The RED UI** (the root layer, its accessibility wiring, the re-entry route with
  `{ animation: "none", gestureEnabled: false, fullScreenGestureEnabled: false,
  statusBarAnimation: "none" }`) is INT-135, which consumes `redFirstPaint` and adds its files
  to the pinned list. No route option is added here without a route to consume it (invariant 17).
- **Device measurement** (event to first RED frame, fired mid-push and mid-pop, and during a
  root-stack transition) belongs to INT-135's DoD, where the UI lands (S-1 step 3).
- **The arbiter** (INT-334) consumes `RedYield`.

## Invariants
- **21**: ON_SITE never mounts 112, not even for a frame; UNKNOWN never mounts one it might have
  to remove. The RED path touches no media transport (the handler scan).
- **9**: the RED path is not awaited on the arbiter, audio or navigation.
- **17**: no token, no route option and no field without a consumer or a test that reads it.
- **8**: tests added, none removed.
- **5**: no copy changed.
