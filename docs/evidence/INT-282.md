# Evidence — INT-282 · the HBYS base layer, and branching on the answers

Tests: `apps/mobile/src/lib/intake/baseLayer.test.ts` (55), plus the INT-256 file it
extends, `apps/mobile/src/lib/intake/history.test.ts`. sec_row: `intake-typed`
(docs/security/threat-model.md "## `intake-typed` — the typed parity path"). That row's
asset is *"typed session content, the same clinical state machine minus audio"*, and its
threat *"[S/T] prompt injection by typed text"* is answered here the way the typed pack
always answers it: the pack is a committed data structure, every gate is a
`{questionId, includesAny}` literal that JSON round-trips, and no patient string is ever
evaluated. INT-282 adds one thing to that row rather than only inheriting it — a
`text_only` class, so a step whose answer is a NUMBER cannot reach a speech path at all.

## What was NOT authored, stated before anything else

**No clinical content.** No threshold, no cut-off, no red-flag level, no age band, no
dose, no "this answer is concerning". Every gate this issue adds turns on **structure** —
did the patient say yes, how long has it been, which relative — and a test asserts the
gate set is exactly the declared one, so a gate that encoded significance would have to be
declared in a table a reviewer reads.

Three specific refusals, each with its owner:

1. **No anchor text for the pain score.** The owner's schema gives `4229_LS` an option
   list of zero to ten and no anchors. Writing *"sıfır ağrı yok, on dayanabileceğiniz en
   şiddetli ağrı"* would be authoring the semantics of a self-report instrument, which is
   the physician of record's (INT-043 → INT-044..051, **HB-C1**). The scale is asked
   without anchors and nothing reads it.
2. **No claim that any of this is validated.** The schema's option lists are one vendor's
   vocabulary. The file header says so, the issue's own acceptance says so, and no string
   anywhere calls a list an instrument (invariant 20).
3. **No 04 §5 note field invented for anthropometry.** `PreVisitNote` has `chief_complaint`,
   `hpi`, `ros_pertinent`, `pmh`, `medications`, `allergies`, `family_social`, `screening`,
   `imported_objective` … and **no vitals or anthropometry field at all**, while 02 §2
   promises "vitals entry (manual/HealthKit/Health Connect)" in the detailed column. Height
   and weight therefore render into a **mobile** section id, `measurements`, exactly as
   `device_health` and `deferred` already do — not into an 04 §5 key that no schema owner
   authored. **This is a real gap and it is the note schema's owner's to close** (files/04
   §5; the mapper is INT-084).

### Family history takes the schema's own shape

INT-256 had `fh_who` → one free-text `fh_detail`. The schema keeps **four** relatives apart
(anne · baba · erkek kardeş · kız kardeş) and asks the **same five conditions** of each, so
`fh_who` lost its undifferentiated `sibling` option and gained `brother` and `sister`, and
each named relative now opens its own checklist. `fh_detail` survives, narrowed to the
relatives the schema does not enumerate (child, grandparent, other) — a checklist and a
free-text field asking the same thing would be one question too many.

**The note attributes the condition to the relative.** The line reads
`Annede: Şeker hastalığı` under `family_social`, and a test asserts the string appears in
no other section — in particular not in `pmh`, which is the patient's own history. That
test is the one that would catch the failure mode the acceptance names.

### Invariant 22, three mechanisms rather than a convention

1. **`kind: "measure"`** — a stepper between authored bounds, no keyboard, no parser. The
   bounds are control bounds and the file says so: nothing reads them and nothing outside
   them is "abnormal". The control opens at a start value which is **not committed**: the
   CTA is disabled until the patient moves it, so tapping through cannot record a number.
2. **`IntakeOption.inline`** — the pain score's labels are the Turkish words `Sıfır … On`
   and the numerals live only as an inline render **on the same option object**. That is
   what makes invariant 22's *"a matching `inline` render on the same `work_id`"* true by
   construction here, and it is the same argument `talker/preemption.py` makes on the
   spoken side. The existing "no numeral in any pack-facing string" tests were not
   weakened to accommodate a scale — they still pass unchanged, because no numeral entered
   the catalogue.
3. **`delivery: "text_only"`** — files/13 §13's own class, whose §9.5 compiler check makes
   "nothing sensitive can be accidentally spoken" a build-time fact. A numeral-bearing step
   declares it, `spokenPack` drops it before the dialogue lane is built, and
   `toQuestionSpecs` refuses it with a type predicate. So *"no numeral reaches any TTS
   model"* holds structurally at three layers, and the numeral questions are asked in the
   typed lane where the guarded controls are.

The zero blood group is written `Sıfır Rh pozitif`, not `0 Rh pozitif`, for the same
reason: invariant 22 expands a digit to Turkish orthography rather than letting one into a
string a voice profile could one day read.

## Half 2 — the branching the owner widened the issue for

### The worked example: one earlier answer, two different flows

`duration` now has two mutually exclusive follow-ups, in **every** department pack:

- `duration = today` → **`onset_today_when`** ("Bugün ne zaman başladı?")
- `duration = week | month` → **`duration_course`** ("Başladığından bu yana nasıl gidiyor?")

so the asked set differs in **both directions** and neither flow is a prefix of the other.
With the duration unanswered, neither is on the frontier — a gate opens only on TRUE.

Both are structural: a clock question and the patient's own account of change, the
dimension `neuro_course` and `derm_course` already ask. Neither grades anything.

### The mode filter is the depth lever, and no new mechanism was added

02 §2 already existed and INT-256 already used it. INT-282 points it at the department
packs:

- the seven level-two department follow-ups (`radiation_side`, `breath_lying`,
  `neuro_head_same`, `ent_swallow`, `ortho_spread_feel`, `derm_itch_sleep`,
  `gastro_bowel_relief`) declare `modes: ["detayli"]`, so **Hızlı asks one level of
  follow-up and Detaylı asks two**;
- `packForVisit` now filters the department dimensions by profile, which it did not before
  — it filtered only the composed blocks;
- the whole base layer is `modes: ["detayli"]`, because 02 §2 puts "PMH/FH/SH deltas" and
  "vitals entry" in the detailed column and leaves the fast column at meds/allergies
  confirm.

Hızlı is therefore strictly shorter than Detaylı in every branch **and still branches**: a
pain complaint and a breathlessness complaint ask different questions in Hızlı too. Short,
not flat.

### The base layer branches on its own answers

`smoking = former` → when did you stop (and a never-smoker is never asked);
`injury_history = yes` → the detail; `pain_present = no` → no score;
`fh_who ⊇ mother` → the mother's checklist and no other relative's.

## Half 2b — the mobile `ask_if` against the INT-081 engine

**They agree on the load-bearing rule.** `docs/evidence/INT-081.md` records that *"a gate
opens only on TRUE, so while n is `ASKED_PENDING` its value is Unknown and the step gated
on it is not on the frontier"*. Mobile's `askIfMet` returns `false` for an unanswered
gating question, so an undecided gate is shut on both sides. A test states it in the
mobile file's own words.

**One genuine disagreement, and it is worth more than the code.** The two layers use
*different* Unknown semantics for **completeness**, not for gating:

- the engine's `must_ask_coverage` counts as *obliged* the `must_ask` steps whose gate is
  **TRUE or UNKNOWN** — an undecidable gate is exactly the case where the question still
  has to be put;
- mobile's `missingQuestions` is `applicableQuestions(...)` minus the answered, and
  `applicableQuestions` keeps only gate-TRUE steps. A question whose gate is still Unknown
  is *"skipped, not missing"* — its own comment says so.

So on a checkpointed session (02 §34, "Sıranız geldi" — which 02 §2 calls **the most common
way a detailed-mode session ends**) the mobile `eksik` list **under-reports** relative to
the engine: a step behind an unanswered gate is invisible, where the engine would count it
obliged-and-uncovered. Today the two never meet — mobile drives a dev-tier fixture pack and
the engine drives compiled packs — so this is not a live defect. It becomes one the moment
INT-096 replaces these packs with compiled ones and both definitions describe the same
session. **It is not mine to resolve**: picking which definition wins decides what a
clinician is told is missing from a partial note, and that is a note-semantics decision
(files/13 §9.4, files/04 §5). Flagged here, and to the parent, rather than silently
reconciled in a mobile fixture.
