# Evidence: INT-561 · Every registry component's licence is verified from its raw LICENSE

**Epic:** E12-admin · **Phase:** P1 · **Sec-Row:** monitoring-contract · **GitHub:** #949 ·
**Depends on:** INT-183, INT-243

## Problem

Owner, 17 Oct 2026 ("solve these"): many rows of the admin console's operability registry page
show **Lisans doğrulandı = yok**. Invariant 19 says every model is open-weights, commercially
usable, and licence-verified from the raw LICENSE blob, never from a badge or a card tag, and the
verification is recorded with `licence_verified_at`.

Acceptance, verbatim (docs/backlog/issues.yaml INT-561):

- A licence-auditor pass fetches each component's raw LICENSE (pinned revision/commit for models:
  model_id@revision; image digest or source tag for services), records the URL, sha256 of the
  blob, SPDX id, commercial-use verdict and licence_verified_at in the model/service registry.
- A component whose raw licence cannot be found or is not commercially usable is marked so (and
  blocks only if the deployed synthetic stack needs it), never shown as verified.
- Tests pin every registry row to a recorded verification; a row without one fails.

## Investigation (main `ab9b8819`)

1. **The page already reads the field.** The ops tile behind the column
   (`intake_api.admin.ops_console._models_tile`) projects `licence_verified_at` from each
   `observability/registry.yaml` row through the INT-183 loader. `apps/admin-web/src/ops/console.tsx`
   renders `row.licenceVerifiedAt ?? c.none`, which is "yok". So the fix is data, plus a type rule
   that keeps a date out of that column for a licence that is unread or unusable.
2. **16 of 28 rows had no `licence_verified_at`:** postgres, redis, hapi, openbao, api, probes,
   metrics, learning, voice-runtime, edge-tls, backups, ci-runners, qwen3.5-9b, whisper-tr-medical,
   freya-tts and deid-tr-ner-v1. The other 12 carried a URL and a sha256 but no SPDX id and no
   verdict, so "verified" did not say whether commercial use is allowed.
3. **What the rows run.** Pins were read from the repository, never assumed:
   - images: `infra/docker-compose.dev.yml`, `infra/staging/compose.yaml` (digest-pinned) and
     `infra/ci/aws-runner/runner.conf` (`RUNNER_VERSION=2.337.0`);
   - image versions: the synthetic host's digest-pinned images, read from their image config on
     registry-1.docker.io: pgvector `PG_VERSION=16.15-1.pgdg13+2`, redis
     `REDIS_VERSION=7.4.11`, openbao revision label `63a65e6b`, caddy
     `CADDY_VERSION=v2.11.4`;
   - tags: each resolved to its commit through the GitHub API, with annotated tags dereferenced;
   - model revisions: resolved to their full 40-hex form through the Hugging Face API.
4. **voice-runtime has no LiveKit dependency at this commit.** `services/voice-runtime/pyproject.toml`
   lists none. Its `license` line names LiveKit Agents and `livekit/turn-detector` as planned
   (files/03 §4.9.1 row 6 and §4.9.2(d)), so the turn-detector blob was read at its Hugging Face
   head, and the row's verdict rests on it.

## The rule applied

- **A blob or nothing.** Every licence was read from a raw file:
  `raw.githubusercontent.com/<owner>/<repo>/<40-hex commit>/<path>`, or
  `huggingface.co/<repo>/raw/<40-hex revision>/<path>`. The fetch used `curl -sSL`, and the
  sha256 is of the bytes as served. The one exception is our own repository, which is private:
  it was read through the authenticated GitHub contents API (`Accept: application/vnd.github.raw`).
  Its sha256 equals the working-tree `LICENSE`. No verdict here comes from a card tag, a badge,
  GitHub's licence detection or an image's `org.opencontainers.image.licenses` label.
- **`licence_commercial_use`:**
  - `yes`: commercial use is permitted, with no restriction beyond notices. Copyleft (AGPL, GPL,
    MPL) is `yes`, because it binds distribution and modification, not use; each note records
    why it is not triggered here.
  - `conditional`: commercial use is permitted under a stated restriction on how the software
    is used. The restriction is in `licence_condition`.
  - `no`: the blob forbids commercial use.
  - `blob_not_found`: there is no raw licence at the pin. Such a row has no hash, its SPDX is
    `NOASSERTION`, its note says where the search was made, and it never has
    `licence_verified_at`.
- **Several blobs in one row.** Where a row runs several projects, the structured fields carry
  the blob that decides the verdict, which is the most restrictive one. `licence_note` names the
  others with their URL and sha256 (see "Other blobs read").
- **Weights with no LICENSE of their own** follow the INT-243 VoxCPM2 precedent. The grant is the
  vendor's source repository at the code pin that serves the weights, and only when nothing in
  that vendor's own statements contradicts it. freya-tts meets this test. whisper-tr-medical does
  not: its card says apache-2.0 and its authors' source repository says MIT.
- **`licence_checked_at`** is the UTC instant of the fetch (a 404 is a fetch too).
  `licence_verified_at` is the UTC date the blob was verified. For the 12 rows verified before
  this issue it keeps its original date, because the re-read was byte-identical. The two
  corrected hashes below are the exception.

## Findings

1. **Two recorded hashes could not be reproduced.** INT-203 recorded the sha256 of Traefik's and
   CrowdSec's MIT text with the final newline stripped. That is what `$(curl …)` hands to
   `sha256sum`. The bytes as served hash differently:

   | Row | Recorded hash | Real hash | Bytes | git blob |
   |---|---|---|---|---|
   | edge-ingress | `4785e89f…` | `c33e2934…` | 1110 | `50d2fa2c` |
   | edge-crowdsec | `b0d4afcd…` | `198fa694…` | 1070 | `de4dbbfb` |

   Both are corrected. `licence_verified_at` moves to 2026-10-16, the date the reproducible hash
   was taken. A test pins both values.
2. **whisper-tr-medical has no licence for its weights.**
   - The weights repo has no LICENSE at the pin or at main. Both raw paths answer 404, and the
     file list confirms it.
   - The card tag (apache-2.0) disagrees with the authors' code repository, whose LICENSE is MIT.
   - That repository's data recipe lists ISSAI Turkish "under the source's own terms", and that
     source dominates the training mix.
   - The row stays `UNVERIFIED`, with verdict `blob_not_found`.
   - It runs on the team GPU box (dev/synthetic only) and is the ASR fallback. Whether the
     synthetic stack needs it is INT-560's severity derivation (`HostInventory.needed()`); this
     issue does not touch that.
   - To close it, the authors add a LICENSE to the weights repo, or counsel accepts another basis.
3. **deid-tr-ner-v1 cannot be verified as it stands.**
   - The base model is MIT, verified from `dbmdz/berts`.
   - The training dataset `BTX24/turkish-privacy-pii-ner` has no LICENSE file at the
     trained-on revision. Only its card tag and a README section say CC BY 4.0.
   - INT-015 recorded CC-BY-4.0 from that card. Under files/03 §4.9.0 rule 3 a card is not a
     blob, so the row now reads `UNVERIFIED …` with verdict `blob_not_found`. It is advisory,
     not blocking.
   - To close it, the dataset author adds a LICENSE, or counsel accepts the README statement.
     The data is machine-generated, so no data subject is involved.
4. **freya-tts's licence line named the wrong pin.** It said "code LICENSE blob verified @d124e07",
   but d124e07 is the weights revision, and the weights repo has no LICENSE (404). The blob that
   grants the licence is the vendor's source repo at the code pin `146d36c`, and the line now says
   so. Its MODEL_CARD.md at the same commit says the small model's weights are released under
   Apache-2.0, and that FreyaTTS-large is not.
5. **`livekit/turn-detector` can be withdrawn at will.** Section 8 lets either party end the
   licence "on immediate written notice". This is a second reason, besides framework lock-in,
   that the files/03 §4.9.2(d) exit (Silero VAD with an adaptive `min_silence_duration`) must
