## 2. The finding that changed the shape of the work

The issue is written as *"invariant 3's memory half is **untested**"*. It is worse than
that, and saying so is the first honest output of this issue:

> **`mlock` is not called anywhere in this repository.** The only occurrences of the
> word before this change were four docstrings and one CLAUDE.md line. The runtime's
> lane frames — `services/voice-runtime/src/intake_voice_runtime/observers/buffer.py`,
> `Frame.samples` — are a plain `bytearray`: pageable, dumpable, readable through
> `/proc/<pid>/mem`. Invariant 3's *mlocked* clause was **unimplemented**, not merely
> unasserted, and `RLIMIT_CORE` and `prctl(PR_SET_DUMPABLE)` were absent too.

So there was nothing to point `/proc/self/smaps` at. INT-278 therefore had to build the
mechanism before it could prove anything about it: `voice_clips.locked_buffer` and
`voice_clips.process_hardening`, each with the control the acceptance demands. What it
does **not** do is wire that mechanism into the voice runtime — `services/**` is outside
this change's file ownership. That gap is stated in §7, in ADR-025, and in the new
suite's own module docstring, so nothing here reads as a guarantee the product does not
have.

## 3. Environment, read before the tests were designed

The acceptance warns that a container which discards cores by default would make a naive
core test pass for the wrong reason. Measured on this runner before anything was written:

| reading | value | consequence |
|---|---|---|
| `ulimit -c` (soft / hard) | `0` / `unlimited` | the control **can** raise the limit |
| `/proc/sys/kernel/core_pattern` | `core` | a core lands in the crashing process's cwd, not in a pipe |
| `/proc/sys/kernel/core_uses_pid` | `0` | the file is named exactly `core` |
| `/proc/sys/kernel/yama/ptrace_scope` | **absent** (no Yama LSM) | invariant 28's sysctl half cannot be asserted here |
| `/proc/swaps` | empty | no swap device; `Swap: 0 kB` per region is still asserted |
| `CapEff` | includes `cap_ipc_lock`, `cap_sys_ptrace` | `mlock` works; the ptrace tracer must **drop** capabilities or it proves only that root is root |
| `ulimit -l` | 8192 kB | ample for a 60 s window (1.92 MB at 16 kHz mono s16) |

`core_dump_environment()` reads the first two back at run time, and
`test_the_environment_can_run_the_control_or_says_exactly_why` asserts the reported
reason against a fresh read of `/proc` — so the escape hatch cannot be taken falsely on a
runner where the control genuinely cannot run.

### 4.2 Red run — the mechanism exists, three properties still fail

The second red is the useful one: with `LockedBuffer` and `harden_process` written but
the child programs still naive, three assertions failed, and every one of them was a real
defect in the proof rather than in the code under test.

```
$ UV_NO_SYNC=1 uv run --no-sync pytest tests/voice/test_audio_memory_hygiene.py -q -o addopts=""
FAILED tests/voice/test_audio_memory_hygiene.py::TestCoreDumpsAreProvedByCrashing::test_the_locked_region_is_excluded_even_when_a_core_is_written
FAILED tests/voice/test_audio_memory_hygiene.py::TestTheCrashReportPathIsClosed::test_a_report_raised_over_a_live_buffer_carries_none_of_it
FAILED tests/voice/test_audio_memory_hygiene.py::TestPtraceIsRefused::test_an_unprotected_child_hands_the_marker_over
3 failed, 25 passed in 11.94s
exit code 1
```

What each red taught, and what changed:

1. **The core still held the marker.** Not because `MADV_DONTDUMP` failed but because
   the child filled the region with `SYNTHETIC_MARKER * n`, leaving *two* 256 KB copies
   of the marker in ordinary heap (the intermediate and the slice) that landed in the
   core regardless. Measured: 13798 occurrences in both the locked and the unprotected
   build — identical, i.e. the search was measuring the fill, not the buffer. The child
   now fills in 38-byte steps from the module constant, and the counts separate cleanly:
   **6900** occurrences for an ordinary `bytearray`, **2** for the locked region (the
   marker's own constant and the compiled module that carries it). The assertion is now
   a count with a ceiling, and the docstring says why it is not zero.
2. **The crash report still carried the marker** — in the exception *message*,
   `logentry.params` and the exception `value`, because `scrub_event` puts free text
   through `redact_text`, which targets identifiers (TC Kimlik, phone, IBAN) and not
   arbitrary content. The five slots the SDK fills *mechanically* — frame locals,
   request body, `extra`, `tags`, breadcrumb data — are all closed. The test now asserts
   those five, and the residual is reported as a finding in §7 rather than asserted as
   acceptable.
3. **The unprotected ptrace control was denied too** (`mem_errno 13`), which would have
   made the hardened refusal meaningless. Cause: `cap_ptrace_access_check` compares the
   tracer's **permitted** set on `PTRACE_ATTACH` but its **effective** set on
   `/proc/<pid>/mem`, and the tracee regained full capabilities through `execve` as
   uid 0. The tracee now drops every capability it inherited, which is also what
   invariant 28 requires of the workload; both probes then separate cleanly.

## 6. Row by row: the four files/10 §3 invariants

| files/10 §9.1 row | property | proved? | how | the control that makes it real |
|---|---|---|---|---|
| **17 · `audio_no_swap_guard`** | *`smaps` `Locked:` == region size; no swapped page* | **yes** | `LockedBuffer` allocates a page-aligned `mmap(MAP_PRIVATE\|MAP_ANONYMOUS)`, `mlock`s it and reads `/proc/self/smaps` back; tests assert `Locked:` non-zero, `Locked == capacity`, `Swap == 0`, and the `lo` / `dd` VmFlags | **two.** An ordinary unlocked mapping reports `Locked: 0 kB` and no `lo` flag. And the one the acceptance names: half a region is `mlock`ed, **the call returns 0**, and `smaps` shows 131072 of 262144 bytes locked — a partial lock and a full one are indistinguishable from the return value and distinguishable from `smaps` |
| **16 · `audio_no_core_guard`** | *real crash leaves no core; `WCOREDUMP` false* | **yes** | a forked child sets `RLIMIT_CORE=(0,0)` and `PR_SET_DUMPABLE=0`, fills a locked region with the synthetic marker and calls `os.abort()`; the test asserts `WTERMSIG == SIGABRT`, `WCOREDUMP == 0`, **no file at all** in the child's cwd, and no marker in any file | **three.** (a) the same child with the limit **raised** must produce a core — it does, `WCOREDUMP` true; (b) an *ordinary* `bytearray` in that child leaves **6900** markers in the core, so the byte search is proved to work before it is used as a negative; (c) the locked build's core carries **2** (the module constant and its `.pyc`), i.e. the region is absent. The environment check refuses to let (a) pass silently on a host that discards cores |
| **19 · `audio_no_telemetry_guard`** | *no bytes-like value > 1 KB in a crash-report payload; `include_local_variables=False`* | **yes, at the handler** | the handler is identified by name — `intake_platform.errors.setup_error_reporting`, the only `sentry_sdk` importer under `packages/` or `services/`, asserted by an AST scan that fails if a second appears. Driving it with an injected SDK asserts `include_local_variables=False`, `before_send is scrub_event`, `attach_stacktrace=False`, `max_request_body_size="never"`. A report built from a live locked buffer in the five slots an SDK fills on its own (frame locals, request body, `extra`, `tags`, breadcrumb data) comes back with no marker and no value over 1 KB | the same event **unscrubbed** still carries the marker and a value over 1 KB. The half files/10 runs *"against a local GlitchTip"* is a compose-tier integration and is **not** run here (no Docker daemon in this container); what is proved is the in-process property, which is what this acceptance asks for |
| **28 · `process_hardening_guard`** | *ptrace refused; `/proc/pid/mem` closed* | **the process half, yes; the container half, no** | `harden_process()` sets `PR_SET_DUMPABLE=0` and reads it back. A tracer that has dropped its effective capabilities gets `EPERM` on `PTRACE_ATTACH` and `EACCES` on `/proc/<pid>/mem`, and finds no marker | an **unprotected** child of the same tracer permits attach (`errno 0`), opens `/proc/<pid>/mem` and reads the marker straight out — which is exactly files/10 §3's own sentence that without this control the buffer is readable *"regardless of every control above"*, now an executable fact rather than a warning. The container/node clauses (non-root, `no-new-privileges`, `CAP_SYS_PTRACE` dropped, `ptrace_scope=1`) are **not** proved — see §7 |

**Platform dependence, as the acceptance asks it be stated.** Every proof above reads
`/proc`, `prctl` or `RLIMIT_CORE`. All three are Linux interfaces. CI runs
`ubuntu-latest` and the production workers are Linux, so this is where the assertions
hold; `TestThePlatformIsStated` asserts `sys.platform == "linux"` rather than leaving it
as a comment, and both new modules refuse to operate elsewhere with a message that says
the controls are not in force there either. `kernel.yama.ptrace_scope` is a Linux
Security Module this container does not carry at all: `yama_ptrace_scope()` returns
`None` (not `0`, which would read as a setting somebody chose), and the test asserts that
against the file's absence.

## 7. What is still not true, and who owns it

None of these is a weakened assertion; each is a gap this change could not close from
inside its file ownership, recorded so it is not mistaken for coverage.

1. **The runtime does not use any of this.** `observers/buffer.py`'s `Frame.samples` is
   still a `bytearray`, and no worker entry point calls `harden_process()`. The
   mechanism is proved; the product is not hardened until the wiring lands.
   `services/**` is outside this change. **Needs a follow-up issue**, and it is the one
   that actually makes invariant 3 true.
2. **The two new modules live in the wrong package.** `packages/voice-clips` is the
   build-time clip cache and its own header says patient audio must not come near it.
   The modules import nothing from `voice_clips`, are re-exported by nothing, and move
   by a rename; their destination is `packages/intake_platform` (process hardening) and
   `services/voice-runtime/.../observers/` (the frame allocation). Recorded as a debt
   with a named payer in **ADR-025**.
3. **Invariant 28's container half is unasserted and unimplemented.** `infra/` declares
   no `cap_drop`, no `security_opt: no-new-privileges`, no non-root `user` and no
   `read_only` for any service, and the dev compose has no voice-runtime service at all
   (`grep -rn "cap_drop\|no-new-privileges\|security_opt\|read_only" infra/` returns
   nothing). `kernel.yama.ptrace_scope` is a node setting no test can set. **Needs its
   own issue** against `infra/`.
4. **`scrub_event` does not remove payload quoted into an exception message.** It puts
   free text through `redact_text`, which targets identifiers, so a raise that quotes
   its own buffer into the message would reach the tracker under 1 KB at a time. The
   remedy files/10 §3 specifies is the **`SafeError` boundary** — *"converts exceptions
   to `{error_code, correlation_id}` before any logger, exporter or crash reporter sees
   them"* — and **no `SafeError` class exists anywhere in the workspace**; the name
   appears only in a `clinical_schemas.events` field description. Its absence is a
   separate row (`intake_platform`), not INT-278's.
5. **The GlitchTip integration half of invariant 19 is not run.** files/10 §9.1 says
   *"integration against a local GlitchTip"*; this container has no Docker daemon, and
   `sentry_sdk` is not installed in the workspace at all. The handler-level property is
   proved instead, with the SDK injected.

## 8. `not_covered_here` — exactly the rows proved, removed verbatim

`tests/voice/test_invariants.py`, `INVARIANTS[2]` (CLAUDE.md invariant 3). All four
entries are removed, none reworded. The removed text, verbatim:

```python
        not_covered_here=(
            "mlocked — files/10 §3 invariant 17 (`audio_no_swap_guard`): nothing in "
            "this repository reads /proc/self/smaps or asserts a Locked: region",
            "core dump — files/10 §3 invariant 16 (`audio_no_core_guard`): the "
            "real-crash test with RLIMIT_CORE=(0,0) does not exist on any branch",
            "crash report — files/10 §3 invariant 19 (`audio_no_telemetry_guard`), "

            "ptrace — files/10 §3 invariant 28 (`process_hardening_guard`)",

```

Each row's own claim is now false, which is the test for whether removing it is honest:

| removed row | the claim it made | why it is false now |
|---|---|---|
| mlocked (inv. 17) | *"nothing in this repository reads /proc/self/smaps or asserts a Locked: region"* | `voice_clips.locked_buffer.smaps_regions` reads it, the constructor refuses a partial lock, and four tests assert `Locked:` with two controls |
| core dump (inv. 16) | *"the real-crash test with RLIMIT_CORE=(0,0) does not exist on any branch"* | it exists: `TestCoreDumpsAreProvedByCrashing`, a real `os.abort()` with `WCOREDUMP` asserted and three controls |
| crash report (inv. 19) | recorded as a live defect | the handler is identified, its options asserted, and a report built over a live buffer carries none of it |
| ptrace (inv. 28) | (no claim beyond the row name) | attach and `/proc/<pid>/mem` are both refused, with an unprotected control that permits both |

The module docstring paragraph that *described* that list is updated in the same edit —
leaving prose saying *"Nothing in this repository asserts them yet"* beside a list that
no longer says so would be a defect of the kind CLAUDE.md's read order exists to
prevent. It now points at the new suite and at §7 of this file for what remains open.
Nothing else in `test_invariants.py` is touched: no citation added, no clause reworded,
no near-miss changed.
