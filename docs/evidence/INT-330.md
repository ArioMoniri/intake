# INT-330 — Native-stack transition policy: 120 ms on every stack, legal instant, intake gesture-locked

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile · **GitHub:** #529
**Spec:** `docs/design/motion/motion-verification.md` §3 S-1 and §4 MOTION-1
(on branch `merge-305`, not yet on `main` when this was written).

## Problem
- All three native stacks (root, `(auth)`, `visits`) set `animation` with no
  `animationDuration`, so iOS ran its 500 ms default fade
  (`react-native-screens/ios/RNSScreenStackAnimator.mm`, `RNSDefaultTransitionDuration = 0.5`).
- react-native-screens defers a push or pop requested while a transition is
  in flight until that transition completes (`RNSScreenStack.mm`,
  `setPushViewControllers`). A RED drawn as a stack push could therefore wait
  up to 500 ms, which alone exceeds 02 §8.1's 300 ms preemption budget. The
  risk is latent: no RED surface exists yet (INT-135).
- Legal text moved on screen (S-4): `(auth)/consent` faded for 500 ms on iOS,
  and `me/consents/index` and `me/consents/[purpose]` faded for 120 ms
  through the tabs.
- The intake could be swiped away by the iOS edge gesture.

## Change
- New pure module `apps/mobile/src/lib/motion/transitions.ts`:
  `RouteClass = "hierarchy" | "auth" | "intake" | "legal"` (as the
  `ROUTE_CLASSES` tuple), `routeClassOf(path)`, `transitionFor(cls, { reduce })`
  and `tabTransition(cls, { reduce })`. It is built on the kept
  `screenAnimation` and `motionMs` primitives (`src/lib/a11y/motion.ts`,
  whose own tests are unchanged) and imports nothing from React Native.
  - `hierarchy`, `auth` and `intake` fade for `motion.duration.fade` (120 ms);
    `intake` also returns `gestureEnabled: false`, at every reduce-motion
    setting. The header back control stays as the exit.
  - `legal` returns `animation: "none"` with `motion.duration.instant`
    whatever the reduce-motion answer, so it does not animate in either
    direction.
  - Under reduce-motion, every class returns `none` / 0.
  - No class can return a slide, a `presentation`, or a duration above
    `fadeMs`.
- `src/lib/theme.ts`: `motion.duration = { instant: 0, fade: 120 }`.
  `motion.fadeMs` is now the alias of `duration.fade`, so the budget is one
  number.
- The root, `(auth)` and `visits` stacks and the JS tabs spread the policy
  from a function-form `screenOptions`. Each one classifies
  `<its directory>/${route.name}`, so the per-screen rules (legal consent
  screens, gesture-locked intake) follow the route and not a declared
  `Stack.Screen` child. Declaring a child would have reordered expo-router's
  screens and changed the visits stack's initial route. No transition literal
  remains in any TSX file.
- `animationMatchesGesture` is not set anywhere; the change does not touch it.

## Tests (TDD)
- New: `apps/mobile/src/lib/motion/transitions.test.ts`, with the seven
  MOTION-1 tests:
  - "every native stack fades for duration.fade": checked per class and on
    every route file under `src/app`.
  - "reduce-motion turns every navigator transition off".
  - "legal routes never animate, with or without reduce-motion".
  - "every route that renders a docs/legal payload classifies as legal". This
    one keys on the payload, not on a path list kept in the test: a route is a
    legal host when it, or an `@/components/*` component it renders
    (transitively), imports the consent ledger. The ledger owns `LoadedText`,
    which carries the docs/legal version, hash and body. For non-vacuity, the
    test also checks that the ledger still declares `LoadedText.body` and that
    the screen printing `.text.body` is among the discovered hosts.
  - "the intake route fades and is gesture-locked".
  - "legal tab screens take no transition; other tabs take duration.fade":
    the tab list is read from the `(tabs)` layout.
  - "no route class returns a slide, a modal presentation or a duration above
    fadeMs".
- Added to `apps/mobile/src/lib/theme.test.ts`: "fadeMs remains the alias of
  duration.fade" and "no motion duration exceeds fadeMs".
- Rewrote `apps/mobile/e2e/a11y.spec.ts` BK14. The old pin (four files
  containing `animation: screenAnimation(`) and the `animation: "fade"` ban
  are replaced by:
  - "every native stack takes its transition, duration included, from the
    motion policy". This pins the three stack files and requires each
    `screenOptions` to spread
    `transitionFor(routeClassOf(<its own directory>/${route.name}))`. A stack
    that classified `consent` instead of `(auth)/consent` would fail.
  - "the JS tabs take theirs from the same policy", the same check for the
    tabs with `tabTransition`. This test is an addition to the spec's list.
  - "no navigator or screen writes a transition literal". It forbids the keys
    `animation`, `animationDuration`, `transitionSpec`, `gestureEnabled`,
    `fullScreenGestureEnabled`, `presentation`, `animationTypeForReplace` and
    `sceneStyleInterpolator` in any TSX under `src/app` or `src/components`.

## Device measurement: PENDING
**Pending: the owner's two reference devices.** This needs a release build on
iOS and Android, timing push and pop on the root, `(auth)` and `visits`
stacks, with the device, OS, build and date recorded here. Nothing in this
PR is a device measurement.
- iOS: expect the fade to follow `animationDuration` (120 ms, 0 under
  reduce-motion) instead of 500 ms. `(auth)/consent` and both
  `me/consents/*` screens should not animate in either direction. The intake
  should ignore the edge swipe.
- Android: react-native-screens' `rns_fade_in.xml` and `rns_fade_out.xml` run
  for a fixed 150 ms, and `animationDuration` is iOS-only. This is a platform
  fact, recorded here, not a token. No deferral of a mid-transition push was
  found on Android (`ScreenStack.kt` commits with
  `commitNowAllowingStateLoss`).
- The RED-mid-transition measurement (event → first RED frame) belongs to
  INT-135's DoD, where the RED UI lands (spec S-1, step 3).
