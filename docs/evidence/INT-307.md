# INT-307 — publish_wait / roll_up_wait accept an unlabelled wait family

**Epic:** E11-observability · **Sec-Row:** observability-pipeline

## Problem
`publish_wait` / `roll_up_wait` handled only the labelled `records_processing`
family, so a wait series such as `wait.doctor_link_first_open_h` had a writer but
no catalogue row (or a catalogue row nothing published). The publisher must
accept an unlabelled wait family, and `WAIT_SOURCES` must stop claiming a landing
issue for a series nobody publishes.

## Change
`observe_wait` in the metrics layer + `wait_times.py` accept an unlabelled wait
family and thread it to a catalogue-backed series; `WAIT_SOURCES` now names either
a publisher or the issue that owes one; `observability/metrics_catalog.yaml`
carries the series. Test: `tests/platform/test_wait_times.py`.
