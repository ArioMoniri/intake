# INT-481 — staff observability stack: dashboards and alerts for the admin panel

GitHub #824 · Sec-Row `monitoring-contract` · phase P1 · 4 Oct 2026 · owner request

**The owner's request (4 Oct 2026, verbatim):** *"have grafana or related better options or more
detailed things for the admin panel and all telemetrics measurements"*.

**What this PR delivers:**
- **A telemetry tier on the AWS host.** It is `infra/staging/compose.obs.yaml`, in the same compose
  project as staging, and runs Prometheus, Alertmanager, node-exporter, the blackbox exporter and
  Grafana. It is synthetic-only, internal networks only, and publishes no port.
- **A staff Grafana.** It is served at `grafana.<host>` behind its own oauth2-proxy and Keycloak
  client, for staff with an ops-console role, and reads Prometheus only (ADR-040, D27).
- **An Alerts page in the admin console.** `/alerts` is fed by `GET /admin/alerts` (Alertmanager,
  ids only) and carries a plain link to Grafana.
- **Five generated, drift-gated dashboards**, plus the seven per-SLO dashboards that already exist.
- **One closed label allow-list**, held against the catalogue, every rule file, every dashboard
  and every staging scrape job (invariant 6).

- **Retention:** Prometheus keeps **30 days or 4 GB**, whichever comes first. The 30 days match the
  INT-190 rolling 30-day cost budgets. Alertmanager keeps 120 h.

## 3. Recommendation

1. **Prometheus v3.15.0** for metrics and rules. Apache-2.0, LICENSE sha256 `c71d239df917…` (11 357 bytes). Capped at 30 d / 4 GB.
2. **Alertmanager v0.34.1** for alert state, read by the console through the API. Apache-2.0, same blob. Its one receiver sends nothing.
3. **node-exporter v1.12.1** for the host and **blackbox-exporter v0.28.0** for synthetic probes. Both Apache-2.0, same blob.
4. **Grafana OSS 13.2.3** for staff dashboards. AGPL-3.0-only, LICENSE sha256 `0d96a4ff68ad…`, plus LICENSING.md `4393eddd…`. Acceptable only self-hosted, unmodified, for our own staff, and never distributed or offered as a service.
5. **Not VictoriaMetrics** (Apache-2.0, `778f2412…`). It is lighter, but the rules, the release gate and the console already speak the Prometheus API, and ~5k series do not need the saving.
6. **Not SigNoz or HyperDX.** SigNoz is MIT `449417bc…` with a proprietary `ee/` `f98f8046…`; HyperDX is MIT `31ab1c54…`. Both are ClickHouse-backed and need several GiB on a host shared with CI.
7. **Not Loki or Tempo** (both AGPL-3.0-only, `0d96a4ff…`). Staging exports no logs or traces, and both are PHI-path stores that F1 keeps out of browser reach.
8. **Placement:** all of it on the AWS host only. Images are pinned by digest and recorded with their licences in `observability/registry.yaml`.

## 5. Invariants

- **Invariant 6, labels.** `intake_platform.observability.labels.ALLOWED_LABEL_KEYS` is a closed
  list of 99 keys.
  - **Refusal rule:** any person, session or device segment is refused, as is any free-text tail
    or any identifier-shaped tail, unless the key is one of six reviewed identifiers. Each reviewed
    identifier carries its reason: `actor` (a staff subject), `budget_id`, `head_sha`, `host_id`,
    `key` (a tenant KEK name), `run_number` and `tenant`.
  - **What is checked:** the catalogue, every rule file, every dashboard and the staging scrape
    jobs. Each job ends in `labelkeep` = the list and caps samples, label count and value length.
  - **Near misses that are refused:** `patient_id`, `session_id`, `user_email`, `device_id`,
    `ip_address`, `free_text`, `request_path`, `token`, `utterance_hash` and others.
  - **Near misses that are admitted:** `message_class` and `subject_count`.
  - **Staff subject id:** `actor` is on the list. Recording it as a reviewed identifier, rather than
    refusing it, is a judgement for review.
- **Invariant 6, logs.** Grafana logs errors only. The Grafana gate's request and auth logs are
  off, because they name the signed-in email.
- **Invariant 6, alerts.** `GET /admin/alerts` never returns annotations, the generator URL or the
  fingerprint.
- **Invariant 13, emitters.** The catalogue's new `emitter` field says what emits each family:
  `code`, `prometheus`, `exporter:<registry row>` or `textfile:<writer>`. Each exporter job keeps
  exactly its catalogued families by name, and every exporter is a registry row with a probe.
- **Invariant 14, images and secrets.**
  - Every image is digest-pinned.
  - The three new secrets (`GRAFANA_SECRET_KEY`, `INTAKE_GRAFANA_CLIENT_SECRET`,
    `OAUTH2_PROXY_GRAFANA_COOKIE_SECRET`) are host-generated by `init.sh` into the root-only env
    file. That is how this tier takes every secret today (INT-345, INT-421).
  - The Keycloak client script takes the admin password and the client secret on stdin.
- **Invariant 15.** No new service under `services/`. The telemetry tier is a coverage `tier`
  entry with probe rows for all five components. Its SLO is exempt with a recorded reason: it
  serves no request of its own, and its failures alert on the host.
- **Invariant 48 / F1.** Grafana reads Prometheus only, sits on its own origin, client and cookie,
  has no password, admin account or Explore, and is linked, never framed. The console CSP is
  unchanged. See ADR-040 and D27.
