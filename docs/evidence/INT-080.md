## Condition grammar — every construct cited

Accepted (all others refused at load with `WhenGrammarError`, never

| construct | source |
|---|---|
| `&&`, `\|\|`, parentheses, dotted slot atoms | files/03 §6 red_flags example (`hpi.single_hot_swollen_joint && (vitals.temp_c >= 38 \|\| symptoms.fever)`) |
| `!`, `in {...}`, string/boolean literals | files/protocols/base.life_threat.yaml exemplars 1–2; `set` is a files/13 §9.5 type |
| `==`, `>=` | files/03 §6 |
| `!=`, `<`, `<=`, `>` | files/03 §8 "CEL-like sandboxed expression engine"; files/12 §4 layer 3 derives its canary corpus at "every comparison boundary the authors actually wrote" (l±ε — both directions of every bound) |
| numbers as `Decimal`, exact comparison | files/13 §9.5 ("no floats anywhere") |
| Kleene three-valued evaluation, fire only on TRUE | files/12 §1.1; files/13 §9.5 |
| `temporal.within(anchor, tense, now)` conjoined per rule | files/12 §2.4 (Unknown on an undated anchor — "a tense-qualified rule cannot fire on an undated symptom") |

Refused at load (tested one by one): function calls, arithmetic,
assignment, single `&`/`|`, signed literals, uppercase identifiers, empty
sets, sets containing references, bare literals as predicates, trailing
tokens, unterminated strings. Type-mismatched comparisons evaluate to
Unknown, never False — a data defect can suppress a firing only into a
coverage gap, not into false reassurance.

## Monotonic merge — property design

Fired rules join under the EK-4 lattice `max` (files/12 §1). `hypothesis`
is not a workspace dev dependency, so the property is proved by exhaustive
small-domain enumeration instead (the INT-080 brief's named alternative):
over a five-rule pool (SARI_K2, SARI_K1, KIRMIZI_K2, KIRMIZI_K1, SARI_K2),
all 32 subsets are evaluated and each must equal the max severity of its
members; all 32×32 subset pairs assert A ⊆ B ⇒ severity(B) ≥ severity(A)
(adding a rule can only escalate); all 120 permutations of the full pool
must produce byte-identical evaluations (no input ordering ever lowers a
level). The runtime backstop of files/12 §4 (`max` over a total order is
monotone in each argument) is what makes this hold by construction: the
engine takes `max` severity over fired rules and sorting is total on
`(−severity, rule_id)`.

Where several REDs fire, one rule supplies both register and script:
severity first, then register restrictiveness (SILENT > CALM > ALERT >
DEFERRED_CLINICIAN — files/02 §5.3: alarm "is a mechanism of harm" for
distress-sensitive and safeguarding REDs, while DEFERRED exists for
findings with no useful patient action and must not swallow one that has
one), then rule id as the total tiebreaker. Register and script travel
together because files/02 §5.3's binding authoring rule approves the
register per rule — mixing rule A's register with rule B's script would
deliver a script in a register no clinician approved for it.

## Type-level LLM cap

`LlmCandidateTriage.level` is `Literal["YELLOW_REVIEW"]` (INT-031) — a
RED-labelled candidate is a `ValidationError`, asserted in the tests along
with the annotation itself. `TriageEvaluation.result` is annotated
`RulesTriageResult` (not the discriminated union), so the level field
derives exclusively from rules; candidates live in the separate
`candidate_flags` field. `with_candidates` passes `result` through as the
same frozen object (identity-asserted) and reads no candidate level.
The import-boundary test walks every module under packages/protocols/src
and asserts no LLM/vendor/network client import exists.

## Action scripts verbatim

The engine returns the winning rule's own frozen `LocationAction`
(REMOTE/ON_SITE) or `UnknownAction` (UNKNOWN → the single `ask_one_tr`)
object — asserted by identity (`is`), so byte-exactness holds by
construction and no paraphrase path exists (invariants 10/21; files/04
§8.1 rule 7). The ON_SITE test asserts `show_112` is false and that no
"112" appears in any of its texts; the schema already rejects
`show_112: true` under ON_SITE at load (INT-040).

`draft_needs_source` rules never evaluate: `pack_compilable` (INT-040)
already excludes them from a served pack, and `evaluate_triage` refuses
them again with `DraftRuleError` — proved both for a directly-passed rule
and for a loaded pack resolved through `resolve_red_flags`. RED rules
stripped of register/action via `model_construct` (the files/12 §2.3
bypass pattern) raise `TriageEngineError` instead of defaulting.
