Listed in the order they can be applied. No issue id is minted; the orchestrator files them.

**D1.** Nothing to build. The build already follows the broader reading (INT-547 left item 2).

**D2 (voice runtime).**

- `SessionCloseHandler` today closes only CD-05 anchors (`session_close.py`). It must also close each slot in CD-04 `unresolved_at_close.slots` that is `ASKED_PENDING` at close: record `UNCLEAR` with the `session_closed` label. A slot already `UNCLEAR` whose follow-up was not yet asked keeps `UNCLEAR`, takes the same label, and counts as spent. Nothing is bound, and no other slot is touched.
- At close, each slot in `never_asked_gate_open.slots` that is `NOT_ASKED` while `chest_pain.present` reads TRUE is labelled `never_asked_at_close` and stays `NOT_ASKED`.
- `ClinicItemWatch` raises `chest_pain_arms_unresolved` once per session in both cases. The level and the Work's determination are unchanged.

  - INT-547's near miss "an onset closed before its follow-up was asked raises nothing" is already superseded for the anchor by CD-04 round 3 (INT-546). The non-anchor equivalent now raises the item.

**D3 (platform, admin API, console, note).**

  - `action_taken` and `plan_to_act` close the entry.
  - `redirected` re-addresses it to a named clinic and keeps it open.
  - Acknowledgement stays audited and never closes.
- The console gains the outcome action. INT-548 (#928) renders an acknowledged-but-open item as open, and a closed item with its code.
- Tests: `acknowledgement_never_closes_an_item`, `redirect_keeps_the_item_open` (CD-08.md).

**D4 (tenant configuration).**

- Test: `inbox_not_ready_names_each_missing_value`.

**D5 (platform, identity, admin API).**

- Each clinic-item `InboxEntry` names the booked clinic.

- Test: `only_a_rostered_clinician_records_an_outcome`.
