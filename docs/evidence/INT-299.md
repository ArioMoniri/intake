# Evidence — INT-299 · A translated answer is not the patient's words

Tests: `tests/engine/test_note_translated_attribution.py` (45). sec_row: `notes`
(docs/security/threat-model.md "## `notes` — the clinician-ready note"). depends_on:
INT-296 (the session locale whose registry holds only `tr`) and INT-084 (the note
composer that owns the attribution model and raises `AttributionRefused`).

## Acceptance (verbatim from docs/backlog/issues.yaml)

- [x] "the clinician reads Turkish and the patient may not have spoken it, so a line
  built from a translated answer carries `translated` rather than `hasta beyanı`"
- [x] "the original is retained verbatim beside the rendering, with its source locale,
  and is reachable from the clinician surface"
- [x] "the translator is identified the way a model is: name, `model_id@revision` and
  `sha256`, recorded on the line … and a line whose translator cannot be identified
  raises rather than rendering unattributed"
- [x] "INT-085's patient summary refuses a translated line whose original the patient can
  no longer see"
- [x] "the attribution vocabulary gains exactly one member and the addition is closed"

## What was NOT built, stated before anything else

**No translator.** `TRANSLATOR_REGISTRY` is empty and `translator()` raises. Choosing a
translation model is CLAUDE.md invariant 19's work — open weights, commercially usable,
licence-verified from the raw LICENSE blob with `licence_verified_at`, and
`model_id@revision` + sha256 in the self-hosting registry — and it is downstream of
**HB-O5** naming the language at all. Writing a plausible model id, revision or sha256 to
make the seam look finished is exactly the invented value HUMAN_BLOCKERS.md Rule 1
forbids, and `intake_platform.adapters.pins` already refuses on that ground for §4.9.1
row 1. The refusal is the artefact.

**No locale.** `enabled_locales()` still returns `("tr",)` and a test asserts it. Five
open blockers sit between this mechanism and a second language and none of them was
answered here: **HB-O5** (which languages), **HB-C19** (who signs the clinical text and
do they read it), **HB-L23** (which language legally binds), **HB-L24** (instrument
licences and validation per language) and **HB-L25** (what KVKK category a stored locale
is once there is more than one — a language choice can proxy ethnic origin).

**No clinical content and no patient copy.** The two new fixed strings are *keys* —
`previsit_note.attribution.translated` and `patient_summary.attribution.translated` —
bound only from the hash-bound `docs/legal/strings.yaml`, which still does not exist, so
both production paths fail closed exactly as INT-084's and INT-085's already do. The
values used by the tests live in the two synthetic fixtures whose headers say they are
synthetic (`synthetic-int084`, `synthetic-int085`).

**No translation-quality figure anywhere** (invariant 20). There is no corpus, so there is
no measurement, so there is no number. The word "accuracy" does not appear in any file
this issue touched.

## 1. `translated` is one member of one closed vocabulary

`Attribution` gains `TRANSLATED` and nothing else. `TestTheVocabularyIsClosed` walks the
enum and asserts the seven-member set by value, asserts `len(Attribution) == 7`, and
asserts that exactly one member is about translation — so a later locale that wants
"post-edited", "interpreted" or "clinician-translated" has to change a line a reviewer
reads, which is the review. `NOTE_COPY_KEYS` is derived from the enum, so the key set
gained exactly one key and a test counts it.

**INT-085's missing vocabulary is intact.** `SUMMARY_ATTRIBUTIONS` gains `TRANSLATED` and
still omits `RULES_ENGINE` and `LLM_CANDIDATE`. That absence is invariant 1's summary face
— there is no marker key by which a fired rule or a candidate flag could be *worded* onto
a card — and the test asserts the two by name rather than by counting members, so widening
the set cannot pass by arithmetic.

### Where a translated answer may sit — one rule, not a second table

`SECTION_ATTRIBUTIONS` admits `TRANSLATED` in exactly the rows that admit `PATIENT_SELF`,
via a single `_SELF_REPORTED` frozenset the eight rows are built from. A translated answer
goes wherever the patient's own answer goes; a row where the two differed would be a place
the distinction was made for a reason nobody wrote down. `TestTheVocabularyIsClosed`
asserts the equivalence over every row rather than restating the table.

`imported_objective` is the one row it does not reach: that row admits `RECORD` and
nothing else, and a translated *document* is a document-extraction question with its own
provenance (files/03 §4.6), not a note-attribution one. INT-084's own
`test_the_attribution_table_is_exactly_the_declared_one` was updated — the table genuinely
changed, and pinning it member by member is what made the change visible.

### The axis that cannot be stacked, recorded rather than smuggled

`Attribution` is one axis and *a relative's condition, spoken in another language* is two.
`Sourced.__post_init__` already refused a relative subject under a non-`RELATIVE`
attribution, so the case is refused today rather than silently dropping either half — the
relative, or the fact that a machine wrote the sentence. `TestTheAxesStayApart` asserts it.
**Widening this is a decision with a clinical owner, not an engineering default**, and it
is reported to the coordinator rather than taken here: no issue id and no blocker id was
minted.

## 2. The original is the record

`TranslatedText` carries the patient's own words verbatim, the locale they were spoken in,
and the translator. It rides on `Sourced` and the composer copies it onto the `NoteFact`,
which is where the span, the attribution and the subject already live — so the original
reaches every renderer that takes a `ComposedNote`, which is all of them.

**The Turkish is deliberately not stored on `TranslatedText`.** The rendering is already
the fact's own `lines`, so the pair sits together with nothing that can drift between them;
storing it twice would create a second copy that a later edit could contradict.

**"Beside the rendering" is taken literally.** The original is rendered on the line
*directly beneath* the one it is the original of, under the same `fNN` handle and one
indent deeper:

```
Başvuru nedeni
  [f01] çeviri: qx — Sentetik çevrilmiş yakınma
    « qx » SENTETIK-OZGUN-YAKINMA
```

A block further down the page would satisfy "retained"; it would not satisfy "beside". A
test asserts the original is on the line immediately after its rendering, carries the
source locale, and is indented deeper than it. `render_note_pdf` shares `document_lines`,
so the PDF carries it too.

**Two constructions are refused, and the refusals name nothing.** An empty original raises
(a line with no way back is not a translated line), and a `source_locale` that is not a
BCP-47-shaped tag raises through INT-296's own `safe_code` — so a sentence a patient typed
into a language field is replaced wholesale rather than truncated (invariant 6). Tests feed
a sentence containing a phone number and assert neither the sentence nor the number
appears in the message, and feed the patient's original and assert it does not either.

A `source_locale` of `tr` is also refused: marking the patient's own Turkish as a machine
rendering is this issue's defect pointing the other way.

## 3. The translator, identified the way a model is

`TranslatorIdentity` has four fields and no defaults: `name`, `model_id`, `revision`,
`sha256`. `pinned_id` is files/03 §4.9.4's `model_id@revision`, the same form
`intake_voice_runtime.adapters.pins` uses. Four refusals, each a *shape* check — nothing
here produces a hash:

| refused | why |
|---|---|
| a blank `name`, `model_id` or `revision` | a rendering on a clinical record whose producer nobody can name is an unattributed machine sentence |
| `model_id` that already carries an `@` | `model_id@revision` is assembled once from two fields, so two revisions cannot end up on one line |
| a `sha256` that is not 64 lowercase hex | a value that cannot be a sha256 is not recorded as one, and a plausible hash is never written to make a check pass |
| `translator(name)` for any name | the registry is empty; see §"What was NOT built" |

**"Raises rather than rendering unattributed" is enforced at three depths**, because
`NoteFact` is a plain dataclass a caller can assemble directly:

1. `Sourced(attribution=TRANSLATED, …)` without a `translation` raises
   `TranslatorUnidentified` at the call site. The value does not exist.
2. The inverse also raises: a `Sourced` carrying a `translation` under any other
   attribution is refused, because *that* is the defect — a machine's sentence labelled
   `hasta beyanı`.
3. `render_soap` / `render_note_pdf` meet a hand-assembled `NoteFact` with
   `attribution=TRANSLATED` and `translation=None` and raise rather than printing the
   line. A test builds exactly that fact and asserts the raise.

**Recorded where the provenance is read.** The SOAP/PDF provenance block resolves each
handle to its span *and*, for a translated fact, to the locale, the translator's name, its
`model_id@revision` and its sha256 **in full** — an auditor reads the note against the
translator, and a truncated hash is a hash nobody can re-check. None of that is patient
material, unlike the original above it.

## 4. The FHIR face refuses rather than exporting the machine version

`render_fhir_document` raises `TranslatedOriginalUnreachable` when the composed note holds
a translated fact, and this is the one decision in the issue that is a judgement rather
than a mechanism, so it is stated plainly.

The bundle is built from the `PreVisitNote` *value*, which holds the Turkish rendering and
nothing else; the original lives on the fact index, and INT-084's provenance extension is
ids and offsets **by contract** (*"Locators are ids and offsets only — never narrative"*,
invariant 6) rather than a place to put a patient's sentence. Exporting the rendering alone
would send the machine's version to the hospital as the patient's own words — this issue's
defect at exchange scale, and the single place where it would leave the building.

Giving `PreVisitNote` a field to hold the original is a files/04 §5 schema change that
needs the invariant 18 inventory annotation, and it persists a **source locale** on the
clinical record, which is a new category of personal data — **HB-L25** says in as many
words that a stored locale becomes a fact about a person the moment a second locale exists,
and that a language choice can proxy ethnic origin. CLAUDE.md makes that a stop-and-ask,
not an engineering call. So the face fails closed and the decision is reported.

It is **inert today**: no translator is registered, so no note in production can hold a
translated fact. A test asserts an untranslated note still renders, so nothing regressed.

## 5. The patient summary shows the patient their own words

The note's job is to give the clinician a Turkish rendering with the original beside it.
The summary's is the reverse, and this is the sharper half of the acceptance: **the patient
is shown the sentence they actually said, and the machine's version is not shown to them at
all.**

`SummaryLine` already splits `authored` (the product's words, readability-gated) from
`quoted` (the patient's or a document's, never measured and never rewritten). A translated
fact's `quoted` is its **original**, so the patient's words travel intact through a gate
that was already designed never to touch them. Tests assert the original appears in the
built summary and that the Turkish rendering appears *nowhere* in it — neither in the line
index nor in the `PatientSummary` value.

The marker is INT-085's rule unchanged: every line carries one, and a translated line's
names the source locale, because the words beside it are the patient's and the language is
how they recognise them.

**The refusal.** A fact attributed `TRANSLATED` whose `translation` is gone refuses the
**whole** summary with `SummaryRefused` — not the line. A summary short by one line reads
as a complete summary; showing a patient a machine version of their own words with no way
back to them is worse than showing nothing, and dropping the line quietly would be the
third option nobody asked for. The refusal message names the `fNN` handle and no patient
material, asserted.

One detail worth naming: a fact that renders into several summary lines (a chief complaint
with goals) still records **one** utterance, so the original is shown once. Repeating it
under each rendered line would read as several separate things the patient said. The
sentinel that expresses "already shown" is deliberately a different value from `None`,
because `None` is what an *absent* original looks like and that case refuses.

## 6. Invariant 1 — a translation is not a route to a level

Nothing here produces, influences or reads a triage level. `translation.py` contains no
`TriageLevel`, no `RED`, no `YELLOW`, no `candidate_flags` and no `rules_engine` token, and
a test reads the module's own source and asserts it. `SECTION_ATTRIBUTIONS` still has no
`RULES_ENGINE` row, so there is no path by which an LLM's reading of a translated answer
could reach the rules engine through the note's attribution axis.

## Open questions for a human — reported, not decided

None of these blocks, and no issue id or blocker id was minted for them: the coordinator
allocates.

1. **A relative's statement in another language is not representable.** `Attribution` is
   one axis and that case is two, so it is refused rather than half-recorded (§1). If
   family history is expected to be taken in a second language, someone with a clinical
   owner has to decide whether the relative or the machine is the thing the marker names.
2. **The FHIR document face refuses a translated note** (§4). Reversing it means giving
   `PreVisitNote` a field for the original and the source locale, which is HB-L25's
   question about a new category of personal data plus a files/04 §5 inventory annotation.
   Both halves are visible in one diff: delete the raise, add the field.
3. **The PDF cannot draw a non-Latin original legibly.** `render_note_pdf` already passes
   `escape_unencodable=True`, so an Arabic or Cyrillic original survives as **named
   codepoints** rather than being transliterated — which is the correct failure (a
   transliteration is a second, unattributed rendering) but is not readable. The SOAP text
   face carries it verbatim and is the surface the Doctor Link uses. A PDF with a
   full-coverage font is a typography decision with a cost.
