# INT-416 — triage context refuses an empty unit at construction

GitHub #707 · Sec-Row `triage` · phase P0 · 16 Oct 2026

**Acceptance, verbatim from GitHub #707** (the row is in PR #867, see *Backlog
row* below):
- "`TriageContext.units` values are `Annotated[str, Field(min_length=1)]`, so a
  malformed unit map is refused when the context is built and never during
  evaluation." — **met.** The field is now
  `dict[str, Annotated[str, Field(min_length=1)]]`. Its JSON schema carries
  `additionalProperties.minLength: 1`, and a test pins that.
- "A safety test proves both halves: a RED with a malformed unit map is refused
  at construction, and the near-miss (a well-formed unit) still returns RED." —
  **met.** `TestAMalformedUnitMapIsRefusedWhenTheContextIsBuilt` in
  `tests/safety/test_numeric_carrier.py` (the numeric-carrier suite the issue
  names).
- "`make safety` passes, and triage branch coverage stays at 100 %." — **met.**
  `make safety` exits 0. Triage branch coverage is 100 % (448 statements, 192
  branches, 0 missed). 18/18 mutations are detected.

**The defect.** `TriageContext.units` was `dict[str, str]`. The value it feeds,
`EvidenceSlot.unit`, is `min_length=1`. So `TriageContext(units={"<slot>": ""})`
built without error. Then `evaluate_triage` raised `ValidationError` on the
first firing KIRMIZI rule that read the slot, instead of returning RED. The
same context with `units={}` returned RED. Reproduced on main `be6c09c1` before
the fix:

```
built
evaluate raised ValidationError
```

No production caller passes `units` today, so a patient could not reach this
yet. It is a way for a RED evaluation to fail (invariant 1), so it is closed
before any caller exists.

**The fix.** One line in `packages/protocols/src/protocols/triage/context.py`:
each unit value is `Annotated[str, Field(min_length=1)]`, the same bound as
`EvidenceSlot.unit`. The field description says why and that a slot with no
unit is absent from the map. The engine is unchanged. A malformed map is now
refused where the context is built, for every slot in the map, whether or not
a rule reads that slot. Evaluation has nothing left to refuse.

| `test_near_miss_a_well_formed_unit_still_returns_red` | `units={FEVER: "°C"}`, value 38.5 | RED; the fire's evidence carries `°C` on the fever slot and no unit on the anchor |
| `test_near_miss_a_one_character_unit_is_the_shortest_accepted` | `units={FEVER: "c"}` | RED |
| `test_an_absent_unit_still_returns_red` | `units={}` | RED |
| `test_the_bound_is_the_type_of_the_field_and_not_a_check_at_evaluation` | `TriageContext.model_json_schema()` | `units.additionalProperties.minLength == 1` |

The three near misses sit on the firing side. A fix that refused every unit,
or that dropped units from evidence, fails them.
