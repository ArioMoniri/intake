## 3. What this PR builds

### 3.1 The compiler emits `bundle.tar.gz` (`protocols.compile.archive`, `bundle.py`, `cli.py`)

- There is a new sixth artefact, `resolved_protocol.json`. It is the merged document the
  resolved hash is computed over (the "YAML" of files/04 §7, resolved), dumped by alias so it
  validates back into `ResolvedProtocol`. `manifest.json` hashes it like every other
  artefact.
- `write_bundle` also writes `bundle.tar.gz` and `bundle.tar.gz.sha256`. The archive is gzip'd
  USTAR with members in name order, mtime/uid/gid/owner zeroed, mode `0644`, and no name or
  timestamp in the gzip header. The sidecar uses `sha256sum` format, so
  `shasum -a 256 -c` checks it by hand.
- `protocol_hash_of(document)` is now the single hash construction. `resolve_protocol` stamps
  with it, and the runtime re-derives with it.
- `protocols compile` prints `bundle_sha256: <hex>`.

### 3.2 Signing (`make sign`)

`make sign SIGN_KEY=<cosign key ref>` runs `cosign sign-blob --yes --key "$SIGN_KEY"
--new-bundle-format=true --bundle <archive>.sigstore.json $(COSIGN_FLAGS) <archive>` on every
`packages/protocols/dist/*/bundle.tar.gz`. Its guards:

- **`SIGN_KEY` has no default**, and without it the target exits 2 and signs nothing. The
  reference can be `hashivault://<key>` (OpenBao transit), `awskms://…`, or a local file for a
  rehearsal. No private key ever enters a Python process or the tree.
- A missing `cosign` binary fails loudly with an install hint (invariant 14). Having no
  compiled bundle also fails.
- `COSIGN_FLAGS` is passed through untouched. The transparency-log choice belongs to the same
  owner decision as the key.

### 3.3 The runtime verifies before it loads (`protocols.serving.trust`)

`verify_bundle(archive, signature, trust_root, expected_sha256=None)` and
`load_verified_bundle(path, trust_root)` are the only way to obtain a `VerifiedBundle`. Its
constructor refuses any caller that does not hold the module's private mint token. The checks
run in this order, and **nothing inside the archive is parsed before the signature
verifies**:

| # | Check | Refusal (all subclass `BundleRefused`, each with a stable `reason`) |
|---|---|---|
| 1 | a signature exists | `BundleUnsigned` |
| 2 | it is a sigstore bundle carrying `messageSignature` (not DSSE, SHA2_256 digest, valid base64) | `BundleSignatureInvalid` |
| 2b | it is not a keyless certificate identity (`certificate` / `x509CertificateChain`) | `BundleUntrustedSigner` |
| 3 | its declared digest, and any deploy-record digest, equal sha256(archive) | `BundleHashMismatch` |
| 4 | ECDSA P-256 / SHA-256 verifies under the trust root (tampered, forged or another key's signature: indistinguishable to ECDSA, all refused) | `BundleSignatureInvalid` |
| 5 | inflate within 64 MiB, in memory (never extracted); gzip complete, no trailing bytes; flat regular members only (no `..`, `/`, symlink, directory, duplicate); members == manifest set; `resolved_protocol.json` present and valid | `BundleArchiveMalformed` |
| 6 | every member hashes to its manifest row; the resolved document **re-derives** its hash, and it equals the manifest's; manifest pack/version/locale equal the document's | `BundleHashMismatch` / `BundleArchiveMalformed` |

Steps 5–6 refuse archives that a trusted key *did* sign, because a signature proves who produced
the bytes, not that the bytes are a bundle. The archive size is also bounded before the read
(32 MiB).

**Trust root.** `TrustRoot.from_pem` accepts an EC P-256 public key and nothing else: RSA,
P-384, garbage and a private-key PEM are all refused with `TrustRootInvalid`. No algorithm is
negotiated from the signature file. `load_trust_root()` reads the path in
`INTAKE_PROTOCOL_TRUST_ROOT`. **If it is unset, the result is `TrustRootMissing` and nothing
loads, with a message naming INT-019. There is no dev bypass.** Tests mint an ephemeral key in
memory.

**Deliberately not verified.** Rekor inclusion is not checked: the serving tier is offline and
in-country. Keyless Fulcio bundles are refused, because trusting one needs an identity policy
(OIDC issuer + workflow subject) that nobody has decided yet.

### 3.4 Per-session pin (`protocols.serving.pins.ServedBundles`)

- `deploy(v)` admits a `VerifiedBundle` and makes it current for its `BundleKey(pack, locale,
  voice)`. `admit(v)` makes it resolvable without deploying it. Anything that is not a
  `VerifiedBundle` raises `TypeError`.
- `pin(session, key)` pins to the current bundle, once and idempotently. **A later `deploy`
  never moves an existing pin.** Re-pinning a session to another pack raises `PinConflict`.
- `resume(session, key, protocol_hash)` is the restart path, driven by the persisted
  `SessionState.protocol_hash`. **It never falls forward** to the current bundle. The version
  the session started on must be re-admitted first; otherwise it raises `UnknownBundle`.
- A published version is byte-immutable. The same `(key, resolved hash)` with different
  archive bytes raises `PublishedVersionConflict` (files/10 §8 inv. 41).
- `SessionPin.protocol` and `SessionPin.protocol_hash` are the exact pair that
  `build_residency_tr_session` / `build_typed_session` take, and `protocol_hash` is the value
  for `SessionState`, `TalkerConfig` and `NoteMeta`.

### 3.5 Note meta shows the pinned hash

The test composes a real `PreVisitNote` through `intake_voice_runtime.note.compose` and renders
it with `render_soap`, for two sessions: one pinned before a new bundle is deployed and one
after. Each rendered note carries `protocol_hash: <its own pinned hash>`, and the early note
does not contain the later hash.

## 9. What the owner must provide (INT-019, awaiting-human; the CI half sits in the protected `security.yml`, HB-O6)

Nothing below blocks any INT-058 acceptance clause, because each clause is proved with an
ephemeral key. They block **production** signing and loading:

1. **Key custody and the key reference.** Pick OpenBao transit (`hashivault://<key>`), a KMS
   key, or keyless CI identity, and provide the `SIGN_KEY` reference. Keyless needs an identity
   policy (issuer + subject), and the verifier would have to be extended for it, because today
   it refuses certificate identities.
2. **The public half** as the runtime trust root file, named by `INTAKE_PROTOCOL_TRUST_ROOT`.
3. **One interop run.** Run `make sign` with the real cosign (≥ 2.4 or 3.x), then load the
   output through `protocols.serving.trust.load_verified_bundle`, and record it here.
4. **The transparency-log policy** (public Rekor or none), passed through `COSIGN_FLAGS`.

The one-sentence ask: *which key signs protocol bundles, and where does its public half live?*

## 10. Deliberately not in this PR

- **No serving process loads bundles yet.** The voice-runtime composition root takes
  `protocol` + `protocol_hash` as parameters, and `SessionPin` supplies exactly those. Wiring a
  live session-start path is the work of the issue that adds one. The
  `sec.pack_signature_failures` counter stays `planned` until that process emits it. The
  `reason` ids are ready for it.
- The dev-only George clip route (`intake_api.dev_voice_guard`, never mounted in production)
  still reads loose clip manifests from `dist/`. It is a dev convenience and not the serving
  path.
- Quarantine, `known_good` fallback and the re-triage sweep (files/10 §8 inv. 44) belong to
  INT-184.
- `.github/workflows/security.yml` is hook-protected and was not edited.
