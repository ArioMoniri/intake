# INT-407 — Visit lifecycle state machine (02 §2b): a RED visit cannot silently move

**Epic:** E02-data · **Phase:** P1 · **Sec-Row:** visits · **GitHub:** #684 ·
**Labels:** area:api, risk:clinical · **Depends on:** INT-197, INT-150, INT-306 (merged),
**INT-406 (PR #683, not yet merged — this branch is based on `origin/int-406-red-ack-sla`)**

## Acceptance (verbatim, GitHub #684)
- "the visit states `planned → confirmed → checked_in → attended`, `cancelled`, `rescheduled` (new datetime → planned), `missed` (datetime + grace, no check-in), as a typed state machine; invalid transitions are refused; every transition is audited by id"
- "a `rescheduled` or `cancelled` transition on a visit carrying an unresolved RED raises a clinic inbox entry (INT-406), regardless of connector presence, and re-shows the crisis signposting in the register the original RED used (the existing RED script, verbatim)"
- "on `cancelled`: shared notes are auto-revoked, and the clinician inbox entry is withdrawn; on `rescheduled`: the note is marked stale 7 days after its session, and a delta session is offered (existing copy only; any new string goes to clinical review)"
- "Doctor Link expiry is pinned to `visit_datetime + 72 h`, never `issue_time + 72 h`"
- "`checked_in` doubt (a geofence outside the building, a QR scanned by someone other than the patient) yields `UNKNOWN` location, never ON_SITE (invariant 21)"
- "the T-24h confirm message is queued as a transactional message and stays unsent while no SMS vendor is configured (INT-358); it is never sent by a fake"

## Problem
files/02 §2b: *"a RED-flagged patient whose appointment moves two weeks out is invisible to
everyone."* On the base, a visit was an INT-197 session row with list/create/read only:
nothing moved one, nothing recorded a state, and INT-406's `SafetyInbox.visit_transition`
had no caller.

## Change
- **`intake_platform.visit_lifecycle`** (new, pure; ids, enums and instants only):
  - `machine.py` — `VisitState` (the seven states); `ALLOWED_TRANSITIONS`; `VisitLifecycle`
    (immutable record, `apply()` → next record or `TransitionRefused(code)`); the guards
    (`schedule_required` / `schedule_not_allowed`, `check_in_evidence_required`,
    `missed_grace_unset` / `missed_schedule_unknown` / `missed_not_due`, `naive_timestamp`,
    `transition_id_invalid`); `CheckInEvidence` (QR `scanned_by_patient`, geofence
    `inside_building`; certain only on an affirmative signal); `derive_location` (files/02
    §5.3 Axis 3); `NOTE_STALE_AFTER` (7 days) and `note_stale`.
  - `confirm.py` — the T-24h `ConfirmRequest` (transactional, SMS, due `visit_instant − 24 h`),
    `ConfirmStatus` = `queued | withdrawn` (no `sent`), `attempt_confirm_dispatch` — refuses
    before any transport: `blocked_transport_unconfigured` (INT-358) or
    `blocked_copy_unreviewed`.
  - `resurface.py` — `RedResurface` (work id, rule id, register, location — a pointer, never
    words) and `red_resurface()` over the visit's RED inbox entries.
- **`intake_platform.safety_inbox`** — a RED `InboxEntry` records the `register` it was told
  in (closed enum; only a RED entry may carry one); the runtime's `SafetyInboxNotifier`
  passes `notification.register`. Optional only for entries written before this change; a
  reader never supplies a default.
- **`intake_platform.doctor_link.visit_instant`** — the visit's instant (the hour where
  recorded, else the start of the date); `link_expires_at` is now `visit_instant + 72 h`.
- **API** — `POST /v1/visits/{visit_id}/transitions` (patient only; `to` ∈ `confirmed`,
  `checked_in`, `cancelled`, `rescheduled`; `intake_api.visit_lifecycle`, DB helpers in
  `visit_lifecycle_store`): the visit row is locked `FOR UPDATE`; a refused move is 409
  `transition_not_allowed` (payload refusals 422) and writes nothing; each move is audited
  `api.visit.transition.<state>` naming `visit:<id>/transition:<id>`.
  - **`rescheduled` / `cancelled`** read the Safety inbox before writing and call
    `SafetyInbox.visit_transition` before commit — no connector on the path; unwired →
    503 `safety_inbox_unconfigured`, unreachable → 503 `safety_inbox_unreachable`, and
    the visit does not move. Each patient-facing RED on the visit is re-shown as a
    `RedResurface` in its recorded register, location re-derived for the new state
    (`UNKNOWN` outside a session); persisted on the lifecycle record so every later read
    carries it.
  - **`cancelled`** — every live share and Doctor Link revoked (routing hints dropped),
    each audited by id, then `api.visit.clinician_entry_withdrawn` for the note; the clinic
    side's note read and the INT-317 read-back both require a live share, so both close;
    the queued confirm is withdrawn.
  - **`rescheduled`** — the new date/time written (INT-306 rules, same reason codes;
    a new schedule with no hour removes the old hour); every live Doctor Link re-pinned
    to the new `visit_datetime + 72 h` (row and routing-hint TTL), audited
    `api.doctor_link.expiry_repinned`; revoked or expired links are never revived; a new
    confirm is queued.
  - Every visit read (`VisitOut`) carries `state`, `check_in_certain`, `note_stale`,
    `delta_session_offered` and `red_resurface`; `NoteOut.stale` and the Doctor Link view's
    `note_stale` carry the same one computation. `create_visit` writes the lifecycle slot
    (`planned`, confirm queued when dated). `ApiState` gains `safety_inbox` and `clock`;
    the previsit output's `completed_at` (the note's staleness anchor) reads that clock.
- **Flag** — `delta_session_offer` added to `SAFETY_FLAG_DEFAULTS` (False): no reviewed
  copy for the offer exists.
- **No migration.** The lifecycle is a plain `visit.lifecycle` slot on the session row —
  INT-134/INT-306's precedent — so no table or column is added and the erasure graph is
  unchanged; the history of moves is the audit chain. `uv run alembic heads` →
  `0013_previsit_output (head)`.

## Reading of the diagram (flagged, not re-litigated)
The §2b diagram draws the happy path; its rules call the T-24h confirm *"the only cheap
correction we get on the OCR value"* — a correction channel, not a gate on arriving. The
table therefore lets a `planned` visit do everything a `confirmed` one may (check in,
attend without check-in, cancel, reschedule, miss) plus confirm; `checked_in` leads only to
`attended`; `attended`, `cancelled`, `missed` are terminal; `rescheduled` lands in `planned`.
At P1 no confirm can be sent at all (INT-358), so a strictly-drawn table would strand every
visit in `planned`. `attended` and `missed` are in the machine but not on the patient route.

## Needs a human (no value invented)
1. **Delta-session offer copy** — clinical review. files/02 §2b quotes *"Geçen sefer
   anlattıklarınızdan bu yana bir değişiklik var mı?"*; no reviewed `tr` resource exists,
   so `delta_session_offered` stays False behind `delta_session_offer` (safety flag) until
   the string is reviewed and added under `tr`.
2. **T-24h confirm body** — clinical + legal. The spec's example names the day, hour and
   department; INT-141's content-free catalogue forbids that on a lock screen. The confirm
   is queued with no body; sending also needs the SMS vendor (INT-358).
3. **`missed` grace** — files/02 names none; the machine refuses `missed` without an
   owner-set grace, and no scheduler applies it yet.
