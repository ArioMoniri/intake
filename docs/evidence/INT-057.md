# Evidence — INT-057 · Protocol Authoring Agent: L0 drafts for every branch + no-serve guard

## Scope

Acceptance, verbatim: "`protocols generate-l0 --branch <id>` scaffolds from
cluster+template with citation placeholders resolved to named Turkish
guidance sources; L0 resolution for a live session raises; regeneration
idempotent" and "agent has zero access to patient data (import-boundary
test)". Test: tests/protocols/test_l0_guard.py.

## What was built

- `packages/protocols/src/protocols/authoring.py` — the Protocol Authoring
  Agent's deterministic scaffold generator (files/09 §2 L0 row). One L0
  draft per intake branch under `packages/protocols/specialty/<id>.yaml`:
  `extends` the branch's cluster pack id from `taxonomy/branches.yaml`,
  a generic visit-context section whose every slot carries
  `ask_tr`/`follow_up_tr` (files/09 §2), and exactly one red-flag entry —
  a `draft_needs_source` stub whose `when` is the invariant-17
  sole-exception form and whose enum fields sit on the schema's lowest
  rungs (YESIL / EXPEDITE), asserting nothing clinically. No clinical value
  was invented anywhere; red flags arrive only through the `extends` chain
  once the clinician-authored cluster packs land (P1).
- Citation resolution: the scaffold names the Turkish guidance sources the
  blueprint itself names — `T.C. Sağlık Bakanlığı klinik protokolleri /
  HSGM rehberleri` (files/09 §2 "MoH clinical protocols"), `ilgili uzmanlık
  derneği kılavuzları` (files/09 §2 "Turkish specialty-society
  guidelines"), and the EK-4 Tebliğ, RG 13/9/2022 sayı 31952 (files/04 §3,
  binding for acuity). files/04 and files/09 name **no cluster-specific
  guideline title for any of the eight intake clusters**; each scaffold
  states that verbatim instead of inventing one (files/04 §8.1 rule 3), and
  the eight clusters are listed below as awaiting-human content.
- `protocols generate-l0` CLI (`--branch <id>` | `--all`): refuses unknown
  branches (fails closed via `UnknownBranchError`), refuses the excluded
  cluster (Acil Tıp — no intake pack may exist, files/09 §1 row 9), never
  overwrites a pack promoted beyond L0 (`PromotedPackOverwriteError`;
  `--all` leaves promoted files untouched), and regenerates byte-identically
  given the same taxonomy + template.
- 91 L0 drafts committed (every intake branch of the 92-branch taxonomy;
  `acil_tip` gets none). The tree-wide `protocols coverage` matrix stays
  91 MISSING / 1 EXCLUDED — an L0 draft never counts as coverage
  (INT-042 semantics, re-pinned here over generated packs), and
  `resolve_branch` on the committed tree raises `L0PackServedError`
  (CLAUDE.md invariant 13).
- Compiler refusal pinned, not re-implemented: `pack_compilable` (INT-040)
  reports the stub in `excluded_rules` and `fully_compilable == False`;
  generation self-checks that refusal and fails closed if the template ever
  drifts to a servable stub.
- Import boundary (files/09 §7: the authoring agent "has no access to
  patient data at all"): AST scan over every module of the protocols
  package with an import allow-list (stdlib + protocols, yaml, pydantic,
  clinical_schemas type definitions) and an explicit deny-set
  (intake_api, connectors, services, apps, voice_runtime, httpx,
  sqlalchemy, …) — enforced by test, not convention.
