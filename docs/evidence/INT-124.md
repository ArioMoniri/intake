## 1. The guard — `intake_platform.records.unit_guard`

One deterministic function, `guard_lab_value(printed_name, printed_value, printed_unit, table)`,
returns a `LabValueVerdict`: the magnitude **exactly as printed** (equal *and* with the printed
exponent, so `12500.00` stays `12500.00`), the unit token **exactly as printed**, the unit an
authored expectation names, and a set of typed `GuardFlag`s. A flag in `STOP_FLAGS` means no
number came out. No model is involved, and the verdict's `repr` names only its flags
(invariant 6).

| behaviour | how it is held | near-miss control |
|---|---|---|
| **Magnitude outranks the printed unit token** | ALT `30 U/mL` against a `U/L` expectation → `{unit_conflict}`, magnitude `Decimal("30")` with the same `as_tuple()`, unit still `U/mL`. Inside the band the magnitude is believed; outside it both flags fire and it is still not rescaled | the same line in `U/L` is clean |
| **Disagreement flags, never converts** | `unit_guard.py`, `numbers.py` and `analytes.py` contain no `*`, `/`, `//`, `**`, `%`, `@` operator and no `scaleb`/`shift`/`quantize` — an AST test. Code that cannot do arithmetic cannot convert | — |
| Unit comparison is byte equality after trim | `µ` U+00B5 vs `μ` U+03BC is a conflict (files/03 §4.9.6 keeps them distinct) | the same code point is clean |
| **`üre` is never substring-matched** | `analyte_key` resolves the whole token sequence under Turkish casing (`İ`→`i`, `I`→`ı`): `Üre`→`urea`, `Üre Nitrojeni`/`ÜRE NİTROJENİ`→`bun`, `KREATİNİN`→`kreatinin`. The expectation follows the analyte: `Üre Nitrojeni` is checked against BUN's row | `Üre Nitrojeni` against Üre's row is a conflict; `Üremi`, `ÜREMİ`, `Serum Üre`, `Üre (serum)`, `BUN/Kreatinin` are flagged `analyte_ambiguous` and **not read** |
| A table cannot smuggle a near miss | table keys go through the same `analyte_key`: `Üremi` cannot be a key, and `BUN` + `Üre Nitrojeni` are one analyte, so both at once is refused rather than overwritten | — |
| **Separator resolved per value** | `8,4`, `4.5`, `0,08`, `0.123` on one page each resolve. A form that reads two ways (`1.500`: 1.5 or 1500) is decided by the expected magnitude band only when exactly one reading lies in it; the printed unit takes no part | the same `1.500` on one page reads 1500 for one analyte and 1.5 for another; a band admitting both or neither stops |
| **Five-digit result with a thousands separator** | `12.500,00`, `12.500,0`, `12,500.00` parse exactly with no table; bare `12.500` / `12,500` read as 12500 under a band near ten thousand | under a band near twelve they read 12.5; with **no** band they **stop** and are never read as 12.5 |
| **A two-number cell stops the parse** | `3,33 - 5,55` (files/03 §4.9.6's mis-aligned glucose column), `3.33–5.55`, `8,4 - 10,2`, `70-110`, `70 / 110`, `12 500` → `two_number_cell`, no magnitude; never 4.44, never 3.33, never 5.55; a band containing the mean does not rescue it | a signed single number (`-5`, `+5`) is one number |
| Bounds and unreadable shapes stop | `>100.000`, `<5`, `≤ 2.5`, `≥ 13.0` → `bound_not_magnitude`; `Negatif`, `45.`, `1,2,3`, empty → `unreadable`; no value → `value_absent` | — |

### The expectation table ships EMPTY — the source of analyte ranges is nobody yet

I searched `docs/` (incl. `docs/sources/`), `packages/clinical-schemas`, `packages/protocols`
(incl. `lexicons/`, `specialty/`) and `files/` for a committed, cited analyte → unit or
analyte → magnitude table. **There is none.** The only analyte-unit facts in the repository
are the two worked errors files/03 §4.9.6 quotes (ALT/AST printed in `U/mL`, Total Protein /
Albümin printed in `mg/dL`), which are evidence that a printed document cannot be its own
authority, not a table. HUMAN_BLOCKERS.md **HB-C24** (open since 3 Sep 2026) is exactly this
ask, owned by the physician of record with a clinical biochemist.

So `SHIPPED_EXPECTATIONS` is empty and the guard **fails closed**: every value is flagged
`no_expectation`, and a two-way form stops instead of being cross-checked against a band
nobody authored. `AnalyteExpectation.source` has no default and `SourceCitation` requires the
red-flag source shape `{guideline_id, version, date, url (https), retrieved_on}`, so a row
cannot land without its citation. Every test that needs a row uses a **test double** whose
analytes (`Analit A`), units (`birim-a`) and citation (`https://example.invalid/…`) cannot be
read as clinical content; the one real analyte given a row (ALT, unit `U/L`, the unit files/03
§4.9.6 states and INT-121's suite already uses) gets an unbounded band so the test says nothing
about a normal ALT. HB-C24's row and `docs/backlog/blockers.md` are updated to say the guard now
fails closed rather than merely reporting itself unchecked, and that the answer needs the
magnitude band too.

### Wired into INT-121's parser, opt-in

`extract_record_items(..., guard=table)` gives every lab item a verdict (`DocumentExtraction.verdicts`,
aligned with `items`; `flagged` lists the positions). A stopped value keeps its box and loses
its number; a near miss on `üre` is one flagged row instead of a lost document. `unit_conflict`
on the item mirrors the guard flag, so the FHIR `unit-conflict` extension still carries it.
Passing both `guard` and `expected_units` is refused. **Without `guard`, INT-121's behaviour is
byte-for-byte what it was** — its 139-test suite and INT-122's pass unchanged.
`parse_printed_magnitude` now delegates to a new `magnitude_readings` (one parser, not two):
the two-way form comes back as both readings for the guard to choose between, and
`parse_printed_magnitude` still refuses it.

## 2. The adapter — `intake_platform.records.lab_extraction`

On INT-083's pattern (ADR-006), below the voice runtime in the dependency graph because
`services/api` does not depend on it.

- **The seam:** `LabExtractionGateway.complete(call) -> LabCompletion`, synchronous.
- **JSON-schema-constrained decoding:** `lab_extraction_schema()` is derived from INT-121's
  `ITEM_KEYS` / `TOP_LEVEL_KEYS`, closed at both levels, every key required (strict mode),
  `printed_*` typed string-or-null and **never a number** (the separator is the guard's to
  resolve), `kind` / `code_system` enums from the record types, no level-shaped key anywhere.
  The self-hosted request sends it as `response_format: {type: json_schema, strict: true}`.
- **Data, never instructions (invariant 14):** `build_lab_instructions(json_schema)` takes one
  parameter; the instructions are English and carry no Turkish letter (a permanent leak check);
  the document reaches the model only inside `intake_platform.data_boundary`'s fence, each
  region under its `[i]` index so a completion can point at a region and carry a box; a region
  carrying the control token refuses the document whole.
- **Recorded lane (CI, no-GPU dev):** a recording is addressed by
  `sha256(schema_id, prompt_version, sha256(instructions), document_sha256)` and re-states all
  three plus the model it is attributable to; drift, a missing model, a non-string completion or
  a non-object is refused, and a missing recording is never synthesised.
- **Self-hosted lane:** OpenAI-compatible `/v1/chat/completions` on our endpoint; a vendor host
  (derived from `VENDOR_LLM_DOMAINS`, never written down) is refused before any client exists;
  an HTTP error or a malformed body is `LabExtractionUnavailable` and echoes nothing.
- **PHI path fails closed, no fallback (invariant 19):** the gateway refuses a pin that is not
  PHI-ready, and `lab_extraction_gateway_from_env` with an endpoint runs the row-9 gate —
  which **refuses today** (`Row9NotServed`, naming INT-381) — and returns nothing in its place.
  The near miss (the same registry with `self_hosted_now: true`) wires the self-hosted lane.
- **Off the spoken loop:** no module under `services/voice-runtime/src` imports
  `lab_extraction`, `lab_model` or `unit_guard` (an AST walk), and nothing on the lane is a
  coroutine.
- **The fixture "eval corpus"** — `tests/fixtures/lab_extraction/handbook_page.json` — is a
  synthetic page that says so in its own `about` field: ALT printed `U/mL` (the wrong unit
  string), `Lökosit 12.500,00` and `Nötrofil 10.250` (five digits with a thousands separator),
  `Glukoz 3.33–5.55` (the two-number cell), `Kalsiyum 8,4` beside `Potasyum 4.5` (mixed
  separators on one page), `Üre` / `Üre Nitrojeni` / `BUN`, and a `>1.000` bound. Its
  completion is authored to the contract and stands in for a recording until INT-381 records
  one; the committed per-row expectation is the verdict under the shipped table. **It is not an
  accuracy corpus, no ratio is computed over it and none is reported (invariant 20).**

## 5. What is deliberately absent

- **No latency figure and no live call.** Row 9's "< 3 s" is INT-381's measurement on the
  target GPU. Nothing here was run against a model, and the self-hosted lane is exercised only
  against `httpx.MockTransport`.
- **No expectation table content.** HB-C24. The mechanism ships and fails closed.
- **No accuracy figure.** INT-380 owns the corpus score, and its harness still refuses without a
  named, dated corpus (HB-A13).
- **No REST route or worker task.** Nothing calls `extract_lab_report` in production yet: with
  the PHI gate refusing, a route would only ever return the refusal. The seam, the pin and the
  guard are what a route will call once INT-381 serves the model.
- **No change to INT-121's non-guard path.** `extract_record_items` without `guard=` behaves as
  it did, including refusing a document on a near-miss analyte.
- **Observed, not fixed (INT-121's renderer):** `render_quantity` writes a decimal point, so a
  magnitude that keeps printed precision renders as, e.g., `12.500` for twelve and a half — the
  string a Turkish reader takes as 12500. It only arises for a band-resolved decimal reading of a
  three-decimal print, which cannot happen while the table is empty, and the confirm card's
  rendering belongs to INT-121/INT-138.
