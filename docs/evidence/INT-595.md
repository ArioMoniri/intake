## 1 · How the Languages row is derived

- **Apple, Technical Q&A QA1828**, "How iOS Determines the Language For Your App". The page was
  updated 2016-03-23 and retrieved 2026-10-31 from
  https://developer.apple.com/library/archive/qa/qa1828/_index.html. It is an archived page.
  - The App Store's Languages field is "determined by the existence of .lproj folders in your app
    bundle". It does not come from the App Store Connect configuration.
  - Only an app that keeps no `.lproj` folders falls back to `CFBundleLocalizations`.
  - At run time, when none of the reader's preferred languages is offered, iOS chooses the
    development region (`CFBundleDevelopmentRegion`).
- **Expo** writes one folder per locale key. `@expo/config-plugins` 57.0.9,
  `build/ios/Locales.js` (line 63), writes `<lang>.lproj/InfoPlist.strings` for each key of
  `expo.locales`.

## 2 · Which .lproj folders ship

- **Build 7's EAS IPA: not downloaded.** Downloading a build artifact needs the owner's own OK,
  and no agent message can give it. Acceptance 1 stays open until the owner either gives that OK
  or accepts §2's local evidence.
- **The same commit, built locally.** For the INT-502 capture, main `690a16bb` (build 7's sha)
  was built as a Debug app on 2026-10-31 and installed on the capture simulator. Its bundle was
  read in place, with nothing downloaded:
  - top-level `en.lproj` and `tr.lproj`, each holding `InfoPlist.strings` only;
  - no other `.lproj` within three levels;
  - `CFBundleDevelopmentRegion` is `en`, and there is no `CFBundleLocalizations`;
  - the base Info.plist camera and microphone strings are Expo's English defaults.
  - Debug and Release builds run the same prebuild, so `expo.locales` sets the same folders in
    both.
- **Conclusion.** `en` ships, so the App Store would list English.

## 3 · What changed

- `apps/mobile/app.json`: `expo.locales` holds `tr` only. `ios.infoPlist.CFBundleDevelopmentRegion`
  is `tr`.
  - Before this change, a reader whose language the app does not offer fell back to `en`.
  - Without `en.lproj`, that fallback would name a language the binary no longer carries, and
    the base Info.plist holds Expo's English defaults.
  - With the region set to `tr`, the fallback is the one language the binary carries, so the
    purpose strings stay Turkish for every reader.
- `src/locales/app-en.json` stays. The purpose-string and store-label suites still read it as the
  English catalogue, and it comes back into `expo.locales` when HB-O5 brings a second language.
- `apps/mobile/plugins/withVoiceAudio.js`: the comment no longer says the microphone string is
  localised through app-en.json.
- Backlog: the INT-595 row is added (the id was minted by the orchestrator), the pins go from
  386 to 387, and files/11 is regenerated.
