# Evidence — INT-306 · The schema records a visit DATE and the expiry rule needs a visit DATETIME

Epic E02-data · phase P1 · `sec_row: visits` · `depends_on: []`.

files/02 §2b pins Doctor Link expiry to `visit_datetime + 72 h` and says in terms that
`issue_time + 72 h` is the wrong clock — *"the single most likely cause of 'the doctor
couldn't see it' at P1"*. This repository recorded a `visit.date` slot and no hour, and
two issues reached that gap from opposite ends:

* **INT-150** could not compute the expiry its own spec states, and took the conservative
  approximation — anchor to the START of the visit day in Türkiye, which is never later
  than the appointment and therefore never later than the spec's value — refusing an
  undated visit outright rather than falling back to an issue-time clock.
* **INT-122** parsed an appointment TIME off an MHRS message (`find_printed_time` has
  worked since that issue landed) and `as_visit_fields()` dropped it, because
  `POST /v1/visits` had no field to put it in.

This issue is the field they were both missing.

## 4. Acceptance, clause by clause

### 4a. *"the slot carries a time of day where one is known, and states that it is unknown where it is not"*

`VisitSchedule.time` is `VisitTime | None` and the store writes **no `visit.time` row** for
a visit whose hour nobody stated. `VisitOut.time` is `None` for it. The acceptance names
its own failure mode — *"a default midnight is indistinguishable from a real 00:00
appointment and silently shortens every link by up to a day"* — so it gets the near-miss:

* `test_a_real_midnight_is_not_the_absent_time` — a `00:00` booking stores
  `{"time": "00:00", "source": "patient_entry"}` and an unknown hour stores nothing. An
  implementation that defaulted to `time.min` passes every expiry assertion in the
  repository and fails this one.
* `test_a_midnight_appointment_shares_the_fallback_instant_and_not_its_record` — the two
  anchors *do* coincide at `00:00`, and that is correct: it is the same instant. The
  assertion is that the RECORD does not.
* `test_a_timed_visit_issues_a_longer_link_than_the_fallback` — the same calendar day, one
  visit at `23:30` and one with no hour, end to end through `POST /v1/visits` and
  `POST …/doctor-links`: the two expiries differ by exactly **23 h 30 min**. That is the
  "up to a day" the clause names, measured rather than asserted.

An empty or whitespace `time` field is `bad_time`, not "absent": a client that sends the
field is asserting it has a value, and reading that as unknown is how a dropped field
becomes a shortened link.

### 4b. *"every producer of a visit time is enumerated and each says which it is"*

`VisitTimeSource` is closed over exactly the three the issue names, asserted by
`test_the_producers_are_a_closed_set_of_three`. Each has a working door, and
`test_every_enumerated_producer_has_a_working_door` is **parametrised off the enum
itself**, so a member added without a path that can write it fails there rather than
sitting in the vocabulary as a provenance nothing produces.

| member | producer today |
|---|---|
| `patient_entry` | `POST /v1/visits` with the patient's own `time` |
| `connector_field` | **no producer in this repository yet.** The member and its door exist so the first MHRS/e-Nabız connector inherits this vocabulary instead of minting a second one; `test_a_connector_time_round_trips_with_its_artefact` exercises the door. |
| `document_extraction` | INT-122's `parse_mhrs_sms` → `confirm_visit_candidate` → `as_visit_fields()` |

*"an extracted time carries the same provenance an extracted value carries elsewhere,
never arriving unattributed"* is carried by the **type**, in the shape
`record_extraction.SourceBox` and `overlay.Confirmation` already use: `source_ref` is
required for both non-patient sources, so an unattributed extracted time is not a case to
reject at a boundary — it cannot be written down. `as_visit_fields()` **derives** both
provenance fields from the candidate's own `document_ref`, for the same reason
`confirm_visit_candidate` takes no `by=`: a caller who could pass provenance in could pass
a different one.

Both near-miss directions are held, so neither "always require a ref" nor "never require
one" survives:

* `test_a_time_read_off_an_artefact_cannot_be_written_down_unattributed` —
  `DOCUMENT_EXTRACTION` and `CONNECTOR_FIELD` with no ref, and with a whitespace-only ref,
  both raise; and `test_the_api_refuses_an_attributed_source_with_no_ref` is the same rule
  at the wire boundary.
* `test_a_patient_entry_may_not_borrow_an_artefact` (and
  `test_the_api_refuses_a_ref_the_patient_typed_a_time_for`) — a ref attached to a time the
  patient typed is refused, because it would claim an artefact was consulted.

**The API takes the producer's declaration rather than deriving it, and that is deliberate
— it is not INT-133's `proxy_reported` case.** That flag is a *consequence* the platform
rules engine computes from facts the client declares, so a client-settable one would be
client-clearable. Where a time was read is not a consequence of anything the server holds:
only the producer knows. What makes the claim checkable rather than free is that the two
non-patient sources must name the artefact. `test_an_unknown_producer_is_refused` closes
the string bypass — the accepted set is the enum, not "whatever was sent".

### 4c. *"INT-150's approximation is replaced rather than duplicated"*

`link_expires_at` now takes a `VisitSchedule`, not a `dt.date`. That is the *replaced*
half: there is no overload, no `visit_time: … = None` default a caller could forget, and
no second function. `mypy --strict` refuses the old call shape at every call site, so the
approximation cannot be re-entered by accident.

The fallback is kept and documented in the module docstring, on the router and in the
function itself. The clause asks for **a test asserting the fallback is never LATER than
the true appointment**, and it is stated as a property rather than a sample:

```python
# tests/clinician/test_doctor_link.py::test_the_fallback_is_never_later_than_the_true_appointment
for hour in range(24):
    for minute in (0, 1, 15, 30, 45, 59):
        assert fallback <= exact
        assert (fallback == exact) is (hour == 0 and minute == 0)
```

144 minutes across the whole day. The second assertion is what makes it a gate rather than
a description: it pins *where* the two coincide, so an implementation that quietly ignored
the recorded time — and therefore satisfied `fallback <= exact` everywhere — fails on the
first non-midnight minute.

`test_a_recorded_visit_time_is_the_anchor` pins the arithmetic against
`Europe/Istanbul`: 2026-09-20 14:30 +03:00 is 11:30 UTC, plus 72 h is
2026-09-23 11:30 UTC. `test_the_fallback_anchor_is_the_start_of_the_visit_day_in_turkiye`
keeps INT-150's original assertion, renamed to say which of the two rules it is.

**An unknown hour is still not a refusal, and an unknown date still is.** A date is the
whole anchor; an hour only sharpens it. `test_a_visit_with_no_date_gets_no_link`
(`visit_date_unknown`, unchanged) and `test_a_dated_visit_with_no_time_is_still_created`
hold the two halves of that apart — the second is the positive control that the INT-150
path this issue built on top of was not broken by building on it.

## 5. Invariants

* **17** — nothing was postponed and nothing was faked. The `connector_field` member has
  no producer today and that is written down here rather than papered over with a stub
  connector; the member is a real, reachable value with a working door, which is why it is
  not a placeholder. No `TODO`, no skipped test, no commented-out code.
* **18** — no new table, no new column, therefore no new inventory annotation. The visit
  hour is operational metadata about a booking the patient already told us the date of;
  it is stored in the same `slots` row shape and under the same `PLAIN` sensitivity as
  `visit.date`, and it inherits that row's retention.
* **22** — the whole spelling half of this issue. `HH:MM`, 24-hour, zero-padded, minute
  resolution, positional digits, one atom, no grouping separator, and exactly one accepted
  spelling: `9:30`, `14:30:00`, `24:00`, `14:60`, `2:30 PM`, `14.30`, `1430` and `""` are
  all `bad_time` (`test_a_time_that_is_not_hh_mm_is_refused`). `time.fromisoformat` is
  deliberately **not** used — it accepts `14:30:00` and `14:30:00.5` for the same minute,
  and two spellings of one value at a representation boundary is how a value changes
  meaning on the way across. The time carries no timezone and no seconds
  (`test_a_visit_time_is_a_civil_time_with_no_zone_and_no_seconds`): the zone belongs to
  the visit's calendar date and is applied once, in `link_expires_at`.
* **6** — no refusal message names a time, a date or a line of a document. `VisitTimeError`
  and the six `visit_invalid` reason codes name the rule; the 422 body carries the code
  only. `source_ref` is an id (`document:…`, `mhrs:appointment:…`), never a reading.
* **8** — no coverage floor moved. The new module is exercised by both suites.
* **4** — untouched: the visit routes' `core` scope check and the doctor-link routes'
  `share` scope check are where they were, and every create/read still appends its
  hash-chained audit entry.

## 6. What was reported rather than fixed

* **No mobile surface.** `apps/mobile/src/app/(tabs)/visits/new.tsx` has no time input, so
  a patient still cannot type the hour in the app; the API door and the extraction path
  are what this issue's acceptance names. Two other lanes own the `app/**/*.tsx` screens in
  this run, so the screen was deliberately not touched. The client's
  `VisitValidation` reason union in `apps/mobile/src/lib/visits.ts` covers
  `missing_fields | bad_date` only — the seven new codes fall to its generic branch, which is
  correct today because the app sends no time and therefore cannot provoke one.
* **No connector producer.** `packages/connectors` has no FHIR `Appointment` and no MHRS
  client, so `connector_field` has a door and no caller. Inventing one would have been
  authoring a connector inside a schema issue.

## 7. The coverage lane that caught the test split

The first full `make check` failed, and the failure is worth writing down because it is a
real property of this repository rather than an accident:

```
packages/clinical-schemas/src/clinical_schemas/visit_time.py    42   42   12    0     0%
TOTAL                                                         1619  159  360   26    89%
FAIL Required test coverage of 90% not reached. Total coverage: 88.83%
```

`make check-py`'s third lane runs **`tests/schemas` alone** against
`--cov=packages/clinical-schemas/src --cov-fail-under=90`. The new module's tests lived in
`tests/api` and `tests/clinician`, so that lane saw 42 uncovered statements and the total
fell below the floor. `record_extraction.py` shows the same 0 % for the same reason — its
tests live in `tests/records`.

The fix was to put the module's own unit tests where its coverage lane can see them:
`tests/schemas/test_visit_time_vocabulary.py`, which is also the more honest home for
them — they need no API, no harness and no database. **The floor was not touched**
(invariant 8), and the five type-level assertions were moved rather than duplicated, so no
assertion exists twice.

The second attempt then failed on a `basename` collision — pytest imports test modules by
basename with no package, so `tests/schemas/test_visit_time.py` and
`tests/api/test_visit_time.py` cannot both exist. Hence the `_vocabulary` suffix. Recorded
because the error message (*"imported module 'test_visit_time' has this `__file__`
attribute"*) reads like a broken install rather than a naming rule.
