# INT-235 — Voice chat surface, realtime section panel, ask-ahead engine

Owner directive (verbatim): "it says yaziya dokuluyo but should be a ui
like the ones u got from mobbin and oura like a voice chat interface to
see what are each side telling and parse in realtime to different muayene
sections like allergy sign symptoms so on and make a dialogue with the
patient and then go on if needed with text based qs and if not just
complete previsit".

Owner feedback mid-iteration (relayed): the INT-233 rhythm "waits for
'soru hazırlanıyor'" and is slow — the coordinator sanctioned reducer
surgery for ask-ahead/reconcile-behind (the blueprint IntakeEngine's own
pattern, 02/INT-081), session-start clip pre-warm, and a ChatGPT-like
transcript with in-place bubble states and an always-present composer.

## What shipped, honestly (two TDD cycles)

**Cycle 1 — conversation surface over the INT-233 blocking engine**: chat
transcript UI, section panel view model, multi-question extract, i18n.

**Cycle 2 — ask-ahead surgery (owner feedback)**: the stream engine was
rewritten so the turn NEVER waits on transcription/extraction:

- `lib/dialogue/stream.ts` — `dialogueStreamReducer` v2: `utterance`
  advances the turn the instant the mic closes; each utterance's
  transcribe→extract pipeline reconciles behind, addressed by work id
  (`transcript_ready` replaces the patient bubble IN PLACE;
  `extract_settled` fills sections as pending suggestions; per question
  the NEWEST work id wins, late older results are dropped). Advance skips
  answered and already-asked questions; a question whose suggestion has
  landed gets a quick spoken CONFIRM turn (candidate pre-selected, one
  tap, no wait) — retroactively too, once its result arrives during the
  end wait. `typed` is the same utterance path (voice and text are one
  conversation). The one honest wait is `settling` at the END while
  in-flight work drains; then all-answered → `done` → review (the
  owner's completion rule), anything left → `handoff`.
- The dev packs carry no answer-gated questions (no askIf), so no
  mid-flow block exists to encode; if compiled packs (INT-096) introduce
  gating, the advance rule is the single place a gate would wait.
- `lib/dialogue/useDialogueSession.ts` — pre-warms the WHOLE session's
  scripted clips in parallel at mount (question clips + the generic text
  confirm clip); `createClipStore.ensure` gained an in-flight memo so the
  pre-warm and the speaking driver share one synthesis per clip. Extract
  failures are SOFT in ask-ahead (settle empty — extraction is
  enrichment); a broken ASR/TTS lane stays a hard failure into the
  manual steps with the honest notice.
- `components/DialogueIntake.tsx` — the transcript surface: agent turns
  as quiet left surface bubbles (question TEXT appears instantly; audio
  catches up — never a spinner without content), patient turns as tonal
  right bubbles born at the mic and replaced in place by the ASR text;
  listening pulse, "Yazıya dökülüyor…" shimmer and the settling row live
  INSIDE the stream. Barge-in unchanged: tapping the speaking bubble
  stops playback in the same JS tick. The persistent composer (surface
  input pill + bone send circle) makes typing always available — no mode
  switch; the old per-step "typing" phase died with it.
- `components/SectionPanel.tsx` + `lib/dialogue/sectionPanel.ts` — the
  "Not oluşuyor · x/y bölüm" strip on the glass bar (GlassBar gained a
  non-floating mode, additive prop) expanding to the muayene-section
  sheet: labels are PACK-driven (`hpiLabelKey`, buildNote's exact
  complaint/extra mapping — never a hardcoded list), rows fill in
  realtime with the chosen option labels + the patient's verbatim quote
  as provenance; suggested rows carry the labelled "Onaylayın" chip.
- `lib/intake/voiceFirst.ts` — the outer machine accepts the dialogue's
  hand-over: leftover unconfirmed suggestions arrive in the manual steps
  as prefill (empty leftovers are NOT a failure there — the patient just
  answers the remaining questions fresh). One existing assertion changed
  with this semantic (the old test pinned `candidates` as a no-op from
  the dialogue phase — that IS the surgery, documented here).

The INT-233 single-question engine (`lib/dialogue/turn.ts`) is untouched
and its 18 tests stay green as the reference for the blocking per-turn
machine; the app surface now drives the ask-ahead stream engine.

Invariants held: 1 (candidates are suggestions; the only commit paths
are the chat confirm turn, the panel-row confirm, and the manual steps

Allergy, for the record: the packs do not ask allergies today. Adding an
allergy anamnesis question is CLINICAL CONTENT and belongs to the pack
owners (packages/protocols lane), not this UI iteration — the owner's
word "allergy" is recorded here so the pack owners see it. The panel
shows the pack's own sections plus the profile-derived meds line exactly
as buildNote does; nothing clinical was invented.

## Deviations

- No simulator pass: the shared simulator was owned by other lanes this
  session (hard boundary), so the surface shipped on the reducer/view-
  model tests, typecheck and lint; the next design pass should
  screenshot the chat beside the Tolan/Cleo/ChatGPT captures as passes
  4–6 did.
- Extraction now runs against every remaining unanswered question per
  utterance — heavier per call than INT-233's single-question hop, but
  off the conversation's critical path by construction (ask-ahead).
- In ask-ahead there is no per-utterance spoken confirmation for a
  question answered while later questions are already being asked; its
  confirmation arrives as the quick confirm turn when the suggestion
  lands (usually one or two turns later), as a panel-row tap, or in the
  prefilled manual steps after handoff — never silently.
