# INT-354: consolidate int-demo into main (plan and slices)

GitHub #560 · Sec-Row `mobile` · this file lives on `main`. A separate, branch-local
`docs/evidence/INT-354.md` exists on `int-354-build-source` (`2c662f12`). That one records
the TestFlight build source, which never targets main. This one records how every int-demo
commit reaches main, or why it does not.

INT-354 stays **open** until every slice below has landed or been dropped with its reason.
This file is a plan, so it carries no red or green run of its own. Each slice's runs live in
that slice's own evidence file.

## Plan

**Scope.** `git log --no-merges origin/main..origin/int-demo` at `origin/int-demo` =
`82c1a1e6` and `origin/main` = `04c7be9d` on 2026-09-27: **26 commits**. The only merge in
that range, `94e5aed3`, brings main into int-demo and carries no content of its own.
`git cherry -v origin/main origin/int-demo` marks all 26 `+`, so none is on main by patch
id. Each one was also checked **by content**: its feature's files and symbols were grepped
on `origin/main`. The "on main?" column below records that check.

**Rules applied (CLAUDE.md "How we work", audit 2026-09-26 §6 item 15).**
- One issue per PR. A slice is one issue and one PR. `wip(...)` commits are squashed into
  Conventional commits, and the red run keeps its own commit.
- Demo-scoped code never reaches main (INT-354 acceptance 2; audit F06, F21):
  - hardcoded connector refs;
  - a demo-tier recipient overlay;
  - a guide that tells a hospital engineer to use the dev admin bearer.

  Such code is either dropped or rebuilt against the registries before it lands.
- A vendor lane that is not self-hosted does not land while its vendor decision is open
  (invariant 19; INT-319 `approval:human-vendor`; audit F24). The bundled clips are scripted
  question text, not patient speech. Even so, the vendor terms and the unsigned copy
  (HB-C1) are human decisions.
- **Ids.** No agent mints an id (memory: parallel agents collide; audit F23). INT-317 and
  HB-A18 were filed on int-demo on 2026-09-04 (`56e8c19b`). Before they were carried, a
  check found no other use of either id on main, on any remote branch (a scan of every
  `origin/*` `issues.yaml` and `HUMAN_BLOCKERS.md`) or in any GitHub issue or PR.
  INT-318 is cited by int-demo code but has **no backlog row anywhere**. The owner confirms
  INT-318, and allocates the ids the mobile slices need, before those slices open.
- **Migrations.** `0013_previsit_output` is the only `0013` on any remote branch. It
  revises main's head `0012_int150`, and `uv run alembic heads` prints one head.
- **Owner's working tree.** The rebrand files in the main checkout (`apps/mobile/app.json`,
  `icon.png`, i18n, locales, `vizite-logo.svg`, `eas.json`) hold uncommitted owner edits
  and are not touched. The rebrand slice is owner-held.
