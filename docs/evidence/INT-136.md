## 3. The heart of it: "rendered verbatim" when there is nothing to render

CLAUDE.md invariant 10 covers validated instruments; files/04's header adds the clinical
half (`allow_paraphrase: false`, response options presented verbatim, and *"an LLM may not
infer a score from narrative"*). The question this issue had to answer is what a mobile
surface does with that today, and the answer is fixed by three facts already in the tree:

1. **No verbatim Turkish instrument item exists anywhere in this repository.**
   `packages/protocols/base/intake.yaml` says so in its own comment at the `screening`
   section — *"Instrument ITEM text is not authored here: the verbatim Turkish items belong
   to the instrument engine (INT-116), and an item reworded by anyone is no longer the
   instrument its validation refers to"*. `packages/protocols/src/protocols/licences.py`
   says the same of itself: *"no instrument content (items, wording, scoring) exists
   anywhere in this package"*.
2. **C-SSRS and WHO-5 are licence-BLOCKED** (HB-L2: Clario holds the exclusive RFMH
   electronic licence; HB-L3: CC BY-NC-SA 3.0 IGO, NonCommercial, with a ShareAlike
   copyleft that reaches a mobile re-layout). **HAQ-DI is NEEDS_PERMISSION** — Stanford's
   permission covers the English version only, and the Turkish translation is the open item.
3. **PHQ-2 and GAD-2 have no Turkish validation at all**, the PHQ-9 Turkish evidence is a
   reliability study only, and GAD-7's Turkish cut-off is 8 — none of which may appear as a
   claim in patient copy (invariant 20).

So the delivered state is HUMAN_BLOCKERS Rule 2 applied exactly: **the mechanism is built,
the gate is wired, it fails closed, and the content is left empty.** `INSTRUMENT_ITEMS` is
`{}`. `instrumentOffer` returns `null` for all seven registered instruments. The wellbeing
screen — which files/02 §4 makes the WHO-5-family space — asks the registry and is refused,
so it renders no instrument frame, no heading and no apology. The day a licensed
instrument's items are committed, that surface renders them byte for byte with no other
change.

**The licence check runs before the content check, always.** Checking content first would
let a BLOCKED instrument with no items report `items_not_authored`, and the refusal would
silently change meaning the day someone authored them. The spec pins the ordering by handing
`resolveInstrument` a full synthetic item set for each of C-SSRS, WHO-5 and HAQ-DI and
asserting the reason is still `licence_not_go`.

**Verbatim is asserted as byte-identity, not similarity.** `resolveInstrument` returns the
authored objects *themselves* — the spec uses `toBe`, not `toEqual`, on the item, on
`textTr` and on `choicesTr`, so a resolver that rebuilt the record (and was therefore free to
trim, re-case or normalise) would fail even though every field matched. The discriminating
negative control is the same Turkish sentence in NFD: visually identical, byte-different, and
the assertion rejects it. The renderer is held to the same line from the source side — it
contains `{item.textTr}` and none of `.trim()`, `.normalize(`, `.toLocaleUpperCase(`,
`.slice(`, `.replace(`, a line cap or `textTransform`.

**Item text is not a catalog string, and that is a rule rather than an oversight.** A
`MessageKey` would give every item an `en` mirror maintained beside the Turkish — a
translation this project has no rights to make (files/04: a translation is an *işlenme eser*
with its own rights holder under FSEK 5846) and a paraphrase surface invariant 10 forbids.
The spec asserts `instruments.ts` imports no i18n module, calls no `t(`, and that no catalog
key is an instrument item. It also sweeps both catalogs for `PHQ`/`GAD`/`WHO-5`/`C-SSRS`/
`HAQ` and for validation-claim wording, so an instrument name cannot arrive in patient copy
by the back door.

**Nothing scores.** Neither module contains `score`, `puan`, `cut-off` or `kesme değeri` in
code. Administration — the explicit selection files/04 §1 requires of every response option,
`administration_mode`, and any arithmetic at all — is INT-116's, and the boundary is written
into the component's header rather than left to be inferred.

## 4. Low-literacy chips — what 02 §3 actually asks for

files/02 §3 does not mean "shorter text". It means **full operation without reading**: every
chip label spoken and selectable by voice; severity numeracy-free, using **3–4 ordinal spoken
anchors** (Cowan 2010, explicitly *not* 7±2); **no free text anywhere on the critical path**;
and acquisition that is non-stigmatising — *never* ask "okuyabiliyor musunuz?". The four are
now enforced rather than intended:

- **Speakable labels.** Every option label and every question title in the authored pack is
  run through `assertSpeakableTr` — the same guard the dialogue lane applies before a string
  reaches a synthesiser, which rejects a numeral (invariant 22's first clause) and an empty
  string. A chip a patient must be able to *hear* is a chip the synthesiser will accept.
- **Ordinal anchors.** `ordinal: true` on a question subjects it to `ORDINAL_ANCHOR_MIN`/`MAX`
  = 3/4. `severity` carries it; the spec fails if an ordinal scale grows a fifth rung.
- **No typing required.** A driver walks all twelve department packs in Detaylı through
  `nextApplicableQuestion`, answering only option questions and passing every free-text step
  without typing, and asserts the flow terminates with every applicable non-text question
  answered. The free-text CTA's `PrimaryButton` carries no `disabled` prop, so the step can
  always be passed — asserted from the screen's source.
- **Never asked about reading.** Both catalogs are swept for `okuyabiliyor`, `okuma yazma`,
  `okur-yazar` and `can you read` — the same assertion `tests/sim` makes of the spoken lane
  (`test_the_persona_is_never_asked_whether_they_can_read`), made here of every string this
  app can render.

### 4.1 Invariant 22 — the refusal, on the side that owns the input control

INT-096 enforces "no free numeric text entry on the clinical critical path" in the runtime: a
numeric slot with no authored `choices_tr` raises `FreeNumericEntryRefused`. Nothing enforced
it in the app, which is the one surface a patient actually touches, and a screen that quietly
opened a decimal keypad would put the whole files/00 §2 display hazard back
(`parseFloat("2,5") === 2`; `parseFloat("1.500") === 1.5`).

`src/lib/intake/affordance.ts` mirrors it, and the mirror is pinned to its sources rather
than trusted: the spec parses `services/voice-runtime/.../typed/affordance.py` for
`NUMERIC_SLOT_TYPES` and `packages/protocols/src/protocols/types.py` for `SlotType`, and
asserts the TypeScript unions equal them. `typedAffordance` refuses each of the four numeric
types with no choices, answers a numeric slot that *has* chips with `choice` (files/00 §2:
"doses use `tam`/`yarım`/`çeyrek` chips"), and leaves a non-numeric slot as `free_text`. The
pack gate `numericStepsWithoutChoices` is empty for every department pack in both modes, and
the intake screen declares no `keyboardType` anywhere.

**No numeric question was authored to make the gate non-vacuous.** The clinical quantities a
real pack will ask for (`weight_kg` and the rest) are HB-C6, and their `choices_tr` are
clinician-authored; the valueset members behind every `vs.*` code slot are HB-C16. The gate
is proved by a negative control instead (§7).

## 5. What this environment could not verify

Stated plainly, once, and not softened anywhere above. **Nothing in this issue was seen
rendered, and nothing is claimed to have been.**

- There is no simulator, no emulator and no Docker daemon in this container, and Expo cannot
  start. No screen was launched, no screenshot exists, and `docs/evidence/screens/` gains
  nothing from this issue.
- The vitest lane runs on `node` with no renderer: `react-native` ships Flow source this lane
  cannot import, and neither `react-test-renderer` nor `@testing-library/react-native` is a
  dependency. Detox, Maestro and Playwright were **not** added — the constraint was worked
  inside, following the idiom of `e2e/a11y.spec.ts`, `e2e/askAhead.spec.ts` and
  `e2e/large-text-overflow.spec.ts`.
- Every claim above is therefore either **a real call into a real module** (the licence gate,
  the resolver, the affordance rules, the pack driver, `resumeQuestion`) or **a statement
  about what the shipped source declares** (the renderer transforms nothing; the intake
  screen opens no numeric keyboard; the free-text CTA is never disabled). A source assertion
  cannot prove a pixel. It can prove that the one place an instrument item becomes a rendered
  string does not transform it, which is the property invariant 10 is about.
- Specifically **unverified**: that `InstrumentItems` lays out correctly at any text scale,
  that the wellbeing screen looks right with the (currently absent) block, and that the
  refactored resume point lands on the same screen a device would show. The first two are
  unobservable while the registry is empty; the third is covered behaviourally by the
  `resumeQuestion` tests, which exercise the identical rule.

## 8. What is missing, and who it waits on

Nothing here is blocked on a decision an agent could take. What is absent is content:

- **Verbatim Turkish items for every instrument.** Owner: INT-116 (the instrument engine),
  and the licence work above it. `INSTRUMENT_ITEMS` is empty and no item was invented.
- **C-SSRS** — HB-L2 (RFMH/Clario electronic sublicence). BLOCKED; cannot render, and the
  gate refuses it with a full item set in hand.
- **WHO-5** — HB-L3 (WHO commercial permission). BLOCKED; same.
- **HAQ-DI** — NEEDS_PERMISSION; the Turkish translation rights are the open item.
- **PHQ-9 / GAD-7 / PHQ-2 / GAD-2** — licence `GO`, items unauthored. Also unbuilt, and
  deliberately: files/02 §2 places PHQ-2/GAD-2 **after the note is assembled** rather than
  inline in the flow, and PHQ-9/GAD-7 only "if screened positive **and if the environment
  permits**". Putting an instrument step inside the typed flow would have contradicted the
  blueprint; the wellbeing surface is where files/02 §4 puts the standalone one, so that is
  where the gate is wired.
- **Chip vocabularies for real clinical slots** — HB-C6 (`weight_kg` and the five other
  `base.intake` additions, each needing `choices_tr[]`) and HB-C16 (valueset members). The
  affordance gate is what will refuse them if they ever arrive numeric and chipless.
- **Cross-launch resume.** Resume today is in-session: `src/lib/session.tsx` is in-memory by
  design ("nothing here may write to disk"). Encrypted-at-rest drafts are **INT-142**, which
  `depends_on: [INT-136]` — so this is the backlog's own ordering, not an omission.

Two things this issue did **not** do, recorded so they are known absences rather than
oversights:

- **No read-aloud control was added to the typed chips.** files/02 §3 wants every chip label
  spoken; the app's only synthesiser today is the dev-lane TTS ladder behind `__DEV__` and a
  host probe (`lib/dialogue/ttsLane.ts`), and CLAUDE.md keeps mocks in tests. What this issue
  delivers instead is the property that makes such a control possible without further work —
  every label is provably speakable — while the spoken half of the low-literacy path stays
  where it already works, in the dialogue lane. The overlay itself (`overlay.low_literacy`,
  files/04 §2.3) is INT-056 and does not exist.
- **No non-stigmatising acquisition prompt** ("Yazıları büyütelim mi?") was written, because
  it would acquire an overlay that does not exist. The negative half of that rule — never
  asking about reading ability — *is* enforced.
