**Issue:** INT-294 (P0, E08-mobile) · **Branch:** `int-294-tts-lane-race`
**Found by:** the end-to-end walkthrough, `docs/evidence/INT-293.md`, 2 Sep 2026.

Two defects, one symptom. The owner saw a dev banner —
"ses hattı yanıt vermedi … Denenen adresler: http://127.0.0.1:8802 — bağlantı

## 3. What changed, and why this state and not another

### 3.1 The latch — `apps/mobile/src/lib/dialogue/stream.ts`

INT-261 latched the mute for the session, and it gave a reason: "re-probing the
TTS ladder on every subsequent turn would spend the turn budget twice per
question to arrive at the same answer, so once is enough." That reason was
sound about a walk which cost the whole clip deadline. It is not sound about a
walk bounded to one admission — and the cost it did not price is the one the
owner paid: a first turn lost by 24 ms, and a whole visit silent beside a Freya
answering in 0.8 s.

The alternatives considered, and why not:

- **Clear the flag somewhere.** Wherever it is cleared, the next turn's failure
  re-sets it, and the caption flickers on and off across a visit. Worse than
  the latch.
- **A wall-clock backoff.** Needs a duration nobody has supplied, and the loop
  it protects is turn-shaped, not time-shaped: a patient who thinks for ninety
  seconds should not thereby earn a retry.
- **An explicit patient mute.** There is no such control today, and inventing
  one is a different issue. If it is ever built it is a *separate* flag: a mute
  the patient chose must never be cleared by a clip that happened to play.

What is there instead: the flag is a **report about the last clip**, and the
reducer distinguishes three outcomes rather than two.

| action | meaning | effect on the voice |
|---|---|---|
| `speech_done` | the clip **played** | not muted; failure count reset |
| `speech_unavailable` | the clip **failed** | muted; one turn further from the next attempt |
| `speech_skipped` | it was **not attempted** | unchanged; one turn closer |

The asymmetry between the last two is the whole design. Before this, the silent
path dispatched `speech_done` — the action that means "the clip played" — so
the state had no way to tell a turn that was heard from a turn that was never
tried, and clearing on `speech_done` would have declared the voice back without
evidence. That is why the latch was the only consistent thing to do with the
state as it stood, and why the fix is a new action rather than a new `if`.

Recovery is therefore **observable**: the caption clears only when a clip the
patient could actually hear finished playing, and
`apps/mobile/src/components/DialogueIntake.tsx` renders that caption from
`state.voiceMuted` and nothing else — asserted, so the reducer test is a test
about what is on screen.

The backoff invents no constant: `voiceRetryIn = voiceFailures - 1`. One
failure retries on the very next turn; each consecutive failure buys one
further turn of silence. A lane that is genuinely gone therefore costs a
bounded admission every few questions rather than one per question, and the
schedule is the failure count itself.

### 3.2 The walk — `apps/mobile/src/lib/dialogue/ttsLane.ts`

`clipDeadlineMs` is `TURN_ROUND_TRIP_BUDGET_MS + sentences × SYNTHESIZE_TIMEOUT_MS`,
and `tts.ts` says in words what that decomposition means: "ONE lane admission
plus ONE synthesis per sentence". The deadline has always allotted admission
exactly one `TURN_ROUND_TRIP_BUDGET_MS`. The defect is that admission never
honoured the figure the deadline was computed from. So `ADMISSION_BUDGET_MS`
is that same constant, re-used, not a new duration.

Three changes make the walk fit inside it:

1. **The budget covers the whole of one lane's admission**, health leg
   included. It used to cover the probe synthesis only, so a lane whose
   `/health` hung cost `timeoutMs + budgetMs` — which is how a configured host
   that answers nothing charged 1505 ms in front of a lane that was answering
   in 798 ms.
2. **The walk is a race resolved by rank, not a queue.** Every candidate is
   measured at once; the winner is the highest-ranked lane that measured `ok`
   once every lane above it has answered. Quality order is preserved exactly —
   ladder order still decides — but it is preserved by *rank* rather than by
   making the patient wait for each tier in turn. The losing probes are
   abandoned the moment the winner is known.
3. **A host that answers nothing is quarantined for the session.** Health
   results are no longer re-derived from scratch: `172.20.10.3` says nothing
   once and is not asked again. Two limits keep that honest — only a
   *transport-level* silence quarantines (a daemon answering 503 says nothing
   about its neighbours on the same box, so `unreachable` is now a distinct
   verdict from `unhealthy`), and the **last reachable host is never
   quarantined**, so a whole-network blip cannot leave a session permanently
   voiceless. Both have tests, the second as a near-miss control.

Cost of the race: each lane is woken with one `/health` and at most one
one-word probe synthesis, once per walk. The previous code woke fewer daemons
and charged the patient the difference. The test that used to assert "Freya is
never woken" now asserts the stronger property it was standing in for — the
walk settles at the winning tier's own figure.

### 3.3 Invariant 21 — nothing here can end up in front of a RED

The race is more concurrent network work than before, so the question is asked
rather than assumed. It cannot get in front of a RED, and the reason is
structural rather than a matter of scheduling: the RED script is pre-positioned
on the device and triggered over the data channel, and the RED module reaches
no TTS code at all — so there is nothing for a probe to be ahead of. Two tests
walk the import graph and pin it in both directions:
`livekit/red.ts` reaches no `dialogue/` module, and `dialogue/ttsLane.ts`
reaches no `livekit/` module. A future import that made the RED path resolve a
voice fails there.

### 3.4 `make voice-doctor` — `scripts/dev/voice_doctor.py`

The doctor printed `voice: UP — every configured lane answered` throughout the
walkthrough, because it only issued `GET /health` — the exact criterion INT-249
had already proved insufficient one level down. Every TTS tier is now asked to
**speak**, with the app's own probe word (`LANE_PROBE_TEXT`, pinned by test)
against the app's own committed budget (`TURN_ROUND_TRIP_BUDGET_MS`, pinned by
test). `asr` and `extract` keep the health probe: neither has a
healthy-but-unusable mode that costs a turn, and POSTing a synthesis at an ASR
daemon probes something else.

The probe counts the bytes and drops them — there is no path from a doctor
probe to a byte anyone can read back, which is invariant 3's posture for
patient audio applied by construction to the agent's. The word is numeral-free
and a test says so (invariant 22).

One thing the first real run caught: the summary said
`voice: UP — tts:voxcpm2 unreachable` about a tier that was reachable,
health-green, and merely too slow. A summary that renames a verdict hides it as
surely as one that omits it, so the summary now prints the detail the probe
produced. That has its own test.

## 7. What this issue did not do

- **`voiceDiagnostic` / the dev banner is untouched.** The banner the owner
  photographed says "the lane did not answer" about a lane that lost a race.
  Its wording is now wrong more often than it is right, but changing dev-only
  diagnostic copy is not in this issue's acceptance, and the underlying race
  it was misreporting is fixed. Worth its own issue.
- **`voice_doctor` still probes serially.** It is a host-side command with no
  patient waiting on it, so the reason to race does not apply; a doctor that
  probed concurrently would also perturb the very timings it reports.
- **A host quarantined for the session stays quarantined even if it comes
  back.** That is the acceptance line as written ("not re-probed for the rest
  of the session"), and the last-host guard keeps its worst case bounded, but
  it is a real trade and it is named here rather than left to be discovered.
- **No new string, no i18n change.** The existing `dialogue.voiceMuted` copy
  reads "Sesli okuma **şu an** çalışmıyor" — already the wording a recoverable
  condition wants — so `tr.ts`/`en.ts` are untouched and the register and
  readability finding lists are unmoved.
