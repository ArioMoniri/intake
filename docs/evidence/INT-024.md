## Measured fallback latency

`make chaos EXPERIMENT=vendor_kill` →

```
chaos vendor_kill: PASS — typed fallback in 0.000002 s (bound 2.0 s)
  pre-kill call served by vendor adapter 'mock_vendor' (mode=vendor)
  kill switch thrown; next call came back mode='typed' (reason=VendorKilled)
  metric vendor_adapter_failures_total +1
  metric vendor_adapter_fallbacks_total +1
```

Measured vendor-kill → typed decision latency: **2 µs** (in-process
exception-shaped failure; the 2 s acceptance bound is the wall bound the
experiment and `tests/chaos` assert). Unknown experiment ids are a typed
refusal: `make chaos EXPERIMENT=bogus` exits 2 naming the known ids.

## What landed

- `packages/intake_platform/src/intake_platform/chaos.py` — the chaos
  harness: `AdapterProbe` (the minimal vendor-adapter seam; no formal
  LLM/speech adapter interface existed in intake_platform, so the harness
  defines the contract the provider-agnostic gateways adopt when they
  land), `MockVendorAdapter` with a kill switch (named by the acceptance;
  on no serving path), `DegradationRouter` (any vendor failure → typed
  fallback decision, ADR-010's degrade-to-text tier; never propagates),
  `run_vendor_kill` + `run_experiment` registry + CLI behind
  `make chaos EXPERIMENT=<id>`.
- Four new live families in `observability/metrics_catalog.yaml`, each with
  unit/owner/description (inv. 13): `vendor_adapter_failures_total{adapter}`,
  `vendor_adapter_fallbacks_total{adapter,mode}`,
  `vendor_fallback_latency_seconds{adapter}` (target: the 2 s bound),
  `chaos_experiment_runs_total{experiment,outcome}` — plus the emitter
  import in `tests/observability/test_metrics_catalog.py` per that gate's
  own convention. The planned `voice_typed_fallbacks` (files/08 §4, owner
  voice-runtime) stays planned: it is the per-turn voice-runtime series,
  not this adapter-seam counter.
- `scripts/load/k6-smoke.js` + `make load` — meta endpoints
  (/healthz, /readyz, /version, /metrics with catalogue check) at 5 VUs for
  30 s, thresholds tied to the api registry row's 800 ms budget, and the
  authed `/v1/visits` happy path gated on `INTAKE_DEV_TOKEN_PATIENT`
  (INT-197 synthetic dev accounts).
- `docs/runbooks/livekit-load-test.md` — the lk load-test recipe against
  the INT-090 dev compose profile: audio-only commands (the dev config's
  sole codec is audio/opus), what the summary reports, what to watch
  server-side, the planned voice_* SLO families it will be read against,
  and no expected numbers because none have been measured (inv. 20).
- Makefile: `chaos` and `load` wired real (arg guard, k6 presence check).

## Staging deferral (honest, not wired)

The acceptance says "k6 API smoke in CI (staging profile)". There is no
staging environment yet — nothing exists for a CI job to hit, and a CI job
pointed at nothing would be a fake. The script and `make load` are the
real, runnable pieces today (documented against a locally running
services/api); the CI job is documented — here, in the Makefile comment and
in the script header — as arriving with the staging environment, alongside
the files/10 §7 monthly staging chaos schedule and the release-gating lk
runs. No workflow files were touched.
