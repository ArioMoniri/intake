## Upload flow as shipped (client side)

1. Pre-check the picked file against the mirrored allow-list and 20 MiB cap
   — honest ≤B1 Turkish refusals; the server stays the enforcer.
2. Read the bytes (`expo-file-system` `File.bytes()`), compute sha256
   (`@noble/hashes`), refuse oversized bytes locally.
3. `POST /v1/visits/{id}/documents` declares `{content_type, sha256}` —
   never a filename (invariant 6).
4. `PUT …/documents/{doc_id}/content` sends the raw bytes THROUGH the API —
   the presigned MinIO URL in the slot points at the server's loopback and
   is unreachable from a device, so the client never touches it.
5. The ingest answer is the scan outcome: clean, or a 422
   `document_rejected` surfaced as the worded "Reddedildi" chip; 503
   scan-not-configured fails closed with honest copy.
6. The filename the patient picked is remembered in module memory only
   (their own data, shown back to them, never sent, never logged).

## Notes / deviations

- The task brief mentioned an `ocr_pending` scan state; the merged INT-197
  server exposes exactly `quarantined | clean | rejected`
  (`DocState` in `services/api/src/intake_api/documents.py`), so the client
  codes against those three — no server change made or needed.
- Documents hang off a server visit, but the app's visit creation
  (INT-193) is session-local until INT-134. Bridge shipped here:
  `ensureServerVisit` resolves a session visit to its server row by
  hospital+department+date and creates it via the existing
  `POST /v1/visits` only at upload time (listing is read-only and never
  writes). No `services/api/**` change.
