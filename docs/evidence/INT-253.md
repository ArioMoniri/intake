# Evidence — INT-253 · Localization completeness (tr 100 %, en 100 %; ar P3 with RTL audit)

## Acceptance (verbatim from docs/backlog/issues.yaml)

- [x] "i18n lint fails on missing keys; clinical tr reviewed flag enforced"

Test the issue names: `tests/release/test_i18n_complete.py` — present, 21 tests.
Wired into `make check` as `check-i18n` (and collected by `check-py` anyway, since it
lives under `tests/`).

**The third language.** The issue *title* is where it is settled — *"tr 100 percent, en
100 percent; ar planned P3 with RTL audit"*. Arabic is **not** delivered here and nothing
in this change moves toward it. What is delivered is the gate that keeps that plan
honest: `test_exactly_the_shipped_locales_have_a_catalogue` fails the build if an `ar.ts`
appears, and `test_no_rtl_affordance_is_claimed_before_the_audit` fails if any shipped
module reaches `I18nManager`, `forceRTL`, `allowRTL`, `isRTL` or a literal `"rtl"`. A
mirrored third catalogue without the bidi audit would be worse than no third catalogue,
because it would look finished.

## What the gate holds, and why it is a Python test over TypeScript source

`apps/mobile/src/lib/i18n.test.ts` already asserts what can be asserted from *importing*
the two catalogues: key parity, non-emptiness, no ALL-CAPS, no bare `sen`. Three of the
four completeness properties are properties of the **tree**, invisible to an import:

| property | why an import cannot see it |
|---|---|
| a key defined and never used | the catalogue does not know who reads it |
| a user-visible string hardcoded in a screen | by construction it has no key |
| the `[REVIEW]` clinical mark | it lives in a source comment |

So the gate reads the source, in the shape `tests/mobile/test_crash_scrub.py` already
uses: recover the property mechanically, record the exceptions in the test file where
widening them is visible in review.

## Flagged, not changed

### 1 · Nine keys an accepted issue requires and no screen renders — mobile owner

`voice.mic.{why,cta,settingsHint}` and `voice.session.{connecting,reconnecting,paused,
interrupted,weakLink,ended}` were in the orphan list. They are **not** deletable:
`apps/mobile/e2e/voice.spec.ts` is INT-103's acceptance test and asserts this copy exists
in both catalogues and says why-before-prompt as the stores require. Deleting them would
have un-delivered a landed acceptance — my first pass did delete them and `pnpm
typecheck` caught it, which is the whole argument for the e2e spec.

The defect they expose is a product gap, not a localization one. `lib/livekit/session.ts`
really does enter `connecting`, `reconnecting`, `backgrounded` and `interrupted`
(`setPhase` at lines 142–371) and **no surface tells the patient about any of them**: a
patient whose voice visit drops sees nothing at all. Likewise the pre-permission primer —
the store-required "why" line exists and nothing shows it; only the OS dialog string in
`src/locales/app-tr.json` ships.

Recorded as `UNWIRED_ACCEPTANCE_KEYS`. The gate asserts they are still unrendered and
still claimed by the spec, so the reservation cannot outlive either fact.

### 2 · Thirty-four instructional-prose strings in the short imperative — copy owner (files/00 §2)

files/00 §2 line 219 is explicit: *"`siz` throughout, **`-in` for short in-flow buttons,
`-iniz` for instructional prose and form labels**. Never `sen`."* `tr.ts`'s own header
claims that split. **The catalogue does not implement it anywhere** — there is not one
`-iniz` imperative verb in the file, and every one of these is short-form:

`a11y.backHint` · `a11y.closeHint` · `a11y.companion.ackHint` · `a11y.companion.roleHint`
· `a11y.companion.speakerHint` · `a11y.companion.thirdPartyHint` · `a11y.confirmHint` ·
`a11y.consent.rowHint` · `a11y.consent.switchHint` · `a11y.dialogue.bargeInHint` ·
`a11y.dialogue.exitHint` · `a11y.dialogue.sectionsHint` · `a11y.dialogue.stopHint` ·
`a11y.notifications.quietHint` · `a11y.notifications.switchHint` · `a11y.openHint` ·
`a11y.selectHint` · `a11y.shareHint` · `a11y.typedHint` · `auth.otp.body` ·
`auth.phone.hint` · `companion.speaker.footer` · `consent.entry.sub` ·
`consent.stale.body` · `dialogue.entryBody` · `dialogue.listeningHint` ·
`dialogue.speakingHint` · `records.needVisit.body` · `records.offline.body` ·
`review.intro` · `visits.new.dateHint` · `visits.new.hint` · `visits.new.smsHint` ·
`wellbeing.intro`

Not rewritten, and the reason is not caution. Nineteen of the thirty-four are what
VoiceOver and TalkBack speak, where brevity is itself an accessibility property, and
`dokununuz` on every hint is a different decision from `giriniz` on a form label. A
partial application would leave the app switching register between screens, which reads
worse than the consistent short form it has now. This is one decision for the copy owner
across all thirty-four, taken once.

What the gate does hold is the boundary: `PROSE_REGISTER_FINDINGS` is asserted by exact
equality, so a *new* prose string in the short imperative fails the build, and
`test_no_short_in_flow_control_uses_the_doubled_polite_form` fails on drift in the other
direction. The set may only shrink.

### 3 · One sentence above the B1 bound — copy owner

`welcome.body`, 17 words against `B1_MAX_WORDS_PER_SENTENCE = 15`:

> Vizite, muayeneden önce şikâyetlerinizi sesli ya da yazılı olarak toplar ve hekiminize
> düzenli bir ön not iletir.

The bound is imported from `intake_voice_runtime.talker.policy_guard` rather than
restated, so the project has one number. The rest of the catalogue is comfortably inside
it — 751 sentences, mean 3.6 words, and this is the only one over. Splitting the
product's own description line is a copy decision, so it is recorded in
`B1_LENGTH_FINDINGS` rather than edited. Scripted protocol text (`intake.q.*`,
`intake.opt.*`, `intake.hpi.*` — 300+ keys) is excluded from this axis and from the
register axis entirely: invariant 10 makes it verbatim, so a long scripted question is a
finding against the pack, never a rewrite here.

### 4 · Twenty-three PolicyGuard findings, every one a guard defect — services/voice-runtime owner

Invariant 2 says patient-facing text passes PolicyGuard. Nothing had ever run the mobile
catalogue through it. Doing so turns out to say more about the guard than about the copy
— **no catalogue sentence is actually giving a diagnosis, a treatment or a prognosis**,
and all 23 findings are the guard mis-reading a correct sentence:

| class | n | what the guard is doing |
|---|---|---|
| `register` | 17 | `_SEN` matches `\w+(?:din\|sın\|sin)\b`. That is the **polite imperative** `edin`/`gidin` and the **third-person optative** `ulaşsın`/`eklensin`, not second-person singular. The live consequence: the Talker cannot say *"Devam edin"* — a non-scripted turn containing it is dropped and replaced by the safe bridge. |
| `treatment` | 3 | `bırakın`/`kullanın` are anchored to the clinical sense, and here mean a date field left empty, an app version to use, and the service itself. |
| `diagnosis` | 1 | `\btanı\s+koy` matches the **negated** disclaimer *"Vizite tanı koymaz"* — the one sentence in the product whose job is to deny diagnosis. |
| `multi_question` | 1 | `health.attach.confirm` is one question whose subject is set off by a comma; `_question_count` reads the comma as a second interrogative. |
| `jargon` | 1 | the length arm of the same check — `welcome.body`, above. |

Not fixed: `services/**` is outside this issue's scope. Recorded as
`POLICYGUARD_FINDINGS` by exact equality, which makes the pairing load-bearing in both
directions — clinical language entering the copy appears as a new pair, and a fix in
`services/voice-runtime` appears as a resolved one, so neither side can drift silently.
Worth the runtime reviewer's attention: the `register` arm is not cosmetic.

## The hardcoded-string scan

Three rules over every shipped module (`src/**`, colocated `*.test.*` and the catalogues
excluded), all three at zero:

1. a user-visible prop (`label`, `title`, `placeholder`, `accessibilityLabel`,
   `accessibilityHint`, `accessibilityValue`, `footer`, `header`, `message`) taking a
   string literal, in either the JSX (`=`) or the object (`:`) form;
2. a JSX text node — any prose between tags that is not an expression. Verified against a
   planted positive in both the inline and the multi-line-close shape, and against the
   whole tree for false positives (one, `bookable.length > shown.length ? (`, which the
   excluded characters now rule out);
3. any string literal containing a letter that exists only in Turkish. This is the
   catch-all for copy reaching the screen by a route the first two rules do not model;
   English identifiers, style tokens and route names carry none.

Three documented exemptions, each asserted to still be load-bearing so the list can only
shrink:

| module | why it is not a localization defect |
|---|---|
| `lib/taxonomy/branches.ts` | `nameTr` is the taxonomy's own `name_tr`, projected verbatim from `packages/protocols/taxonomy/branches.yaml` and pinned field-for-field by `branches.test.ts`. Copying 60 branch names into the catalogue would create a second source of truth for a name the served feed also sends. |
| `lib/dev/accounts.ts` | synthetic demo accounts behind `__DEV__`, compiled out of release builds. Fixture data, not product copy. |
| `lib/taxonomy/mhrsSms.ts` | a Turkish character class inside the MHRS-message parser's regex, matched against pasted text and never rendered. |

## Notes for the next iteration

- The two missing surfaces in §1 are the real product finding here. A voice visit that
  reconnects, backgrounds or is interrupted by a phone call currently tells the patient
  nothing, and the copy for all six states is written and reviewed.
- The `register` arm of PolicyGuard (§4) blocks *"Devam edin"* today. That is the
  commonest imperative in the product.
- The register decision in §2 is a single call across thirty-four strings. Until it is
  taken the catalogue is uniformly short-form, which is the coherent state; the gate
  keeps it from becoming a mixed one in either direction.
