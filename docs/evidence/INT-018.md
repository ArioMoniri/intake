partially met (allow-list semantics, logging shape, `sec.egress_denied` on

## What the tests pin

- The shipped allow-list validates; the **PHI-path tier is empty** (invariant
  19 / 00_STATE D11: the PHI path is self-hosted, so there is no vendor host
  it may reach); every dev row is `phi_allowed: false` with purpose + basis.
- **Default deny**: unknown host refused; empty host refused; matching is
  case-insensitive with trailing-dot normalisation and **port-strict**.
- **Glob discipline**: `*` in a host is a validation error unless the entry
  declares `glob: true`, and then only the leading `*.suffix` form;
  `*.hf.co` covers `cdn-lfs-us-1.hf.co`, never the apex, never `evilhf.co`;
  no implicit subdomain matching without the flag.
- **files/10 §4 carried over the issue brief**: literal-IP hosts (metadata
  endpoint included) are denied outright at check time, and the allow-list
  itself refuses IP-literal entries.
- **PHI double-gate**: `phi_allowed: true` without `phi_exception_approval`
  (a recorded human decision id) fails validation; with the approval it
  still denies at runtime unless `INTAKE_ALLOW_PHI_EGRESS=explicit-yes`
  (near-miss control: `yes` is refused).
- **Invariant 19 pin**: `assert_dev_only_vendors()` raises when any entry
  covers a vendor LLM **domain family** with `phi_allowed: true`, or puts one
  on the PHI-path tier at all; a lookalike domain is the near-miss negative
  control.
- **The httpx guard**: `guarded_transport()` composed over
  `httpx.MockTransport` (CI stays vendor-free) passes an allow-listed call
  through and raises `EgressDenied` for an unlisted host; `http://` infers
  port 80 and is refused by the 443-only list.
- **The log is transfer evidence, not a leak**: denial emits a WARNING record
  with message `sec.egress_denied` and `{host, port, decision, purpose,
  bytes_out, reason}`; allowed calls emit `sec.egress_allowed` with the
  header-declared `bytes_out`; URL paths, query strings and bodies are
  asserted absent from every record (invariant 6 — a query string is exactly
  where an identifier would leak). `bytes` and `ts` of the acceptance map to
  `bytes_out` + the record timestamp; byte-accurate accounting moves to the
  proxy tier.

## Decisions and collisions surfaced while proving it

- **Vendor literals vs the INT-001 gate**: the brief asked the vendor pin to
  name the three vendor API hosts, but
  `scripts/ci/assert_no_vendor_calls.sh` refuses those literal endpoint
  strings anywhere outside `files/` — and widening a CI security gate's
  exclusions is exactly what CLAUDE.md forbids. Resolved by matching vendor
  **domain families** (`anthropic.com`, `openai.com`, `googleapis.com` as
  suffixes, with glob-wider-than-family covered too), which is strictly
  broader than three exact hosts and leaves the gate untouched.
- **Event name**: the backlog acceptance says `sec.egress_denied`
  (implemented); files/07 §6 spells it `security.egress_denied` in one spot.
  The acceptance spelling won; flagged for a docs-consistency pass.
- **Hook-protected file**: `infra/security/egress-allowlist.yaml` is on the
  guard-protected list (07 §3.8) by design. It was created (not modified)
  via the sanctioned `ALLOW_PROTECTED=1` route under this issue, which is the
  issue that introduces the file; every later change goes through the guard.
- The backlog `tests:` field names `tests/security/test_egress_allowlist.py`;
  the suite landed as `tests/security/test_egress_policy.py`. One of the two
  needs a one-line reconciliation when the proxy tier closes the issue.
