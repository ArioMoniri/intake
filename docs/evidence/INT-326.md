# Evidence — INT-326: the dev George clip route is not an open paid proxy (audit F05)

Date: 2026-09-26 · Sec-Row: `cloud-clipgen` · Branch: `int-326-george-hardening`

## The defect

`POST /dev/voice/george-clip` (`intake_api.dev_voice`, PR #519) synthesised ANY text of up to
600 characters through the ElevenLabs key for ANY caller:

- no principal — the `dev_voice_scripted()` consent-guard declaration is a marker, not a check;
- "scripted text only" was enforced only by the mobile client's `ScriptedTr` brand;
- no budget;
- nothing kept it out of production beyond the dev opt-in phrase.

On a public host that is cost abuse, and arbitrary (possibly PHI) text reaching a US vendor,
which invariant 19 forbids.

## What changed

- **(a) Patient principal.** The route resolves `intake_api.auth.Principal` (DPoP/OTP or the
  dev bearer, the same door as every patient route) and `require_patient`. Anonymous or wrong
  token → 401, before the lane says whether it is configured. Clinic-admin → 403.
- **(b) Server-side catalogue.** `intake_api.dev_voice_guard.load_scripted_catalogue` reads every
  compiled `clips.<locale>.<voice>.json` under the dist root (`INTAKE_DEV_GEORGE_CLIP_DIST`,
  default `packages/protocols/dist`, where `make protocols-compile` writes and `make clips`
  reads). It goes through `voice_clips.load_clip_manifest`, so schema, voice/locale and tamper
  checks all apply, and it collects each row's `text_hash`. A request is admitted only if
  `protocols.dsl.clip_text_hash(text_tr)` is in that set. Otherwise the answer is 422
  `not_in_catalogue`: no vendor dial, no cache write, and the text is not echoed (invariant 6).
  A tampered, unreadable or empty catalogue means no wiring, so the route answers 503.
- **(c) Per-principal budget.** The INT-012 Redis token bucket
  (`intake_platform.security.rate_limit.TokenBucketLimiter`, dimension `user`, key = account id):
  capacity 30, refill 0.5/s. It is charged at the door, so refused requests cost a token. An
  empty bucket → 429 with `Retry-After`. An unreachable Redis → 503 `george_budget_unavailable`
  (fail closed).
- **(d) Absent in prod.** `INTAKE_ENV` is read the platform's way (default `dev`, case-folded, any
  `prod*`). In prod, `create_app` does not mount the router (404), and `george_wiring_from_env`
  returns `None` before reading the key, whatever the dev flags say.
- **Unchanged:** 503 when unconfigured, 502 on a vendor error (key never echoed), and the 422
  `not_speakable` numeral refusal (invariant 22). The numeral check still runs before the
  catalogue check.

`test_dev_voice_hardening.py` (32 tests) proves each door with the fake vendor held at zero
calls whenever the door refuses:

- **(a)** Through the real app and dev-bearer door:
  - no credentials → 401;
  - wrong bearer → 401;
  - unconfigured lane, anonymous → still 401;
  - patient → 200 (positive control);
  - admin → 403.
- **(b)** Against a bundle the REAL compiler wrote from the committed synthetic pack
  (`tests/fixtures/protocols/compile`):
  - the catalogue equals the manifest rows' hashes;
  - a compiled row → 200, sent to the vendor verbatim;
  - free text → 422, not echoed;
  - five near-miss negative controls → 422: trailing space, last character dropped, case
    changed, suffix appended, prefix prepended;
  - numerals still → `not_speakable`.
- **(c)** Budget:
  - exhaustion → 429 with `Retry-After`, then a refill admits again;
  - refused requests spend budget;
  - principals do not share a bucket;
  - Redis down → 503.
- **(d)** Production:
  - `prod`/`production`/`PROD`: the route is not mounted (checked with the consent scan's own
    router walker) → 404;
  - `george_wiring_from_env` → `None` with every flag set;
  - dev with every flag and a compiled catalogue builds the wiring (positive control);
  - an empty dist leaves the lane unconfigured;
  - a tampered manifest leaves the lane unconfigured.

Mutation check: each door was disabled in turn (prod mount gate forced on, catalogue check
forced off, role check removed), with files restored from a copy afterwards. That turned 11
tests red: 3 prod, 7 catalogue (free text + 5 near-misses + refused-spend), and the admin 403.

## Consequences to note

- The mobile George client (`apps/mobile/src/lib/dialogue/georgeClip.ts`) sends no
  Authorization header. Its question text is composed from i18n keys, not from compiled pack
  `text_tr`. After this change it gets 401 (or 422), which it already treats as "unavailable",
  so it falls back to the self-hosted TTS. The turn is never blocked. George's voice will play
  again once the client sends its DPoP/bearer credentials and asks only for compiled catalogue
  text.
- Serving George clips in dev now needs a compiled pack under the dist root
  (`make protocols-compile PACK=… VOICE=…`). Without one the lane stays 503.
