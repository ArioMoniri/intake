# Evidence — INT-324 · agent WAV framing lives in voice-clips (invariant-3 guard green)

## Acceptance

From the production audit of 2026-09-26, finding F08: the invariant-3 guard
`tests/voice/test_audio_retention_guard.py` is red on main, which makes
`make safety` and `check-py` red. Cause: PR #519 (ADR-028 on-demand George
dev route) framed agent PCM as WAV inside `services/api/src/intake_api/dev_voice.py`,
with a `.wav` cache-file literal and an `audio/wav` content type. The guard
allows agent-audio encoding in exactly one module (`voice_clips/audio.py`)
and one content-type literal (`audio/ogg` in `voice_clips/cache.py`).
`test_the_allow_lists_hold_exactly_the_clip_cache_grant` locks that grant.
It is **not** edited here.

Sec-Row: voice-runtime (files/10 §9 "Voice intake (runtime)". This row is
the same as INT-060, the clip-cache grant, and INT-090, the guard itself).

## Change

- `packages/voice-clips/src/voice_clips/audio.py`: new `wav_bytes(speech)`,
  the inverse of `wav_to_speech`. It only assembles the header, using
  bytes literals (`b"RIFF"`, `b"WAVE"`, `b"fmt "`, `b"data"`). It adds no
  string literal and no import, so the module keeps its single allowed
  import (`soundfile`). The function is exported from `voice_clips`.
- `services/api/src/intake_api/dev_voice.py`: the local `pcm_to_wav` and its
  `_Speech` Protocol are removed. The route now calls `voice_clips.audio.wav_bytes`.
  - The cache file is named by `clip_text_hash(text_tr)` alone, with no extension.
  - The response is served as `application/octet-stream`. The mobile client
    (`apps/mobile/src/lib/dialogue/georgeClip.ts`, `fetchGeorgeClip`) reads
    `res.arrayBuffer()` and never inspects the content type.
  - `voice_clips.gateway`, which dev_voice already imported, imports
    `voice_clips.audio` at module level. So the api gains no new runtime
    dependency.
- Tests:
  - `tests/api/test_dev_voice_george.py` asserts the octet-stream content
    type and the RIFF/WAVE magic bytes. It also asserts that the on-disk
    name is exactly `clip_text_hash(text)`.
  - `tests/voice/test_clip_cache_builder.py::TestTheWavWriter` has three
    tests: framing, a round trip through `wav_to_speech`, and RIFF/data size
    fields that match the payload.
