## The defect, as it was measured

`composition._compose` built the handler with `valuesets=dict(valuesets or {})`,
and no production caller passed a table (`session_router` builders,
`scripts/voice/live_smoke.py`). `slot_output_schema` refuses a code slot whose
members it was not given. The result was worse than the issue title says:

1. The first question of every session, `identity_check.subject_role`, is a
   code slot. Its Work was refused (`ExtractionRefused`, Work `failed`).
2. A refused Work leaves its step `ASKED_PENDING`, and the handler declares
   every awaiting step on every later Work. So **every later Work declared
   `subject_role` too and was refused**: a session bound nothing at all after
   its first question.
3. `chest_pain.character` and `chest_pain.radiation`, the code inputs of
   `rf.chest_pain_cardiac_features`, could never bind, so the K2 rule could fire
   only on a boolean answer (sweating, breathlessness), and the near-miss SARI
   sibling (`radiation == "yok"`) could never fire at all.

Only three of the ten base.intake code slots had a committed set (INT-441), so
loading the file alone would not have fixed (3).

## Residuals (no id minted; for the orchestrator)

1. **No in-session rules-engine call exists in production.** No module under
   `services/` calls `evaluate_triage`. The handler's docstring says it sets no
   `triage_update`, and no other handler does. With INT-518, the answers a
   rule needs now bind, but nothing in the live runtime evaluates them, so the
   RED path in `work_queue`/`red_path` is still fed only by tests. The end-to-end
   test here evaluates the rules the way the simulator does.
2. **`chest_pain.onset_at` (the K2 rule's tense anchor) binds only from a
   completion that already carries an ISO date.** It is a `date` slot answered
   by four closed choices. CD-05 resolves each choice to a date against the
   reference time, and that resolution is not built in the runtime. The
   extraction schema offers the model `{"type": "string", "format": "date"}`
   with no reference date, and its instructions forbid inference. An unbound
   anchor reads Unknown and the rule cannot fire (`rule_truth` = `when ∧
   anchor`, files/12 §2.4). The recorded completion in this test carries the
   reference date.
3. `scripts/voice/live_smoke.py` calls `build_residency_tr_session` without the
   required `clinic` argument (INT-406), so it raises `TypeError` before this
   issue's change is reached. It now gets the committed table by default.
