## Design (read-only console module on the INT-180 admin surface)

INT-189 is a read/aggregation module. It builds four id-only, audited read
surfaces on the existing `/admin/*` descriptor table (write-ahead audit +
Keycloak RBAC + IP allow-list reused unchanged), plus an evidence export:

- `GET /admin/compliance/vendor-register` — the KVKK transfer register
  **auto-filled from the egress `TransferLog` feed** (`intake_platform.egress.TransferRecord`),
  each row carrying the inventory shape `{category, purpose, basis, retention,
  recipients}` (Inv 18) with `notification_due = first_seen + 5 business days`.
- `GET /admin/compliance/consents` — consent coverage by scope/version, counts only.
- `GET /admin/compliance/audit-search` — ids/codes-only search over **administrative**
  audit rows; patient-content-access rows are out of scope (HB-L6 governs those via
  the break-glass / patient access-log path). Never returns content or chain hashes.
- `GET /admin/compliance/dsar` — the DSAR queue + KVKK m.13 SLA from
  `intake_api.dsar.sla.overdue_requests`, ids/clocks only.
- `GET /admin/compliance/evidence-export` — a text-typed evidence bundle
  (every cell through `intake_platform.export_safety.sanitise_cell`, Inv 47),
  ids/counts/dates only, with a content digest.

All surfaces are GET (non-mutating) → no new `DangerousAction`/four-eyes and no
new persistence; the module is fail-closed (empty feed → empty register,
unknown audit-chain status → not-verified). Reuses: admin descriptor router,
`AdminActionRecord`, `AdminRole.{COMPLIANCE_OFFICER,AUDITOR}`, egress feed,
dsar SLA, consent registry, `sanitise_cell`, the `{category,...}` inventory shape.

### Invariants engaged
Inv 4/31 (every read audited, write-ahead) · Inv 6/36 (ids only, no PHI) ·
Inv 18 (inventory shape carries a lawful basis) · Inv 37 (tenant scope from the
claim) · Inv 47 (export injection guard) · HB-L6 (no new unmanaged read path
into patient content).

### Negative controls (near-misses)
- a vendor register row with no lawful basis is refused (`MissingLawfulBasis`);
- an audit search that would surface patient content is refused (`AuditSearchContentRefused`);
- a DSAR/compliance read without a compliance role is refused (403, audited);
- an evidence-export cell that would evaluate in a spreadsheet is neutralised.

## What was built

Pure logic (unit-tested without a DB or app), `packages/intake_platform/compliance/`:
- `register.py` — `build_register(feed, allowlist, now)` folds the egress
  `TransferRecord` feed into `VendorRegisterRow`s carrying the
  `{category, purpose, basis, retention, recipients}` shape; `add_business_days`
  computes `notification_due = first_seen + 5 business days`; a transfer with no
  sourced basis raises `MissingLawfulBasis`.
- `audit_search.py` — `search_audit` projects **administrative** rows ids-only
  (no `resource_ref`, no hash); a query aimed at patient content or a free-text
  filter raises `AuditSearchContentRefused`.
- `evidence.py` — `build_evidence_bundle` assembles the four-section bundle,
  every cell through `sanitise_cell` (Inv 47); the digest is base64url(sha256)
  (never a 64-hex chain-hash shape, HB-I12).

API (`services/api/src/intake_api/admin/`): five GET routes added to the INT-180
descriptor table (`ADMIN_ROUTES`) — `vendor-register`, `consents`,
`audit-search`, `dsar`, `evidence-export` — with `compliance_source.py` wiring
them to the egress feed, the `consents`/`dsar_requests` tables and the audit
chain. Every read runs through the existing write-ahead `AdminActionRecord` and
role guard; permitted roles = `{compliance_officer, auditor, platform_owner}`.
Tenant scope comes from the claim (fail-safe empty on an unresolvable tenant).
`ApiState.transfer_feed` carries the feed (empty by default — the durable Loki
egress-log query is a follow-up, not fabricated).

Console (`apps/admin-web/src/compliance/module.ts`): pure render functions with
refusals mirroring the server — `MissingLawfulBasis`, `UnsafeExportCell`,
`ChainMaterialLeaked`; e2e spec `apps/admin-web/e2e/compliance.spec.ts` over a
fixture recorded from the API by `scripts/dev/record_compliance_fixture.py`.

### Four sub-surfaces + negative controls
| surface | negative control | result |
|---|---|---|
| vendor register (auto-fill + 5-bday due dates) | row with no lawful basis | `MissingLawfulBasis` (py + ts) |
| audit search (ids only) | query reaching patient content / free-text filter | 422 `audit_search_content_refused` |
| DSAR queue (m.13 SLA) | read without a compliance role | 403 `forbidden` (sre_oncall) |
| evidence export bundle | cell that would evaluate in a spreadsheet | neutralised / `UnsafeExportCell` |
