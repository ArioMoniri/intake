# Evidence: INT-562 · Safety queue page in the admin console over GET /admin/safety-queue, with acknowledge

**Epic:** E12-admin · **Phase:** P0 · **Sec-Row:** admin-console · **GitHub:** #951 ·
**Depends on:** INT-406 (the queue route and the inbox), INT-459 (the shell; PR #963, which this
branch is stacked on)

## Request

From the admin audit of 18 Oct 2026: on the synthetic host REDs land in the clinic Safety inbox and
no console page shows them; the API is live (`services/api/src/intake_api/admin/safety_queue.py`),
the store is wired in compose. Acceptance, verbatim from the row:

- "The page renders every entry of GET /admin/safety-queue in the inbox's order (open REDs,
  on-site notifications and RED-visit transitions first, oldest first; then acknowledged, newest
  answer first) and refuses a body out of that order rather than re-sorting it."
- "Rows carry ids, rule codes, the RED register, the raised time, the age and the tenant SLA only
  (invariant 6); a name, a mail or a word in an id field is refused, and the kind, register and
  age-band vocabularies are sealed."
- "Every open entry offers one acknowledgement, a same-origin form forwarding the entry id alone;
  the API's refusals (role, tenant, not found, already acknowledged, inbox down) come back as
  codes, never prose."
- "The inbox's 503s render as a named unavailable state with a next step, never an empty queue;
  the empty queue says what fills it; a refused caller keeps the shell; every state passes axe; tr
  is the source of truth."

**Scope against main's contract.** The API on `main` records four entry kinds (`red`,
`red_on_site`, `visit_rescheduled`, `visit_cancelled`), the RED register on a RED entry, and
orders the queue open-first/oldest-first then answered/newest-first (INT-406; INT-553's F3
restates it on the API). INT-553's clinic items (`chest_pain_arms_unresolved`,
`proxy_chest_pain_screen_unasked`; PR #944, open) are not on `main`, so the page's sealed kind
vocabulary is main's four; when #944 lands, the vocabulary and its words grow by one commit.
Clinician outcome codes wait on INT-554 (#962). The acknowledgement is tier 1, one key, the
tenant's clinical responsible's alone (`SAFETY_QUEUE_ACKNOWLEDGE`): no four-eyes, no WebAuthn
step-up, so the console completes it; the page says so in one sentence rather than offering a
control it cannot finish.
