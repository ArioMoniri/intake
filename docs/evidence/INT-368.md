## Settings verified against Renovate's source (renovate 44.115.10)
- **Config location.** `.github/renovate.json` is in `configFileNames`
  (`lib/config/app-strings.ts`), next to `renovate.json{,c,5}`,
  `.gitlab/…`, `.renovaterc*` and a `renovate` key in `package.json`. The test
  requires exactly one of them.
- **Security updates are forced.** The `vulnerabilityAlerts` default is
  mergeable, and it carries `schedule: []`,
  `dependencyDashboardApproval: false`, `minimumReleaseAge: null`,
  `prCreation: immediate` and `prConcurrentLimit: 0`. It is attached to each
  vulnerable dependency as `force`
  (`lib/workers/repository/process/vulnerabilities.ts`), and
  `mergeChildConfig` spreads `config.force` last (`lib/config/utils.ts`). So it
  overrides every package rule: the major, Expo and Python approvals and the
  release-age cooldown.
- **Security PRs are not throttled.** The hourly limit is skipped for them,
  and their concurrent-PR count is kept separately
  (`lib/workers/global/limits.ts`).
- **Defaults that had to be overridden.** `platformAutomerge` defaults to
  `true`, `pinDigests` to `false`, and the `pre-commit` manager is disabled.
  All three are set explicitly.
- **Where the cooldown applies.** `minimumReleaseAgeBehaviour` defaults to
  `timestamp-required`. The cooldown is therefore scoped to datasources that
  carry a release timestamp:
  - npm and PyPI;
  - the ruff pre-commit tag (GitHub tags);
  - the two Docker Hub rules (`tag_last_pushed`).

  It is not set on container images wholesale. An image from a registry
  without timestamps (ghcr.io) would otherwise wait forever.
- **Why both halves of the ruff pair cool down.** A group drops its pending
  upgrades and ships the rest (`lib/workers/repository/updates/generate.ts`).
  Without the same cooldown on the tag, it would arrive without the PyPI half.
- **Why the ignore list is kept narrow.** An `ignorePaths` entry matches by
  plain substring *or* by minimatch with `dot: true`
  (`lib/workers/repository/extract/file-match.ts`). The test models both, and
  its near-miss control plants a bare `staging` entry.
- **How a retitle survives.** A retitle *without* a commit on the Renovate
  branch is reverted on the next run. Once the branch carries a foreign commit,
  Renovate returns `pr-edited` before it updates the PR
  (`lib/workers/repository/update/branch/index.ts`). This is the order the
  runbook gives for in-place handling.

## Maintainer handling of a Renovate PR
The evidence and sec_row gates refuse `chore(deps): …` titles, and they are
not weakened; a test asserts both still refuse one. A Renovate update reaches
`main` under an issue. The coordinator allocates an INT-368 follow-up or the
owning issue. The preferred route is to cherry-pick onto `int-<n>-<slug>`
with `docs/evidence/INT-<n>.md`, then close the Renovate PR. The other is to
retitle in place *after* pushing the evidence commit. Both are set out in the
runbook.
