# Evidence — INT-297 · The DSL's `*_tr` fields become per-locale maps, mechanically and with `tr` still required

Epic E03-protocols · phase P1 · `sec_row: protocol-registry` · depends on INT-296 (done).

`text_tr`, `ask_tr`, `follow_up_tr`, `choices_tr` and `why_tr` become maps keyed by
locale, with `tr` required by the schema. `allow_paraphrase` travels with them, because
the acceptance names it in the same breath and a permission is about a language.

**The headline is at the bottom of this file, in §5: every one of the 468 authored
Turkish fields in the tree, and every byte of the served bundle, is unchanged.**

## 1. The finding that had to be written down first

This section exists because the run that produced it was killed mid-write when the host
machine slept, and the finding lived only in a dead context. It belongs to INT-297 — it
is a direct consequence of this issue's schema change, in code this issue must change —
so it is recorded here rather than raised as a separate id.

**Two production sites in `services/voice-runtime` read the DSL's `*_tr` fields
directly, and one of them fails *silently* under the new shape.**

### 1a. `typed/affordance.py` — the silent one

```python
choices_tr=tuple(resolved.slot.choices_tr or ()),
```

`Slot.choices_tr` is now `{"tr": ("evet", "hayır", "bilmiyorum")}`. `tuple()` over a
mapping yields its **keys**. So this expression does not raise, does not fail validation,
and does not fail a type check: it quietly produces `("tr",)`.

`SlotFacts.choices_tr` is declared `tuple[str, ...]`, and `("tr",)` satisfies it
perfectly. The consequence in typed mode is a patient looking at a single answer chip
labelled **`tr`** where three answer chips should be — and `free_numeric_critical_path_steps`,
which decides whether invariant 22's "no free numeric text entry on the clinical critical
path" gate passes, reads the same field to ask whether a numeric slot has authored
discrete answers. A numeric slot would have appeared to have one, so the gate would have
passed a pack that cannot actually be completed without a free numeric field.

This is the exact failure mode the issue brief names — a refactor that changes what a
patient sees while every type check stays green — appearing in the *consumer* rather than
in the packs. It was found by two independent agents updating the voice and sim test
suites, not by the compiler, because nothing in the compiler touches this path.

Fixed by extracting a named function whose docstring records why it may not be inlined:

```python
def _choices(slot: Slot, locale: str) -> tuple[str, ...]:
    if slot.choices_tr is None:
        return ()
    return tuple(entry_for(slot.choices_tr, locale))
```

`entry_for` raises on a missing locale rather than falling back (INT-296), so the
degenerate case is now a stop rather than a wrong list.

### 1b. `clinical_agent/plan.py` — the loud one

`build_plan` passed `slot.ask_tr`, `slot.follow_up_tr` and `tuple(slot.choices_tr or ())`
straight into `EngineStep`, whose `text_tr` / `choices_tr` are plain `str` /
`tuple[str, ...]`. The first two raise a pydantic `ValidationError` (a dict is not a
`str`), so this one announces itself. The third is the same silent-keys bug as 1a.

Both now project through `entry_for(..., protocol.locale)`. `ResolvedProtocol` gained a
`locale` field for exactly this: the resolved document speaks one language — INT-296's
one-locale-per-session rule, carried into the compiler — so the engine step keeps one
string and the pack keeps the distinction.

### 1c. What this changes about the shape of the work

The five migrated fields have exactly three readers outside the DSL:
`protocols.compile.emit_clips`, `protocols.validator`, and these two runtime modules.
All four now go through `entry_for`. `packages/voice-clips` reads the *compiled manifest*
rather than the DSL, so it needed the (locale, voice) key rather than the map.
