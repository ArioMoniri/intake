# Evidence — INT-297 · The DSL's `*_tr` fields become per-locale maps, mechanically and with `tr` still required

Epic E03-protocols · phase P1 · `sec_row: protocol-registry` · depends on INT-296 (done).

`text_tr`, `ask_tr`, `follow_up_tr`, `choices_tr` and `why_tr` become maps keyed by
locale, with `tr` required by the schema. `allow_paraphrase` travels with them, because
the acceptance names it in the same breath and a permission is about a language.

**The headline is at the bottom of this file, in §5: every one of the 468 authored
Turkish fields in the tree, and every byte of the served bundle, is unchanged.**

## 1. The finding that had to be written down first

This section exists because the run that produced it was killed mid-write when the host
machine slept, and the finding lived only in a dead context. It belongs to INT-297 — it
is a direct consequence of this issue's schema change, in code this issue must change —
so it is recorded here rather than raised as a separate id.

**Two production sites in `services/voice-runtime` read the DSL's `*_tr` fields
directly, and one of them fails *silently* under the new shape.**

### 1a. `typed/affordance.py` — the silent one

```python
choices_tr=tuple(resolved.slot.choices_tr or ()),
```

`Slot.choices_tr` is now `{"tr": ("evet", "hayır", "bilmiyorum")}`. `tuple()` over a
mapping yields its **keys**. So this expression does not raise, does not fail validation,
and does not fail a type check: it quietly produces `("tr",)`.

`SlotFacts.choices_tr` is declared `tuple[str, ...]`, and `("tr",)` satisfies it
perfectly. The consequence in typed mode is a patient looking at a single answer chip
labelled **`tr`** where three answer chips should be — and `free_numeric_critical_path_steps`,
which decides whether invariant 22's "no free numeric text entry on the clinical critical
path" gate passes, reads the same field to ask whether a numeric slot has authored
discrete answers. A numeric slot would have appeared to have one, so the gate would have
passed a pack that cannot actually be completed without a free numeric field.

This is the exact failure mode the issue brief names — a refactor that changes what a
patient sees while every type check stays green — appearing in the *consumer* rather than
in the packs. It was found by two independent agents updating the voice and sim test
suites, not by the compiler, because nothing in the compiler touches this path.

Fixed by extracting a named function whose docstring records why it may not be inlined:

```python
def _choices(slot: Slot, locale: str) -> tuple[str, ...]:
    if slot.choices_tr is None:
        return ()
    return tuple(entry_for(slot.choices_tr, locale))
```

`entry_for` raises on a missing locale rather than falling back (INT-296), so the
degenerate case is now a stop rather than a wrong list.

### 1b. `clinical_agent/plan.py` — the loud one

`build_plan` passed `slot.ask_tr`, `slot.follow_up_tr` and `tuple(slot.choices_tr or ())`
straight into `EngineStep`, whose `text_tr` / `choices_tr` are plain `str` /
`tuple[str, ...]`. The first two raise a pydantic `ValidationError` (a dict is not a
`str`), so this one announces itself. The third is the same silent-keys bug as 1a.

Both now project through `entry_for(..., protocol.locale)`. `ResolvedProtocol` gained a
`locale` field for exactly this: the resolved document speaks one language — INT-296's
one-locale-per-session rule, carried into the compiler — so the engine step keeps one
string and the pack keeps the distinction.

### 1c. What this changes about the shape of the work

The five migrated fields have exactly three readers outside the DSL:
`protocols.compile.emit_clips`, `protocols.validator`, and these two runtime modules.
All four now go through `entry_for`. `packages/voice-clips` reads the *compiled manifest*
rather than the DSL, so it needed the (locale, voice) key rather than the map.

## 5. The headline — byte-identity for `tr`

### 5a. Every authored Turkish string in the tree

`protocols.migrate.tr_baseline` reads the *raw* YAML and takes the `tr` entry out of
either shape, so the same code produced the baseline before the migration and
re-derives it after. It records the authored string **and** its `expand_tr` expansion —
the bytes that actually reach TTS (invariant 22).

```
96 documents · 468 fields · authored and expanded · identical
```

`test_every_turkish_string_in_the_tree_is_byte_identical_to_the_pre_migration_baseline`
— **passes**. All 93 packs are `maturity: L0` (HB-C1) so the serve interlock refuses
them; this is the only complete projection of their content that exists, and it covers
every one of the five fields in every document.

### 5b. The served bundle

For the one tree that compiles, every artefact was compared byte for byte. The result is
stronger than the acceptance asks for: **the only difference anywhere in the served
bundle is a single identifier.**

| artefact | result |
|---|---|
| `questionnaire.json` | identical apart from the embedded protocol hash |
| `openehr_bindings.json` | **byte-identical** |
| `slots.py` | identical apart from the hash in its header comment |
| `slots.ts` | identical apart from the hash in its header comment |
| clip manifest — `subject`, `text_tr`, `scripted`, `text_hash` × 13 rows | **byte-identical** |

Two things moved, both identifiers, and each is *asserted* rather than excluded:

1. `resolved_protocol_hash` `1ff5ba02…` → `fa1ba233…`. A sha256 over the canonical
   resolved document, whose shape moved when a string became a one-key map. The test
   substitutes it back before comparing rather than dropping the three artefacts that
   embed it — dropping them to avoid one changed line would drop the FHIR item texts and
   the slot schemas with them, which is exactly what the comparison is for.
2. `clip.<voice>.<digest>` → `clip.<locale>.<voice>.<digest>`, and
   `clips.<voice>.json` → `clips.<locale>.<voice>.json`, because acceptance line 4
   requires the manifest to key on (locale, voice) and a key omitting the locale is not
   keyed on it.

`test_the_served_bundle_for_tr_is_byte_identical` and
`test_the_two_recorded_differences_are_identifiers_and_nothing_else` — **both pass**.

### 5c. The migration is a line edit, not a re-dump

`migrate_text` rewrites only the five fields' own lines and re-indents their
continuations; it never round-trips a pack through PyYAML, which would reflow every
quote, comment and block scalar and bury five real changes in three thousand cosmetic
ones. `migrate_file` refuses to write unless the parsed result of the line edit equals
the declared shape-level transformation, so a line edit that lost a byte fails loudly
rather than landing.

Idempotent (`--check` exits 0 on the migrated tree) and reversible
(`unmigrate_document` is the exact inverse for a one-key map, and refuses a wider one
rather than choosing a locale to drop).

## 7. Invariants

- **Invariant 5** — `tr` required by the schema on every map. `test_every_pack_in_the_tree_carries_tr_in_every_migrated_field` walks all 93 packs.
- **Invariant 7** — monotonic inheritance untouched. `tests/protocols/test_overlay_monotonicity.py` (hypothesis properties P1–P4b) and the compile goldens pass unchanged; no rule field, id or predicate was renamed.
- **Invariant 10, restated per locale and not weakened** — scripted text is read from the locale's own entry via `entry_for`; `allow_paraphrase` is per locale, and a missing entry reads `False`, the safe reading of silence. A locale absent from any speakable field cannot be selected: `resolve_protocol` raises `LOCALE_NOT_SELECTABLE` before any emitter runs.
- **Invariant 17** — the `draft_needs_source` stubs and their `TODO: … requires clinical sign-off` strings are carried through untouched; they are in the 468 compared fields' neighbourhood and the `when:` predicate that holds them was never in scope. No test is skipped or xfailed (the two skips an earlier draft had are gone — §2 commit `40291eb`).
- **Invariant 22** — the compiler is still the only expander and it still runs before the clip key is computed. The expansion is now per locale *by construction*, since the text handed to `expand_tr` is the locale's own entry. A locale with no expander cannot reach TTS because it cannot be selected at all; building that properly is INT-300's clause and nothing here pre-empts it.

### The import boundary, and why the registry appears twice

`packages/protocols` may not import `intake_platform` — files/09 §7 gives the authoring
surface zero access to patient data, enforced by AST scan in
`test_import_boundary_no_patient_data_access`. INT-296's registry lives behind that
boundary, so `protocols.locale_text` restates the closed set, and
`test_the_dsl_and_the_session_registry_agree_about_which_locales_exist` asserts the two
are the same set in **both** directions — a locale registered for sessions but unknown to
the DSL would be selectable with no content behind it, and one the DSL accepts but the
registry does not know would be content no session can reach. That test is the seam; it
is not decoration.
