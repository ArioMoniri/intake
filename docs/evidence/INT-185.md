## Acceptance, verbatim — one line, one artefact

Acceptance: *"triage events, false-RED queue, PolicyGuard classes, acceptance by specialty"*.

- **"triage events"** → `renderTriageEvents` in `apps/admin-web/src/safety/module.ts` paints the RED/YELLOW/GREEN routing distribution, one row per `clinical_schemas.triage.TriageLevel`, each attributed to the rules engine, with the LLM candidate ceiling (`YELLOW_REVIEW`) shown separately. Data recorded into `apps/admin-web/e2e/fixtures/safety.payload.json` by `scripts/dev/record_safety_fixture.py`; metric id `triage.events_total` (planned → counts are 0). Tests: `triage events (RED/YELLOW/GREEN distribution) > …` (6 cases, incl. the invariant-1 refusal `TriageNotFromRulesEngine`).
- **"false-RED queue"** → `renderFalseRedQueue` projects the INT-175 `false_red_review` annotation queue (its enqueue scope, reviewer roles, closed-enum verdict labels and section reasons, `content_scope=null`, `content_blocker=HB-L6`). It renders **annotations only** — a rules-engine RED can never be downgraded here (`TriageDowngradeInFalseRedQueue`); pointers are ids only (`ClinicalContentLeaked`); a granted content-read path is refused (`ContentReadNotRefused`); verdicts outside the closed vocabulary/roles are refused (`ForbiddenReviewVerdict`). Tests: `false-RED queue (annotation only, never a downgrade) > …` (8 cases).
- **"PolicyGuard classes"** → `renderPolicyGuardClasses` paints the breakdown of `policyguard.blocks_total` by `intake_voice_runtime.talker.policy_guard.ViolationClass` — the seven invariant-2 categories (diagnosis/treatment/prognosis, multi_question, too_long, register, jargon). A class off the sealed set is refused (`UnknownPolicyClass`); counts are non-grouped atoms (invariant 22). Tests: `PolicyGuard classes (invariant 2 categories) > …` (3 cases).
- **"acceptance by specialty"** → `renderAcceptanceBySpecialty` rolls `note.acceptance_rate` up over the real intake branches of the taxonomy (Acil Tıp excluded — no intake note is produced for it). These are **counts** (delivered, accepted); a rate is shown only through the INT-183 measurement discipline (`renderMeasurement`, which refuses an unlabelled figure — `UnlabelledMeasurement`), never as an accuracy/sensitivity claim (invariant 20). Impossible counts are refused (`AcceptanceCountsInconsistent`). Tests: `acceptance by specialty (counts, never an accuracy claim) > …` (4 cases).

## The one decision that shapes it

Like the Models (INT-183), Compliance (INT-189) and Protocols (INT-184) modules, **the console renders the source, it does not keep one.** The four surfaces are pure, typed projections of real data recorded into one composite fixture by `scripts/dev/record_safety_fixture.py` so the spec asserts against what the sources actually say rather than a hand mock (invariant 13, invariant 17):

- triage levels ← `clinical_schemas.triage.TriageLevel`; the candidate ceiling ← the `LlmCandidateTriage` `YELLOW_REVIEW` literal
- the false-RED queue contract ← `intake_platform.observability.annotation` (`QueueId.FALSE_RED_REVIEW`'s `QueueDef`: enqueue scope, reviewer roles, `content_scope`, `content_blocker`), plus its closed `Label`/`SectionReason` enums; content-read state is `refused` because `authorize_content_read` has no granted counterpart (HB-L6)
- PolicyGuard classes ← `intake_voice_runtime.talker.policy_guard.ViolationClass`
- acceptance rows ← the intake branches of `protocols.taxonomy.load_taxonomy(...)`
- every referenced metric id (`triage.events_total`, `policyguard.blocks_total`, `note.acceptance_rate`) is resolved against `observability/metrics_catalog.yaml` at record time (invariant 15); a miss raises rather than records.

The recorded state is the honest current state: triage counts are **0** (the metric is planned, no emitting session has landed), the false-RED queue is a **genuine empty list** (no persisted item store; enqueue/review flow through the INT-175 annotation module), PolicyGuard classes are a **0-count skeleton** (the console reads a live scrape at serve time; the fixture records the class set so the spec runs without a Prometheus), and every one of the **91 intake specialties is an empty state** (no note delivered yet). The annotate-never-downgrade, content-leak, content-read and verdict refusals are exercised with near-miss rows constructed inline in the spec — the same convention `compliance.spec.ts` and `protocols.spec.ts` use for emptyable surfaces.

## Invariants touched — named individually

- **Invariant 1** (RED/YELLOW only from the rules engine; LLM caps at `YELLOW_REVIEW`): triage rows are all attributed to `rules_engine`, and the false-RED queue records annotations and can never downgrade a RED. `TriageNotFromRulesEngine` refuses a routing count from any other producer or a candidate cap above the ceiling; `TriageDowngradeInFalseRedQueue` refuses any item carrying a triage-level mutation. Tested (both).
- **Invariant 2** (PolicyGuard categories): the class breakdown is `ViolationClass` verbatim; `UnknownPolicyClass` refuses a class off the sealed set. Tested.
- **Invariant 4** (audit + four-eyes + authz on every admin action): enqueue/review are the INT-175 annotation module's consent-checked, audited, closed-role operations and the INT-180 shell's audited routes — **reused, not re-implemented**. This console is a read projection; `ForbiddenReviewVerdict` holds a rendered verdict to the permitted roles (files/08 §2.1).
- **Invariant 6** (no PHI/PII; ids only): every field is an id, a count, a closed-enum value or a dated measurement. `ClinicalContentLeaked` refuses any false-RED pointer that is not id-shaped (regex mirrored from `intake_platform.observability.spans`), so a transcript cannot reach the console.
- **Invariant 12** (no protocol mutation from the console): the safety console reads triage/PolicyGuard/acceptance and annotates false-REDs; it never edits a rule, level or instrument. The downgrade refusal makes that structural.
- **Invariant 15** (every referenced metric is catalogued): the record script resolves each metric id against `observability/metrics_catalog.yaml` and raises on a miss.
- **Invariant 17** (real data or a genuine empty state): every field is projected from a real source; zero triage counts, the empty false-RED queue, the 0-count PolicyGuard skeleton and the 91 empty acceptance rows are the honest current state, each with a note. No demo/lorem data.
- **Invariant 20** (no accuracy claims): acceptance is described as counts; a rate renders only via `renderMeasurement` (named corpus + date), and `UnlabelledMeasurement` refuses a bare figure. No sensitivity/specificity/accuracy/WER figure appears anywhere.
- **Invariant 22** (numbers as guarded atoms): every count renders with `useGrouping:false`. Tested.
- **HB-L6** (staff access to patient content unruled): `content_read_state` is `refused` and only `refused`; `ContentReadNotRefused` refuses a body asserting a granted path. The annotation module has no granted content-read counterpart to project.

## Scope note — what is delivered here and what is sequenced

The named acceptance test is `apps/admin-web/e2e/safety.spec.ts`, delivered green, with the recorded fixture and the record script that keeps it honest. The `GET /admin/quality-safety` FastAPI route (an `ADMIN_ROUTES` descriptor + view + a `tests/admin/test_safety_module.py` parity test, as INT-183/189 carry) is **not wired in this PR**: it is a follow-up that lands the route inside the INT-180 shell so the fixture becomes recorded-from-the-API and a parity test holds it against the live response — the same sequencing INT-183/184 used. No new numbered artefact (ADR/HB/alembic) was minted; INT-175's HB-L6 is referenced, not extended.

## No PHI egress path added

The change adds no outbound call: it is one TS projection module + spec + fixture, one dev record script (local file read/write only — taxonomy YAML, metrics catalog, and in-process reads of the annotation/triage/policy_guard contracts), an `index.ts` re-export, and a Makefile target line.
