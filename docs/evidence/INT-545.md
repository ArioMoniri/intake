## The defect, as it was measured

`VoiceSessionRouter.end()` queued `close_session` (INT-540) and then called
`stop_red_watch()` (INT-531). The close runs later, on the Backend pump; a RED
it raises is settled, sealed behind and posted to the mailbox — and nobody is
parked on the mailbox any more. An ended session takes no next turn, so the
turn's drain, the push's fallback route, never runs either. The clinician
route is told (Layer B notifies at the determination); the device is not.

## The design

**The router** (`session_router.py`) keeps a `_closing` map
`{session_id: _Closing(stack, close work_id | None, settled_seen)}`.

- `end()` pops the session from the live set and queues its close. If
  `close()` returns `None` — a RED already sealed the queue — **and** the
  session is quiescent, the watch is ended at once. Otherwise the close is
  recorded and the watch is kept running (started, where a loop runs and no
  turn ever started it). `end()` still awaits nothing.
- `poll()` first calls `_release_closed()`. A closing session is released when
  its close is settled (`COMPLETED`, `FAILED` or `CANCELLED`; a sealed one with
  no close counts as settled) on this poll **and** the one before, **and** it
  is quiescent. Until then its watch is kept running, and started if none is.
  The second poll is the issue's grace for a worker-thread pump, which marks
  a Work settled a moment before it posts the RED that Work raised.
- *Quiescent* is two reads: the Backend's engine lock is free, and
  `TalkerSession.red_watch_idle`. A RED is determined, settled, sealed behind
  and posted inside one state-lane Work under the engine lock
  (`BackendAgent._execute_state`; the background lane cannot produce a RED),
  so with the lock free nothing more is on its way to the mailbox; with the
  watch idle everything already posted has been taken and delivered or
  recorded as failed.
- `closing()` lists the ended sessions still held; `start()` refuses a session
  id that is still closing, as it refuses one that is live.

**The sealed branch.** The issue's design stops the watch at `end()` whenever
`close()` returns `None`. Sealed is not delivered: the seal happens before the
post (deliberately — the Talker must never hear of a stopping RED while the
queue still admits Work), and the post only wakes the watch on the loop's next
iteration. Measured above, a worker that ends the session in the same step the
pump sealed it loses the RED. On a worker-thread pump the window is the few
statements between `_seal()` and `_push_red()`, both under the engine lock.
So a sealed session is released at `end()` only if quiescent, and is
otherwise held by the same rule as any other. The acceptance's near miss (a
sealed session whose RED was delivered) still stops at once.

**The Talker** (`talker/session.py`):

- `red_watch_idle`: the mailbox is empty (or absent) and no RED the watch took
  is still in delivery. A RED whose delivery failed is not in flight.
- `end_red_watch()`: the session is over. Stops the watch, then for every RED
  whose delivery failed and was waiting for a next turn to retry it — an
  ended session takes none — counts `red_watch_failures_total{kind=
  "unreached"}`, logs `red never reached the device` by work id and tells the
  clinician route through `RedPreemption.not_reached`. Returns those work ids;
  idempotent; awaits nothing. `stop_red_watch()` is unchanged (a test stops
  and restarts a watch on a live session; that is not a session end).

**The mailbox** (`talker/red_push.py`): `RedMailbox.empty`, read under the
post's lock.

**The notification** (`talker/red_path.py`):

- `DeviceDelivery` (closed): `pending` — told ahead of the trigger, which is
  every first notification, because both clinician routes run before the
  device by design; `withheld` — `DEFERRED_CLINICIAN`, nothing is sent to the
  device; `not_reached` — the device was meant to show it and the session
  ended without it.
- `RedNotification.delivery`, required (no default), with a validator:
  `withheld` exactly where `patient_facing` is false, and `silent_generic`
  only on a `pending` notification.
- `delivery_before_trigger(register)` gives Layer B's notification
  (`work_queue._notify_clinic`) and the path's own (`RedPreemption.trigger`)
  the same value from the register table.
- `RedPreemption.not_reached(result, evaluated_at_ms=...)`: the second
  notification for the same `work_id`. Nothing for a register that never
  triggers the device (it was told `withheld`). A route that raises is logged
  by work id and counted on `clinic_red_inbox_route_failures_total`, never
  raised.

`patient_facing` keeps its meaning (the register's intent) and every
existing caller is unchanged; `delivery` is what happened.

### Why invariant 9 still holds

The Talker keeps six tools; nothing in this change adds, removes or wraps one.
`end()`, `poll()` and `end_red_watch()` await nothing. The router reads the
Backend's engine lock with `locked()` — a non-blocking read, never an acquire
— and a close record by id. The watch still awaits only the mailbox and the
RED path. Backend speech is untouched. Only a rules-engine RED is posted or
delivered: the paths it takes are INT-531's, unchanged.

### Invariant 21

The RED still touches no media transport: the change keeps the existing
trigger over the data channel alive longer; it adds no route. The register
and location axes are carried, unchanged, on every notification, `not_reached`
included.

## Residuals (no id minted; for the orchestrator)

1. **The Safety inbox entry does not store the delivery.**
   `SafetyInboxNotifier` maps a notification to `InboxEntry.for_red`, whose
   store is insert-once by the entry id derived from the `work_id`; the
   `not_reached` notification lands on the RED's existing entry and changes
   nothing stored (as `patient_facing` and `silent_generic` already do). For
   the clinic queue to *show* "the patient was not told", the entry needs a
   field (with the inventory annotation, invariant 18) or a sibling kind like
   INT-475's `red_on_site`, and the store an update path — the platform and
   clinician-web lanes, not this one. Until then the statement is carried by
   the notification and counted on `red_watch_failures_total{kind="unreached"}`.
2. **A failed RED is reported, not retried, after the session ends.** A
   watch delivery that failed waits for the next turn to retry it; an ended
   session takes none, so `end_red_watch` tells the clinician instead. A
   router-driven retry before release would give a still-present device one
   more chance.
3. **The turn path's own failure** (pre-existing, INT-521/531): a RED the
   turn's drain hands to the path is marked seen before `deliver_preempt`; if
   the data channel raises there, the exception reaches the worker and the RED
   is neither retried nor reported `not_reached`.
4. **A data channel that never resolves** keeps a delivery in flight, so the
   session is never idle and never released. The production `RedDataChannel`
   adapter (none exists yet) must bound `publish` with a timeout.
5. **INT-542 item 1** should now read: a worker that ends sessions through
   `VoiceSessionRouter.end()` must run `watch()`/`poll()` on the sessions'
   loop; one that ends them otherwise must call `end_red_watch()` once the
   watch is idle.
