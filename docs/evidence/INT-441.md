## The defect

`base.intake` gated two questions on literals no answer equals:
- `identity_check.proxy_reported` had `ask_if: "subject_role != 'kendim'"`. The
  slot offers `"kendim için"` and `"yakınım adına"`. No answer equals `'kendim'`,
  so the gate opened for a patient speaking for themselves, and they were asked
  "Hastanın adına konuştuğunuzu not ediyorum. Doğru mu?".
- `pmh_fh_sh.lmp_date` had `ask_if: "pregnancy_status != 'hayir'"`. The slot
  offers `"evet"`, `"hayır"`, `"emin değilim"`. `'hayir'` matches nothing, so the
  LMP was asked after every answer. files/13 §4 asks for that ("Pregnancy/LMP
  early, universally"), so the behaviour is kept and only the literals change.
  Whether "hayır" may skip the LMP is a clinical decision (HB-C6), not made here.

No value set for either slot was committed, so nothing could show the defect.
The engine tests that pinned these gates answered `"yakinim"`, `"kendim"`,
`"emin_degilim"` and `"hayir"`, values no patient can give, so they passed
over it.

## The fix

| Change | Where |
|---|---|
| The two gates, aligned to the slots' own authored values (no clinical re-decision) | `packages/protocols/base/intake.yaml` |
| Committed value sets: `vs.subject_role`, `vs.pregnancy_status`, `vs.immunosuppression`. Each is the authored `choices_tr.tr` of the base.intake slot that names it, copied in order. A set is committed for every code slot any gate in the repository compares. | `packages/protocols/base/valuesets.yaml` (`kind: valueset_table`, passed over by the registry loader) |
| Loader, fail closed: id shape `vs.*`, members non-empty and distinct, a `source` naming where they were copied from, no extra keys | `packages/protocols/src/protocols/valuesets.py` |
| The compiler check | `packages/protocols/src/protocols/compile/gate_values.py`, called from `resolve_protocol` beside the INT-355 gate-reference check |
| Three refusal codes | `compile/errors.py`: `GATE_VALUE_OUTSIDE_VALUESET`, `GATE_VALUESET_UNCOMMITTED`, `CHOICE_OUTSIDE_VALUESET` |
| Wiring | `resolve_protocol(..., valuesets=)` and `compile_bundle(..., valuesets=)`: omitted, nothing is committed, so every gate on a code slot refuses. `protocols compile --valuesets` defaults to the committed file. |
| Spec quote kept verbatim | `packages/protocols/decisions/CD-100.yaml` spec_basis T1 (see D18 list) |
| Directory layout line | `files/12_DSL_V2_AND_RUNTIME_SPEC.md` §1 |

**What the check refuses.** Every literal the closed `when` grammar can place
against a code slot, in `ask_if` and `skip_if`: `==`, `!=` and the ordered
operators either way round, set membership, and comparisons under `!`, `&&`
and `||`.
- `GATE_VALUE_OUTSIDE_VALUESET`: the literal is not a member. A prefix, an
  ASCII folding, a case change, a trailing space and a non-string all refuse.
- `GATE_VALUESET_UNCOMMITTED`: the code slot's value set is not committed. This
  is fail closed: it is how `'kendim'` went unseen.
- `CHOICE_OUTSIDE_VALUESET`: a `tr` choice of a slot whose set is committed is
  not a member, so the set and what the patient is offered cannot drift.

The check reads gates only. It never rewrites a gate, and it does not read
red-flag `when`s, levels or the life-threat set (invariants 1 and 7). A gate
outside the grammar or naming no slot is refused elsewhere (`GATE_NOT_PROJECTABLE`,
`GATE_REF_*`) and skipped here.

## For the D18 lane (not decided here)

The check now refuses four gates in three review-queue cluster packs. They are
L0, never served, and the default registry never reads them. Each compares a
code slot against a literal its slot never carries. Aligning each one is a
clinical choice between the author's evident intent and the behaviour the
broken literal produced, so each is kept as authored: refused, fail closed.

| Pack · gated slot | Gate | What it does today | The choice D18 makes |
|---|---|---|---|
| `cluster.mental_health` · `sorular.diger_madde_kullanimi` | `subject_role == 'kendim'` | never opens: the substance-use question is never asked | `== 'kendim için'` opens it for self-report sessions. The proposal (`docs/evidence/proposals/cluster_mental_health.md` §0) says the gate "fails closed until the self/proxy ADR … and the owner may lift it then"; ADR-040 is PR #833, open. |
| `cluster.mental_health` · `sorular.baskalarinin_duymadigi_sesler` | `subject_role == 'kendim'` | never opens | same as above |
| `cluster.medical` · `sorular.bagisiklik_tedavisinde_enfeksiyon` | `immunosuppression != 'hayir'` | opens after every answer, "hayır" included | `!= 'hayır'` (the proposal's stated intent, "opens on evet and on bilmiyorum") asks fewer patients; the three-choice form keeps today's behaviour |
| `cluster.womens_health` · `sorular.gebelik_dogrulandi` | `pregnancy_status != 'hayir'` | opens after every answer, "hayır" included; it gates Q3–Q9 | same two readings. CD-100 T4 reads the gate as closed on "hayır"; T4(b), when applied, must use an authored literal or it refuses too |

register refuses a quote that is no longer in the file. The quote is updated
to the new line. Its `supports` text is corrected: it said "base asks the LMP
only when pregnancy is possible", which was never true, because `'hayir'`
