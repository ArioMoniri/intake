## Invariant 9, clause by clause — where each is asserted

**Clause 1, exactly six tools.** `tests/voice/test_six_tools.py::test_the_talker_registers_exactly_the_six_tools`
enumerates the registry built by the real `build_talker_tools(session)` and asserts
`registry.names == TALKER_TOOLS` — set equality, so a superset and a subset both fail.
The gate's own ability to fail is proven separately against synthetic registries of seven
(`test_a_seventh_tool_fails_introspection`, which names `set_triage` in the error) and of
five (`test_a_missing_tool_fails_introspection`). The registry seals after construction,
so a seventh cannot even be added at runtime, and eight forbidden capability names from
files/03 §4.2's negative list — plus `get_work_status`, which files/12 §7.1 deleted — are
asserted absent.

**Clause 2, never awaits Backend Work.** Two independent proofs.
*Structural*: `WorkSubmitter` has no awaitable member — `submit`, `cancel` and
`drain_results` are ordinary functions, so there is no expression the Talker could write
that would wait. `test_the_work_port_has_no_awaitable_member` introspects the Protocol and
fails if any member becomes a coroutine.
*Measured*: `test_turn_latency_is_unchanged_by_an_arbitrarily_stalled_backend` runs the
same turn on a virtual clock against backends stalled 10 s, 10 000 s and 0 s and asserts
all three turn latencies are **equal** (32 ms of playback, well inside the 505 ms scripted
budget of files/03 §4.5). The fake clock is a real virtual-time driver: `sleep` parks on a
heap of waiters and time only advances when every task is parked, so the backend's waiter
can never be popped before the turn's own. That is RT-03 with the stall taken to absurdity.
`test_submit_utterance_returns_before_the_backend_has_run` additionally asserts
`clock.now_ms() == 0.0` after submitting against a backend stalled an hour.

**Clause 3, a safe insertion window.** `tests/voice/test_insertion_window.py` drives the
files/12 §6 ladder: held while the patient talks; spoken at NATURAL only with silence
≥ 300 ms ∧ talker idle ∧ no pending response (each conjunct has its own negative control);
RELAXED drops the pending-response conjunct at the 20 s soft deadline; INTERJECT takes the
next sentence boundary at 45 s, cancelling non-RED playback and prefixing the polite clip;
a patient who talks for 200 s of fake clock drives the item to EXPIRED **with its note flag
committed first**, and a note write that fails rolls back to `Hold` with the item still
`PENDING` (files/12 §9 invariant 18). Delivery is idempotent on `work_id`: a re-enqueue of a
delivered work is a no-op, so `delivery_duplicates` is zero by construction.
`tests/voice/test_talker_session.py::test_backend_speech_waits_while_the_patient_talks_and_lands_at_the_pause`
is the same thing through a whole session — RT-01.

**Clause 4, only a rules-engine RED may preempt.** Two gates, tested separately.
*Shape*, a `model_validator` on `BackendResult`: `priority=preempt` requires
`triage_update` to be a `RulesTriageResult` at `RED`. YELLOW, GREEN, no triage update, an
`LlmCandidateTriage`, and candidate flags whose **text** is the string `"RED"` riding
alongside a YELLOW are all refused. `LlmCandidateTriage` cannot express RED at all — its
`level` is the literal `"YELLOW_REVIEW"` (invariant 1), asserted directly.
*Provenance*, `authorise_preempt`: every fired rule id must belong to the session's pinned
pack. A well-formed RED naming `rf.uydurma_kural` is refused, and an **empty** rule set
authorises nothing, so an unpinned session fails closed.
`test_the_session_refuses_an_unauthorised_preempt_and_speaks_nothing` proves the runtime
honours both and leaves `session.preempts` empty;
`test_a_yellow_result_goes_to_the_insertion_scheduler_not_the_preempt_path` is RT-07.

## Blocked, with the ask and the named human

- **`blocked:dependency` — INT-060 has not landed on `origin/main`.** The issue brief said
  the clip cache "just landed"; `packages/voice-clips` exists only on the unmerged local
  branch `int-60-clip-cache` (commit `217bfae`), and `docs/backlog/issues.yaml` still reads
  `INT-060 … status: todo`. **Nothing from that branch was merged into this one** — one
  issue per PR. The Talker therefore consumes a `ClipStore` **port** and the compiler's
  committed manifest format, so binding `voice_clips.cache` to the port when INT-060 merges
  is a wiring change with no edit to the Talker.
- **`blocked:route` — no room-token HTTP route.** `RoomTokenSource` is a port; the route is
  the API's to serve. Same finding as INT-103.
- **`awaiting-human` — the safe-bridge sentence.** Ask for **ClinicalAuthor**: *"When
  PolicyGuard drops the Talker's whole turn, what one B1-Turkish sentence should the patient
  hear instead?"* It must not diagnose, treat, prognose or ask a second question, and it will
  be pre-synthesised into the clip cache. Until it exists, `TalkerConfig.safe_bridge_clip_id`
  is `None` and the turn is silent — asserted by
  `test_a_dropped_turn_says_nothing_while_the_bridge_copy_is_unsigned`. This is not yet a
  row in files/HUMAN_BLOCKERS.md; it needs one, and that file is edited by whoever owns it.
- **`awaiting-human` — delivery deadlines for `CLINICAL_INFO` and `ROUTINE`.** Ask for
  **ClinicalAuthor**: *"How long may a document result, and how long may an ordinary
  acknowledgement, wait before the agent interrupts the patient to say it (soft / hard /
  terminal, as files/12 §6 gives 20/45/90 s for TRIAGE_YELLOW)?"*
- **INT-093 owns the HMAC attestation.** files/12 §5 requires `TriageVerdict` to carry an
  HMAC-SHA256 over `(session_id, ek4, disposition, rule_ids, inputs_hash, protocol_hash,
  life_threat_version, engine_version, issued_at, nonce, key_id)` with the signing key
  fetched from OpenBao by the rules-engine subsystem alone, plus the seven-way forgery
  mutation test. That attestor does not exist on any branch. **Nothing here pretends to be
  it**, and nothing here is weakened by its absence: both gates that can be built today
  refuse by default. `preemption.py`'s module docstring records the handover.

## Deviations, and why each was taken

1. **No `livekit-agents` dependency.** The blueprint names LiveKit Agents as the framework,
   and files/03 §4.2's mechanics assume it. But INT-091's acceptance is the six-tool
   registry, PolicyGuard, the insertion window and the clip player — none of which needs the
   framework — and the mandate is not to call a live model or a live LiveKit server in tests.
   Adding a realtime framework (and its plugin tree) for code that would be untestable
   without a server is the opposite of ADR-006's gateway posture. Layer A is therefore
   framework-independent behind `ports.py`, and the LiveKit Agents worker entrypoint binds to
   those ports in INT-095, where the real adapters and the on-hardware smoke live.
2. **No `pytest-asyncio`.** The repo has no async test plugin and no precedent for one
   (`tests/api/api_harness.py::run` drives coroutines with `asyncio.run`). The virtual-clock
   driver in `tests/voice/talker_harness.py` follows that convention, so this issue adds no
   test dependency and no licence-audit event.
3. **`enqueue` takes `now_ms`.** See the red run — a lazily stamped arrival time resets the
   ladder on a quiet session.
4. **PolicyGuard reports scripted text, never mutates it.** files/03 §4.6 invariant 7 is
   explicit that `kind=scripted` output equals `text_tr` *and* that the guard still runs.
   Where invariant 2's drop action would collide with invariant 10, verbatim wins and the
   violation becomes a finding against the pack. `policyguard_blocks_total` counts only real
   blocks, so a report on authored text does not inflate the safety signal.
5. **Two words are absent from the treatment lexicon.** `için` is the postposition "for" far
   more often than the imperative "drink" and would silence *"Bu şikâyet için tedavi gördünüz
   mü?"*; `alın` is the imperative "take" **and** the noun "forehead", so it is anchored to
   clause-final position. Four near-miss negative controls hold this — a guard that suppresses
   the intake's own questions is worse than no guard.
6. **`make safety` grew a lane.** CLAUDE.md defines `make safety` as "triage goldens +
   policyguard suite + runtime invariants"; the PolicyGuard suite did not exist until now, so
   the target only ran the triage half. It now runs `tests/voice` at the invariant-8 floor.
7. **One SLO, not four.** `docs/slo/voice-runtime.yaml` declares availability only. The
   interesting objectives are per-turn (`voice.round_trip_ms`, `preempt.red_latency_ms`) and
   need a real session against a real LiveKit tier; an objective over a series that carries no
   data is an objective nobody can breach. They join the file with INT-094/INT-095. The
   reasoning is written into the file so the gap is a recorded decision, not an omission.
8. **Three metrics promoted to `live`, not twenty.** `talker_tool_calls_total`,
   `policyguard_blocks_total` and `delivery_insertion_wait_ms` are emitted, so their catalogue
   rows flip and `tests/observability/test_metrics_catalog.py` gains the emitter import. Every
   other `voice_*` row stays `planned`, honestly, because nothing emits it yet.
9. **The `voice-runtime` registry row is untouched.** `self_hosted_now` stays `false`: this
   issue lands the code, not a deployment, and flipping it would make `make release-gate` block
   on a `phi_path` component with no healthy fallback.

## Explicitly out of scope (and untouched)

`packages/protocols/**` and `packages/voice-clips/**` are consumed, never edited —
`protocols.dsl.clip_text_hash` is imported so the Talker and the compiler agree on the clip
key by derivation. No `docs/backlog`, no `docs/PROGRESS.md`, no `.github/**`, no `apps/**`.
Layer B (INT-092), the RED preemption path (INT-093), the latency harness (INT-094) and the
`typed` profile's parity run (INT-096) are all behind ports rather than stubbed.

One gap found and **not** fixed here, reported instead: `protocols.compile.resolve` carries a
private `_question_count` / `_is_interrogative` pair that answers the same question
PolicyGuard's turn-level check answers, at compile time instead of at runtime. They should
share one implementation. Doing that means editing `packages/protocols/**`, which this issue
may not.
