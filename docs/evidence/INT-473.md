# INT-473: in-tree detent sheet (ADR-038 A3) for the dialogue's section sheet

GitHub #807. This is section 5 of the native pass. Decision: ADR-038 A3 (accepted on #788; owner, "yes approve 1-3"). The dialogue's section sheet was a React Native `Modal`, which is a window of its own: a RED root layer mounted after the navigator could not paint above it. It is now an in-tree detent sheet.

The spec is `docs/design/library-patterns.md` §5.2, the "Section sheet" row (Astryx BottomSheet and beUI bottom-sheet, both MIT; rebuilt natively, with no code copied).

## Stacked on

This branch is `int-473-detent-sheet`, stacked on #806 (INT-472), which contains #801, #797 and #792. Merge order: … → #797 → #801 → #806 → this PR.

## What changed

- **Pure rules (`lib/motion/sheet.ts`), unit-tested.**
  - Detents: medium is half the frame, and large sits under the screen's own bar.
  - The release rule: the throw is projected 120 ms ahead, and a release past the threshold closes.
  - A tap on the grabber moves to the other detent.
  - Presenting is on A1's spring, or the 120 ms fade under Reduce Motion. Settling is on the spring, or a snap.
  - A close by the patient settles. A privacy close and a RED close are instant at every setting.
- **The spring module (`lib/motion/native/sheetMotion.ts`).** It takes `SHEET_SPRING` from the pure module and writes no number of its own. The motion guard now names it beside the bubble entrance. ADR-038's consequences said the sheet would add exactly this module.
- **`components/DetentSheet.tsx`.** It renders in the opening screen's own tree:
  - a dimmed backdrop that closes it;
  - a grabber and header that a drag follows (PanResponder);
  - the content in a ScrollView;
  - `accessibilityViewIsModal`, the VoiceOver escape and Android's back button, each of which closes it;
  - the side and bottom insets.
- **`SectionSheet`.** It is a `DetentSheet` now. Its rows, its copy and its close control are unchanged. The dialogue passes `top`, the height of the bar the stage runs under.

## Guards moved, each keeping its intent

- **`e2e/sheets.spec.ts` (new).** Nothing in `src` presents a window of its own: no `Modal`, no `formSheet` or `modal` presentation, no portal, no bottom-sheet library. A near miss covers each form. The section sheet is in-tree, and the root layout presents nothing.
- **`e2e/motion.spec.ts`.** The spring allow-list is A1's bubble plus A3's sheet, and it may only shrink. The sheet module has no number of its own and moves only translateY.
- **`e2e/a11y.spec.ts`:**
  - **No Modal is left.** The Modal rules (focus flag, rotation, Reduce Motion) stay for any Modal that comes back. A new test pins the in-tree sheet's focus flag and its escape.
  - **SC 2.1.4.** Android's back button is a navigation key, not a character key. Only the sheet takes it, to close itself as `Modal`'s `onRequestClose` did.
  - **SC 2.5.1 and 2.5.7.** The one drag is the sheet's, and each thing it does has a tap: the grabber tap changes the detent, and the backdrop and the close control close the sheet.
  - **Landscape.** The `maxHeight: "78%"` exception is gone along with the Modal's style.
- **`src/lib/motion/transients.test.ts`.** Exits are instant everywhere except the sheet's dismissal by the patient. A3 grants that exit, and it comes from the policy, which makes privacy, RED and Reduce Motion closes instant.

## Found on the simulator, and fixed

**The bar item vanished after a fast refresh.** After a hot reload of the dialogue, the note's progress item ("1 / 10 bölüm") was gone. INT-466's cleanup that removes the item on unmount was a passive effect. expo-router's `Stack.Screen` sets options in a layout effect, so on a refresh the passive cleanup ran after the screen had set the item again, and wiped it.

The cleanup is now a layout effect, so every cleanup in that phase runs before every setup. `chatStage.spec` pins it:
- red: 1 failed and 15 passed;
- green: 16 passed.

This was dev-only: a production build never fast-refreshes. It is fixed here because the sheet opens from that item.
