# INT-410 — Release bundles carry no synthetic seed accounts (audit F30)

**Epic:** E08-mobile · **Phase:** P1 · **Sec-Row:** mobile · **GitHub:** #689 ·
**Labels:** area:mobile, risk:security · **Depends on:** INT-130 (merged) ·
**Found by:** INT-179's close-out (PR #687); production audit F30

## Acceptance (verbatim)
- "the seed accounts and their fixtures live behind a dev-only module that the release bundle excludes (a lazy import in a `__DEV__` branch the bundler strips, or a dev-only entry); a bundle test over the production export proves no seed identifier, name or fixture string is present, with a near-miss control where a planted seed string in a release path fails"
- "invariant 17: no demo data outside tests or fixtures reaches a release build"

## Problem
The synthetic seed lives in `apps/mobile/src/lib/dev/accounts.ts`. It holds two
accounts, three visits, two carried facts and two records, with names,
hospitals, a medication and an allergy.

The welcome screen rendered the seed only under `__DEV__`, but it imported
`testAccounts` **statically**. Metro keeps a statically imported module
whatever reads it. The production export of main shows the result: every seed
identifier, name, hospital, fact text and record title was in both the iOS and
the Android bundle, all 17 markers, next to a live `testAccounts` getter.

Eight more shipped modules imported the seed module for its types. Types are
erased, so those imports carried nothing into the bundle. They did make
"nothing shipped touches the seed" impossible to check mechanically.

## Change
- **`src/lib/types/account.ts` (new, types only).**
  - `NoteStatus`, `ConsentState`, `VisitFixture`, `RecordFixture` and
    `TestAccount` move here unchanged, as the audit's F30 fix column asks.
  - The seven shipped modules that used them now import them from here:
    `session.tsx` (import and re-export), `visits.ts`, `VisitCard.tsx`,
    `StatusChip.tsx`, `StatusLadder.tsx`, `consent/purposes.ts` and
    `health/capability.ts`.
  - `intake/note.test.ts` now takes its `TestAccount` type from here too.
- **`src/lib/dev/accounts.ts`** now holds only the seed. It imports its
  shape, and its header says how it is reached.
- **`src/app/(auth)/welcome.tsx`.** The static import is gone.
  - The dev card is now its own component, `DevSignIn`. It is still rendered
    under `{__DEV__ ? <DevSignIn /> : null}`.
  - It loads the seed with `import("@/lib/dev/accounts")` **inside
    `if (__DEV__)`**, in an effect with an unmount guard.
  - Why this removes the seed, checked in the source rather than assumed: in
    `metro-transform-worker@0.84.5` (`src/index.js`), `inlinePlugin` replaces
    `__DEV__` with `dev`. For a release build, `constantFoldingPlugin` then
    drops the dead branch. Both run **before** `collectDependencies`, so the
    `import()` never becomes an edge in the release graph.

## The tests: one per CI job, because each job has one toolchain
The first design was a single pytest that ran `expo export`. It passed locally,
red and green, both platforms. It needed the check-py CI job to install the Node
workspace, which meant adding three pinned pnpm/Node steps to
`.github/workflows/ci.yml`. **The permission system refused to stage the
workflow file**, so this PR does not touch CI.

The export therefore runs where Node already is, and the issue's named Python
file checks the same property statically in check-py.

### `apps/mobile/e2e/releaseBundle.spec.ts`: the production export (check-ts)
- **Build.** `beforeAll` runs
  `node_modules/.bin/expo export --platform ios --platform android --no-bytecode`
  into an `os.tmpdir()` directory, which `afterAll` removes and which is never
  committed.
  - The environment is
    `CI=1 NODE_ENV=production EAS_BUILD_PROFILE=production EXPO_NO_TELEMETRY=1 EXPO_OFFLINE=1`.
  - That is Metro with `dev=false` and minification, the transform a store
    build runs through `export:embed`.
  - `--no-bytecode` stops before `hermesc`, which compiles this JS and keeps
    its strings.
  - With the workspace absent, `beforeAll` **throws** and names the install
    command. It never skips (invariant 17).
- **Markers.** They are read out of the seed at run time: every `id`, `name`,
  `hospital`, `text` and `title` value, 17 today. The test never spells them,
  and it fails if fewer than 10 are derived.
- **Search.** Metro escapes non-ASCII as `\uXXXX` or `\xNN`. Main's bundle has
  `"Ayşe Yılmaz"` and `"İ\xe7 Hastalıkları"`, so the bundle is decoded
  before it is searched. A marker counts only as a whole string literal.
- **What the 10 tests check.**
  - The markers are derived.
  - The iOS bundle and the Android bundle each carry no marker.
  - Each bundle is the real app: over 1 MB, carrying `"welcome.phoneCta"`.
- **Controls: a planted seed string fails.**
  - A seed name, escaped as Metro writes it, is appended inside a module
    factory to the real iOS bundle. It is found.
  - A seed id is appended to the real Android bundle as a single-quoted
    literal. It is found.
  - Every marker, each in escaped form, is found.
- **Near misses: what is not the seed passes.**
  - The seed's `department` values are the taxonomy's own branch names. They
    are not markers, and at least one of them really ships in the release
    bundle.
  - A marker inside a longer word (`"k<marker>ri"`, the shape of a short id
    inside a city name) is not a hit.

### `tests/release/test_release_bundle_has_no_fixtures.py`: the release graph (check-py)
- **Entry.** `package.json` `main` is asserted to be `expo-router/entry`.
  - The roots are what its `require.context` over `src/app` matches: every
    `.ts`, `.tsx`, `.js` and `.jsx` file except `+api` and the root
    `+html`/`+middleware`.
  - Test files count as roots, since a test under `src/app` is a route.
  - There are 27 roots today.
- **Edges.**
  - A static `import`/`export … from` is an edge unless it is type-only. That
    covers `import type`, and `{ type A, type B }` where every name is a type.
  - A dynamic `import()`/`require()` is an edge unless it lies inside an
    `if (__DEV__) {…}` block. The block is found by brace matching that skips
    strings and comments.
  - Every platform variant of a file is followed (`.ios`, `.android`,
    `.native`, `.web`).
  - Packages are not followed.
  - The walk may reach more than Metro does, never less.
- **What it checks on the real tree.**
  - The seed module is not reachable.
  - No reachable module holds a marker as a string literal. There are 169
    reachable modules.
  - The one folded edge to the seed is the welcome screen's.
  - Every local specifier resolves, so no subtree is silently dropped.
  - `lib/types/account.ts` is not reachable, because it is imported for types
    only.
- **Controls, on a planted tree in `tmp_path`.** The tree holds a copy of the
  real seed.
  - A static import is caught: the seed is reached and all 17 markers found.
  - An unguarded `import()` is caught the same way.
  - A seed name planted as a literal in a release module is caught.
- **Near misses, on the same planted tree.** Each passes:
  - an `import()` inside `if (__DEV__)`;
  - an `import type`, and an all-`type` named import;
  - a seed name in a module no route reaches;
  - the seed's shared `department` string in a release module;
  - a marker inside a longer word.

## Outside the acceptance (recorded, not built here)
- **CI wiring the owner may prefer.** The artefact test could also run in
  check-py. That needs the three pinned steps `check-ts` already uses
  (`pnpm/action-setup`, `actions/setup-node` with `cache: pnpm`, and
  `pnpm install --frozen-lockfile`) added to the `check-py` job. The workflow
  file is the owner's to change, and this PR does not need it.
- **The type names still say "Fixture".** `VisitFixture` and `RecordFixture`
  are the production shapes of a real account's visits and records. Renaming
  them touches every screen and is not F30.
- **The dev card is not exercised on a device here.** `import()` in a
  development build goes through Metro's lazy bundling (Expo Go and the dev
  client). The `--dev` export above shows the module is reachable. There was no
  simulator run.
- **`lib/auth/expoApiBase.ts` reaches `../dev/expoHosts` through an
  `import()` that is not inside `if (__DEV__)`.** That module derives dev LAN
  candidates from Metro's host URI and the app config. It holds no seed data,
  so it is not F30. INT-328 owns the dev-host tier.
- **PR #687** (INT-179's close-out) quotes the old accounts test name, "exactly
  one screen imports the fixtures", and the finding "the seed module is still in
  the release bundle". Both stop being true once this merges. That text belongs
  to #687, and this PR does not edit it.
