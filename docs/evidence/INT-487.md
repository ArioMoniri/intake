# INT-487 — probe emitters use fullmatch for id, ref and sha shapes

GitHub #832 · Sec-Row `admin-console` · phase P1 · 16 Oct 2026

**Acceptance, verbatim from GitHub #832** (the row is in PR #867, see *Backlog
row* below):
- "use .fullmatch everywhere, with near-miss tests per emitter." — **met.** All
  nine shape checks in `services/probes` now use `.fullmatch`. Each emitter has
  near-miss tests: the clean value is accepted and the same value plus `"\n"`
  is refused. An AST guard keeps `.match(` out of the service.

**The defect.** The ops collector in `services/probes` exports GPU, CI and
CI/CD series that the admin consoles read through Prometheus. It held ids,
refs and shas to `$`-anchored patterns with `re.match`. Python's `$` also
matches just before a final `"\n"`, so a value with a trailing newline passed
the shape check. Some of those values became labels: a workflow `"security\n"`,
a head sha, a failing job `"check-integration\n"`, a release tag. Two
consequences are worse than an untidy label:
- A host id, repository or branch with a trailing newline was accepted as
  configuration.
- A pull-request head sha ending in `"\n"` went into the check-runs URL.
  httpx then raised `InvalidURL`. That is not a `CiSourceError`, so
  `collect_once` did not catch it, and the error reached `run_collector`'s
  loop. The red run below shows it.

This is the emitting side of INT-486 (#831, PR #845), which fixed the same
`$` + `.match` check in the API's `ops_prom.PromSession`.

**The fix.** Each check now calls `pattern.fullmatch(value)`, so the shape must
hold the whole value. The patterns themselves are unchanged. One comment at
`ID_SHAPED` (`ops_gpu.py`) and one above the shapes in `ops_ci.py` say why.
Nine call sites changed. `git diff` shows exactly these:

| File | Line | Shape | What it guards |
|---|---|---|---|
| `ops_gpu.py` | 76 | `ID_SHAPED` | `require_id`: the GPU host id (`host_id` label) |
| `ops_ci.py` | 124 | `_REPO_RE` | `check_github_target`: the repository |
| `ops_ci.py` | 126 | `REF_RE` | `check_github_target`: the watched branch (`branch` label) |
| `ops_ci.py` | 163 | `_WORKFLOW_PATH_RE` | `parse_run`: the run's workflow file path |
| `ops_ci.py` | 171 | `ID_SHAPED` | `parse_run`: the workflow stem (`workflow` label) |
| `ops_ci.py` | 176 | `SHA_RE` | `parse_run`: the run's head sha (`head_sha` label) |
| `ops_cicd.py` | 169 | `SHA_RE` | `_sha`: branch head, pull head and tag commit shas |
| `ops_cicd.py` | 353 | `JOB_NAME` | `_failed_jobs`: a failing job's name (`job` label) |
| `ops_cicd.py` | 424 | `REF_RE` | `_releases`: a release tag (`tag` label) |

`GithubCicdSource` checks its target through the same `check_github_target`,
so the repository and branch fixes cover both GitHub sources.

## The repository grep: fixed and left

`.match(` on a pattern ending in a bare `$` was found by an AST scan of every
tracked `.py` under `services/`, `packages/` and `scripts/`, tests excluded.
The scan resolves module-level `re.compile` constants.

**Fixed (this PR):** the nine sites above. They are every `.match(` in
`services/probes`.

**Left, with the reason:**
- `services/probes/src/intake_probes/registry.py` declares
  `Field(pattern=…)` shapes (`_SHA256_RE`, `_REVISION_RE`, `_IMAGE_RE`,
  `_FALLBACK_RE`, `component`). These are already strict. pydantic-core uses
  the Rust `regex` engine, where `$` is end of text only. Checked on pydantic
  2.13.4: a 40-hex value is accepted, and the same value plus `"\n"` is refused.
  The weights check in the same file already uses `re.fullmatch`.
- `services/api/src/intake_api/admin/ops_prom.py:179` is INT-486 (#831,
  PR #845, open). This PR does not touch it. The mirror assertion in
  `tests/observability/test_ops_cicd.py::TestExport` is also #845's change.
- No other probe or ops metric emitter calls `.match(`.
  - `services/metrics` has no `.match(` call.
  - Of the modules that build Prometheus metrics, only
    `intake_platform/analytics/k_anonymity.py:203` hits the scan. It checks
    analytics cell dimensions, not label values. Its counters label only the
    view name and a reason enum.
- The other hits are validators in other bounded contexts, not emitters. Each
  has its own Sec-Row and tests, and changing them is a separate issue (one
  issue per PR):
  - consent: `consent/service.py:173`, `consent/guardian.py:74`,
    `consent/minors.py:390,431`
  - audit: `compliance/audit_search.py:88,129`
  - SIEM: `siem/models.py:94,99,132`
  - legal: `legal/document_index.py:118,121,126,194`, `legal/strings.py`
  - connectors: `destinations.py`, `identity.py`, `fhir.py`, `filedrop.py`,
    `acibadem.py`, `usvs.py`
  - cost config: `cost/config.py:59,175,183`
  - SLO and alert-rule loaders over committed YAML: `slo.py`,
    `slo_coverage.py`, `alert_rules.py`
  - the CI pin check: `ci/workflows.py:168`
  - embed registry: `embed/registry.py`
  - locale codes, the protocol compiler, voice-clips delivery, and the
    voice-runtime parsers (`extraction/parse.py:146`,
    `note/translation.py:106`)
  - backlog and CI scripts that match one line at a time, after
    `splitlines()` or `.strip()`, so no line ends in `"\n"`
  - The id, ref and sha shapes on PHI or security paths in this list are
    candidates for one repo-wide sweep issue. That id is for the orchestrator
    to allocate. No id is minted here.
