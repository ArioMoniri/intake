# ADR-028 · The edge is a second enforcement point, and a proxied personal-data transport is the fourth bypass

Status: Accepted

## Context

INT-203 adds an edge tier — Traefik with Coraza and the OWASP CRS, CrowdSec at the perimeter, cert-manager for certificates, and a forward egress proxy — and with it a new shared surface, `intake_platform.edge`. Two things about that are not obvious enough to leave implicit. The first is that the egress allow-list now has **two** enforcement points rather than one, and they enforce by different means: the in-process guard resolves a destination and pins the socket to the resolved address, while the proxy matches a CONNECT line against an ACL and never lets the process resolve at all. Two enforcement points that can disagree are worse than one, because a reviewer who checks either concludes the boundary holds. The second is that ADR-025 catalogued four ways a hostname allow-list is bypassed, INT-160 found a fifth shape (a host approved for a different tenant) and INT-161 a sixth (a token endpoint approved for a purpose that is not receiving records) — and INT-203 found that the next one is not a call site at all. It is a **configuration**: a personal-data transport pointed at the forward proxy. That is the single arrangement in which *neither* enforcement point resolves, because the process delegates the lookup to the proxy and the proxy's allow-list carries no connector rows and an empty PHI tier. It looks like an ops setting rather than a change to a security boundary, which is precisely why someone would make it.

A third thing was measured rather than assumed. files/10 §4 asks this tier to *"resolve once and pin, re-validating on connect"*. squid evaluates its `dst` ACL against an IP cache whose default positive TTL is **six hours**, so a name can be authorised against one answer and connected to against another — a DNS-rebinding window that the in-process guard provably cannot close, because behind a proxy the process deliberately does not resolve.

## Decision

The two enforcement points are rendered **from one generator**, so they cannot drift: the same source produces the in-process allow-list and the squid configuration, and a destination that is absent from one is absent from both. The proxy's rebinding window is closed at the proxy, where it exists — `ipcache_size 0`, `fqdncache_size 0`, one-second TTLs and `dns_defnames off`, so the ACL check and the connect share one lookup per request — rather than by adding a guard in the process, which would be a control placed where the vulnerability is not. A personal-data transport constructed with `proxy=` is **refused at construction**, with the reason carried in the exception, because the refusal must land before any byte is in flight rather than at the moment of a denied CONNECT; the near-miss control asserts that a *non-personal* call — a package or model pull — may still use the proxy and its hostname still reaches the CONNECT line, so the rule does not disable the tier it guards. Coraza's default log line quotes the offending argument back, which for this system means the patient's own utterance in `ARGS:json.text_tr`; that is answered with `EdgeEvent`, a **closed record** of what fired and where, rather than with a redaction filter over free text, because a filter is a list of things someone remembered and a closed record is a list of things that exist (invariant 6).

The WAF, CrowdSec and certificate clauses are **not claimed at close**. They were measured green on 3 Sep 2026 against a real Traefik 3.3.7 with Coraza and OWASP CRS 4.0.0 — twelve corpus cases, seven CRS families refused, five ordinary Turkish clinical turns served, cold boot to green in 28 s — and that measurement is recorded in `docs/evidence/INT-203.md` with its date and named corpus, never as a property of the product (invariant 20). The acceptance is a property of a *running tier*, and there is now no sanctioned runtime anywhere: Docker is forbidden on the development machine and the GPU server has none, being itself a pod. The suite therefore **fails rather than skips** — 17 errors, 0 skipped, rc=1, never reaching `docker compose` — because a skipped suite reports the same green as a passing one (invariant 17).

## Consequences

`intake_platform.edge` becomes a shared surface with the same standing as the connector framework, and the egress composition documented by ADR-025 is **narrowed**: `proxy=` and a personal data class are now mutually exclusive, which invalidates any deployment note that suggested routing connector traffic through the forward proxy. One existing test moved as a result — `test_a_wrong_purpose_is_still_refused_behind_the_proxy` reached the purpose check through a PHI data class and now uses `NON_PERSONAL`, with a new test beside it asserting the earlier refusal for both personal classes; the refusal moved earlier, which is strictly stronger. Three CrowdSec scenarios in one file load as **one**, so scenario counts are asserted after load rather than by counting documents. The tier ships with `domains: []` and no `Certificate` rendered, and the ACME account email is an environment variable with no default, because a production hostname and a mailbox are human facts (HB-I13, HB-I14). Enforced by `tests/infra/test_edge_egress.py` (18 assertions, a local resolver stub and recorded fixtures, no container) and the deliberately-failing `tests/infra/test_edge_waf.py`; signalled by `sec_egress_denied_total`, whose catalogue row is `status: live` with `target: "0 (any increase pages)"`; recorded against files/10 §9 row `edge`.
