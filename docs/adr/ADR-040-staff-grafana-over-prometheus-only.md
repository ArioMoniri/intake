# ADR-040 · A staff Grafana over Prometheus only, on the synthetic staging host

Status: Accepted (owner request, 4 Oct 2026; INT-481)

## Context

The owner asked, on 4 Oct 2026, to *"have grafana or related better options or more detailed things for the admin panel and all telemetrics measurements"*. The staging host had no metrics store at all: every Prometheus-fed tile in the admin console read *unknown* there. files/08 §0b F1 (CRITICAL) and files/10 §2 say Grafana, Langfuse, Loki, Tempo and Unleash are *"unreachable from any browser origin"*, and invariant 48 (`console_isolation_guard`) says *"no PHI-bearing datastore reachable from a browser origin that did not transit `services/api/admin`"*. F1's reasons are specific: Loki and Tempo carry PHI-path log lines and spans, Langfuse stores prompts verbatim, a Grafana account is a second identity store that offboarding misses, Explore runs any query a user types, and an iframe forces a third-party `frame-src` into the console's CSP. A Grafana that keeps none of those properties is a different object from the one F1 describes, and the owner has now asked for it. Without a decision the request either goes unanswered or reopens F1 by accident.

## Decision

The synthetic staging host runs a staff Grafana whose **only datasource is Prometheus**, and Prometheus stores **only the reviewed label keys** (every scrape job ends with a `labelkeep` of `intake_platform.observability.labels.ALLOWED_LABEL_KEYS`), so nothing Grafana can read is PHI-bearing. Grafana is served on **its own origin**, `grafana.<host>`, behind **its own oauth2-proxy and its own Keycloak client**, never the console's origin, session or token audience. It admits a staff session from the realm's two-factor flow holding one of the roles that may read the ops console (`admin.ops.read`), re-checked against Keycloak every five minutes. Grafana has **no identity of its own**: no admin account, no password, no sign-up, no anonymous access, no API key. Every user is a Viewer, with Explore off and every dashboard provisioned from generated, drift-gated files. It has **no egress**: internal networks only, with plugin, update, news, snapshot and gravatar traffic all disabled. The admin console **links** Grafana from its Alerts page and never frames it, so the console's CSP keeps `frame-src 'none'`. **Loki, Tempo and Langfuse remain unreachable from any browser origin**, and a Grafana datasource of any other type fails the build. A deployment that holds real patient data does not inherit this decision. It needs its own, after HB-I5 and HB-L11.

## Consequences

The owner gets dashboards for host health, the synthetic probes, every SLO's remaining error budget, API and voice latency, model-lane usage and the budget alerts, triage and RED safety in aggregate, CI, and deploy markers. The admin panel gets an Alerts page fed through the API (`GET /admin/alerts`, ids only). F1 is narrowed, not withdrawn: the threats it names are each closed by a test rather than by the absence of Grafana. `tests/infra/test_staging_obs_tier.py` pins the single Prometheus datasource, the auth-proxy header, the role list (equal to `_PLATFORM_SCOPE_ROLES`), the separate client and cookie, the absence of any published port or data-network attachment, and Caddy routing the Grafana host to its gate only. `tests/observability/test_metric_labels.py` pins the label allow-list across the catalogue, the rule files, the dashboards and the staging scrape jobs. The console's CSP tests are unchanged. What becomes harder: Grafana is a second web surface on the host and an AGPL-3.0-only component. It runs unmodified from the upstream image, for this deployment's staff only, and is never distributed or offered to anyone else. A modification or an offer to third parties reopens the licence row in `observability/registry.yaml`. Offboarding still revokes it, because Keycloak is the only identity.
