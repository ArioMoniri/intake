# ADR-043 · A multi-select option can be exclusive, and only the patient clears a selection

Status: Accepted (INT-604, GitHub #1029; owner decision M1, 17 Nov 2026, under D18: synthetic host and simulated patients only, a licensed physician signs before any real patient)

## Context

The protocol DSL had no multi-select slot and no per-option attribute (`packages/protocols/src/protocols/dsl.py`), and the app's chips steps let a patient hold "Yok" beside a symptom, so the review could read "Eşlik edenler: Boğaz ağrısı, Yok" (design audit 2026-11, Part B M1). `base.intake` `chest_pain.radiation` is the input of both active chest-pain rules: the K2 cardiac RED reads `radiation in {"kol", "çene", "sırt"}` and its SARI sibling reads `radiation == "yok"`. Two answers that contradict each other in that one slot make the SARI rule's premise false while the RED's is true. The obvious fixes are both unsafe. A server that trims "yok" decides for the patient after they submitted. A server that trims the symptom, or refuses the set, leaves a firing symptom unevaluated, and invariant 1 exists to prevent exactly that. The triage hop had a further defect: a chips answer reached the engine as one list value, which reads Unknown, so a symptom chosen among several could never fire.

## Decision

A code slot may declare `multiple: true`, and its `options:` map may mark one member `exclusive: true`. Selecting an exclusive option clears every other selection, and selecting any other option clears it. **This happens only on screen, before submit, in the one function both intake lanes call (`toggleOption`). Nothing after submit ever removes a value from a submitted set.** The schema refuses `exclusive` on a single-select slot and refuses a second exclusive option on one slot. No exception is allowed: two options that each clear the other leave the patient no way to say both. The compiler refuses an `options` key that is not a member of the slot's value set (`OPTION_OUTSIDE_CHOICES`). It also refuses a multi-select "yok"/"hiçbiri" choice that is not exclusive (`NONE_CHOICE_NOT_EXCLUSIVE`). The server binder (`protocols.choices.bind_choice_set`) refuses a set that holds the exclusive option beside another member, and it never trims one. Its production caller is the voice runtime's extraction parser: a multi-select slot's schema is an array of the committed members, a set holding "yok" beside a site is flagged `exclusive_conflict` and nothing is bound. The extraction handler then asks the step again through the engine's clarify path, using its verbatim `follow_up_tr`. Once the clarify budget is spent, it binds the named members as named, and triage reads them as the union. A named site therefore always reaches triage and is never left pending or recorded as a bare UNCLEAR. The triage hop and the voice runtime's live triage read a submitted set whole (`submitted_set_answer`): one member is that member, and several are the files/12 §7.3 union, so any member that fires, fires. The hop applies no exclusivity, because refusing a mixed set there would leave a firing site unevaluated. The hop does refuse (422) a set holding a value outside a committed code slot's members, and several members on a single-select slot. The engine bounds the contested-world product at `MAX_CONTESTED_WORLDS` (4096). Past the cap the predicate reads TRUE: the rule fires. That is the over-triage direction, never a skip. A suggested set, such as a voice candidate or a prefill, that holds both is reconciled before it is shown, by dropping the exclusive option and keeping the symptom. A suggestion can therefore only show more than "Yok", never less.

## Consequences

Contradictory selections cannot be submitted from either lane, and a set that bypasses the lanes still fires every rule its members fire. Triage sees exactly the submitted set: `tests/safety/test_exclusive_choice_triage.py` pins that "kol" + "yok" still fires the cardiac RED, and that "yok" alone, the near miss, does not. Red-flag semantics are unchanged: no rule was added, removed or relaxed, and invariant 7 is untouched. Overlays cannot change `multiple` or `options`, because neither is in the files/12 §3.2 `set_attr` table, so no layer can turn an exclusive option off. The cost is one more field pair on `Slot` and one more compile check. Tests: `tests/protocols/test_exclusive_options.py` (schema, compiler, binder), `tests/api/test_triage_hop.py` (the hop reads a set whole), `apps/mobile/src/lib/intake/exclusive.test.ts` (both lanes, every "Yok" marked, and triage sees only the final set) and `apps/mobile/src/lib/dialogue/stream.test.ts` (suggestions). `tests/voice/test_multi_select_voice.py` covers the voice lane ("omuz" + "kol" fires K2; near miss: "omuz" alone does not) and `tests/safety/test_contested_world_cap.py` covers the cap and its timing bound.
