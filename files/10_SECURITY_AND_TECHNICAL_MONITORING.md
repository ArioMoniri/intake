# 10 · Security architecture and technical monitoring — cross-cutting for every feature (v1.4, 21 Aug 2026)

> Security and monitoring are not a module; they are properties every feature must prove. This file is the canonical spec; each other file carries a short "Security & technical monitoring" section that points here and adds what is specific to its scope. Three rules govern everything: **(1) every feature ships with its threats, controls, signals and tests written down** (§9 matrix); **(2) every service exposes the same health/metrics/trace contract** (§6); **(3) every control on the PHI path is self-hostable and verifiable from the admin console** (`08`). Standards we map to: OWASP ASVS 5.0 (L2), OWASP MASVS 2.x (mobile), OWASP Top 10 for LLM Applications 2025, NIST SSDF, CIS Benchmarks (k8s, Postgres, Linux), ISO/IEC 27001:2022 + 27701, KVKK Board "adequate technical measures", and the Turkish *Bilgi ve İletişim Güvenliği Rehberi* for public-hospital tenants.

## 1. Threat model (summary; full STRIDE/LINDDUN model lives in `docs/security/threat-model.md`)
**Assets:** patient identity (TC Kimlik, phone), clinical narrative and notes, audio in flight, learned facts, consent state, share tokens, clinician identities, protocol packs (clinical safety), model weights/prompts, audit log, admin controls.
**Adversaries:** opportunistic internet attackers (credential stuffing, OTP abuse, SMS pumping), malicious or careless insiders (support, hospital IT, contractors), a compromised vendor or dependency (supply chain), a malicious patient/companion (prompt injection by voice or uploaded document, impersonation, triage manipulation), a hostile network (public Wi-Fi, kiosk tampering), and an attacker with physical access to a kiosk or lost phone.
**Top risks and the control that owns each:** PHI exfiltration via logs/analytics → redaction + no-PHI invariants + egress allow-list; account takeover via OTP → rate limits, device attestation, device binding, anomaly alerts; prompt injection by speech/document → data/instruction boundary, six-tool Talker, deterministic triage, PolicyGuard, injection eval suite; unauthorised note access via Doctor Link → OTP + short-lived scoped tokens + revoke + access log; insider browsing → RBAC/ABAC, break-glass with 4-eyes, hash-chained audit, Wazuh alerts; supply-chain compromise → SBOM, scanning, signed images/protocol packs, admission control, pinned model weights; cloud-vendor overreach → de-identification before cloud calls, ZDR contracts, egress logs as transfer evidence; kiosk tampering → lockdown, ephemeral sessions, no local persistence; ransomware/DR → immutable backups, PITR, quarterly restore drills.

## 2. Identity, access and session security
- **Patients:** phone OTP (6 digits, 5-min TTL, 5 attempts, 3 requests/hour/phone, 10/hour/IP, carrier/geo sanity checks against SMS pumping) + **device attestation** (Apple App Attest / Google Play Integrity) on OTP request and session start; optional passkeys (WebAuthn) after first login; e-Devlet identity assurance as a P3 option for hospital tenants that require it. Access tokens 15 min, refresh tokens rotating and **device-bound** (DPoP, RFC 9449); refresh reuse detection revokes the family; biometric gate on app open and before note/share screens; idle timeout 10 min on clinical screens.
- **Clinicians (Doctor Link):** OTP to the phone/e-mail the patient chose + 128-bit random token + expiry (default 72 h) + view limit + instant revoke; PDF downloads watermarked with recipient and timestamp; optional hospital SSO (SAML/OIDC via Keycloak) for console users.
- **Staff/admin:** Keycloak (self-hosted) OIDC with MFA (TOTP/passkeys), RBAC + ABAC by tenant, IP allow-list for console, session ≤ 8 h, step-up auth for safety-critical switches, **4-eyes** for kill switch / profile change / S2S enable / proposal approval / break-glass, quarterly access reviews recorded in the console.
- **Services:** workload identity via k8s service accounts + SPIFFE-style certificates from the mesh; no shared service passwords; dynamic database credentials from OpenBao (TTL 24 h); least-privilege Postgres roles + row-level security per tenant.

## 3. Data security and privacy engineering
- **Encryption:** TLS 1.3 everywhere (HSTS, modern ciphers, certificate automation with cert-manager/Let's Encrypt or hospital CA); **mTLS between services** via a service mesh (Linkerd, or Cilium) with default-deny NetworkPolicies; volumes encrypted (LUKS/cloud volume encryption) **and** field-level **envelope encryption** (AES-256-GCM) for identifiers, transcripts, notes and learned facts with per-tenant data keys wrapped by keys held in **OpenBao** (open-source Vault fork; Transit engine); key rotation quarterly; **crypto-shredding** implements hard delete.
- **Tokenization:** TC Kimlik and phone are never stored in clear in application tables — a tokenization service returns a keyed pseudonym (HMAC-SHA-256 with a rotated key) for joins and an encrypted value in a separate vault table; logs and analytics only ever see the pseudonym's hash prefix.
- **De-identification before any cloud model call** (`cascade_fast`, `s2s_cloud` text paths, Loop 2): a redaction service (Microsoft Presidio with Turkish recognizers: TC Kimlik checksum, phone, IBAN, names via a Turkish NER model, addresses, dates shifted) with unit tests per entity type and a measured leak rate (< 0.1 % on the synthetic corpus); raw audio to S2S vendors is itself the payload and is therefore a DPIA-addendum item (`06`).
- **No PHI in telemetry:** OTel collector runs a redaction processor (regex + allow-list of attributes); logs are structured JSON with ids only; an `audit.v1`/`security.v1` event schema separates security events from application logs; CI test greps fixtures for PHI patterns.
- **Audit log:** append-only, hash-chained (each entry includes the previous hash), daily chain verification, copied to MinIO with **object lock (WORM)**; 10-year retention for hospital tenants; patient-visible access log for shares.
- **Backups & DR:** Postgres PITR (pgBackRest/WAL-G) encrypted with separate keys to a second location in Türkiye; MinIO/EHRbase/HAPI included; **RPO 15 min, RTO 4 h**; quarterly restore drills with evidence in the console; immutable backup copies defend against ransomware.
- **Retention automation:** jobs enforce `06 §3` (raw audio never written; lane windows zeroed; logs 30 d hot/1 y cold; deletion 30 d grace); job success is a tracked metric.

## 4. Application, API and mobile security
- **API:** OpenAPI-first with strict schemas (Pydantic), input limits, schemathesis fuzzing in CI, CSRF-safe (token auth only), CORS allow-list, security headers, idempotency keys on writes, per-route consent-scope checks (`consent_guard`), rate limits per user/IP/tenant, request size limits, file-type sniffing and sandboxed OCR for uploads (no macro/JS execution; PDFs rendered in an isolated worker with seccomp), antivirus scan (ClamAV) on uploads, signed URLs for object access (short TTL), no direct object references.
- **Edge:** Traefik or Envoy ingress with **Coraza WAF (OWASP CRS)** and **CrowdSec** for reputation/bot behaviour; **egress proxy with an allow-list** — only contracted vendors are reachable from the PHI path, and every egress call is logged with vendor, purpose and bytes, which doubles as KVKK transfer evidence.
- **Mobile (MASVS 2.x):** Expo dev builds only; tokens in SecureStore (Keychain/Keystore, biometrics-protected); certificate pinning; FLAG_SECURE / screenshot blocking on clinical screens; no PHI in push notifications or deep links; deep-link and QR validation (signed check-in payloads); jailbreak/root detection as a soft signal (degrade to typed mode + warn); App Attest / Play Integrity; **EAS Update code signing** for OTA; MobSF scan of every build; crash reports without PHI (self-hosted GlitchTip or Sentry self-hosted).
- **Kiosk mode:** guided-access/kiosk launcher, device enrolled in MDM, no biometrics, PIN per clinic, session auto-wipe after 60 s idle, no local persistence, tamper alert when the app is backgrounded, camera indicator for OCR.
- **Clinician web & admin console:** Next.js with strict CSP, SameSite cookies, SSO, no PHI in URLs, short sessions, audit on every view, download watermarking, break-glass only.

## 5. AI and voice-runtime security (OWASP LLM Top 10 2025 mapping)
| risk | control in INTAKE | test |
|---|---|---|

| LLM02 sensitive information disclosure | no cross-patient data in any context; de-identification before cloud calls; system prompt contains no secrets; `patient_memory` holds non-clinical preferences only | leak tests on fixtures; egress log review |
| LLM03 supply chain | model weights pinned by revision + sha256, mirrored in the internal registry (no runtime downloads in prod); prompts versioned and signed; vendor models pinned by name/date | registry test; provenance check |
| LLM04 data/model poisoning | Loop 2 is proposal-only with k-anonymity, clinician approval, canary; Loop 1 requires confirmation | `proposal_scope`, `k_anonymity` |
| LLM05 improper output handling | all model output validated against Pydantic schemas; never executed, never rendered as HTML; clip cache keyed by hash | schema tests; XSS tests on note rendering |
| LLM06 excessive agency | six-tool Talker registry (hook-protected); Backend Work types enumerated; no write tools to EHR from models | six-tool introspection test |
| LLM07 system prompt leakage | prompts contain policy only; secrets live in OpenBao; leakage detector on Talker output | PolicyGuard corpus |
| LLM08 vector/embedding weaknesses | pgvector rows scoped by patient + consent; RLS; no shared namespaces | RLS tests |
| LLM09 misinformation | clinician review, deterministic triage, "not a diagnosis" labels, provenance on every fact | goldens, note audits |

**Voice transport:** LiveKit room tokens per session with minimal grants (join, publish mic, subscribe agent) and 10-min TTL; rooms ephemeral and auto-closed; TURN credentials short-lived; DTLS-SRTP in transit; the agent worker is inside the trust boundary (no E2EE by design — documented in the DPIA); no recording features enabled on the SFU; `audio_retention_guard` proves no write paths.

## 6. Technical monitoring contract (every service, no exceptions)
- **Endpoints:** `GET /healthz` (liveness, no dependencies), `GET /readyz` (readiness: DB, Redis, queue, model reachability with timeouts), `GET /metrics` (Prometheus), `GET /version` (git sha, build time, SBOM digest). Mobile and web report `app_version`, `build_id`, `sbom_digest` in telemetry.
- **Telemetry:** OpenTelemetry traces, metrics and logs from api, voice-runtime, workers, metrics, probes, learning, clinician-web and admin-web; propagation of `trace_id`, `session_id` (hashed), `tenant_id`, `protocol_hash`, `prompt_version`; **golden signals** (latency, traffic, errors, saturation) dashboards per service; LiveKit Agents metrics (EOU/LLM/TTS/STT/VAD/Realtime/Interruption) and worker Prometheus (`worker_load`, `active_jobs`); client network quality from the LiveKit SDK (RTT, jitter, packet loss, connection-quality events) attached to each turn.
- **SLOs and error budgets** (`08 §4 A`): API availability 99.9 %, voice session success 99.5 %, note ready ≤ 60 s 99 %, Doctor Link open p95 < 2 s; multi-window burn-rate alerts (page at 14.4×/1 h and 6×/6 h, ticket at 1×/3 d); a frozen-deploy policy when the monthly budget is exhausted.
- **Synthetic probes:** `services/probes` exercises every model and service every 60 s (1-s Turkish audio through STT, "merhaba" through TTS, schema-constrained prompt through each LLM, room join through LiveKit, FHIR `metadata`, EHRbase health, OpenBao seal status, certificate expiry, backup freshness) and writes the registry the console renders.
- **Client monitoring:** crash-free sessions ≥ 99.5 % (GlitchTip/Sentry self-hosted), cold start p95 < 2 s, ANR rate, RUM for web (Core Web Vitals), device/OS matrix, offline-draft sync success.
- **Capacity & resilience:** k6 load tests and `lk load-test` for voice concurrency before each release; GPU headroom ≥ 30 %; autoscaling on queue depth and `worker_load`; chaos experiments (kill a vendor adapter, stall the Backend, drop the SFU) in staging monthly; results tracked as metrics.
- **Logging:** JSON, levels, no PII, sampling for debug, 30 d hot / 1 y cold, correlation ids; security events to Wazuh; `docs/runbooks/` linked from every alert; on-call rotation documented.

## 7. Security monitoring, detection and response
- **Signals:** failed logins and OTP anomalies (per phone/IP/ASN), impossible travel, new-device logins, token reuse detections, WAF/CrowdSec blocks, admin actions (all), break-glass events, consent-scope denials (`consent_guard` refusals), egress denials (attempted calls to non-allow-listed hosts — a hard alert), injection suspicions, PolicyGuard spikes, integrity failures (audit chain, image signature, protocol signature), vulnerability counts by severity and age, secret-rotation and certificate-expiry countdowns, backup freshness, DR-drill status, Falco runtime alerts, k8s audit anomalies.
- **Stack (self-hosted):** Wazuh (SIEM/XDR) + Falco (runtime) + CrowdSec (edge) + OTel security events; dashboards in the console's **Security** module (`08 §3`).
- **Targets:** MTTD < 15 min for P1 signals, MTTR < 4 h; vulnerability SLA critical 72 h / high 7 d / medium 30 d; patch latency tracked; quarterly tabletop exercises; annual external pen-test (first before P2 pilot) with findings tracked to closure in the console.
- **Incident response:** `docs/security/incident-runbook.md` — triage, containment (kill switch → typed mode, token revocation, key rotation), forensics on immutable logs, **KVKK Board notification within 72 h** and data-subject notification, hospital-tenant notification per DPA, post-incident review with action items tracked as tasks.

## 8. Secure SDLC and CI/CD gates (all open-source, all self-hostable)
> v1.4: the delivery workflow itself is a control — one issue → one PR with `no_placeholders` and `evidence_check` gates, red-run evidence, and `approval:human-*` labels for clinical/legal/vendor/infra decisions (07 §0/§3; ADR-019). Backlog `sec_row:` fields point at the §9 rows below, so every feature PR links its threat row by construction.
- **Pre-commit/PR:** gitleaks (secrets), Semgrep + Bandit (SAST), ESLint security rules, dependency review; Renovate for updates with lockfiles; OSV-Scanner and Trivy (fs, image, IaC) with fail-on critical/high; Checkov for Terraform/k8s; license check (Apache/MIT/BSD allow-list; AGPL flagged); Syft **SBOM** (CycloneDX) attached to every artifact; **cosign** keyless signing of images and protocol-pack bundles with SLSA provenance attestations from GitHub Actions; schemathesis API fuzzing; `make safety` and runtime invariants; PHI-pattern scan of fixtures; MobSF on mobile builds.
- **Nightly/staging:** ZAP baseline DAST; LLM red-team suite within budget; k6 load; chaos experiment; restore drill (quarterly).
- **Deploy:** Argo CD GitOps; **Kyverno/Sigstore policy-controller** admits only signed images from the internal Harbor registry; Pod Security Standards *restricted*; read-only root FS, non-root, seccomp, resource limits; default-deny NetworkPolicies; secrets injected from OpenBao (no secrets in env files or images); canary + automatic rollback on SLO/guardrail breach; DPIA delta check when vendors or consent texts change.
- **Protocol packs and prompts are artifacts:** signed bundles, hash pinned per session, CODEOWNER review; unsigned or tampered packs fail to load at runtime.

## 10. Ownership, cadence and evidence
Security owner = founder until a security lead exists; the `security-reviewer` subagent runs on every PR; a monthly security review reads the console's Security module (vulnerabilities, access reviews, drills, pen-test findings); evidence for ISO 27001 (target P3) accumulates automatically from the console (audit exports, drill records, access reviews, SBOMs, scan reports) so certification is a packaging exercise, not a project.
