# 10 · Security architecture and technical monitoring — cross-cutting for every feature (v1.4, 21 Aug 2026)

> Security and monitoring are not a module; they are properties every feature must prove. This file is the canonical spec; each other file carries a short "Security & technical monitoring" section that points here and adds what is specific to its scope. Three rules govern everything: **(1) every feature ships with its threats, controls, signals and tests written down** (§9 matrix); **(2) every service exposes the same health/metrics/trace contract** (§6); **(3) every control on the PHI path is self-hostable and verifiable from the admin console** (`08`). Standards we map to: OWASP ASVS 5.0 (L2), OWASP MASVS 2.x (mobile), OWASP Top 10 for LLM Applications 2025, NIST SSDF, CIS Benchmarks (k8s, Postgres, Linux), ISO/IEC 27001:2022 + 27701, KVKK Board "adequate technical measures", and the Turkish *Bilgi ve İletişim Güvenliği Rehberi* for public-hospital tenants.

## 1. Threat model (summary; full STRIDE/LINDDUN model lives in `docs/security/threat-model.md`)
**Assets:** patient identity (TC Kimlik, phone), clinical narrative and notes, audio in flight, learned facts, consent state, share tokens, clinician identities, protocol packs (clinical safety), model weights/prompts, audit log, admin controls.
**Adversaries:** opportunistic internet attackers (credential stuffing, OTP abuse, SMS pumping), malicious or careless insiders (support, hospital IT, contractors), a compromised vendor or dependency (supply chain), a malicious patient/companion (prompt injection by voice or uploaded document, impersonation, triage manipulation), a hostile network (public Wi-Fi, kiosk tampering), and an attacker with physical access to a kiosk or lost phone.
**Top risks and the control that owns each:** PHI exfiltration via logs/analytics → redaction + no-PHI invariants + egress allow-list; account takeover via OTP → rate limits, device attestation, device binding, anomaly alerts; prompt injection by speech/document → data/instruction boundary, six-tool Talker, deterministic triage, PolicyGuard, injection eval suite; unauthorised note access via Doctor Link → OTP + short-lived scoped tokens + revoke + access log; insider browsing → RBAC/ABAC, break-glass with 4-eyes, hash-chained audit, Wazuh alerts; supply-chain compromise → SBOM, scanning, signed images/protocol packs, admission control, pinned model weights; cloud-vendor overreach → de-identification before cloud calls, ZDR contracts, egress logs as transfer evidence; kiosk tampering → lockdown, ephemeral sessions, no local persistence; ransomware/DR → immutable backups, PITR, quarterly restore drills.
**Added 25 Aug 2026 with the admin-console audit (`08 §0b–0c`), because five of these were absent and each has a named path:** a **parallel authorization plane** — Grafana, Langfuse and Unleash reached directly rather than through `/admin/*`, where `tenant_id` is a label and not an RLS boundary → server-rendered panels only, no browser reach, hashed-content Langfuse, safety flags out of Unleash (inv. 48); an **unrecorded device-classification change** — `device_functions` flipped with an Unleash API token, placing an uncertified Class IIb device into service → gated-capability service with tier-3 four-eyes and write-ahead audit (inv. 34); a **stale study assertion** outliving its approval, which is the *default* outcome rather than an attack → signed Study Registry with `approval_valid_until` and no grace (inv. 35); **`tenant_admin` as SSRF and PHI-redirection primitive** — hospital IT types a connector URL our server fetches from inside the PHI network → registered destinations, select not free text, pinned resolution (inv. 46); and an **insider who repairs the audit chain** rather than merely editing it → INSERT-only writer plus an externally anchored chain head (inv. 40). **The unifying observation: the console's threat model is not "privilege misuse" as `§9` said, it is patient safety, device classification and Art. 9 lawfulness.**

## 2. Identity, access and session security
- **Patients:** phone OTP (6 digits, 5-min TTL, 5 attempts, and request budgets of **3/phone, 10/IP and 3/device counted over a rolling hour ending at each request** — not per fixed hour, which hands the whole budget back at the boundary and therefore admits twice the number inside one rolling hour; a 60 s resend cooldown sits under them, and a refused caller is told the true wait for the bound rather than the time to the next boundary. ⚠ **Corrected 3 Sep 2026 (INT-263):** §2 was silent on rolling versus fixed, which is what let a fixed hourly bucket read as compliant through INT-131 and INT-285; ⚠ `carrier/geo sanity checks against SMS pumping` remains a *named but unbuilt* control — no code honours it, and the budgets above are what actually stands between a caller and SMS pumping) + **device attestation** (Apple App Attest / Google Play Integrity) on OTP request and session start; optional passkeys (WebAuthn) after first login; e-Devlet identity assurance as a P3 option for hospital tenants that require it. Access tokens 15 min, refresh tokens rotating and **device-bound** (DPoP, RFC 9449); refresh reuse detection revokes the family; biometric gate on app open and before note/share screens; idle timeout 10 min on clinical screens.
- **Clinicians (Doctor Link):** OTP to the phone/e-mail the patient chose + 128-bit random token + expiry (default 72 h) + view limit + instant revoke; PDF downloads watermarked with recipient and timestamp; optional hospital SSO (SAML/OIDC via Keycloak) for console users.
- **Staff/admin:** Keycloak (self-hosted) OIDC, RBAC + ABAC by tenant, IP allow-list for console, session ≤ 8 h — **and 30-minute idle timeout on any session that can reach PHI**. ⚠ **Rewritten 25 Aug 2026; the roles and the four-eyes list live in `08 §2` and three properties here were wrong.**
  - **MFA mandatory for every role; phishing-resistant WebAuthn mandatory** for anything touching a protocol pack, the device flag, the study assertion, patient content, connector endpoints or audit configuration. TOTP is phishable, and a phished `platform_owner` plus a phished second approver is a device-mode flip.
  - **Step-up is a fresh, single-use WebAuthn assertion at the moment of the action**, its credential id recorded in the audit row. "Remember this device for 15 minutes" is how a four-eyes ceremony becomes one person with two tabs.
  - **Four-eyes is a server-side pending-action protocol, not a form field.** Actor initiates → 15-minute TTL → a **different `sub`, on a different authenticator (distinct AAGUID and credential id), in their own session on their own device** approves → both identities and both assertion signatures land in `admin_audit.v1` **before** execution. For tier-3, actor and approver **may not share an employer**. Self-approval attempts are rejected and metered (`admin.four_eyes_self_approval_attempt_total` — an intrusion signal, not hygiene). The covered list is the `DangerousAction` registry (`08 §8.2`), which is what the old five-item list should have been: it omitted the device flag, the study assertion, pack promotion, connector endpoints, DSAR deletion, key rotation and role grants, every one more dangerous than the profile change it did cover.
  - **Asymmetric authority.** The kill switch, pack quarantine, lane disable, token revoke and `device_functions` **off** move the system to the *safer* state and take **one** actor. Requiring a second approver at 03:00 to make the product safer is an availability control on a safety control.
  - **Offboarding**: Keycloak is the single source; an SCIM/HR-triggered disable revokes OIDC sessions **and** OpenBao leases **and** the vendor-console accounts in one action; 60-day auto-disable on no login; a departed approver's pending actions **expire**. **Quarterly access reviews are generated by the console and signed with KEP/e-imza, and a review older than 100 days downgrades `platform_owner` and `tenant_admin` sessions to read-only** (`08 §2.7`).
- **Services:** workload identity via k8s service accounts + SPIFFE-style certificates from the mesh; no shared service passwords; dynamic database credentials from OpenBao (TTL 24 h); least-privilege Postgres roles + row-level security per tenant — **with the tenant GUC set from the OIDC claim and never from the request, and a per-request DB role so RLS is actually exercised rather than merely configured**. **A service account never holds a console role.** New: **`svc-audit-writer` holds the only INSERT grant on the audit table; UPDATE and DELETE are granted to no principal anywhere.**

## 3. Data security and privacy engineering
- **Encryption:** TLS 1.3 everywhere (HSTS, modern ciphers, certificate automation with cert-manager/Let's Encrypt or hospital CA); **mTLS between services** via a service mesh (Linkerd, or Cilium) with default-deny NetworkPolicies; volumes encrypted (LUKS/cloud volume encryption) **and** field-level **envelope encryption** (AES-256-GCM) for identifiers, transcripts, notes and learned facts with per-tenant data keys wrapped by keys held in **OpenBao** (open-source Vault fork; Transit engine); key rotation quarterly; **crypto-shredding** implements hard delete.
- **Tokenization:** TC Kimlik and phone are never stored in clear in application tables — a tokenization service returns a keyed pseudonym (HMAC-SHA-256 with a rotated key) for joins and an encrypted value in a separate vault table; logs and analytics only ever see the pseudonym's hash prefix.
- **De-identification before any cloud model call** — ⚠ **corrected 25 Aug 2026: this is structurally impossible on the first hop, and the original wording overstated the control.** In `cascade_fast` the **first cloud call is the STT audio stream itself, and audio cannot be Presidio-redacted.** Every session ships the patient's raw voice — including a spoken TC Kimlik, which our own RT-13 scenario expects — to the STT vendor. Say this plainly and control it with **contract + residency + ZDR**, not with a technical control that does not exist.
  ⚠ **Second correction, 25 Aug 2026 — the two-stream defect is fixed at the source, not by cutting a lane.** The earlier text here recorded that the `affect` lane adds *a second full audio stream to a second vendor*, so two complete copies of the patient's voice left the country by default, while `02 §9` names the vendor in the **singular**. That was true, and the proposed remedy — cut the lane — was wrong (`00 §3` D1, withdrawn). The actual defect was that vendor voice profiling is a **flag on the same transcription request**, not a second socket; the design had specified two streams by accident. Per `03 §4.7.2` the architectural default is now **Soniox direct for STT + open SER run locally on the agent worker**: **one** outbound audio stream, one vendor, **stream-minutes 8.4 → 4.4 (−48 %)**, and the consent text and the egress allow-list are held in agreement by CI. Enforced by three invariants rather than by discipline: `audio_single_egress_guard` (12), `lane_shared_stream_guard` (13, lanes have no network capability at type level) and `consent_vendor_parity` (25). **`02 §9`'s singular vendor is now true rather than aspirational.**
  Where text *does* leave (extraction, Loop 2 exports), Presidio applies — but note **spaCy ships no Turkish model** (`tr_core_news_sm` and `tr_core_news_md` both 404), so Presidio's default NLP engine is unusable here; it needs the `transformers` or `stanza` extra plus custom Turkish recognizers (TC Kimlik checksum, phone, IBAN, addresses, date shifting).
  ⚠ **The `< 0.1 %` leak-rate target is unfalsifiable as written** — it is measured "on the synthetic corpus" *we author*, so we can always hit it by generating entities our own recognizers catch. Realistic recall on conversational Turkish is 0.85–0.95 because names appear in oblique cases (*Ahmet'in*, *Ayşe'ye*) and the language is agglutinative; at 3–8 direct identifiers per 4-minute intake that is **~0.3–1.0 expected leaks per session**. **Redefine the metric as recall per entity class on a held-out, human-labelled, real-transcript corpus with a published confusion matrix**: TC Kimlik ≥ 0.99 (checksum-verifiable and genuinely achievable), names and addresses ~0.90, stated honestly.
- **No PHI in telemetry:** OTel collector runs a redaction processor (regex + allow-list of attributes); logs are structured JSON with ids only; an `audit.v1`/`security.v1` event schema separates security events from application logs; CI test greps fixtures for PHI patterns.
- **Audit log:** append-only, hash-chained (each entry includes the previous hash), daily chain verification, copied to MinIO with **object lock (WORM)**; 10-year retention for hospital tenants. ⚠ **Corrected 25 Aug 2026 — as written this is tamper-evident only against an attacker who cannot recompute the chain.** A `platform_admin` with DB access edits a row **and recomputes the chain forward**, and the verifier goes green; INT-016's acceptance test flips one row, which is not the attack. Four changes: **(a)** `svc-audit-writer` holds the only INSERT grant, with UPDATE/DELETE granted to no principal; **(b)** the chain head is published **hourly outside the `platform_admin` blast radius** — a second organisation's object store, or a KEP/e-imza timestamp from a Turkish TSP, reusing the KEP machinery that already exists for DPA execution — and the daily verifier checks against the **external** head; **(c)** `seq` is monotonic **per actor and per tenant** so a **gap** alerts independently of hash failure, because a clean deletion leaves a valid chain; **(d)** the MinIO/Garage decision (`08 §6`: **Garage does not implement S3 Object Lock, silently voiding the WORM guarantee**) closes **before P1**. Schema in `08 §8.1`; write-ahead ordering is part of it — the row precedes the mutation.
- **Patient-visible access log — shares *and now staff reads*.** It previously covered Doctor Link only, so the honest answer to "does the patient ever find out a member of staff read their intake?" was *only if they file a KVKK m.11 request, and the DSAR export is not specified to include staff reads at all.* **Every break-glass grant now writes an entry to the patient's own access log within 24 h** — date, actor **role** (not name), reason category, duration. This is the m.11/m.13 answer, it makes the DSAR export complete by construction, and it is the single change that most improves the honesty of the design (`08 §2.5`).
- **Errors are not a side channel.** ⚠ **Added 25 Aug 2026.** Beyond the `include_local_variables` defect below: **Pydantic's `ValidationError` includes the offending input in its message by default**, so a malformed extraction turns the patient's sentence into an error string → Loki → the Ops dashboard → the crash reporter, in one hop; and Celery logs task kwargs, while `extract_slots` carries transcript text. A **`SafeError` boundary** converts exceptions to `{error_code, correlation_id}` **before any logger, exporter or crash reporter sees them**, with full detail written only to an encrypted store behind a break-glass grant; Pydantic is configured to omit `input`; `task_kwargs` are never logged. And §8's PHI scan moves **from fixtures to runtime** — scanning fixtures we author proves only that we can author clean fixtures (inv. 36).
- **Backups & DR:** Postgres PITR (pgBackRest/WAL-G) encrypted with separate keys to a second location in Türkiye; MinIO/EHRbase/HAPI included; **RPO 15 min, RTO 4 h**; quarterly restore drills with evidence in the console; immutable backup copies defend against ransomware.
- **Retention automation:** jobs enforce `06 §3` (raw audio never written; lane windows zeroed; logs 30 d hot/1 y cold; deletion 30 d grace); job success is a tracked metric.
- **Raw audio in memory — get the scope right first, then harden.** ⚠ **Framing correction, 25 Aug 2026.** Raw audio is **never persisted**: invariant 9 forbids it, the guard proves there are no write paths, and `03 §4.7` keeps the lane window in memory only and zeroes it after scoring. So the defect is not retention. The real defect is **transient exposure through crash artefacts**, and it applies to **every lane buffer, not just `acoustic`** — `affect` in `residency_tr` also holds decoded PCM, and under the Option-B default (`03 §4.7.2`) it holds it in every profile. Six controls, each with a blocking test:
  - **Core dumps** — `RLIMIT_CORE=(0,0)` set at worker start, container `ulimit -c 0`, and the node's `kernel.core_pattern` verified. Prove it by **actually crashing**: fork a child, set the limit, `os.abort()`, assert `WCOREDUMP` false and no core file at the pattern path. That is a test a fake filesystem cannot satisfy (`audio_no_core_guard`, inv. 16).
  - **Swap** — allocate the ring buffer **once** as a page-aligned `mmap(MAP_ANONYMOUS|MAP_PRIVATE)` region plus `mlock` (the container needs `memlock: unlimited` or `CAP_IPC_LOCK`); swap disabled on the node. Verify via `/proc/self/smaps`: `Locked:` == region size, and `SwapTotal: 0` (`audio_no_swap_guard`, inv. 17).
  - **Zeroization** — wrap the region in a type whose only public API is `write_frames()` / `consume_window()`, zeroing consumed bytes with `ctypes.memset` **on the buffer address**. Not a Python slice assignment, which can leave copies behind. Triggers: window consumed, gate rejection, lane disabled, **consent withdrawn**, session end, and `atexit` plus SIGTERM/SIGINT (`audio_zeroization_guard`, inv. 18).
  - **The crash reporter — the leak nobody mentioned and the one likeliest to actually happen.** GlitchTip/Sentry's Python SDK serialises **local variables into the event by default**. A local named `pcm` is ~960 KB of patient voice posted to the error tracker on any exception in the audio path. Require `include_local_variables=False` globally **plus** a `before_send` hook that drops events whose frames reference the audio module. **This is a live defect today, independent of the acoustic lane** (`audio_no_telemetry_guard`, inv. 19).
  - **Process hardening** — non-root, `no-new-privileges`, `CAP_SYS_PTRACE` dropped, `kernel.yama.ptrace_scope=1`. Without the last one, `/proc/pid/mem` reads the buffer regardless of every control above (`process_hardening_guard`, inv. 28).
  - **Guard naming** — `audio_retention_guard` proved **one** thing (no write path) and was cited as proving four. It is split and renamed: `audio_no_write_guard` (inv. 27) keeps the static scan + fake-fs test, and inv. 16–19 and 28 carry the rest under their own names. A guard cited for a property it does not test is worse than no guard.

## 4. Application, API and mobile security
- **API:** OpenAPI-first with strict schemas (Pydantic), input limits, schemathesis fuzzing in CI, CSRF-safe (token auth only), CORS allow-list, security headers, idempotency keys on writes, per-route consent-scope checks (`consent_guard`), rate limits per user/IP/tenant, request size limits, file-type sniffing and sandboxed OCR for uploads (no macro/JS execution; PDFs rendered in an isolated worker with seccomp), antivirus scan (ClamAV) on uploads, signed URLs for object access (short TTL), no direct object references. **Added 25 Aug 2026: (a) tenant scope is taken from the OIDC claim and `?tenant=` is rejected for every role but `platform_owner` — RLS protects the row, not the parameter, and a pooled connection makes the wrong version the easy one to write (inv. 37); (b) every export serialiser is fuzzed for formula, control-character and CRLF payloads — the DSAR export is the perfect injection vehicle because the attacker writes the content, a compliance officer opens it in Excel, and KVKK m.13 obliges us to produce it within 30 days; export XLSX with text-typed cells, or CSV prefixed and quoted per OWASP (inv. 47).**
- **Edge:** Traefik or Envoy ingress with **Coraza WAF (OWASP CRS)** and **CrowdSec** for reputation/bot behaviour; **egress proxy with an allow-list** — only contracted vendors are reachable from the PHI path, and every egress call is logged with vendor, purpose and bytes, which doubles as KVKK transfer evidence. ⚠ **The allow-list did not cover server-side fetches the console itself provokes.** `tenant_admin` — hospital IT, an adversary in §1 — could type a connector endpoint that our server then fetches **from inside the PHI network holding OpenBao credentials**: `169.254.169.254`, `http://openbao:8200`, `http://unleash/api/admin/features`, where even a failure discloses because the error carries the body. The quieter version is worse: an attacker-controlled host receives **every `push_previsit` with full clinical notes, indefinitely, looking exactly like normal operation**. Therefore **destinations are not free text** — registered out-of-band at onboarding, bound to the signed DPA, rendered as a **select**; the proxy denies literal IPs and private / link-local / metadata ranges, **resolves once and pins, re-validating on connect** (DNS rebinding), and disables redirects; the change is tier-2 by `platform_owner` and pages (inv. 46). **The allow-list is also live configuration in the console, not only a CI assertion** — `consent_vendor_parity` (inv. 25) runs in CI, which is the wrong place to notice that production diverged.
- **Mobile (MASVS 2.x):** Expo dev builds only; tokens in SecureStore (Keychain/Keystore, biometrics-protected); FLAG_SECURE / screenshot blocking on clinical screens; no PHI in push notifications or deep links; deep-link and QR validation (signed check-in payloads); jailbreak/root detection as a soft signal (degrade to typed mode + warn); **EAS Update code signing** for OTA; MobSF scan of every build; crash reports without PHI (self-hosted GlitchTip/Sentry — **and note the server-side default that defeats this: `include_local_variables` must be `False` in every service, see §3 raw audio**).
  ⚠ **Attestation and pinning have no off-the-shelf path — corrected 25 Aug 2026, and this work is currently invisible in the backlog.** `expo-app-integrity` was **last published 2023-04-09** with peers pinned to the SDK 48/49 era (`expo-secure-store ~12.1.1`, now 57.0.1) — **it cannot install alongside SDK 57.** `react-native-app-attest` is **iOS-only** and gives no Play Integrity. **DPoP (RFC 9449) has no Expo module at all** — it needs a device-bound private key plus a per-request JWS proof, i.e. a from-scratch native module on both platforms. And a `fetch`-patching pinning shim will **not** pin the LiveKit WebRTC/DTLS path, `expo-file-system` uploads, or the OTel exporter — i.e. most PHI traffic; pin natively via ATS / `network_security_config` instead, and document an EAS-Update rotation recovery path. **Budget 4–6 engineer-weeks for a first-party config-plugin wrapping `DCAppAttestService` + Play Integrity + a Keychain/StrongBox P-256 key, and file it as its own issue.**
- **Kiosk mode:** guided-access/kiosk launcher, device enrolled in MDM, no biometrics, PIN per clinic, session auto-wipe after 60 s idle, no local persistence, tamper alert when the app is backgrounded, camera indicator for OCR.
- **Clinician web & admin console:** Next.js with SameSite cookies, SSO, no PHI in URLs, short sessions, audit on every view, download watermarking, break-glass only. ⚠ **"Strict CSP" was an aspiration, and the console is the one artefact where it matters most** — a large npm tree running **inside the PHI trust boundary**, in a browser session holding a privileged Keycloak token and rendering break-glass transcripts. Next.js App Router without nonce plumbing typically ships `unsafe-inline`, and the embedded Grafana panels require a third-party `frame-src`, which is `08 §0b` F1 arriving from the other side. Required: **nonce-based CSP with no `unsafe-*`**, `require-trusted-types-for 'script'`, SRI, `npm ci --ignore-scripts`, **no iframes and no third-party `frame-src`**, and a CI test that fetches the **built** app and asserts the emitted header — a policy nobody verifies is a policy nobody has (inv. 48). Panels are server-rendered by `services/api/admin` from the caller's token claims; Grafana, Langfuse, Loki, Tempo and Unleash are unreachable from any browser origin.

## 6. Technical monitoring contract (every service, no exceptions)
- **Endpoints:** `GET /healthz` (liveness, no dependencies), `GET /readyz` (readiness: DB, Redis, queue, model reachability with timeouts), `GET /metrics` (Prometheus), `GET /version` (git sha, build time, SBOM digest). Mobile and web report `app_version`, `build_id`, `sbom_digest` in telemetry.
- **Telemetry:** OpenTelemetry traces, metrics and logs from api, voice-runtime, workers, metrics, probes, learning, clinician-web and admin-web; propagation of `trace_id`, `session_id` (hashed), `tenant_id`, `protocol_hash`, `prompt_version`; **golden signals** (latency, traffic, errors, saturation) dashboards per service; LiveKit Agents metrics (EOU/LLM/TTS/STT/VAD/Realtime/Interruption) and worker Prometheus (`worker_load`, `active_jobs`); client network quality from the LiveKit SDK (RTT, jitter, packet loss, connection-quality events) attached to each turn.
- **SLOs and error budgets** (`08 §4 A`): API availability 99.9 %, voice session success 99.5 %, note ready ≤ 60 s 99 %, Doctor Link open p95 < 2 s; multi-window burn-rate alerts (page at 14.4×/1 h and 6×/6 h, ticket at 1×/3 d); a frozen-deploy policy when the monthly budget is exhausted.
- **Synthetic probes:** `services/probes` exercises every model and service every 60 s (1-s Turkish audio through STT, "merhaba" through TTS, schema-constrained prompt through each LLM, room join through LiveKit, FHIR `metadata`, EHRbase health, OpenBao seal status, certificate expiry, backup freshness) and writes the registry the console renders.
- **Client monitoring:** crash-free sessions ≥ 99.5 % (GlitchTip/Sentry self-hosted), cold start p95 < 2 s, ANR rate, RUM for web (Core Web Vitals), device/OS matrix, offline-draft sync success.
- **Capacity & resilience:** k6 load tests and `lk load-test` for voice concurrency before each release; GPU headroom ≥ 30 %; autoscaling on queue depth and `worker_load`; chaos experiments (kill a vendor adapter, stall the Backend, drop the SFU) in staging monthly; results tracked as metrics.
- **Logging:** JSON, levels, no PII, sampling for debug, 30 d hot / 1 y cold, correlation ids; security events to Wazuh; `docs/runbooks/` linked from every alert; on-call rotation documented.

## 7. Security monitoring, detection and response
- **Signals:** failed logins and OTP anomalies (per phone/IP/ASN), impossible travel, new-device logins, token reuse detections, WAF/CrowdSec blocks, admin actions (all), break-glass events, consent-scope denials (`consent_guard` refusals), egress denials (attempted calls to non-allow-listed hosts — a hard alert), injection suspicions, PolicyGuard spikes, integrity failures (audit chain, image signature, protocol signature), vulnerability counts by severity and age, secret-rotation and certificate-expiry countdowns, backup freshness, DR-drill status, Falco runtime alerts, k8s audit anomalies. **Added 25 Aug 2026 (`08 §4` group O, `08 §5`):** `device_functions` changes **in either direction**, study-assertion changes and assertion-expiry countdown, **asserted-but-expired → page *and* auto-de-assert**, break-glass rate per actor (> 3 / 30 d) and out-of-hours grants without an open P1, patient-access-log publication lag, pack promotion and quarantine, connector-endpoint and egress-allow-list changes, privileged role grants, DSAR deletions with subject count > 1, audit `seq` gaps and external-anchor age, access-review age past 100 days, unacknowledged REDs past the tenant SLA, and **four-eyes self-approval attempts — an intrusion signal, not a hygiene metric**. `sec.admin_actions_total` and `sec.break_glass_total` already existed as metrics **with nothing attached to them**, which is why the console paged on egress denials and chain failures but not on a single admin action.
- **Stack (self-hosted):** Wazuh (SIEM/XDR) + Falco (runtime) + CrowdSec (edge) + OTel security events; dashboards in the console's **Security** module (`08 §3`).

## 8. Secure SDLC and CI/CD gates (all open-source, all self-hostable)
> v1.4: the delivery workflow itself is a control — one issue → one PR with `no_placeholders` and `evidence_check` gates, red-run evidence, and `approval:human-*` labels for clinical/legal/vendor/infra decisions (07 §0/§3; ADR-019). Backlog `sec_row:` fields point at the §9 rows below, so every feature PR links its threat row by construction.
- **Pre-commit/PR:** gitleaks (secrets), Semgrep + Bandit (SAST), ESLint security rules, dependency review; Renovate for updates with lockfiles; OSV-Scanner and Trivy (fs, image, IaC) with fail-on critical/high; Checkov for Terraform/k8s; license check (Apache/MIT/BSD allow-list; AGPL flagged); Syft **SBOM** (CycloneDX) attached to every artifact; **cosign** keyless signing of images and protocol-pack bundles with SLSA provenance attestations from GitHub Actions; schemathesis API fuzzing; `make safety` and runtime invariants; **PHI-pattern scan — now at *runtime*, not over fixtures** (§3, inv. 36); MobSF on mobile builds; **export-serialiser fuzzing** (inv. 47); **CSP header assertion against the built console** (inv. 48); **`DangerousAction` registry completeness against the admin route table** (inv. 33); **instrument-licence gate — a fixture pack referencing C-SSRS must fail the build** (inv. 45); **the clip round-trip gate, synthesise → independent ASR → normalised diff against `text_tr`, made blocking** (inv. 43, `00 §5` Q10).
- **Nightly/staging:** ZAP baseline DAST; LLM red-team suite within budget; k6 load; chaos experiment; restore drill (quarterly).
- **Deploy:** Argo CD GitOps; **Kyverno/Sigstore policy-controller** admits only signed images from the internal Harbor registry; Pod Security Standards *restricted*; read-only root FS, non-root, seccomp, resource limits; default-deny NetworkPolicies; secrets injected from OpenBao (no secrets in env files or images); canary + automatic rollback on SLO/guardrail breach; DPIA delta check when vendors or consent texts change.
- **Protocol packs and prompts are artifacts:** signed bundles, hash pinned per session, CODEOWNER review; unsigned or tampered packs fail to load at runtime. **And two properties signature does not give you:** a published version that has served a session is **byte-immutable** and reproducible from recorded hashes alone (inv. 41), and there is an **emergency un-publish with a stated RTO** — `POST /admin/protocols/{id}/quarantine`, ≤ 60 s for new resolutions, ≤ 5 min from decision including tenant notification, fallback to the last `known_good`, in-flight safety-quarantined sessions switching at the next section boundary, plus a **re-triage sweep** over every session run under the quarantined version (inv. 44, `08 §0c` F7). A signed pack that says the wrong thing loads perfectly.
- **`docs/legal/strings.yaml` and PolicyGuard rules are not editable from any console at any privilege** — PR with legal CODEOWNER review only. Stating this matters because silence reads as permission, and a console that can edit the consent text can also edit the sentence naming which vendor hears the patient.

### 9.2 Invariants 50–65 — RESERVED, NOT SPECIFIED. Do not cite them as if they exist.

⚠️ **This section exists because `03 §4.9.6` and `03 §10` both cite "invariant 53" as though it were catalogued, and it is not.** Numbers 50–65 were **proposed** during the data-import hardening pass and **never written down**. The proposals did not survive; **the numbers did**, and a number without a specification is worse than no number, because it reads as a guarantee that CI is enforcing when nothing is.

**The rule for this range:**

1. **Only invariant 53 has a written behavioural specification** — the unit-resolution guard, stated in prose at `03 §4.9.6` and `03 §10`: *magnitude outranks the printed unit token; disagreement raises a flag rather than triggering a silent conversion; resolve the decimal separator per value, not per document; never substring-match `üre`; a two-number reference cell is a signal to stop, not to average.* **That prose is the specification until someone writes the row.** It is not yet a test, so **do not report it as enforced.**
2. **50, 51, 52 and 54–65 have no specification at all.** They are **reserved and unallocated**. **Nothing may cite them**, and a citation to one of them is a build-review finding.
3. **Nothing enters this range without arriving the way 12–49 did**: a named guard, a stated enforcement point (CI / runtime / simulator), and a source in the legal or clinical files. **The catalogue is the definition of correct; a gap in it is a gap in the definition.**

Security owner = founder until a security lead exists; **device change control is owned by `qms_owner` (`08 §2.1`), a role `09 §4` requires and nobody held before 25 Aug 2026** — a release touching the device boundary does not pass without that signature; the `security-reviewer` subagent runs on every PR; a monthly security review reads the console's Security module (vulnerabilities, access reviews, drills, pen-test findings); evidence for ISO 27001 (target P3) accumulates automatically from the console (audit exports, drill records, access reviews, SBOMs, scan reports) so certification is a packaging exercise, not a project.
